1. SMU coverage targets and closure policy

This chapter defines what the SMU release group is graded on and how a hole is waived. It does not install a CI fail-on-hole gate; that gate needs a measured database first.

Table 1. SMU coverage targets and closure policy
Field Value

Release group

--dut smu --items all on VCS, the coverage set (cov/config/vcs/README.md); hosted is its toolchain-free subset (live sizes in the Release Qualification section of hw/sys/smu/dv/docs/SMU_VPLAN.adoc)

Metrics

the runner’s native families: user (the cov/sv cover properties) on Verilator and VCS; on VCS also line, condition, branch and toggle over the SMU’s own logic, where toggle is every bit of every net of smu_wrapper, smu, smu_axi_xbar and axi_window_remap in both directions after the exclusion files have left the population, and assertion, where urg reads the cover properties and the one smu_axi_xbar assertion

Numeric target

VCS toggle 80 percent effective and assertion 80 percent effective, both gated by cov/config/vcs/smu_wrapper_coverage_policy.toml; user 95 percent effective on Verilator, reported and not yet gated

Measured (VCS, scope epoch smu-vcs-cov-v2)

all, 102 leaves: toggle 57.54 raw / 81.62 effective, condition 76.92, branch 100.00, line 100.00, assertion 90.74, user 90.65 (97 of 107 cover properties). hosted, 70 leaves: toggle 54.07 raw / 75.04 effective, condition 38.46, branch 50.00, assertion 85.19, user 85.05

cov/sv/ carries ten cover-property modules, 111 points in all; the counts are the OCAH_FCOV_COVER invocations in each file. tb/tb_wrapper_top.sv instantiates all ten, and 107 points elaborate on its single target, compile_smu_chiplet, which has SEP present: the four inside g_nosep generate blocks exist only on a SEP=0 elaboration, which this package does not build.

1.1. Public versus commercial evidence

Table 3. Public versus commercial evidence
Path What it collects Where it runs

Public Verilator

line / expr / user over smu_wrapper_cov_scope.vlt, which drops everything the wrapper instantiates at compile time — the SMU block, the SEP, SMC and DTP trees, the hw/top integration shells, vendored and generated RTL. Toggle is not collected on Verilator, as the DTP set does not collect it: coverage_off -file does not apply to a source file whose last line has no newline, and the vendored and hw/common files in that state would carry subsystem toggle points into the wrapper’s database

weekly --cov on the large runner (regress.yml). Nightly does not collect.

Commercial

line / condition / branch / toggle / assertion databases under the licensed flow. smu_wrapper_cov_scope.hier, written by gen_smu_cov_scope.py, follows the rule the SEP and SMC scopes state: SMC, DTP and SEP leave as instance trees because each is graded on its own bench, as do the integration shells and the bench’s AXI egress glue; bench units, library cells and the vendored interconnect cells leave by design unit; the cov/sv monitors leave the code and toggle metrics and stay in the assertion metric. Toggle covers every net of what stays, and -cm_noconst leaves tied-off nets out. cov/config/vcs/smu_wrapper_toggle_exclusions.el and smu_toggle_exclusions.el name, one fact per class, the fields no SMU logic reads or writes, and the policy applies them at report time. cov/config/vcs/smu_wrapper_coverage_policy.toml floors toggle and assertion at 80 percent; run_dv.py grades both and prints them on its coverage line (see cov/config/vcs/README.md)

not a public CI job; not a substitute for the public weekly

The VCS figure is the SMU’s own logic: the wrapper’s wiring, smu.sv with its reset, lifecycle and cross-trigger glue, smu_axi_xbar and the SEP alias remap. Most of it is wiring, so toggle carries most of the population, on the same per-bit, both-directions definition and through the same runner family as every other DUT. The Verilator figure is narrower, the wrapper and the cov/sv points; quote the flow with the number. The exclusion files are the only place where the population is shaped after compile, and every class in them states its fact and what would retire it. A Python smu_fcov.py sampler is not the release metric and is not a gate.

A vendor site that coverage_off cannot name (hierarchy under .u_smc / .u_dtp) is a hole with category = "out_of_scope" and disposition = "exclude_scope". Write it only from a real database: expected_matches is a hard count, and a guessed count is a ConfigError on the first run.

1.3. Waiver fields

Every row must carry:

  • tool, metric_family (the family that database holds: user and the wrapper’s own toggle), hierarchy or file selector

  • category (one of the runner’s hole categories, such as missing_stimulus, config_disabled, out_of_scope or unreachable)

  • disposition

  • owner

  • review_date

  • issue when the disposition is actionable

max_unclassified_points = 0 is the fail-on-new-hole knob. It is not set here; it is set together with the threshold, from a measured weekly --cov database.

A waiver reaches a finished run without a simulator: python3 tools/dv/run_dv.py --dut smu --run-dir <run> --waive re-grades the run’s report against this policy and rewrites its coverage grade in place. A dispatch of dashboard.yml with the weekly’s regress run id does the same for the published weekly. Both are described on the runner and dashboard pages under tools/dv/doc/.
