1. SMC coverage targets and closure policy

This chapter defines what the SMC release group is graded on and how a hole is waived. It does not install a CI fail-on-hole gate; that follows a measured database and an owner-signed number.

Field Value

Release group

--dut smc --items hosted (nightly and weekly, regress.yml). --dut smc already instantiates smc_wrapper; there is no second wrapper job.

Public metrics

line, branch, expression, and the native user family

Numeric target

none until an owner signs a measured number

1.1. Public versus commercial evidence

Path What it collects Where it runs

Public Verilator

line, branch and expression (--coverage-line, --coverage-expr) plus the user family from the hw/sys/smc/dv/cov/sv/ cover properties, scoped at compile time by smc_cov_scope.vlt

weekly hosted with coverage: true. That is collection, not a signed gate.

Commercial

code + assertion + covergroups under ifndef VERILATOR

licensed VCS; not a public CI job

FUNC_COV_VALUE log text from SmcScoreboard is not a mergeable metric. Nothing under tools/ or .github/ reads it. Do not credit it as the release functional-coverage gate.

There is no checked-in 98%-after-waiver figure. SMC does not inherit an unwritten default. Do not invent one.

SAMPLE-only Python bins that saturate at unique=1 (i2c_state, gpio_state, irq_state, axil_master) are stimulus holes, not coverpoints to publish as 100%.

1.2. Structural OUT versus a waiver hole

Kind Effect Carrier

Structural OUT

the point never enters the database

compile-time scope (coverage_off / VCS hier). Vendored RTL and the chipyard-generated CPU cluster are SMC-level OUT; they are not this package’s to close.

Waiver hole

the point exists and is not hit

coverage_policy.toml [[holes]], written from a measured run

Do not write [[holes]] or [[thresholds]] before a database exists. expected_matches is a hard count.

1.3. Waiver fields

Every [[holes]] row must carry:

  • tool, metric_family, hierarchy or file selector

  • category (out_of_scope / excluded / waived / open)

  • disposition

  • owner

  • review_date

  • issue when the disposition is actionable

max_unclassified_points = 0 is the fail-on-new-hole knob; it is set once the owner signs a measured number. Weekly coverage: true without that knob is not a release coverage gate.

A waiver reaches a finished run without a simulator: python3 tools/dv/run_dv.py --dut smc --run-dir <run> --waive re-grades the run’s report against this policy and rewrites its coverage grade in place. A dispatch of dashboard.yml with the weekly’s regress run id does the same for the published weekly. Both are described on the runner and dashboard pages under tools/dv/doc/.
