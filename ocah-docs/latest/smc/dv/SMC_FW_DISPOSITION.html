1. SMC firmware image disposition

This is the disposition of record for every firmware image name under hw/sys/smc/dv/fw/tests/. The shared engine (hw/common/dv/fw/compile.mk) builds every tests/<name>/ directory it finds, so being built is not a consumer. A consumer is a testlist entry that stages the image: a firmware = "<name>" key in hw/sys/smc/dv/testlists/.toml resolved through a [c_build.] block of smc_sim_cfg.toml, or an SMU DV [c_build.*] that builds and stages it. Every directory in the tree has a row here, and the rule for adding one is in hw/sys/smc/dv/fw/README.md: a new image is added together with its consumer and its row.

Buckets:

  • enrolled — staged by a testlist entry in this tree. The row names the leaf and the [c_build.*] block.

  • external-consumer — staged only by another package: an SMU DV group outside SMU all, or a regression outside this repository. The image is kept for that consumer and is not counted toward this tree’s coverage.

  • deferred — kept for a stated blocker. The row is the blocker and the condition that closes it; a closed row moves to enrolled with its leaf, or to superseded.

  • superseded — the property is proven by a live enrolled name, or the image duplicates another image that has its own row, or the image has no DUT property. There is no directory in the tree; the code is in git history under the image name, and the row is what a reader searching for that name finds.

The cocotb test names of this package have their own record, SMC_DEFERRED_DISPOSITION.adoc; rows below that cite a waived cocotb alias point at it. SMU’s record of the tests that stage SMC images is hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc.

1.2.1. Shared sources with an external consumer

The build of the companion regression outside this repository resolves its firmware includes against this tree’s fw/tests/ and fw/include/, so a shared header has a consumer when that firmware includes it or when an external-consumer image above includes it.

Source Consumer

tests/cla_sanity_sequence.h, tests/uart_sanity_sequence.h, tests/reset_ctrl_sequence.h

Included by firmware of the companion regression outside this repository; reset_ctrl_sequence.h also by reset_ctrl_sanity. Closes with the last includer.

1.3. Deferred images

Each row states the blocker and the consumer whose arrival closes it. The smc_fw_hello_world_test pattern is a fire-and-forget CPU verdict on CPU_CTRL SCRATCH_0; the smc_fw_plic_claim_test pattern adds an arm_value the cocotb side waits for before it drives a stimulus. Rows that need a rom-mode OCCP build share one trigger: the generic [c_build.*] is added with the first image that consumes it, not ahead of it.

Image Bucket Blocker and what closes the row

i2c_p1_back_to_back_xfer

deferred

The header promises eight back-to-back transfers but main() performs one 4-byte write (Step 4) and posts PASS; a wire decoder on the pad bus saw one START and one STOP. Closes when the image runs the transactions its header describes and is enrolled as smc_fw_i2c_p1_back_to_back_xfer_test on the smc_fw_i2c_pair_test_seq wire-floor pattern.

mailbox_sanity

deferred

PLIC claim of a mailbox IRQ is provable only from the CPU; smc_mailbox_irq_test and smc_mailbox_event_irq_test observe the IRQ pin. Closes with a smc_fw_plic_claim_test-pattern leaf (arm_value plus an on_armed stimulus from cocotb) in testlists/fw.toml whose stimulus writes the mailbox after the 'interrupts set up' word.

wdt_sanity

deferred

Cluster WDT bark, stuck handler, second-stage reset and revive need a running hart; smc_wdt_key_csr_test (testlists/power.toml) is CSR-only. Closes with a smc_fw_plic_claim_test-pattern leaf (arm_value plus an on_armed stimulus from cocotb) in testlists/fw.toml arming on scratch[7].
