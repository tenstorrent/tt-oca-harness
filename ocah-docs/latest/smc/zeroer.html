Zeroer

The SMC Memory Zeroer efficiently initializes large memory regions to zero without CPU intervention. The unit uses a state machine-based architecture with dual clock domains.

Table 1 summarises the zeroer control aperture and fabric integration.

Table 1. SMC Memory Zeroer Integration
Parameter Description

Address Range

0xC003_8200 - 0xC003_83FF (512 bytes)

Control Interface

AXI4-Lite

Data Interface

AXI4 Master (56-bit address, 64-bit data, 4-bit ID)

Maximum Burst Length

256 beats (AWLEN = 255)

Outstanding Transactions

Counted by a 32-bit counter; no 32-transaction issuance limit or counter-based back-pressure

Figures and tables: Table 1.

1. Use Cases

  • System Initialization: Clear memory regions during boot or reset sequences

  • Security Operations: Sanitize sensitive data areas

  • Memory Management: Initialize allocated memory blocks

  • Error Recovery: Clear corrupted memory regions

2. Architecture

The DMA and zeroer share the data-accelerator fabric path shown in SMC DMA and memory-zeroer architecture.

2.1. State Machine

The zeroer implements a three-state operation model (Table 2).

Table 2. SMC zeroer state machine
State Description

ST_IDLE (3’b001)

Idle state waiting for configuration and trigger

ST_ISSUE_ADDR (3’b010)

Address phase - issuing AXI write addresses

ST_ISSUE_DATA (3’b100)

Data phase - streaming zero data for all beats

Figures and tables: Table 2.

2.2. Operation Flow

  1. Configuration: Software writes destination address and size to registers

  2. Trigger: Write to control/status register initiates operation

  3. Address Phase: Hardware calculates optimal burst patterns and issues write addresses

  4. Data Phase: Hardware streams zero data matching issued address beats

  5. Completion: State machine returns to idle with status update and optional interrupt

2.3. AXI Master Interface

Table 3 summarises the zeroer’s AXI master interface.

ID Width

4-bit transaction ID (internal 3-bit usage)

User Signals

12-bit user field for system-specific attributes

Maximum Burst Length

256 beats (AWLEN = 255)

Burst Calculation

Automatic optimal burst sizing

Address Alignment

Intelligent handling of unaligned start addresses

Boundary Handling

Automatic burst fragmentation at page boundaries

2.4. Outstanding Transaction Management

The zeroer counts accepted write addresses and consumed write responses in a 32-bit outstanding-request counter. The counter determines whether responses remain pending; it does not impose a limit of 32 transactions or throttle address issuance. AXI AWREADY and WREADY provide downstream back-pressure.

The response channel is consumed without checking BRESP. Completion means that all responses have arrived, not that every write succeeded. The internal error state handles an illegal state-machine encoding, not AXI bus errors. Software requiring verified clearing must use an independent verification path.

2.5. Dual Clock Domain Architecture

The zeroer implements dual clock domain operation for power management and interface isolation.

2.8.1. Operation Control

Table 6. SMC zeroer Configuration and Control

64-bit byte count for zeroing operation

Control and status register (trigger, busy status)

CTRL_STATUS.INT_EN

2.8.2. Status Features

  • Busy Status: Real-time indication of zeroing operation in progress

  • Completion Status: Updates when all write responses received

  • Error Reporting: No software-visible AXI error report; failed write responses are not distinguished from successful responses

  • Interrupt Generation: Optional interrupt on operation completion
