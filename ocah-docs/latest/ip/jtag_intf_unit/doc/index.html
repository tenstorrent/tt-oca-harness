JTAG Interface Unit

The JTAG Interface Unit (JIU) is the top-level JTAG control module for the DTP subsystem. It manages the primary JTAG port and all supporting instrument logic.

1. Overview

The JIU contains:

  • A Primary TAP (PTAP) with chiplet IDCODE, boundary scan, BIST, reset control and JTAG2AXI bridges.

  • A configurable number of Secondary TAPs (STAPs) for downstream chiplet JTAG, SMC CPU debug, SEP CPU debug, and optional additional TAPs.

  • An iJTAG network with SIB-based chains for DFT (secure and non-secure), DFD, and JTAG2AXI bridges to the SMC fabric, SMC OTP and SEP OTP controllers.

  • Per-path debug-disable inputs gate STAPs, iJTAG SIBs, and JTAG2AXI bridges.

The PTAP, STAP and all supporting logic conform to IEEE 1149.1-2013 (JTAG), IEEE 1687-2014 (iJTAG) and IEEE 1838-2019 (3DIC).

2. Configuration Parameters

The JIU is configured through the PTAP feature enables, the I/O, SMC debug and SEP debug STAP enables, the number of additional STAPs, the IDCODE and JTAG_CAPS values, and the JTAG2AXI pipeline depths.

The parameters of jtag_intf_unit are listed in jtag_intf_unit.

3. Architecture

The JTAG Interface Unit integrates the PTAP, STAP chain and iJTAG network into a unified debug access point.

Figure 1 shows the PTAP, STAP chain, and iJTAG network at the debug access point. Follow the arrows from TDI to TDO: italic labels beside a mux name the instructions or select bit that choose its input, 0 or 1 at a mux input is the select value that picks it, and italic labels in the STAPs and SIBs name the dbg_disable_i field that closes each one. Dashed blocks exist only when their enable parameter is set; NUM_EXTRA_STAPS sets the number of u_stap_extra instances. TDO is retimed on the falling edge of TCK except during a ZERO_LENGTH_BYPASS DR scan with the TAP_3DCR STAP-select bit clear, when the last mux takes the TDO mux output ahead of the retimer and TDI reaches TDO combinationally. While the bit is set, ZERO_LENGTH_BYPASS behaves exactly as BYPASS: the PTAP bypass register leads the STAP chain and the chain’s return is retimed, because the chain launches its last bit on the rising TCK edge.

Figure 1. JTAG Interface Unit scan chain

3.1. Scan Chain Topology

The PTAP is connected to the incoming JTAG interface for the chiplet. The scan chain is organized in three major segments: the Primary TAP processes all instructions, the Secondary TAP chain provides hierarchical TAP access, and the iJTAG network enables instrument-level access to debug blocks.

The I/O STAP enables TDI lockup to handle the longer propagation delays across die boundaries. On-chip STAPs (SMC Debug, SEP Debug) disable TDI lockup since signal routing is local to the chiplet.

No STAP in the chain enables scan output lockup. The chain return reaches the PTAP’s falling-edge TDO retimer, and a lockup ahead of that retimer would add one TCK of latency to every scan through the STAP chain. The last STAP’s scan output also drives stap_host_scan_out_o, which launches on the rising edge of TCK like the host scan outputs of the iJTAG SIBs.

stap_host_scan_out_o carries the scan bit of the last STAP’s SIB. That bit resets to 0 on TRST and in Test-Logic-Reset, so the port reads 0 from reset.

3.1.2. Debug Disable Synchronization

dbg_disable_i (sep_lifecycle_ctrl_pkg::dbg_disable_t) is in the system clock domain and must be synchronized to TCK before use. The interface unit synchronizes each bit through a 2-FF chain whose reset value is 1 (fail-closed). The synchronized fields gate STAP and SIB selection and are forwarded to the PTAP for the JTAG2AXI bridges.

Each field is active-high (1 = path disabled).

3.2. iJTAG Network

The iJTAG network is organized into three cascaded Segment Insertion Bit (SIB) chains. Each SIB is gated by the corresponding synchronized debug-disable field. Each SIB’s scan bit and control bit reset to 0 on TRST and in Test-Logic-Reset, so dft_secure_host_scan_out_o, dft_host_scan_out_o and dfd_host_scan_out_o read 0 from reset, whether or not the SIB is disabled.

The PTAP selects the iJTAG network as its DR under SELECT_IJTAG and, when RUNBIST_ENABLE is set, under RUNBIST. From TDI the scan path passes through the DFT Secure SIB, the DFT Non-Secure SIB and the DFD SIB, and the DFD SIB’s output returns to the PTAP. Each SIB is one bit long. While a SIB is open, its segment is inserted on the TDO side of its bit: the SIB bit drives the segment’s scan input, and the segment’s return continues to the next SIB. With every SIB closed the iJTAG DR is three bits long, laid out as in Table 3.

Table 3. JIU iJTAG DR with every SIB closed
DR Bit SIB Segment Ports Disable Field

1

dft_host_scan_*

dbg_disable_i.dft_nonsecure

2

Bit 0 is nearest TDO and is the first bit shifted in. A SIB bit shifted in as 1 opens that SIB at Update-DR, and its segment is on the scan path from the next DR scan. Each SIB captures its own open state. A SIB whose disable field is set stays closed and remains a one-bit stage that captures 0, whatever is shifted into it.

To reach a segment through the iJTAG network:

  1. Shift SELECT_IJTAG, or RUNBIST to run BIST, into the instruction register using the IR-Scan sequence.

  2. Shift three bits into TDI using the DR-Scan sequence, starting with the least significant bit, to open the target SIB: 3’b100 for DFT Secure, 3’b010 for DFT Non-Secure or 3’b001 for DFD. The target SIB’s disable field must be clear.

  3. Shift the lengthened DR into TDI using the DR-Scan sequence, starting with the least significant bit, with the target SIB’s bit held at 1. With the DFT Non-Secure SIB open and an N-bit segment, the DR is N + 3 bits long: bit 0 is the DFD SIB, bits N to 1 are the segment with the bit nearest its scan output at bit 1, bit N + 1 is the DFT Non-Secure SIB and bit N + 2 is the DFT Secure SIB. The contents and length of each segment are defined by the network attached to its ports.

  4. The captured contents of the same scan path shift out on TDO.

  5. To close the SIB, shift the same DR with the target SIB’s bit at 0.

3.2.1. DFT Secure Chain

The DFT Secure chain is gated by dbg_disable_i.dft_secure. This port is for security-sensitive DFT control.

3.2.2. DFT Non-Secure Chain

The DFT Non-Secure chain is gated by dbg_disable_i.dft_nonsecure. General DFT control is attached to this port.

3.2.3. DFD Chain

The Design-for-Debug (DFD) chain is gated by dbg_disable_i.dfd. Integrator-defined debug instruments are attached to this port.

3.3. JTAG2AXI Interfaces

The interface unit instantiates multiple JTAG2AXI bridges. Each bridge is a set of PTAP TDRs selected by its own instructions and gated by its own dbg_disable_i field (Table 2); no bridge is reached through the iJTAG network.

  • SMC JTAG2AXI TDRs: This set of TDRs provide a mechanism to inject AXI transactions onto the SMC AXI local interconnect.

  • SMC Fuse JTAG2AXIL TDRs: This set of TDRs provide a mechanism to interact directly with the SMC fuse controller. The JTAG2AXIL interface connects to the fuse controller CSRs through an AXI4-lite-to-APB bridge.

  • SEP Fuse JTAG2AXIL TDRs: This set of TDRs provide a mechanism to interact directly with the SEP fuse controller. The JTAG2AXIL interface connects to the fuse controller CSRs through an AXI4-lite-to-APB bridge.

4.2. Signal Interface

Packed control and bus types remain bundles at the jtag_intf_unit boundary; their members are not separate scalar ports.

The parameters and ports of jtag_intf_unit are listed in jtag_intf_unit.

4.3. Dependencies

The JTAG Interface Unit depends on the following components:

  • hw/ip/jtag/jtag_ptap - Primary TAP

  • hw/ip/jtag/jtag_stap - Secondary TAP

  • hw/common/ocah_prim - Primitive cells
