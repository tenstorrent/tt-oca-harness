0.5.18

Haohao Liao

Reframed the SEP secure-boot signing model as fuse-seeded and firmware-propagated: REQUIRED_SIGNERS is now the required-signer set (0 = required; firmware-writable shadow, seed made immutable by a fuse-only LOCK) decoupled from REQUIRED_ALGS; added KEY_PROVISIONED (per owner/algorithm) with a fuse-map reorg (32 fields, 8192 bits); rewrote the Signing-Model Enforcement section (three-fuse model, firmware propagation, manifest terminology) and added signing-model examples.

0.5.19

2026-07-22

Haohao Liao

Revised the Life Cycle Controller and Fuse Controller specification following manager review of the secure-boot and demotion model. Simplified the secure-boot signing model (2-bit REQUIRED_SIGNERS; removed KEY_PROVISIONED); reworked in-field debug demotion into two independent controls, Demotion 1 (local debug) and Demotion 2 (inter-chiplet debug bypass); added a Secure-Boot Enforcement section; added a second SiP root-key slot for key revocation; and revised the wording throughout for clarity.

0.5.20

2026-07-26

Haohao Liao

Lifecycle Controller: clarified that SIP_DBG is the SiP debug-access gate at each LCC-bearing chiplet and reworked the Multiple Security Domains access rules and example accordingly. Security Disable: restructured the section to present rationale and behavior before implementation requirements. Key Manager: the life-cycle state is now an input to the software/hardware root-key derivations, aligning the chapter with the KM KDF design specification; demotion is excluded from root derivation and binds at leaf-key derivation only.

0.5.21

2026-07-28

Haohao Liao

Addressed review feedback. Life Cycle Controller: aligned the scan-protection and demotion text with the SIP_DBG debug-access-path model (SEP_DBG / CHIPLET_DBG are local gates; external access additionally requires the SIP_DBG path). Key Manager: made the implicit life-cycle binding of UID-derived keys explicit (a life-cycle transition invalidates the roots and the entire UID-derived hierarchy). Security Disable: the comparator kill switch is a metal-programmable revision cell, and the token hash is not a secret — secrecy rests on the full-entropy token held in the HSM.

0.5.22

2026-08-05

Haohao Liao

Expanded the SEP fuse map to relieve the lock-bit budget and to carry Key Manager identity inputs. LOCK is widened from 64 to 96 bits, raising the field count from 32 to 48 slots (41 now defined). Added three public per-owner identity fuses, SEP_CHIPLET_ID / SEP_SIP_ID / SEP_SYS_ID, which personalize each owner’s Key Manager identity root and, being public, need no read protection. Replaced the two coarse reserved blocks with eight individually lockable 256-bit spare fields (spare0-spare7) so an adopter can provision and lock spare storage one field at a time. The map remains 8192 bits.
