Serial Peripheral Interface (SPI)

SEP will have one SPI host to support access to external NOR flash devices which are the primary BL1 image source. Modern devices are MT35 type and have octal x8 DDR interfaces; the OpenTitan SPI Host does not drive those, so SEP uses the x4 and x1 channel modes it does support and attaches MT25 category devices.

1. Use Cases

  • BL1 boot image access from external flash device

  • Sensor interfaces (automotive primarily)

2. Features

The component will be based on the OpenTitan SPI Host design and support the following features:

  • Single channel (x1) mode, clock frequency up to 80 MHz

  • Dual channel (x2) mode

  • QSPI (x4), quad channel mode, clock frequency up to 166 MHz

  • Separate FIFOs for transmit and receive. Each can be parameterized for distinct depth.

  • AXI4-lite slave port for system interconnect

Quad is the widest mode the IP offers: it drives four data lines, and its per-segment speed selector encodes only standard, dual and quad. All transfers are single transfer rate, so there is no octal (x8) mode, no DDR mode and no DQS read data strobe. An integrator needing those must substitute their own controller at the sep_io_spi boundary.

The SPI pass-through mode supported by OpenTitan is used on discrete secure element designs as a security bridge to filter, modify or otherwise modify traffic coming from a separate SPI slave device. We do not support this feature and will leave this interface on the component unconnected or terminated. Furthermore, there is no SPI Slave device present in the SEP peripheral subsystem.

The SEP instantiates a SPI host controller for boot. The sep_ot_spi_wrap module wraps the unmodified OpenTitan SPI host on its native TL-UL register interface and bridges the AXI4-Lite bus the peripheral fabric presents, the same arrangement the cryptographic accelerators use. It exposes the standard SPI pad signals (SCK, CS, 4-bit bidirectional I/O), an interrupt output and a DMA trigger (lsio_trigger_o). The NUM_CS parameter controls the number of chip-select outputs. Because this controller is software-driven rather than memory-mapped, an integrator wanting XIP flash access can substitute their own controller at the sep_io_spi boundary. The controller’s interrupt is consumed internally: it feeds the SEP PIC via sep_internal_interrupts (through the irq field of sep_io_spi_req_t). The two OpenTitan interrupt sources, error and SPI event, are combined onto that single line, so software reads INTR_STATE to tell them apart. There is no busy output: the OpenTitan host reports activity only through STATUS.ACTIVE, which software reads over the register interface. The block’s access-control (RACL) and SPI pass-through interfaces are not used and are tied off.

The interrupt semantics are the OpenTitan ones throughout. INTR_STATE.ERROR is a latched event: an error condition or a write to INTR_TEST sets it, it stays set once the cause goes away and once INTR_TEST is written back to zero, and software clears it by writing 1 to it. Clearing ERROR_STATUS does not clear it. INTR_STATE.SPI_EVENT is a status bit that instead follows the level of the events selected by EVENT_ENABLE. INTR_ENABLE qualifies only the outgoing interrupt line; neither state bit is gated by it, so both read their source with the enable clear.

SEP instantiates the vendored OpenTitan SPI Host without RTL modification. Before the core, sep_io narrows the 64-bit peripheral AXI bus to 32 bits and the wrapper converts AXI4-Lite to TL-UL. An 8-byte write is therefore emitted as two 4-byte writes. If its byte strobes select only one half, the other reaches the AXI4-Lite bridge with all strobes clear. The bridge completes that no-op locally with OKAY and does not issue a TL-UL request; if forwarded, the upstream register block would set ERROR_STATUS.ACCESSINVAL and return an error.

Consult the OpenTitan SPI Host documentation for the authoritative core functionality of the IP. The Programmer’s Guide gives the programming guidance for this block. The register map follows below.
