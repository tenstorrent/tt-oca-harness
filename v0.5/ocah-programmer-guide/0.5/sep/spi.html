Serial Peripheral Interface (SPI)

SEP instantiates one OpenTitan SPI Host for software-controlled access to external devices. NOR flash is the primary source of the BL1 boot image. The controller uses commands and transmit/receive FIFOs; it does not provide a memory-mapped flash window for execute-in-place (XIP) access.

1. Use Cases

  • Read the BL1 boot image from external NOR flash.

  • Connect to sensors, particularly in automotive applications.

The intended flash interface uses the x1 and x4 modes of MT25-class devices. The host cannot drive the octal x8 DDR interface of MT35-class devices. Select a flash device and command protocol compatible with the supported modes below.

2. Features

Capability SEP implementation

Transfer width

Standard (x1), dual (x2) and quad (x4), selected per command segment.

Transfer rate

Single transfer rate only. No octal (x8), DDR or DQS read-data strobe.

Chip select

One chip-select output. The wrapper parameter NUM_CS supports other counts, but sep_io instantiates it with NUM_CS = 1.

Data buffering

Separate transmit and receive FIFOs, with independently defined depths in the core configuration.

Register interface

32-bit AXI4-Lite converted to the core’s native TL-UL interface.

External signals

SCK, active-low chip select and four bidirectional data lines, with output enables.

The frequency targets are up to 80 MHz in x1 mode and 166 MHz in x4 mode. These are design targets, not guaranteed operating limits for an integrated platform. Software sets the serial clock through CONFIGOPTS.CLKDIV: f_SCK = f_clk_i / (2 * (CLKDIV + 1)). Select the divider and sampling timing for the attached device and the platform’s validated clock and I/O timing.

3. Integration and Register Access

sep_io narrows the 64-bit peripheral AXI bus to 32 bits. The sep_ot_spi_wrap wrapper then converts AXI4-Lite accesses to TL-UL for the vendored OpenTitan SPI Host. Software submits command segments and moves data through the FIFOs; controller activity is available in STATUS.ACTIVE, not on a separate busy output.

An 8-byte write is split into two 4-byte writes. If the byte strobes select only one half, the other reaches the AXI4-Lite bridge with all strobes clear. The bridge completes that no-op locally with OKAY and sends no TL-UL request. Forwarding it to the core would set ERROR_STATUS.ACCESSINVAL and return an error.

The core’s access-control (RACL) interface is disabled and its SPI pass-through interface is tied inactive. SEP contains no SPI slave device and does not use the pass-through arrangement that lets a discrete secure element interpose on another SPI device’s traffic. An integration requiring XIP, octal or DDR operation needs a different controller; sep_io_spi is the existing SPI integration boundary.

4. Interrupts

The core’s error and SPI-event interrupt outputs are ORed onto one line. The irq field of sep_io_spi_req_t carries that line to sep_internal_interrupts and the SEP PIC. Software reads INTR_STATE to identify the source.

INTR_STATE bit Behavior and clearing

ERROR

Latched event. An enabled error event or an INTR_TEST write sets it. It remains set after the cause disappears or INTR_TEST is written back to zero. Clear it by writing 1 to the state bit; clearing ERROR_STATUS alone does not clear it.

SPI_EVENT

Level-sensitive status of the conditions selected by EVENT_ENABLE. Service the condition or change its selection to remove the source; it is not a latched error event.

INTR_ENABLE qualifies only the outgoing interrupt line. It does not gate either state bit. ERROR_ENABLE selects the configurable error events; invalid register accesses always generate an error event.

5. DMA Trigger

The host’s lsio_trigger_o connects to Secure DMA handshake input 0. It is the registered OR of the transmit and receive watermark conditions: TXQD < TX_WATERMARK or RXQD >= RX_WATERMARK. These thresholds are in 32-bit FIFO words. The trigger does not depend on EVENT_ENABLE or INTR_ENABLE; interrupt selection and DMA pacing are separate controls. Configure the FIFO watermarks for the intended transfer direction and use the DMA chapter’s handshake setup.

6. Core Reference

The OpenTitan SPI Host documentation describes core operation and command sequencing. The register map below records the integrated core’s registers and fields. The Programmer’s Guide gives the programming guidance for this block.
