SMU Composition and Internal Wiring

The System Management Unit (SMU) combines the SMC, DTP, and optionally the SEP into a unified subsystem. The interface descriptions in the preceding sections apply directly when integrating the SMU, since the SMU inherits all three subsystems' ports. This section covers the module variants available to adopters, how the SMU wires its subsystems together internally, and what additional configuration it exposes.

1. Module Variants and IP Integration

OCAH core modules (smc.sv, sep.sv, dtp.sv, and the composite smu.sv) expose logic-level interfaces only. All technology-specific components — PLLs, PVT sensors, eFuse shims, memory macros, GPIO padrings, SPI controllers, and external TRNG — are instantiated outside the core modules by the adopter. This separation keeps the OCAH deliverable technology-neutral.

The figure below shows that boundary. smu exposes a technology integration interface for each of these components, and a reference integration module holds the shims, models and macros behind them. An adopter keeps the interfaces and replaces what lies below the boundary with its own technology IP.

Figure 1. SMU Technology Integration

The repository provides reference wrappers that demonstrate how to bridge the gap between OCAH core interfaces and adopter-specific IP:

  • smu_wrapper.sv wraps smu.sv with pad-level signal handling for clocks, resets, GPIO, eFuse, and JTAG interfaces. It internally instantiates smc_ip_integration.sv for SMC-related vendor IP and sep_ip_integration.sv for SEP-related vendor IP. Each integration module holds its own eFuse interface shim and eFuse bank.

  • smc_wrapper.sv provides an equivalent reference wrapping smc.sv alone, useful when integrating the SMC without the DTP/SEP subsystems.

Neither the wrappers nor the IP integration modules are part of the OCAH deliverable; they exist as integration guides. Adopters must develop their own equivalents following the interface patterns demonstrated in these modules. The interface contracts at the module boundaries ensure technology substitution without modifying the verified OCAH logic.

1.1. IP Integration Modules

smc_ip_integration.sv demonstrates integration of SMC-side technology components: PLL wrappers (generating pll_cgm_clk_o and pll_awm_clk_o), PVT sensor interfaces, eFuse shims, GPIO padring logic, memory macros (ROM, scratchpad RAM, cache tag and data arrays), and trace memory instances.

sep_ip_integration.sv demonstrates integration of SEP-side technology components: SEP memory macros (TCM, scratch SRAM, boot ROM, OTBN IMEM/DMEM, Key Manager ROM/SRAM), eFuse shim, external TRNG, and SPI controller selection.

1.2. Wrapper Clock Architecture

The behavioral pll_wrap model is a DV/reference placeholder: it free-runs refclk, sys_clk, and periph_clk at 100 / 800 / 200 MHz (+pll_sys_period_ns=10 runs sys_clk at 100 MHz; with +pll_osc_bench a bench toggles the oscillator nets itself), muxes sys and periph with ref through prim_clock_mux2 then prim_ag_clk_mux, and terminates the AXI-Lite PLL control interface with OKAY. It is not a synthesis stand-in. An adopter who replaces smc_ip_integration supplies equivalent clocks internally; the bare cores still have the three clock inputs.

2. Clock and Reset Architecture

Connect clk_smu_i to the primary system clock and clk_ref_i to a stable reference source. The DTP operates on TCK for JTAG logic and on the system clock for cross-trigger and AXI bridges. Reset sequencing follows the SMC flow; the DTP JTAG state machine uses pwr_on_rst_ni, which the SMU connects to the SMC powergood_stable_o output. The SMU internally connects DTP debug paths to the SMC and optionally instantiates the SEP when CFG.SEP is set to 1. The full interconnection details are described in SMC-DTP Internal Interconnection and SEP-Conditional Wiring below.

3. SMU AXI Crossbar Address Map

Inside the SMU, the smu_axi_xbar module routes traffic between three AXI4 manager/subordinate pairs: the SEP outbound master (sep_out), the SMC outbound master (smc_out), and the external SMU AXI input (ext_in / smu_axi_in). The corresponding targets are the SEP and SMC inbound subordinates, and the external SMU AXI output (ext_out / smu_axi_out).

The SMU instantiates smu_axi_xbar only when CFG.SEP is 1. When CFG.SEP is 0, AXI ID-width converters connect the SMC system AXI ports to smu_axi_in / smu_axi_out instead: every SMC-initiated transaction leaves through smu_axi_out, every smu_axi_in transaction targets the SMC, and the aperture rules below do not apply. The smu_axi_in / smu_axi_out port types are the same in both configurations.

Connectivity is described in SMU AXI Crossbar; the split between hardware-fixed behavior and firmware-programmable apertures is documented in OCAH Memory Map.

The crossbar uses a runtime address map with two rules, the SEP and SMC apertures, both programmable at runtime. ext_out has no address rule. The apertures are driven as follows:

  • sep_global_base_addr_i / sep_region_size_i come from the sep_cpu_ctrl CSRs SEP_GLOBAL_BASE_ADDR / SEP_REGION_SIZE, exposed at the sep.sv boundary as sep_global_base_addr_o / sep_region_size_o, and at the smu.sv boundary as sep_global_base_o / sep_region_size_o (both 56-bit). SEP_REGION_SIZE is a 32-bit CSR field, zero-extended to 56-bit at the SEP system CSR; the xbar input takes only the lower 32 bits. SEP_REGION_SIZE defines the SEP global/chiplet aperture for SMU routing and SEP inbound global-to-local remap. It is distinct from the SEP CPU’s architectural local-alias span. SEP_REGION_SIZE currently resets to 0x0100_0000 (16 MiB). Tied to '0 at the smu.sv boundary when CFG.SEP is 0.

  • smc_global_base_addr_i / smc_region_size_i come from the smc_base_config CSRs GLOBAL_BASE / REGION_SIZE, exposed at both the smc.sv and smu.sv boundaries as smc_global_base_o (56-bit) / smc_region_size_o (32-bit). REGION_SIZE resets to 0x0100_0000 (16 MiB).

SEP, SMC, and smu_axi_xbar all run on clk_smu_i, so these quasi-static CSR fields need no clock-domain crossing. The crossbar’s address arithmetic is done on 57-bit widened sums. For where unmatched requests go, and which requests return DECERR, see SMU AXI crossbar routing.

3.1. Firmware programming order

Firmware must program SEP_GLOBAL_BASE_ADDR / SEP_REGION_SIZE and SMC GLOBAL_BASE / REGION_SIZE during early boot, before any cross-subsystem AXI traffic is issued, and must ensure the two apertures do not overlap and both fall within the chiplet-visible SMU envelope assigned by the integrator. The SMU crossbar does not itself constrain envelope size.

See OCAH Memory Map for the responsibility split between integrator, firmware, and the internal SEP/SMC address maps.

4. SMU Default Parameters

The DTP JTAG features, identification, cross trigger, and pipeline depths are fields of the CFG parameter, of type smu_pkg::smu_cfg_t. CFG defaults to the smu_pkg::SmuConfigs preset that the CFG_IDX parameter selects: smu_pkg::DefaultCfg at the default index 0, or smu_pkg::NoSepCfg, which differs only in SEP, at index 1. A CFG passed directly takes precedence over CFG_IDX. Flows that override parameters with elaborate -param, which cannot set a struct, select the preset through CFG_IDX.

The parameters of smu are listed in smu.

SEP-related DTP configuration has no smu_cfg_t field of its own. The SMU derives SEP debug/STAP enablement from CFG.SEP and wires the corresponding DTP interfaces internally to the SEP block when CFG.SEP=1.

5. IC_RESET TDR Structure

The DTP primary TAP implements the IEEE 1149.1-2013 §17 IC_RESET TDR as three independently enabled slices plus a single reset_hold bit nearest TDO. At the SMU the scan order from TDI to TDO is:

TDI → SMC slice → SEP slice → external slice → reset_hold → TDO

The SMU enables the SMC slice unconditionally, the SEP slice when CFG.SEP=1 (otherwise that slice has width 0 and is omitted), and the external slice when JTAG_IC_RESET_ENABLE is set. Each slice is a packed struct with .ovrd and .val halves of equal width; jtag_ptap sizes the slice from $bits(type)/2. Each port has the reset-enable and reset-control pair IEEE §17 requires, with reset_enable nearer TDO. .val carries reset_control, and .ovrd carries the inverse of reset_enable. Declaration order within each half is the TDI-to-TDO scan order: the first field is nearest TDI.

5.3. External slice (adopter-defined)

The external slice is reserved for reset overrides on logic instantiated outside the SMU. OCAH does not name its ports. Set the SMU type parameter ic_reset_ext_t to a packed struct with .ovrd and .val halves of equal width, and route jtag_ic_reset_ext_o to that logic. The parameter default (jtag_tap_pkg::jtag_ic_reset_default_t) is a single-override stub. Clear JTAG_IC_RESET_ENABLE when no external overrides are required.

Declare a new external override at each half’s MSB so already-assigned TDR positions do not shift. Extra subsystem reset controls beyond the SMC slice use this typed port.

The SMC uses pulse-synchronization mode, so ack signals for the reserved lanes are unused: the DTP xtrig_ctm_src_ack_i reserved slice is tied to '0 and xtrig_ctm_dst_ack_o reserved bits are left unconnected. The usage of ack signals depends on the XTRIG_INT_CT_MODE parameter: when a mode bit is 0 (pulse synchronization), the corresponding ack is unused; when 1 (req/ack handshaking), the ack must be connected to the cross trigger endpoint.
