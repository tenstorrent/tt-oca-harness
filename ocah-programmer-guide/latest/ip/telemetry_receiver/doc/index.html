Telemetry Receiver

1. Overview

The Telemetry Receiver decodes, buffers, and processes telemetry data from telemetry transmitters. It implements a receiver for a probe-ID and multi-counter message format.

1.1. Message Format

Eight little-endian ATB beats form a 64-bit packet. One or more packets form a message that ends when last_packet is set.

Telemetry packet fields defines the fields carried in each telemetry packet.

Table 1. Telemetry packet fields
Field Width Location

last_packet

1 bit

Bit 63 of each packet

probe_id

5 bits

Bits [60:56] of the first packet

block

9 bits

Seven per packet: 1-bit valid + 8-bit data

counter

32 bits

Four consecutive blocks, most-significant byte first

A counter is valid only when all four of its blocks are valid. The number of counters per message is parameterized (default 4); the field layout is fixed.

2. Description and Features

  • 32-bit APB4 or AXI4-Lite Register Interface: Standard bus interfaces for system integration and configuration access

  • 8-bit ATB Telemetry Interface: High-speed telemetry data reception with ATB protocol compliance

  • Configurable Circular Buffer: Programmable buffer depth (default 8 entries) with threshold-based monitoring

  • Multi-Counter Message Support: Decodes messages with probe ID and up to 4 counter values per message

  • Comprehensive Interrupt System: Event-driven notifications for buffer thresholds and error conditions

3. Architecture

The Telemetry Receiver leverages a dual-buffer design for robust and continuous telemetry data capture from an Advanced Trace Bus (ATB) source. Its architecture brings together configurable register interfaces, full ATB compliance, intelligent buffering, and efficient message processing—balancing narrative clarity with compact organization.

3.1. Functional Blocks

3.2. Register Interface Block

The register interface uses an AXI4-Lite bus for access to control, status, and data registers. Control registers handle buffer thresholds and interrupt enables for system optimization. Status registers provide real-time buffer occupancy and error flags. Data registers make probe ID and counter details accessible, while interrupt registers support selective and responsive event handling for seamless system integration.

3.3. ATB Interface Block

The ATB interface guarantees protocol-compliant 8-bit telemetry data reception using handshaked ready/valid flows, supporting industrial trace infrastructures. It manages per-source ID tracking for multi-source collection and delivers reliable operation under variable load, with flush signaling to mark stream boundaries and maintain session integrity.

3.4. Assembly Buffer

This buffer assembles streams of 8-bit ATB data into 64-bit packets. It ensures data ordering, detects packet boundaries, and supports little-endian (LSB-first) byte alignment. Temporary storage enables storage of successive packets. A last-packet flag or receiver flush resets the assembly write pointer but does not clear the stored bytes.

3.5. Message Decoder

Assembled packets are parsed for the probe ID and counters in the fixed layout in Message Format. Each 9-bit block is checked for validity, and last-packet boundaries mark the end of a message.

The decoder examines all configured counter positions, including positions beyond the last packet received. After a shorter message follows a longer one, trailing counter values and validity bits can therefore come from the earlier message. CTRL.TELEMETRY_RX_FLUSH does not remove this stale data. To avoid relying on those positions, producers must overwrite the complete configured message footprint and mark unused counter blocks invalid. Only reset clears the assembly storage.

3.6. Message Buffer

A circular message buffer persistently holds decoded messages. It offers configurable depth (2–N entries), FIFO access, threshold monitoring with interrupt generation, and full status reporting (occupancy, empty/full).

3.7. Data Flow

Reception Phase The ATB interface receives telemetry in 8-bit beats, accumulated into 64-bit packets in the assembly buffer, then validated for structure.

Decoding Phase Packets are parsed for headers (probe ID), broken into 9-bit blocks, counters are extracted and checked, and validity flags assigned.

Buffering Phase Decoded messages are stored FIFO-style; pointers, counters, and flags update atomically. Threshold or error interrupts are generated as needed.

Readout Phase Telemetry is accessed by software via register reads. Reads expose the oldest queued message without consuming it. Read the probe ID, validity bitmap, and required counters, then write CTRL.BUFFER_POP = 1 to advance to the next message. A pop while empty has no effect. When a new message arrives while the buffer is full, hardware drops the oldest entry and advances the read pointer; software must drain the buffer fast enough to avoid loss or a change of the visible message during a multi-register read.

3.8. Control Path

Configuration Control Software configures buffer thresholds, enables interrupts, and clears errors, permitting runtime adaptation and robust error handling.

Status Reporting Occupancy, availability, and error flags are accessible, providing up-to-date telemetry collection health.

Interrupt Handling Interrupts are generated for buffer threshold conditions and a missing last-packet flag. INTR_STATUS.MISSING_LAST is sticky and write-one-to-clear. INTR_STATUS.BUFFER_THRESHOLD is read-only and reflects occupancy strictly greater than CTRL.BUFFER_THRESHOLD (or an asserted threshold test bit). Drain the buffer, raise the threshold, or clear the test condition to remove that source; writing the status bit does not acknowledge it.

3.9. Clocking and Reset

Clock Domain The design operates fully synchronous on clk_i, avoiding clock crossing complexity and easing verification.

Reset Architecture An asynchronous reset (rst_ni), synchronously deasserted, clears the assembly storage and resets the buffer pointers. The message-buffer payload storage is not cleared; empty-buffer reads return zero. CTRL.TELEMETRY_RX_FLUSH discards queued messages and resets the assembly write pointer without clearing either payload store. It is not a data-erasure operation.

4. Interface

The Telemetry Receiver component provides AXI4-Lite register access and Advanced Trace Bus (ATB) telemetry data reception interfaces.

4.1. Configuration Parameters

The parameters and ports of telemetry_receiver are listed in telemetry_receiver.

The telemetry buffer dimensions are described as NUM_BUFFERS (default 2, a dual-buffer architecture), BUFFER_DEPTH (default 16 entries per buffer), ATB_DATA_WIDTH (default 8 bits), PACKET_WIDTH (default 64 bits), ADDR_WIDTH (default 32-bit register address) and DATA_WIDTH (default 32-bit data bus).

4.2. Signal Interfaces

4.3. Global Interface

The global interface provides fundamental clock and reset signals required for basic operation.

4.4. Clock and Reset Specifications

  • Clock Frequency: The component can operate at frequencies up to 200 MHz

  • Clock Jitter: Maximum 100ps peak-to-peak jitter tolerance

  • Reset Duration: Minimum 10 clock cycles for complete reset

  • Reset Recovery: Component ready for operation 2 clock cycles after reset deassertion

4.5. ATB Telemetry Interface

The ATB (Advanced Trace Bus) interface receives telemetry data using standard ATB protocol.

4.6. ATB Protocol Specifications

  • Data Width: 8 bits per beat

  • ID Width: 7 bits (128 unique trace sources)

  • Flow Control: Valid/ready handshaking for reliable data transfer

  • Flush Support: Bidirectional flush signaling for stream management

  • Back-pressure: Component can assert atready_o low to apply back-pressure

  • Latency: Zero-cycle latency when ready, immediate acceptance when atready_o is high

4.7. Interrupt Interface

The interrupt interface provides a single interrupt output for event notification.

4.8. Interrupt Specifications

  • Polarity: Active high (asserted when high)

  • Duration: Level-sensitive, remains asserted until cleared

  • Sources: Buffer threshold and error condition interrupts

  • Clearing: MISSING_LAST is write-one-to-clear. The read-only BUFFER_THRESHOLD source remains asserted while occupancy exceeds the configured threshold or its test bit is set; it cannot be cleared by writing status.

  • Latency: Interrupt assertion within 2 clock cycles of triggering condition

5. Memory Map

The Telemetry Receiver provides a comprehensive register interface for configuration, status monitoring, and telemetry data access. All registers are accessed through a 32-bit AXI4-Lite interface with 4-byte address alignment.

5.1. Address Space Overview

The component uses a 256-byte address space (8-bit address width) with the following organization:

  • Control and Status: 0x00 - 0x1F (Configuration, status, probe ID, and counter validity registers)

  • Counter Array: 0x80 - 0xFF (32 × 32-bit counter value registers)

5.2. Reset Behavior

Upon system reset (rst_ni assertion):

  • All registers reset to their default values as specified

  • Message buffer is cleared and marked empty (STATUS.BUFFER_EMPTY = 1)

  • All interrupts are cleared and disabled

  • Telemetry data registers reset to zero

  • Component enters idle state ready for telemetry reception

The reset operation is asynchronous for assertion and synchronous for deassertion, ensuring clean startup behavior and proper synchronization with the system clock domain.
