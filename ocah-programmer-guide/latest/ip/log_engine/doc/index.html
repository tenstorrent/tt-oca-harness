Log Engine

1. Overview

The OCA Log Engine is a DMA-based logging system that efficiently transfers log messages from a configured memory region to a UART interface. It provides a scalable solution for system-level logging with hardware acceleration, reducing CPU overhead for log transmission. The engine supports up to 16 independent log entries with fair round-robin arbitration, making it suitable for multi-threaded or multi-core logging scenarios.

2. Description and Features

The Log Engine features a multi-interface architecture, combining a 32-bit AXI4-Lite register interface with both 64-bit log fetch and 32-bit log write AXI4-Lite interfaces for efficient data movement. Its design scales to manage up to 16 independent log entries, each with flexible, configurable memory regions and 64-bit addressing.

Round-robin arbitration ensures fair scheduling among logs, and hardware integration with the UART transmitter—including flow control—streamlines log data output. Error conditions in log fetch or write operations are tracked via a comprehensive interrupt system for robust monitoring.

3. Architecture

3.1. Overview

The OCA Log Engine is a DMA-powered logging system that transfers log messages from memory to a UART interface. It supports up to 16 log entries with fair round-robin arbitration for efficient multi-source logging.

3.2. Functional Blocks

3.3. Control and Status Registers (CSRs)

CSRs, accessed via AXI4-Lite, configure the engine and report status. Key registers control global enable/disable (CTRL), region size/alignment (LOG_REGION_SIZE), 56-bit base address (LOG_REGION_ADDR), UART target (LOG_WRITE_ADDR), and per-log-entry control and length (LOG_CTRL[0:15]). Interrupt registers (INTR_STATUS/ENABLE/TEST) enable robust error detection and error recovery.

3.4. Round Robin Arbiter

A prim_arbiter_tree-based round robin arbiter ensures fair, starvation-free access to DMA for all 16 log entries. It systematically selects among entries with non-zero lengths, preventing monopolization and balancing throughput regardless of data rates across logs. Tight integration with the fetch FSM ensures smooth flow.

3.5. Log Fetch FSM

The fetch FSM coordinates DMA reads based on arbitration results and FIFO space. It cycles through idle, request, and wait states: checking for ready entries and FIFO space, issuing AXI4-Lite read requests, and handling responses with word counters. Addresses are computed as log_region_addr + (log_region_size/16) * log_index + word_offset, supporting efficient, aligned memory access. Progress tracking and FIFO handoff ensure reliable completion and seamless operation.

3.6. RDATA FIFO

A configurable-depth (default 4), synchronous 64-bit FIFO decouples memory reads from UART writes, smoothing timing mismatches. All-zero outputs when empty help security. Ready/valid handshakes on both sides ensure safe, lossless transfer through variable system conditions.

3.7. Log Write FSM

This FSM manages conversion from 64-bit log words to 8-bit UART writes. It only advances when UART is ready and FIFO data is available, sequencing through idle, request, and wait states. Byte pointers extract one byte at a time; FIFO is accessed every eight bytes. A completion signal updates registers, enabling accurate monitoring and coordination.

3.8. Data Flow and Control Path

3.9. Data Flow

  1. Software configures memory region, UART address, and enables engine.

  2. Non-zero LOG_CTRL[i] length triggers log transfer.

  3. Arbiter selects a log entry.

  4. Fetch FSM performs memory reads.

  5. Data is buffered in RDATA FIFO.

  6. Write FSM sends bytes to UART.

  7. Transfer completion clears the length register.

3.10. Control Path

  • Global enable gates operation.

  • Fetch/write FSMs are coordinated via FIFO ready/valid signals.

  • AXI4-Lite errors trigger interrupts.

  • Completion updates registers and advances arbitration.

3.11. Clocking and Reset Methodology

The engine runs in one clock domain (clk_i) shared by all logic and AXI4-Lite interfaces.

  • Reset (rst_ni) is active-low async, sync deassertion.

  • Global reset clears FSMs, counters, and logic.

  • FIFO can be cleared independently when the engine is disabled.

  • On reset: FSMs idle, counters zeroed, FIFO flushed, registers preserved (except control fields).

3.12. Memory Interface Protocol

Log Fetch: 64-bit AXI4-Lite read, single-beat transfers, errors signaled via LOG_FETCH_ERR.

Log Write: 32-bit AXI4-Lite write, single byte accesses using strobes, errors signaled via LOG_WRITE_ERR.

3.13. Performance Characteristics

  • Fetch Bandwidth: Limited by AXI4-Lite single transfers.

  • Write Throughput: Determined by UART ready signal.

  • Latency: Minimal, due to light buffering.

  • Fairness: Maintained by round-robin selection.

3.14. Design Trade-offs

  • Memory Simplicity vs. Efficiency: Fixed equal partitioning eases logic at expense of flexibility.

  • Throughput vs. Area: Single-beat transfers are simple but limit bandwidth; FIFO depth is tunable.

  • Robustness vs. Complexity: Comprehensive error checking improves reliability at increased logic cost.

5. Memory Map

5.1. Overview

The Log Engine provides a comprehensive register interface for configuration, control, and status monitoring. All registers are accessible via a 32-bit AXI4-Lite interface and follow standard read/write access patterns. The register map is organized into logical groups for ease of use and programming.

6. Programming

6.1. Simple Log Transfer

// Initialize log engine for 4KB region at 0x10000000
// UART at 0x40001000

#define LOG_ENGINE_BASE 0x50000000
#define LOG_REGION_ADDR 0x10000000
#define LOG_REGION_SIZE 0x1000
#define UART_TX_ADDR    0x40001000

// Disable and configure
write32(LOG_ENGINE_BASE + 0x00, 0);          // Disable
write32(LOG_ENGINE_BASE + 0x04, LOG_REGION_SIZE);
write32(LOG_ENGINE_BASE + 0x08, LOG_REGION_ADDR);
write32(LOG_ENGINE_BASE + 0x0C, 0);          // High address
write32(LOG_ENGINE_BASE + 0x10, UART_TX_ADDR);
write32(LOG_ENGINE_BASE + 0x18, 0x11);       // Enable error interrupts
write32(LOG_ENGINE_BASE + 0x00, 1);          // Enable

// Send 100-byte log via entry 0
write32(LOG_ENGINE_BASE + 0x40, 100);

// Wait for completion
while (read32(LOG_ENGINE_BASE + 0x40) != 0);

6.2. Multiple Entry Management

// Send logs via multiple entries simultaneously
write32(LOG_ENGINE_BASE + 0x40, 50);   // Entry 0: 50 bytes
write32(LOG_ENGINE_BASE + 0x44, 75);   // Entry 1: 75 bytes
write32(LOG_ENGINE_BASE + 0x48, 120);  // Entry 2: 120 bytes

// Check completion status
for (int i = 0; i < 3; i++) {
    uint32_t len = read32(LOG_ENGINE_BASE + 0x40 + (i * 4));
    if (len == 0) {
        printf("Entry %d completed\n", i);
    } else {
        printf("Entry %d: %d bytes remaining\n", i, len);
    }
}
