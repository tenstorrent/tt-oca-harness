Memory Map and Register Reference

1. Memory Map

This section provides a comprehensive overview of the SMC memory map. The SMC address space is organized to provide access to various functional units including CPU control, peripheral interfaces, system management functions, and fabric control mechanisms.

All addresses below are expressed as BASE + offset, where BASE can be either the local alias (LOCAL_BASE, fixed read-only at 0xC000_0000) or the global system address (GLOBAL_BASE, programmable by firmware). The fabric routes transactions to SMC resources identically regardless of which base is used, as long as the access falls inside the relevant local or global aperture. Both apertures are sized by the SMC REGION_SIZE CSR, which resets to 16 MiB and may be reprogrammed by firmware. Address ranges include both endpoints. Addresses are 32-bit aligned and follow standard AXI4-Lite addressing conventions. For details on how LOCAL_BASE and GLOBAL_BASE relate and how an adopter maps this aperture into the system address space, refer to the SMC Address Map Integration section of the Integration Guide.

The last two columns state how the SMC answers a 32-bit access that no register or memory backs, as seen at its inbound AXI port, and Decode Response Codes defines them and their codes.

An address between unit apertures reaches no unit. A read there answers DECERR with data 0xBADCAB1E, and a write answers DECERR, except from BASE + 0x001_7000 through BASE + 0x001_7FFF, where it answers SLVERR.

An address inside neither the local nor the global aperture answers DECERR to reads and writes. The M-mode and Xvisor remap regions forward accesses from SMC initiators only; an access to them from the inbound port answers DECERR.

The inbound port reaches a unit only while its whole aperture lies below BASE + REGION_SIZE. At the reset value the PLIC, CLINT and bus-error units lie beyond it and answer DECERR. The SMC harts reach the PLIC and CLINT inside the CPU cluster regardless of REGION_SIZE.

The I2C, UART, I3C, AVSBus and Telemetry Receiver windows answer SLVERR, with read data 0xBADCAB1E, while the peripheral’s CLOCK_GATE_CONTROL enable in SMC_BASE_CONFIG is set and its clock is stopped.

1.2. AXI-Lite External Window

The smc_external window at BASE + 0x040_0000 is the adopter extension window. OCAH exposes this AXI-Lite bus so an adopter can attach their own technology- and vendor-specific implementations of memory-mapped blocks. The window is split into two regions (see smc_external.rdl). Apart from the eFuse SHIM control block described below, hardware treats both identically; the split is purely organizational:

  • Mandatory (BASE + 0x040_0000): blocks every integration must implement. Their function is dictated by the OCAH specifications, but their implementation is inherently technology- and vendor-specific — the eFuse SHIM, the per-pad GPIO controls, the PLL wrapper and the strap registers at BASE + 0x040_3000.

  • Supplementary (BASE + 0x040_4000): any additional memory-mapped devices the adopter wants to expose, such as peripheral controllers, extra pad controls and the PVT wrapper.

The generated SMC map reports this as one opaque adopter-owned aperture. Concrete placements inside it are integration-specific and are documented by the adopter. The strap registers are read-only values consumed by boot firmware; how the adopter captures them is implementation-defined. Both boot ROMs read them at BASE + 0x040_3000, so an integration places them there.

The eFuse SHIM control block is the exception. Its placement is fixed at the base of the window, BASE + 0x040_0000, and its size is the EFUSE_SHIM_SIZE parameter (CFG.SMC_EFUSE_SHIM_SIZE at the SMU). The peripheral crossbar routes that range to the eFuse controller, which forwards it unchanged on efuse_bank_ctrl to the adopter’s SHIM. It never appears on the external port. The adopter defines the SHIM’s control registers at offset 0x0 of its own smc_external map.

The supplementary (optional) region of the window is passed through to the SMU’s smc_external_req_o / smc_external_resp_i ports for adopter integration. The adopter may implement any memory-mapped functions there, or may instead terminate the region with an error response. The reference integration (hw/top/smc_ip_integration.sv) terminates unclaimed accesses in this region with a DECERR response via the prim_axi_lite_err_slv helper; this is one integration choice, not a requirement.

BitsFieldAccessResetDescription
31:20Reserved--Reserved
19:0valueRW0x1000Threshold in clock cycles. Default 0x1000. 20 bits => up to ~1M cycles (~1ms at 1GHz). 0 disables timeout detection: a stalled bus never asserts irq_o, though irq_test still asserts it.
