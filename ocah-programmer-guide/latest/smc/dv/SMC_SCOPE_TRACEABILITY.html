1. SMC scope and traceability

This chapter is the requirement-to-test-to-coverage matrix. Live group membership is hw/sys/smc/dv/testlists/all.toml and the lists it includes; hw/sys/smc/dv/docs/SMC_VPLAN.adoc states what each testcase verifies. This file is the reconciliation between the two — which of those testcases count as feature credit, and which are bring-up or decode-only names that must not be counted twice.

1.1. Live groups versus credit

Executable membership is resolved from the testlists; the groups and their expected_count guards are in hw/sys/smc/dv/testlists/all.toml:

Group Role

smoke

PR gate (sim.yml): canonical bring-up, cold reset, and a CSR frontdoor read

hosted

Nightly and weekly (regress.yml): all minus the seventeen leaves that need the RISC-V toolchain (fourteen fw leaves, three dual-target leaves that run a ROM or firmware image)

rtl_issue

Weekly on its own regress.yml row: defect reproducers graded under expect_fail; no feature credit

per_ip

One pass across every IP the bench drives

all

The package regression; all.toml names the leaves outside it and why, and SMC_DEFERRED_DISPOSITION.adoc records the leaves no scheduled tier runs

functional

One name per functional bucket; mixes SAMPLE bring-up with feature rows

smoke is the three-leaf PR gate (smc_canonical_smoke_test, smc_cold_reset_test, smc_register_sanity_test). smc_i3c_to_fabric_test is in neither smoke nor functional and receives no feature credit.

1.2. Credit rules

  • Feature credit requires active CSR/fabric/pin stimulus and a non-vacuous SmcScoreboard count. SAMPLE-only bring-up stays in functional (smc_cold_reset_test is also in smoke) and is not a requirement row.

  • smc_i3c_to_fabric_test is HCI_VERSION decode (proxy=True). It remains runnable via i3c_depth / per_ip / by name. It is not stub-signature SLVERR, and it is not I3C protocol credit.

  • Names in SMC_DEFERRED_DISPOSITION.adoc, adopter PLL/PVT OKAY+0 wraps, and TB-glue DFD tokens are OUT.

  • UART loopback / ROM firmware stay on their existing intake issues. They are not re-scoped here.

  • --dut smc already instantiates smc_wrapper. There is no separate wrapper.toml and no test named main_wrapper or main_wrapper_por. Bring-up / POR successors are smc_canonical_smoke_test and the reset cluster (smc_cold_reset_test, smc_powergood_glitch_test, smc_multi_reset_csr_persistence_test).

1.3. Matrix (feature-credit subset)

Requirement IDs are the VPLAN TC rows or the canonical scenario those tests actually run. Coverage bins are the hw/sys/smc/dv/docs/SMC_FCOV.adoc families the scoreboard can hit; Verilator does not close SV covergroups.

The Groups column is resolved membership, not intent. Every feature-credit row below is in all and hosted, and every one but smc_cpu_to_sep_axi_test is also in per_ip; the column names the narrower groups that also carry it, so a reviewer can run one feature without the whole regression.
