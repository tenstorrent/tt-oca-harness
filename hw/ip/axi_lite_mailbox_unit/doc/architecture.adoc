[[mailbox-unit-architecture]]
== Architecture

The Mailbox IP provides inter-processor and inter-chiplet communication
through a register-based interface. A single AXI4-Lite slave port is demuxed
into one register aperture per mailbox direction, and each mailbox pair owns
the two FIFOs that carry data between its two apertures.

=== Address Space

The architecture supports up to 64 mailbox instances (32 bidirectional
pairs):

* *Total Space*: 2 × `MAILBOX_SIZE` × `NUM_MAILBOXES`, 
decoded from a port that is `ADDR_WIDTH` bits wide
* *Data Width*: 64 bits
* *Per-Aperture Space*: 0x800 bytes (2KB)
* *Decoding*: Address bits above `$clog2(MAILBOX_SIZE)` select one of
`2 × NUM_MAILBOXES` apertures

The 64-bit data width handles addresses, data payloads and status
information without multi-word transfers. The 2KB allocation per aperture
leaves the ten registers sparsely mapped; offsets above the register map are
unmapped rather than aliased.

=== Internal Structure

The unit is an `axi_lite_demux` in front of `NUM_MAILBOXES` mailbox instances.
Each mailbox instance has two AXI4-Lite slave ports, one per aperture, and
holds two message FIFOs of `MAILBOX_DEPTH` entries each. The FIFOs are
cross-coupled between the two ports: the push side of one port is the pop side
of the other. The FIFOs are internal to the IP; there is no external FIFO
interface.

=== Transaction Processing

AXI4-Lite transactions follow this flow:

1.  *Aperture Decode*: The demux selects an aperture from the address bits
above `$clog2(MAILBOX_SIZE)`, relative to `MAILBOX_BASE_ADDR`
2.  *Register Decode*: The mailbox slave port decodes the offset within the
aperture into one of the ten registers
3.  *FIFO Access*: `WRITE_DATA` pushes the port's write FIFO, `READ_DATA` pops
the port's read FIFO; full and empty conditions set the error flags described
in the Error Handling table
4.  *Response*: The B and R responses are emitted through spill registers,
giving one cycle of latency and keeping the response path free of
combinational paths from the request

=== Bidirectional Communication

Each mailbox pair provides two register apertures, conventionally used as an
outbound and an inbound direction. The two are not independent storage: they
share the same pair of FIFOs, so `WRITE_DATA` in one aperture is what
`READ_DATA` in the other aperture returns. Both apertures hang off the same
AXI4-Lite slave port, so a local agent can drive either end; the direction
naming reflects intended use, not an access restriction.

Separate apertures give each direction its own thresholds, status, error flags
and interrupt output.

=== Clock and Reset

The mailbox uses a single clock domain for integration reliability.

No internal clock domain crossings eliminates CDC complexity. Single
clock domain simplifies timing analysis and integration verification.

=== Interrupt Architecture

The mailbox provides independent interrupt outputs for each mailbox
instance:

* `inbound_interrupt_o[NUM_MAILBOXES-1:0]`: Inbound communication events
* `outbound_interrupt_o[NUM_MAILBOXES-1:0]`: Outbound communication
events

Separate inbound/outbound interrupts reflect different processing
requirements. Inbound interrupts indicate incoming commands requiring
immediate processing; outbound interrupts indicate successful
transmission or buffer availability.

<<mailbox-interrupt-sources-table>> reports the interrupt sources.

[[mailbox-interrupt-sources-table]]
[width="100%",cols="30%,70%",options="header",]
.Mailbox interrupt sources
|=======================================================================
|Source |Description
|Write Threshold |FIFO fill level exceeds configured threshold
(proactive buffer management)

|Read Threshold |FIFO data available for efficient retrieval scheduling

|Access Error |Write to full FIFO or read from empty FIFO; both set the same
error interrupt bit (fault detection)
|=======================================================================

Each interrupt output aggregates these sources and is level-triggered and
active high. Threshold-based interrupts reduce polling overhead; error
interrupts enable fault recovery and diagnostic analysis.
