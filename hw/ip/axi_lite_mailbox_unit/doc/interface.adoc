[cols="2,3",options="header"]
.Mailbox port groups
|===
|Ports |Contract
|`mailbox_axi_req_i`, `mailbox_axi_resp_o` |One AXI4-Lite slave for all apertures;
address/data widths and channel/aggregate struct types are elaboration parameters.
|`inbound_interrupt_o`, `outbound_interrupt_o` |`NUM_MAILBOXES` active-high level
interrupts in each vector, one per aperture.
|`clk_i`, `rst_ni`, `test_en_i` |Clock, active-low asynchronous reset and test input.
|===

The per-aperture B and R responses pass through spill registers. Request
arbitration, arrival of both write channels, and response backpressure also
affect observed latency; software must not assume a fixed completion cycle.
Reads and writes use separate AXI4-Lite channels but operate on the same FIFO
and status state.

[[mailbox-error-handling-table]]
[cols="2,3",options="header"]
.Mailbox access results
|===
|Access |Result
|Read `READ_DATA` while empty |`SLVERR`, data `0xFEEDDEAD`; sets the read-error
flag and `IRQS[2]`.
|Write `WRITE_DATA` while full |`SLVERR`; data discarded; sets the write-error
flag and `IRQS[2]`.
|Read write-only `WRITE_DATA` |`OKAY`, data `0xFEEDC0DE`; no FIFO access or error flag.
|Write `READ_DATA`, `STATUS`, `ERROR_FLAGS` or `IRQP` |Ignored with `SLVERR`.
|Unmapped register offset in an aperture |`SLVERR`; reads return zero, writes ignored.
For the 64-bit map, offsets `0x50` and above are unmapped.
|Read `ERROR_FLAGS` |Returns and clears both detailed error flags. A new error
in the same cycle is retained.
|Write `CTRL` flush bits |Pulses the selected FIFO flush; the bits are not stored
configuration and read back as zero.
|===

=== Sending and Receiving

++++

. Assign one software producer and consumer per direction, or serialize shared
  access. The register interface does not allocate FIFO ownership to clients.
. Before sending, check the aperture's write-full status, then write `WRITE_DATA`.
  Handle `SLVERR` if another writer consumed the space in between.
. Before receiving, check read-empty status, then read `READ_DATA`. Each successful
  read consumes one word; status and data accesses are not one atomic operation.
. Read `ERROR_FLAGS` once to capture any access errors, then separately acknowledge
  `IRQS[2]` if interrupt status was set. Avoid diagnostic reads that unintentionally
  consume data or clear error information.

To receive an interrupt for any available data, program `RIRQT=0`, service or
acknowledge old status, and enable `IRQEN[1]`. Drain received words before
acknowledging `IRQS[1]`; a remaining live condition can set it again. Coordinate
FIFO flushes with the peer because a flush discards words already queued for it.
