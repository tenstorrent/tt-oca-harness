[[gpio-interface]]
== Interface

The tables distinguish the per-pad controller from its shim. Pad count and
padring address allocation belong to the enclosing subsystem. The modules
shown here expose AXI4-Lite; they do not contain an APB port.

The SMC integration defines 65 GPIO wrappers: 61 bonded pads and four
unbonded pads (`smc_pkg::NUM_BONDED_GPIO` and `NUM_UNBONDED_GPIO`).
These are subsystem constants, not `NUM_GPIO` or `BUS_PROTOCOL` parameters
of the per-pad controller. Address and data widths are both 32 bits.

[[gpio-configuration-parameters-table]]
[cols="2,1,4",options="header"]
.GPIO controller parameters
|===
|Parameter |Default |Meaning
|`MAX_TRANS` |32 |Outstanding-transaction limit passed to the access-filter demux.
|`INPUT_BY_DEFAULT` |1 |Enable RX when cold reset or the default path owns the pad.
|`GPIO_INTF_REG_MAP_SIZE` |0 |Integration must supply the aperture size;
its logarithm sets the register-address slice width.
|===

`gpio_pkg` defines 32-bit addresses and data. The shim has three parameters:
`INPUT_BY_DEFAULT = 1`, `ENABLE_PULL = 0`, and `USE_PULL_UP = 0`.
These select strap capture and the default electrical settings.

[cols="2,4",options="header"]
.Shim pad and override interface
|===
|Signals |Meaning
|`gpio_in_i`, `gpio_out_o`, `gpio_in_en_o`, `gpio_out_en_o`
|Pad data and active-high RX/TX enables.
|`gpio_ctrl_o`, `gpio_status_i`
|Pad-control and status bundles defined by `gpio_shim_pkg`. The current shim does not use `gpio_status_i`.
|`core2pad_ovrd_i`, `core2pad_en_ovrd_i`, `pad2core_en_ovrd_i`, `pad2core_ovrd_o`
|Secondary-function data, active-high direction controls and input return.
|`force_primary_i` |Suppresses the secondary-function override while asserted.
|`ext_intf_sel_i`, `reg_lsio_sel_i`, `reg_lsio_disable_i`
|Hardware request, software request and disable controls for electrical-setting ownership.
|`ext_drive_strength_i`, `ext_pull_en_i`, `ext_pull_sel_i`, `ext_gf_disable_i`
|LSIO electrical settings: 3-bit drive strength, pull enable, pull direction
(0 down, 1 up), and active-high input-conditioning disable.
|===

Data and direction muxes are combinational. This does not guarantee a
glitch-free handover or a pad settling time; coordinate ownership changes
with the connected peripheral and external driver.
