[[ctrl-register]]
CTRL register
^^^^^^^^^^^^^

* Absolute Address: 0x10
* Base Offset: 0x10
* Size: 0x4

Control Register

[cols=",,,,",options="header",]
|=====================================
|Bits |Identifier |Access |Reset |Name
|7:0 |RX_WATERMARK |rw |0x7F |—
|15:8 |TX_WATERMARK |rw |0x0 |—
|29 |OUTPUT_EN |rw |0x0 |—
|30 |SW_RST |w |0x0 |—
|31 |SPIEN |rw |0x0 |—
|=====================================

[[rx_watermark-field]]
RX_WATERMARK field
++++++++++++++++++

If !!EVENT_ENABLE.RXWM is set, the IP will send an interrupt when the
depth of the RX FIFO reaches RX_WATERMARK words (32b each).

[[tx_watermark-field]]
TX_WATERMARK field
++++++++++++++++++

If !!EVENT_ENABLE.TXWM is set, the IP will send an interrupt when the
depth of the TX FIFO drops below TX_WATERMARK words (32b each).

[[output_en-field]]
OUTPUT_EN field
+++++++++++++++

Enable the SPI host output buffers for the sck, csb, and sd lines. This
allows the SPI_HOST IP to connect to the same bus as other SPI
controllers without interference.

[[sw_rst-field]]
SW_RST field
++++++++++++

Clears the entire IP to the reset state when set to 1, including the
FIFOs, the CDC’s, the core state machine and the shift register. In the
current implementation, the CDC FIFOs are drained not reset. Therefore
software must confirm that both FIFO’s empty before releasing the IP
from reset.

[[spien-field]]
SPIEN field
+++++++++++

Enables the SPI Controller. On reset, this field is 0, meaning that no
transactions can proceed.

[[txqd-field]]
TXQD field
++++++++++

Transmit queue depth. Indicates how many unsent 32-bit words are
currently in the TX FIFO. When active, this result may be an
overestimate due to synchronization delays.

[[rxqd-field]]
RXQD field
++++++++++

Receive queue depth. Indicates how many unread 32-bit words are
currently in the RX FIFO. When active, this result may an underestimate
due to synchronization delays.

[[cmdqd-field]]
CMDQD field
+++++++++++

Command queue depth. Indicates how many unread 32-bit words are
currently in the command segment queue.

[[rxwm-field]]
RXWM field
++++++++++

If high, the number of 32-bits in the RX FIFO now exceeds the
!!CONTROL.RX_WATERMARK entries (32b each).

[[byteorder-field]]
BYTEORDER field
+++++++++++++++

The value of the ByteOrder parameter, provided so that firmware can
confirm proper IP configuration.

[[rxstall-field]]
RXSTALL field
+++++++++++++

If high, signifies that an ongoing transaction has stalled due to lack
of available space in the RX FIFO

[[rxempty-field]]
RXEMPTY field
+++++++++++++

When high, indicates that the receive fifo is empty. Any reads from RX
FIFO will cause an error interrupt.

[[rxfull-field]]
RXFULL field
++++++++++++

When high, indicates that the receive fifo is full. Any ongoing
transactions will stall until firmware reads some data from !!RXDATA.

[[txwm-field]]
TXWM field
++++++++++

If high, the amount of data in the TX FIFO has fallen below the level of
!!CONTROL.TX_WATERMARK words (32b each).

[[txstall-field]]
TXSTALL field
+++++++++++++

If high, signifies that an ongoing transaction has stalled due to lack
of data in the TX FIFO

[[txempty-field]]
TXEMPTY field
+++++++++++++

When high, indicates that the transmit data fifo is empty.

[[txfull-field]]
TXFULL field
++++++++++++

When high, indicates that the transmit data fifo is full. Any further
writes to !!RXDATA will create an error interrupt.

[[active-field]]
ACTIVE field
++++++++++++

When high, indicates the SPI host is processing a previously issued
command.

[[ready-field]]
READY field
+++++++++++

When high, indicates the SPI host is ready to receive commands. Writing
to COMMAND when READY is low is an error, and will trigger an interrupt.

[[cfg-register]]
CFG register
^^^^^^^^^^^^

* Absolute Address: 0x18
* Base Offset: 0x18
* Size: 0x4

Configuration Register

[cols=",,,,",options="header",]
|=====================================
|Bits |Identifier |Access |Reset |Name
|15:0 |CLKDIV |rw |0x0 |—
|19:16 |CSNIDLE |rw |0x0 |—
|23:20 |CSNTRAIL |rw |0x0 |—
|27:24 |CSNLEAD |rw |0x0 |—
|29 |FULLCYC |rw |0x0 |—
|30 |CPHA |rw |0x0 |—
|31 |CPOL |rw |0x0 |—
|=====================================

[[clkdiv-field]]
CLKDIV field
++++++++++++

Core clock divider. Slows down subsequent SPI transactions by a factor
of (CLKDIV+1) relative to the core clock frequency. The period of sck,
T(sck) then becomes 2__(CLK_DIV+1)__T(core)

[[csnidle-field]]
CSNIDLE field
+++++++++++++

Minimum idle time between commands. Indicates the minimum number of sck
half-cycles to hold cs_n high between commands. Setting this register to
zero creates a minimally-wide CS_N-high pulse of one-half sck cycle.

[[csntrail-field]]
CSNTRAIL field
++++++++++++++

CS_N Trailing Time. Indicates the number of half sck cycles, CSNTRAIL+1,
to leave between last edge of sck and the rising edge of cs_n. Setting
this register to zero corresponds to the minimum delay of one-half sck
cycle.

[[csnlead-field]]
CSNLEAD field
+++++++++++++

CS_N Leading Time. Indicates the number of half sck cycles, CSNLEAD+1,
to leave between the falling edge of cs_n and the first edge of sck.
Setting this register to zero corresponds to the minimum delay of
one-half sck cycle

[[fullcyc-field]]
FULLCYC field
+++++++++++++

Full cycle. Modifies the CPHA sampling behaviour to allow for longer
device logic setup times. Rather than sampling the SD bus a half cycle
after shifting out data, the data is sampled a full cycle after shifting
data out. This means that if CPHA = 0, data is shifted out on the
trailing edge, and sampled a full cycle later. If CPHA = 1, data is
shifted and sampled with the trailing edge, also separated by a full
cycle.

[[cpha-field]]
CPHA field
++++++++++

The phase of the sck clock signal relative to the data. When CPHA = 0,
the data changes on the trailing edge of sck and is typically sampled on
the leading edge. Conversely if CPHA = 1 high, data lines change on the
leading edge of sck and are typically sampled on the trailing edge. CPHA
should be chosen to match the phase of the selected device. The sampling
behavior is modified by the !!CONFIGOPTS.FULLCYC bit.

[[cpol-field]]
CPOL field
++++++++++

The polarity of the sck clock signal. When CPOL is 0, sck is low when
idle, and emits high pulses. When CPOL is low, sck is high when idle,
and emits a series of low pulses.

[[cmd-register]]
CMD register
^^^^^^^^^^^^

* Absolute Address: 0x20
* Base Offset: 0x20
* Size: 0x4

Command Register

[cols=",,,,",options="header",]
|=====================================
|Bits |Identifier |Access |Reset |Name
|8:0 |LEN |w, wuser |0x0 |—
|9 |CSAAT |w |0x0 |—
|11:10 |SPEED |w |0x0 |—
|13:12 |DIRECTION |w |0x0 |—
|=====================================

[[len-field]]
LEN field
+++++++++

Segment Length.

For read or write segments, this field controls the number of 1-byte
bursts to transmit and or receive in this command segment. The number of
cyles required to send or received a byte will depend on
!!COMMAND.SPEED. For dummy segments, (!!COMMAND.DIRECTION == 0), this
register controls the number of dummy cycles to issue. The number of
bytes (or dummy cycles) in the segment will be equal to !!COMMAND.LEN +
1.

[[csaat-field]]
CSAAT field
+++++++++++

Chip select active after transaction. If CSAAT = 0, the chip select line
is raised immediately at the end of the command segment. If
!!COMMAND.CSAAT = 1, the chip select line is left low at the end of the
current transaction segment. This allows the creation longer, more
complete SPI transactions, consisting of several separate segments for
issuing instructions, pausing for dummy cycles, and transmitting or
receiving data from the device.

[[speed-field]]
SPEED field
+++++++++++

The speed for this command segment: ``0'' = Standard SPI. ``1'' = Dual
SPI. ``2''=Quad SPI, ``3'': RESERVED.

[[direction-field]]
DIRECTION field
+++++++++++++++

The direction for the following command: ``0'' = Dummy cycles (no
TX/RX). ``1'' = Rx only, ``2'' = Tx only, ``3'' = Bidirectional Tx/Rx
(Standard SPI mode only).

ERROR_ENABLE register

[cols=",,,,",options="header",]

|=====================================

[[cmdbusy-field]]
CMDBUSY field
+++++++++++++

Command Error: If this bit is set, the block sends an error interrupt
whenever a command is issued while busy (i.e. a 1 is when !!STATUS.READY
is not asserted.)

[[overflow-field]]
OVERFLOW field
++++++++++++++

Overflow Errors: If this bit is set, the block sends an error interrupt
whenever the TX FIFO overflows.

[[underflow-field]]
UNDERFLOW field
+++++++++++++++

Underflow Errors: If this bit is set, the block sends an error interrupt
whenever there is a read from !!RXDATA but the RX FIFO is empty.

[[cmdinval-field]]
CMDINVAL field
++++++++++++++

Invalid Command Errors: If this bit is set, the block sends an error
interrupt whenever a command is sent with invalid values for
!!COMMAND.SPEED or !!COMMAND.DIRECTION.

[[csidinval-field]]
CSIDINVAL field
+++++++++++++++

Invalid CSID: If this bit is set, the block sends an error interrupt
whenever a command is submitted, but CSID exceeds NumCS.

[[cmdbusy-field-1]]
CMDBUSY field
+++++++++++++

Indicates a write to !!COMMAND when !!STATUS.READY = 0.

[[overflow-field-1]]
OVERFLOW field
++++++++++++++

Indicates that firmware has overflowed the TX FIFO

[[underflow-field-1]]
UNDERFLOW field
+++++++++++++++

Indicates that firmware has attempted to read from !!RXDATA when the RX
FIFO is empty.

[[cmdinval-field-1]]
CMDINVAL field
++++++++++++++

Indicates an invalid command segment, meaning either an invalid value of
!!COMMAND.SPEED or a request for bidirectional data transfer at dual or
quad speed

[[csidinval-field-1]]
CSIDINVAL field
+++++++++++++++

Indicates a command was attempted with an invalid value for !!CSID.

[[accessinval-field]]
ACCESSINVAL field
+++++++++++++++++

Indicates that TLUL attempted to write to TXDATA with no bytes enabled.
Such `zero byte' writes are not supported.

[[rxfull-field-1]]
RXFULL field
++++++++++++

Assert to send a spi_event interrupt whenever !!STATUS.RXFULL goes high

[[txempty-field-1]]
TXEMPTY field
+++++++++++++

Assert to send a spi_event interrupt whenever !!STATUS.TXEMPTY goes high

[[rxwm-field-1]]
RXWM field
++++++++++

Assert to send a spi_event interrupt whenever the number of 32-bit words
in the RX FIFO is greater than !!CONTROL.RX_WATERMARK. To prevent the
reassertion of this interrupt, read more data from the RX FIFO, or
increase !!CONTROL.RX_WATERMARK.

[[txwm-field-1]]
TXWM field
++++++++++

Assert to send a spi_event interrupt whenever the number of 32-bit words
in the TX FIFO is less than !!CONTROL.TX_WATERMARK. To prevent the
reassertion of this interrupt add more data to the TX FIFO, or reduce
!!CONTROL.TX_WATERMARK.

[[ready-field-1]]
READY field
+++++++++++

Assert to send a spi_event interrupt whenever !!STATUS.READY goes high

[[idle-field]]
IDLE field
++++++++++

Assert to send a spi_event interrupt whenever !!STATUS.ACTIVE goes low
