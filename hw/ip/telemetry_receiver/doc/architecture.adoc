[[telemetry-receiver-architecture]]
== Architecture

The Telemetry Receiver leverages a dual-buffer design for robust and
continuous telemetry data capture from an Advanced Trace Bus (ATB) source.
Its architecture brings together configurable register interfaces, full
ATB compliance, intelligent buffering, and efficient message
processing—balancing narrative clarity with compact organization.

=== Functional Blocks

=== Register Interface Block

The register interface uses an AXI4-Lite bus for access to control,
status, and data registers. Control registers handle buffer thresholds
and interrupt enables for system optimization. Status registers provide
real-time buffer occupancy and error flags. Data registers make probe ID
and counter details accessible, while interrupt registers support
selective and responsive event handling for seamless system integration.

=== ATB Interface Block

The ATB interface guarantees protocol-compliant 8-bit telemetry data
reception using handshaked ready/valid flows, supporting industrial
trace infrastructures. It manages per-source ID tracking for
multi-source collection and delivers reliable operation under variable
load, with flush signaling to mark stream boundaries and maintain
session integrity.

=== Assembly Buffer

This buffer assembles streams of 8-bit ATB data into 64-bit packets. It
ensures data ordering, detects packet boundaries, and supports
little-endian (LSB-first) byte alignment. Temporary storage enables
storage of successive packets. A last-packet flag or receiver flush resets the
assembly write pointer but does not clear the stored bytes.

=== Message Decoder

Assembled packets are parsed for the probe ID and counters in the fixed
layout in <<telemetry-receiver-message-format>>. Each 9-bit block is
checked for validity, and last-packet boundaries mark the end of a
message.

IMPORTANT: The decoder examines all configured counter positions, including
positions beyond the last packet received. After a shorter message follows a
longer one, trailing counter values and validity bits can therefore come from
the earlier message. `CTRL.TELEMETRY_RX_FLUSH` does not remove this stale data.
To avoid relying on those positions, producers must overwrite the complete
configured message footprint and mark unused counter blocks invalid. Only
reset clears the assembly storage.

=== Message Buffer

A circular message buffer persistently holds decoded messages. It offers
configurable depth (2–N entries), FIFO access, threshold monitoring with
interrupt generation, and full status reporting (occupancy, empty/full).

=== Data Flow

*Reception Phase* The ATB interface receives telemetry in 8-bit beats,
accumulated into 64-bit packets in the assembly buffer, then validated
for structure.

*Decoding Phase* Packets are parsed for headers (probe ID), broken into
9-bit blocks, counters are extracted and checked, and validity flags
assigned.

*Buffering Phase* Decoded messages are stored FIFO-style; pointers,
counters, and flags update atomically. Threshold or error interrupts are
generated as needed.

*Readout Phase* Telemetry is accessed by software via register reads.
Reads expose the oldest queued message without consuming it. Read the probe ID,
validity bitmap, and required counters, then write `CTRL.BUFFER_POP = 1` to
advance to the next message. A pop while empty has no effect. When a new message
arrives while the buffer is full, hardware drops the oldest entry and advances
the read pointer; software must drain the buffer fast enough to avoid loss or a
change of the visible message during a multi-register read.

=== Control Path

*Configuration Control* Software configures buffer thresholds, enables
interrupts, and clears errors, permitting runtime adaptation and robust
error handling.

*Status Reporting* Occupancy, availability, and error flags are
accessible, providing up-to-date telemetry collection health.

*Interrupt Handling* Interrupts are generated for buffer threshold
conditions and a missing last-packet flag. `INTR_STATUS.MISSING_LAST` is sticky
and write-one-to-clear. `INTR_STATUS.BUFFER_THRESHOLD` is read-only and reflects
occupancy strictly greater than `CTRL.BUFFER_THRESHOLD` (or an asserted threshold
test bit). Drain the buffer, raise the threshold, or clear the test condition to
remove that source; writing the status bit does not acknowledge it.

=== Clocking and Reset

*Clock Domain* The design operates fully synchronous on `clk_i`,
avoiding clock crossing complexity and easing verification.

*Reset Architecture* An asynchronous reset (`rst_ni`), synchronously
deasserted, clears the assembly storage and resets the buffer pointers. The
message-buffer payload storage is not cleared; empty-buffer reads return zero.
`CTRL.TELEMETRY_RX_FLUSH` discards queued messages and resets the assembly write
pointer without clearing either payload store. It is not a data-erasure operation.
