[[telemetry-receiver-interface]]
== Interface

=== Configuration Parameters

[[telemetry-receiver-configuration-parameters-table]]
[cols="2,1,3",options="header",role="telemetry-table"]
.Telemetry receiver configuration
|===
|Core parameter |Default |Meaning
|`BUFFER_DEPTH` |8 |Decoded-message queue depth. Use a power-of-two depth of
at least two: the RTL pointer wraps by its binary width.
|`MAX_NUM_COUNTERS_PER_MESSAGE` |4 |Counter positions decoded per message;
the software register bank exposes 32 positions. This also determines assembly
capacity. Values beyond 32 cannot all be exposed through that register bank.
|===

The ATB beat width (8 bits), packet width (64 bits), counter width (32 bits)
and ATB ID width (7 bits) are package constants.
The core register port has an 8-bit address and 32-bit data path.

=== Subsystem Wrapper

// Preserve incoming links to the consolidated sections.
++++
<span id="clock-and-reset-specifications"></span>
++++
endif::backend-html5[]

`telemetry_receiver_wrap` defaults to three receivers. It configures their queue
depth with `TELEMETRY_RECEIVER_BUFFER_DEPTH` (default 8) and counter counts with
`TELEMETRY_RECEIVER_MAX_NUM_COUNTERS_PER_MESSAGE` (default 4 per receiver).
Actual subsystem values and aperture assignments come from the integration.

The wrapper receives ATB traffic on `clk_telemetry_i` / `rst_telemetry_ni` and
crosses it into `clk_i` / `rst_ni` through an eight-entry asynchronous FIFO per
receiver. Its external ready signal reflects crossing-FIFO capacity. This does
not turn the core's decoded-message queue into a lossless backpressured queue.
The wrapper also contains flush-handshake synchronizers and returns a decode
error for register addresses outside its configured receiver apertures.

Clock frequency, jitter, reset duration and physical timing constraints must
come from the integration timing specification.
