[[telemetry-receiver-interface]]
== Interface

The Telemetry Receiver component provides AXI4-Lite register access and
Advanced Trace Bus (ATB) telemetry data reception interfaces.

=== Configuration Parameters

[width="100%",cols="30%,20%,50%",options="header",]
|====================================================================================
|Parameter |Default |Description
|NUM_BUFFERS |2 |Number of telemetry buffers (dual-buffer architecture)
|BUFFER_DEPTH |16 |Depth of each telemetry buffer (entries)
|ATB_DATA_WIDTH |8 |ATB interface data width (bits)
|PACKET_WIDTH |64 |Telemetry packet width (bits)
|ADDR_WIDTH |32 |Register address width (bits)
|DATA_WIDTH |32 |Data bus width (bits)
|====================================================================================

=== Signal Interfaces

=== Global Interface

The global interface provides fundamental clock and reset signals
required for basic operation.

.Global Interface Signals
[width="100%",cols="15%,10%,10%,10%,55%",options="header",]
|=====================================================================================
|Signal Name |Width |Direction |Active |Description
|`clk_i` |1 |Input |Rising |System clock input. All synchronous
operations are performed on the rising edge.

|`rst_ni` |1 |Input |Low |System reset input. Asynchronous assertion,
synchronous deassertion.
|=====================================================================================

=== Clock and Reset Specifications

* *Clock Frequency*: The component can operate at frequencies up to 200
MHz
* *Clock Jitter*: Maximum 100ps peak-to-peak jitter tolerance
* *Reset Duration*: Minimum 10 clock cycles for complete reset
* *Reset Recovery*: Component ready for operation 2 clock cycles after
reset deassertion

=== ATB Telemetry Interface

The ATB (Advanced Trace Bus) interface receives telemetry data using standard
ATB protocol.

.ATB Interface Signals
[width="100%",cols="15%,10%,10%,65%",options="header",]
|=================================================================================
|Signal Name |Width |Direction |Description
|`atdata_i` |8 |Input |Telemetry data input (8-bit data beats)
|`atid_i` |7 |Input |ATB ID field (trace source identification)
|`atvalid_i` |1 |Input |ATB valid signal (data valid indication)
|`atready_o` |1 |Output |ATB ready signal (receiver ready indication)
|`afvalid_o` |1 |Output |ATB flush valid (flush request indication)
|`afready_i` |1 |Input |ATB flush ready (flush acknowledgment)
|=================================================================================

=== ATB Protocol Specifications

* *Data Width*: 8 bits per beat
* *ID Width*: 7 bits (128 unique trace sources)
* *Flow Control*: Valid/ready handshaking for reliable data transfer
* *Flush Support*: Bidirectional flush signaling for stream management
* *Back-pressure*: Component can assert `atready_o` low to apply
back-pressure
* *Latency*: Zero-cycle latency when ready, immediate acceptance when
`atready_o` is high

=== Interrupt Interface

The interrupt interface provides a single interrupt output for event
notification.

.Interrupt Interface Signals
[width="100%",cols="15%,10%,10%,65%",options="header",]
|=====================================================================
|Signal Name |Width |Direction |Description
|`irq_o` |1 |Output |Interrupt request output (active high)
|=====================================================================

=== Interrupt Specifications

* *Polarity*: Active high (asserted when high)
* *Duration*: Level-sensitive, remains asserted until cleared
* *Sources*: Buffer threshold and error condition interrupts
* *Clearing*: Cleared by writing appropriate bits in interrupt status
registers
* *Latency*: Interrupt assertion within 2 clock cycles of triggering
condition
