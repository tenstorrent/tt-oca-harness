[[ptap-architecture]]

The PTAP is fully compliant with the IEEE JTAG specifications. It implements a
modular design with a core TAP controller, dedicated register modules for each
instruction type, and optional AXI bridge modules for debug access. The
architecture supports Test Mode Persistence (TMP), boundary scan with dedicated
scan ports and control signals, BIST functionality, and 3DIC support with STAP
scan ports and control signals derived from internal TDRs.

<<ptap-module-architecture-figure>> shows the control, decode, and scan-data paths
through the PTAP.

[[ptap-module-architecture-figure]]
.PTAP module architecture
image::ptap-architecture.svg[alt="PTAP module diagram showing the TRST and power-on reset AND gate, the TAP controller, TMP controller, the instruction register and test data registers with the IR opcodes that select each one, the JTAG2AXI bridges, the TDR multiplexer that takes every register output, and the zero-length-bypass, STAP and retimer-bypass multiplexers on the TDO path with their selects",width=100%,pdfwidth=100%]

Blue lines carry scan data and grey lines carry control. `client_tdi_i` feeds the
instruction register and every register in the scan-register group, whose last
column gives the IR opcodes, in hex, that select each register for a DR scan. The
6-bit instruction register captures `6'b000001`, resets to IDCODE and decodes its
opcode one-hot onto `inst_decoded_o[63:0]`. An opcode with no register of its own,
or one whose enable parameter is 0, selects BYPASS. Dashed registers and bridges
are present only when their parameter enables them
(<<ptap-module-hierarchy-table>>). The boundary-scan chain and the iJTAG network
lie outside the PTAP: `client_tdi_i` is forwarded to them, and their returns enter
the TDR multiplexer.

`tdr_mux` takes the output of every register in the group and the boundary-scan
and iJTAG returns. It selects the instruction register while `ir_scan_ctrl.select`
is set, and otherwise the register that `inst_decoded_o` selects. The numbers on
the inputs of each 2:1 multiplexer are the select values that pass them.
`u_zlb_tdr_mux` passes `client_tdi_i` instead of `tdr_mux` during a
ZERO_LENGTH_BYPASS DR scan, and its output also leaves on `stap_host_scan_out_o`
toward the STAP chain. `u_tdo_mux` passes the chain return `stap_host_scan_in_i`
while `stap_select`, the TAP_3DCR select bit, is set. The retimer registers the
result on the falling TCK edge, and `u_tdo_bypass_mux` bypasses the retimer during
a ZERO_LENGTH_BYPASS DR scan. Both ZERO_LENGTH_BYPASS multiplexers take their
select from `inst_decoded_o[3D]` ANDed with `dr_scan_select_reg`, the DR scan
select registered on the falling TCK edge, and with the inverse of `stap_select`.
While `stap_select` is set, ZERO_LENGTH_BYPASS therefore behaves exactly as
BYPASS (<<ptap-zero-length-bypass>>).

`pwr_on_rst_ni` is ANDed with the client TRST in `u_trst_n_and`. The result,
`jtag_trst_n`, resets the TAP controller and the retimer, and the controller
forwards it with TCK and TMS on `host_tap_ctrl_o`. The controller also drives the
IR and DR scan controls, ORed together and gated by `stap_select`, on
`stap_host_scan_ctrl_o`, so the STAP chain holds its state while the bit is clear.
The TMP controller takes the decoded CLAMP_HOLD, CLAMP_RELEASE and BYPASS
instructions and the TMP_STATUS `bypass_escape_bit`, and returns `persistence_mode`
to the TAP controller. The AXI side of each JTAG2AXI bridge runs on `clk_i` and
`rst_n_i` and takes the DFT test-mode enable `test_en_i`; the figure omits all
three. Each bridge has its own `*_security_disable_i` input
(<<ptap-debug-disable-inputs-table>>).

=== TAP Controller State Machine

The TAP controller implements the IEEE 1149.1 16-state finite state machine
using one-hot encoding. Each state is assigned a unique bit position within a
16-bit vector, enabling direct state detection via single-bit comparisons.

<<ptap-state-encodings-table>> lists the one-hot encodings and functions of the sixteen
TAP-controller states.

[[ptap-state-encodings-table]]
[width="100%",cols="<20%,<20%,<60%",options="header"]
.PTAP state encodings
|===
|State |Encoding |Description

|TEST_LOGIC_RESET |16'h0001 |State 0: Reset state, instruction register loads IDCODE
|RUN_TEST_IDLE |16'h0002 |State 1: Idle state between operations
|SELECT_DR_SCAN |16'h0004 |State 2: Select data register scan path
|CAPTURE_DR |16'h0008 |State 3: Capture data into selected DR
|SHIFT_DR |16'h0010 |State 4: Shift data through selected DR
|EXIT1_DR |16'h0020 |State 5: Exit from shift to either pause or update
|PAUSE_DR |16'h0040 |State 6: Pause DR shift operation
|EXIT2_DR |16'h0080 |State 7: Exit from pause back to shift or update
|UPDATE_DR |16'h0100 |State 8: Update DR from shift register
|SELECT_IR_SCAN |16'h0200 |State 9: Select instruction register scan path
|CAPTURE_IR |16'h0400 |State 10: Capture data into IR (fixed pattern 6'b000001)
|SHIFT_IR |16'h0800 |State 11: Shift data through IR
|EXIT1_IR |16'h1000 |State 12: Exit from shift to either pause or update
|PAUSE_IR |16'h2000 |State 13: Pause IR shift operation
|EXIT2_IR |16'h4000 |State 14: Exit from pause back to shift or update
|UPDATE_IR |16'h8000 |State 15: Update IR, decode new instruction
|===

Five consecutive TCK cycles with TMS high bring the state machine to
TEST_LOGIC_RESET from any state, as the IEEE 1149.1 state graph defines. A state
register value that is not one of the sixteen one-hot encodings also moves to
TEST_LOGIC_RESET on the next rising edge of TCK.

Control signals are generated using a split approach. The update and
run-test-idle signals are decoded combinationally from the current state as
Moore machine outputs. The capture, shift, test-logic-reset and TDO output
enable signals are decoded from the current state and registered on the falling
edge of TCK, so they are stable before the next rising edge samples data.

=== Reset Hierarchy

The PTAP employs a three-level reset hierarchy to support power-on
initialization, JTAG reset, and conditional register preservation.

<<ptap-reset-hierarchy-table>> identifies the source and scope of each PTAP reset.

[[ptap-reset-hierarchy-table]]
[width="100%",cols="<25%,<35%,<40%",options="header"]
.PTAP reset hierarchy
|===
|Reset Signal |Source |Scope

|`jtag_trst_n`
|`pwr_on_rst_ni && client_tap_ctrl_i.trst_n`
|Primary reset for all JTAG logic, combines power-on and external TRST

|`test_logic_reset`
|Derived from TAP FSM state (asserted when state == TEST_LOGIC_RESET)
|Resets instruction and data registers

|`chrst_n`
|`TMP_ENABLE ? (!test_logic_reset \|\| persistence_mode_i) : !test_logic_reset`
|Channel reset for TMP-aware registers, preserves state when in persistence mode
|===

The primary reset `jtag_trst_n` is formed by AND-gating the power-on reset input
with the external TRST signal. This combined reset feeds all JTAG clock domain
logic. The TAP controller derives `test_logic_reset` from the FSM state, which
normally resets all registers. When Test Mode Persistence is enabled, the
conditional reset `chrst_n` allows boundary scan and configuration registers to
survive TEST_LOGIC_RESET state transitions while in persistence mode.

=== TDR Multiplexer

The PTAP implements an instruction-dependent data register multiplexer.
During IR scan operations, the instruction register connects to the scan path.
During DR scan operations, the appropriate data register is selected based on
the currently decoded instruction. Each test data register has dedicated scan
control logic that enables selection only when the corresponding instruction is
active and the required feature is enabled.

The scan path supports zero-length bypass through explicit `prim_stdmux2`
multiplexer cells rather than behavioral multiplexing. This implementation
prevents glitches on scan path selectors during instruction transitions.

STAP selection is implemented as a second-level multiplexer. When the 3DCR
register's select bit is asserted, the STAP chain input replaces the TDR
multiplexer output. The STAP scan control signals are generated by OR-combining
the instruction register and data register scan controls, enabling STAP
operation during both IR and DR scan sequences as required by IEEE 1838. The
select bit also gates the select, capture, shift and update strobes of the STAP
scan interface, so they stay low while the bit is clear.

[[ptap-zero-length-bypass]]
==== Zero-Length Bypass

While the TAP_3DCR STAP-select bit is clear, the ZERO_LENGTH_BYPASS instruction
connects TDI directly to TDO without intermediate register stages, providing
minimum scan latency for hierarchical JTAG chains. The DR scan adds no bit, and
TDO follows TDI combinationally rather than through the retimer.

While the STAP-select bit is set, ZERO_LENGTH_BYPASS behaves exactly as BYPASS.
The last stage of the STAP chain shifts on the rising TCK edge, so its return
must reach TDO through the falling-edge retimer, and a path that skips the
retimer cannot carry it. The bypass register is selected, captures 0 and leads
the STAP chain, and TDO is retimed. A DR scan under ZERO_LENGTH_BYPASS is then
one bit longer than the STAP chain and matches a DR scan under BYPASS bit for
bit.

=== TDO Retiming

The TDO output is retimed on the falling edge of TCK as required by IEEE 1149.1
Section 4.5.2. The retiming register ensures that TDO transitions occur at the
same clock edge that samples TDI at the receiving device, maintaining timing
margins across board-level JTAG chains. For zero-length bypass operation with
the TAP_3DCR STAP-select bit clear, the retimer is bypassed using an explicit
`prim_stdmux2` cell to minimize scan latency. While the bit is set, TDO is
retimed under every instruction, ZERO_LENGTH_BYPASS included.

The IDCODE instruction accesses a TDR containing device identification
information.

[[ptap-idcode-fields-table]]

To access the IDCODE TDR:

1. Shift the IDCODE instruction into the instruction register using the IR-Scan
   sequence.
2. Shift any pattern into the IDCODE TDR on TDI using the DR-Scan sequence,

3. The bits shifted into the IDCODE TDR will be ignored. The contents of the
   IDCODE TDR will shift out on TDO.

=== Boundary Scan Support

All boundary scan and BIST instructions defined in IEEE 1149.1 are optionally
supported, but support is not enabled by default. RTL parameters are provided to
selectively enable support for each instruction. Any disabled instruction has
the same behavior as the BYPASS instruction.

To access the boundary scan registers:

1. Shift any boundary scan instruction that selects the BSRs into the
   instruction register using the IR-Scan sequence.
2. Shift any pattern into the BSRs on TDI using the DR-Scan sequence, starting
   with the least significant bit.
3. The contents of the BSRs will shift out on TDO.

=== BIST Support

The RUNBIST instruction is optionally supported, but support is not enabled by
default. An RTL parameter is provided to selectively enable support. Any
disabled instruction has the same behavior as the BYPASS instruction.

When the RUNBIST instruction is selected, the iJTAG network is selected as the
active scan chain. An iJTAG network control signal indicates that the RUNBIST
instruction is active. A designer may also utilize the decoded INST_SELECT
signal to trigger the BIST logic for any instructions that they have enabled.

The PTAP adds no Segment Insertion Bit (SIB) or other scan cell to the iJTAG
path. TDI is forwarded unchanged to the iJTAG network, and the network's return
is the RUNBIST TDR, so the length and contents of the RUNBIST DR are defined
entirely by the iJTAG network attached to the PTAP.

To execute BIST and access the BIST TDR:

1. Shift the RUNBIST instruction into the instruction register using the IR-Scan
   sequence.
2. Shift the configuration vector that the attached iJTAG network defines for
   reaching the BIST TDR into TDI using the DR-Scan sequence, starting with the
   least significant bit. A hierarchical network requires one DR scan for each
   level of SIBs that must be opened on the way to the BIST TDR.
3. Shift the BIST TDR contents, together with the bits of every SIB and register
   that remains on the scan path, into TDI using the DR-Scan sequence, starting
   with the least significant bit.
4. The captured contents of the same scan path shift out on TDO.

=== Test Mode Persistence (TMP) Support

There is optional support for TMP, but support for TMP is disabled by default.
An RTL parameter enables support for TMP.

When TMP support is enabled, a TMP controller is included in the PTAP. The TMP
controller manages the active-low _CH_RESET_N_ signal. The _CH_RESET_N_ signal
is the reset signal for any registers that must retain their state across TLR
soft resets, mainly the boundary scan cells. _CH_RESET_N_ asserts whenever the
TAP is in the TLR state _except_ when the TMP controller is in the
_PERSISTENCE_ON_ state. When the TMP controller is in the _PERSISTENCE_ON_
state, the only events that will assert _CH_RESET_N_ are full power-on-reset
(POR) or TRST signal assertion.

When TMP support is disabled, the _CLAMP_HOLD_, _CLAMP_RELEASE_, and
_TMP_STATUS_ instructions have the same behavior as the _BYPASS_ instruction,
and the _CH_RESET_N_ signal always responds to every POR, TRST, or TLR event,
i.e. it is an exact copy of the _RESET_N_ signal.

<<ptap-tmp-status-fields-table>> defines the bypass-escape and persistence-status bits.

[[ptap-tmp-status-fields-table]]
[width="100%",cols="3,1,6",options="header"]
.PTAP TMP_STATUS fields
|===
|*Bit* |*Reset* |*Description*
|Bypass Escape (bit 0) |0 |Whenever this bit is set, the TMP controller will transition to the _PERSISTENCE_OFF_ state when the TAP controller enters the _UPDATE_IR_ state after the _BYPASS_ instruction has been selected.
|TMP Status (bit 1) |0 on capture |Capture-DR samples whether the TMP controller is in the Persistence-On state. The update register resets to `2'b10`; its bit 1 is replaced by the controller state on capture and does not enable persistence.
|===

=== 3DIC Support

There is optional support for STAP interfaces, and support is enabled by
default. An RTL parameter selects the number of STAP interfaces, where a value
of 0 disables STAP support.

In order to properly support the IEEE 1838 standard, a chain of STAP interfaces
must be inserted at the end of each chiplet's scan chain. This is done after the
_IR Select_ MUX to ensure that both the instruction registers and TDRs from all
enabled PTAPs in the scan chain are scannable. As a consequence, the STAPs
require dedicated capture, shift, and update control signals that are triggered
during both the IR and DR sequences.

The PTAP has a 2-bit _3DCR_ register that is accessed with the _TAP_3DCR_
instruction. This register provides an option to bypass all STAPs in the scan
chain.

<<ptap-3dcr-fields-table>> defines the configuration-hold and STAP-selection bits.

[[ptap-3dcr-fields-table]]
[width="100%",cols="3,1,6",options="header"]
.PTAP 3DCR fields
|===
|*Bit* |*Reset* |*Description*
|Config Hold |0 |When this bit is set, the PTAP TLR state does not reset this TDR, and it will hold its current state until TRST is asserted.
|Select |0 |When this bit is unset, the PTAP's top-level STAP scan interface is completely bypassed: TDO does not come from the STAP chain, and the select, capture, shift and update strobes of the STAP scan interface stay low, so the STAP chain holds its state through every IR and DR scan.
|===

The select bit takes effect at Update-DR of the scan that writes it. A scan
that sets it therefore covers only this register, and the STAP chain joins the
scan path from the next IR or DR scan onwards. Software sets the select bit in a
TAP_3DCR scan of its own before programming any STAP.

When STAP support is disabled, the TAP_3DCR instruction has the same behavior as
the _BYPASS_ instruction, and the STAP scan chain cannot be selected.

=== IC_RESET Support

The PTAP provides support for a configurable number of IEEE 1149.1-compliant
reset controls. The IC_RESET TDR is composed of three independently-enabled
slices:

* *SMC slice* (nearest TDI): driven by the `ic_reset_smc_t` struct type and
  gated by `IC_RESET_SMC_ENABLE`. Sized from `$bits(ic_reset_smc_t)`.
* *SEP slice*: driven by the `ic_reset_sep_t` struct type and gated by
  `IC_RESET_SEP_ENABLE`. Sized from `$bits(ic_reset_sep_t)`.
* *External slice* (nearest TDO): driven by the `ic_reset_ext_t` struct type and
  gated by `IC_RESET_EXT_ENABLE`. Sized from `$bits(ic_reset_ext_t)`. The
  instantiator supplies this type; the PTAP does not name the external ports.

Each slice's struct must contain `.ovrd` and `.val` sub-structs of identical
width (checked via an elaboration-time assertion in `jtag_ptap`). Within
`jtag_ic_reset_reg`, the reset-enable and reset-control bits are interleaved in
IEEE 1149.1 §17 order: in each port's pair, `reset_enable` is nearer TDO and
`reset_control` nearer TDI, so port _n_ occupies TDR bits `2*n+1` and `2*n+2`
(<<ptap-ic-reset-fields-table>>). `jtag_ptap` packs the three struct slices into
that interleaved bus and unpacks the outputs back into structured form. The TDR carries the SMC slice closest to TDI, then SEP, then
the external slice, followed by the single `reset_hold` bit.

The total length is `2 * (NumSmcIcReset + NumSepIcReset + NumExtIcReset) + 1`
bits. Each `Num*IcReset` is half the width of its slice's struct type,
`+$bits(ic_reset_*_t) / 2+`, when the matching `+IC_RESET_*_ENABLE+` parameter is
set, and 0 otherwise.

<<ptap-ic-reset-fields-table>> defines the reset-control, reset-enable, and bypass
fields in the IC_RESET TDR.

[[ptap-ic-reset-fields-table]]
[width="100%",cols="2,2,1,1,6",options="header"]
.PTAP IC_RESET fields
|===
|Bits |Field |Access |Reset |Description
|2*n+2 |reset_control |RW |1 |The controlled, active-low reset value driven while _reset_enable_ is 0 (i.e. while JTAG override is active).
|2*n+1 |reset_enable |RW |1 |Active-LOW per IEEE 1149.1 §17: 1 (default) ⇒ JTAG override DISABLED (upstream reset passes through); 0 ⇒ JTAG override ENABLED (the port is driven by _reset_control_). The "enable" in the IEEE name refers to "enabling the controlled reset state", not the override mechanism.
|0 |reset_hold |RW |1 |When 0, TLR will *not* reset the _reset_enable_ and _reset_control_ bits. TRST/POR will always reset all bits.
|===

[IMPORTANT]
====
*Polarity convention* — the TDR field names come from the IEEE 1149.1 §17
specification and use an active-low `reset_enable`. `jtag_ic_reset_reg`
converts this into a conventional *active-high* override signal
(`ic_reset_ovrd_o[i] = !reset_enable[i]`) before it leaves the register, so
every downstream consumer sees `.ovrd == 1` meaning "JTAG is currently
overriding this port". Do not re-invert this signal downstream.
====

For each of the resets defined in the TDR, the PTAP exposes two logical signals
(grouped into the per-slice `jtag_*_reset_ctrl_t` structs):

* _ic_reset_ovrd_ / `.ovrd` - *Active-high* JTAG-override flag (the bit-wise
  inversion of _reset_enable_). 1 ⇒ JTAG is driving this reset, 0 ⇒ upstream
  reset passes through.
* _ic_reset_ctrl_n_ / `.val` - Active-low reset value driven when
  _ic_reset_ovrd_ is asserted (identical to the _reset_control_ TDR bit).

=== iJTAG Support

The PTAP provides a scan port for an IEEE 1687-2014-compliant hierarchical iJTAG
network. The _SELECT_IJTAG_ instruction is always decoded; no configuration
parameter removes it. While it is the current instruction, a DR scan selects the
iJTAG network and the network return drives TDO.

==== *_AXI_SINGLE_OP

This is a private instruction that generates a single AXI read or write
transaction. It provides a mechanism for an external debugger to do sparse reads
or writes to nearly any register in the design. Since the entire address must be
shifted in for each transaction, this instruction is most useful for sparse
accesses. This instruction uses semantics very similar to the RISC-V DTM DMI
instruction.

Let `D` be the AXI data width in bits, `A` the address width, and `S` the
scan size-field width: 1 bit for `D <= 16`, 2 bits for `D <= 64`, and 3 bits
otherwise. The single-operation TDR has `2 + S + D/8 + D + A` bits.
For `D=64` and `A=51`, it has 127 bits.

The size field requests a transfer of `2**size` bytes. The AXI protocol does not
allow a transfer wider than the data bus, so the bridge uses the effective size
`E = min(size, data_size)`, where `data_size = log2(D/8)` is the capability field of
the same name. A size above `data_size` transfers one full `D`-bit beat: for
`D=32`, the 2-bit size field admits 3, and the bridge transfers 4 bytes.

<<jtag2axi-single-operation-layout-figure>> shows the single-operation TDR for a 64-bit
data bus and a 51-bit address bus. In this and the following layout figures the most
significant bit is on the left, nearest TDI, and bit 0 on the right shifts out to TDO
first. The bit range of each field is above it and its width below it; field widths
are not drawn to scale.

==== *_AXI_SERIES_CTRL

This is a private instruction that preloads the start address of a region that
will be subsequently read or written using the AXI_SERIES_DATA instruction. It
is used when an external debugger wants to either:

* Read or write a contiguous block of registers or memory.
* Repeatedly read or write the same location (e.g., polling)

Using the series instructions instead of the AXI_SINGLE_OP instruction is much
more time efficient for these use cases.

The pipeline-depth field width `P` is 1 when `FIFO_DEPTH=0`, otherwise
`$clog2(FIFO_DEPTH+1)`. The control TDR has `2 + S + P + A + 1` bits.
For `D=64`, `A=51`, and `FIFO_DEPTH=3`, the length is 58 bits.

<<jtag2axi-series-control-layout-figure>> shows the series-control TDR for 64-bit data,
51-bit addresses, and FIFO_DEPTH=3.

==== *_AXI_SERIES_DATA_INCR

This is a private instruction that does the actual read/write to the address
previously specified.

After the access is completed, an internal address register used for the series,
which was previously loaded by AXI_SERIES_CTRL, is incremented as follows:

AXI_SERIES_CTRL.address += 2**E

This allows the debugger to load or dump contiguous regions of address space.

Note that this is a variable-length data register. The length is n bits where
n = 8*(2**E).

The data field is the logical transfer payload. The bridge places that payload
on the AXI byte lanes selected by the current address and the effective size `E`,
and Capture-DR returns the payload from those lanes.

The data field is drawn as the payload bytes it holds, with bit 0 aligned across the
four sizes. The incrementing payload layouts for effective sizes `E` of 0, 1, 2, and 3
are shown in <<jtag2axi-incrementing-data-layout-for-size-0-figure>>,
<<jtag2axi-incrementing-data-layout-for-size-1-figure>>,
<<jtag2axi-incrementing-data-layout-for-size-2-figure>>,
<<jtag2axi-incrementing-data-layout-for-size-3-figure>>, respectively.
Effective size 3 needs a 64-bit data bus, which the last figure assumes.

[[jtag2axi-system-reset]]
==== System Reset Recovery

A system reset resets the AXI side of each JTAG2AXI instrument while its JTAG
side keeps running. The instrument recovers without a TAP reset. When the
reset reaches its JTAG side, it discards every operation that is in flight or
queued: the AXI transaction it was waiting on, series requests not yet issued,
and series read data not yet shifted out. The target can still complete a
transaction that was already on the AXI bus before the reset reached it, so
the debugger must treat a discarded write as having an unknown effect.

After the discard:

* The SINGLE_OP op field reads 2 if a single operation or an error-status
  series operation was discarded, and its captured read-data field reads 0.
  Otherwise both keep their values.
* The SERIES_CTRL op field reads 2 if a series operation was discarded and it
  held no earlier series error. Otherwise it keeps its value, including a
  sticky status of 3. Only AXI_SERIES_CTRL.reset clears it.
* The SERIES_CTRL address, size, pl_depth and op settings keep their values,
  but the read pipeline restarts empty. Reprogram SERIES_CTRL before resuming
  a pipelined series read.

Recovery starts when the system reset asserts and completes within 52 periods
of the slower of TCK and the AXI clock after the system reset deasserts. TCK
periods count only while the debugger drives TCK, for example with transitions
in Run-Test/Idle. An operation shifted in during that time is held and issued
once recovery completes, and the SINGLE_OP op field reads 3 until the
operation finishes.

=== Debug Disable

The PTAP has three per-bridge debug-disable inputs. The JTAG interface unit
synchronizes those bits to TCK and presents them here as ready-to-gate signals.
Each input is active-high: when it is 1, the corresponding `jtag2axi` instance
blocks AXI transaction generation.

<<ptap-debug-disable-inputs-table>> maps the three JTAG2AXI bridges to their active-high
disable inputs.
