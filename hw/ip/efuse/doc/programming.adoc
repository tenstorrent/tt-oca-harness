[[smc-dv-efuse-programming]]
== Programming

=== Exclusive program and read enables

`EFUSE_PROGRAM_CTRL.program_enable` and `EFUSE_READ_CTRL.read_enable` are
mutually exclusive. After fuse sense completes, program and read share a
single command path to the OTP bank, and `program_enable` owns that path
whenever it is set. A read issued while `program_enable` is still high
does not reach the bank.

Treat `program_enable` as a mode-ownership bit, not sticky configuration.
After a program completes (`PROGRAM_DONE`), deassert `program_enable`
before any later read. Leave address, data, and the other program
fields as they are. Deassert `read_enable` the same way before starting
a program. The two enables are never asserted together.

=== Usage Examples

=== Example 1: Programming a Single Bit

[source,sourceCode,c]
----
// Own the program path (program_enable is bit 27). read_enable must be 0.
EFUSE_PROGRAM_CTRL = (1 << 27) | (1 << 16) | (bit_addr & 0xFFFF);

// Trigger program
EFUSE_PROGRAM_CTRL |= (1 << 17);

// Wait for completion
while (!(EFUSE_PROGRAM_CTRL & (1u << 25))); // Wait for PROGRAM_DONE

// Check status
if ((EFUSE_PROGRAM_CTRL >> 26) & 0x1) {
    // Handle error
}

// Release program ownership before any later read
EFUSE_PROGRAM_CTRL &= ~(1 << 27);
----

=== Example 2: Reading Multiple Words

[source,sourceCode,c]
----
// Each command reads one 32-bit word; addresses are measured in bits.
// program_enable must already be 0.
for (uint32_t i = 0; i < num_words; ++i) {
    uint32_t addr = bit_addr + 32u * i;
    EFUSE_READ_CTRL = (1u << 28) | (addr & 0xFFFFu);
    EFUSE_READ_CTRL |= (1u << 16); // READ_GO
    while (!(EFUSE_READ_CTRL & (1u << 25))); // READ_DONE
    if (EFUSE_READ_CTRL & (1u << 26)) {
        // Handle read error before consuming data.
        break;
    }
    data[i] = EFUSE_READ_INTERFACE_READ_DATA;
}

// Release read ownership before any later program.
EFUSE_READ_CTRL &= ~(1u << 28);
----

=== Program Operation Sequence

1.  *Setup Phase*:
* Confirm `EFUSE_READ_CTRL.read_enable` is 0
* Set `program_enable` = 1 in `EFUSE_PROGRAM_CTRL`
* Configure `efuse_addr` with target bit address
* Set `efuse_data` = 1 (only 1s can be programmed)
* Optionally set `efuse_program_read_back` = 1 for verification
2.  *Execute Phase*:
* Set `efuse_program_go` = 1 to trigger operation
* Monitor `program_busy` until it goes low
* Check `program_done` = 1 for completion
3.  *Status Check*:
* Read `program_status` field:
** 0: Success
** 1: Error. This one-bit field does not distinguish failure causes.
4.  *Release*:
* Clear `program_enable` in `EFUSE_PROGRAM_CTRL`. This returns the
command path so a subsequent read can proceed.

=== Read Operation Sequence

1.  *Setup Phase*:
* Confirm `EFUSE_PROGRAM_CTRL.program_enable` is 0
* Set `read_enable` = 1 in `EFUSE_READ_CTRL`
* Configure `efuse_addr` with target bit address
* Issue one command per 32-bit word; advance the bit address by 32 for each
additional word. There is no software read-length field.
2.  *Execute Phase*:
* Set `efuse_read_go` = 1 to trigger operation
* Monitor `read_busy` until it goes low
* Check `read_done` = 1 for completion
3.  *Data Retrieval*:
* Read data from `EFUSE_READ_INTERFACE_READ_DATA`
* Check `read_status` for any errors
4.  *Release*:
* Clear `read_enable` in `EFUSE_READ_CTRL` so a subsequent program can
own the command path.
