[[uart-global-signals-table]]
[cols="2,1,3",options="header"]
.UART port groups
|===
|Signal |Direction |Use
|`clk_i`, `rst_ni` |Input |Clock and active-low asynchronous reset. Supply reset
release synchronized to `clk_i`; there is no reset-release synchronizer in the core.
|`axil_req_i`, `axil_resp_o` |Input / output |32-bit AXI4-Lite register access.
|`rx_i`, `tx_o` |Input / output |Serial data, idle high. RX is synchronized internally.
|`cts_ni`, `dsr_ni`, `ri_ni`, `dcd_ni` |Input |Active-low, internally synchronized
modem inputs. MSR reports their asserted states and changes.
|`rts_no`, `dtr_no`, `out1_no`, `out2_no` |Output |Active-low modem outputs,
software-controlled in normal mode.
|`rxrdy_o`, `txrdy_o` |Output |Active-high DMA service indications, as below.
|`err_o` |Output |Internal FIFO/holding-register parity error; not serial parity.
|`irq_o` |Output |Active-high combined interrupt request.
|===

The serial and modem ports are logic signals; electrical interfaces such as
RS-232 or RS-485 require appropriate external transceivers. Higher-level serial
protocols and half-duplex direction policy belong to software/integration.

[[uart-dma-interface-signals-table]]
[cols="1,2,2",options="header"]
.UART DMA-ready behavior
|===
|Mode |`rxrdy_o` |`txrdy_o`
|Mode 0, or FIFO disabled |High when receive data is available. |High when the
transmit FIFO/holding register is empty, not merely when it has free space.
|Mode 1 with FIFO enabled |Asserts at the receive trigger or timeout and remains
high until the RX FIFO is empty. |Allows filling until the TX FIFO becomes full;
then remains low until it is empty again.
|===

DMA uses the same THR/RBR register accesses as software. Its configuration must
respect buffer capacity and register side effects; the UART exports no separate
DMA data port.
