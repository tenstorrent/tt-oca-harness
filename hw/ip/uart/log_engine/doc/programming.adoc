[[log-engine-setup]]
=== Configure the Engine

. Start from reset or an idle engine with all pending lengths clear.
  Clear `CTRL.EN` before changing shared configuration.
. Allocate a readable region with an 8-byte-aligned base and a size that
  is a multiple of 128 bytes, no larger than 512 KiB.
. Write `LOG_REGION_SIZE` and both halves of `LOG_REGION_ADDR`. Only address
  bits `[55:0]` are implemented; bits `[63:56]` are reserved zero.
. Set `LOG_WRITE_ADDR` to the UART transmit register and configure the UART
  and its readiness path.
. Clear stale error status by writing `0x11` to `INTR_STATUS`. If required,
  write `0x11` to `INTR_ENABLE` and configure the receiving interrupt controller.
. Set `CTRL.EN = 1`.

For a 4 KiB region, each of the 16 slots has 256 bytes. Slot 0 begins at
the region base, slot 1 at base+256, and so on. Use the system memory map
for actual memory, engine and UART addresses.

[[log-engine-submit]]
=== Submit and Complete a Message

. Wait for `LOG_CTRL[i].LOG_LEN` to become zero before reusing slot `i`.
. Write the message into that slot. Keep its length within the slot capacity,
  and make the complete final fetch word readable.
. Make the data visible to the engine using the platform's cache-maintenance
  and memory-ordering rules, then write the byte length to `LOG_CTRL[i]`.
. Leave the buffer and length unchanged while pending. Poll for zero with a
  timeout appropriate to UART speed and other pending messages, or use a
  software scheduling mechanism that checks completion later.
. Inspect error status before treating completion as successful. A slot
  reaching zero does not mean the UART serial transmitter is empty.

Several slots can be pending at once. Assign slots to producers or serialize
access in software; writing a new length to an active slot is not a queueing
operation. A zero length submits no message.

[[log-engine-recovery]]
=== Handle an Error or Timeout

Read `INTR_STATUS` to distinguish fetch and write errors, diagnose the
memory or UART path, then clear the handled bits with write-one-to-clear.
There is no automatic retransmission. Because status is shared, it does not
identify which pending slot encountered the error.

If progress stops, check UART readiness and outstanding bus responses.
Do not free pending buffers solely because `CTRL.EN` was cleared;
<<log-engine-reset>> describes the disable behavior. Recovery must account
for any characters already sent, since restarting may duplicate output.
