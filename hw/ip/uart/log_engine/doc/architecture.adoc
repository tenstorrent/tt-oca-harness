[[log-engine-architecture]]
===== Architecture

====== Overview

The OCA Log Engine is a DMA-powered logging system that transfers log
messages from memory to a UART interface. It supports up to 16 log
entries with fair round-robin arbitration for efficient multi-source
logging.

====== Functional Blocks

====== Control and Status Registers (CSRs)

CSRs, accessed via AXI4-Lite, configure the engine and report status.
Key registers control global enable/disable (CTRL), region
size/alignment (LOG_REGION_SIZE), 56-bit base address (LOG_REGION_ADDR),
UART target (LOG_WRITE_ADDR), and per-log-entry control and length
(LOG_CTRL[0:15]). Interrupt registers (INTR_STATUS/ENABLE/TEST) enable
robust error detection and error recovery.

====== Round Robin Arbiter

A `prim_arbiter_tree`-based round robin arbiter ensures fair,
starvation-free access to DMA for all 16 log entries. It systematically
selects among entries with non-zero lengths, preventing monopolization
and balancing throughput regardless of data rates across logs. Tight
integration with the fetch FSM ensures smooth flow.

====== Log Fetch FSM

The fetch FSM coordinates DMA reads based on arbitration results and
FIFO space. It cycles through idle, request, and wait states: checking
for ready entries and FIFO space, issuing AXI4-Lite read requests, and
handling responses with word counters. Addresses are computed as
`log_region_addr + (log_region_size/16) * log_index + word_offset`,
supporting efficient, aligned memory access. Progress tracking and FIFO
handoff ensure reliable completion and seamless operation.

====== RDATA FIFO

A configurable-depth (default 4), synchronous 64-bit FIFO decouples
memory reads from UART writes, smoothing timing mismatches. All-zero
outputs when empty help security. Ready/valid handshakes on both sides
ensure safe, lossless transfer through variable system conditions.

====== Log Write FSM

This FSM manages conversion from 64-bit log words to 8-bit UART writes.
It only advances when UART is ready and FIFO data is available,
sequencing through idle, request, and wait states. Byte pointers extract
one byte at a time; FIFO is accessed every eight bytes. A completion
signal updates registers, enabling accurate monitoring and coordination.

====== Data Flow and Control Path

====== Data Flow

1.  Software configures memory region, UART address, and enables engine.
2.  Non-zero LOG_CTRL[i] length triggers log transfer.
3.  Arbiter selects a log entry.
4.  Fetch FSM performs memory reads.
5.  Data is buffered in RDATA FIFO.
6.  Write FSM sends bytes to UART.
7.  Transfer completion clears the length register.

====== Control Path

* Global enable gates operation.
* Fetch/write FSMs are coordinated via FIFO ready/valid signals.
* AXI4-Lite errors trigger interrupts.
* Completion updates registers and advances arbitration.

====== Clocking and Reset Methodology

The engine runs in one clock domain (`clk_i`) shared by all logic and
AXI4-Lite interfaces.

* Reset (`rst_ni`) is active-low async, sync deassertion.
* Global reset clears FSMs, counters, and logic.
* FIFO can be cleared independently when the engine is disabled.
* On reset: FSMs idle, counters zeroed, FIFO flushed, registers
preserved (except control fields).

====== Memory Interface Protocol

*Log Fetch*: 64-bit AXI4-Lite read, single-beat transfers, errors
signaled via LOG_FETCH_ERR.

*Log Write*: 32-bit AXI4-Lite write, single byte accesses using strobes,
errors signaled via LOG_WRITE_ERR.

====== Performance Characteristics

* *Fetch Bandwidth*: Limited by AXI4-Lite single transfers.
* *Write Throughput*: Determined by UART ready signal.
* *Latency*: Minimal, due to light buffering.
* *Fairness*: Maintained by round-robin selection.

====== Design Trade-offs

* _Memory Simplicity vs. Efficiency_: Fixed equal partitioning eases
logic at expense of flexibility.
* _Throughput vs. Area_: Single-beat transfers are simple but limit
bandwidth; FIFO depth is tunable.
* _Robustness vs. Complexity_: Comprehensive error checking improves
reliability at increased logic cost.
