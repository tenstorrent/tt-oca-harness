= Cross-Trigger Matrix
:description: CTM — AND-OR crossbar for cross-trigger pulse routing, configured as 26×26 in the DTP.

[[cross-trigger-matrix]]

The Cross Trigger Matrix (CTM) is an AND-OR crossbar that aggregates and
statically routes cross-trigger pulses between all sources (CTPs, CLAs,
internal devices) and sinks under AXI-Lite CSR control.
The current DTP configuration uses 26 input ports and 26 output ports.

== Overview

The CTM is compatible with both wire-OR and point-to-point CTPs. Typical
connections include Core Logic Analyzers (CLAs) and Cross Trigger Ports (CTPs).
Each device connected to the CTM acts as both a source and a sink.

The `NUM_CT_SRC` and `NUM_CT_DST` parameters in
`regs/cross_trigger_matrix.rdl` define the matrix dimensions and default to
26 each. The RTL derives the following localparams from the generated
register map:

[cols="<20%,<12%,<68%",options="header"]
|===
|Constant |Value |Description

|`NUM_CT_SRC`
|26
|Number of CT_Src output ports (sized by the `CT_SRC` array in the register map).

|`NUM_CT_DST`
|26
|Number of CT_Dst input ports (sized by the `CT_DST_SELECT` field width in the
register map).
|===

These values cannot be overridden at instantiation. Resizing the matrix
requires changing the SystemRDL parameters and regenerating the register map.
The CTM takes the AXI-Lite
request and response types as module parameters, which the CTN overrides to
match its own crossbar.

Every CT_Src port occupies 8 bytes regardless of the port count. At or below
32 destinations (including the DTP's 26), each register is a single 32-bit
word with immediate write semantics. Above 32 destinations both words must be
written before the mask takes effect, preventing half-programmed states.
