============
Verification
============

Testbench Overview
==================

The CTN testbench is located in ``hw/comp/cross_trigger_network/tb_vcs/`` and uses a cocotb-based verification environment.

Testbench Architecture
----------------------

::

    tb_cross_trigger_network.sv (Top-level testbench, generated)
    └── cross_trigger_network (DUT)

    test/
    ├── test_base.py       (Common test utilities, generated)
    ├── test_sanity.py     (Basic sanity test)
    ├── test_routing.py    (Cross trigger routing tests)
    ├── test_loopback.py   (Loopback routing tests)
    └── test_clock_stop.py (Clock stop control test)

The testbench and test_base.py are generated by ``generate_comp.py`` to match
the CTN configuration (NUM_CTP, NUM_INT_CT, etc.).

Test Descriptions
=================

Sanity Test (test_sanity.py)
----------------------------

**Purpose**: Verify basic CTN functionality has not broken.

**Test Sequence**:

1. Initialize DUT and AXI-Lite interface
2. Read CTP[0] CONFIG register via crossbar
3. Write and readback CTP[0] CONFIG register
4. Read CTM register to verify crossbar routing
5. Verify no bus errors

**Pass Criteria**: All register accesses complete without error.

Routing Test (test_routing.py)
------------------------------

**Purpose**: Verify cross trigger routing through CTM.

**Tests**:

* ``test_routing``: Basic CTM routing configuration
* ``test_mixed_mode_routing``: Routing between CTPs in different modes

**test_routing Sequence**:

1. Configure CTM to route CTP[0] → CTP[1]
2. Apply trigger pulse on CTP[0] GPIO input
3. Verify trigger appears on CTP[1] GPIO output
4. Test OR-ing of multiple sources

**test_mixed_mode_routing Sequence**:

Tests routing between external and internal CTPs configured in mixed modes:

1. Configure external CTP[0,1] in Wire-OR mode, CTP[2,3] in P2P mode
2. Test: External Wire-OR → External P2P (CTP[0] → CTP[2])
3. Test: External P2P → External Wire-OR (CTP[2] → CTP[1])
4. Test: External Wire-OR → Internal P2P (CTP[0] → Internal CT)
5. Test: Internal Wire-OR → External P2P (Internal CT → CTP[3])
6. Test: Internal P2P → External Wire-OR (Internal CT → CTP[0])

**Pass Criteria**: Triggers route correctly regardless of source/destination mode.

Loopback Test (test_loopback.py)
--------------------------------

**Purpose**: Verify loopback routing for all CTP types and modes with full signal verification.

**Tests**:

* ``test_external_ctp_wire_or_loopback``: Wire-OR mode loopback for all external CTPs
* ``test_external_ctp_p2p_loopback``: P2P mode loopback with full handshake for all external CTPs
* ``test_internal_ct_wire_or_loopback``: Wire-OR mode loopback for internal CTs (lower half)
* ``test_internal_ct_p2p_loopback``: P2P mode loopback with full handshake for internal CTs (upper half)
* ``test_ctm_routing_matrix``: Verify all CTM port routing combinations
* ``test_ctm_multi_source_or``: Test OR-ing multiple sources to single destination

**External CTP Wire-OR Loopback Sequence**:

1. Configure CTP in Wire-OR mode
2. Configure CTM for loopback: CTP[n] → CTP[n]
3. Inject trigger via GPIO input
4. Model Wire-OR bus (copy dout_en to din)
5. Verify output enable is asserted

**External CTP P2P Loopback Sequence**:

1. Configure CTP in P2P mode
2. Configure CTM for loopback: CTP[n] → CTP[n]
3. Inject request via ct_req_in
4. Verify request appears on ct_req_out
5. Complete handshake via ct_ack_in
6. Verify output clears after handshake

**Internal CT P2P Full Handshake Verification**:

1. Assert ctm_dst_req (CLA to CTP request)
2. Verify ctm_dst_ack asserts (CTP acknowledges)
3. Verify ctm_src_req asserts (looped back through CTM)
4. Assert ctm_src_ack (CLA acknowledges)
5. Clear ctm_dst_req
6. Verify ctm_src_req and ctm_dst_ack clear

**Pass Criteria**: All loopback routes work with proper signal assertion/deassertion.

Clock Stop Test (test_clock_stop.py)
------------------------------------

**Purpose**: Verify clock stop aggregation and gating.

**Test Sequence**:

1. Verify stop_clks_o is 0 at reset
2. Assert clk_stop_req[0] with cla_clock_stop_en = 0
3. Verify stop_clks_o remains 0
4. Set cla_clock_stop_en = 1
5. Verify stop_clks_o asserts after one cycle
6. Clear clk_stop_req[0]
7. Verify stop_clks_o deasserts
8. Test jtag_clock_stop direct path

**Pass Criteria**: Clock stop logic operates correctly.

Running Tests
=============

Prerequisites
-------------

* VCS simulator
* Python 3.8+
* cocotb

Build and Run
-------------

.. code-block:: bash

    cd hw/comp/cross_trigger_network/tb_vcs
    make clean
    make TEST=test_sanity
    make TEST=test_routing
    make TEST=test_loopback
    make TEST=test_clock_stop

Run All Tests
-------------

.. code-block:: bash

    make regression

View Results
------------

Test results are in ``sim/logs/<test_name>/``:

* ``vcs.log`` - Simulation log
* ``results_<test_name>.xml`` - JUnit results

Coverage
========

The testbench collects the following coverage:

* **Functional Coverage**: Cross trigger events, clock stop assertions
* **Code Coverage**: Line, toggle, FSM coverage via VCS

Coverage reports are generated with:

.. code-block:: bash

    make coverage

Debugging
=========

Waveform Dump
-------------

Enable waveform dumping:

.. code-block:: bash

    make TEST=test_sanity WAVES=1

View waveforms with DVE:

.. code-block:: bash

    dve -vpd sim/build/test_sanity/waves.vpd &

Log Verbosity
-------------

Increase cocotb verbosity:

.. code-block:: bash

    make TEST=test_sanity COCOTB_LOG_LEVEL=DEBUG
