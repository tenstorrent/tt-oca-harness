= Cross-Trigger Port
:description: CTP — pad-facing cross-trigger signalling module, wire-OR and point-to-point modes, architecture and interface.

[[cross-trigger-port]]

The Cross Trigger Port (CTP) is the pad-facing signalling module for
cross-trigger communication per the Open Chiplet Cross Triggering (OCCT)
specification. Each CTP connects the chiplet core logic to four I/O pads and
handles the timing and handshaking required for both wire-OR and
point-to-point signalling schemes.

== Overview

Each CTP connects to four I/O pads:

* *CT_Req_out* — cross-trigger request output.
* *CT_Ack_in* — acknowledge input (point-to-point only).
* *CT_Req_in* — cross-trigger request input (point-to-point only).
* *CT_Ack_out* — acknowledge output (point-to-point only).

Two inter-chiplet signalling schemes are supported:

* *Wire-OR* — supports a wide range of existing chiplet implementations and
  is resource efficient. Uses pulse stretching to ensure reliable detection
  across chiplet boundary delays.
* *Point-to-point* — faster, more reliable, and simpler to configure. Uses
  four-phase handshaking with CDC synchronisers at the die boundary.

== Configuration

The CTP has no build-time parameters. All operational settings are
programmed at runtime through the AXI-Lite CSR interface:

<<ctp-configuration-registers-table>> summarises the runtime controls exposed through
the CTP CSR interface.
