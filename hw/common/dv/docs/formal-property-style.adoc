[[formal-property-style]]
== Formal Property Style and Layout

This chapter fixes how formal properties are written, attached, labelled and
placed so that one property file elaborates on the open-source path and on the
licensed backends alike. The open-source path is SymbiYosys (`sby`) driving
Yosys with the yosys-slang frontend (`read_slang`). Licensed backends run from
separate integrations and read the same property files. The DTP DV root is the
reference implementation of this style (<<formal-style-example>>).

[IMPORTANT]
====
The open-source frontend elaborates the RTL and reads immediate and concurrent
`assert`, `assume` and `cover` statements whose body is a boolean expression.
It reads neither sequences and implication operators nor the `$stable`,
`$rose` and `$fell` family. Every property meant for both paths is written in
that subset. The concurrent SystemVerilog Assertions (SVA) protocol checkers
`ocah_axi_sva` and `ocah_jtag_sva` under `hw/common/dv/vip/*/sva/` and the
`OCAH_ASSERT` macro family elaborate on licensed backends only; `ocah_axi_fv`
and `ocah_jtag_fv` beside them state the same protocols' handshake rules in
the subset (<<formal-style-shared-checkers>>).
====

[[formal-style-constructs]]
=== Accepted constructs

The table records what the frontend accepts, checked by elaborating each
construct in a bound property module. "Rejected" constructs stop elaboration
with an `unsupported SVA feature` or `unsupported system task` diagnostic.

[cols="3,1,3",options="header"]
|===
| Construct | Open path | Write instead

| `label : assert/assume/cover property (@(posedge clk) disable iff (c) <bool>)`
| accepted
| --

| immediate `assert`, `assume`, `cover` inside `always_ff`, `always_comb`, `initial`
| accepted
| --

| `$past(x)`, `$past(x, n)`
| accepted
| --

| `$countones`, `$clog2`, `!==`, an `else` action block with `$error`
| accepted
| --

| `bind` with downward hierarchical references in the port list
| accepted without `--keep-hierarchy`
| --

| declaration initializer `logic q = 1'b0;`
| accepted as initial state
| --

| `default clocking`, `default disable iff`
| rejected
| explicit clocking per property; the macros supply it

| `a \|-> b`
| rejected
| `OCAH_FV_IMPLIES(a, b)`, that is `!(a) \|\| (b)`

| `a \|=> b`
| rejected
| `!$past(a) \|\| (b)`

| `##n`, `##[m:n]`, `[*n]`, `property … endproperty`, `sequence … endsequence`
| rejected
| a boolean over `$past` and helper flops

| `$stable(x)`, `$rose(x)`, `$fell(x)`
| rejected
| `OCAH_FV_STABLE(x)`, `OCAH_FV_ROSE(x)`, `OCAH_FV_FELL(x)`

| `$isunknown`, `$onehot`, `$onehot0`, `$sampled`, `$changed`, `$initstate`
| rejected
| the model is two-state, so `$isunknown` has no meaning; `$onehot0(x)` is `(x & (x - 1)) == 0`

| `@(posedge clk iff en)`, `$past(x, n, gate)`
| rejected
| gate inside the boolean expression

| `final` block
| accepted, produces no check
| licensed backends only

| `T'(2 ** x)` with an unsized literal base, in the RTL
| accepted, sized to the literal's 32 bits before the cast
| `T'(T_WIDTH'(1) << x)`; a simulator sizes the cast operand to `T`, so the
  RTL idiom decides whether the two agree
|===

[[formal-style-macros]]
=== Property macros

`hw/common/assert/ocah_fv_macros.svh` is the macro layer for property modules.
It expands on `FORMAL` alone. The simulation macros in `ocah_assert.svh` expand
only when `OCAH_INC_ASSERT` is set, which `SYNTHESIS` clears, and the open path
keeps `SYNTHESIS` defined (<<formal-style-guards>>), so they are not the
property layer.

[cols="2,3",options="header"]
|===
| Macro | Expansion

| `OCAH_FV_ASSERT(name, expr, clk, rst_n)`
| `name : assert property (@(posedge clk) disable iff (!(rst_n)) (expr));`

| `OCAH_FV_ASSUME(...)`, `OCAH_FV_COVER(...)`
| the same shape with `assume` and `cover`

| `OCAH_FV_INITIAL_RESET(clk, rst_n)`
| a first-cycle flop with a declaration initializer plus `asm_initial_reset`, which pins reset low in the initial state

| `OCAH_FV_RULE(assume, label, expr, clk, rst_n)`
| `OCAH_FV_ASSUME(asm_<label>, ...)` when `assume` is set, `OCAH_FV_ASSERT(ast_<label>, ...)` otherwise, inside a generate block `gen_<label>`; the form a shared checker uses to emit a side's rules as assertions or assumptions

| `OCAH_FV_ASSERT_I(name, expr)`, `OCAH_FV_ASSUME_I(name, expr)`
| the immediate forms, for a procedural block: at every step in an `always_comb`, such as a rule over the level of a clock, or on the edge the block is clocked on

| `OCAH_FV_IMPLIES(a, b)`
| `(!(a) \|\| (b))`

| `OCAH_FV_STABLE(x)`, `OCAH_FV_ROSE(x)`, `OCAH_FV_FELL(x)`
| the sampled-value functions written with `$past`; the edge helpers take one bit
|===

The vendored OpenTitan `prim_assert.sv` also carries Yosys macro bodies, an
`always_ff` around an immediate `assert`, selected by `YOSYS`. They are not
used as the property layer: selecting them switches every vendored primitive's
assertions to that form, temporal ones included, and they read `SYNTHESIS` as
"no assertions".

[[formal-style-guards]]
=== Preprocessor guards

`FORMAL`::
Every formal backend script defines it: `read_slang -D FORMAL` on the open
path, the equivalent define on licensed backends. It is the only macro a
property module tests. Without it the `OCAH_FV_*` macros expand to nothing,
so a property module compiles on simulation and lint filelists.

`SYNTHESIS`::
`read_slang` defines it; `--no-synthesis-define` removes it. The open path
leaves it defined, which is the view the yosys synthesis flow and the slang
lint flow elaborate: assertions under `ifndef SYNTHESIS` in vendored RTL and
the `OCAH_ASSERT` family stay out of the model. Licensed backends leave it
undefined, so those checkers elaborate there. Property modules do not test it.

`YOSYS`::
Reserved to the vendored `prim_assert.sv`, which selects its Yosys macro bodies
on it. Property modules do not test it and the open-path script does not
define it. Whether the frontend predefines it differs between yosys-slang
versions, so the generated filelist puts `hw/common/assert/yosys` first on the
include path, as the yosys synthesis flow does, and the shim there governs.

[[formal-style-attachment]]
=== Attaching a property module

Every file under the DUT's DV tree carries `<dut>_` as its prefix. Properties
live in `<dut>_<block>_props.sv`, a module of the same name with input ports
only, attached by one `bind` statement in `<dut>_<block>_bind.sv`. `<block>`
names the module the properties describe, prefixed by the formal top when
that top is not the DUT (`dtp_ctn_csr_props.sv` on the cross-trigger
network); the bind names the described module, so every instance under the
top is checked. The
RTL carries no properties and is not edited for formal. Internal signals reach
the module through the bind port list, downward hierarchical references and
struct members included; the frontend accepts them when it elaborates without
`--keep-hierarchy`, so the `.sby` script does not pass that option. Enum types
from a package are imported into the property module; module-local enums are
compared against `localparam` encodings declared there.

A formal wrapper, a top that instantiates the DUT next to the properties, is
not used: it duplicates the DUT interface, needs internal signals exposed
through the RTL, and gives the licensed backends a different top than
simulation. A `bind` file compiles unchanged on every backend and in
simulation.

[[formal-style-shared-checkers]]
=== Shared protocol checkers

`hw/common/dv/vip/ocah_axi_vip/sva/ocah_axi_fv.sv` and
`hw/common/dv/vip/ocah_jtag_vip/sva/ocah_jtag_fv.sv` are the protocol
checkers of the open path: the AXI4 and AXI4-Lite handshake, reset,
burst-legality and response-ordering rules, and the IEEE 1149.1 TAP state,
TDO and phase rules, each a boolean written with the macros above. They
carry the flat port lists of `ocah_axi_sva` and `ocah_jtag_sva` and cite the
same public specification sections; the rules that need per-ID or per-beat
history stay in the SVA checkers. Every rule belongs to the side that drives
its signals, the master (the AXI manager, the JTAG host) or the slave (the
AXI subordinate, the TAP), and the parameters `ASSUME_MASTER_RULES` and
`ASSUME_SLAVE_RULES` emit that side's rules through `OCAH_FV_RULE` as
assumptions instead of assertions. A formal environment binds one instance
with the design's side asserted and the environment's side assumed, so the
environment module states only what the protocol leaves open, such as an
outstanding bound or a single-beat fact, and a property of the design that
holds only under the protocol, such as the bridge's
`ast_j2a_resp_only_while_waiting`, is proven against the checker's
assumptions rather than against a hand-written restatement. The two SVA
checkers take the same
two parameters through `OCAH_SVA_RULE` and `OCAH_RULE`
(`hw/common/assert/ocah_sva_macros.svh`), and their
two-state rules are live under `FORMAL` as well as `SIMULATION`, so a licensed
backend binds them the same way; both default to assertions, which is the
simulation shape.

The bind of a shared checker is a `props/` file named
`<dut>_<top>_<protocol>_fv_bind.sv`, for example
`dtp_ctn_axi_fv_bind.sv` on the `cross_trigger_network` AXI-Lite port with the
manager's rules assumed and the network's asserted, or
`dtp_jtag2axi_axi_fv_bind.sv`, which binds `ocah_axi_fv` on the request
machine's side of the bridge's CDC with the responder's rules assumed. A
rule's path in every report is
`<instance>.gen_<rule>.ast_<rule>` or `asm_<rule>`, for example
`u_ocah_axi_fv.gen_axi_aw_valid_held.asm_axi_aw_valid_held`. The checkers
pin their own clock's reset through `OCAH_FV_INITIAL_RESET` and guard every
`$past` of an input with the past reset, so on a top with a second clock
domain the environment's reset model covers them too. The shared checkers'
covers name the handshakes only, so an instance binds where its channels are
reached within the task's depth; a cover on a backpressure or a response
code belongs to the design's property module. The checker files join the formal filelist through
`[build].sources` of the DUT's formal configuration.

[[formal-style-labels]]
=== Labels

`ast_` for an assertion, `asm_` for an assumption, `cov_` for a cover, then
`<feature>_<behavior>` in lower snake case, for example
`ast_tap_five_tms_high_reach_tlr`. The label is the check name in every
report: sby prints `Assert failed in <top>: <instance path>.ast_...` and
writes the same path as the JUnit `id`; licensed backends report the same
hierarchical name. Every `ast_` whose antecedent is not trivially reachable
has a paired `cov_` on the antecedent, and every `asm_` carries a one-line
rationale naming the protocol or design fact that makes it legal.

[[formal-style-reset]]
=== Reset and history

Each property module starts with `OCAH_FV_INITIAL_RESET(clk_i, rst_ni)`, so a
`$past` sampled in the first cycle after reset release reads a value from the
trace rather than an unconstrained initial state. Two rules follow.

* `$past` of an input, or of an expression over inputs, is guarded with
  `$past(rst_ni)`: the previous cycle may have been in reset, where the input
  was unconstrained while the state held its reset value. `$past` of reset
  state needs no guard.
* History deeper than one cycle uses a register the DUT already has, or a
  helper flop with a reset in the property module, not `$past(x, n)`: the
  deeper `$past` stages have no reset and are free in the first cycles.

Registered outputs reflect their inputs from the second cycle after reset
release, so a property comparing them against configuration inputs is guarded
with `$past(rst_ni)` as well.

[[formal-style-clocks]]
=== Clock modelling

sby's default abstraction advances every clock on each step and turns
asynchronous resets into step-synchronous ones; it refuses a design that
clocks flops on both edges of one clock. The JTAG logic in DTP does, so the DTP
task files set `multiclock on`: every step is a time point, a `tck` cycle costs
at least two steps of depth, and the asynchronous resets are free inputs.
Under that model a reset that changes at a sampling edge, or between two edges,
lands in the state register without the sampled `disable iff` seeing it, so
the open path needs a reset environment. It lives in
`<app>/sby/<dut>_sby_env.sv`, or `<dut>_<top>_sby_env.sv` for a top other than
the DUT, a module bound to the top and read only by the task file: it is the open-path counterpart of the clock and reset commands a
licensed backend's script issues, and it holds `asm_env_` assumptions on the
top's input ports, and on internal state where the environment stands for a
peer or a configuration bound. An assumption that one block's tasks alone
need lives in a second module beside it, `<dut>_<block>_sby_env.sv`, read by
those tasks only (`dtp_tap_sby_env.sv`). The DTP environments assert every reset up to
the first sampling edge, so each clock domain starts from its reset state,
and release all of them there for the rest of the trace; each property module
pins its own reset low in the first cycle through `OCAH_FV_INITIAL_RESET`.
With the clocks modelled, a negedge-clocked flag sampled at a `tck` posedge
has already taken the value derived from the state sampled at that same edge,
and a property can state that equality directly. A free input that a negedge
latch samples takes the shape of a posedge flop through a negedge helper
latch and a posedge-sampled assumption that the input equals it. A register
whose only role in a target is to carry data, such as a JTAG shift register,
can be a `cutpoint` in the task file: its value is then free at every step,
which shortens the covers and keeps every proof over the surrounding control
valid. The `prove` task of a multiclock top runs a property-directed engine:
k-induction cannot close a `$past` relation there, because an induction
window may hold a single edge of the property's clock and the sampled history
before it is unconstrained.

[[formal-style-layout]]
=== Layout under the DUT DV root

----
<dut-dv-root>/
  <dut>_formal_cfg.toml            runner launch fields (--mode formal)
  formal/
    props/<dut>_<block>_props.sv   property module, one per described block
    props/<dut>_<block>_bind.sv    bind statement
    props/<dut>_<top>_<protocol>_fv_bind.sv
                                   bind of a shared protocol checker (<<formal-style-shared-checkers>>)
    <app>/sby/<dut>.sby            open-path task file, one per app, the DUT as top
    <app>/sby/<dut>_<top>.sby      open-path task file for another top
    <app>/sby/<dut>_sby_env.sv     open-path clock and reset environment, one per top
                                   (<dut>_<top>_sby_env.sv for another top)
    <app>/sby/<dut>_<block>_sby_env.sv
                                   assumptions one block's tasks alone read
    build/                         generated: bender filelist, sby work directories
----

`<app>` names the check the tasks implement: `fpv` for property checking; the
connectivity, register, unreachability and X-propagation apps follow the same
shape. Optional backend integrations mirror the path under
`<dut-dv-root>/formal/<app>/<tool>/`; each tool script reads
the same `props/` files from the open tree. `formal/build/` falls under the
repository's `**/build/` ignore rule.

The `.sby` file names its inputs in `[files]` relative to the directory sby is
started from, and sby copies them into each task's `src/` directory. The
generated filelist therefore uses absolute paths, and sby runs from the `.sby`
file's directory with `--prefix ../../build/<top>`. The runner's `sby` launch
template (`tools/dv/doc/run-dv.adoc`) starts sby from the app's `cwd`, the
same directory, and places the work directories under the run directory.

[[formal-style-reachability]]
=== Cover reachability after assumption changes

Every `cov_` label stays reachable after any assumption change. An `asm_` that
makes a `cov_` unreachable has over-constrained the environment, and a proof
under it is not evidence. The `cover` task runs in the same sby invocation as
`bmc` and `prove`, and a cover that is not reached within the task depth fails
that task: status `FAIL`, exit code 2, a `<failure>` element in the JUnit
file. A run whose `bmc` passes and whose `cover` fails is a failed run. The
cover depth is set above the step at which the deepest `cov_` is reached, and
the `bmc` depth is set to the same value.

[[formal-style-toolchain]]
=== Open-path toolchain

* Yosys with the yosys-slang plugin (`plugin -i slang`), from a build that
  includes the concurrent-assertion lowering (yosys-slang releases from
  2026-05 on). `read_slang` reads the filelist with `--single-unit`, as the
  slang lint flow does, so packages and macros carry across files.
* SymbiYosys (`sby`) with `yosys-smtbmc` and `yosys-abc`. The `cover` task
  needs an SMT solver (`yices` in the task files); `abc pdr` needs none. The
  runner's tool registry names this backend `sby`, the default of the
  `native-formal` profile (`tools/dv/doc/run-dv.adoc`).
* Bender, to generate the DUT filelist.

[[formal-style-example]]
=== Worked example: the DTP TAP controller

`hw/sys/dtp/dv/formal/` holds the reference implementation. The IEEE 1149.1
TAP controller inside the primary TAP is the block described here, with `dtp`
as the formal top; the plan section of `hw/sys/dtp/dv/docs/DTP_VPLAN.adoc`
lists the other described blocks over the `dtp`, `jtag2axi` and
`cross_trigger_network` tops in the same shape.

* `props/dtp_tap_props.sv`: assertions and covers on the TAP state register
  and its outputs, all in the boolean subset: one-hot state, the rule that
  five consecutive `tms`-high cycles reach Test-Logic-Reset from any state,
  the entry and hold conditions of the reset, idle, shift and update states,
  the exclusivity of the DR and IR scan selects, and the Moore and
  negedge-clocked scan-control flags following the state. A helper flop in
  the module counts the consecutive `tms`-high cycles. Enum states come
  from `jtag_tap_pkg`.
* `props/dtp_tap_bind.sv`: binds the module to `jtag_tap_ctrlr` and connects
  the TAP control struct, the state and the scan-control struct members.
* `props/dtp_jtag_fv_bind.sv`: binds the shared JTAG checker to `dtp` on the
  primary TAP, the host's phase rule assumed and the TAP's rules asserted;
  `dtp_jtag2axi_axi_fv_bind.sv` and `dtp_ctn_axi_fv_bind.sv` do the same with
  the shared AXI checker on the other two tops.
* `fpv/sby/dtp_sby_env.sv`: the open-path reset environment
  (<<formal-style-clocks>>).
* `fpv/sby/dtp.sby`: one task triple per block on the `dtp` top, selected by
  the block's tag; the TAP triple is `tap_bmc` and `tap_cover` on `smtbmc`
  with yices at depth 30 and `tap_prove` on `abc pdr`, all under
  `multiclock on`. `dtp_jtag2axi.sby` and `dtp_cross_trigger_network.sby` beside it
  carry the other two tops.
* `dtp_formal_cfg.toml` and `testlists/formal.toml`: the runner launch entry,
  one app table and one item per block. The `flist` stage regenerates the
  filelist and the `formal` stage runs an item's three tasks in one `sby`
  invocation; the depth justification is the "Formal Verification Plan"
  section of `hw/sys/dtp/dv/docs/DTP_VPLAN.adoc`.

The runner drives the tasks:

[source,bash]
----
python3 tools/dv/run_dv.py --dut dtp --mode formal
----

By hand, generate the filelist from the repository root, then run the tasks
from the `.sby` directory:

[source,bash]
----
mkdir -p hw/sys/dtp/dv/formal/build
{
  echo "+incdir+$PWD/hw/common/assert/yosys"
  echo "+incdir+$PWD/hw/common/assert"
  bender script flist-plus -D SYNTHESIS=1 -t axi_rtl -t apb_rtl -t common_cells_rtl \
    -t common_cell_sync_shim -t register_interface_l1 -t dtp
  echo "$PWD/hw/common/dv/vip/ocah_axi_vip/sva/ocah_axi_fv.sv"
  echo "$PWD/hw/common/dv/vip/ocah_jtag_vip/sva/ocah_jtag_fv.sv"
} > hw/sys/dtp/dv/formal/build/dtp.f

cd hw/sys/dtp/dv/formal/fpv/sby
sby --prefix ../../build/dtp -f dtp.sby tap_bmc tap_cover tap_prove
----

Each task writes `<workdir>/status` (`PASS`, `FAIL`, `UNKNOWN`, `ERROR`) and a
JUnit file `<workdir>/<sby-name>_<task>.xml` with one `testcase` per label.
The runner's formal stage grades an item from these files and the `DONE`
lines in its log, never from the exit code (`tools/dv/doc/run-dv.adoc`, Formal
result grading).
