[[sep-interrupts]]
=== Interrupts

The SEP integrates a VeeR EL2 core with a built-in
**Programmable Interrupt Controller (PIC)**. All maskable external interrupt
sources feed a single `extintsrc_req` bus; the core's `meipl`, `meie`, and
`meigwctrl` CSRs configure priority, enable, and gateway polarity per source.

The PIC base address is `0xC008_0000`; its register layout is described in the
<<sep-pic-registers,Register Interfaces>> section below.

Interrupt source IDs are **1-based** inside the PIC. Source 0 is permanently
tied to zero inside the core. Firmware programs source `N` by writing the
`meipl[N]` and `meie[N]` CSR entries and reading/clearing `meip[N]`.

==== SEP CPU Interrupt Vector Map

The PIC supports 255 external sources. Slots 1–39 are individually assigned to
specific peripherals and subsystems connected to the SEP, including both
SEP-internal blocks (crypto engines, DMA, entropy) and cross-block sources
(SMC mailboxes, SPI). Slots 40–255 are reserved for chip-level external inputs
passed in at the SEP block boundary.

[[sep-non-pic-paths]]
==== Non-PIC Interrupt Paths

Three CPU interrupt pins bypass the EL2 PIC entirely.

===== NMI — Watchdog Timer Bark

The VeeR EL2 `nmi_int` pin is wired to the watchdog timer bark signal from
`sep_wdt_wrap`. When the bark fires, the CPU jumps to the NMI vector address
held in the `SEP_NMI_VEC` register. The `SEP_NMI_VEC_LOCK` register prevents
runtime modification of the vector once locked.

The NMI is non-maskable: it cannot be suppressed by `mstatus.MIE` or any PIC
configuration register.

===== Timer and Software Interrupts (TBD)

The `timer_int` and `soft_int` pins of the VeeR EL2 core are both tied to zero
at the SMU integration boundary; external CLINT-style delivery is not yet
routed. The VeeR core contains independent internal timers that generate
standard RISC-V `mip.MTIP` and `mip.MSIP` interrupts without requiring an
external signal; those remain functional.
