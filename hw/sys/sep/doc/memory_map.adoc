== Memory Map

SEP uses 32-bit addressing. The following table outlines the SEP CPU's
logical view of the SEP-local address space. External masters use the
chiplet-global base programmed in `SEP_GLOBAL_BASE_ADDR`; SEP CPU
software uses either direct internal addresses (`0x1000_0000`,
`0x1080_0000`, and so on) or the local alias view described below.

The `SEP Local Alias` row is an alternate CPU-side name for the same
hardware listed in the `SEP Local` and `SEP External` rows. For
example, `0xD000_0000` aliases `0x1000_0000` and `0xD080_2000` aliases
`0x1080_2000`. This alias range is used by SEP-local masters, while
external masters use chiplet-global addresses.

The EL2 CPU resources are mapped into a separate segment than the SEP
Local resources due to constraints on the CPU memory map. The ICCM,
DCCM, and PIC addresses in the `0xC000_0000` region are statically
configured in the CPU core module and are reached through the CPU's
internal wiring. The high local-alias mapping covers the `0xD000_0000`
and above alias view. CPU CSRs are accessed with dedicated RISC-V
instructions and do not appear in the address map.

The high local alias span has a fixed SEP-local size of 768 MiB
(`0xD000_0000` through `0xFFFF_FFFF`), corresponding to the direct
internal range `0x1000_0000` through `0x3FFF_FFFF`. The
chiplet-global SEP aperture configured by `SEP_GLOBAL_BASE_ADDR` /
`SEP_REGION_SIZE` controls the SMU xbar and inbound global-to-local
remap.

The remaining subsystems are mapped into regions 1 and 2 for the EL2 CPU.

Each row below is the aperture reserved for a unit, and the Decoded Extent
column gives the part of it that registers or memory back. The last two
columns state how SEP answers a 32-bit access that no register or memory
backs, as seen at its inbound AXI port, and

endif::backend-html5[]
ifdef::backend-pdf[]

defines them and their codes.

The TRNG aperture is forwarded in full to an adopter-defined external IP. SEP
does not decode offsets inside that window, so every access reaches the TRNG
slave. Intra-aperture decode is an integrator constraint: an address that owns
no register must return SLVERR and must not alias onto a live register. See the
{sep-integrator-guide-ref}.

The crypto region, 0x1090_0000 - 0x1094_FFFF (OTBN through ABR), accepts
single-beat transactions only; see {sep-crypto-access-ref}.

== Units Unreachable from the Inbound Port

Several SEP units are not connected to the external inbound port and answer
`DECERR` to any external access attempt. These units include the Boot ROM,
Reset Control, ICCM, DCCM, PIC, and AP/STEE remap regions. The inbound port
serves the mailbox and system CSR windows, and forwards all other addresses
below 0x4000_0000 (outside the mailbox and system CSR windows) to the SEP local
crossbar. Addresses above 0x4000_0000 and the units listed above are not
reachable through this external path and receive error responses from the
`smn_inbound` port. Their rows in the table below state what the SEP CPU sees.

=== External Window Reference Model

The SEP external-window model supplies the eFuse SHIM control register below.
The `efuse_shim_ctrl` instance at offset `0x0` fixes where that block sits.
`EFUSE_SHIM_SIZE` bytes from that base (`SEP_EFUSE_SHIM_SIZE` at the SMU,
default `0x4`) are routed to the eFuse controller, which forwards them
unchanged on `efuse_bank_ctrl` to the adopter's SHIM rather than out the
external port. An adopter external map must keep an `efuse_shim_ctrl`
instance at that offset.
Its execute-in-place region is a memory window rather than a register bank.
Adopter-specific external devices require their own register documentation.
