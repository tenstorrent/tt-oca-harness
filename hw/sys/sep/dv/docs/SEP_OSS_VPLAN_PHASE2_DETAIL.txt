================================================================================
SEP OSS VPLAN — PHASE 2 (basic-feature breadth) — LEDGER + DETAILED TEST CARDS
================================================================================
Phase 2 grows the 31-test Phase-1 baseline toward 100+ tests so every IP has its
basic functional behavior covered (>=60% of OCAH SEP basic feature intent). Rules:
the VPLAN creation rules. Summary + coverage matrix: SEP_OSS_VPLAN_PHASE2.md.
Closed Phase-1 record: verification_plan_phase1.adoc.

OCAH PROVENANCE GATE: every card's OCAH-REFS must name >=1 real OCAH test/seq/fw
(1:1 port, merge, randomized rep, or stronger re-expression). Empty OCAH-REFS =>
the card is not a Phase-2 basic-coverage test (infra-smoke is the only carve-out).

================================================================================
PART A - BASIC-FEATURE COVERAGE LEDGER (the >=60% denominator/numerator)
================================================================================
The primary Phase-2 planning artifact. One table per subsystem, filled incrementally
as that subsystem is swept. Granularity is coarse/checklist-style (modes, key/config
widths, datapath, CSR/status sanity, the cross-subsystem happy path) derived from the
OCAH tests + the IP .adoc. OCAH is the 100% denominator; advanced corner/negative
features are listed as `GAP (deferred)` so they are not lost. The >=60% read-off for
an IP is COVERED / total-basic-features, judged as a mindset not a precise number.

Outcome taxonomy: COVERED_BY | COVERED_STRONGER | MERGED_INTO | OSS_DELTA_ACCEPTED |
GAP (basic) | GAP (deferred).

Ledger row format:
 IP | basic feature (from OCAH) | OCAH test(s) | OSS coverage | outcome

SUBSYSTEM: CPU complex [toml: cpu]
--------------------------------------------------------------------------------
Scope: the VeeR EL2 core complex -- EL2 boot/run, IFU/LSU, TCM (ICCM/DCCM), CPU CSRs,
traps/NMI, the PIC + interrupt delivery to the CPU (mailbox->PIC, IP-IRQ->PIC, RISC-V
timer/soft int), CPU reset (warm/cold domains, dbg_rstb, sep_cpu_reset_n gating),
firmware PASS/FAIL harness, CPU debug. The PIC and TCM live INSIDE the core, so
interrupt delivery and CPU reset are CPU -- not a separate group. External SRAM/ROM
(Memory) and the per-IP SW-reset glue + WDT/AON-timer peripheral (Reset & timer glue)
are NOT here (see "Cross-sweep handoff"). Lens: HW-under-test, not firmware
application (boot ROM BL0/BL1 app logic is FW, not DV; we prove only that the CPU
executes from ROM).

SUBSYSTEM: Memory subsystem [toml: memory]
--------------------------------------------------------------------------------
Scope: external scratch SRAM (0x1000_0000), boot ROM AXI read-port (0x1004_0000),
memory responders, DMA<->memory visibility (CPU-visible TCM/ICCM/DCCM is CPU complex,
not here). OCAH categories: uvm_tests/sram/* (~24), uvm_tests/rom/* (~21), fw
memory_sanity/rom_sanity. RTL anchors (pinned @ 9ec8f9f4b): SRAM reached via the xbar
sram port (no_cpu CPU-LSU splice reaches it). Boot ROM is on a DEDICATED CPU port
(sep.sv:566/621 lsu_rom_axi via u_boot_rom_axi_mux, SEPARATE from the xbar-bound
lsu_axi_req_o the no_cpu splice forces) => ROM is reachable ONLY by the REAL CPU
(cpu mode), NOT by the no_cpu splice or any external master. ROM writes are silently
ignored, NOT DECERR'd (sep_rom_interface_shim.sv:43 macro_req=req&~wenable, l.53 rvalid
asserts for both read+write) => a write returns a normal response with content unchanged.
SRAM scrambler is disabled by default and ECC is not implemented in the bare-sep RTL.
