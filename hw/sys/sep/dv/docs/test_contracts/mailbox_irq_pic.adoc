[[sep_mailbox_plic_test]]
===== 3.1 `sep_mailbox_plic_test`

*Phase*: 1

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu`, `+skip_fuse_sense`

*Source Module*: `sep_mailbox_plic_test`

*BFM / Model*: ocah_axi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: Completes the interrupt path all the way to the CPU for every inbound mailbox channel, and shows the paired outbound push does not take that path.

*Test Coverage*: Inbound mailbox push to PIC to a CPU interrupt service routine, channels 0..7, plus an outbound push that must raise none of the eight PIC sources and must assert `smc_mailbox_interrupt_o` instead.

*Test Procedure*:

[arabic]
. Initialise the fabric filter. The firmware also writes the clock-gate control register, but the only field the generated map defines there is the PKA gate, so that write ungates nothing in this design and is not on the proof path.
. Register a service routine on that channel's PIC source and enable it.
. Arm the mailbox: clear pending status, set the watermark to fire on one word, enable the interrupt.
. Write one word into that channel's queue.
. Wait for interrupt; the routine claims it, raises the watermark, clears the status bits, confirms they read back clear while the enable is still set, then masks the enable. Repeat for channels 0..7.
. With all eight mailbox PIC sources enabled, push one word at the OUTBOUND channel-0 aperture and wait a quiet window. No service routine may run. The entry is left pending, so the testbench reads `smc_mailbox_interrupt_o` at end of run: bit 0 set, the other seven clear.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-DELIVER
|The service routine actually runs on every inbound channel — the interrupt reached the CPU rather than stopping at the aggregator. The host counts eight `CHK-DELIVER` lines so a skipped channel cannot hide behind the PASS magic.
|CHK-RW1C
|For each channel, the interrupt status register clears on write-one-to-clear, and the read-only pending register — derived as status AND enable — reads back zero while the enable is still fully set, so that zero is not a masking artefact.
|CHK-NOSTORM
|For each channel the routine runs exactly once — the count is compared against one, not merely printed — and the interrupt does not re-fire afterwards.
|CHK-DIRECTION
|A push at the outbound aperture raises none of the eight mailbox PIC sources, with every one of them enabled so a miswire onto a neighbour is not silent. The spec gives PIC sources 1-8 to the SMC-to-SEP (inbound) mailbox channel interrupts (`hw/sys/sep/doc/interrupts.adoc`) and gives the mailbox interrupts toward the SMC to `smc_mailbox_interrupt_o` (`hw/sys/sep/doc/port_table.adoc`).
|CHK-SMC-LINE
|`smc_mailbox_interrupt_o` reads zero before the firmware runs and `0b00000001` after it: the pending outbound push asserts bit 0. While each of the eight inbound interrupts is pending on `sep_internal_interrupts[7:0]`, the SMC-facing line does not carry that bit; every inbound interrupt must be seen pending, so the check runs inside each window. Observed on the testbench probes, not reported by the firmware.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

[[sep_irq_ip_to_aggregator_test]]
===== 3.2 `sep_irq_ip_to_aggregator_test`

*Phase*: 1

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu`, `+skip_fuse_sense`

*Source Module*: `sep_irq_ip_to_aggregator_test`

*BFM / Model*: ocah_axi_vip

*Objective*: Proves that interrupts owned by the entropy blocks, HMAC error, and DMA done/chunk/error reach the SEP interrupt aggregator on the correct bit, using each block's real interrupt-test register rather than a forced wire. After that walk, one in-window unmapped read through the Secure DMA adapter, the same hole written, and one read through each HMAC, KMAC and OTBN adapter must complete SLVERR, latch the matching `DMA_BUS_ERR_STATUS` / `PERIPH_BUS_ERR_STATUS` bit, raise aggregator bits 40 and 42, and clear on the matching CLEAR write.

*Test Coverage*: Entropy, HMAC-error, and DMA `INTR_TEST` bits plus adapter SLVERR into the aggregator.

*Test Procedure*:

[arabic]
. For each covered interrupt: clear the test register and the pending state.
. Assert the aggregator bit is low.
. Enable the interrupt and write the real test bit.
. Wait for the matching aggregator bit to assert; confirm the other covered bits stay low.
. Clear the test bit. For an Event source, confirm the aggregator bit stays high for 32 clocks and the pending state still reads 1, then clear the pending state. Wait for deassertion.
. Confirm both bus-error STATUS registers and aggregator bits 40 and 42 read 0.
. Read the unused word between the last DMA `INTR_SRC_ADDR` and the first `INTR_SRC_WR_VAL`; require SLVERR, exclusive `reg_path_err`, and bit 40.
. Write `DMA_BUS_ERR_CLEAR`; STATUS and bit 40 read 0.
. Write the same DMA hole full-width; require BRESP=SLVERR, exclusive `reg_path_err`, and bit 40, then clear again.
. Read the unused word between the HMAC CSRs and the message FIFO; require SLVERR, exclusive `hmac`, and bit 42. Write `PERIPH_BUS_ERR_CLEAR.hmac`; STATUS and bit 42 read 0.
. Repeat for the KMAC CSR/STATE gap (`kmac`) and the OTBN CSR/IMEM gap (`otbn`).

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-AGG
|All covered interrupts (CSRNG, EDN, HMAC error, DMA done/chunk/error) propagate to their expected aggregator bit and clear again — baseline-low, assert, isolation and clear all covered. Event sources stay set after `INTR_TEST=0` (aggregator bit 1 for 32 clocks, `INTR_STATE` bit 1) and clear only by W1C of `INTR_STATE`; DMA Status sources clear by `INTR_TEST=0`, and the slowest of them must drop inside those 32 clocks, so the hold is long enough to catch a state that follows the test level. "One-hot" here means one-hot among the covered bits. Bits outside that set are not compared; the logged vector shows some of them high during the walk. HMAC/KMAC `fifo_empty` Status bits are idle-true and are not walked.
|Non-vacuity (not a leaf checker)
|A non-zero number of AXI transactions was observed, so the run cannot pass having done nothing. This leaf emits no `CHK-NONVAC` of its own: the floor is the shared scoreboard's `checks > 0` activity guard (`cocotb/env/sep_scoreboard.py`). It is a transaction floor, not a per-source minimum — no assertion requires that every covered source ran. The per-source lines are what evidence that.
|CHK-BUSERR-BASE
|`DMA_BUS_ERR_STATUS` and `PERIPH_BUS_ERR_STATUS` read 0, and aggregator bits 40 and 42 read 0, before either fault. A stuck-high latch fails here.
|CHK-BUSERR-DMA
|The DMA hole read completes SLVERR, not DECERR. `DMA_BUS_ERR_STATUS` is exactly `reg_path_err`. Aggregator bit 40 is 1; bits 41 and 42 stay 0.
|CHK-BUSERR-DMA-WR
|A full-width write to the DMA hole completes BRESP=SLVERR. `DMA_BUS_ERR_STATUS` is exactly `reg_path_err`; aggregator bit 40 is 1 and bits 41 and 42 stay 0. The write walks `TL_PUT_REQ`/`TL_PUT_ACK`/`AXI_B_RESP` (`hw/common/axi/axi_lite_to_tlul.sv`), a different FSM arm from the read leg, and raises the sticky error from BRESP rather than RRESP.
|CHK-BUSERR-DMA-WR-CLR
|The CLEAR write after the write-direction fault returns `DMA_BUS_ERR_STATUS` and bit 40 to 0.
|CHK-BUSERR-PERIPH
|Each HMAC, KMAC and OTBN hole read completes SLVERR, not DECERR. `PERIPH_BUS_ERR_STATUS` is exactly that block's bit. Aggregator bit 42 is 1; bit 40 stays 0.
|CHK-BUSERR-CLR
|Each matching CLEAR write returns its STATUS word and its aggregator bit to 0. The CLEAR registers are write-only single-pulse fields that always read 0, so their read value is not graded.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Not claimed*: the bridge's `PUT_PARTIAL_DATA` opcode arm — a sub-word write is refused upstream of the bridge from this master (SLVERR, status register unchanged), so only the `PUT_FULL_DATA` arm is reachable here. DMA host-path integrity (`host_path_err` / bit 41) — this leaf does not start a DMA transfer, so the host-adapter checker never sees `a_valid`. AES, CSRNG, EDN and WDT register-bridge bits — unreachable from this testbench. For AES, CSRNG and EDN all three of the block's `d_error` sources (`reg_top reg_error = addrmiss | wr_err | intg_err`) are closed: the extents are fully packed, so no in-window address owns no register (EDN maps 18 registers in 18 words, CSRNG 24 in 24, AES 35 in 35); a sub-word write is refused upstream of the bridge (SLVERR, `PERIPH_BUS_ERR_STATUS` still 0); and the bridge generates command integrity itself so it cannot mismatch. HMAC/KMAC/OTBN differ only in having a CSR-to-memory gap inside their window. Lockstep punch-through. Per-block clear isolation: each hole is raised and cleared on its own, so no run holds two peripheral bits at once. The aggregator OR is likewise never driven by more than one source at a time. Persistence across a CPU-only reset, and the rule that a fault arriving in the clear cycle still latches, are unproven. The misaligned-offset term of both status registers is <<sep_periph_bus_err_misaligned_test>>.

[[sep_periph_bus_err_misaligned_test]]
===== 3.3 `sep_periph_bus_err_misaligned_test`

*Phase*: 1

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu`, `+skip_fuse_sense`

*Source Module*: `sep_periph_bus_err_misaligned_test`

*BFM / Model*: ocah_axi_vip

*Objective*: A misaligned CPU access inside a mapped register extent. `sep_cpu_ctrl.rdl` and `doc/interrupts.adoc` require SLVERR and the owning block's status bit.

*Test Coverage*: The misaligned-offset term of `PERIPH_BUS_ERR_STATUS`, on the `hmac` bit, and of `DMA_BUS_ERR_STATUS`, on `reg_path_err`.

*Test Procedure*:

[arabic]
. Confirm `PERIPH_BUS_ERR_STATUS` and `DMA_BUS_ERR_STATUS` both read 0, so the assertions below cannot be satisfied by stale state.
. HMAC control: read two bytes at the aligned HMAC `CFG` offset (AxSIZE=2). Require one R beat answered OKAY and both registers still 0.
. HMAC probe: read two bytes at `CFG` + 2 (AxSIZE=2). The read ends on the word boundary, so the master issues one beat. Require one R beat answered SLVERR, then SLVERR on the probe, `PERIPH_BUS_ERR_STATUS` exactly the `hmac` bit, and `DMA_BUS_ERR_STATUS` still 0.
. DMA control: read two bytes at the aligned Secure DMA `INTR_STATE` offset. Require one R beat answered OKAY and both registers unchanged.
. DMA probe: read two bytes at `INTR_STATE` + 2. Require one R beat answered SLVERR, then SLVERR on the probe, `DMA_BUS_ERR_STATUS` exactly `reg_path_err`, and `PERIPH_BUS_ERR_STATUS` still exactly the `hmac` bit.

Each probe must be one beat. A four-byte read at a word offset + 2 crosses the word and goes out as a two-beat burst, and on the crypto path `doc/crypto.adoc` § "Single-Beat Access Only" refuses it with DECERR before any beat reaches HMAC, so it never exercises the alignment check.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-MISALIGN-BASE
|`PERIPH_BUS_ERR_STATUS` and `DMA_BUS_ERR_STATUS` read 0 before the probes. A bit left set by an earlier step fails here.
|CHK-MISALIGN-CTRL, CHK-MISALIGN-DMA-CTRL
|The aligned read of the same shape completes as one OKAY beat and leaves both registers unchanged. Each probe then differs from an accepted access only in address bits [1:0].
|CHK-MISALIGN-BEAT, CHK-MISALIGN-DMA-BEAT
|The bus monitor records exactly one R beat for the probe, answered SLVERR. A burst, or any other response code, fails here.
|CHK-MISALIGN-LATCH, CHK-MISALIGN-DMA-LATCH
|The probe's response is SLVERR, and both registers read exactly the expected value: the owning block's bit latched and the other register unchanged.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Not claimed*: the same term on the AES, KMAC, OTBN, CSRNG, EDN and WDT bits. The error response's read data is not graded: no specification defines it.

[[sep_axil_mailbox_iface_rand_test]]
===== 3.4 `sep_axil_mailbox_iface_rand_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds

*Source Module*: `sep_axil_mailbox_iface_rand_test`

*BFM / Model*: ocah_axi_vip

*Randomization*: RANDCFG -- `SepMboxCfg.per_half` draws two write thresholds
from the run seed, one from the low half (1 to `MAILBOX_DEPTH`/2 - 1) and one
from the high half (`MAILBOX_DEPTH`/2 to `MAILBOX_DEPTH` - 1) of the legal
range, in seeded order, with a seeded first fill length and seeded payloads for
each. Both halves are programmed and graded on every seed; `reseed = 3`.

*Objective*: 64-bit TX FIFO, status, threshold IRQ, empty/full errors, and flush on the outbound mailbox aperture.

*Test Coverage*: Outbound mailbox TX FIFO, status, threshold IRQ, errors, and flush, at one low-half and one high-half write threshold per run.

*Test Procedure*:

[arabic]
. Run the steps below once per drawn threshold. The second run starts from the drained, error-free state the first run's flush leaves.
. Program `WIRQT` and confirm empty FIFOs in STATUS.
. Read `WRITE_DATA`: the documented constant with OKAY, and STATUS unchanged.
. Read `ERROR_FLAGS` and `IRQS` and confirm `read_error` and `eirq` are clear, then read `READ_DATA` on the empty receive FIFO: SLVERR with the documented sentinel and error flag, then clear the flag and the interrupt.
. Push native 64-bit WRITE_DATA beats across `WIRQT` and on to full, comparing STATUS and `IRQS.wtirq` against the golden after every push; grade the enable gating and the level-held re-assert.
. Push once more into the full FIFO: SLVERR with the documented error flag and interrupt, both read clear before the push. Flush the transmit FIFO.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-NONVAC
|Step 2. The empty transmit FIFO is reflected in STATUS, compared field-by-field against the mailbox golden. Receive-FIFO bits stay at their empty-reset values because this aperture never fills RX.
|CHK-64B
|Step 5. Native 64-bit writes each occupy exactly one FIFO entry, so `depth` pushes reach exactly full. Occupancy is compared against the golden after every push, which is what makes the one-entry-per-beat claim real — a 32-bit split would trip `full` early. The transmit FIFO is write-only on this aperture, so payload survival is not claimed.
|CHK-WIRQT
|Step 5. `STATUS.write_level_above` and the write-threshold interrupt state match the golden prediction after every push, in each half of the threshold range, the pending register is gated by the enable (IRQP drops when IRQEN is cleared, IRQS stays), and the interrupt re-asserts after write-one-to-clear while still above threshold.
|CHK-ERR-RD
|Step 4. `read_error` reads clear before the access. A read of the empty FIFO returns SLVERR, the `0xFEEDDEAD` sentinel, and a sticky read-error flag with read-clear semantics. Both the sentinel and the `read_error` flag are the documented contract (`hw/ip/axi_lite_mailbox_unit/doc/interface.adoc`). The golden takes those values from `env/sep_spec_tables.py`. Deny is distinguished three ways.
|CHK-ERR-IRQ / CHK-ERR-WR / CHK-ERR-WR-IRQ
|Steps 4 and 6. The error interrupt reads clear before each error access, sets after it, and clears on write-one-to-clear; a write to the full FIFO returns SLVERR and sets the write-error flag, with its own interrupt.
|CHK-FLUSH
|Step 6. The control flush drains the transmit FIFO below the write threshold: not-full afterwards, and the threshold interrupt clears. Occupancy to empty is not observable on this aperture.
|CHK-WDATA-RD
|Step 3. The push register is write-only: a read of it returns the documented `0xFEEDC0DE` constant (`hw/ip/axi_lite_mailbox_unit/doc/interface.adoc`) with an OKAY response — not a FIFO entry and not an error — and leaves the transmit occupancy unchanged, re-compared against the golden afterwards. The golden takes the sentinel from `env/sep_spec_tables.py`.
|===

*Pass Criteria*: Every named checker PASSes in both runs of the steps, and each PASS line logs the register values it read. The test declares every checker as required evidence, so a run that omits one fails. UVM_ERROR == 0.

*Not claimed*: the read half of the threshold pair. `RIRQT` and
`STATUS.read_level_above` need the receive FIFO filled from the peer side,
which this aperture cannot do, so the golden predicts `read_level_above` as
constant false and no vehicle grades it. Data round-trip readback is not
claimed for the same reason. Both need the external inbound master — see
<<known-limitations>>.

[[sep_mailbox_peer_rx_rirqt_test]]
===== 3.5 `sep_mailbox_peer_rx_rirqt_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`) plus the external SMN-inbound master, `+skip_fuse_sense`

*Source Module*: `sep_mailbox_peer_rx_rirqt_test`

*BFM / Model*: ocah_axi_vip (CPU-LSU and external master)

*Objective*: `fabric.adoc`: the mailbox registers sit on an 8-byte stride and a register's low and high halves alias to the same register, so "a read of `READ_DATA` at either half pops one FIFO entry. The mailbox drives the whole entry; the CPU keeps the half selected by address bit 2 and discards the other. Reading both halves consumes two entries." That, the data round-trip readback, and the read half of the threshold pair all need a value in the receive FIFO, which only the peer aperture can place there.

*Test Coverage*: Peer-filled receive FIFO: round-trip readback, pop-per-read at either half with the discarded half lost, the `RIRQT` read threshold with its interrupt, and the inbound filter gating that live peer path both ways.

*Test Procedure*:

[arabic]
. Bring up in `no_cpu` mode with fuse sense skipped and ungate the mailbox clock.
. Program one inbound-filter entry to allow reads and writes over the peer aperture. The filter blocks by default, so without this the external master cannot reach the register and every check below would be vacuous.
. Read `STATUS` and `READ_DATA` before the peer writes anything, and read `ERROR_FLAGS` twice.
. Push two 64-bit entries whose four halves are all distinct, from the external master, at the peer aperture's `WRITE_DATA`. A non-OKAY response here fails immediately rather than being carried into the checks.
. Read `READ_DATA` at the low half, then at the high half, and compare each against the entry halves.
. Program `RIRQT`, enable `rtirq`, write-1-clear `IRQS.rtirq` and read `IRQS` and `IRQP`. Fill to exactly the threshold and read `STATUS` and `IRQS`; fill above it and read `STATUS`, `IRQS` and `IRQP`; then drain back to exactly the threshold.
. Close the allow window, repeat the peer write, and read `STATUS` either side of it. Then reopen the window and repeat the write once more.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-RX-EMPTY
|Before the peer writes, `STATUS.empty` is set, a read returns SLVERR with the documented empty sentinel, and `ERROR_FLAGS.read_error` is set and then read-clears. This is the control for everything below: if the receive FIFO answered the same way whether or not the peer had written, none of the following checkers could fail.
|CHK-PEER-RX
|The low-half read returns the low word of the first entry the peer pushed. This is the data round trip the host aperture alone cannot show, and because CHK-RX-EMPTY established the FIFO was empty first, a match cannot come from a stale or constant read.
|CHK-POP-PER-READ
|One 4-byte `READ_DATA` beat pops one whole entry. The second read, taken at the other half, returns the second entry rather than any part of the first, and `STATUS.empty` is set again after two reads of two entries.
|CHK-HIGH-HALF-LOSS
|The high-half read does not return the high word of the first entry. This is the specified behaviour and it is the opposite of the intuitive one: two 32-bit reads do not reassemble one 64-bit entry, they consume two entries and the discarded half is lost. A DUT that packed two reads into one entry fails here, and it is the reason the two entries are chosen with four distinct halves.
|CHK-RIRQT
|`RIRQT` reads back as written; `STATUS.read_level_above` is clear on an empty FIFO, set once the fill exceeds the threshold, and clear again at exactly the threshold, matching the strict greater-than the write half already uses. `IRQS.rtirq` is sticky and the two earlier pushes already exceeded the reset `RIRQT`, so it is cleared first and must read 0 in `IRQS` and `IRQP`; it must stay 0 at exactly the threshold, and only then, once the fill exceeds the threshold with `rtirq` enabled, is it raised and reaches `IRQP` through the enable gate.
|CHK-FILTER-DENY
|With the allow window closed, the same peer write that succeeded a moment earlier takes DECERR from the filter error slave and `STATUS` does not move. The refusal is measured on a path a healthy design has just been shown to complete, rather than against a bus that might be dead, which is what makes it a real deny rather than an absence of traffic. A DECERR that still enqueued would fail the second half.
|CHK-FILTER-REOPEN
|Reopening the window restores the peer write and the receive FIFO moves again. This is the positive control for CHK-FILTER-DENY: without it, a permanently broken peer path would satisfy the deny.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Evidence*: `CHK-RIRQT-CLEAR` (the cleared `rtirq` before the fill) and `CHK-RIRQT-AT` (flag and `rtirq` still clear at exactly the threshold) are PASS records within CHK-RIRQT; a failure of either reports as `CHK-RIRQT FAIL`.

'''''

[[sep_mailbox_datapath_walk_test]]
===== 3.6 `sep_mailbox_datapath_walk_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`) plus the external SMN-inbound master, `+skip_fuse_sense`, 3 seeds

*Source Module*: `sep_mailbox_datapath_walk_test`

*BFM / Model*: ocah_axi_vip (CPU-LSU and external master), `SepMboxWalkCfg` (`seq_lib/sep_mailbox_walk_seq.py`)

*Randomization*: RANDCFG -- the mailbox order, the start bit of each walk, the
strobe runs and their data, and every inbound request attribute (AxID 1 to 63,
AxPROT, a non-reserved AxCACHE, AxQOS, AxREGION, AxUSER, WUSER, ARLOCK on
reads) come from the run seed (`SepMboxWalkCfg`, `SepInboundAttrs`). Every
mailbox, every bit position, both directions and every byte lane are walked on
every seed; `reseed = 3`.

*Objective*: `hw/sys/sep/doc/mailbox.adoc`: each of the eight mailboxes holds two FIFOs of eight 64-bit entries, and `WRITE_DATA` in one port pushes the FIFO that `READ_DATA` in the other port pops; a write pushes one entry. The inbound filter decides on the address, `prot[1]`, `user[3:0]` and `AxLEN` only (`hw/ip/axi_filter/doc/index.adoc`, "Match, Then Permit"), so the other request fields of an admitted access must not change the data.

*Test Coverage*: The data path of every mailbox in both directions, on both ports, under seeded inbound request attributes.

*Test Procedure*:

[arabic]
. Bring up in `no_cpu` mode with fuse sense skipped. Program two inbound-filter entries per mailbox over exactly that mailbox's inbound register map, one with `allow_ns = 1` and one with `allow_ns = 0`, both read+write, `src_id = 0`, `allow_burst = 0`. The inbound and outbound ports interleave at 0x800, so a window over several inbound ports would also hold the outbound ports between them; one window per port avoids that.
. Read STATUS of both ports of every mailbox.
. For each mailbox in seeded order, and for each direction: push a walking one then a walking zero over all 64 bits, eight entries at a time, on the writing port; read STATUS on both ports; pop the eight entries on the other port and compare; read STATUS on the reading port. The host port is the CPU-LSU master; the peer port is the external master.
. For each mailbox and direction, push eight partial-strobe entries, entry _j_ a contiguous byte run at an unaligned `WRITE_DATA` address that contains lane _j_, and pop them on the other port.
. Read STATUS of both ports of every mailbox again.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-MBX-EMPTY
|Before any push, STATUS.empty is set and STATUS.full is clear on both ports of every mailbox. It is the control for the compares and for CHK-MBX-NO-LEAK.
|CHK-MBX-H2P-WALK / CHK-MBX-P2H-WALK
|Each of the 1024 words per direction pops on the other port bit-exact and in push order. A stuck, swapped or crossed data bit on either port of any mailbox, a reordered FIFO, or a lost or duplicated entry fails a compare.
|CHK-MBX-DEPTH
|STATUS is read on both ports after every push and every pop, so both flags are graded at every depth from 0 to 8: on the writing port STATUS.full is set only with eight entries queued, and on the reading port STATUS.empty is set only with none queued.
|CHK-MBX-STROBE
|A partial-strobe push at an unaligned `WRITE_DATA` address pushes one entry, and that entry pops with every strobed byte in its own lane.
|CHK-MBX-RESP-ID
|Every peer access answers OKAY (EXOKAY allowed on an exclusive read) and returns a BID / RID equal to the AWID / ARID it issued.
|CHK-MBX-NO-LEAK
|After the walk both FIFOs of every mailbox are empty again on both ports, so no push reached a mailbox other than its own.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Not claimed*: the zero fill of unstrobed bytes. The VIP drives the unstrobed `WDATA` lanes to zero, so a mailbox that passed those lanes through would pop the same entry. Exclusive-write semantics: AWLOCK stays 0, because an exclusive write a slave refuses leaves the target unchanged and the SEP documents do not state whether the mailbox supports exclusive access.

'''''

[[sep_irq_simultaneous_fanin_no_alias_test]]
===== 3.7 `sep_irq_simultaneous_fanin_no_alias_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`

*Source Module*: `sep_irq_simultaneous_fanin_no_alias_test`

*BFM / Model*: ocah_axi_vip

*Randomization*: none. Each source alone and all eleven subsets of two or more
of the four cross-IP sources walk on every run.

*Objective*: Simultaneous IP-IRQ fan-in into the aggregator: one-hot map, no alias, RW1C clear.

*Test Coverage*: Simultaneous IP-IRQ fan-in: one-hot map, no alias, RW1C clear.

*Test Procedure*:

[arabic]
. Fire each of the four sources alone and require exactly its one aggregate bit.
. For each of the eleven subsets of two or more sources, fire the subset together; the `[8:33]` region must equal exactly the driven mask.
. Re-sample the region raw and require every bit in it to be resolved.
. Write-one-to-clear each source and require the region to return to zero.

*Checkers*:

[cols="2,5",options="header"]
|===

|CHK-NONVAC

[[sep_pic_irq_source_map_delivery_test]]
===== 3.8 `sep_pic_irq_source_map_delivery_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu`, firmware `pic_irq_source_map_test`, `+skip_fuse_sense`

*Source Module*: `sep_pic_irq_source_map_delivery_test`

*BFM / Model*: ocah_axi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Randomization*: RANDCFG — the three required sources (mailbox, OTBN done, HMAC done)
and all eight extras (DMA done/chunk/error, HMAC-err, KMAC, CSRNG, EDN, KMAC-err)
walk on every seed, so every run grades every catalog source. The seed sets only
the order in which the extras are raised, so the test runs one seed per regression.

*Objective*: Prove the PIC delivers every source in the firmware catalog to the CPU with one-hot claim and its clear: write-one-to-clear of `INTR_STATE` or IRQS for the event-type sources and the mailbox, and `INTR_TEST` back to 0 with a write-one clear of `STATUS` for the three DMA sources, whose `INTR_STATE` is read-only: the three required sources and all eight extras on every seed.

*Test Coverage*: PIC delivers all eleven catalog sources with one-hot claim and the clear of each source (write-one-to-clear, or `INTR_TEST` back to 0 for the DMA sources).

*Test Procedure*:

[arabic]
. Patch the three required sources and all eight extras, in the seeded order, into the firmware DTCM parameter block.
. Boot the `pic_irq_source_map_test` firmware. The firmware prints its banner and a `SCENARIO` line with the source list it resolved.
. The firmware registers one handler per selected source, sets gateway, priority and enable, and arms each IP interrupt enable and the mailbox IRQ. It waits a quiet window and requires no handler run, no unexpected claim and a zero dummy-handler count (CHK-NONVAC).
. For each selected source in turn, the firmware snapshots the per-source counters and triggers the source: a mailbox FIFO push for the mailbox, `INTR_TEST` for the others. It requires the counter that the claim id selects to rise (CHK-DELIVER), no other selected counter to change (CHK-ONEHOT), and the IP state bit or IRQS to read set before the handler clear and 0 after it (CHK-IP-RW1C).
. After the walk, the firmware waits a second quiet window. It requires no counter change and no unexpected claim (CHK-PIC-COMPLETE), and a zero dummy-handler count (CHK-DUMMY).
. On the host, require the logged `SCENARIO` line to match the Python config exactly (CHK-RANDCFG).
. Require each whole-run checker line, and exactly one `CHK-DELIVER`, `CHK-ONEHOT` and `CHK-IP-RW1C` line per selected source. Then require the PASS verdict (CHK-FW-REPORTED).

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-NONVAC
|No spurious interrupt service before any trigger, over a quiet window with every selected source's interrupt enable already armed. The default vector-table handler increments `sep_dummy_int_count`; a non-zero count fails this checker, so an unregistered source cannot be swallowed silently.
|CHK-DUMMY
|After the source walk the same dummy-handler count is still 0, so an unregistered source did not fire during delivery either.
|CHK-DELIVER
|Each source's interrupt reaches the CPU and its handler runs. This also *carries the source-to-PIC-id map*, but by the claim id rather than by which handler ran: the firmware registers ONE shared service routine for every non-mailbox source, so the identity of the running handler distinguishes nothing among them. The routine reads the claim id out of `meihap` and increments the per-source delivery counter selected by that id, and the test waits on that specific counter. A wrong id therefore resolves to no selected source, or to a different one, and the wait expires either way.
|CHK-ONEHOT
|Triggering one source does not fire another *selected* source. Every selected PIC source stays interrupt-enabled throughout, including after the mailbox ISR (WIRQT is raised past occupancy rather than masking IRQEN). The selection is the whole firmware catalog; sources outside it are not observed, so this is not a claim about the full aggregator.
|CHK-IP-RW1C
|Event-type sources and the mailbox clear by write-one-to-clear of `INTR_STATE` / IRQS. DMA is Status-type: `INTR_STATE` is read-only, and the ISR writes INTR_TEST=0 (and W1C `STATUS`). The clear is bracketed: the ISR reads the IP state bit (or IRQS) set immediately before its clear, and the bit reads 0 afterwards, so a clear that did nothing fails.
|CHK-PIC-COMPLETE
|No source re-fires after its handler cleared it — the claim completed, no storm. An unexpected PIC claim during that window also fails. The quiet window runs with every selected source still interrupt-enabled.
|CHK-RANDCFG
|Firmware consumed the patched three required sources plus all eight extras in the seeded order: the logged `SCENARIO` line must match the Python config exactly, which is what rules out an inert patch running only the compiled-in MUST trio. The firmware's own line here reports only that its parameters resolved — the compiled default satisfies that — so the host-side needle owns this contract.
|CHK-FW-REPORTED
|Every firmware checker above appears in the console, AND the per-source checkers appear once per selected source. The pass magic cannot show that a source was skipped or that a check was compiled out; a line count short of the selected-source count can. The pass verdict itself is asserted before any summary line is logged, so a kept log cannot carry a PASS summary under a failing verdict.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Not claimed*: "wake on wait-for-interrupt, not by polling". The wait helper loops
on a `wfi` and a counter, so a `wfi` implemented as a no-op degenerates to a spin
poll and yields the same pass.

[[sep_spi_ot_host_csr_irq_rand_test]]
===== 3.9 `sep_spi_ot_host_csr_irq_rand_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds

*Source Module*: `sep_spi_ot_host_csr_irq_rand_test`

*BFM / Model*: ocah_axi_vip

*Objective*: OpenTitan SPI host CSR reset, R/W, interrupt test, and error-status W1C.

*Test Coverage*: SPI host CSR reset, R/W, interrupt test, and error-status W1C.

*Test Procedure*:

[arabic]
. Read the eight control registers at documented reset with STATUS idle.
. Walk each read/write register: write, read back, then drive its unimplemented bits and require them to read zero without disturbing the writable ones.
. Drive a 64-bit CONTROL write that enables only four payload bytes, so the neighbour STATUS half arrives with no strobe.
. Drive each interrupt source: Event latch and Status force first with the enable clear, then raise `INTR_ENABLE` and sample aggregator bit 13.
. Induce each of the five claimed error conditions in turn and write-one-to-clear it.
. For one transmit watermark from 2-4 and one from 5-8, in seeded order, fill the transmit FIFO across the programmed watermark.
. Measure the enabled command drain, then hold the same command off with `SPIEN=0` and `OUTPUT_EN=1` for a multiple of that measurement, then set `SPIEN` alone to release it.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-RESET
|Eight control registers read their documented reset values and the status register reads idle. Six of the eight expect zero, which a tied-off decode would also return — mitigated within this entry by the writability, interrupt and error checks below, each of which drives a register non-zero.
|CHK-REG-RW
|Each read/write register accepts a write and reads it back exactly. Each register that HAS unimplemented bits additionally has those bits driven to one and confirmed to read back zero, with the writable bits undisturbed. The probe pattern is derived from the register's implemented mask, not from the walk mask: `CONTROL.SW_RST` is implemented and outside the walk, since driving it would soft-reset the core mid-walk. `CSID` implements all 32 bits and so has no unimplemented half to probe.
|CHK-NONVAC
|EVERY walked register's readback differs from its own observed pre-write value. Where a seeded value happens to equal what the register already holds, the test flips the lowest writable bit instead, so no register on any seed can satisfy this by writing back what was already there.
|CHK-INTR
|`INTR_STATE.ERROR` is an Event latch: `INTR_TEST` sets it with `INTR_ENABLE` clear, aggregator bit 13 stays 0, a write of 0 to `INTR_TEST` does not clear it, `INTR_ENABLE` then raises the aggregator, and write-one-to-clear drops both. `INTR_STATE.SPI_EVENT` is Status-type: it tracks the `INTR_TEST` force, stays off the aggregator while the enable is clear, and follows the enable gate. The wrapper OR of the two core lines is the aggregator sample.
|CHK-ERR-W1C
|Five error conditions (UNDERFLOW, CMDINVAL, CSIDINVAL, OVERFLOW, CMDBUSY) are each induced by their own trigger, observed set, and cleared by write-one-to-clear, with a clean precondition asserted first. Each trigger must set its OWN bit and no other: the clean precondition makes exclusivity checkable, and without it a device that raised every error bit on any stimulus would satisfy all five legs. The OVERFLOW and CMDBUSY triggers find the boundary from the DUT's own `STATUS.TXFULL` / `STATUS.READY` report and then write one beat past it, so no FIFO depth is imported as a golden. The sixth bit the register block defines, ACCESSINVAL, is *not claimed*: its documented trigger is a TXDATA write with no bytes enabled, which neither this AXI master nor the wrapper's zero-strobe ack presents to the core.
|CHK-WATERMARK
|`STATUS.TXWM` follows the documented polarity (upstream `spi_host` `STATUS.TXWM`: set while TXQD is below `CONTROL.TX_WATERMARK`): set while empty and at occupancy `wm-1`, clear at the exact watermark and after filling past it, with `TXQD` read at each step. Graded for one watermark from each half of the 2-8 draw range on every seed.
|CHK-ENABLE
|`CONTROL.SPIEN` alone gates command execution: with `SPIEN=0` and `OUTPUT_EN=1` (pad buffers on, which is legal) the queued command is held off, and a write that changes only `SPIEN` to 1 drains the transmit FIFO. Both `CONTROL` values are read back and logged, so a device that gated commands on `OUTPUT_EN` instead fails the hold leg. The negative window is not a constant: the test first measures how many polls the same one-word command takes to drain with the core ENABLED, then requires the disabled command to survive a fixed multiple of that measurement, with `TXQD` still 1 and `TXEMPTY` clear at the end of it. A device that ignored the enable but merely executed slowly would pass a hand-picked window; it cannot pass a calibrated one.
|CHK-ZERO-STRB
|A 64-bit beat (`AxSIZE=3`) that writes only the 4-byte CONTROL half returns OKAY, the CONTROL readback matches the written value, and `ERROR_STATUS` stays 0. The empty STATUS half is the neighbour the 64-to-32 downsizer presents with `WSTRB==0`; without the wrapper ack that beat is SLVERR from the upstream register file.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

===== 3.10 `sep_locked_field_access_irq_path_test`

*Phase*: 2

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu`, real fuse sense (no `+skip_fuse_sense`), `LC_PROD`

*Source Module*: `sep_locked_field_access_irq_path_test`

*BFM / Model*: ocah_axi_vip

*Objective*: Stage the spare field's lock bits in the OTP image (same spare-slot geometry as <<sep_efuse_program_lock_matrix_test>>), sense at `LC_PROD`, then access the *shadow* aperture.

*Test Coverage*: Locked-field write refuse and the matching interrupt path.

The shared config draws four distinct spares and stages `SIP_DIS` /
`SYS_DIS` at 0. That is this leaf's seed-to-image map.

*Test Procedure*:

[arabic]
. Stage write-lock and read-lock on two seed-selected spare fields, plus an unlocked spare as contrast, in one OTP image, and sense at `LC_PROD`. Require `[33]` low before any shadow access.
. Access the shadow aperture for each of the three, watching the interrupt probe for the duration of each access beat.
. Write and read back the unlocked spare (CHK-UNLOCKED).
. Every seed, walk write-lock first: read the write-locked spare, write its complement, and read it again (CHK-WRITE-LOCK).
. Then walk read-lock: read the read-locked spare (CHK-READ-LOCK).

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-UNLOCKED
|Unlocked spare write/read never raises `[33]`; readback matches the write.
|CHK-WRITE-LOCK
|Bit [33] during the write, following read equals pre-write, bit [33] low after retire. BRESP is logged, not graded.
|CHK-READ-LOCK
|Bit [33] during the read, RDATA differs from the stored field value, bit [33] low after retire. RRESP and RDATA are logged, not graded. The staged pattern never equals the error-slave value named in `hw/ip/efuse/doc/architecture.adoc`, so a readback of that value still differs.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Scope*: This is not an OTP program: the program-lock vehicle owns `PROGRAM_ERR`. The unlocked spare in the same image is the negative control. The specification states write-lock and read-lock as two separate lock bits per field, so both are walked every seed.

*Facts that decide the checkers*: `hw/sys/sep/doc/otp_fuse_controller.adoc`
(Fuse Fields) says a write-locked shadow register is not writable and a
read-locked shadow register is not readable. It names no AXI response code and
no read data for a locked shadow access, so neither is graded; both are logged.
Consequently:

* *Write-lock* — the denial proof is `[33]` high during the write, then a read
  of the same field (write-lock does not block reads) returning the pre-write
  value.
* *A read-lock has no following legal read* — `LOCKS` are OTP W1S, so the field
  stays read-locked. The read itself is the denial proof: RDATA is not the
  stored field value, and `[33]` is high during the beat. The scoreboard does
  not grade the locked read's response code; a locked read that times out
  still fails.
* *The interrupt is combinational and pulse-only* — there is no sticky status bit
  and no `W1C` on this path, so the clear contract is deassertion after the
  access retires. `sep_internal_interrupts_probe_o` must be watched continuously
  across the beat; a sample taken after the access completes is always 0.

*Anti-vacuity*: the locked and unlocked accesses are the same driver, the same
aperture and the same run, differing only in the lock bits of the field, so a
probe stuck low fails the assert leg and a probe stuck high fails the unlocked
leg. The deassert leg is credited only after the assert leg has been observed
high. The denial conjunct (unchanged write-lock readback / read-lock data that
is not the stored value) attributes `[33]` to the locked path.

*Not claimed*: end-to-end delivery to the CPU — PIC claim, masking and ISR entry
— which needs `cpu` mode and a firmware image. This entry is
generate-and-deassert on both lock flavours of one seed-selected spare; the
`SecureTmLock` fields are graded by <<sep_efuse_secure_tm_write_lock_test>>.

[[sep-vplan-phase3-mailbox-irq-pic]]
==== 3. Mailbox, IRQ, PIC, Phase 3

All paths in this section are relative to the repository root. Source numbers
follow the SEP CPU interrupt vector map in `hw/sys/sep/doc/interrupts.adoc`:
bit `i` of the aggregate vector is PIC source `i + 1`, and sources 40 to 43 are
the token match fault, the DMA register-path error, the DMA host-path error and
the peripheral bridge fault.

Common rules for every Phase 3 entry in this section:

* The spec and the RDL are the only golden. No RTL, no test and no value read from the DUT is a golden.
* Probe names. `sep_internal_interrupts_probe_o` is the testbench mirror of the vector that drives the PIC. `smc_mailbox_interrupt_o` is a SEP port (`hw/sys/sep/doc/port_table.adoc`).
* Observation class. Each entry lists its probes and injects under *Probes and injects* and marks each added hook as an added hook. An item without a mark exists in `hw/sys/sep/dv/tb/tb_top.sv` and is listed in `hw/sys/sep/dv/docs/SEP_TB_ARCH.adoc`: the vector probe `sep_internal_interrupts_probe_o`; the DUT boundary ports `smc_mailbox_interrupt_o`, `wdt_timer_rst_req_o` and `m_axi_*`; the CPU-LSU master on `s_axi_*` in a `no_cpu` leaf; the CPU trace `cpu_trace_*`; and the firmware console and the firmware CSR reads in a `cpu` leaf. `crypto_alert_pulse_probe_o`, `pic_rd_data_probe_o` and `sep_cpu_ctrl_err_pulse_probe_o` are observation taps the test adds to the SEP_TB_ARCH observation-probe list. They read only, and a check on them is graded. Two added hooks (<<sep-vplan-credit-rules>>) serve this section. The drive of the boundary input `sep_ext_interrupts_i` (`extintsrc_req_i` of `sep`, tied to 0 in `tb_top`) is a top-port drive that the test adds to the HDL Top port table of `SEP_TB_ARCH.adoc`. The response control of the outbound responder on the `sep` input `smn_outbound_axi_resp_i` (a non-OKAY response or a response hold; without it `sep_outbound_mbx` answers OKAY at once) is an error inject that the test adds to the inject exceptions of `SEP_TB_ARCH.adoc`. An added hook blocks no check. A check that needs a value that the specification does not state is a blocked check, marked `Blocked: <value>` (<<sep-vplan-credit-rules>>). It is not a reached check. The leaf logs the value and does not grade it.
* Inbound mailbox lines. The inbound line of mailbox `m` is bit `m` of the mirror, which is PIC source `m + 1` (`hw/sys/sep/doc/interrupts.adoc`, "SEP PIC source assignments", rows 1 to 8; `hw/sys/sep/doc/mailbox.adoc`).
* Outbound mailbox lines. The eight outbound-port interrupts leave SEP as eight bits of `smc_mailbox_interrupt_o` (`hw/sys/sep/doc/mailbox.adoc`; `hw/sys/sep/doc/port_table.adoc`). No text states which mailbox sits on which port bit (see <<sep-vplan-phase3-blocked,Blocked features>>). No leaf compares a port bit to a mailbox index, and no leaf uses a map that it observed on the DUT as an expected value. A leaf grades the port as a set. The number of high bits equals the number of outbound ports whose model line is 1. The Hamming distance between two quiet samples equals the number of outbound ports whose model line changed between them. The port reads 0x00 when every model line is 0 and 0xFF when every model line is 1. When exactly one outbound line rises, the leaf logs the port bit that rose (`OBS-SMC-MAP mbox=m bit=o`). The log is not graded.
* Excluded idle bits. The specification states no idle level for source 13 (the WDT aggregate), source 15 (the Key Manager mailbox line; the reset level of the Key Manager mailbox status bits is open, see <<sep-vplan-phase3-blocked,Blocked features>>), source 16 (which entropy source causes it carries is not stated), source 37 (`pool_low`) and source 38 (`fill_stall`). `hw/sys/sep/doc/interrupts.adoc` ties source 39 (the pointer fault) to zero, and `hw/sys/sep/doc/entropy_pool.adoc` says the integrity fault is also raised to the PIC, so source 39 is masked because the two files disagree. The six sources are vector bits 12, 14, 15, 36, 37 and 38 and `meip` bits 13, 15, 16, 37, 38 and 39 (see <<sep-vplan-phase3-blocked,Blocked features>>). No leaf drives them. Every compare of the vector or of `meip` that expects 0 or an exact vector masks these six bits, and the leaf logs their value (`OBS-IDLE-UNSTATED src13=a src15=f src16=e src37=b src38=c src39=d`).
* Source drive recipe. A mailbox source is driven through the inbound port of mailbox `k` (index 0 to 7), which is PIC source `k + 1`: `IRQEN.wtirq` 1, `WIRQT` 0, an open inbound filter window and one pushed word. It is released by a pop of that word from the outbound `READ_DATA` of the same mailbox and a write of `IRQS` bit 0 of the inbound port. An OpenTitan source whose `INTR_STATE` bit is RW1C (an event) is driven by its `INTR_ENABLE` bit and its `INTR_TEST` bit, and released by `INTR_TEST` 0 and a write of 1 to its `INTR_STATE` bit. An `INTR_STATE` bit of access R (a status) has no write-one-to-clear: the leaf takes its expected level from the stimulus model (the set-up that makes the status read 1 and the `INTR_ENABLE` value that the leaf writes). The IP read-back of `INTR_STATE` and `INTR_ENABLE` is a control and never sets the expected value. The leaf releases the source by clearing its `INTR_ENABLE` bit, the gate that the register text states. Entries name a source by its PIC source number and a mailbox by its index `k`.
* Mailbox FIFO model. Pair `m` has FIFO A and FIFO B, each 8 entries of 64 bits. The outbound aperture writes A and reads B. The inbound aperture writes B and reads A (`hw/ip/axi_lite_mailbox_unit/doc/architecture.adoc`, "Paired FIFOs"). A write threshold event is occupancy of the write FIFO strictly above `WIRQT`. A read threshold event is occupancy of the read FIFO strictly above `RIRQT`. Both thresholds clamp to 7 (same file, "Interrupts"). The golden model is written from this text.
* Mailbox drivers. The CPU-LSU master drives outbound apertures. The external SMN master drives inbound apertures through one inbound filter window per port with `SEP_DBG` off. A window over a whole 4 KiB pair also admits the outbound port (`hw/sys/sep/doc/mailbox.adoc`).
* Extends. An entry that shares stimulus and run mode with an open test extends that test and lists only the cells that the open test does not grade. An entry is a separate leaf only for a different run mode, tool, reset state or injected illegal flow, and it says which one.
* A level check grades the end state after a quiet window. No check grades the clock of a transition.
* Reserved bits. A graded compare of a register read covers only the bits of the RDL fields of that register (`axil_mailbox.adoc`, `sep_cpu_ctrl.adoc`, `el2_pic.adoc` and the other register descriptions that an entry cites). A bit whose RDL row is `Reserved` with no access and no reset value has no stated value: the compare masks it, and the PASS line logs it as `rsvd=0x<v>`. A register value in a check or a step of this section (`ERROR_FLAGS` reads `0x1`, `DMA_BUS_ERR_STATUS` equals 0b10, a timeout count reads 0x1, a clear register reads 0) is the value of the field bits. The read data of an offset that holds no register keeps its full-word compare where the memory map states it (a mailbox or PIC hole reads 0x0).
* Log lines. A check prints `CHK-<NAME> PASS <key>=<value> ...` on pass and `CHK-<NAME> FAIL ...` on fail. A leaf prints `SEED seed=<S>` first and `DRAW <name>=<value>` for every drawn value. The host counts the expected `CHK` lines of each check. A leaf passes only when every named check prints PASS and no error is reported. A missing line fails the leaf. A clean simulator exit is not evidence. A firmware test prints the same line shapes on the console, and the host also gates on the pass or fail magic word of the firmware. A blocked check prints `OBS-<NAME> LOG ...` and never `CHK-<NAME> PASS`.
* Random stimulus is a pure function of the seed. Every draw uses `SepSeededRng`. A firmware test receives the drawn values in its parameter block. The stream is not a CSPRNG. Mailbox payloads are test data, and no key, token or nonce is drawn. No per-seed value is quoted as evidence.
* Seed-dependent cells. A cell that a leaf draws from its seed fills on a merge of regressions and never in one regression (`SEP_FCOV.adoc`, "Seed-dependent groups"). A leaf has no run index, so no seed pins a cell, and no testlist variant pins a cell. Each entry names its seed-dependent cells. Cheap boundary cells, one representative of each leg and the error-injection cases run on every seed.
* No leaf draws `SYS_DIS` or any disable-vector bit. Bit 0 is `SEP_DBG`, and it admits all inbound traffic (`hw/sys/sep/doc/fabric.adoc`, "Filtering and Protection").
* Every negative ("never") check has a control in the same leaf where a healthy design drives the same signal. The entry names the control.
* Run modes. `no_cpu` means target `lsu_stub_all_live` with the CPU-LSU master as a testbench master. `cpu` means the full CPU model on the default target with firmware. The PIC is inside the CPU, so a PIC register is reachable only from firmware in a `cpu` leaf (`hw/sys/sep/doc/memory_map.adoc`, "Units Unreachable from the Inbound Port").
* Every entry also carries the shared `CHK-FW-IDENTITY` and `CHK-FW-CONSOLE` records when it runs firmware, as stated in Test Procedures.

[[sep_mailbox_fifo_model_rand_test]]
===== 3.13 `sep_mailbox_fifo_model_rand_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds

*Source Module*: `sep_mailbox_fifo_model_rand_test`

*BFM / Model*: ocah_axi_vip (CPU-LSU master on the outbound apertures; external SMN master on the inbound apertures through one open inbound filter window per port); a golden queue per FIFO and a golden `STATUS`, `IRQS`, `IRQP` and line model, written from the spec text. Observation points: `sep_internal_interrupts_probe_o` bits [7:0] and bit 14 (`hw/sys/sep/dv/tb/tb_top.sv`) and `smc_mailbox_interrupt_o` (DUT port). No PROPOSED item. Every check is a reached check.

*Randomization*: RAND-REP. `SepSeededRng` from the run seed. The draws are: the mailbox order; for each threshold run `IRQEN` in [0, 7] per port (the gate and acknowledge legs drive every `IRQS` and `IRQEN` cell of each cause on each port); the payload (non-zero, no repeated word inside one fill); the access width (64-bit, or 32-bit at either half); two threshold values for each FIFO of each mailbox (0 to 255, weighted toward the corners 1, 6 and 9, the other values from 2 to 5 and 10 to 254); the fill count of a threshold run below 7 (in {threshold-1, threshold, threshold+1}, threshold-1 only for a threshold above 0; a threshold of 7 or more always fills to 8); the flush kind of each mailbox (each of the four kinds on two mailboxes); the fill counts of the flush leg (1 to 8 per FIFO); the two alias thresholds; the subsets of mailboxes with a high line. Every push runs below occupancy 8 and every pop above occupancy 0. `reseed = 3` samples different mailbox orders, payloads, widths, threshold values, flush-kind assignments, fill counts and subsets. The boundary threshold values 0, 7, 8 and 255 on both FIFOs of the first mailbox of the order, the four flush kinds and the all-eight outbound step run on every seed. The threshold values 1, 6, 9 and the other 8-bit values are seed-dependent cells and close on a merge of regressions (`SEP_FCOV.adoc`, "Seed-dependent groups").

*Objective*: Each mailbox pair holds two 8-entry FIFOs of 64 bits. A write at either half of `WRITE_DATA` pushes one entry. A read at either half of `READ_DATA` pops one entry. A threshold above 7 acts as 7, and a threshold of 0 detects any queued word. A flush bit discards the selected FIFO, and `CTRL` reads back 0. The level interrupt of each port is the OR of `IRQS` AND `IRQEN` of that port. The inbound line of mailbox `m` is vector bit `m` (PIC source `m + 1`). The outbound lines are eight bits of `smc_mailbox_interrupt_o`, graded as a set. The two ports of one mailbox share a FIFO, so a push on one port can raise the line of the peer port. A line carries no state of another mailbox. Sources: `hw/sys/sep/doc/mailbox.adoc` ("Mailboxes"); `hw/ip/axi_lite_mailbox_unit/doc/architecture.adoc` ("Paired FIFOs", "Interrupts"); `hw/ip/axi_lite_mailbox_unit/doc/interface.adoc` ("Access Results", "Sending and Receiving"); `hw/ip/axi_lite_mailbox_unit/regs/gen/adoc/axil_mailbox.adoc` (`STATUS`, `WIRQT`, `RIRQT`, `IRQS`, `IRQEN`, `IRQP`, `CTRL`); `hw/sys/sep/doc/interrupts.adoc` ("SEP PIC source assignments"); `hw/sys/sep/doc/port_table.adoc` (`smc_mailbox_interrupt_o`).

*Test Coverage*: Threshold values 0, 7, 8 and 255 on both roles of FIFO A and of FIFO B on every seed, and drawn values (1, 6, 9 and other 8-bit values) on every mailbox, with occupancy moved across 0, 1, 7 and 8. Flush of each kind (`wflush`, `rflush`) on both ports while the other FIFO of the pair holds data, each kind on two drawn mailboxes. The two-threshold alias on FIFO A. The `IRQEN` gate on the line. The acknowledge with occupancy below and above the threshold. The lines of all 16 ports together; probe bit 14 is logged. The outbound lines as a set, up to all eight high. The width of the port. The test extends the open tests named below, and only the new cells are graded. On outbound mailbox 0 the open tests grade the write threshold and the `wtirq` gate of FIFO A, the `IRQS` write-one-to-clear while the occupancy is above the threshold, the outbound `wflush`, and the outbound read threshold of FIFO B at, over and drain. The leaf runs these cells on mailbox 0 as controls of the other mailboxes and prints them as `CTL-<NAME> LOG`, not as `CHK` lines. On outbound mailbox 0 only the thresholds 0, 7, 8, 9 and 255, the alias leg and the flush kinds other than the outbound `wflush` print `CHK` lines. `sep_mailbox_peer_rx_rirqt_test` keeps the round trip, one pop per read, the lost high half and `RIRQT` at, over and drain. `sep_mailbox_datapath_walk_test` keeps the empty and full bits of `STATUS` at every depth, the push-order walk, the strobe lanes and the partial push that makes one entry and does not merge. `sep_axil_mailbox_iface_rand_test` keeps one `wflush`, the `IRQP` gate and the `IRQS` write-one-to-clear at register level on outbound mailbox 0. `sep_mailbox_plic_test` keeps the delivery of the inbound line to PIC source `m + 1` for a push. `sep_mailbox_peer_rx_rirqt_test`, `sep_mailbox_datapath_walk_test` and `sep_axil_mailbox_iface_rand_test` share the run mode and the tool of this entry. `sep_mailbox_plic_test` runs firmware. Functional coverage: `sep_mbox_fifo_model_cg` (`x_occ_op`, `cp_boundary_move`, `cp_thresh_val`, `x_clamp`, `x_flush`, `x_alias_thresh`), `sep_mbox_irq_line_cg` (`x_gate`, `cp_w1c_ack`, `cp_line_iso`, `cp_quiet_glitch`) and `sep_mbox_transfer_cg` (`x_in_attr`, `x_out_count`).

*Test Procedure*:

[arabic]
. Bring up in `no_cpu` mode with fuse sense skipped and ungate the mailbox clock. Reset SEP. Print `SEED seed=<S>` and a `DRAW` line for every drawn value. Read `$bits` of the `smc_mailbox_interrupt_o` port as declared on the DUT instance.
. With the CPU-LSU master, program one inbound filter window per mailbox over its inbound aperture (start `0x10A0_0800` + _m_ × `0x1000`, end `0x10A0_0FFF` + _m_ × `0x1000`): `entry_enabled` 1, `src_id` 0, read and write allowed. `SEP_DBG` stays off. The external master drives `AxPROT[1]` equal to `allow_ns`.
. Define the check cycle. After an operation, wait until `sep_internal_interrupts_probe_o` [7:0] and `smc_mailbox_interrupt_o` equal the golden model values (a bounded wait; a timeout fails the check cycle). Then run one quiet window: a fixed number of clocks, set by the test, with no access to the mailbox unit. Sample `sep_internal_interrupts_probe_o` [7:0], `smc_mailbox_interrupt_o` and bit 14 of the probe on every clock of the quiet window. Bit 14 is logged as `OBS-KM-LINE LOG bit14=b` and is not graded. Then read `STATUS`, `IRQS`, `IRQEN` and `IRQP` of both ports of the mailbox under test. Compare `STATUS` bits [3:2] with the golden model (CHK-STATUS) and print bits [1:0] against the model (`CTL-STATUS LOG`), and `IRQS` and `IRQP` with the golden model (CHK-LINE-IN, CHK-GATE, CHK-W1C). The model sets a cause bit of `IRQS` when the golden occupancy of the watched FIFO is above the golden threshold, keeps it until the test writes a one to it, and sets it again after that write while the occupancy condition still holds. `IRQP` is `IRQS` AND the `IRQEN` that the test wrote, and `IRQEN` reads back the written value. No expected value comes from a read-back of the DUT. When exactly one outbound model line rose in the step, log `OBS-SMC-MAP LOG mbox=m bit=o`.
. Draw the mailbox order, a permutation of 0 to 7. Run steps 5 to 10 on each mailbox in that order. Steps 11 to 14 run once, after the last mailbox. Each mailbox starts at its reset state: both FIFOs empty, `IRQS`, `IRQEN`, `WIRQT` and `RIRQT` 0. On mailbox 0 the cells named in Test Coverage as open cells (the outbound write threshold and `wtirq` gate of FIFO A, the acknowledge while above the threshold, the outbound `wflush` and the outbound read threshold of FIFO B) run in the same steps as controls and print `CTL-<NAME> LOG`.
. Threshold leg. On the first mailbox of the order take the boundary values 7, 0, 8 and 255 (7 first, as the reference of CHK-CLAMP) and then its drawn values. On every other mailbox take its drawn values. For each value run one fill on FIFO A and one on FIFO B. For each run: draw `IRQEN` in [0, 7] for both ports; write the value to the `WIRQT` of the write port and to the `RIRQT` of the read port of that FIFO; push to the fill count (the count is 8 for a value of 7 or more, and a drawn count in {value-1, value, value+1} with value-1 only above 0 for a smaller value); run a check cycle after each push; pop to 0 with a check cycle after each pop; then write `IRQS` as `0x7` on both ports. Pushes use a 64-bit full-strobe store or a 32-bit store at a drawn half. Pops use a 64-bit read or a 32-bit read at a drawn half.
. Alias leg. Draw two different thresholds `a` and `b` in [0, 7]. Write `WIRQT` of the outbound port as `a` and `RIRQT` of the inbound port as `b`. Push 8 distinct non-zero 64-bit full-strobe words into FIFO A through the outbound `WRITE_DATA`, with a check cycle after each push. Pop all 8 words through the inbound `READ_DATA`, compare each with the head of the golden queue (`CTL-ENTRY LOG`), and run a check cycle after each pop. Write `IRQS` as `0x7` on both ports.
. Flush leg. Run the flush kind drawn for the mailbox, one of the four kinds: `wflush` on the outbound port (discards FIFO A), `rflush` on the inbound port (discards FIFO A), `wflush` on the inbound port (discards FIFO B) and `rflush` on the outbound port (discards FIFO B). Over the eight mailboxes each kind runs twice. The outbound `wflush` control of mailbox 0 runs only when mailbox 0 draws that kind. For the drawn kind: push a drawn count of 1 to 8 distinct full-strobe words into FIFO A and another into FIFO B; run a check cycle; the `STATUS` of the port that reads the FIFO to be flushed is the pre-flush control and reads non-empty; write the flush bit of `CTRL` on the port of that kind; read `CTRL`; run a check cycle; pop the entries left in the FIFO that is not flushed, compare each with the head of the golden queue, and run a check cycle after each pop; write `IRQS` as `0x7` on both ports.
. Gate leg. Run it for each cause (`wtirq`, `rtirq`) on each port. Write `IRQEN` 0 and `WIRQT` and `RIRQT` 0 on the port, and write `IRQS` as `0x7`. Push one word into the FIFO that the cause watches (the write FIFO for `wtirq`, the read FIFO for `rtirq`) and run a check cycle: the cause bit of `IRQS` reads 1, `IRQP` reads 0 and the line of the port equals the model (low, because no other cause bit is set on that port). Write `IRQEN` with only that cause bit and run a check cycle: `IRQP` reads 1 and the line is high. Pop the word and write `IRQS` as `0x7`.
. Acknowledge leg. Run it for each cause on the outbound port and on the inbound port, with `IRQEN` set to only that cause bit. Draw a threshold `w` in [1, 6] and write it to the `WIRQT` (cause `wtirq`) or the `RIRQT` (cause `rtirq`) of the port. Push `w + 2` words into the watched FIFO and run a check cycle (cause set, line high). Pop 2 words so the occupancy is `w`, which is not above the threshold, and run a check cycle (the latched cause stays set and the line stays high). Write `IRQS` with that cause bit and run a check cycle (`IRQS` reads 0 and the line is low). Push 2 words so the occupancy is `w + 2` again and run a check cycle. Write `IRQS` with that cause bit while the occupancy is above the threshold, and run a check cycle (`IRQS` reads 1, the line stays high). Pop all words, write `IRQS` as `0x7` and write `IRQEN` 0.
. Drain the mailbox. Pop every remaining entry, write `IRQS` as `0x7` on both ports, write `IRQEN` 0, and run a check cycle. All lines of the mailbox are low.
. Outbound-set leg. It runs once, after the last mailbox. Write `IRQEN` as `0x1` and `WIRQT` 0 on the outbound port of every mailbox. Draw an order of all eight mailboxes and a subset size _k_ in [1, 6]. The first _k_ mailboxes of the order are the subset. Raise the outbound line of each member in order: one push into FIFO A through the outbound `WRITE_DATA`, then a check cycle. Raise mailboxes _k_ + 1 and _k_ + 2 back to back, with one check cycle after both pushes, so that two outbound model lines rise in one check cycle. Raise the remaining mailboxes one at a time with a check cycle after each, until all eight outbound lines are high (the port reads `0xFF`).
. With the outbound lines still high, write `IRQEN` as `0x1` and `WIRQT` 0 on the inbound port of each mailbox of the subset. Push one word through each of those inbound `WRITE_DATA` (external master), with a check cycle after each push. The inbound lines of the subset and all outbound lines are high.
. Release one at a time in drawn order. For an outbound line: pop the word through the inbound `READ_DATA`, write `IRQS` as `0x1` on the outbound port, run a check cycle. For an inbound line: pop the word through the outbound `READ_DATA`, write `IRQS` as `0x1` on the inbound port, run a check cycle. When all lines are released the port reads `0x00`.
. End state. Check that every FIFO is empty and write `IRQS` as `0x7` on all 16 ports. Run a check cycle: the 8 inbound lines and the whole outbound port read 0.

===== 3.14 `sep_mailbox_access_error_inject_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds

*Source Module*: `sep_mailbox_access_error_inject_test`

Wait one quiet window (a fixed number of clocks, set by the test, with no access to the mailbox unit). Probe bit `m` is high. Read `STATUS` of the outbound port: non-empty. Send the external write with the attributes that its entry admitted before. Expected response: `DECERR` (`CTL-RESP`; error injection: no matching entry). Wait a quiet window. Probe bit `m` is low. Count the entries by a drain of the outbound `READ_DATA` (0 pops). Write `entry_enabled` 1 to every entry again. Read `IRQS` of the inbound port with an admitted access (reads 0).

Expected response: `DECERR` (`CTL-RESP`; the open `sep_fabric_remap_filter_csr_bank_test` grades the response of a write to a locked entry). Send the external write with the drawn new source ID and the admitted `AxPROT[1]`. Expected response: `DECERR`. Wait a quiet window. Probe bit `m` is low. *Source Module*: `sep_mailbox_debug_bypass_test`

Functional coverage: `sep_mbox_qualification_cg` (`cp_bypass_accept`, `cp_bypass_pair`).

*Test Procedure*:

[arabic]

After the `OKAY` wait one quiet window. Probe bits [7:0] equal the mask of the mailboxes written so far.

Expected response: `OKAY`. After each write wait one quiet window. Probe bits [7:0] equal the mask of the mailboxes written so far.

|===
|Checker |Contract

===== 3.17 `sep_mailbox_reset_clear_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds. One leaf runs on VCS for the X-free part and on Verilator for the value checks. Each leaf runs one reset round.

*Source Module*: `sep_mailbox_reset_clear_test`

*BFM / Model*: ocah_axi_vip (CPU-LSU master for the mailbox apertures and the filter programming; external SMN master for the inbound `WRITE_DATA` that the filter entry admits; the CPU-LSU master does all filter programming); a golden mailbox model for the reset values, written from the spec text. Observation points: the reset input `rst_ni`; `sep_internal_interrupts_probe_o` bits [7:0] and `smc_mailbox_interrupt_o` (the whole port is compared with `0x00`, so no port-bit map is used; `hw/sys/sep/dv/tb/tb_top.sv`, DUT port). No PROPOSED item. Every check is a reached check.

*Randomization*: RAND-REP. `SepSeededRng` from the run seed. The draws are: the pre-reset FIFO counts (1 to 8 per FIFO, with FIFO A above the `WIRQT` of the outbound port); `IRQEN` in [1, 7]; the thresholds in [1, 6]; the mailbox of the locked filter entry and the two mailboxes of the error injections (all different); the reset cell, one per leaf, out of nine equally likely cells: the operation that the reset hits {push, pop, `IRQS` write} x the offset class {0 to 7, 8 to 31, 32 to 64 clocks after the request handshake of that operation}; the mailbox and port of the operation and the offset inside the class. A push is drawn only below occupancy 8 and a pop only above occupancy 0. FIFO A of the second error mailbox is outside the count draw and is filled to 8 for error injection 2. FIFO A of the first error mailbox is empty at error injection 1 and takes its drawn count after it. Only a full SEP reset is drawn. `reseed = 3` samples different counts, enables, thresholds, reset cells and offsets. The reset cell is a seed-dependent cell: one regression does not fill the nine cells, and they close on a merge of regressions (`SEP_FCOV.adoc`, "Seed-dependent groups").

*Objective*: SEP reset empties all FIFOs, clears thresholds, error flags, interrupt status and enables, drops every mailbox line, and restores the ISS source ID of an inbound filter entry to its reset value. The reset source of the `locked` bit and of `entry_enabled` is not stated, so they are logged. Sources: `hw/ip/axi_lite_mailbox_unit/doc/architecture.adoc` ("Clock and Reset"); `hw/sys/sep/doc/mailbox.adoc` ("Mailboxes", the ISS source ID is reset by SEP reset); `hw/ip/axi_filter/regs/gen/adoc/filter_ctrl.adoc` (`FILTER_CONFIG` reset values).

*Test Coverage*: Reset in the middle of a push, a pop or an `IRQS` write at an offset class of 0 to 7, 8 to 31 or 32 to 64 clocks after the request handshake (one drawn cell in each leaf; the nine cells close on a merge of regressions), with a non-reset pre-state on all eight mailboxes. All 16 apertures after the reset. The 16 lines. The ISS source ID of the filter entry (the lock and `entry_enabled` after the reset are logged). The mailbox after the reset. The test extends `sep_reg_bit_bash_rand_test`, which keeps the reset values at idle. This entry is a separate leaf because it resets a mailbox unit that holds live traffic, a different reset state from the idle reset of `sep_reg_bit_bash_rand_test`, and only the new cells are graded. It adds the reset in the middle of a push, a pop or an `IRQS` write, the lines after the reset and the ISS source ID restore. Functional coverage: `sep_mbox_reset_cg` (`x_op_offset`, `cp_pre_nonzero`, `cp_post_state`, `cp_lines_low`, `cp_filter_restore`, `cp_reuse`).

*Test Procedure*:

[arabic]
. Bring up in `no_cpu` mode with fuse sense skipped and ungate the mailbox clock. Reset SEP. Print `SEED seed=<S>` and a `DRAW` line for every drawn value.
. With the CPU-LSU master, write the drawn thresholds to `WIRQT` and `RIRQT` and the drawn `IRQEN` to every one of the 16 ports. The `IRQEN` of the inbound port of the first error mailbox and of the outbound port of the second error mailbox includes bit 2 (`eirq`).
. Filter entry. With the CPU-LSU master, program one inbound entry over the inbound aperture of the drawn filter mailbox: `src_id` 5, `allow_ns` 0, `entry_enabled` 1, read and write allowed. From the external master, send a write with source ID 5 and `AxPROT[1]` 0 to the inbound `WRITE_DATA` of that mailbox. Expected response: `OKAY`. Write `FILTER_CONFIG` with the same fields and `locked` 1. Read `FILTER_CONFIG` (`locked` reads 1, `src_id` reads 5).
. Error injection 1. On the inbound port of the first error mailbox, with FIFO A empty, read `READ_DATA`. Expected response: `SLVERR`, read-error flag set, `IRQS` bit 2 set. Do not read `ERROR_FLAGS`.
. Fill the FIFOs. For each mailbox, including the first error mailbox after error injection 1, push the drawn count into FIFO A through the outbound `WRITE_DATA` and into FIFO B through the inbound `WRITE_DATA`. Every drawn count is above 0. The count of FIFO B of the filter mailbox includes the word of step 3. The count of FIFO A is above the `WIRQT` of the outbound port. The count of FIFO A of the second error mailbox is 8.

For every port read `STATUS` (empty 0), `WIRQT`, `RIRQT` and `IRQEN` (all non-zero). For the outbound port of every mailbox read `IRQS` (bit 0 reads 1). Start the operation with the CPU-LSU master. The master holds the ready of the response channel low (`BREADY` for a push or an `IRQS` write, `RREADY` for a pop) from the start of the operation. Wait for the request handshake in a bounded wait: the later of the AW and W handshakes for a push or an `IRQS` write, the AR handshake for a pop, each with VALID and READY high in the same clock on the channel monitor of the master. A timeout logs `CTRL-MISSING` and fails the leaf. At the drawn offset, in clocks after the request handshake, assert `rst_ni` low for the same duration as the reset of step 1 (CTL-OP-INFLIGHT), and release it. The master abandons the outstanding transaction while `rst_ni` is low, so no beat or retry of it reaches the unit after the release. The response of the interrupted operation is not graded. No access to the mailbox unit is issued before the sample of step 10.

. Wait one quiet window. Sample probe bits [7:0] and the whole `smc_mailbox_interrupt_o`.

From the external master, send the write of step 3 (source ID 5, `AxPROT[1]` 0) and log its response. The response and the later state of the entry are not graded, because the specification does not state which reset restores the lock and `entry_enabled` (see <<sep-vplan-phase3-blocked,Blocked features>>).
. On a drawn mailbox, push one word through the outbound `WRITE_DATA` with the CPU-LSU master. Expected response: `OKAY`. Pop it through the inbound `READ_DATA` with the CPU-LSU master and compare it with the pushed word.

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu`, `+skip_fuse_sense`, 3 seeds. VCS (4-state) for the reset X check, Verilator for the value checks. Testlist groups `all`, `cpu`.

*Source Module*: `sep_pic_reg_rand_test`

[arabic]

The 0 write changes every armed register that it reaches. The all-ones write changes `meipl` and `meigwctrl`, and a one-bit field takes the same value from it, so the 0 write covers `meie` and `mpiccfg`. The firmware writes the armed registers back to 0 (CHK-HOLE).

After the read-back it writes the three registers back to 0. Then it writes `mpiccfg.priord` with 1 and reads it back, and writes it with 0 and reads it back (CHK-RW). No drawn value stays armed after this step. On VCS the host compares `pic_rd_data_probe_o` at each read-back of this step with the read value that the firmware prints (control of CHK-RESET-X).

Control: it writes the all-ones value of each field (0xF, 1 and 3) to entry 1 of the three arrays and reads each back equal. It writes entry 1 of the three arrays back to 0.
. `meigwclr` corner. For each drawn source N, the firmware writes `meigwctrl[N]` with 2 (edge, active high), so the clear acts on an edge-configured entry. It writes the drawn non-zero value to `meigwclr[N]` and reads `meigwclr[N]` (CHK-GWCLR0). It writes `meigwctrl[N]` back to 0.
. `meigwclr` control. The firmware writes `meigwctrl[1]` with 2, `meie[1]` with 1 and `meipl[1]` with 1. It raises source 1 with the source drive recipe on mailbox 0 and releases it with the same recipe. The edge gateway holds the pending bit, so `meip[0]` bit 1 reads 1. The firmware writes the first drawn `meigwclr` value to `meigwclr[1]` and reads `meip[0]` bit 1: it reads 0. The firmware writes `meigwctrl[1]`, `meie[1]` and `meipl[1]` back to 0.
. Source 0 cell control. With `mstatus.MIE` and `mie.MEIE` at 0 and source 1 idle, the firmware writes `meigwctrl[1]` with 1 (level, active low), `meie[1]` with 1 and `meipl[1]` with 15. It reads `meip[0]` bit 1: it reads 1, because an idle-low input is pending in this cell (`el2_pic.adoc`, `meigwctrl` polarity). It writes the three registers back to 0.
. Source 0 all-ones leg. The firmware writes 0xFFFF_FFFF to entry 0 of the four arrays. It installs a counting handler on every external-interrupt vector other than source 1, and a control handler on source 1. It sets `mie.MEIE` and `mstatus.MIE`. It holds for a hold window (a test parameter). It reads `meip[0]` and the count of the counting handlers (CHK-SRC0, `leg=allones`).
. Source 0 level, active-low leg. The firmware writes entry 0 of `meigwctrl` with 1 (level, active low), entry 0 of `meie` with 1 and entry 0 of `meipl` with 15. It holds for the hold window. It reads `meip[0]` and the count of the counting handlers: bit 0 reads 0 and the count is 0 (CHK-SRC0, `leg=lowlevel`). This is the gateway cell where a constant 0 input is pending, so an entry 0 that holds the write would show. The firmware writes entry 0 of the three arrays back to 0.
. Source 0 handler control. The firmware writes `meie[1]` with 1 and `meipl[1]` with 1 and raises source 1 with the recipe. The control handler reads `meip[0]` (bit 1 reads 1 and bit 0 reads 0), counts its run, writes `meie[1]` with 0 and releases the source. The firmware waits for the control run in a bounded wait; a timeout fails CHK-SRC0. It writes `meipl[1]` back to 0.
. The firmware prints one `CHK` line per check and the pass magic word. The host requires the shared `CHK-FW-IDENTITY` and `CHK-FW-CONSOLE` records, the pass magic word, and the expected number of `CHK` lines of each named checker.

[[sep_pic_external_access_refuse_test]]
===== 3.19 `sep_pic_external_access_refuse_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu` plus the external SMN master, `+skip_fuse_sense`, 3 seeds. Verilator and VCS. Testlist groups `all`, `cpu`.

*Source Module*: `sep_pic_external_access_refuse_test`

*BFM / Model*: CPU firmware (PIC, mailbox and filter drivers under `hw/sys/sep/dv/fw/drivers/`); the external SMN master (`ocah_axi_vip`) on the inbound port and its response codes. Probes and injects: the external SMN master and its response codes, the firmware CSR reads of the armed PIC state, and the firmware reads of the inbound filter entry registers. No PROPOSED item. Every check is a reached check.

*Randomization*: RAND-REP. `SepSeededRng` from the run seed. Dimensions: the interior entry J of each array (2 to 254, never one of the sources 13, 15, 16, 37, 38 and 39); the interior `meip` word (1 to 6); the hole address; the past-extent address; the access order; the order of read and write on each target. Addresses are aligned and lie inside 0xC008_0000 to 0xC008_7FFF. `SEP_DBG` stays off. `reseed = 3` samples different interior registers, addresses and orders. Both regimes and every target are walked on every seed.

*Objective*: The PIC is reachable only through the CPU internal wiring. An external access through the inbound port to any PIC address answers DECERR and changes no PIC register. In regime B the claim rests on two items: the read-back of the PIC window entries, which shows that the entries hold the programmed values, and the response code. Sources: `hw/sys/sep/doc/memory_map.adoc` ("Units Unreachable from the Inbound Port"); `hw/sys/sep/regs/gen/adoc/memory_map.adoc` (EL2_PIC row); `hw/ip/axi_filter/regs/gen/adoc/filter_ctrl.adoc` (`FILTER_CONFIG`, `START_ADDR`, `END_ADDR`); `hw/ip/axi_filter/doc/index.adoc` ("Address Range Granule").

*Test Coverage*: External read and write to the first, an interior and the last register of the six PIC groups, to a hole address and to a past-extent address, in the open-window regime (B), with the default-block regime (A) as the control. The default-block regime is a control: DECERR there also comes from the default block, so the claim rests on regime B and on the read-back of its window entries. This entry extends `sep_lcc_uvm_inbound_filter_gating_test`, which grades, with the filter bypassed, an external read and write of the first and last word of the PIC (DECERR, state unchanged). This entry is a separate leaf because the armed PIC state needs firmware and the external master together, a run mode that the open test does not use. Only the new cells are graded here: the interior registers of all six groups, the hole and past-extent addresses, the open-window regime with `SEP_DBG` off, and the PIC state read back by firmware. The open test keeps the first and last word with the filter bypassed. Functional coverage: `sep_pic_fabric_isolation_cg`.

*Test Procedure*:

[arabic]
. The host draws the dimensions with `SepSeededRng`, prints `SEED seed=<S>` and `DRAW` lines, and patches them into the firmware parameter block. The firmware boots with `mstatus.MIE` and `mie.MEIE` at 0 and `SEP_DBG` off.
. The firmware arms distinct non-zero values: `mpiccfg.priord` with 1; at entry 1, at entry J and at entry 255, `meipl` with 7, 9 and 11, `meie` with 1 and `meigwctrl` with 2 (edge, active high). Entry 0 is tied to 0 and is not armed.
. The firmware programs the inbound filter with one allow window over the inbound port of mailbox 0 (read and write), because the source drive recipe pushes a word through it. This window is a mailbox window and not a PIC window. It stays open in both regimes.
. The firmware raises source 1 with the source drive recipe on mailbox 0 and releases it with the same recipe. The edge gateway holds the pending bit, so `meip[0]` bit 1 is armed. The `meigwclr` registers read 0 and hold no value, so a write that lands in `meigwclr[1]` is visible only as the loss of this held bit.
. The firmware reads every armed register through the CPU and prints the values with `PIC-ARMED` (CHK-CPU-READ). The excluded idle bits of `meip` are masked.
. The firmware programs one more allow window over the inbound port of mailbox 7 (read and write). The window stays open in both regimes. It is the completion channel and the liveness control. Mailbox 7 `IRQEN` stays 0, so a pushed word raises no PIC source. The firmware prints `PIC-REGIME-A`.
. Regime A (control, error injection). Point: the inbound port at a PIC address. Kind: an external access to an unreachable unit. No window covers the PIC aperture, so the inbound filter blocks it by default. The host sends one read and one write to each target, in the drawn order: for each of the six groups the first implemented register (entry 1; `meip[0]`; `mpiccfg`), the interior register (entry J; the drawn `meip` word) and the last register (entry 255; `meip[7]`), one hole address and one past-extent address. Write data is the bit inverse of the armed value, and 0xFFFF_FFFF where no value is armed. Expected response: DECERR for every read and write (CHK-DECERR). Each external read of an armed register returns data that differs from the armed value (CHK-NO-LEAK).
. The host writes one completion word to the inbound `WRITE_DATA` of mailbox 7. Expected response: OKAY (CHK-WINDOW-LIVE, regime A). The firmware pops the word from the outbound `READ_DATA` of mailbox 7 in a bounded wait; a timeout fails the leaf.
. The firmware programs one allow window over 0xC008_0000 to 0xC008_7FFF (read and write, `entry_enabled` 1, `src_id` 0 as a wildcard, one entry per NS value) and prints `PIC-REGIME-B`.
. The firmware reads back `FILTER_CONFIG`, `START_ADDR` and `END_ADDR` of each PIC window entry and prints them with `PIC-WINDOW`. `START_ADDR` reads 0xC008_0000 and `END_ADDR` reads 0xC008_7FFF, because the range spans more than one granule and read-back then returns the programmed values. The fields that the firmware wrote in `FILTER_CONFIG` read back as written, and `data_bus_width` reads its fixed value and is masked (CHK-DECERR, regime B).
. Regime B (error injection). Point: the inbound port at a PIC address. Kind: an external access to an unreachable unit. The host repeats the accesses of step 7 in the same drawn order with the same write data. Expected response: DECERR for every read and write (CHK-DECERR, CHK-NO-LEAK).
. The host logs the response of its last PIC access. It then writes the second completion word to mailbox 7. Expected response: OKAY (CHK-WINDOW-LIVE, regime B). The firmware pops the word in a bounded wait.
. After the pop, the firmware reads back `mpiccfg`, `meipl`, `meie` and `meigwctrl` at entries 1, J and 255, and `meip[0]` with the excluded idle bits masked. It prints the values (CHK-LANDED). The host requires that its logged completion of the last PIC access precedes the firmware read-back line (CHK-WINDOW).
. The host requires the shared `CHK-FW-IDENTITY` and `CHK-FW-CONSOLE` records, the pass magic word, and the expected number of `CHK` lines of each named checker.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-CPU-READ
|(Control) The armed state is live: the firmware read of every armed register before the external accesses is non-zero, and `meip[0]` bit 1 reads 1. Without this control, the no-change checks prove nothing. Anchor: the firmware CSR reads. Evidence: `CHK-CPU-READ PASS armed_regs=N nonzero=N`.
|CHK-DECERR
|Every external read and write to a PIC address answers DECERR, in both regimes (`hw/sys/sep/doc/memory_map.adoc`, "Units Unreachable from the Inbound Port"). A wrong DUT answers OKAY or SLVERR. Anchor: the response code on the external master. The regime A result is a control only. The claim rests on regime B. In regime B the check also requires the `PIC-WINDOW` read-back of every PIC window entry to equal the programmed values, so a DECERR is not a missing window entry: the read-back shows that the entry is programmed, and the response code shows that the unit is unreachable. A wrong DUT with a reachable PIC answers OKAY. A mis-programmed entry fails the read-back. The response code of a CPU access to the PIC is not graded. Evidence: `CHK-DECERR PASS seed=S regime=B op=wr addr=0xC0082004 resp=DECERR window_entries_match=1` for each access, and the `PIC-WINDOW ns=0 FILTER_CONFIG=0xH START_ADDR=0xC0080000 END_ADDR=0xC0087FFF` line of each entry.
|CHK-NO-LEAK
|An external read of an armed register does not return the armed value. A wrong DUT serves the read from the PIC. Anchor: the external read data against the armed value, which the log carries. Registers with no armed value (`meigwclr`, holes, past extent, other entries) are graded by CHK-DECERR and CHK-LANDED only. Evidence: `CHK-NO-LEAK PASS addr=0xC0082004 armed=0x1 ext_read=0xH`.
|CHK-LANDED
|No external write lands in a PIC register: the firmware read-back of every armed register equals the armed value, and `meip[0]` bit 1 still reads 1, so a write that lands in `meigwclr[1]` fails. A write to `meigwclr` at entry J or entry 255 leaves no readable state and is graded by CHK-DECERR only. Anchor: the firmware read-back after all external accesses. Evidence: `CHK-LANDED PASS regs=N same=1`.
|CHK-WINDOW-LIVE
|(Control) The open-window regime is live: an external write to the open mailbox 7 window answers OKAY in both regimes, so a DECERR on a PIC address is not a dead window. Anchor: the response code of the completion words on the external master. Evidence: `CHK-WINDOW-LIVE PASS regime=B mailbox_resp=OKAY` (and the same line with `regime=A`).

[[sep_pic_priority_gate_rand_test]]
===== 3.20 `sep_pic_priority_gate_rand_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu`, `+skip_fuse_sense`, 3 seeds. Verilator and VCS. Testlist groups `all`, `cpu`.

*Source Module*: `sep_pic_priority_gate_rand_test`

*BFM / Model*: CPU firmware (PIC driver `hw/sys/sep/dv/fw/drivers/sep_pic.h`, handler order log, trap dispatcher with one counter per trap class). Probes and injects: the firmware handler log, the firmware CSR reads (`meip`, `mie`, `mip`, `mcause`) and the claim-id CSR of the firmware driver (firmware console and CSR reads). No PROPOSED item. Every check is a reached check.

*Randomization*: RANDCFG. `SepSeededRng` from the run seed. Dimensions: `priord` of each round (0 or 1; each value in at least one round); the source set of each round (2 to 5 of PIC sources 1 to 8, HMAC 18 and 20, KMAC 21 and 23, CSRNG 24, EDN 28, OTBN 30; the set size is drawn for each round); distinct raw priorities that give distinct effective priorities in 1 to 15; the gate kind per source (enable 0, or the never priority; each set holds at least one source of each kind); the gate-open order; the number of rounds (3 to 6); the source of the encoding sweep. At least one round per seed holds a source at effective priority 1 and one holds a source at effective priority 15. The never value (0 in standard order, 15 in reverse order) is drawn only as a negative. Equal priorities are not drawn. `priord` changes only with nothing pending and enabled. The non-PIC window (`mie.MTIE` and `mie.MSIE` set) is a constant of every leaf and is not drawn. The host patches the drawn rounds into the parameter block. `reseed = 3` samples different sets, priorities, gate kinds and orders. Every seed runs both orders, both gate kinds and every `meipl` encoding in both orders. The set size and the drawn priorities are seed-dependent cells: the winner cells of 2, 3, 4 and 5 sources, the `meipl` encodings 2 to 13 and the interior priority cells close on a merge of regressions (`SEP_FCOV.adoc`, "Seed-dependent groups").

*Objective*: A pending source is delivered only when its `meie` bit is 1, its priority is not the never value, and `mstatus.MIE` is 1. No handler runs while one of the three gates is closed. With several such sources the one with the highest effective priority is delivered first and the others stay pending. The never value is 0 in standard order and 15 in reverse order. The array index equals the source ID. `timer_int_i` and `soft_int_i` are tied to zero at the SMU boundary and drive `mip.MTIP` and `mip.MSIP`, which stay inactive. The leaf grades that the core does not set `mip.MTIP` or `mip.MSIP` by itself, so no timer or software trap is taken while `mie.MTIE`, `mie.MSIE` and `mstatus.MIE` are set. The tie-off at the SMU boundary is not graded here. Sources: `hw/sys/sep/regs/gen/adoc/blocks/el2_pic.adoc` (`mpiccfg`, `meipl`, `meie`, and the register description header); `hw/sys/sep/doc/interrupts.adoc` ("Software Handling", "Timer and Software Interrupts"); `hw/sys/sep/doc/port_table.adoc`.

*Test Coverage*: The three gates per source (enable 0, never priority, `mstatus.MIE` 0) with a twin that opens the gate; the winner by effective priority in both orders; waiting sources that stay pending while a handler runs; the never value with an effective-priority-1 twin in both orders; the order flip with mirrored priorities; winners of sets of 2 to 5 sources (the set size is drawn for each round); every `meipl` encoding written in both orders; `mip.MTIP` and `mip.MSIP` at reset, at the end of a hold window with `mstatus.MIE` set and with a control source pending; the absence of a timer or software trap with `mie.MTIE`, `mie.MSIE` and `mstatus.MIE` set. This entry extends `sep_pic_irq_source_map_delivery_test` (same run mode and tool), which grades that source `N` reaches handler `N` for the catalog. Only the new cells are graded here: the order, the gates, the never value and the timer and software tie-off cells. The open test keeps the source-to-handler delivery. Functional coverage: `sep_pic_enable_priority_cg`, `sep_pic_delivery_cg`, `sep_cpu_nonpic_irq_cg`.

*Test Procedure*:

[arabic]
. The host draws the dimensions with `SepSeededRng`, prints `SEED seed=<S>` and `DRAW` lines, and patches the rounds into the parameter block. The firmware boots and installs one handler for each drawn source, and always one control handler on source 1 (the same handler when source 1 is drawn). Each handler reads `meip` first, logs its source ID in the order log, releases its source with the source drive recipe, and returns. A handler does not enable interrupts, so handlers do not nest. The firmware also installs a trap dispatcher that every interrupt trap enters. The dispatcher classifies the trap by `mcause` (interrupt bit set and the timer, software or external code), increments one counter for the class, and calls the handler of the source for the external class.
. The firmware writes `mie` with `MEIE`, `MTIE` and `MSIE` set and reads it back (CHK-MIE-LIVE). It reads `mip` (CHK-MIP-IDLE, `when=reset`). It sets `mstatus.MIE`.
. Reset-state window. With every `meie`, `meipl` and `mpiccfg` at reset, the firmware asserts every source of the round 1 set with the recipe and holds for a hold window (a test parameter, logged as `hold_clk`). No handler runs (CHK-NONE-BEFORE-PROGRAM). The firmware releases the sources with the recipe.
. Encoding sweep. With every `meie` at 0 and nothing pending, for `priord` 0 and then 1, the firmware writes each of the 16 encodings 0 to 15 to `meipl` of the drawn sweep source and reads it back. The read-back is logged as `OBS-LEVEL-SWEEP LOG priord=<p> wrote=<v> read=<r>` and is not graded here, because `sep_pic_reg_rand_test` grades the `meipl` read-back. The firmware writes `meipl` of the source and `mpiccfg.priord` back to 0. The sweep is outside the graded window.
. For each round, the firmware writes every `meie` and `meipl` of the set to 0, so nothing is pending and enabled, and then writes `mpiccfg.priord` with the drawn value.
. Gate corner. With `mstatus.MIE` at 1, the firmware gives each source of the set its drawn closed gate: `meie` 0 with the drawn priority, or `meie` 1 with the never value of the current order. It asserts all sources and holds for the hold window. No handler runs (CHK-GATED). It logs the `meip` bit of each closed source as `OBS-NEVER-MEIP LOG`. It then opens the gates one source at a time in the drawn order (it writes `meie` 1, or the drawn priority) and waits for the handler in a bounded wait. Exactly the opened source runs once, and no other handler runs (CHK-GATED, twin).
. `mstatus.MIE` gate. The firmware clears the order log and its count, so that the log holds no entry from the gate corner. It writes `mstatus.MIE` with 0, gives every source of the set `meie` 1 and its drawn priority, and reads `meip`: the bits of the set read 0, because every source of the set is released (control of CHK-STAY-PENDING). It asserts all sources, and holds for the hold window. No handler runs (CHK-GATED, `gate=mie0`).
. Winner corner. The firmware writes `mstatus.MIE` with 1 once. The handlers run to completion in a bounded wait. The winner handler reads `meip` before it releases its own source: the bits of the sources that wait read 1 (CHK-STAY-PENDING). The host reads the first entry that the handlers wrote to the order log after the clear of the `mstatus.MIE` gate step, and compares its source ID with the source of highest effective priority, computed from the drawn raw priorities and `priord` (CHK-WINNER). The later order is logged.
. Never corner. The firmware writes every `meie` and `meipl` of the set to 0. With `mstatus.MIE` at 1, it gives one drawn source `meie` 1 and the never value, and asserts it. It holds for the hold window. The handler does not run (CHK-NEVER). It logs the `meip` bit as `OBS-NEVER-MEIP LOG`. It then writes the priority for effective priority 1 (raw 1 in standard order, raw 14 in reverse order). The handler runs once in a bounded wait (CHK-NEVER, twin).
. Flip corner. The firmware writes every `meie` and `meipl` of the set to 0 and writes `mstatus.MIE` with 0. It writes `mpiccfg.priord` with the opposite value. It writes every priority as the mirror of its raw value (15 minus the raw value), so the effective priorities do not change, and sets `meie` 1. The firmware clears the order log and its count, and then asserts all sources and writes `mstatus.MIE` with 1. The first entry that the handlers write to the order log after that clear equals the source of highest effective priority (CHK-FLIP).
. After the last round, the firmware writes every `meie` and `meipl` of the set to 0 and `mpiccfg.priord` with 0. With `mstatus.MIE`, `mie.MTIE` and `mie.MSIE` set and no PIC source enabled, it holds for the hold window. The timer and software class counters of the dispatcher stay 0 (CHK-NO-TIMER-TRAP). At the end of the hold window, with `mstatus.MIE`, `mie.MTIE` and `mie.MSIE` set, the firmware reads `mip`: `MTIP` and `MSIP` read 0 (CHK-MIP-IDLE, `when=hold`).
. Control. The firmware writes `mstatus.MIE` with 0. It reads the timer and software class counters of the dispatcher, which hold the totals of the leaf, and then writes 0 to all three class counters. It writes `meie[1]` with 1 and `meipl[1]` with 1 and asserts source 1 (mailbox 0) with the recipe. It reads `mip`: `MEIP` reads 1, `MTIP` and `MSIP` read 0 (CHK-MIP-IDLE, `when=after_control`). It writes `mstatus.MIE` with 1. The control handler runs once in a bounded wait, entered through the dispatcher, and its `mcause` has the interrupt bit set (CHK-CONTROL). The handler releases source 1. The firmware reads the three class counters: the external counter reads 1, and the timer and software counters read 0 (CHK-NO-TIMER-TRAP). It writes `meie[1]` and `meipl[1]` back to 0.
. The firmware prints one `CHK` line per check and the pass magic word. The host requires the shared `CHK-FW-IDENTITY` and `CHK-FW-CONSOLE` records, the pass magic word, and the expected number of `CHK` lines of each named checker.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-NONE-BEFORE-PROGRAM

*Test Procedure*:

[arabic]
. The host draws the dimensions with `SepSeededRng`, prints `SEED seed=<S>` and `DRAW` lines, and patches them into the firmware parameter block. The firmware keeps `mstatus.MIE` at 0 for the whole leaf, so `meip` is the observation. The host samples `sep_internal_interrupts_probe_o` and `sep_io_spi_req_o` on every clock.
. Reset baseline. Before any PIC write, the host reads the 43 vector bits and the firmware reads `meip[0]` to `meip[7]`. The six excluded idle bits (vector bits 12, 14, 15, 36, 37, 38; `meip` bits 13, 15, 16, 37, 38, 39) are masked and printed as `OBS-IDLE-UNSTATED LOG`. All other bits and the band above source 43 (`meip[1]` bits 12 to 31 and `meip[2]` to `meip[7]`) read 0. On VCS no vector bit is X, and `pic_rd_data_probe_o` shows no X at the `meip` reads (CHK-BASE, `when=reset`).
. The firmware programs each map source: `meipl` 1 and `meie` 1; the gateway at reset (level, active high) for the level sources, and `meigwctrl` 2 (edge, active high) for the pulse sources 12 and 33. It writes `INTR_ENABLE` of each IP from the drawn pass 1 enable mask (HMAC, KMAC, CSRNG, EDN, OTBN, SPI), with at least one bit set per IP, except the `fifo_empty` bits of HMAC and KMAC, which step 5 writes with 1. A map source whose enable bit is 0 is still driven, and it stays off. The firmware programs sources 12 and 33 as pulse sources even when they are not drawn, because the later alert steps need them.
. FIFO-empty set-up. For source 19 and source 22, the firmware makes the IP status read 1 under the stated conditions before it writes the enable. It configures the engine and starts a message without the Process command (HMAC `CMD.hash_start`; KMAC start, so that `STATUS.sha3_absorb` reads 1). The `fifo_empty` status rises only after the message FIFO was full (`hmac.adoc`, `kmac.adoc`, `INTR_STATE.fifo_empty`). For HMAC (source 19) the host applies the inject `hmac_fifo_drain_stall_i` before the fill. The firmware writes message words and reads `STATUS` after each write until `STATUS.fifo_full` reads 1 (a bounded number of writes, a test parameter; no read of 1 fails CHK-FIFO-EMPTY, because the stalled FIFO cannot drain). The host then releases the inject, and the firmware waits in a bounded wait for `STATUS.fifo_empty` to read 1. The firmware does not read the HMAC `INTR_STATE`, because `sep_hmac_fifo_stream_rand_test` (1.28, CHK-HMAC-FIFOEMPTY) grades that bit. For KMAC (source 22) no drain stall exists. The firmware writes message words and reads `STATUS` after each write, up to a bounded number of writes (a test parameter). If a read shows `STATUS.fifo_full` = 1, the firmware stops writing, waits in a bounded wait for `STATUS.fifo_empty` to read 1, and reads `INTR_STATE.fifo_empty`: it reads 1. If no read shows `fifo_full` = 1, the firmware prints `CTRL-MISSING ip=kmac fifo_full=0`, and source 22 is not graded in that seed: CHK-FIFO-EMPTY does not grade the KMAC cell, the `meip` and vector compares of the map passes mask bit 22 and vector bit 21, and the KMAC bin of `cp_fifo_empty_hold` is not sampled. After a `fifo_full` read of 1 (HMAC, or KMAC), a timeout of the `fifo_empty` wait or a status that reads 0 fails CHK-FIFO-EMPTY.
. The firmware asserts the map sources in the drawn order with the drawn gaps, with the source drive recipe (a mailbox push for sources 1 to 8; `INTR_TEST` for the OpenTitan sources; for sources 19 and 22, a write of 1 to `INTR_ENABLE.fifo_empty` (the status is 1 from the set-up), because their status follows the FIFO and no `INTR_TEST` is used; `ALERT_TEST` for the DMA alert on source 12 and for one drawn alert kind on source 33; `INTR_TEST.error` for source 14). At each assertion the host checks, as a control (`CTL-VECTOR`), that only the vector bit of that source rises.
. After the last assertion and a settle window (a test parameter), the firmware reads `meip[0]` to `meip[7]` and prints them. The host compares the words with the expected OR vector of the map sources whose enable is 1, with the excluded idle bits masked. On VCS the host also compares `pic_rd_data_probe_o` at each of these reads with the word that the firmware prints (control of the `meip` X part of CHK-BASE). The expected bit of source 19 and of source 22 comes from the stimulus model: 1, because the set-up of step 4 makes the status 1 and step 5 writes `INTR_ENABLE.fifo_empty` with 1. The IP read-back of `INTR_ENABLE` (and, for source 22, of `INTR_STATE`) at the compare is printed as a control (`CTL-FIFO-EMPTY`) and does not change the expected vector. The HMAC `INTR_STATE` is graded in 1.28 and is not read here. The host compares the vector probe with the same expected vector for the level sources as a control (`CTL-VECTOR`). For sources 12 and 33, the host requires at least one high clock on vector bit 11 and bit 32, and `meip` holds the bit (CHK-VECTOR). A source with its IP enable at 0 adds no bit.
. For source 19 and source 22: before the clear, the firmware reads `meip[0]` bit 19 or bit 22: the model value is 1 (set-up status 1, enable 1 written in step 5), and it reads 1 (CHK-FIFO-EMPTY). The host reads vector bit 18 or bit 21 in the same window: the model value is 1, and it reads 1 (CHK-FIFO-EMPTY). The read-back of `INTR_ENABLE.fifo_empty` (and, for source 22, of `INTR_STATE.fifo_empty`) is printed as a control. The firmware clears `INTR_ENABLE.fifo_empty` and reads `meip[0]` again: the model value is 0, and the bit reads 0. The host reads vector bit 18 or bit 21 after the clear: the model value is 0, and it reads 0 (CHK-FIFO-EMPTY). The firmware then completes the open message of each IP with its Process command, waits in a bounded wait for the engine to return to idle, and writes 1 to the done bit of `INTR_STATE`.
. For source 14: the firmware writes 1 to the SPI `INTR_ENABLE.error`, because the drawn mask can hold 0 and `INTR_ENABLE` qualifies the outgoing line. The host compares vector bit 13 with the `irq` field of `sep_io_spi_req_o` while the error cause is raised: both read 1. The firmware writes `INTR_TEST` 0 and writes 1 to `INTR_STATE.error`. The host compares them again: both read 0 (CHK-SPI).
. The firmware releases every source of step 5 with the recipe (event sources by `INTR_TEST` 0 and a write of 1 to `INTR_STATE`; mailbox sources by a pop and an `IRQS` write; sources 19 and 22 are already released by the enable clear; the edge bits by `meigwclr`). It reads `meip[0]` to `meip[7]`: all words equal the baseline (CHK-BASE, `when=map_release`). Map pass 2: the firmware writes `INTR_ENABLE` of each IP with the complement of the pass 1 mask over the bits of the driven sources (the SPI `INTR_ENABLE.error` bit of source 14 takes the complement of its pass 1 bit, in place of the 1 that step 8 writes), runs steps 5, 6 and 9 again with the pass 2 assertion order for every map source except 19 and 22, whose enable-0 cell step 7 grades, and grades them in the same way (CHK-VECTOR, CHK-BASE).
. Single-source reads. The firmware asserts source 24 alone and reads `meip[0]`: only bit 24 is set. It releases source 24. It writes one drawn `ALERT_TEST` bit and, after the alert pulse, reads `meip[1]`: only bit 1 (source 33) is set. It clears the held bit with `meigwclr[33]` (CHK-VECTOR).
. Alert kinds. For each of the 11 kinds in the drawn order (HMAC `fatal_fault`; OTBN fatal and recov; AES `recov_ctrl_update_err` and `fatal_fault`; KMAC `fatal_fault_err` and `recov_operation_err`; CSRNG fatal and recov; EDN fatal and recov), the host confirms vector bit 32 reads 0 in a quiet window. The firmware writes the `ALERT_TEST` bit. The host waits for a high clock of bit 32 in a bounded wait and then confirms that bit 32 returns to 0 (CHK-ALERT-AGG). `crypto_alert_pulse_probe_o` shows exactly one receiver index, inside the range of the block (CHK-ALERT-IDX). The firmware reads that `meip[1]` bit 1 holds the edge bit, and clears it with `meigwclr[33]`.
. No-write window. The host samples vector bit 32 over a hold window (a test parameter) with no `ALERT_TEST` write. It sees no high clock (CHK-ALERT-NONE).
. Pair trial. The firmware writes the `ALERT_TEST` bits of two kinds of two blocks, one after the other, with the drawn alert gap. Vector bit 32 shows a high clock. `crypto_alert_pulse_probe_o` shows both indices (CHK-ALERT-IDX). The firmware clears the held bit with `meigwclr[33]`.
. Native errors. For each of HMAC err (source 20), KMAC err (source 23), CSRNG `CS_FATAL_ERR` (source 27) and EDN `fatal_err` (source 29), which are native error interrupts, and OTBN done (source 30), which is a non-alert interrupt because OTBN has no native error interrupt, in the drawn order, the firmware sets the `INTR_ENABLE` bit and writes the `INTR_TEST` bit. The host sees the own vector bit set, and sees no high clock of bit 32 over a hold window. Control: the firmware writes the `ALERT_TEST` bit of the same block, and bit 32 shows a high clock. The firmware releases the native source and clears the held bit with `meigwclr[33]` (CHK-ALERT-NATIVE).
. DMA alert. The host confirms that vector bit 11 reads 0 in a quiet window. The firmware writes `ALERT_TEST.FATAL_FAULT` of the Secure DMA. The host waits for a high clock of bit 11 in a bounded wait and logs the latency and the shape (pulse or level); neither is graded (CHK-ALERT12).
. Masked report (logged). The firmware writes the Secure DMA `ALERT_TEST.FATAL_FAULT` and one drawn crypto `ALERT_TEST` bit, so that the edge bits of sources 12 and 33 are both held. It writes `meie` and `meipl` of both sources to 0 and reads `meip`. It logs the bits as `OBS-MASKED-VISIBLE LOG`. It writes `meie` and `meipl` back to 1, clears both held bits with `meigwclr`, and reads `meip`: all words equal the baseline.
. Control window. The firmware asserts control source 24 with the recipe. It writes `meie` 1 and `meipl` 1 on entry 17 and on every entry 44 to 255 (the gateways stay at reset), so a pending bit of source 17 or above source 43 could show. It reads `meip[0]` to `meip[7]` and the host reads the vector in the same window. Source 17 (vector bit 16 and `meip` bit 17) reads 0 (CHK-SRC17). The band (`meip[1]` bits 12 to 31 and `meip[2]` to `meip[7]`) reads 0 (CHK-IDLE-BAND). The excluded idle bits are logged (`OBS-IDLE-UNSTATED LOG`). Source 24 reads 1 in the same reads.
. Quiet window set-up. The firmware writes 0 to `INTR_ENABLE` and writes 1 to the RW1C bits of `INTR_STATE` of HMAC, KMAC, EDN, OTBN and SPI, and of CSRNG except the control source's command-done bit, which stays set and enabled. No IP interrupt can then rise in the next step, including the EDN and CSRNG completion bits that an AES run can legitimately raise.
. Slotless blocks. With control source 24 asserted, the firmware runs one AES encryption, one OTP read and one life-cycle controller read, one after the other. The host samples all 43 vector bits on every clock of each operation. The six excluded idle bits are masked. The IP interrupt enables stay cleared, except the control bit. During the OTP read vector bit 33 (source 34) is also masked and logged as `OBS-SRC34 LOG`. The AES status reads done after the encryption (CHK-SLOTLESS).
. The firmware releases control source 24 with the recipe.
. Idle window. The firmware starts an HMAC hash and a KMAC hash and writes message words to each without the Process command, so that each message stays open. It starts an OTBN program that runs longer than the hold window (a test parameter) and an AES block stream. Before the hold window it reads the status of each engine: HMAC `STATUS.hmac_idle` reads 0, KMAC `STATUS.sha3_idle` reads 0 and OTBN `STATUS` reads busy. The host samples vector bit 32 over the run and the hold window. It sees no high clock. After the hold window the firmware reads the three statuses again (still busy). A status that reads idle at either read fails CHK-ALERT-IDLE. The firmware then completes the HMAC and KMAC messages with the Process command, waits in a bounded wait for each engine to finish, and clears their done status (CHK-ALERT-IDLE).
. Gateway cells. For each source of the drawn gateway assignment (HMAC done 18, KMAC done 21, CSRNG command done 24, EDN command done 28 and PIC sources 1 to 8), with its IP `INTR_ENABLE` bit written to 1, `meie` 1 and `meipl` 1, the firmware writes `meigwctrl[N]` while the source is deasserted. It reads the `meip` bit with the source idle, asserted and deasserted. For an EH source (edge, active high) it then writes the clear value and reads again. The expected values are in CHK-GW-CELL. The LH cell of the same leaf is the level twin of the EH cell (CHK-GW-CELL, CHK-EDGE-HOLD, CHK-GW-NONVAC). The firmware writes `meigwctrl[N]` back to 0 while the source is deasserted.
. Clear-value corner. On an EH source, for each of the values 0, 1, 0x8000_0000, 0xFFFF_FFFF and the drawn value, the firmware asserts the source, deasserts it so that the edge bit is held, reads the `meip` bit (the held bit reads 1), writes the value to `meigwclr[N]` and reads the `meip` bit again (CHK-GWCLR-VALUE).
. Cell EL. On the EL source, the firmware asserts, deasserts, asserts again and writes the clear value, and reads the `meip` bit after each action. The bits are logged as `OBS-GW-EL LOG`. The firmware releases the source and writes `meigwctrl[N]` back to 0 while the source is deasserted.
. Level hold. On an LH source, the firmware asserts the source, holds for a hold window and reads the `meip` bit at the end of the window. It then clears the source through the IP status (`INTR_TEST` 0 and a write of 1 to `INTR_STATE`) and reads again (CHK-HOLD).
. Idle clear. On an EH source whose input is deasserted and whose pending bit is 0, the firmware writes the clear value that dropped the held bit of that source in the gateway cell or the clear-value corner to `meigwclr[N]`. It reads the `meip` bit before and after (CHK-CLR-IDLE).
. Boundary input. The firmware asserts control source 24 and reads `meip[0]` to `meip[7]` as the baseline. The gateways of entries 44 to 255 stay at reset and `meie` and `meipl` stay 1 from the control window. The host asserts one drawn bit of `sep_ext_interrupts_i` (the added top-port drive), and the firmware reads `meip[1]` to `meip[7]`. It counts the pending bits above source 43 and compares sources 1 to 43 with the baseline. The host deasserts the bit and the firmware reads again. The host then asserts two drawn bits together and the firmware reads again. The host deasserts both bits and the firmware reads again (CHK-EXT-IN).
. The firmware releases every driven source (control source 24 and the event sources by the recipe, sources 19 and 22 by `INTR_ENABLE.fifo_empty` 0, the edge bits by `meigwclr`) and writes `meie`, `meipl` and `meigwctrl` of every touched entry (including entry 17 and the entries 44 to 255) back to 0. It reads `meip[0]` to `meip[7]`: all words equal the baseline, and on VCS no vector bit is X (CHK-BASE, `when=final`).
. The firmware prints one `CHK` line per check and the pass magic word. The host requires the shared `CHK-FW-IDENTITY` and `CHK-FW-CONSOLE` records, the pass magic word, and the expected number of `CHK` lines of each named checker.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-BASE
|Before any stimulus, after the map release and after the final release, every vector bit and every `meip` bit reads 0, with the six excluded idle bits masked, and a released source does not stay pending (`interrupts.adoc`, "Sources and Routing"). A wrong DUT holds a bit high, leaves X on a vector bit or on a `meip` read, or keeps a released source pending. Anchor: the vector probe (value and, on VCS, X), the `meip` read-back (value) and, on VCS, `pic_rd_data_probe_o` at each `meip` read of the reset baseline (X). Control of the `meip` X part: at the CHK-VECTOR `meip` reads of the same leaf, `pic_rd_data_probe_o` equals the firmware `meip` word, and one or more of these words are non-zero. A mismatch, or no non-zero compared word, fails CHK-BASE. Evidence: `CHK-BASE PASS when=reset vec_masked=0x00000000000 band_zero=1 vec_x_free=1` (and the same line with `when=map_release` and `when=final`); `vec_x_free=na` on Verilator; `CHK-BASE PASS when=reset meip_reads=8 x_seen=0 ctrl_reads=N ctrl_match=N ctrl_nonzero=K` on VCS.
|CHK-VECTOR
|Each driven source sets its own pending bit in `meip`, and no other. The `meip` words equal the expected OR vector of the sources with IP enable 1, with the excluded idle bits masked. The expected bit of source 19 and of source 22 comes from the stimulus model (the status 1 of the set-up and the enable 1 that the firmware writes), not from an IP read-back; the IP read-back is a control (`CTL-FIFO-EMPTY`). The HMAC `INTR_STATE` is graded in 1.28 and is not read here. For sources 12 and 33, the probe shows a high clock and `meip` holds the bit. A wrong DUT sets another `meip` bit, misses its own, or sets a bit for a source whose IP enable is 0. The single-source reads (source 24 alone, source 33 alone) are cells of this check. The vector probe equals the expected vector for the level sources as a control: the vector equals state AND enable is graded in `sep_irq_ip_to_aggregator_test`, extension leg (1.25, `CHK-INTR-LINE`), and for sources 19 and 22 in CHK-FIFO-EMPTY, so the probe compare prints `CTL-VECTOR LOG`. Anchor: the `meip` words from the firmware. The logged live bits make an all-zero PIC fail. Evidence: `CHK-VECTOR PASS seed=S drawn=1,12,24,33 meip0=0x01001002 meip1=0x00000002 exp0=0x01001002 exp1=0x00000002 meip2_7=0`; `CTL-VECTOR LOG probe_equal=1`.
|CHK-FIFO-EMPTY
|Source 19 (HMAC) and source 22 (KMAC) show in `meip` after a real FIFO set-up while `INTR_ENABLE.fifo_empty` is 1 (for KMAC, as `INTR_STATE` AND `INTR_ENABLE`; the HMAC `INTR_STATE` bit is graded in 1.28), and drop when `INTR_ENABLE.fifo_empty` clears (`hmac.adoc`; the KMAC register description). This check grades the `fifo_empty` line gate (vector bit 18 or bit 21 equals state AND enable), including the drop at the enable clear; `sep_irq_ip_to_aggregator_test` (1.25) excludes the `fifo_empty` bits. A wrong DUT stays pending or keeps the vector bit after the enable clear, or does not follow the IP status. Anchor: `meip[0]` bit 19 or bit 22 and vector bit 18 or bit 21 against the stimulus model: 1 before the enable clear (the set-up status 1 and the enable 1 that the firmware writes) and 0 after the enable clear that the firmware writes. The IP read-backs (KMAC `INTR_STATE`, HMAC `STATUS.fifo_empty`, `INTR_ENABLE`) are controls and never set the expected value. The status rises only after the FIFO was full: the HMAC fill runs under the inject `hmac_fifo_drain_stall_i`, so `fifo_full` reads 1 on a compliant DUT, and the KMAC cell is graded only in a seed where a firmware read shows KMAC `STATUS.fifo_full` = 1 (otherwise `CTRL-MISSING ip=kmac fifo_full=0`, and the cell is not graded). After a `fifo_full` read of 1, a set-up status that does not read 1 in the bounded wait fails the check, so a dead `fifo_empty` path cannot pass with 0 = 0, and a `meip` bit of 0 before the clear fails it. Evidence: `CHK-FIFO-EMPTY PASS ip=kmac src=22 exp_before=1 meip_before=1 vec_before=1 exp_after=0 meip_after=0 vec_after=0`; `CTL-FIFO-EMPTY LOG intr_state=0xH\|na intr_enable=0xH`.
|CHK-SPI
|Source 14 follows the `irq` field of `sep_io_spi_req_t` for the SPI error cause, raised and after the write-one-to-clear (`hw/sys/sep/doc/spi.adoc`; `interrupts.adoc`). `INTR_ENABLE` qualifies the outgoing line, so the firmware sets `INTR_ENABLE.error` to 1 before the compare. A wrong DUT differs from the port, or never raises source 14. Anchor: vector bit 13 against the `irq` field of `sep_io_spi_req_o`: both read 1 while the cause is raised and both read 0 after the write-one-to-clear. Evidence: `CHK-SPI PASS cause=error bit13=1 port_irq=1 after_w1c_bit13=0 after_w1c_port_irq=0`.
|CHK-ALERT12
|The DMA alert reaches source 12 (`interrupts.adoc`, source 12). A wrong DUT does not raise bit 11. Anchor: at least one high clock of vector bit 11 inside the bounded wait, after a quiet window that reads 0. No latency is graded. Evidence: `CHK-ALERT12 PASS pre_window_src12=0 src12_high_cycles=N shape=pulse`.
|CHK-ALERT-AGG
|Each of the 11 alert kinds raises source 33 (`interrupts.adoc`, source 33; `crypto.adoc`, "OpenTitan Alert Termination"). A wrong DUT misses a kind or holds the bit high. Anchor: at least one high clock of vector bit 32 per kind, with 0 before the write and 0 after the pulse. Evidence: `CHK-ALERT-AGG PASS seed=S block=otbn kind=recov pic33_high_cycles=1 pre_window_high=0 back=0`.
|CHK-ALERT-IDX
|An alert reaches exactly one receiver index, inside the block range (HMAC [0], OTBN [2:1], AES [4:3], KMAC [6:5], CSRNG [8:7], EDN [10:9]), and the pair trial pulses both indices (`crypto.adoc`, alert table). A wrong DUT pulses the wrong index or two indices for a single alert. Anchor: `crypto_alert_pulse_probe_o`. Evidence: `CHK-ALERT-IDX PASS seed=S block=otbn kind=recov idx=2 range=1-2 pulse_vector=0x004`.
|CHK-ALERT-IDLE
|Normal work of HMAC, KMAC and OTBN does not raise source 33. A wrong DUT pulses bit 32 while the engines run. Anchor: no high clock of vector bit 32 in the idle window. The AES stream in the same window is a control: the AES no-alert and no-interrupt contract is graded in `sep_crypto_delivered_key_select_rand_test` (1.30, `CHK-KEYSEL-AES-SW`) and `sep_aes_stream_status_rand_test` (1.32, `CHK-AES-NOIRQ`). HMAC and KMAC hold an open message and the OTBN program runs longer than the hold window, so the three engines read busy before and after the window; an engine that reads idle at either read fails the check, so the window does not grade idle engines. The AES busy state is logged. Control: CHK-ALERT-AGG in the same leaf, where bit 32 shows high clocks; the line logs their count. Evidence: `CHK-ALERT-IDLE PASS pic33_high_cycles=0 engines_busy=3 aes_busy=b ctrl_high_cycles=N`.
|CHK-ALERT-NONE
|Source 33 does not rise with no alert written. Anchor: no high clock of vector bit 32 in the no-write window. Control: CHK-ALERT-AGG. Evidence: `CHK-ALERT-NONE PASS pic33_high_cycles=0 ctrl_high_cycles=N`.
|CHK-ALERT-NATIVE
|A native error sets its own source and does not raise source 33 (`crypto.adoc`: native error interrupts are not OR'd). The OTBN done interrupt is a non-alert interrupt, because OTBN has no native error interrupt (`crypto.adoc`, routing table), and it does not raise source 33 (`crypto.adoc`: the Crypto alert source is the OR of every receiver pulse and integrity-fail). A wrong DUT raises bit 32, or does not set its own bit. Anchor: the own vector bit at 1 and no high clock of bit 32 over the hold window. Control: an `ALERT_TEST` of the same block raises bit 32. Evidence: `CHK-ALERT-NATIVE PASS block=kmac kind=native native_src=23 native_bit=1 pic33_high_cycles=0 ctrl_alert_cycles=N` and `CHK-ALERT-NATIVE PASS block=otbn kind=non_alert src=30 own_bit=1 pic33_high_cycles=0 ctrl_alert_cycles=N`. The masked report prints `OBS-MASKED-VISIBLE LOG src=33 meie=0 pri=0 meip1_bit1=V`.
|CHK-SRC17
|Source 17 never sets (`interrupts.adoc`: tied to zero in this integration). A wrong DUT drives it. Anchor: vector bit 16 and `meip` bit 17 read 0, with `meie[17]` and `meipl[17]` at 1 so that a pending source 17 shows in `meip`. Control: source 24 reads 1 in the same read. Evidence: `CHK-SRC17 PASS live_src=24 live_bit=1 bit17=0`.
|CHK-IDLE-BAND
|No source above 43 is pending while the boundary input is idle (`interrupts.adoc`, "SEP CPU Interrupt Vector Map"). `meie` and `meipl` are armed on entries 44 to 255, so a pending bit could show. A wrong DUT shows a pending bit in the band. Anchor: `meip[1]` bits 12 to 31 and `meip[2]` to `meip[7]` read 0. Control: source 24 reads 1 in the same read. Evidence: `CHK-IDLE-BAND PASS live_src=24 live_bit=1 meip1_hi=0 meip2_7=0`.
|CHK-SLOTLESS
|An OTP read and a life-cycle controller read move no vector bit, because these blocks have no PIC slot (`interrupts.adoc`, source table). A wrong DUT moves a bit. Anchor: every non-masked vector bit equals its start value on every sampled clock of each operation, with the `INTR_ENABLE` of every IP except the control bit cleared in the quiet window set-up, so that no IP completion bit rises legitimately. During the OTP read bit 33 is masked and logged (`OBS-SRC34 LOG op=otp bit33_changed_clk=N`), because the specification does not state which access raises source 34 (see <<sep-vplan-phase3-blocked,Blocked features>>). Control: source 24 reads high on every sampled clock. The AES operation in the same window is a control: its no-interrupt contract is graded in 1.32 (`CHK-AES-NOIRQ`), so it prints `CTL-SLOTLESS LOG op=aes ...` and the AES status reads done. Evidence: `CHK-SLOTLESS PASS op=otp ctrl_src24_high_clk=N other_bits_changed_clk=0 ip_enables_cleared=1`.
|CHK-GW-CELL
|The pending bit follows the gateway cell (`el2_pic.adoc`, `meigwctrl`; `meigwclr`). LH: 0 idle, 1 asserted, 0 deasserted. LL: 1 idle, 0 asserted, 1 deasserted. EH: 0 idle, 1 asserted, 1 held after deassert, 0 after `meigwclr`. A wrong DUT gives another value for a cell. Anchor: the `meip` read-back against the model from the `meigwctrl` and `meigwclr` text. Cell EL is logged and not graded. Evidence: `CHK-GW-CELL PASS seed=S src=18 type=edge pol=high cfg=0x2 start=0 asserted=1 after_deassert=1 after_clr=0 clr_val=0xH`.
|CHK-EDGE-HOLD
|An edge source keeps its pending bit when its input falls (`el2_pic.adoc`, `meigwclr`: an edge bit holds until cleared). A wrong DUT drops it with the input. Anchor: the `meip` bit after the deassert. Control: the level twin (an LH source) of the same leaf drops with its input. Evidence: `CHK-EDGE-HOLD PASS src=21 type=edge held=1 level_twin_dropped=1`.
|CHK-HOLD

===== 3.22 `sep_cpu_bridge_fault_matrix_rand_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 3 seeds. Verilator and VCS. Testlist groups `all`, `cpu_stub`.

*Source Module*: `sep_cpu_bridge_fault_matrix_rand_test`

*BFM / Model*: CPU-LSU master (testbench master on `s_axi_*`), `ocah_axi_vip`, Secure DMA with an SRAM endpoint. Probes and injects: the CPU-LSU master for in-extent hole accesses, unmapped Secure DMA register offsets, clear writes and status reads; `sep_internal_interrupts_probe_o` bits 40 to 42 (`tb_top.sv`); the response control of the outbound responder on the `sep` input `smn_outbound_axi_resp_i`, which answers each source read of a DMA copy with `SLVERR` (without the inject `sep_outbound_mbx` answers OKAY at once; an error inject that the test adds to the inject exceptions of `SEP_TB_ARCH.adoc`), and the outbound port monitor, which counts the source-read requests on `smn_outbound_axi_req_o` that get `SLVERR`; `sep_cpu_ctrl_err_pulse_probe_o`, read-only, the fault pulse and the clear pulse of each of the seven peripheral latches and of the two DMA latches (an observation tap the test adds to the SEP_TB_ARCH observation-probe list; the anchor of the coincidence in CHK-RACE). *Randomization*: RAND-REP. `SepSeededRng` from the run seed. Dimensions: the order of the blocks hmac, kmac and otbn (every seed faults all three, so the latched set grows through the sizes 1, 2 and 3); the order of the three blocks in the same-cycle sweep; the in-extent hole offset inside the block (a stated hole); read or write for each re-fault after step 3 (the first fault of each block in step 3 is a write); the clear order (a permutation of the bits 0 to 6); the clear masks over bits [6:0] (1 to 3 steps; each mask holds at least two set bits, at least one of them the bit of an unlatched block); the re-trigger choice; the DMA source address (inside the fixed outbound filter window of step 11) and transfer size. *Objective*: A CPU access that gets a TL-UL error from a bridge at an unmapped offset latches its block bit, and the faulting access answers `SLVERR`. Source 43 is the OR of the seven bits `aes`, `hmac`, `kmac`, `otbn`, `csrng`, `edn`, `wdt`. Each `PERIPH_BUS_ERR_CLEAR` bit clears only its own block, and both clear registers read 0. `DMA_BUS_ERR_CLEAR.clr` clears both DMA latches only for a written 1. A non-OKAY AXI response to a DMA transfer sets `ERROR_CODE.BUS_ERROR` and `STATUS.ERROR`, latches `host_path_err` (not `reg_path_err`) and raises source 42. A fault that arrives in the same cycle as the clear of its own latch still latches, so a clear cannot drop a concurrent fault. Sources: `hw/sys/sep/doc/interrupts.adoc` (sources 41 to 43); `hw/sys/sep/regs/gen/adoc/blocks/sep_cpu_ctrl.adoc` (`PERIPH_BUS_ERR_STATUS`, `PERIPH_BUS_ERR_CLEAR`, `DMA_BUS_ERR_STATUS`, `DMA_BUS_ERR_CLEAR`); `hw/sys/sep/doc/crypto.adoc` ("Single-Beat Access Only"); `vendor/lowRISC/opentitan/overlay/regs/secure_dma/regs/gen/adoc/secure_dma.adoc` (`ERROR_CODE`, `STATUS`).

*Test Coverage*: One to three latched block bits from in-extent holes of hmac, kmac and otbn; the clear matrix of the seven clear bits against the latched bits; the drain to zero; mask clears that include unlatched bits; the re-trigger of a cleared block and of a block that is still set; the clear register reads; the DMA register-path latch with a write of 0 and a write of 1; the DMA host-path latch from a non-OKAY response to a DMA source read; the host-path clear cells; the same-cycle fault and clear for a peripheral block; the same-cycle fault and clear for the DMA host path. This entry extends `sep_irq_ip_to_aggregator_test` and `sep_periph_bus_err_misaligned_test` (same run mode and tool), which grade a single-block latch and the DMA register-path latch and clear, and `sep_dma_basic_test`, which grades a destination-side fabric non-OKAY with an exclusive `host_path_err`, its clear and a recovery copy. The `SLVERR` of a hole read, the `SLVERR` of a CPU read or write to an unmapped Secure DMA register offset, the `reg_path_err` latch and its clear by a write of 1 are graded in `sep_irq_ip_to_aggregator_test`; here they are controls and print `CTL-RESP LOG`, `CTL-LATCH LOG` and `CTL-DMA-CLR LOG`. [arabic]
. The host draws the dimensions with `SepSeededRng` and prints `SEED seed=<S>` and `DRAW` lines. After reset, the CPU-LSU master reads `PERIPH_BUS_ERR_STATUS` and `DMA_BUS_ERR_STATUS`: both read 0, and on VCS no bit is X. The host reads vector bits 40 to 42: all read 0 (CHK-CTRL).

After each access, the master reads `PERIPH_BUS_ERR_STATUS`: it equals the set of blocks faulted so far (CHK-LATCH), and vector bit 42 equals 1 (CHK-OR).
. Error injection. The CPU-LSU master accesses an unmapped Secure DMA register offset. Expected response: `SLVERR` (`CTL-RESP LOG`). `reg_path_err` latches, and the master reads `DMA_BUS_ERR_STATUS`: it equals 0b01, and vector bit 40 reads 1 (`CTL-LATCH LOG`, the set-up of the DMA clear cells).
. With both status registers non-zero, the master reads `PERIPH_BUS_ERR_CLEAR` and `DMA_BUS_ERR_CLEAR`: both read 0 (CHK-CLR-READ0).
. DMA register-path cells. The master writes 0 to `DMA_BUS_ERR_CLEAR.clr`: `DMA_BUS_ERR_STATUS` still equals 0b01 and vector bit 40 reads 1 (CHK-DMA-CLR). The master writes 1: `reg_path_err` reads 0 and vector bit 40 reads 0 (`CTL-DMA-CLR LOG`, the control of the write of 0). `host_path_err` reads 0 and vector bit 41 reads 0 (CHK-DMA-CLR, the host-path 0 cell; its control is CHK-HOST of the same leaf, where a healthy DUT sets `host_path_err`).
. Clear matrix. For each clear bit i in the drawn order over the bits 0 to 6: the master first faults every drawn block whose bit reads 0, so that the full set of the three block bits is latched (CHK-NONVAC). It writes 1 to bit i only. It reads `PERIPH_BUS_ERR_STATUS`: the status equals the set minus bit i. A clear of an unlatched bit leaves the set unchanged. Vector bit 42 equals (status != 0) (CHK-CLR-MATRIX).
. Drain. The master restores the full drawn set. It clears the latched bits one at a time in the drawn order. After each clear, the status equals the set minus the cleared bits, and vector bit 42 stays 1 while any bit is set and drops with the last bit (CHK-CLR-MATRIX).
. Mask clears. For each of the 1 to 3 drawn steps: the master restores the full drawn set (CHK-NONVAC), writes the drawn mask over bits [6:0] (the mask includes bits of unlatched blocks), and reads the status. The status equals the previous status AND NOT the mask, and vector bit 42 equals (status != 0) (CHK-MASK).
. Re-trigger. The master restores the full drawn set. It clears one drawn block and faults that block again: its bit sets again and the other bits keep their values. It then faults a block whose bit is still set: the bit stays set and the other bits keep their values (CHK-AGAIN).
. Host-path fault (error inject). The master writes 1 to `DMA_BUS_ERR_CLEAR.clr` and reads `DMA_BUS_ERR_STATUS` as 0. Before the first copy of the leaf, it programs an outbound filter entry pair (one entry with `allow_ns` 0 and one with `allow_ns` 1, read allowed, `src_id` 0, because the Secure DMA leaves the source ID at `OTHERS`) over a fixed source window of the SMU aperture at its reset values (`0x8000_0000` to `0xBFFF_FFFF`), above `0x8000_1000` and away from the console and verdict words of the responder, and large enough for the largest drawn copy. The outbound filter has no bypass and blocks traffic that matches no entry (`fabric.adoc`), so without the entry pair no source read reaches `smn_outbound_axi_req_o`. It programs a DMA copy of the drawn size from the drawn source address inside the window, which the outbound responder serves, into SRAM. The DMA enabled memory range is set wide enough that no address check masks the bus error. The inject makes the responder answer every source read of the copy with `SLVERR`. The master reads `STATUS`: `BUSY` and `ERROR` read 0 (the idle check). It starts the copy and waits for `STATUS.ERROR` in a bounded wait; a timeout fails CHK-HOST. It reads `ERROR_CODE`, `STATUS` and `DMA_BUS_ERR_STATUS`. Expected response: `ERROR_CODE.BUS_ERROR` 1, `STATUS.ERROR` 1, `DMA_BUS_ERR_STATUS` 0b10 (`host_path_err` only), vector bit 41 at 1 and vector bit 40 at 0. The outbound port monitor shows one or more source reads that got `SLVERR`, and a count of 0 fails the check (CHK-HOST).
. Host-path clear cells (error inject). With `host_path_err` set alone, the master writes 0 to `DMA_BUS_ERR_CLEAR.clr`: both latches keep their state. It writes 1: both latches clear and vector bits 40 and 41 read 0. To latch both bits, the master writes 1 to `STATUS.ERROR` (RW1C) and reads `STATUS`: `BUSY` and `ERROR` read 0 (the idle check). It starts a second failing DMA copy as in step 11 and waits for `STATUS.ERROR` in a bounded wait: `host_path_err` latches. It then accesses an unmapped Secure DMA register offset: `reg_path_err` latches and `DMA_BUS_ERR_STATUS` equals 0b11. The master repeats the write of 0 and the write of 1 (CHK-DMA-CLR, host-path cells). It writes 1 to `STATUS.ERROR` so that the next transfer starts from the idle state.
. Peripheral same-cycle fault and clear. For each of the three blocks in the drawn sweep order, the master latches the bit of the block. It then issues the clear write for that bit on the write channel and a faulting hole read to the same block on the read channel, and sweeps the offset between the two over a range of clocks (a test parameter) until `sep_cpu_ctrl_err_pulse_probe_o` shows the fault pulse and the clear pulse of that block in one cycle and no later fault pulse of that block before the status read. A sweep that never shows the coincidence fails CHK-RACE. After the coincidence, the master reads `PERIPH_BUS_ERR_STATUS` and the vector (CHK-RACE).
. DMA same-cycle fault and clear (error inject). The sweep covers a bounded range of clock offsets (a test parameter) between the failing source read of a copy and the `DMA_BUS_ERR_CLEAR` write. For each offset: the master writes 1 to `STATUS.ERROR` and reads `STATUS`, where `BUSY` and `ERROR` read 0 (the idle check). It latches `host_path_err` with a failing copy as in step 11, writes 1 to `STATUS.ERROR`, and repeats the idle check. It then starts a second copy of one word, whose single source read gets `SLVERR`, and issues the `DMA_BUS_ERR_CLEAR` write at the offset. The sweep stops at the first offset where `sep_cpu_ctrl_err_pulse_probe_o` shows the clear pulse and the fault pulse of `host_path_err` in one cycle and no later fault pulse of `host_path_err` before the status read. A sweep that never shows the coincidence fails CHK-RACE. After the coincidence, the master reads `DMA_BUS_ERR_STATUS` and the vector (CHK-RACE). It writes 1 to `STATUS.ERROR`.
. The host requires the expected number of `CHK` lines of each named checker, and no `CHK-<NAME> FAIL` line.

*Objective*: The timeout block is reserved and not implemented. `TIMEOUT_INTERRUPT` (R, reset 0) reads 0. `TIMEOUT_ENABLE` and each of the eight `TIMEOUT_COUNT_*` registers have one RW bit 0 with reset 0 and hold a written 1. *Test Coverage*: Extends `sep_address_map_test` (open, same run mode and tool), which reads `TIMEOUT_INTERRUPT` and six of the counts at reset and writes and reads back `TIMEOUT_COUNT_DMA`, `TIMEOUT_COUNT_SYS_IN` and `TIMEOUT_ENABLE`, and `sep_reg_bit_bash_rand_test` (open), which grades the reset value of the timeout registers and proves nothing on a count whose register has no software-usable field. `sep_cpu_ctrl_reg_shape_test` (Phase 3, 5.21 of this plan, not an open test) grades the write of `TIMEOUT_CLEAR` and `TIMEOUT_MODE`. This test grades only the new cells: the write of 1 and the read-back of the six counts that `sep_address_map_test` does not write and read back (`TIMEOUT_COUNT_MAILBOX_INBOUND`, `TIMEOUT_COUNT_MAILBOX_OUTBOUND`, `TIMEOUT_COUNT_ENTROPY_WRITE`, `TIMEOUT_COUNT_ENTROPY_READ`, `TIMEOUT_COUNT_FILTER_OUT` and `TIMEOUT_COUNT_ALIAS_REMAP`) and the inertness under a real stall of each block path. The reset reads, and the write and read-back of `TIMEOUT_COUNT_DMA`, `TIMEOUT_COUNT_SYS_IN` and `TIMEOUT_ENABLE`, run as controls (`CTL-ARMED`). Cells: the 12 register and direction cells of the six counts (read and write); a read stall and a write stall for the system input, the inbound mailbox and the outbound mailbox; a read stall and a write stall for the outbound filter and the alias remap, and a source-read stall for the DMA, each held in the outbound responder; the entropy write and entropy read stalls. Functional coverage: `sep_cpu_ctrl_timeout_inert_cg` (`x_reg_dir`, `cp_stall_block`, `cp_stall_inert`).

*Test Procedure*:

[arabic]

Read the entries back.

. After a bounded quiet wait, sample `sep_internal_interrupts_probe_o` with the six excluded idle bits masked. This sample is the vector baseline. Log the six masked bits (`OBS-IDLE-UNSTATED`).

The system input read targets `SCRATCH[0]` of the cold scratch bank through the SMN master. This register is in a different register block than `TIMEOUT_INTERRUPT`, so the crossbar decodes the two to different targets (`fabric.adoc`, Fabric Topology). The inbound mailbox read targets `WIRQT` of the inbound port of mailbox 0 through the SMN master. The outbound mailbox read targets `WIRQT` of the outbound port of mailbox 0 through the CPU-LSU master. Each target has no read side effect.

During the hold, read `TIMEOUT_INTERRUPT` with the master that does not hold the stall (the CPU-LSU master when the SMN master holds, otherwise the SMN master) and wait for its response (a bounded wait). When the read completes, it is the during-hold sample. When it does not complete in the bounded wait, print `OBS-TO-INERT LOG block=<block> dir=<dir> sample=during_hold status=not_sampled`. The spec does not state that a read completes while another response is held, so this outcome does not fail CHK-TO-INERT. Sample the masked vector at the end of the hold.
. Raise `READY`. The response handshake count of the stalled access becomes 1 (CHK-STALL-REAL). After a bounded quiet wait, read `TIMEOUT_INTERRUPT` and sample the masked vector. Compare both and the response of the stalled access (CHK-TO-INERT).
. Repeat steps 6 to 9 with a write that holds `BREADY` low. The write targets the same register as the read of the block, and its data is the value that the register already holds (0x0 for `SCRATCH[0]` and `WIRQT`).
. Outbound filter, alias remap and DMA legs. Through the CPU-LSU master, program an outbound filter entry pair (one entry with `allow_ns` 0 and one with `allow_ns` 1, read and write allowed, `src_id` 0) over a fixed word of the SMU aperture at its reset values (`0x8000_0000` to `0xBFFF_FFFF`), above `0x8000_1000` and away from the console and verdict words of the responder. Program one valid alias remap region over a fixed local page, with an offset (bit 32 set) that translates the page to a fixed outbound word, and a second outbound entry pair over that translated word (`fabric.adoc`, Fabric Topology and Address Remapping). Each leg issues one access that reaches `smn_outbound_axi_req_o`, and the error inject holds the response of the outbound responder for the hold length. The outbound filter leg is a CPU-LSU read and a CPU-LSU write to the SMU aperture word, which no alias region hits. The alias remap leg is a CPU-LSU read and a CPU-LSU write to the remapped local page. The write data is 0x0. The DMA leg is a Secure DMA copy of one word from the SMU aperture word into SRAM, with the DMA enabled memory range set wide enough that no address check stops the copy, and with `INTR_ENABLE` of the Secure DMA at its reset value 0, so sources 9 to 11 stay low. Each leg runs steps 7 to 9 with the hold in the responder in place of the master `READY` hold, and the SMN master is the master that does not hold the stall. In the DMA leg the CPU-LSU master also reads the Secure DMA `STATUS` during the hold and, after release, in a bounded wait for `STATUS.DONE`.
. Entropy read leg and entropy write leg. The CPU-LSU master issues a single-beat 64-bit (AxSIZE 3) access to the entropy pool `STATUS` register (offset 0x0 of `sep_entropy_fifo`, `entropy_pool.adoc`; `sep_entropy_pool.adoc`), a read with `RREADY` low and a write with `BREADY` low. A `STATUS` read is non-destructive, and a write to the read-only pool changes no state and terminates with `BRESP=SLVERR` (`entropy_pool.adoc`, "Access Policy"). The write data is 0x0. Each leg runs steps 7 to 9 with the SMN master as the master that does not hold the stall. The anchor of CHK-STALL-REAL is the CPU-LSU R and B channel. The read data is logged (`OBS-ENTROPY-STATUS LOG fifo_level=<n>`) and is not graded, because the pool fills autonomously.
. Vector control. Through the SMN master, write `IRQEN` as `0x1` on the inbound port of mailbox 0 (`WIRQT` stays 0) and push one word through the inbound `WRITE_DATA`. Vector bit 0 (PIC source 1), which reads 0 in the baseline of step 4, reads 1 within a bounded wait. Pop the word through the outbound `READ_DATA` with the CPU-LSU master and write `IRQS` as `0x1` and `IRQEN` as 0 on the inbound port. Vector bit 0 reads 0 again (`CTL-VEC-LIVE`). A missing rise or fall prints `CTL-VEC-LIVE FAIL` and fails the leaf.

*Checkers*:

[[sep_nmi_vector_bark_rand_test]]
===== 3.24 `sep_nmi_vector_bark_rand_test`

*Phase*: 3

*Area*: Mailbox, IRQ, PIC

*Run mode*: `cpu`, `+skip_fuse_sense`, `reseed = 3`. One leaf runs two boots of the same image with a cold reset (`rst_ni`) between them, because the lock holds until a cold reset: the locked-copy boot and the free-address boot.

*Source Module*: `sep_nmi_vector_bark_rand_test`

*BFM / Model*: CPU firmware (an image with a stub at 0xC000_0100, four trampoline copies in ICCM and one common NMI handler); ICCM backdoor load for the free handler `Hk`; firmware console and firmware CSR reads; CPU trace `cpu_trace_addr_i` as the retired PC; `wdt_timer_rst_req_o` (DUT port, logged only); register model from the generated IP-XACT (`sep_reg_meta`). No PROPOSED item. Every check is a reached check.

*Randomization*: RANDCFG. `SepSeededRng` from the run seed, passed to the firmware in its parameter block: the trampoline copy (one of four 256-byte-aligned copies in ICCM); the free handler address `A` (halfword-aligned, 0xC000_1000 up to 0xC004_0000 minus the size `H` of `Hk`, outside the image and the four copies, so that `A` plus `H` is at or below the ICCM end 0xC004_0000; `H` is a test parameter and `Hk` stays inside ICCM; `cpu.adoc`, closely coupled memories); the bark threshold of each bark (1 to `N_BARK`; `N_BARK` is a test parameter that the leaf logs, far below the bite threshold 0xFFFF_FFFF, and every bounded wait for a bark is longer than `N_BARK` `clk_wdt_i` periods); the second concurrent-state case ((b) to (d); case (a) always runs first); the pending source (one of the OpenTitan event sources 18, 20, 21, 23, 24, 28 and 30); the raw priority; `priord`. `reseed = 3` samples three draws of each. Every seed runs the reset vector, one trampoline copy, the address `A`, case (a) and one of the cases (b) to (d). The trampoline copy and the case (b) to (d) are seed-dependent cells: one regression does not fill the four copies or the three cases, and they close on a merge of regressions (`SEP_FCOV.adoc`, "Seed-dependent groups"). The lock is set once per boot. A second NMI, an NMI during an external handler and a takeable PIC source at the bark are not drawn.

*Objective*: `SEP_NMI_VEC` holds address bits [31:1]. The NMI is not suppressed by `mstatus.MIE` or any PIC register, and the bark moves no pending bit. A bark with the vector at its reset value jumps to 0xC000_0100. With the vector programmed, then locked, then the bark enabled, a bark jumps to the programmed address and the code at the reset vector does not run. Sources: `hw/sys/sep/regs/gen/adoc/blocks/sep_cpu_ctrl.adoc` (`SEP_NMI_VEC`, `SEP_NMI_VEC_LOCK`); `hw/sys/sep/doc/interrupts.adoc` ("NMI — Watchdog Timer Bark", "Sources and Routing"); `hw/sys/sep/doc/watchdog.adoc` ("Bark Interrupt and Bite Reset"); `hw/sys/sep/regs/gen/adoc/blocks/el2_pic.adoc` (`mpiccfg`, `meipl`, `meie`, `meip`).

*Test Coverage*: Extends `sep_nmi_sanity_test` (same run mode and tool), which grades the reset vector default, the vector write-back, the sticky lock, the order vector then lock then bark enable, and the handler entered at the programmed trampoline. The reserved bit 0 of `SEP_NMI_VEC` after a write is graded by `sep_reg_bit_bash_rand_test` (open). The upper word and the write of 0 or all-ones to the RW1S lock are graded by `sep_cpu_ctrl_reg_shape_test` (Phase 3, 5.21 of this plan, not an open test). This test grades only the new cells: the bark with the vector at its reset value, the jump to a free address `A` with its retired PC, the concurrent PIC states and the PIC state unchanged by the bark. The open owners keep the rest. Cells: a bark with the vector at reset (graded by CHK-BARK-VEC; it is also the control that shows that the detection sees the reset-vector path); one locked-copy boot with a drawn trampoline copy and two barks with the vector locked: case (a) `mstatus.MIE` 0 with a pending enabled source, then one drawn case of (b) `mstatus.MIE` 1 with a pending source and `meie` 0, (c) `mstatus.MIE` 1 with a pending source at the never priority, (d) `mstatus.MIE` 1 with nothing pending; the pending source delivers after the gate opens; and, after a cold reset, a bark with `A` programmed and locked. Functional coverage: `sep_nmi_vector_cfg_cg` (`cp_vec_class`, `cp_order_at_enable`, `cp_nmi_target`), `sep_nmi_concurrency_cg` (`x_case_taken`, `cp_vec_unchanged`, `cp_pic_live_after`) and `sep_pic_no_delivery_cg` (`cp_bark_vec_same`).

*Test Procedure*:

[arabic]
. Before the first boot, the host loads the free handler `Hk` (size `H`) at `A` in ICCM by backdoor. `A` plus `H` is at or below 0xC004_0000. `Hk` writes the marker `Mk` to the firmware console, writes the end-of-firmware word that the host gates on, and loops. The image holds the stub at 0xC000_0100 in a fixed linker section, the four trampoline copies and the common NMI handler. Each copy records its own address and jumps to the common handler.
. Boot with `+skip_fuse_sense`. The firmware prints `SEED seed=<S>` and a `DRAW` line for each drawn value. It reads `SEP_NMI_VEC` and `SEP_NMI_VEC_LOCK` and prints them. They hold the RDL reset values 0xC000_0100 as an address and 0.
. Reset-vector corner (error injection: bark with the vector unprogrammed). Write `WDOG_BITE_THOLD` 0xFFFF_FFFF, `WDOG_COUNT` 0 and `WDOG_BARK_THOLD` a drawn value in 1 to `N_BARK`. Expected response: the CPU jumps to 0xC000_0100 and runs the stub there (`sep_cpu_ctrl.adoc`, `SEP_NMI_VEC`).
. The CPU jumps to the stub. The stub prints the marker `M0`, writes 1 to `INTR_STATE.wdog_timer_bark`, writes 0 to `WDOG_CTRL.enable` and `WDOG_COUNT`, and returns with `mret`. The host records the first retired PC after the loop (CHK-BARK-VEC control).
. Choose the drawn trampoline copy. Write its address to `SEP_NMI_VEC`. Write 1 to `SEP_NMI_VEC_LOCK`. Read both back.
