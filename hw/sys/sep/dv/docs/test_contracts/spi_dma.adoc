==== 4. SPI and DMA

[[sep_dma_hash_test]]
===== 4.1 `sep_dma_hash_test`

*Phase*: 1

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`

*Source Module*: `sep_dma_hash_test`

*BFM / Model*: ocah_axi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: Drives the secure DMA engine from real firmware to copy a block from SRAM into the CPU's data tightly-coupled memory with the inline hash engine enabled, then proves two things independently: the copied data is identical to the source, and the hardware digest is correct. Completion is delivered as an interrupt to a registered service routine, so the interrupt path is proven as well as the datapath. The digest comparison is the strong part: copy correctness alone would not show the inline hash engine consumed the same bytes that were copied. Two digest lengths are walked. SHA-256 runs over build-varying data (the firmware never seeds `rand()`, so the byte vector is fixed within one build and changes when the firmware is rebuilt) against a software SHA-256 computed in firmware over the same bytes. SHA-384 has no 64-bit SHA-2 core in this firmware, so it runs over a fixed message against the published FIPS 180-4 digest for that message; `OpcSha384` is a supported DMA opcode alongside `OpcSha256`.

*Test Coverage*: Firmware DMA SRAM to DCCM with inline SHA-256 and SHA-384, digest compare, copy, and IRQ.

*Test Procedure*:

[arabic]
. Initialise the fabric filter; register the DMA done and error service routines.
. Program the enabled memory range and confirm the configuration lock is open.
. Fill the SRAM source region with random data.
. Program source, destination, size, transfer width and increment modes.
. Start the transfer with the SHA-256 opcode and digest-swap set.
. Wait on interrupt; the service routine clears status.
. Read the hardware digest; compute the software digest; compare. Compare source against destination word for word.
. Then stage the fixed FIPS 180-4 56-byte test message in the same SRAM region, reprogram only the length and the opcode, and start a second transfer with the SHA-384 opcode.
. Wait on the interrupt again; read the twelve digest words; render them as hex and compare against the published vector. Compare the copied message against the source bytes.
. Disable the DMA interrupt enables, then carry the same 56-byte message as two 28-byte chunks, pacing the chunks on `STATUS.chunk_done` and counting them. Compare the digest against the published SHA-256 vector for the whole message.
. Finally run the same single-chunk SHA-256 twice, once with `DIGEST_SWAP` set and once clear, and compare the two digest word arrays against each other.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-CFG
|The DMA configuration lock is open before programming. A wrong value is counted as an error: the firmware emits `ERROR: CFG_REGWEN not unlocked`, increments its error count, and that count gates the mailbox PASS magic.
|CHK-COMPLETE
|The transfer completes and the interrupt reaches the service routine.
|CHK-DIGEST
|The hardware digest equals an independent software SHA-256 over the same data. The eight hardware digest words are read through the array-indexed accessor `SHA2_DIGEST_0_BASE_ADDR(i)`, so a wrong array stride or a wrong register symbol shifts the assembled digest and the `memcmp` below fails.
|CHK-COPY
|Destination matches source word for word.
|CHK-NONVAC
|For the SHA-256 pass: the software digest is recomputed from the actual SRAM contents on every run and no SHA-256 digest literal exists anywhere in the firmware or the testbench, so the comparison cannot be satisfied by a constant. `rand()` is never seeded, so the byte vector is the same for every seed within one firmware build -- the seed randomises only the clock period -- but it is not stable across builds.
|CHK-SHA384
|The twelve hardware digest words, rendered big-endian as hex, equal the FIPS 180-4 digest for the 56-byte message the firmware staged. Unlike the SHA-256 pass this compares against a literal, so its non-vacuity argument is different and is stated rather than inherited: the message is the published input and the vector is the published output, neither is read back from the engine, and a DUT that returned a constant, a zero digest, or the SHA-256 of the same message fails. The 56-byte message is used in place of the one-block "abc" vector because the DMA transfers whole 4-byte words. `OPCODE_ERROR` on this transfer is reported as a failure, not skipped, so a build that does not implement `OpcSha384` fails here rather than passing quietly.
|CHK-SHA384-COPY
|The same SHA-384 transfer also copied the message to the destination, checked byte for byte. A digest engine fed correctly while the copy path is broken fails here.
|CHK-MULTICHUNK
|The same 56-byte message carried as two 28-byte chunks produces the published FIPS 180-4 SHA-256 digest for the whole message. A hash that restarted per chunk, or that dropped the tail, produces a different digest and fails. The observed chunk count is required to be at least two before the digest is compared, so a transfer that silently completed in one chunk fails rather than passing a single-chunk digest under a multi-chunk name. A chunk counts only when its pacing poll ends on `STATUS.chunk_done` or `STATUS.done`; a poll that runs out of budget fails the pass and is never counted. Interrupts are disabled for this pass because the service routine clears `STATUS.chunk_done`, which the pacing loop has to read.
|CHK-DIGEST-SWAP
|Every digest word produced with `DIGEST_SWAP` clear is the byte-reverse of the corresponding word produced with it set, over the same message. Every other pass in this entry sets the bit, so none of them can tell a working `DIGEST_SWAP` from a DMA that ignores it; this is the only entry that grades the bit. All-words-identical is failed explicitly, since a palindromic digest is the one way a byte-reverse comparison could be satisfied while the bit does nothing.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Evidence*: CHK-NONVAC is a property of the sources rather than a run record -- no SHA-256 digest literal exists in the firmware or the testbench, so the comparison cannot be satisfied by a constant. Every other row is logged by the test: CHK-DIGEST compares the two digests the console carries, and CHK-CFG, CHK-COMPLETE, CHK-COPY, CHK-SHA384-COPY, CHK-SHA384, CHK-MULTICHUNK and CHK-DIGEST-SWAP each gate on the firmware line that scores them.

===== 4.2 `sep_spi_ot_dma_rx_test`

*Phase*: 1

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`

*Source Module*: `sep_spi_ot_dma_rx_test`

*BFM / Model*: ocah_axi_vip, ocah_spi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: Proves the hardware handshake between the SPI host and the secure DMA engine.

*Test Coverage*: SPI-FIFO to DMA to SRAM handshake with a known RX pattern.

*Test Procedure*:

[arabic]
. Initialise the fabric filter; preload the flash model with a known byte pattern.
. Configure the SPI host: receive watermark, clock divider, enable, watermark event.
. Issue a flash read command and address, then request the payload.
. Program the DMA: source is the receive register in wrapping mode, destination is SRAM incrementing, hardware handshake enabled; start.
. Poll to completion, read the status again and require done still set, then write-one-to-clear the status bits.
. Check every DMA-written SRAM word against the pattern.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-DATAPATH
|Every word the DMA wrote to SRAM carries the preloaded pattern, proving the chain from flash model through receive queue and trigger to SRAM. The compare is exclusive: all-ones is rejected, since that is what a mis-wired MISO, a garbled address phase and an unrecognised opcode all produce.
|CHK-RW1C
|The DMA done status bit still reads set on a second read after the poll, so a read does not clear it and it does not drop by itself; it then clears on write-one-to-clear and reads back clear. Both status values are logged. `ERROR` and `CHUNK_DONE` are never set in hardware-handshake mode, so their clear is not exercised.
|CHK-NOERR
|The DMA reports no error and the SPI controller reaches idle with clean error status.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

[[sep_dma_cpu_contention_test]]
===== 4.3 `sep_dma_cpu_contention_test`

*Phase*: 1

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`

*Source Module*: `sep_dma_cpu_contention_test`

*BFM / Model*: ocah_axi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: Prove CPU and DMA SRAM traffic is correct under real local-crossbar contention. A TB monitor counts cycles where both masters present an SRAM request on the same AXI address channel; DMA BUSY is the independent proof that the job spans the CPU store loop.

*Test Coverage*: CPU and DMA as concurrent SRAM masters.

*Test Procedure*:

[arabic]
. Inherit the global side-effect region marking from startup code; this test performs no per-test region write of its own.
. Seed the source pattern; clear the destination and the CPU's own region.
. Start the DMA copy and do not wait.
. Immediately run the CPU store loop.
. Sample DMA status at store-loop exit, then poll to completion. After firmware completion, require the TB's same-channel CPU/DMA SRAM-request overlap count to be nonzero.
. Check both regions; read the status again and require done still set, then clear the status bits.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-IN-FLIGHT
|A status sample at store-loop exit shows the DMA busy and not done, proving the DMA job spans the CPU store loop.
|CHK-OVERLAP
|The CPU-LSU and DMA masters simultaneously present SRAM requests on the same local-crossbar AW or AR channel for at least one cycle. The monitor filters both addresses to the generated SRAM aperture, so a concurrent DMA-CSR status read cannot satisfy this checker.
|CHK-NOERR
|The DMA completes with no error.
|CHK-RW1C
|The done status bit still reads set on a second read after the poll, so a read does not clear it and it does not drop by itself; it then clears on write-one-to-clear. Both status values are logged. Chunk-done is never raised in this single-chunk configuration, so its clear is not exercised.
|CHK-DMA-DATA
|The DMA destination matches its source.
|CHK-CPU-DATA
|The CPU's own region holds exactly what the CPU wrote — its traffic was not corrupted by the competing master.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

[[sep_spi_ot_dma_tx_test]]
===== 4.4 `sep_spi_ot_dma_tx_test`

*Phase*: 2

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`, firmware `spi_ot_dma_tx_test`

*Source Module*: `sep_spi_ot_dma_tx_test`

*BFM / Model*: ocah_axi_vip, ocah_spi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address), observation-only probes `spi_tx_qd_probe_o`, `spi_lsio_trigger_probe_o` and `dma_busy_probe_o`

*Objective*: Drives SRAM through the secure DMA into the OpenTitan SPI host transmit FIFO and on to the flash BFM, then reads the flash back and compares against the cocotb-seeded random source data. After the walk, a TXDATA write past `STATUS.TXFULL` must latch exclusive `ERROR_STATUS.OVERFLOW` and the host must run again after recovery.

*Test Coverage*: DMA SRAM to SPI TX to flash, readback compare, and TX overflow recovery.

*Test Procedure*:

[arabic]
. Walk the seeded length and trigger cells: DMA SRAM into the OpenTitan SPI TX FIFO, page-program the flash BFM, read the flash back and compare to the SRAM source; read the DMA status again and require done still set, then W1C-clear DMA done. While DMA `STATUS.busy` is set, cocotb samples the DMA trigger input and the transmit FIFO depth on each clock.
. Write TXDATA past `STATUS.TXFULL`; expect exclusive `ERROR_STATUS.OVERFLOW`; `CONTROL.SW_RST` plus write-one-to-clear; a flash status read must complete.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-TRIGGER
|The transmit watermark tracks FIFO occupancy across the threshold, with the exact polarity asserted and the observed values logged. `EVENT_ENABLE.TXWM` is programmed.
|CHK-DMA-TX
|The flash content equals the SRAM source, compared against cocotb-seeded random data.
|CHK-DMA-DONE
|The DMA done bit still reads set on a second read after the poll, so a read does not clear it and it does not drop by itself; it then clears on write-one-to-clear and reads back clear. Both status values are logged. Handshake mode does not raise `STATUS.chunk_done` (RTL: chunk_done is the inverse of cfg_handshake_en); that status is `sep_dma_basic_test`.
|CHK-SPI-IDLE
|The SPI host returns to idle with a clean error status.
|CHK-NONVAC
|The flash readback holds content that is not the erased 0xFF pattern, so the content compare above is not erased-against-erased. Scanned on the value the flash returned, not on the staged source, which the config forces non-erased and could never fail.
|CHK-RAND-REP
|The cocotb golden walked the deterministic length and trigger cells, requiring a literal floor of write-enable and page-program transactions on the bus and a per-case address and data match.
|CHK-MULTICHUNK
|The transmit watermark paces every DMA transfer. Per case, during DMA `STATUS.busy`, the DMA trigger input shows at least as many separate assertions as the transfer has 16-byte chunks, with a literal floor of 2, and the transmit FIFO depth never goes above `TX_WATERMARK` - 1 + one chunk (7 words). A trigger held high, or a DMA that refills without waiting for the watermark, fills the FIFO past that bound in one burst. Graded on DUT probes, not on the bus byte count.
|CHK-ERR-OVERFLOW
|A TXDATA write past `STATUS.TXFULL` latches exactly `ERROR_STATUS.OVERFLOW`; `CONTROL.SW_RST` plus write-one-to-clear then lets a flash status read complete.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

[[sep_spi_ot_flash_cmd_rand_test]]
===== 4.5 `sep_spi_ot_flash_cmd_rand_test`

*Phase*: 2

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`, firmware `spi_ot_flash_cmd_test`, 3 seeds

*Source Module*: `sep_spi_ot_flash_cmd_rand_test`

*BFM / Model*: ocah_axi_vip, ocah_spi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: JEDEC, WREN/RDSR, WRDI, page program, FAST_READ, and sector erase against the flash BFM, with a neighbour-sector intact check, write-protect and status-register breadth, and the three host `ERROR_STATUS` classes with recovery.

*Test Coverage*: JEDEC, program, read, erase, write-protect, and host error-status recovery.

*Test Procedure*:

[arabic]
. READ ID, then prove WEL set by WREN and cleared by WRDI.
. Program, FAST_READ, and sector-erase with neighbour intact.
. After the erase: prove WEL consumed; the controller delivers a page program with WEL clear (the device model refuses it); opcode `0x35` returns the seeded status-register-2 value.
. `ERROR_STATUS` is zero after that sequence. Then inject underflow, reserved `COMMAND.SPEED`, and an out-of-range chip-select, each exclusive; after each, pulse `CONTROL.SW_RST`, read `ERROR_STATUS` and require the class still set, then write-one-to-clear and require 0; READ ID works again.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-PROGRAM / CHK-READ
|A page program followed by a read returns the exact random pattern at the exact random address.
|CHK-ERASE
|A sector erase leaves the programmed region reading all-ones and leaves the adjacent 4 KiB neighbour sector intact. The region is proven non-erased earlier in the walk, by the page program and read-back pair that `CHK-PROGRAM`/`CHK-READ` covers, so the all-ones result is a change of state rather than a region that was never written.
|CHK-NO-ERROR
|The SPI host error status is zero after the sequence.
|CHK-JEDEC
|READ ID returns the BFM JEDEC identity.
|CHK-RDSR
|RDSR sees WEL set after WREN. A controller timeout is a distinct failure, not a status byte that looks like WEL.
|CHK-WRDI
|WRDI runs on a WEL that RDSR just proved set, then RDSR sees WEL clear.
|CHK-FAST-READ
|FAST_READ returns the programmed pattern.
|CHK-WEL-AUTOCLR
|The erase consumes the write-enable latch. The latch is state of the SPI flash device model, not of SEP: what this grades is that the controller drove a well-formed erase the device accepted and retired, and it fails if the controller leaves the device armed. It is not RTL coverage of a SEP register, and takes no feature credit as such.
|CHK-WP-PP
|The controller delivers a page program issued with the write-enable latch clear: the firmware command completes, and the golden requires a third page-program transaction at the device with the full address phase at the random address. It fails if the controller drops, truncates or mis-addresses the command. The refusal itself is device-model behaviour, not SEP: the latch is state of the SPI flash device model, which drops any page program while the latch is clear, whatever the controller drives. The firmware all-ones read-back, the empty payload record and the direct read of the model's stored array are therefore model self-checks and take no feature credit, the same as `CHK-WEL-AUTOCLR`.
|CHK-RDSR2
|Opcode `0x35` returns the seeded non-zero status-register-2 value. A decode that folds `0x35` onto `0x05` returns the write-enable SR1 encoding (`0x02`) and fails. A receive path that returns all-zero also fails. The firmware does not re-read SR1 on this step; the fail cases are the two wrong bytes, not a live SR1 compare.
|CHK-ERR-UNDERFLOW
|Reading `RXDATA` with the receive FIFO empty latches exactly `ERROR_STATUS.UNDERFLOW`. It still reads set after the `CONTROL.SW_RST` pulse, which clears internal state and not registers, so the write-one-to-clear that follows is what releases it.
|CHK-ERR-CMDINVAL
|A command with the reserved speed encoding latches exactly `ERROR_STATUS.CMDINVAL`. It still reads set after the `CONTROL.SW_RST` pulse, which clears internal state and not registers, so the write-one-to-clear that follows is what releases it.
|CHK-ERR-CSIDINVAL
|A segment whose chip-select is outside `NumCS` — driven at the top of the 32-bit `CSID` field, so the stimulus assumes no particular `NumCS` — latches exactly `ERROR_STATUS.CSIDINVAL`. It still reads set after the `CONTROL.SW_RST` pulse, which clears internal state and not registers, so the write-one-to-clear that follows is what releases it.
|CHK-ERR-RECOVER
|READ ID completes with the BFM JEDEC identity after the three injections, so the host was released rather than left disabled.
|CHK-RAND-REP
|The seed varies the programmed address, word count and payload. The opcode sequence is fixed, and the BFM golden requires that exact observed order.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Scope*: the transaction-order golden requires the BFM-visible opcode sequence
(JEDEC, WREN, RDSR, WRDI, program/read, FAST_READ, neighbour program/read, erase,
primary and neighbour read, post-erase status, the ignored write-protect program,
RDSR2, and the recovery READ ID). The three `ERROR_STATUS` injections put nothing
on the bus: the host disables its core the cycle the error latches. Dual and quad
modes are not exercised: the flash BFM does not support them.

'''''

[[sep_dma_basic_test]]
===== 4.6 `sep_dma_basic_test`

*Phase*: 2

*Area*: SPI and DMA

*Run mode*: `cpu`, `+skip_fuse_sense`, firmware `dma_basic_test`, 3 seeds

*Source Module*: `sep_dma_basic_test`

*BFM / Model*: ocah_axi_vip, CPU FW, `tb/sep_outbound_mbx.sv` (console + verdict mailbox; OKAY / zero read data for any address)

*Objective*: Secure-DMA control and copy breadth over the CPU LSU: documented reset values, the configuration lock reading locked while the engine is observed busy, the range-valid gate and its rw0c lock each with a positive control, FIXED/INCR/WRAP against a per-mode golden, 1/2/4-byte widths, `STATUS.done` RW1C, one invalid-opcode error with recovery, the address, address-space-id and transfer-width refusals, the inverted-range refusal, a copy that leaves SRAM for the instruction memory and back, a DMA-issued host-path command-integrity inject, and a fabric DECERR dest that raises `host_path_err` with the pin low. The mode and width walk is directed.

*Test Coverage*: Secure-DMA locks, address modes, widths, errors, and host-path integrity.

*Test Procedure*:

[arabic]
. Read DMA config registers at documented reset, then prove CFG_REGWEN lock while BUSY.
. While the range registers are still writable: `RANGE_VALID=0` raises `range_valid_error`, and an enabled range whose limit sits below its base raises exclusive `base_limit_error` with `STATUS.done` clear. Then lock `RANGE_REGWEN`.
. Walk INCR / FIXED / WRAP × 1B/2B/4B; consume the seed-patched SCENARIO line.
. Provoke one invalid opcode, then four exclusive address-alignment refusals; a clean copy after each error class proves the engine recovers.
. With `dma_host_intg_inject_i` high, one legal SRAM copy raises exclusive `host_path_err` and aggregator bit 41. `DMA_BUS_ERR_CLEAR` returns STATUS and bit 41 to 0. A legal copy with the pin low then matches the source snapshot.
. With the pin low, one copy whose destination is the first word past the DMA CSR window raises exclusive `host_path_err` from the fabric DECERR. CLEAR and a legal recovery copy follow.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-RESET
|The DMA configuration registers read their documented reset values.
|CHK-CFG-REGWEN
|The model check in this entry: the configuration lock reads locked while the engine is busy — with busy actually observed, failing loudly if the copy finished too fast — and the *same* write is rejected while locked and lands while unlocked.
|CHK-RANGE-REGWEN
|The range-valid gate produces the documented error, an enabled range whose limit sits below its base raises `base_limit_error` *exclusively* and sets no `STATUS.done`, and the range base register rejects a write once locked. A positive control precedes the lock — a non-reset value is written and proven to land first — so "unchanged after the lock" cannot pass identically for a read-only register or a missing decode.
|CHK-COPY-MODE
|Increment, fixed-source, fixed-destination and wrap addressing each produce their expected image against an independent local snapshot of the source fill, with a sentinel neighbour check per iteration.
|CHK-WIDTH
|Each transfer-width encoding is written *and read back*, and the copy is byte-exact. Without the read-back the three iterations are indistinguishable — 16 bytes is a whole multiple of 1, 2 and 4, so a register stuck at its reset produces identical output.
|CHK-DONE-RW1C
|The done bit is observed set and then cleared to zero.
|CHK-ERR-OPCODE
|An invalid opcode raises exactly the opcode error — asserted *exclusively*, so no other error bit may be set — with the done bit required clear, then cleared by write-one-to-clear. The recovery copy after the error matches the independent source snapshot.
|CHK-ERR-ADDR
|The address validation the engine applies before it moves a byte. Four refused descriptors, each asserting its `ERROR_CODE` bit *exclusively*: a 4-byte transfer whose source is not 4-byte aligned raises `src_addr_error`, the same on the destination raises `dst_addr_error`, a 2-byte transfer on an odd source raises `src_addr_error`, and a 2-byte transfer on an odd destination raises `dst_addr_error`. None may set `STATUS.done`, and a clean copy after the four proves the engine recovers. The inverted-range leg sits in `CHK-RANGE-REGWEN`, which must run before the one-way range lock closes.
|CHK-ERR-ASID
|An address-space id outside the three encodings the IP register specification enumerates (`OT_ADDR` 0x7, `SYS_ADDR` 0x9, `SOC_ADDR` 0xa) is refused. Walked on the source field and on the destination field separately, each asserting `asid_error` *exclusively* with `STATUS.done` clear, then cleared by write-one-to-clear, then a clean copy at the legal id. The legal set is a DV-owned table in `fw/drivers/sep_dma.h`, since the register description carries only the reset value.
|CHK-ERR-SIZE
|A transfer width outside the 1/2/4-byte encodings raises `size_error` *exclusively* with `STATUS.done` clear, then clears, then a clean copy at a legal width. Distinct from `CHK-ERR-ADDR`, where the width is legal and the address is not: this is the width decode itself refusing.
|CHK-ICCM
|A copy that leaves SRAM. Every other transfer in this entry is SRAM to SRAM, so an engine that cannot reach the instruction memory passes all of them. The data goes SRAM to ICCM and back to a second SRAM region, and the returned words are compared against the source over a sentinel pre-fill, with the count of words that changed required to be non-zero so a transfer that moved nothing fails. The round trip is used because the core takes a store access fault on a direct write to ICCM, so the processor cannot pre-fill or read back that memory; only the DMA touches it, which is what the checker is about.
|CHK-HOSTINTG
|A DMA-issued host command under `dma_host_intg_inject_i` raises exactly `DMA_BUS_ERR_STATUS.host_path_err`. Control: with the pin already high and no DMA command issued, `DMA_BUS_ERR_STATUS` still reads 0 before GO, so the pin alone does not set the latch. Aggregator bit 41 is 1 and bit 40 stays 0. `DMA_BUS_ERR_CLEAR` returns STATUS and bit 41 to 0. A legal copy with the pin low then matches the independent source snapshot. Each leg also requires the transfer to terminate, so a wedged engine cannot pass on a latch raised from its first command.
|CHK-HOSTFABRIC
|A DMA transfer whose destination is the first word past the DMA CSR window, with the inject pin low, raises exactly `host_path_err`. `DMA_BUS_ERR_CLEAR` returns STATUS to 0. The CLEAR register is a write-only single-pulse field that always reads 0, so its read value is not graded. A legal copy then matches the independent source snapshot.
|CHK-RAND-REP
|Mode and width cells walk every seed; src/dst/length/fill come from the run seed.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Evidence*: `CHK-HOSTINTG-ARM`, `CHK-HOSTINTG-RELEASE` and `CHK-HOSTFABRIC-ARM` are firmware handshake markers: the host drives `dma_host_intg_inject_i` high from the first to the second and requires it low at the third. `CHK-HOSTINTG-PIC` (aggregator bit 41 set, bit 40 clear) and `CHK-HOSTINTG-CLR` (bit 41 back to 0 after the clear) are the host-side records of CHK-HOSTINTG.

*Not claimed*: lockstep punch-through. The register path (`reg_path_err`) is not
exercised by this leaf at all; the unmapped-window term is proven by
<<sep_irq_ip_to_aggregator_test>>. Persistence across a CPU-only reset, and
the rule that a fault arriving in the clear cycle still latches — both stated in
the register description — are unproven here.

'''''

==== 4. SPI and DMA, Phase 3

This section holds the Phase 3 entries of the SPI and DMA area. Entry 4.10
extends an open test. Every entry names the open test it builds on and states
only the cells that the open test does not grade. The contracts that the
specification leaves open are in <<sep-vplan-phase3-blocked,Blocked features>>.
A check that needs a value that the specification does not state is blocked and is marked `Blocked: <value>`
(<<sep-vplan-credit-rules>>). A blocked check does not run and is not counted as reached.
Every contract below comes from the specification and the register description.
No contract comes from the RTL.

*Rules for every entry in this section*. An entry states only what differs.

* Seed. Every random value, and every per-seed choice of a leg, an order or an
enable value, is a pure function of the seed. No stimulus depends on a seed
index. `--stage sim --seed N` replays the leaf. The generator is not a CSPRNG.
All drawn data is test data. No document quotes a per-seed value as evidence.
* Log shape. Each check logs `CHK-<NAME> PASS|FAIL seed=<n> <values>`. The leaf
ends with `RESULT <test> seed=<n> PASS checks=<k>`, where k counts the checks
that run. PASS needs positive evidence in `results.xml`. A clean simulator exit
is not evidence. A leg whose control shows no cause logs `CTRL-MISSING` and
fails. An `OBS-` line records a value and grades nothing. A check marked
Blocked does not run, does not count in k and is not a reached check.
* Probes and injects. Each entry names the probes it reads. A probe is
"approved" when `SEP_TB_ARCH.adoc` lists it or `tb_top.sv` has it. A probe
outside the closed set of `docs/SEP_TB_ARCH.adoc` is an observation tap the test adds to the SEP_TB_ARCH observation-probe list. No entry adds an error inject
or a top-port drive. A check is blocked only when it needs a PROPOSED item or a
value that the specification does not state (<<sep-vplan-credit-rules>>).

The specification does not list the members of the SPI pad structs (see
<<sep-vplan-phase3-blocked,Blocked features>>). No check claims a signal
polarity or reads a pad struct member other than through an approved port.

* Control window. Each "never" check names a window in which a healthy design
drives the signal, and the leaf logs the value of that window.
* Reset release. After every `rst_ni` pulse the leaf waits, with a bound, for the
`sep_reset_n` release on `dbg_sep_reset_n_o` (`reset_controller.adoc`, SEP Reset
Controller) before the first register access.
* One fault per injection, from a clean state. SPI clean state: write-one-to-clear
on ERROR_STATUS and INTR_STATE.ERROR, CSID=0, then SW_RST with both FIFOs empty
before release. DMA clean state: write one to STATUS.ERROR, STATUS.ABORTED,
STATUS.DONE and STATUS.CHUNK_DONE. A write of one to STATUS.ERROR clears
ERROR_CODE (`dma.hjson`, ERROR_CODE). INTR_STATE is read-only
(`secure_dma.adoc`, INTR_STATE) and the specification states no write that
releases it (see <<sep-vplan-phase3-blocked,Blocked features>>), so a trial that
grades INTR_STATE or an interrupt line starts from a cold reset.
* DMA codes. OPCODE 0 is COPY, and 1, 2 and 3 select SHA-256, SHA-384 and
SHA-512. TRANSFER_WIDTH 0, 1 and 2 select 1, 2 and 4 bytes per transaction, and 2
is the reset value (`sep-programming.adoc`, DMA; `dma.hjson`, OPCODE,
TRANSFER_WIDTH). `secure_dma.adoc` has no table for these encodings. Where
`secure_dma.adoc` or `secure_dma.rdl` states the access type of a register, it
wins over `dma.hjson`; `dma.hjson` gives the text that they leave out.
A plain copy uses OPCODE 0 and width 2 unless the entry walks the widths.
The tests use 4-aligned addresses and sizes that are multiples of 4. An
address is aligned to the transfer width (`secure_dma.adoc`, SRC_ADDR_LO,
DST_ADDR_LO).
Source and destination footprints, guard words included, are disjoint and lie
inside BASE to LIMIT.
* Sentinel. Every byte of the sentinel word of a memory-to-memory transfer is
one byte value s that no source byte of that transfer takes: drawn source data
excludes s, and for a published hash vector s is a value that the vector does
not hold. So every byte that the transfer writes differs from the sentinel.
Drawn source words are unique within a transfer. The handshake entry draws its
sentinel from its reference run (<<sep_spi_dma_handshake_rand_test,entry 4.15>>).
* DMA transaction size. The specification states single-beat DMA transactions
(`fabric.adoc`, Top Level AXI4) and the width of each transaction
(`secure_dma.adoc`, TRANSFER_WIDTH). It does not state the AxSIZE that the
TL-UL to AXI4 path gives a narrow transaction, and it does not state the address bits [1:0] of a 1-byte or 2-byte transaction. At width encodings 0 and 1 the address checks grade AxADDR[31:2] and the WSTRB byte lanes, and log AxADDR[1:0]. The beat checks (AxLEN 0, beat
count, write byte count from WSTRB, read address step) read
the observation tap `dma_axi_req_probe_o`. AxSIZE is not
graded. The destination image is graded through the frontdoor.
* DMA chunks. The specification does not state whether one GO runs every chunk
of a multi-chunk memory-to-memory transfer or one GO runs one chunk (see
<<sep-vplan-phase3-blocked,Blocked features>>). A multi-chunk leg accepts both
readings: after a chunk end with DONE=0 and the engine idle, the leaf writes GO
again with INITIAL_TRANSFER=0. The number of GO writes is logged as
`go_writes` and not graded. Every wait for DONE has a bound, and a timeout
fails with `FAIL-DMA-TIMEOUT`.
* FIFO depth. The leaf finds the SPI FIFO depths at run time from STATUS and uses
them only to size stimulus. It never compares a depth with a value.
* Time. Every time relation is in core clocks, sck half-cycles or ratios. No
check uses an absolute frequency.
* Rx data at the pad. The specification does not state which line carries the
Rx bit at each speed (see <<sep-vplan-phase3-blocked,Blocked features>>). Rx data
is graded by word count. The bit content of Rx data at the pad is not graded.
* Disable vector. The vector stays at the harness value. SYS_DIS bit 0 is never
randomized, because it filters inbound traffic (`lifecycle_controller.adoc`,
Disable Vector Format).
* Tool and run mode. A `no_cpu` leaf uses target `lsu_stub_all_live`, joins the
testlist groups `cpu_stub` and `all`, and lives in `spi.toml` (SPI, the
SPI-to-DMA handshake included) or `system.toml` (DMA). Tool "both" means Verilator and VCS. Tool "VCS" means a
`tools = ["vcs"]` pin, because the leaf reads state after reset. A leg that
reads reset state on a four-state simulator is a VCS-only leg inside a
both-tools leaf. A leaf that asserts `rst_ni` runs with real fuse sense (no
`+skip_fuse_sense`).

===== 4.7 `sep_spi_pad_speed_dir_matrix_test`

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, no `rst_ni` pulse, 4 seeds; tool: both (Verilator and VCS); testlist groups `cpu_stub` and `all`, file `spi.toml`, one testlist entry. The seed draws the long dummy leg with a weight of 1 in 4. The leg takes 2,097,152 core clocks, so a seed that draws it runs longer.

*Source Module*: `sep_spi_pad_speed_dir_matrix_test`

*BFM / Model*: `ocah_axi_vip` for the register frontdoor over `s_axi` (CPU-LSU splice, approved), with the response code of every access. A test-side sampler reads the pad ports `spi_sck_o` and `spi_cs_n_o` on each core clock (approved). It counts one sck cycle at each leading edge, an edge that leaves the idle level, while chip select is low. `OcahSpiFlash` (`ocah_spi_vip`) drives `spi_miso_i` as the Rx responder (approved); the bits it returns are not graded. No checker needs a proposed probe. No inject. No check is blocked.

*Randomization*: `SepSeededRng` from the run seed (RAND-REP). Dimensions: the order of the 16 cells; the LEN class of each legal cell and of each dummy segment, `len0` (LEN 0), `sub_word` (LEN 1), `word_multiple` (LEN 3, 15, 31, or 0x3FF for a dummy segment) or `non_multiple` (LEN 4, 16, 32, or a value up to 63 with LEN+1 not a multiple of 4), weighted toward `len0` and `word_multiple`, and the value inside the class; the CLKDIV class of each cell, `zero` (0), `small` (1 to 3) or `mid` (4 to 7), and the value inside the class; the chain shapes (2 to 6 segments, the speed and direction of each segment); the long dummy leg (weight 1 in 4); the TX words and the responder stream. One constraint holds: each of DIRECTION 1 and 3 has at least one cell in `word_multiple`, so that CHK-SPI-RXCNT grades both directions on every seed. Every seed walks all 16 cells, one short register-level segment each. `reseed = 4` samples other orders, classes, values inside a class, chains, long dummy draws and data. The LEN class, CLKDIV class and CSAAT=1 cells depend on the seed, so `sep_spi_seg_rand_cg` closes on a merge of regressions (<<sep-fcov-rand,SEP_FCOV>>). No single regression is claimed to fill them.

*Objective*: The SPI host command contract holds (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, COMMAND and ERROR_STATUS registers; `hw/sys/sep/doc/spi.adoc`, Features; later cites in this entry use the file names only). SPEED 0, 1 and 2 move LEN+1 bytes at one bit per data line per sck cycle on 1, 2 and 4 data lines, so a data segment takes (LEN+1)*8/lanes sck cycles and a dummy segment (DIRECTION 0) takes LEN+1 sck cycles. The host runs at single transfer rate and has no x8 lane group, so a DDR or x8 host gives another count. CSAAT joins segments under one chip-select assertion. SPEED 3, and DIRECTION 3 at SPEED 1 or 2, raise ERROR_STATUS.CMDINVAL. The lane that carries each bit is not graded (see <<sep-vplan-phase3-blocked,Blocked features>>).

*Test Coverage*: The 10 legal SPEED x DIRECTION cells as single segments with CSAAT=0, at LEN classes 0, 1, 3, 4, 15, 16, 31, 32 and a value up to 63, and LEN 0x3FF for dummy segments. The Rx word count at every speed when LEN+1 is a multiple of 4. A dummy segment with TXQD and RXQD both at least 1. Chains of 2 to 6 legal segments in which speed and direction change while chip select stays low. A long dummy segment (LEN 0xFFFFF at CLKDIV 0) on a seed that draws it. The 6 illegal cells (SPEED 3 with DIRECTION 0 to 3, and DIRECTION 3 at SPEED 1 and 2). The open tests `sep_spi_ot_flash_cmd_rand_test` and `sep_spi_ot_host_csr_irq_rand_test` drive SPEED 0 for data and grade SPEED 3 with DIRECTION 2 at the ERROR_STATUS level. That cell runs here as a control: it logs `CTL-SPI-ILLEGAL LOG`, prints no CHK-SPI-ILLEGAL line and fills no bin. This entry adds the cycle counts at SPEED 1 and 2, dummy segments, chains and the five other illegal cells. INTR_STATE.ERROR for a real CMDINVAL is graded in <<sep_spi_ot_host_csr_irq_rand_test_leg,entry 4.10>>. Functional coverage: `sep_spi_command_segment_cg` (`cp_speed_dir_legal`, `cp_chain_change`, `cp_fifo_effect`), `sep_spi_seg_rand_cg` (graded on a merge of regressions: `cp_len_x_kind`, `cp_csaat_x_dir`, `cp_clkdiv_x_speed`), `sep_spi_illegal_access_cg` (`cp_illegal_speed_dir`), `sep_spi_fifo_status_cg` (`cp_cmd_accept`) and `sep_spi_pad_rand_cg` (graded on a merge of regressions: `cp_mode_x_dir`, `cp_clkdiv_class`).

*Test Procedure*:

[arabic]
. Draw the cell order, the LEN class and the CLKDIV class of each cell and the value inside each class, the chain shapes, the long dummy choice, the TX words and the responder stream from the seed. Log the plan first (`PLAN seed=<n> ...`), with the class of every cell, the CSAAT=1 directions of the chains and `long_dummy=<0 or 1>`. Every wait in the steps below is a bounded wait; a timeout fails the check that the step feeds. A segment is done when the sampler has shown chip select low and then high (for a chain with CSAAT=1, high after the last segment) and a later STATUS read shows ACTIVE=0 and CMDQD=0. Every wait for a segment below is this bounded wait, so a STATUS read taken before the command starts does not end it. Before every COMMAND write the test polls STATUS until READY=1 (bounded). The SW_RST helper writes CONTROL.SW_RST=1 with the other fields kept, polls STATUS until TXEMPTY=1 and RXEMPTY=1, then writes CONTROL.SW_RST=0. The SPI clean state writes 1 to every bit of ERROR_STATUS and to INTR_STATE.ERROR, writes CSID=0, and runs the SW_RST helper.
. Start from the harness reset state. Write CONTROL with SPIEN=1, OUTPUT_EN=1, SW_RST=0 and both watermark fields at their reset values. Write CSID=0. Leave ERROR_ENABLE at its reset value 0x1F. Read ERROR_STATUS and INTR_STATE; both read 0.
. Single-segment leg: repeat steps 3 to 7 for each legal cell in the drawn order. Write CONFIGOPTS with CPOL=0, CPHA=0, FULLCYC=0, CSNLEAD, CSNTRAIL and CSNIDLE at 0 and the drawn CLKDIV, while ACTIVE=0 and chip select is high.
. Poll STATUS until READY=1. Write COMMAND with the cell's SPEED and DIRECTION, the drawn LEN and CSAAT=0. For DIRECTION 0 and 2, read STATUS before the COMMAND and require RXEMPTY=1 (control for CHK-SPI-RXCNT).
. Service the segment until it is done. Write the TXDATA words that the segment needs (LEN+1 bytes rounded up to words), each after a STATUS read that shows TXFULL=0. For DIRECTION 1 and 3, read one RXDATA word after each STATUS read that shows RXFULL=1, and count the words read in the segment.
. After the segment is done, read STATUS for RXQD. For DIRECTION 1 and 3, the total Rx word count is the words read in the segment plus RXQD. Read RXDATA until STATUS shows RXEMPTY=1, each read after a STATUS read that shows RXEMPTY=0; the words read equal RXQD. For DIRECTION 0 and 2, RXQD reads 0. When LEN+1 is not a multiple of 4, the Rx word count is read and not graded.
. Compare the sck cycle count that the sampler took for the segment with the expected count. Read ERROR_STATUS; it reads 0. Run the SW_RST helper.
. Dummy and FIFO leg. Run the SW_RST helper. Write one TXDATA word with no COMMAND. Run a 4-byte Rx segment (SPEED 0, DIRECTION 1, CSAAT=0) and do not read RXDATA. After the segment is done, read STATUS; TXQD and RXQD are each at least 1 (control; else CTRL-MISSING). Log both values. Run a dummy segment (DIRECTION 0, a LEN of the drawn class of this segment, a drawn SPEED from 0 to 2, CSAAT=0). After the segment is done, read TXQD and RXQD again. Read RXDATA until RXEMPTY=1 and run the SW_RST helper.
. Chain leg. Control for the sampler: write two legal dummy commands (DIRECTION 0, a drawn LEN, CSAAT=0 on both) back to back, each after a STATUS read that shows READY=1, and wait until the sampler has shown chip select low and then high twice and a STATUS read shows ACTIVE=0 and CMDQD=0. Require that the sampler saw chip select rise between the two low windows, else CTRL-MISSING. Then, for each drawn chain, write CONFIGOPTS (drawn CLKDIV) while ACTIVE=0. Build the chain from 2 to 6 legal segments with at least one change of speed or of direction between neighbours. Data segments in a chain have LEN+1 a multiple of 4, so the word count does not depend on how a partial word packs across segments. Write each COMMAND after a STATUS read that shows READY=1, with CSAAT=1 on every segment except the last, which has CSAAT=0. The depth of the command queue is not claimed, so interleave the data with the COMMAND writes: between the COMMAND writes and while waiting for READY=1, write the TXDATA words of the Tx segments already written, in order, each after a STATUS read that shows TXFULL=0, and read RXDATA as in step 5 for the Rx segments already written. After the last COMMAND, write the remaining TXDATA words and read RXDATA as in step 5 until the chain is done (the sampler shows chip select high after the last segment, and STATUS shows ACTIVE=0 and CMDQD=0). Read ERROR_STATUS; it reads 0. Run the SW_RST helper.
. Long dummy leg, on a seed that draws it. Write CONFIGOPTS with CLKDIV 0 while ACTIVE=0. After a STATUS read that shows READY=1, write COMMAND with DIRECTION 0, SPEED 0, LEN 0xFFFFF and CSAAT=0. Wait until the segment is done and take the sck cycle count.
. Illegal cells, as error injection. For each of the 6 illegal cells in the drawn order, run the SPI clean state and poll STATUS until READY=1. Write COMMAND with the cell's SPEED and DIRECTION, a drawn LEN and CSAAT=0, and push no TX data. Point: COMMAND write over the register bus. Kind: reserved SPEED encoding, or bidirectional at dual or quad. Expected response: ERROR_STATUS.CMDINVAL=1 and no other ERROR_STATUS bit (`spi_controller.adoc`, ERROR_STATUS). Poll ERROR_STATUS until CMDINVAL reads 1, then require the value 0x08. The cell SPEED 3 with DIRECTION 2 is a control: it logs `CTL-SPI-ILLEGAL LOG seed=<n> speed=3 dir=2 err_status=0x<v>`, a value other than 0x08 fails the leaf, and it prints no CHK-SPI-ILLEGAL line.
. After each illegal cell, run the SPI clean state and poll STATUS until READY=1. Write one legal control command (SPEED 0, DIRECTION 0, a drawn LEN, CSAAT=0) and wait until the segment is done. Read ERROR_STATUS; it reads 0.

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, no `rst_ni` pulse, 3 seeds; tool: both (Verilator and VCS); testlist groups `cpu_stub` and `all`, file `spi.toml`. Every run grades two mode cells.

*Randomization*: `SepSeededRng` from the run seed (RAND-REP). Every seed grades two mode cells (CPOL x CPHA x FULLCYC). The seed draws the first mode cell from the 8. The second mode cell has the other CPOL value, the other CPHA value and a drawn FULLCYC, so every seed grades both sck idle levels and both CPHA values. Dimensions: the two mode cells and their order, and per mode cell CLKDIV a (0 to 15), CSNLEAD, CSNTRAIL and CSNIDLE (0 to 15 each) and CLKDIV b for the ratio leg (0 to 15, not equal to a). The plan shape (two mode cells, each with a control run, a graded run and a ratio leg) is the same on every seed. The 8 mode cells, the CLKDIV and CSN classes and the CPHA=1 edge depend on the seed and close on a merge of regressions (<<sep-fcov-rand,SEP_FCOV>>); with two of the 8 mode cells per seed and 3 seeds, about 8 x ln 8 / 6, so about three regressions, fill the 8 mode cells.

*Objective*: The pad effect of CONFIGOPTS holds (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, CONFIGOPTS register; later cites in this entry use the file name only). sck idles at the CPOL level. The sck period is 2*(CLKDIV+1) core clocks. Chip select falls (CSNLEAD+1) half sck cycles before the first sck edge, rises (CSNTRAIL+1) half sck cycles after the last sck edge, and stays high at least (CSNIDLE+1) half sck cycles between commands, where a half sck cycle is CLKDIV+1 core clocks. Tx data changes on the trailing sck edge when CPHA=0 and on the leading edge when CPHA=1. The core clock frequency is not stated, so the test grades a period ratio between two CLKDIV values and no absolute frequency (`hw/sys/sep/doc/clk_rst.adoc`).

*Test Coverage*: CPOL x CPHA x FULLCYC (two mode cells per seed, one at each CPOL value and each CPHA value; the 8 mode cells close on a merge of regressions; FULLCYC is written and its Rx sampling point is not graded), CLKDIV 0 to 15, CSNLEAD and CSNTRAIL 0 to 15, CSNIDLE 1 to 15 in the graded run (step 4 raises it above the control gap, so CSNIDLE 0 is not graded), the sck idle level, the sck period, the chip-select lead, trail and idle gap, the Tx data edge at CLKDIV 1 or more, and the period ratio of two CLKDIV values. The cell CPHA=1 with FULLCYC=1 is logged and not graded, because `spi_controller.adoc` (CONFIGOPTS) gives it a shift edge that differs from the general CPHA text. The open test `sep_spi_ot_host_csr_irq_rand_test` grades CONFIGOPTS read-back only; the pad effect is graded here. Functional coverage: `sep_spi_pad_interface_cg` (`cp_pad_timing_ok`) and `sep_spi_pad_rand_cg` (`cp_idle_level`; graded on a merge of regressions: `cp_mode8`, `cp_mode_x_dir`, `cp_clkdiv_class`, `cp_csn_class`, `cp_cpha_edge`).

. Control run. With ACTIVE=0, write CONFIGOPTS with the drawn mode cell, CLKDIV a, the drawn CSNLEAD and CSNTRAIL, and CSNIDLE=0. Never write CONFIGOPTS while a transaction runs. Write the TXDATA words of a Tx segment of 16 bytes (4 words, each with bytes that alternate 0x55 and 0xAA). After a STATUS read that shows READY=1, write COMMAND for that Tx segment (SPEED 0, DIRECTION 2, CSAAT=0). Then poll STATUS until a read shows READY=1 and ACTIVE=1, so that the first segment is still active, and write COMMAND for an Rx segment of 4 bytes (SPEED 0, DIRECTION 1, CSAAT=0) right after that read. Wait until the pair is done. Read RXDATA until RXEMPTY=1, each read after a STATUS read that shows RXEMPTY=0. Take g0, the number of core clocks that chip select stays high between the two transactions.
. Raise CSNIDLE. When (CSNIDLE+1)*(a+1) is not above g0, set CSNIDLE to the smallest value in 0 to 15 whose minimum (CSNIDLE+1)*(a+1) is above g0. When even the value 15 does not give a minimum above g0, log CTRL-MISSING and fail.
. Graded run. With ACTIVE=0, write CONFIGOPTS with the drawn mode cell, CLKDIV a, CSNLEAD, CSNTRAIL and the CSNIDLE of step 4. Write the TXDATA word first, with bytes that alternate 0x55 and 0xAA as in step 3, so that step 7 has at least two data changes after the first bit when it grades this run; then after a STATUS read that shows READY=1 write COMMAND for one Tx segment of 4 bytes (SPEED 0, DIRECTION 2, CSAAT=0), wait until the segment is done, and take the sck period as period_a. With ACTIVE=0, write CONFIGOPTS with CLKDIV b and the other fields unchanged. Run the same Tx segment in the same order, wait until the segment is done, and take the period as period_b.
. Grade the Tx data edge on the run whose CLKDIV is 1 or more: the graded run of step 5 when a is at least 1, else the CLKDIV b run of step 6. Take the data changes on `spi_mosi_o` after the first bit. The first bit is exempt, because it is set up before the first sck edge. A change is "in the stated half" when it lies at or after the stated sck edge and before the next sck edge: the trailing edge for CPHA=0 and the leading edge for CPHA=1. In the cell CPHA=1 with FULLCYC=1, do not grade; log the cell as not graded and ambiguous. When the graded run has fewer than two data changes after the first bit, log CTRL-MISSING and fail.

===== 4.9 `sep_spi_fifo_stall_watermark_rand_test`

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, no `rst_ni` pulse, 3 seeds; tool: both (Verilator and VCS); testlist groups `cpu_stub` and `all`, file `spi.toml`

*Source Module*: `sep_spi_fifo_stall_watermark_rand_test`

*BFM / Model*: `ocah_axi_vip` for the register frontdoor over `s_axi` (CPU-LSU splice, approved). A test-side sampler reads the pad ports `spi_sck_o` and `spi_cs_n_o` on each core clock (approved). No responder is attached; `spi_miso_i` stays at its testbench default and Rx bit content is not graded. No checker needs a proposed probe. No inject. No check is blocked.

*Randomization*: `SepSeededRng` from the run seed (RAND-REP). Dimensions: the SPEED of the stall legs (0, 1 or 2), the TX arrival gap, the Rx read gap and burst length, the payload words, the mid TX watermark value (2 up to the TX depth minus 1), the TX control watermark (1, the mid value or the TX depth), the mid RX watermark value (2 up to the RX depth minus 2), the order of the RX watermark values and CLKDIV (1 to 3). Every seed runs the stall legs at the drawn SPEED, the TX watermarks 0 and the TX depth plus 1 (when that is at most 255) with the drawn control watermark, and the RX watermarks 0, 1 and the mid value. The graded TX cells are TX_WATERMARK 0 and the TX depth plus 1. The classes "depth" and "depth plus 1" resolve against the depth that the leaf finds in the run. `reseed = 3` samples other speeds, gaps, bursts, payloads, control watermarks, mid values and CLKDIV values. The plan of legs is the same on every seed. The stall x SPEED cells depend on the seed and close on a merge of regressions (<<sep-fcov-rand,SEP_FCOV>>).

*Objective*: The FIFO status contract holds (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, CONTROL and STATUS registers; later cites in this entry use the file name only). TXSTALL and RXSTALL assert, and sck pauses, while an active segment waits for TX data or for RX space. STATUS.TXWM is set while TXQD is below TX_WATERMARK. STATUS.RXWM is set while RXQD exceeds RX_WATERMARK. Each TXDATA write and each RXDATA read moves one 32-bit word. CMDQD counts the accepted commands. TXFULL, TXEMPTY, RXFULL and RXEMPTY follow the occupancy, and a FIFO is never full and empty together.

*Test Coverage*: TXSTALL and RXSTALL at a drawn speed (0, 1 or 2) on every seed, with the three speeds closing on a merge of regressions; TX watermark cells at watermark 0 and above the depth; RX watermark cells on both sides of each of the thresholds 0, 1 and a mid value; each RXDATA read; CMDQD with a held head segment; TXFULL while a segment is active; RXFULL below and at the RX depth while the host is idle; the four flags TXFULL, TXEMPTY, RXFULL and RXEMPTY. The open test `sep_spi_ot_host_csr_irq_rand_test` grades TXWM and TXQD at TX_WATERMARK 2 to 8, and the open test `sep_spi_ot_dma_tx_test` grades STATUS.TXWM against TXQD at TX_WATERMARK 4. The TX cells at watermark 1, a mid value and the TX depth are controls here: the leaf runs one of them, drawn per seed, logs it with `OBS-SPI-WM` and grades nothing. Entry 4.7 grades the Rx word count and RXQD (CHK-SPI-RXCNT), so TXQD and RXQD at idle are logged and not graded here. This entry adds watermark 0, a watermark above the depth, the RX axis, the stall flags, the RXQD step per read and RXFULL. The overflow and underflow kinds are graded in <<sep_spi_ot_host_csr_irq_rand_test_leg,entry 4.10>>. Functional coverage: `sep_spi_fifo_status_cg` (`cp_flag`, `cp_stall`, `cp_ready_x_active`, `cp_cmd_accept`, `cp_tx_write_space`, `cp_rx_read`, `cp_depth_counter`), `sep_spi_fifo_rand_cg` (`cp_txwm`, `cp_rxwm`; graded on a merge of regressions: `cp_stall_x_speed`) and `sep_spi_pad_rand_cg` (graded on a merge of regressions: `cp_clkdiv_class`).

*Test Procedure*:

[arabic]
. Draw the SPEED of the stall legs, the TX arrival gap, the Rx read gap and burst, the payload words, CLKDIV, the two mid watermark values, the TX control watermark and the RX watermark order from the seed. Log the plan first (`PLAN seed=<n> ...`). "The drawn speed" in the steps below is that SPEED. Every wait in the steps below is a bounded wait; a timeout fails the check that the step feeds. The stall window is 8 sck periods, a test parameter. A segment is done when the sampler has shown chip select low and then high (for a chain with CSAAT=1, high after the last segment) and a later STATUS read shows ACTIVE=0 and CMDQD=0. Every wait for a segment below is this bounded wait, so a STATUS read taken before the command starts does not end it. Before every COMMAND write the test polls STATUS until READY=1 (bounded). Run the SPI clean state before every leg. The SW_RST helper writes CONTROL.SW_RST=1 with the other fields kept, polls STATUS until TXEMPTY=1 and RXEMPTY=1, then writes CONTROL.SW_RST=0. The SPI clean state writes 1 to every bit of ERROR_STATUS and to INTR_STATE.ERROR, writes CSID=0, and runs the SW_RST helper.
. Start from the harness reset state. Write CONTROL with SPIEN=1, OUTPUT_EN=1, SW_RST=0, TX_WATERMARK=0 and RX_WATERMARK=0x7F. Write CONFIGOPTS with CPOL=0, CPHA=0, FULLCYC=0, CSNLEAD, CSNTRAIL and CSNIDLE at 0 and the drawn CLKDIV. Write CSID=0. Read STATUS; log that TXEMPTY and RXEMPTY are set.
. TX depth. With no COMMAND, write TXDATA words one at a time, each after a STATUS read that shows TXFULL=0 and ACTIVE=0. Stop at the first STATUS read that shows TXFULL=1, and never write once more. The number of words written is the TX depth; log it. Run the SW_RST helper.
. RX stall. Poll STATUS until READY=1, then write COMMAND for an Rx segment of 1032 bytes (the drawn speed, DIRECTION 1, CSAAT=0), which is more words than the 8-bit RXQD counts. Read no RXDATA. Count the sck edges from the COMMAND write until a STATUS read shows RXFULL=1 and RXSTALL=1; this count is the control and must be above 0, else CTRL-MISSING. Open the stall window at that read and count the sck edges in it. Read STATUS at the start and at the end of the window; both reads show RXFULL=1 and RXSTALL=1 and the same RXQD. Log that RXQD as s. Because RXQD may be an underestimate while ACTIVE=1, s is a lower bound of the RX depth and only the start of the search in step 5. When the two RXQD values differ, log CTRL-MISSING and fail.
. Drain the RX FIFO in bursts of the drawn length with the drawn gap, each RXDATA read after a STATUS read that shows RXEMPTY=0, until the segment is done and RXEMPTY=1. The drain reads 258 words in total, the words of the 1032 bytes. Then find the RX depth with ACTIVE=0: for r from the larger of 1 and s minus 1 upward, run the SPI clean state, run an Rx segment of 4*r bytes (the drawn speed, DIRECTION 1, CSAAT=0) with no RXDATA read, wait until the segment is done, and read STATUS. The first r whose read shows RXFULL=1 is the RX depth R; log it. Every smaller r shows RXFULL=0; log RXQD with `OBS-SPI-QD`. When r reaches 255, the largest the 8-bit RXQD holds, with no RXFULL=1, log CTRL-MISSING and fail. Read RXDATA until RXEMPTY=1 and run the SW_RST helper.
. TX stall. Draw m (the segment length in words, 2 up to the TX depth) and m1 (1 up to m minus 1). After a STATUS read that shows READY=1, write COMMAND for a Tx segment of 4*m bytes (the drawn speed, DIRECTION 2, CSAAT=0). Write m1 TXDATA words. Wait until the sampler shows 4*m1*8/lanes sck cycles. Poll STATUS until TXSTALL=1. Open the stall window at that read and count the sck edges in it; read STATUS at the start and at the end of the window, and both show TXSTALL=1. Hold for the drawn gap after the window. Write the remaining m minus m1 words. Poll STATUS until TXSTALL=0. Wait until the segment is done and take the sck cycle count of the segment.
. TX stall control. Run the SPI clean state. Write all m TXDATA words, then after a STATUS read that shows READY=1 write the same COMMAND. Read STATUS repeatedly until the segment is done. Every read that the sampler shows taken while chip select is low shows TXSTALL=0; at least one read is taken while chip select is low, else CTRL-MISSING. Take the sck cycle count.
. TX watermark. Take three values of Wt, resolved against the TX depth: 0, the TX depth plus 1 (skipped when it is above 255) and the drawn control value (1, the drawn mid value or the TX depth). At each q, poll STATUS until TXQD=q with ACTIVE=0; that read gives TXWM. The reads of Wt 0 and of the TX depth plus 1 are graded; the reads of the control value are logged with `OBS-SPI-WM`. Run the SW_RST helper after each Wt.
. TX watermark control. Run the SPI clean state. Write CONTROL.TX_WATERMARK=1 and poll STATUS until TXWM=1, with TXQD=0 in that read.
. RX watermark. For each Wr of 0, 1 and the drawn mid value, in the drawn order, write CONTROL.RX_WATERMARK=Wr with the other fields kept. For each r in Wr minus 1 (when Wr is at least 1) and Wr plus 1, run the SPI clean state, then after a STATUS read that shows READY=1 run an Rx segment of 4*r bytes (DIRECTION 1, CSAAT=0) with no RXDATA read, skipping the segment when r is 0. Wait until the segment is done, then poll STATUS until RXQD=r; that read gives RXWM. Never drive r equal to Wr. After the Wr plus 1 run of each Wr, run step 11 before the next Wr.
. RX drain and counters. After the Wr plus 1 run of each Wr, read RXDATA one word at a time until RXEMPTY=1, each read after a STATUS read that shows RXEMPTY=0. After each read, poll STATUS until RXQD is one lower; that read gives RXWM. For Wr of 1 or more, the read at RXQD equal to Wr minus 1 shows RXWM=0 (CHK-SPI-WM, crossing out). RXWM at RXQD equal to Wr is logged and not graded. Run the SW_RST helper.
. Command queue. After a STATUS read that shows READY=1, write COMMAND for a Tx segment of 4 bytes (SPEED 0, DIRECTION 2, CSAAT=0) with no TX data. Poll STATUS until ACTIVE=1 and TXSTALL=1; the head segment is held. Read CMDQD as c0. Write n further COMMANDs (DIRECTION 0, LEN 0, CSAAT=0), n drawn from 1 to 3, each after a STATUS read that shows READY=1; stop when READY=0. After each accepted COMMAND, poll STATUS until CMDQD differs from its previous value; the new value is the previous value plus 1. Log CMDQD and READY. At least one COMMAND must be accepted, else CTRL-MISSING.
. Release the queue. Write one TXDATA word. Wait until the sampler has shown, after that write, one chip-select rise for the held segment and one chip-select-low window per accepted COMMAND, and STATUS shows ACTIVE=0 and CMDQD=0. Run the SW_RST helper.
. TX full while active. Write CONFIGOPTS with CLKDIV 3 and the other fields as in step 2. Let D be the TX depth and K a test parameter equal to D. After a STATUS read that shows READY=1, write COMMAND for a Tx segment of 4*(D+K) bytes (SPEED 0, DIRECTION 2, CSAAT=0). Write TXDATA words, each after a STATUS read that shows TXFULL=0, until a STATUS read shows TXFULL=1 with ACTIVE=1; log its TXQD. When the segment is done, or all D+K words are written, without such a read, log CTRL-MISSING and fail. Write the remaining words, each after TXFULL=0. Wait until the segment is done and take the sck cycle count.
. RX full while idle. Run the SPI clean state. Run an Rx segment of exactly 4*R bytes (the drawn speed, DIRECTION 1, CSAAT=0), where R is the RX depth found in step 5, with no RXDATA read. Wait until the segment is done. Read STATUS; RXFULL is graded and RXQD is logged with `OBS-SPI-QD`. Capacity check: after a STATUS read that shows READY=1, write COMMAND for one more Rx segment of 4 bytes (the drawn speed, DIRECTION 1, CSAAT=0) with no RXDATA read. Wait until the sampler shows chip select high after that segment, or until the stall window passes with no sck edge, and read STATUS: RXQD is not above R, because a full FIFO takes no word. Then read RXDATA until the segment is done and RXEMPTY=1, each read after a STATUS read that shows RXEMPTY=0; the words read equal R+1. Run the SW_RST helper.
. Apply the flag-pair rule to every STATUS read of the seed: TXFULL and TXEMPTY are never both set, and RXFULL and RXEMPTY are never both set. Require that each of the four flags is set in at least one read of the seed.

|CHK-SPI-QD
|With ACTIVE=0, each RXDATA read lowers RXQD by 1 (`spi_controller.adoc`, STATUS.RXQD). TXFULL is set in a STATUS read with ACTIVE=1 during a Tx segment of 4*(D+K) bytes, and that segment ends with 4*(D+K)*8 sck cycles, so a full FIFO loses no word. R is the first idle segment length whose read shows RXFULL=1, so RXFULL below R is the search itself and is logged, not graded. After an Rx segment of exactly R, RXFULL is set; a further 4-byte Rx segment does not raise RXQD above R, and the drain then reads R+1 words, so RXFULL marks the real capacity of the RX FIFO and the held word is not lost. A host that sets RXFULL before the FIFO is full shows RXQD of R+1 after the further segment and fails. R comes from idle reads only; the RXQD of the stall window is a lower bound and is not graded. TXFULL and TXEMPTY, and RXFULL and RXEMPTY, are never both set. A host that keeps RXQD after a read, that loses a word at a full TX FIFO, or that sets both flags of a pair, fails. Anchor: STATUS readback (approved frontdoor). TXQD and RXQD at idle are logged and not graded: the open test `sep_spi_ot_host_csr_irq_rand_test` grades TXQD against the words written (CHK-WATERMARK), and entry 4.7 grades the received word count (CHK-SPI-RXCNT). Control for the flag pairs: each of the four flags is seen set in the same seed, else CTRL-MISSING. Evidence: `CHK-SPI-QD PASS seed=<n> idle=1 rxqd_step_ok=1 txfull_active=1 txfull_cycles=<got>/<exp> rxfull_at_R=1 rxqd_after_extra=<q> max=<R> words_after_extra=<w>/<R+1> pairs_both_set=0 seen_txfull=1 seen_txempty=1 seen_rxfull=1 seen_rxempty=1` and `OBS-SPI-QD seed=<n> txqd=<t> rxqd=<r>` per idle read.
|CHK-SPI-CMDQD
|CMDQD rises by 1 per accepted COMMAND while the head segment is held, and after the held segment is released every queued command runs on the pad (one chip-select-low window per accepted COMMAND after the held segment) and the queue empties (CMDQD reads 0 with ACTIVE low) (`spi_controller.adoc`, STATUS.CMDQD). A host that does not count a queued command, or that drops it, fails: a dropped command gives CMDQD 0 with fewer chip-select-low windows. Anchor: STATUS readback (approved frontdoor) and the pad ports `spi_sck_o` and `spi_cs_n_o` (approved). Control: the head segment is held (ACTIVE=1 and TXSTALL=1) when the first COMMAND is written, and at least one COMMAND is accepted, else CTRL-MISSING. Evidence: `CHK-SPI-CMDQD PASS seed=<n> queued=<n> cmdqd=<c> ready=<r> cs_windows=<got>/<1+n> drained=1`.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Scope limit*: The TX and RX depths are found at run time and never compared with a value. RXWM at RXQD equal to RX_WATERMARK is not graded. A watermark of 0x7F against the reset value of RX_WATERMARK is not graded, because the RX depth is not stated. TXQD and RXQD are not compared while ACTIVE=1. The values read from RXDATA are not graded. The open tests `sep_spi_ot_host_csr_irq_rand_test` and `sep_spi_ot_dma_tx_test` own their TX watermark cells; the TX cells at watermark 1, a mid value and the TX depth are controls here and are not graded. TXQD and RXQD at idle are logged and not graded. Overflow and underflow are graded in entry 4.10.

===== 4.10 `sep_spi_ot_host_csr_irq_rand_test` (extension)

*Phase*: 3 (extends an open test)

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`) with `+skip_fuse_sense`, as the open test, 3 seeds, the seed count of the open test entry; tool: both (Verilator and VCS); the entry of the open test in `spi.toml`, with no testlist entry added

*Source Module*: `sep_spi_ot_host_csr_irq_rand_test`

*BFM / Model*: `ocah_axi_vip` for the register frontdoor over `s_axi` (CPU-LSU splice, approved), including 8-byte writes with a chosen strobe and the response code of every access. A test-side sampler reads the pad ports `spi_sck_o` and `spi_cs_n_o` on each core clock (approved). `sep_internal_interrupts_probe_o` index 13 is PIC source 14 (approved). No checker needs a proposed probe. No inject. No check is blocked.

*Randomization*: `SepSeededRng` from the run seed. RANDCFG: INTR_ENABLE of the L1 state reads, the source-state order and the masked kind. RAND-REP: the rest. Dimensions: one EVENT_ENABLE value (a subset of TXEMPTY, TXWM, RXFULL and RXWM) at each true state, INTR_ENABLE of the L1 state reads (0 to 3), the order of the four INTR_ENABLE values of the line walk, the kind order, the command kind of the accumulation and of the write of 0 (CSIDINVAL, CMDINVAL or CMDBUSY), the accumulation depth (2 to 3), a 6-bit clear mask (at least one injected bit inside the mask and at least one outside), the pair order, the strobe order, the data words (implemented bits only, unique per word, different from the register content), the out-of-range CSID value v (2 to 0xFFFFFFFE, uniform), the SW_RST point inside a segment, the extra TX words (1 to 4) and the queued command count n (1 to 3). `reseed = 3` samples other orders, enables, masks, command kinds, points and data. Every seed runs each source level change with its EVENT_ENABLE bit at 0 and at 1, the 16 (INTR_ENABLE, INTR_STATE) cells of the line walk (register accesses only), the five error kinds, CSIDINVAL at v (graded) and at CSID=1 (logged only), and all 12 strobe cells. The write of 0 runs over the drawn command kind with UNDERFLOW and OVERFLOW, so the `w0_on_set` cells of the command kinds in `cp_clear_form` depend on the seed and close on a merge of regressions (<<sep-fcov-rand,SEP_FCOV>>).

*Objective*: This entry extends the open test `sep_spi_ot_host_csr_irq_rand_test`. The open test grades the reset values and the read-write walk, INTR_STATE.ERROR set by INTR_TEST and cleared by write one, SPI_EVENT following the INTR_TEST force level, PIC source 14 against INTR_ENABLE for both sources, each ERROR_STATUS kind set by its own trigger and cleared by write one, TXWM at two TX_WATERMARK values, one SPIEN hold window with OUTPUT_EN=1, the SW_RST FIFO check, and a zero-strobe half on the CONTROL register. Every cell of the open test stays as a control, and the open test keeps the grading of those cells. The four legs below add only the new cells.

* Leg L1, event sources and interrupt line (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, INTR_STATE, INTR_ENABLE, EVENT_ENABLE and STATUS registers; `hw/sys/sep/doc/spi.adoc`, Features; `hw/sys/sep/doc/interrupts.adoc`, SEP CPU Interrupt Vector Map; later cites in this entry use the file names only). INTR_STATE.SPI_EVENT follows the OR of the levels of the sources that EVENT_ENABLE selects. The level of IDLE is STATUS.ACTIVE low. The level of READY, TXEMPTY, RXFULL, TXWM and RXWM is the matching STATUS bit. INTR_ENABLE gates only the line into PIC source 14.
* Leg L2, error latch (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, ERROR_ENABLE, ERROR_STATUS, INTR_STATE and STATUS.READY; `hw/sys/sep/doc/spi.adoc`, Features). Each injected condition with its ERROR_ENABLE bit set sets the latched INTR_STATE.ERROR. A clear of ERROR_STATUS leaves INTR_STATE.ERROR set. Accumulated kinds OR into ERROR_STATUS, and a write of 1 clears only the written bits. A COMMAND written while READY=0 sets CMDBUSY also when no segment is active.
* Leg L3, 8-byte writes (`hw/sys/sep/doc/spi.adoc`, Features; `vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, ERROR_STATUS). An 8-byte AXI write whose strobes select one 4-byte half lands that half, leaves the other half unchanged and returns OKAY. A half with all strobes clear issues no TL-UL request and queues no TXDATA word. A forwarded half returns an error (`spi.adoc`, Features), so BRESP OKAY and an unchanged TXQD grade that the bridge does not forward the half.
* Leg L4, SW_RST and SPIEN (`vendor/lowRISC/opentitan/overlay/regs/spi_controller/regs/gen/adoc/spi_controller.adoc`, CONTROL and STATUS). CONTROL.SW_RST reads back 1 until firmware writes 0, and clears the FIFOs and the core state but not the registers. CONTROL.SPIEN=0 holds queued commands off the pad, and SPIEN=1 runs them in order.

*Test Coverage*: This entry extends `sep_spi_ot_host_csr_irq_rand_test`. Only the new cells below are graded here. The open test keeps every cell listed in the Objective. L1: SPI_EVENT from real sources (TXEMPTY, TXWM, RXWM, RXFULL, IDLE, READY) for EVENT_ENABLE 0xF and a drawn EVENT_ENABLE value at each true state, each source level change with its EVENT_ENABLE bit at 0 and at 1, INTR_ENABLE 0 to 3 with an enabled twin, the line walk of INTR_ENABLE 0 to 3 against the INTR_STATE cells none, error, event and both (11 graded cells; the five cells that the open test grades with the same stimulus are controls), the mask step and the level legs for IDLE and READY. L2: the five kinds CSIDINVAL, CMDINVAL, UNDERFLOW, OVERFLOW and CMDBUSY singly (the INTR_STATE.ERROR latch cells; the own-bit and clear cells stay with the open test) and accumulated (at most one command kind, injected first), with 6-bit clear masks that have a hit bit and a kept bit, a write of 0 with the drawn command kind set together with UNDERFLOW and OVERFLOW, CMDBUSY with ACTIVE=1 and with ACTIVE=0, and one kind injected with its ERROR_ENABLE bit clear (logged only). L2 also grades the own-bit value of CSIDINVAL at a drawn CSID from 2 to 0xFFFFFFFE and logs it at CSID=1, where the specification texts differ (<<sep-vplan-phase3-blocked,Blocked features>>); the open test drives CSID=0xFFFFFFFF. L3: four register pairs (0x00, 0x18, 0x28 and 0x30) with strobes 0x0F, 0xF0 and 0xFF (12 cells), including the TXDATA half. L4: SW_RST at a drawn point of a segment with non-reset register values, and SPIEN=0 with 1 to 3 queued commands followed by SPIEN=1. Functional coverage: `sep_spi_interrupt_cg` (`cp_event_aggregation`, `cp_intr_test`), `sep_spi_misc_rand_cg` (`cp_event_src_x_en_x_cond`, `cp_intr_en_x_state`, `cp_swrst_midseg`; graded on a merge of regressions: `cp_clear_form`), `sep_spi_error_status_cg` (`cp_error_raised_cleared`, `cp_intr_error_latch`, `cp_underflow_cell`, `cp_overflow_cell`, `cp_zero_strobe_cell`, `cp_csid_out_of_range`), `sep_spi_illegal_access_cg` (`cp_cmdbusy_cell`, `cp_spien0_cmd_write`), `sep_periph_reset_state_cg` (`cp_sw_rst_domain`, `cp_sw_rst_hold`), `sep_spi_pad_interface_cg` (`cp_spien_hold_run`) and `sep_spi_fifo_status_cg` (`cp_ready_x_active`, `cp_depth_counter`).

Every wait for a segment below is this bounded wait, so a STATUS read taken before the command starts does not end it. [arabic]

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`), `+skip_fuse_sense`, 4 seeds, Verilator and VCS; testlist groups `cpu_stub` and `all`, file `system.toml`, one testlist entry. The test never asserts `rst_ni`. Leg A runs 16 transfers per run, one per mode cell, each of at most 1 KB.

Every drawn offset and guard is a multiple of 4, so both addresses are aligned to every width encoding and have the same alignment (`secure_dma.rdl`, SRC_ADDR_LO, DST_ADDR_LO, TRANSFER_WIDTH). Every drawn size is a multiple of 4, TOTAL_DATA_SIZE is a multiple of CHUNK_DATA_SIZE, and the message and split lengths of the hash trials are multiples of 4. Every seed runs the 16 mode cells, each width encoding, the totals 4 and 16384 bytes, the six edge cells, each algorithm with its published vector at both DIGEST_SWAP values, and the pairs of `sep_dma_basic_test` at n of 2 or more. `reseed = 4` samples four different widths, chunk counts, orders, middle totals, region orders, message lengths, splits, offsets and data sets. *Objective*: The DMA transfer contract holds in four legs. The open tests `sep_dma_basic_test` and `sep_dma_hash_test` grade the cells listed in each leg. Those cells are controls here.

* Leg A, address modes and widths (`secure_dma.adoc`, TRANSFER_WIDTH, SRC_CONFIG, DST_CONFIG; `dma.adoc`, overview; `fabric.adoc`, Top Level AXI4). INCREMENT=1 advances the address by the transfer width after each transaction. INCREMENT=0 keeps every access at one address. WRAP=1 returns the address to the start at each chunk end. WRAP=0 places the chunks at contiguous ascending addresses. Transactions of the programmed width are issued until TOTAL_DATA_SIZE bytes have moved, each as a single beat. `sep_dma_basic_test` walks the increment, fixed and wrap modes at 4 bytes, and the width encodings with INCREMENT only. This leg adds all 16 source-and-destination cells with three width encodings, destination wrap and single-chunk wrap. `sep_dma_basic_test` grades six pairs of a cell and a width encoding at one shape: INCREMENT=1 with WRAP=0 on both sides at the width encodings 0, 1 and 2 with one chunk; source INCREMENT=0 with WRAP=1 and destination INCREMENT=1 with WRAP=0, and source INCREMENT=1 with WRAP=0 and destination INCREMENT=0 with WRAP=1, each at the width encoding 2 with one chunk; source INCREMENT=1 with WRAP=1 and destination INCREMENT=1 with WRAP=0 at the width encoding 2 with two chunks. This entry runs those six pairs with n of 2 or more (n of 3 or more for the last pair), so no graded run repeats the open shape.
* Leg B, geometry and completion (`secure_dma.adoc`, TOTAL_DATA_SIZE, CHUNK_DATA_SIZE, CONTROL.GO, STATUS). A normal transfer sets DONE, clears GO itself, clears DONE when the next transfer starts, raises no CHUNK_DONE for a single chunk, and raises CHUNK_DONE for a multi-chunk memory-to-memory transfer. `sep_dma_basic_test` copies 16 to 32 bytes, polls DONE and grades that a multi-chunk transfer raises CHUNK_DONE. This leg adds sizes up to 16 KB, the single-chunk negative, and DONE and GO auto-clear. The zero-size error is graded in <<sep_dma_irq_error_lock_rand_test,entry 4.13>>.
* Leg C, range edges (`secure_dma.adoc`, ENABLED_MEMORY_RANGE_BASE, ENABLED_MEMORY_RANGE_LIMIT, RANGE_VALID). With RANGE_VALID set, a transfer whose source and destination bytes all lie in BASE to LIMIT (LIMIT inclusive) completes. `sep_dma_basic_test` grades RANGE_VALID=0, BASE above LIMIT, one lock and one rejected write. This leg adds the exact edges in both region orders. The lock is graded in entry 4.13.
* Leg D, inline hashing (`dma.adoc`, overview and Completion Reporting; `secure_dma.adoc`, CONTROL, STATUS, SHA2_DIGEST_0, TRANSFER_WIDTH). With inline hashing selected, a transfer chain with INITIAL_TRANSFER on the first transfer gives SHA2_DIGEST_0 words equal to the SHA-2 digest of the bytes. SHA2_DIGEST_VALID clears at the initial transfer and sets when the digest is written. DIGEST_SWAP=1 gives each word in big-endian order without changing the word order. `sep_dma_hash_test` grades SHA-256 on random data, SHA-384 on one 56-byte vector, a two-chunk message and DIGEST_SWAP set against clear. This leg adds SHA-512, block boundaries and SHA2_DIGEST_VALID. The cells that `sep_dma_hash_test` grades are controls: SHA-256 at 56 bytes as one transfer with either DIGEST_SWAP value, SHA-256 at 56 bytes as one transfer of two 28-byte chunks with DIGEST_SWAP=1, and SHA-384 at 56 bytes as one transfer with DIGEST_SWAP=1. The leaf runs them, logs `OBS-DMA-HASH-CTRL`, prints no `CHK-DMA-HASH` or `CHK-DMA-HASH-CHAIN` PASS line for them and does not count them in k. The hash width rule is graded in entry 4.13.

*Test Coverage*: Leg A: the 16 cells of source {INCREMENT, WRAP} x destination {INCREMENT, WRAP} on every seed, each at a drawn width encoding (every encoding on every seed; the 48 mode and width cells close on a merge of regressions) and with a drawn chunk count, destination wrap, single-chunk wrap (same image as WRAP=0), multi-chunk wrap (restart at each chunk start), and INCREMENT=0 with WRAP=0 on a side with one chunk; the six pairs that `sep_dma_basic_test` grades run with n of 2 or more. Leg B: the single-chunk total 4 bytes and a drawn single-chunk total of 64, 256, 1024 or 4096 bytes, one 16384-byte total as four chunks of 4096 bytes, drawn multi-chunk transfers, DONE and GO auto-clear, no CHUNK_DONE for a single chunk. Leg C: BASE and LIMIT exactly on the region edges (low edge, high edge, both edges, both edges with a guard at either end and at both ends), each in a drawn region order. Leg D: SHA-256, SHA-384 and SHA-512 at 4-byte transfers, drawn block-boundary lengths, the published 56-byte and 112-byte vectors, each message as one single-chunk transfer and, where an equal split exists, as one transfer of 2 to 4 equal chunks, both DIGEST_SWAP values, SHA2_DIGEST_VALID, with its clear graded on one long message of 1024 to 4096 bytes per seed; the three cells that `sep_dma_hash_test` grades are controls. The test builds on the open tests `sep_dma_basic_test` and `sep_dma_hash_test`. Only the cells above are graded here. The open owners keep the cells they grade. Functional coverage: `sep_dma_transfer_cg` (`cp_src_x_dst_mode`, `cp_alignment_baseline`, `cp_mode_hash_chunk`), `sep_dma_xfer_rand_cg` (`cp_mode_x_width`, `cp_mode_x_chunkcount`, `cp_wrap_independence`), `sep_dma_endpoint_cg` (`cp_beats_per_txn`, `cp_src_x_dst_endpoint`), `sep_dma_completion_cg` (`cp_go_lifecycle`, `cp_busy_phase`, `cp_done_set`, `cp_done_clear_path`, `cp_chunk_done_class`, `cp_chunk_done_clear`, `cp_chunk_decomp`), `sep_dma_copy_hash_cg` (`cp_hash_opcode`, `cp_chunk`), `sep_dma_hash_cg` (`cp_initial_transfer_ctx`, `cp_digest_valid_lifecycle`, `cp_digest_swap_x_word`, `cp_msg_len_class`), `sep_dma_range_config_cg` (`cp_range_valid_at_go`, `cp_base_limit_rel`, `cp_inrange_pos_x_side`, `cp_unlocked_write`) and `sep_dma_rand_cg` (`cp_len`). Graded on a merge of regressions, because the seed draws their cells: `cp_mode_x_width`, `cp_mode_x_chunkcount`, `cp_wrap_independence`, `cp_inrange_pos_x_side`, `cp_msg_len_class` and the `cp_len` bins `b64` to `b4096`.

*Test Procedure*:

[arabic]
. Draw every value from the seed and log it in `DRAW` lines. Build the model of the register text and the digest golden from the drawn data. The model never reads a value from the DUT.
. Write ENABLED_MEMORY_RANGE_BASE = 0x10000000 and ENABLED_MEMORY_RANGE_LIMIT = 0x1003FFFF (the SEP SRAM, `memory_map.adoc`) and RANGE_VALID = 1. Write ADDR_SPACE_ID = 0x77 and both ADDR_HI registers = 0. Write 1 to STATUS.DONE and STATUS.CHUNK_DONE. Write INTR_ENABLE with DMA_CHUNK_DONE=1 and the other bits 0, and from this step sample bit 9 of `sep_internal_interrupts_probe_o` at every clock (the control of CHK-DMA-CHUNKDONE). Never write RANGE_REGWEN. Never write a configuration register while STATUS.BUSY reads 1.
. Leg A. For each of the 16 mode cells, in a drawn order and at the drawn width encoding of the cell: fill the source footprint with unique words (index plus drawn bits). Fill the destination footprint and one guard word before and one after it with sentinel words (see Sentinel in the rules of this section). Keep the footprints disjoint and inside BASE to LIMIT.
. Leg A. Write SRC_ADDR_LO, DST_ADDR_LO, TOTAL_DATA_SIZE, CHUNK_DATA_SIZE, TRANSFER_WIDTH, SRC_CONFIG and DST_CONFIG in a drawn order. A side with INCREMENT=0 and WRAP=0 runs with one chunk (TOTAL_DATA_SIZE equals CHUNK_DATA_SIZE). Write CONTROL with OPCODE 0 (COPY), INITIAL_TRANSFER=1 and GO=1.
. Leg A. Poll STATUS until DONE=1 and BUSY=0, with a bounded wait that scales with the total of the cell. DONE and CHUNK_DONE are clear at the GO write (step 2 and step 7), so a DONE=1 read is the result of this transfer. A timeout fails with `FAIL-DMA-TIMEOUT`. When STATUS reads CHUNK_DONE=1, DONE=0 and BUSY=0, write CONTROL with OPCODE 0, GO=1 and INITIAL_TRANSFER=0, count the write in `go_writes`, and wait with a bound until `dma_busy_probe_o` has risen since that write before the next evaluation. This re-GO rule writes no STATUS bit, so CHUNK_DONE clears only by the hardware when the next chunk starts (CHK-DMA-CHUNKRISE). Log every STATUS value read.
. Leg A. After the poll ends, read STATUS and ERROR_CODE. Read the destination footprint and both guard words through the frontdoor. Compare them with the model (CHK-DMA-IMAGE).
. Leg A. Write 1 to STATUS.DONE and STATUS.CHUNK_DONE, so that the next run starts with both bits clear.
. Leg B. Run the single-chunk total 4 bytes, the drawn single-chunk total (64, 256, 1024 or 4096 bytes; CHUNK_DATA_SIZE equals TOTAL_DATA_SIZE) and the 16384-byte total as four chunks of 4096 bytes, back to back, with INCREMENT=1 and WRAP=0 on both sides and width encoding 2. Then run the drawn transfers (C up to 4096 bytes, total at most 16 KB). Before each transfer, fill the source with unique words and the destination and guards with sentinel words, and write the addresses, TOTAL_DATA_SIZE, CHUNK_DATA_SIZE, TRANSFER_WIDTH = 2, SRC_CONFIG and DST_CONFIG of the transfer. Never write STATUS.DONE between two transfers, so DONE from the previous transfer stays set.
. Leg B. Before the GO write of every transfer, write 1 to STATUS.CHUNK_DONE only. From the second transfer on, read STATUS once just before the GO write (DONE reads 1, the control of CHK-DMA-DONE-CLR). Write CONTROL with OPCODE 0, INITIAL_TRANSFER=1 and GO=1.
. Leg B. From the GO write, sample `dma_busy_probe_o` at every clock and poll STATUS with a bounded wait. The poll ends when the probe has risen since the GO write and STATUS shows DONE=1 and BUSY=0. A timeout fails with `FAIL-DMA-TIMEOUT`. When STATUS reads CHUNK_DONE=1, DONE=0 and BUSY=0, apply the re-GO rule of step 5. For a total of 1024 bytes or more, read CONTROL at least once while the probe reads 1 at the clock of the read (`control_go_busy`). Log every BUSY, DONE and CHUNK_DONE value read, the CONTROL.GO value, and the value of the probe at each clock from the GO write to the end of the poll.
. Leg B. After the poll ends, read STATUS, CONTROL.GO, ERROR_CODE, the destination and the guards (CHK-DMA-GEOM, CHK-DMA-DONE-CLR, CHK-DMA-CHUNKDONE).
. Leg C. Write 1 to STATUS.DONE and STATUS.CHUNK_DONE, because Leg B leaves DONE set.
. Leg C. For each edge cell (low edge: BASE exact and LIMIT wide; high edge: LIMIT exact and BASE wide; both edges exact; both edges exact with a guard word of 4 bytes or more just outside the range at the low end, at the high end and at both ends), in the drawn region order of the cell (source below destination, or the reverse): fill the regions and guards, write BASE equal to the lowest byte and LIMIT equal to the highest byte of the two regions as the cell requires, and write RANGE_VALID = 1. Write the addresses, TOTAL_DATA_SIZE and CHUNK_DATA_SIZE (equal), TRANSFER_WIDTH = 2, and SRC_CONFIG and DST_CONFIG with INCREMENT=1 and WRAP=0. Write CONTROL with OPCODE 0, INITIAL_TRANSFER=1 and GO=1, and poll STATUS until DONE=1 and BUSY=0 with a bounded wait. A timeout fails with `FAIL-DMA-TIMEOUT`.
. Leg C. Read STATUS, ERROR_CODE, the destination and the guards (CHK-DMA-RANGE-OK). Write 1 to STATUS.DONE and STATUS.CHUNK_DONE.
. Leg C. Control. Refill the destination and the guards with sentinel words. Write BASE = 0x10000000 and LIMIT = 0x1003FFFF (the range of step 2, wide over the regions) and run the same copy as in step 13. Poll STATUS until DONE=1 and BUSY=0 with a bounded wait, read STATUS, ERROR_CODE, the destination and the guards (`control_wide` of CHK-DMA-RANGE-OK), and write 1 to STATUS.DONE and STATUS.CHUNK_DONE. Never write RANGE_REGWEN in this leg.
. Leg D. For each algorithm in the drawn order, run three messages: the published vector (56 bytes for SHA-256, 112 bytes for SHA-384 and SHA-512) and the two drawn lengths. After the last algorithm, run the long message (the drawn algorithm, length and DIGEST_SWAP value) as one transfer only. Draw the message bytes of the drawn lengths and of the long message. Place the message in the source region and fill the destination region with sentinel words. Keep the regions disjoint and inside BASE to LIMIT.
. Leg D. For each form (the single-chunk form; for a message with a split form, the drawn split into k equal chunks) run the transfer, with each DIGEST_SWAP value in the drawn order for the published vector and with the drawn DIGEST_SWAP value for a drawn length. Write SRC_ADDR_LO, DST_ADDR_LO, TOTAL_DATA_SIZE = L, CHUNK_DATA_SIZE (L for the single-chunk form, L / k for the split form), TRANSFER_WIDTH = 2 (4 bytes), and SRC_CONFIG and DST_CONFIG with INCREMENT=1 and WRAP=0, so the chunks occupy contiguous ascending addresses (`secure_dma.adoc`, TOTAL_DATA_SIZE, SRC_CONFIG.WRAP, DST_CONFIG.WRAP).
. Leg D. From the second message of the seed on, read STATUS just before the GO write of the initial transfer and log SHA2_DIGEST_VALID (the control of CHK-DMA-HASH-VALID). Write CONTROL with OPCODE 1, 2 or 3 (SHA-256, SHA-384, SHA-512, `dma.hjson`, OPCODE), the DIGEST_SWAP value, INITIAL_TRANSFER=1 and GO=1.
. Leg D. After the initial GO write poll STATUS with a bounded wait until DONE=1 and BUSY=0 (single-chunk form) or until BUSY=0 with CHUNK_DONE=1 or DONE=1 (split form), and log every value read with BUSY=1. A timeout fails with `FAIL-DMA-TIMEOUT`. At DONE=1 write 1 to STATUS.DONE and STATUS.CHUNK_DONE.
. Leg D. For each later chunk of the split form: when STATUS reads CHUNK_DONE=1, DONE=0 and BUSY=0, write 1 to STATUS.CHUNK_DONE, then write CONTROL with the OPCODE and DIGEST_SWAP value of the initial GO write, INITIAL_TRANSFER=0 and GO=1, with no change to the addresses or sizes, and wait with a bound until `dma_busy_probe_o` has risen since that write before the next evaluation (the BUSY condition and the wait of the re-GO rule of step 5). Poll STATUS again as in the step before. At DONE=1 write 1 to STATUS.DONE and STATUS.CHUNK_DONE. More than k GO writes for one transfer fails with `FAIL-DMA-TIMEOUT`.
. Leg D. After the last transfer of the chain, poll STATUS until SHA2_DIGEST_VALID=1 with a bounded wait. A timeout fails CHK-DMA-HASH-VALID.
. Leg D. Read the used SHA2_DIGEST_0 words (8, 12 or 16 for SHA-256, SHA-384 or SHA-512) and the destination bytes. Compare the words with the golden for the DIGEST_SWAP value used (CHK-DMA-HASH). Compare the digest of the single-chunk form with the digest of the split form of the same message and swap value (CHK-DMA-HASH-CHAIN). A message with no split form (no k for which L / k is a multiple of 4, and the long message) runs no CHK-DMA-HASH-CHAIN and does not count it in k. For a control cell of Leg D the leaf logs `OBS-DMA-HASH-CTRL` with the compare result and grades nothing from this step.
. Beat and status checks. Sample `dma_axi_req_probe_o` and `dma_status_probe_o` at every clock from the first GO write of each transfer of Leg A and Leg B to the end of its poll. Grade CHK-DMA-BEAT and CHK-DMA-ADDR on the AR, AW and W beats of each Leg A transfer, CHK-DMA-CHUNKRISE on the CHUNK_DONE level of each transfer, and CHK-DMA-DONE-ORDER on the DONE rise against the last B response of each transfer.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-DMA-IMAGE
|After DONE, the destination image equals the image that the register text gives for the cell, the guard words are unchanged, and ERROR and ERROR_CODE read 0 (`secure_dma.adoc`, SRC_CONFIG, DST_CONFIG, TRANSFER_WIDTH). The model gives transaction k (k = 0 to T/w - 1, with width w, total T, chunk C) in chunk j = floor(k*w/C) at position p = k - j*C/w. The address of the transaction is SRC + p*w for INCREMENT=1 and WRAP=1, SRC + k*w for INCREMENT=1 and WRAP=0, and SRC for INCREMENT=0. The destination address follows the same rule with DST. The image is the source word of each transaction written in order. A wrong word address sequence, a wrong width, a missing wrap restart or a write outside the footprint gives another image or a changed guard. Anchored on frontdoor reads of the source and destination footprints. Control: every byte that the transfer writes differs from the sentinel byte s, so a missing write shows. The source words are unique, so a word read from a wrong word address shows wherever that word stays in the image. Source bytes are not unique, so at width encodings 0 and 1 a wrong byte address that reads an equal byte value does not show; the beat address check is CHK-DMA-ADDR. Evidence: `CHK-DMA-IMAGE PASS seed=<n> cell=<sI><sW><dI><dW> enc=<e> w=<w> chunk=<C> n=<n> bytes=<T> mem_mismatch=0 guard_ok=1 error=0 go_writes=<g>`, one line per cell and transfer. The six pairs of Leg A that `sep_dma_basic_test` grades are graded only at n of 2 or more (n of 3 or more for the last pair).
|CHK-DMA-BEAT
|Every DMA AR and AW has AxLEN 0, and the read and write beat counts each equal TOTAL divided by the width. Each write beat carries a WSTRB popcount equal to the width of the encoding. At width encoding 2 with INCREMENT=1, the read address step between two reads of one chunk equals 4 (`secure_dma.adoc`, SRC_CONFIG.INCREMENT: incremented by transfer_width after each read). The first read of a later chunk with WRAP=1 is not a step: the address returns to SRC_ADDR_LO there (`secure_dma.adoc`, SRC_CONFIG.WRAP), and CHK-DMA-ADDR grades that address. At width encodings 0 and 1, CHK-DMA-ADDR grades the read addresses on AxADDR[31:2]. A probe that sees no traffic gives a beat count of 0 and fails. Anchored on `dma_axi_req_probe_o`. Evidence: `CHK-DMA-BEAT PASS seed=<n> cell=<sI><sW><dI><dW> enc=<e> w=<w> bytes=<T> ar=<r> aw=<a> axlen_nonzero=0 wstrb_bad=0 rstep_bad=0`, one line per transfer.
|CHK-DMA-ADDR
|Every beat address equals the expectation that the model of CHK-DMA-IMAGE gives from the programmed registers and the width of the encoding (`secure_dma.adoc`, SRC_CONFIG, DST_CONFIG: the address steps by transfer_width, and with WRAP=1 it returns to the starting address when a chunk finishes). At width encoding 2 the check compares the full AxADDR. At width encodings 0 and 1 it compares AxADDR[31:2] with bits [31:2] of the model address, and for each write beat it compares the WSTRB byte lanes with bits [2:0] of the model address. AxADDR[1:0] of a 1-byte or 2-byte beat is logged as `OBS-DMA-ADDR-LOW LOG seed=<n> enc=<e> beats=<k> low_eq_model=<m>` and not graded, because the specification does not state the address low bits that the TL-UL to AXI4 path gives a narrow transaction (DMA transaction size rule). Anchored on `dma_axi_req_probe_o` against the model. Evidence: `CHK-DMA-ADDR PASS seed=<n> cell=<sI><sW><dI><dW> enc=<e> beats=<k> addr_mismatch=0 strb_lane_mismatch=0`, one line per transfer.
|CHK-DMA-GEOM
|After each transfer DONE=1, BUSY=0, GO=0 and ERROR=0, the destination equals the source and the guards are intact (`secure_dma.adoc`, CONTROL.GO, STATUS). A DUT that leaves GO set, leaves BUSY set, drops a tail or writes outside the footprint fails. Anchored on frontdoor reads of STATUS, CONTROL and the images. Control, on totals of 1024 bytes or more: a CONTROL read returns GO=1 while `dma_busy_probe_o` reads 1 at the clock of the read, so the transfer ran. The seed must show it on at least one transfer, else CTRL-MISSING. A total below 1024 bytes ends before a frontdoor read can land, so it is graded on the reads after DONE only. Evidence: `CHK-DMA-GEOM PASS seed=<n> total=<T> chunk=<C> n=<n> go_writes=<g> done=1 busy=0 go=0 error=0 mem_mismatch=0 control_go_busy=<1\|->`, with `-` for a total below 1024 bytes or a transfer where no read landed.
|CHK-DMA-DONE-CLR
|With no write of STATUS.DONE between the previous DONE and the GO write, at least one STATUS read with BUSY=1 shows DONE=0 before DONE rises again (`secure_dma.adoc`, STATUS.DONE: cleared automatically when a new transfer starts). A DUT that keeps the old DONE shows DONE=1 on every read of the transfer. Anchored on STATUS readback and `dma_busy_probe_o`. Control: DONE reads 1 on the read just before the GO write. The check runs on the Leg B totals of 1024 bytes or more (the 16384-byte total on every seed, and the drawn total when it is 1024 or 4096 bytes), whose transfer time lets the frontdoor read STATUS several times. Evidence: `CHK-DMA-DONE-CLR PASS seed=<n> total=<T> pre_go_done=1 busy_reads_done0=<k>`.
|CHK-DMA-CHUNKDONE
|A single-chunk transfer reads CHUNK_DONE=0 at every STATUS poll from the GO write to DONE, with CHUNK_DONE cleared by a write of 1 before the GO write so that a bit from an earlier transfer cannot show (`secure_dma.adoc`, STATUS.CHUNK_DONE: raised only for multi-chunk memory-to-memory transfers). A DUT that raises CHUNK_DONE for a single chunk shows 1. Anchored on STATUS readback. Control: the multi-chunk transfers of the seed, polled the same way, read CHUNK_DONE=1 at least once in total, or bit 9 of `sep_internal_interrupts_probe_o` (PIC source 10, with INTR_ENABLE.DMA_CHUNK_DONE=1) rises at least once during them, else CTRL-MISSING. The probe is part of the control because CHUNK_DONE clears when the next chunk starts, so a poll can miss a short pulse (`secure_dma.adoc`, STATUS.CHUNK_DONE, INTR_STATE.DMA_CHUNK_DONE). Evidence: `CHK-DMA-CHUNKDONE PASS seed=<n> n=<n> single=<0\|1> polls_with_chunk_done=<k> control_multi_polls=<m> control_chunk_irq_rises=<r>`.
|CHK-DMA-CHUNKRISE
|An n-chunk transfer shows n-1 to n rises of CHUNK_DONE, and a single-chunk transfer shows none (`secure_dma.adoc`, STATUS.CHUNK_DONE: only raised for multi-chunk memory-to-memory transfers). In an n-chunk transfer, each of the first n-1 CHUNK_DONE rises is followed by a later chunk start, so it is followed by a fall before the next CHUNK_DONE rise or the DONE rise, with no STATUS write between the rise and the fall (`secure_dma.adoc`, STATUS.CHUNK_DONE: cleared automatically by the hardware when starting the transfer of a new chunk). An n-th rise belongs to the last chunk, which no new chunk follows, so the check does not require its fall, and its order against the DONE rise is not graded. The window starts at the first GO write of the transfer and ends at the end of its poll, so the STATUS writes of steps 7 and 8 are outside it. A DUT that raises CHUNK_DONE for a single chunk, or that keeps CHUNK_DONE set when the next chunk starts, fails. Anchored on `dma_status_probe_o` and the frontdoor write log. Evidence: `CHK-DMA-CHUNKRISE PASS seed=<n> n=<n> rises=<r> hw_falls=<f> last_rise_exempt=<0\|1> status_writes_in_window=0`, with f at least the smaller of r and n-1, one line per transfer.
|CHK-DMA-DONE-ORDER
|No DONE rise in the window comes before the last B response of the transfer (`secure_dma.adoc`, STATUS.DONE: configured DMA operation is complete). The window starts at the first GO write of the transfer and ends at the end of its poll. A DUT that raises DONE early shows the rise before the B response. Anchored on the DONE level of `dma_status_probe_o` and the B handshake of `dma_axi_req_probe_o`. Control on the same observables: in the window the probe shows a B handshake count equal to the AW count, and at least one DONE rise. A transfer with no B handshake, a B count other than the AW count, or no DONE rise in the window fails the check. Evidence: `CHK-DMA-DONE-ORDER PASS seed=<n> bytes=<T> aw=<a> b=<a> done_rises=<k> last_b_clk=<b> done_rise_clk=<d>`, one line per transfer.
|CHK-DMA-RANGE-OK
|A copy with BASE and LIMIT exactly on the edges, with or without guards, in the drawn region order, sets DONE, leaves ERROR clear and copies the data (`secure_dma.adoc`, ENABLED_MEMORY_RANGE_LIMIT: inclusive). A DUT that rejects an edge byte, or treats LIMIT as exclusive, shows ERROR or a missing tail. Anchored on frontdoor reads of STATUS, ERROR_CODE and the destination. Control: the same regions with a wide range complete in the same seed. Evidence: `CHK-DMA-RANGE-OK PASS seed=<n> edge=<low\|high\|both\|guard> order=<src_low\|dst_low> base=0x<b> limit=0x<l> done=1 error=0 mem_mismatch=0 control_wide=1`.
|CHK-DMA-HASH
|The used SHA2_DIGEST_0 words with DIGEST_SWAP=1 equal the digest of an independent SHA-2 library as big-endian words (`secure_dma.adoc`, CONTROL.DIGEST_SWAP). The words with DIGEST_SWAP=0 equal their byte reversal at the same position. The copy bytes equal the source. A wrong digest, a wrong word order, a missing swap or a wrong algorithm for the opcode gives a mismatch. Anchored on frontdoor reads of the digest words against the library digest. The unused words are not read. The three control cells of Leg D print `OBS-DMA-HASH-CTRL` and no PASS line. Evidence: `CHK-DMA-HASH PASS seed=<n> alg=<256\|384\|512> len=<L> split=<k> swap=<s> words=<8\|12\|16> mismatch=0`.
|CHK-DMA-HASH-VALID
|After the GO write of the initial transfer, at least one STATUS read with BUSY=1 shows SHA2_DIGEST_VALID=0, and the bit reads 1 within a bounded wait after the DONE of the last transfer of the chain (`secure_dma.adoc`, STATUS.SHA2_DIGEST_VALID: cleared on the initial transfer, set when the digest is written; `sep-programming.adoc`: read the digest only when the bit is set). The specification does not state that DONE implies the bit, so the leaf polls for it, and a timeout fails. A DUT that never clears the bit, or never sets it, fails. Anchored on STATUS readback. Control: the bit reads 1 on the read just before the GO write of the second message. The clear is graded on the long message (1024 bytes or more), whose transfer time lets a frontdoor STATUS read land with BUSY=1, the same bound as CHK-DMA-GEOM. A long message with no STATUS read at BUSY=1 logs CTRL-MISSING and fails. A shorter message ends before a frontdoor read can land, so it is graded for the set only. Evidence: `CHK-DMA-HASH-VALID PASS seed=<n> alg=<a> len=<L> busy_reads_valid0=<k> after_last=1 control_before_second=1`, with `busy_reads_valid0=-` for a message below 1024 bytes.
|CHK-DMA-HASH-CHAIN
|A single-chunk run and a split run of the same message and swap value give the same digest. The split run is one transfer with TOTAL_DATA_SIZE = L and k equal chunks, INITIAL_TRANSFER on its first GO write only (`secure_dma.adoc`, TOTAL_DATA_SIZE: the complete transfer operation may consist of multiple chunks; CONTROL.INITIAL_TRANSFER: the initial transfer initializes the SHA engine for one transfer that spans multiple single DMA transfers). The SHA-2 library digest of the whole message is the expected value of both runs (CHK-DMA-HASH). A DUT that restarts the hash at a later chunk, or that drops or repeats a chunk, gives another digest. The split run has 2 to 4 chunks, so it always has a later chunk. A message with no split form and the long message run no CHK-DMA-HASH-CHAIN. Anchored on frontdoor reads of the digest words of both runs. Evidence: `CHK-DMA-HASH-CHAIN PASS seed=<n> alg=<a> len=<L> split=<k> single_eq_split=1`.
|===

*Pass Criteria*: Every named checker PASSes. UVM_ERROR == 0.

*Scope limit*: This entry grades the cells of its four legs only. The open tests `sep_dma_basic_test` and `sep_dma_hash_test` keep the cells that they grade: AxSIZE of a DMA beat is not graded, a TRANSFER_WIDTH of 3 is graded by `sep_dma_basic_test`, and the software clear of STATUS.DONE is graded by `sep_dma_basic_test`. The zero-size error, the hash width rule and the range lock are graded in entry 4.13.

[[sep_dma_irq_error_lock_rand_test]]
===== 4.13 `sep_dma_irq_error_lock_rand_test`

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`) with real fuse sense (no `+skip_fuse_sense`), because the leaf asserts `rst_ni`. 4 seeds. Verilator and VCS; testlist groups `cpu_stub` and `all`, file `system.toml`, one testlist entry. Leg L3 runs on VCS only, because it reads state after reset. Leg L1 runs six short trials per run, each from a cold reset.

*Source Module*: `sep_dma_irq_error_lock_rand_test`

*BFM / Model*: ocah_axi_vip register frontdoor over `s_axi` (also for the SRAM images); a model of the interrupt gate (the line of source n is the matching event AND the matching INTR_ENABLE bit). Approved probes: `sep_internal_interrupts_probe_o` indices 8, 9 and 10 (PIC sources 9, 10 and 11), `dma_busy_probe_o` and `dbg_sep_reset_n_o`. The probe `dma_busy_probe_o` orders the re-GO of a multi-chunk copy only. No added tap. No inject. * Leg L1, enable gate (`secure_dma.adoc`, INTR_STATE, INTR_ENABLE; `interrupts.adoc`, SEP CPU Interrupt Vector Map). * Leg L2, SIZE_ERROR (`secure_dma.adoc`, ERROR_CODE, STATUS, INTR_STATE; `dma.adoc`, overview). A TOTAL_DATA_SIZE of zero, a CHUNK_DATA_SIZE of zero, and hashing at a width of 1 or 2 bytes each set ERROR_CODE.SIZE_ERROR, STATUS.ERROR and INTR_STATE.DMA_ERROR.

The release of the lock by a cold reset and the reset values of the range registers are graded in <<sep_cpu_reset_retention_test,entry 5.15>>.

===== 4.14 `sep_dma_abort_recovery_rand_test`

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`) with real fuse sense (no `+skip_fuse_sense`), because the leaf asserts `rst_ni`. 4 seeds. Verilator and VCS; testlist groups `cpu_stub` and `all`, file `system.toml`, one testlist entry. Two abort runs per seed, each from a cold reset.

*Source Module*: `sep_dma_abort_recovery_rand_test`

*BFM / Model*: ocah_axi_vip register frontdoor over `s_axi` (also for the SRAM source and the destination image). Approved probes: `dma_busy_probe_o` and `dbg_sep_reset_n_o`. `dma_axi_req_probe_o` and `dma_status_probe_o` (checker CHK-DMA-ABORT-BEATS, and the phase class of each run) are observation taps the test adds to the SEP_TB_ARCH observation-probe list. No inject.

*Randomization*: `SepSeededRng` from the run seed. Dimensions and legal ranges: chunk size C (1024 to 4096 bytes, a multiple of 4), chunk count n (from the larger of 2 and ceil(4096 / C) to floor(16384 / C)) and transfer size T = n * C (4 KB to 16 KB), so that n is 2 or more and every chunk holds at least 256 transactions; the phase class of abort run 2 (first transaction, chunk boundary or final transaction); abort point inside the class; source and destination offsets (footprints with guards disjoint and inside BASE to LIMIT); all data. Run 1 of every seed has the class mid chunk. Source and destination offsets are multiples of 4, T and C are multiples of 4, and T is a multiple of C (`secure_dma.rdl`, SRC_ADDR_LO, DST_ADDR_LO, TRANSFER_WIDTH). The delay d counts clocks from the end of the first GO write to the start of the ABORT write. The reference copy measures its clean transfer time t_clean on the same base: the clocks from the end of its first GO write to the clock at which its STATUS poll first reads DONE=1, with the gaps of the re-GO writes included. The class gives d as a fraction of t_clean: first transaction, the first delay of the sequence 0, s, 2s, ... with s = t_clean / (10 n) that gives busy_at_abort = 1; mid chunk, 25 to 75 percent of the share t_clean / n of the first chunk; chunk boundary, within 5 percent of j * t_clean / n for a drawn j from 1 to n - 1; final transaction, 90 to 99 percent of t_clean. The value t_clean is measured and sets the stimulus only. It is never an expected value. `reseed = 4` samples four different sizes, run-2 classes, points, offsets and data sets. The class of run 2 depends on the seed, so the three classes other than mid chunk close on a merge of regressions (<<sep-fcov-rand,SEP_FCOV>>).

*Objective*: The DMA abort contract holds (`secure_dma.adoc`, CONTROL.ABORT, STATUS.ABORTED). Writing CONTROL.ABORT during a transfer sets STATUS.ABORTED once the aborted operation drains, so no DMA beat follows the ABORTED rise. ABORTED clears by write-one-to-clear. A copy after recovery completes with the right data. The open DMA tests `sep_dma_basic_test`, `sep_dma_hash_test` and `sep_dma_cpu_contention_test` do not grade CONTROL.ABORT or STATUS.ABORTED.

*Test Coverage*: ABORT in the middle of a chunk of a 4 KB to 16 KB copy on every seed, and at the first transaction, at a chunk boundary or at the final transaction in a second run whose class the seed draws (these three classes close on a merge of regressions), the rise of ABORTED, the write-one-to-clear of ABORTED, the stability of the destination image after ABORTED, and a recovery copy after the abort with no reset. The data written on the SoC side is not graded, because the CONTROL.ABORT text gives no guarantee there. The test builds on the open DMA tests named in the objective, which grade no abort cell. Functional coverage: `sep_dma_error_terminal_cg` (`cp_abort_outcome`, `cp_abort_quiet`), `sep_dma_xfer_rand_cg` (`cp_abort_phase`, graded on a merge of regressions), `sep_dma_range_config_cg` (`cp_range_valid_at_go`) and `sep_dma_endpoint_cg` (`cp_src_x_dst_endpoint`).

*Test Procedure*:

[arabic]
. Draw every value from the seed and log it in `DRAW` lines. Every run below except the recovery starts with a cold reset: assert `rst_ni`, release it, and wait with a bound for the `sep_reset_n` release on `dbg_sep_reset_n_o` before the first register access.
. Reference copy. After a cold reset write BASE = 0x10000000, LIMIT = 0x1003FFFF (the SEP SRAM, `memory_map.adoc`) and RANGE_VALID = 1. Write ADDR_SPACE_ID = 0x77 and both ADDR_HI registers = 0. Fill the source with unique words and the destination and the guards with sentinel words. Write the addresses, TOTAL_DATA_SIZE = T, CHUNK_DATA_SIZE = C, TRANSFER_WIDTH = 2, INCREMENT=1 and WRAP=0 on both sides. Write CONTROL with OPCODE 0, INITIAL_TRANSFER=1 and GO=1.
. Reference copy. Poll STATUS with a bounded wait until DONE=1 and BUSY=0. A timeout fails with `FAIL-DMA-TIMEOUT`. . Abort run. For each of the two runs (run 1 has the class mid chunk; run 2 has the drawn class): run a cold reset. Program the range and the same configuration as the reference copy. Fill the source and write sentinel words to the destination and guards. Read STATUS and log ABORTED (the control of CHK-DMA-ABORT).
. Abort run. Write CONTROL with OPCODE 0, INITIAL_TRANSFER=1 and GO=1. Sample `dma_busy_probe_o` at every clock from the GO write and record whether it has risen. While the delay d runs, poll STATUS and apply the re-GO rule of step 3 to each read of CHUNK_DONE=1, DONE=0 and BUSY=0.

Expected response (`secure_dma.adoc`, CONTROL.ABORT, STATUS.ABORTED): ABORTED reads 1 and no further beat follows. Sample `dma_busy_probe_o` on the clock in which the ABORT write completes on the bus (`busy_at_abort`). The data written on the SoC side is not graded, because the CONTROL.ABORT text gives no guarantee there.
. Abort run. If `busy_at_abort` is 0, the abort did not arrive during a transfer. When the probe has not risen since the GO write, the engine has not started (case `not_started`): use a larger delay. When the probe has risen, the transfer has ended or is between chunks (case `ended`): use a smaller delay, never below 0. Each change is t_clean / (10 n). If no repeat reaches `busy_at_abort` = 1, the leaf fails with CTRL-MISSING.
. Abort run. If `busy_at_abort` is 1, poll STATUS until ABORTED=1 with a bounded wait. A timeout fails CHK-DMA-ABORT. In the final-transaction class, when the bounded wait ends with DONE=1 and ABORTED=0, the transfer finished before the abort took effect. In the chunk-boundary class, when the bounded wait ends with CHUNK_DONE=1 or DONE=1, BUSY=0 and ABORTED=0, the chunk finished before the abort took effect. In both cases the leaf logs `OBS-DMA-ABORT-REDRAW` (case `finished`), grades nothing from the run, and repeats the abort run with a smaller delay within the 8 repeats of step 7. . Abort run. Read the destination footprint and the guards (image 1). Wait as long as t_clean. Read them again (image 2). Compare image 1 with image 2 (CHK-DMA-ABORT-QUIET). Count the destination words that differ from the sentinel and the words that equal it.

Write CONTROL with OPCODE 0, INITIAL_TRANSFER=1 and GO=1. Poll DONE with a bounded wait, with the re-GO rule of step 3. Read ERROR, the destination and the guards (CHK-DMA-RECOVER).
. Seed control. Check that at least one graded abort run of the seed shows both a destination word that differs from the sentinel and a destination word that equals it. Run 1 of the seed has the class mid chunk for this reason. If no run shows both, fail with CTRL-MISSING.
. Beat checks. Sample `dma_axi_req_probe_o` and `dma_status_probe_o` at every clock from the GO write of each graded run to the DONE of its recovery copy, and grade CHK-DMA-ABORT-BEATS. The leaf also compares the beat count at the ABORT write with the phase class of the run; a run outside its class is repeated from a cold reset with a changed delay, up to a bound that is a test parameter, and at the bound the leaf fails with CTRL-MISSING. So each run lands in its class.

*Checkers*:

[[sep_spi_dma_handshake_rand_test]]
===== 4.15 `sep_spi_dma_handshake_rand_test`

*Phase*: 3

*Area*: SPI and DMA

*Run mode*: `no_cpu` (`lsu_stub_all_live`) with real fuse sense (no `+skip_fuse_sense`), because the leaf asserts `rst_ni`. 3 seeds; tool: both (Verilator and VCS); testlist groups `cpu_stub` and `all`, file `spi.toml`.

*Source Module*: `sep_spi_dma_handshake_rand_test`

*BFM / Model*: ocah_axi_vip register frontdoor over `s_axi` (also for the destination image); the SPI responder `OcahSpiFlash` on the pad ports, serving a flash read with unique words. Approved probes: `spi_lsio_trigger_probe_o`, `dma_busy_probe_o`, `spi_tx_qd_probe_o`, `dbg_sep_reset_n_o`, and bit 9 of `sep_internal_interrupts_probe_o` (PIC source 10, DMA chunk done, `interrupts.adoc`) for the control of CHK-HS-NOCHUNK. The probe `spi_tx_qd_probe_o` is sampled and logged only. The probe `dma_busy_probe_o` is sampled and logged, and it orders the re-GO of the normal-mode control. No added tap. No inject. CHK-HS-DATA is blocked: the specification does not name the line that carries the Rx bit in standard mode (see Checkers).

*Randomization*: `SepSeededRng` from the run seed. Dimensions and legal ranges: chunk size C (4 to 16 bytes, multiple of 4); chunk count n (2 to 8); HANDSHAKE_INTR_ENABLE.MASK bits 10:1 (any value; those handshake inputs are tied low); stop count n_stop (1 to n - 1); CLKDIV; RX_WATERMARK W (C/4 to 7); the unique flash words; the sentinel word of the destination, drawn after the reference run of step 4 as a word that equals no word of the reference stream, so that the poll of step 6 ends and the chunk count of step 8 holds for every Rx word that the host returns. The RX FIFO depth must exceed W + 1, else the leaf fails with CTRL-MISSING. `reseed = 3` samples three different chunk shapes, mask bits, stop counts, CLKDIV values, watermarks and word sets.

*Objective*: The DMA hardware handshake contract holds (`dma.adoc`, OCAH Modifications; `secure_dma.adoc`, CHUNK_DATA_SIZE, CONTROL.GO, CONTROL.HARDWARE_HANDSHAKE_ENABLE, STATUS.CHUNK_DONE, HANDSHAKE_INTR_ENABLE; `sep-programming.adoc`, DMA). In hardware handshake mode the DMA reads chunks of CHUNK_DATA_SIZE from the peripheral when the trigger of an enabled handshake input is asserted. The SPI trigger `lsio_trigger_o` is the registered OR of `TXQD < TX_WATERMARK` and `RXQD >= RX_WATERMARK`, and it does not depend on EVENT_ENABLE or INTR_ENABLE (`spi.adoc`, DMA Trigger). The DMA does not clear GO itself, raises no CHUNK_DONE (CHUNK_DONE is only for memory-to-memory transfers), and stops when firmware clears GO. The open tests `sep_spi_ot_dma_rx_test` and `sep_spi_ot_dma_tx_test` run one handshake configuration with mask bit 0 set, and `sep_spi_ot_dma_tx_test` grades that the DMA waits for the trigger in the TX direction. Those cells are controls here.

*Test Coverage*: Mask bit 0 set (the RX word order over n chunks is blocked, see CHK-HS-DATA) and clear (the DMA moves no word while the trigger is high), random upper mask bits 10:1, GO still set after n chunks, no CHUNK_DONE in the handshake run, and the stop after firmware clears GO. The test builds on the open tests `sep_spi_ot_dma_rx_test` and `sep_spi_ot_dma_tx_test`. Only the masked negative, GO persistence, the stop after the GO clear, no CHUNK_DONE and random upper mask bits are graded here. The RX word order over n chunks (CHK-HS-DATA) is blocked: the specification does not name the line that carries the Rx bit in standard mode. The open owners keep the rest. Functional coverage: `sep_dma_completion_cg` (`cp_go_lifecycle`, `cp_chunk_done_class`), `sep_dma_transfer_cg` (`cp_peripheral_stream`), `sep_dma_endpoint_cg` (`cp_src_x_dst_endpoint`), `sep_spi_dma_use_case_cg` (`cp_use_case_matrix`) and `sep_spi_flash_cg` (`cp_hs`).

*Test Procedure*:

[arabic]
. Draw C, n, the mask bits 10:1, n_stop, CLKDIV, W and the flash words from the seed. Keep C/4 at or below W. Log them in `DRAW` lines. Every run below starts with a cold reset: assert `rst_ni`, release it, and wait with a bound for the `sep_reset_n` release on `dbg_sep_reset_n_o` before the first register access. CFG_REGWEN locks the DMA configuration registers while the DMA operates (`dma.hjson`, CFG_REGWEN) and a handshake run keeps GO set, so each run starts from a cold reset and programs its own configuration.
. SPI sequence (used by every run below). Write CONTROL with SPIEN=1, OUTPUT_EN=1, TX_WATERMARK=0 and RX_WATERMARK=W, so that only the RX term can raise the trigger. Write EVENT_ENABLE=0 and INTR_ENABLE=0. The trigger does not depend on either enable (`spi.adoc`, DMA Trigger), so a DUT whose trigger needs an enable moves no word: the poll of step 6 times out, and the trigger controls of CHK-HS-MASKED and CHK-HS-STOP log CTRL-MISSING. Write CSID=0 and CONFIGOPTS with the drawn CLKDIV. Load the read command words of `OcahSpiFlash` into TXDATA. Write COMMAND for one Tx segment (DIRECTION Tx, SPEED 0, CSAAT=1) that carries the command. Write COMMAND for one Rx segment (DIRECTION Rx, SPEED 0, CSAAT=0) of the length that the run states.
. Depth check. After a cold reset run the SPI sequence with an Rx segment of 4*(W+1) bytes and no DMA and no RXDATA read. Poll STATUS until ACTIVE=0 with a bounded wait. If STATUS.RXFULL reads 1, fail with CTRL-MISSING. The RX depth exceeds W + 1 otherwise. The leaf uses the depth only to size the stimulus.
. Reference run. After a cold reset run the SPI sequence with an Rx segment of n*C + 4*(W+1) bytes. Read RXDATA (`spi_controller.rdl`, RXDATA at offset 0x24 of the SPI base `0x10B00000` in `memory_map.adoc`) through the frontdoor until the segment is done and STATUS shows RXEMPTY=1, n*C/4 + W + 1 words, and poll STATUS.RXEMPTY=0 before each read. These words are the reference stream, and the first n*C/4 of them are the reference of CHK-HS-DATA. Every later run sends the same read command to the same flash content after a cold reset with the same SPI configuration, so every Rx word of a later run is a word of the reference stream. Draw the sentinel word from the seed as a word that equals no word of the reference stream, and log it. The comparison is word to word, so it needs no byte-order claim. Log whether the n*C/4 reference words are pairwise distinct (`ref_distinct`, the control of CHK-HS-DATA, because a reference with a repeated word cannot show a duplicate or a missing word). CHK-HS-DATA is blocked, so `ref_distinct` is logged only.
. Handshake run. After a cold reset write BASE = 0x10000000 (the SRAM base) and LIMIT = 0x10BFFFFF (the end of the SPI window, `memory_map.adoc`) and RANGE_VALID = 1. Write ADDR_SPACE_ID = 0x77 and both ADDR_HI registers = 0. Fill the destination footprint (n*C bytes) with sentinel words. Write SRC_ADDR_LO = 0x10B00024 with SRC_CONFIG INCREMENT=0 and WRAP=1, DST_ADDR_LO in SRAM with DST_CONFIG INCREMENT=1 and WRAP=0, TRANSFER_WIDTH = 2 (4 bytes), TOTAL_DATA_SIZE = n*C and CHUNK_DATA_SIZE = C. Write HANDSHAKE_INTR_ENABLE.MASK = 0x001 plus the drawn mask bits 10:1. Write CONTROL with OPCODE 0, HARDWARE_HANDSHAKE_ENABLE=1, INITIAL_TRANSFER=1 and GO=1. Run the SPI sequence with an Rx segment of n*C + 4*(W+1) bytes. The extra 4*(W+1) bytes keep the FIFO past W at every chunk.
. Handshake run. Poll in a loop with a bounded wait: read STATUS (log CHUNK_DONE) and read the last destination word, until the last word of chunk n differs from the sentinel. A timeout fails with `FAIL-DMA-TIMEOUT`. Measure the poll time from the GO write to that point as t_fill, in clocks. Read the destination (CHK-HS-DATA). Read CONTROL.GO. Wait as long as t_fill, read CONTROL.GO again and keep polling STATUS for CHUNK_DONE over the same wait (CHK-HS-GO, CHK-HS-NOCHUNK). Log `dma_busy_probe_o` and `spi_tx_qd_probe_o`.
. Masked run. After a cold reset repeat step 5 with MASK bit 0 clear (the mask bits 10:1 stay as drawn). Do not wait for the SPI segment to end, because a masked DMA leaves the RX FIFO full. Sample `spi_lsio_trigger_probe_o` at every clock of a window as long as t_fill from the handshake run, and poll the destination. At the end of the window read the whole destination (CHK-HS-MASKED).
. Stop run. After a cold reset repeat step 5 with an Rx segment of n_stop*C + 4*(W+1) bytes, TOTAL_DATA_SIZE = T*C with T = n_stop + ceil(4*(W+1)/C) + 1 chunks, and a destination footprint of T*C bytes. The segment holds n_stop*C/4 + W + 1 words. These words fill at most n_stop + floor(4*(W+1)/C) chunks, also when the DMA drains every word of the segment, so at least one chunk of the total stays unmoved for every legal C, W and n_stop (for example, C = 4 and W = 7 fill at most n_stop + 8 chunks of T = n_stop + 9). Wait until STATUS.ACTIVE reads 0, then read the destination twice, separated by a wait as long as t_fill. When the two images are equal, count the chunks whose words all differ from the sentinel as n_moved. If n_moved is 0 or equals TOTAL_DATA_SIZE / C, fail with CTRL-MISSING.
. Stop run. Write CONTROL with GO=0 and the other fields kept. Run the SPI sequence again with an Rx segment of 4*(W+1) bytes. Sample `spi_lsio_trigger_probe_o` at every clock from the GO clear for a window as long as t_fill. Do not wait for the segment end, because the RX FIFO can fill. Read the destination at the end of the window (CHK-HS-STOP).
. Normal-mode control. After a cold reset write BASE = 0x10000000, LIMIT = 0x1003FFFF (the SEP SRAM, `memory_map.adoc`) and RANGE_VALID = 1. Write ADDR_SPACE_ID = 0x77 and both ADDR_HI registers = 0. Fill a 4096-byte source in the SRAM with unique words and a 4096-byte destination with sentinel words, both at addresses that are multiples of 4, disjoint and inside the range. Write SRC_ADDR_LO, DST_ADDR_LO, TOTAL_DATA_SIZE = 4096, CHUNK_DATA_SIZE = 1024 (the chunk shape of this control is a test parameter), TRANSFER_WIDTH = 2, and SRC_CONFIG and DST_CONFIG with INCREMENT=1 and WRAP=0. Write INTR_ENABLE with DMA_CHUNK_DONE=1 and the other bits 0. Write CONTROL with OPCODE 0, HARDWARE_HANDSHAKE_ENABLE=0, INITIAL_TRANSFER=1 and GO=1.
. Normal-mode control. Poll STATUS with a bounded wait until DONE=1 and BUSY=0. A timeout fails with `FAIL-DMA-TIMEOUT`. Log CHUNK_DONE at every poll. From the GO write to the end of the poll, sample bit 9 of `sep_internal_interrupts_probe_o` at every clock and count its rises. When STATUS reads CHUNK_DONE=1, DONE=0 and BUSY=0, write 1 to STATUS.CHUNK_DONE, write CONTROL with OPCODE 0, HARDWARE_HANDSHAKE_ENABLE=0, GO=1 and INITIAL_TRANSFER=0, and wait with a bound until `dma_busy_probe_o` has risen since that write before the next evaluation.
. Normal-mode control. After DONE read CONTROL.GO.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-HS-DATA

|CHK-HS-MASKED

|CHK-HS-GO

Evidence: `CHK-HS-GO PASS seed=<n> go_after_n=1 go_after_wait=1 control_normal_go=0`.

Control: the chunks before the clear are filled (n_moved at least 1), at least one chunk of the total is unmoved (n_moved below TOTAL_DATA_SIZE / C, else CTRL-MISSING), and the trigger probe is high in the window. Evidence: `CHK-HS-STOP PASS seed=<n> n_stop=<k> n_moved=<m> chunks_total=<c> dest_after_clear_sentinel=1 trigger_high_clk=<t>`.
|CHK-HS-NOCHUNK

Control: the multi-chunk normal-mode copy in the same seed, polled the same way, reads CHUNK_DONE=1 at least once, or bit 9 of `sep_internal_interrupts_probe_o` (PIC source 10, with INTR_ENABLE.DMA_CHUNK_DONE=1) rises at least once during it, else CTRL-MISSING. The probe is part of the control because CHUNK_DONE clears when the next chunk starts, so a poll can miss a short pulse (`secure_dma.adoc`, STATUS.CHUNK_DONE, INTR_STATE.DMA_CHUNK_DONE). Evidence: `CHK-HS-NOCHUNK PASS seed=<n> polls_with_chunk_done=0 polls=<p> control_normal_polls=<m> control_chunk_irq_rises=<r>`.

*Scope limit*: The open tests `sep_spi_ot_dma_rx_test` and `sep_spi_ot_dma_tx_test` keep the single handshake configuration with mask bit 0 set and the TX-direction wait. Not claimed: the interrupt clear write (the leaf does not drive it), handshake inputs 1 to 10 (tied low), BUSY before the GO clear, the count of beats per chunk, the words beyond n*C/4 in the handshake run, the number of chunks that the DMA moves before the stop (the leaf requires at least one unmoved chunk), and the RX watermark equality (C/4 stays at or below W, so both readings of the watermark leave at least C/4 words when the trigger fires).
