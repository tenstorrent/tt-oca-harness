[[sep-dv-testbench-architecture]]
== SEP OCAH Open-Source Testbench Architecture

=== Overview

[cols=",",options="header"]
|===
|Field |Value
|DUT |`sep_wrapper` (`hw/top/sep_wrapper.sv` + `hw/top/sep_ip_integration.sv`)
|Bare core |`sep` (`hw/sys/sep/rtl/sep.sv`)
|Repository |`tt-oca-harness`
|Project |OCAH
|Framework |PyUVM on cocotb; SystemVerilog UVM smoke set on the same top (`--framework uvm`, VCS)
|Primary simulator |Verilator
|Supported simulator matrix |cocotb on `verilator` (default), `vcs` and `xcelium`; SV-UVM on `vcs` only, because Verilator has no SV-UVM support
|Commercial simulator use |VCS / Xcelium for development iteration; VCS for graded coverage and the SV-UVM realization. Verilator is pre-merge acceptance
|How to run |`README.md` (`tools/dv/run_dv.py --dut sep`)
|===

The OCAH open-source SEP testbench lives under `hw/sys/sep/dv/`. The Layout
table of the DV `README.md` says what each directory holds, and its Getting
Started section gives the runner commands. It uses a PyUVM environment and the unified OCAH
BFM packages for AXI, SPI, and (where needed) JTAG. Sibling SMC and DTP envs
share the same runner and cocotb/PyUVM idioms; this document describes *SEP*.

eFuse image selection, memory/eFuse/SPI models, CPU-trace reconstruction,
Boot ROM image builds, and Key Manager `rom_main` builds are covered in the
sections below. Test contracts live in
xref:SEP_VPLAN.adoc#sep-dv-verification-plan[SEP_VPLAN].

=== VIP Selection Policy

[arabic]
. Import unified OCAH BFM wrappers from `hw/common/dv/vip` for standard
  protocol access.
. Wrap those BFMs in PyUVM agents so tests remain sequence-based and reusable.
. Keep DUT-local goldens, scoreboards, and register metadata in `cocotb/env/`.
. Prefer frontdoor stimulus and observation. The probe / init exceptions are
  listed under <<sep-hdl-top>> and form a closed set.

[cols=",,,",options="header"]
|===
|SEP Interface |Preferred VIP |Modeling Approach |Notes
|CPU-LSU AXI (no_cpu) |`ocah_axi_vip` via `SepAxiAgent` (`s_axi`) |Unified OCAH BFM |Primary stimulus; no inbound filter on this path
|SMN-inbound AXI |Second `SepAxiAgent` (`m_axi`) |Unified OCAH BFM |Real DUT inbound port; traverses inbound filter (block-by-default)
|SPI flash pads |`ocah_spi_vip` `OcahSpiFlash` |Unified OCAH BFM |Pads are scalar ports on `tb_top`
|JTAG (eFuse mux path) |`ocah_axi_vip` AXI-Lite master on the OTP JTAG2AXIL port (`j_axi_*`) |Unified OCAH BFM |eFuse JTAG–AXI-Lite coexistence tests
|Entropy raw noise |`esrc_noise_ext_i` + Python goldens |DUT-local |Deterministic noise shared with the decorrelator golden
|eFuse / OTP |Generic OSS eFuse bank model |Shared OSS model |No foundry OTP macros; staged via `+sep_efuse_hex`
|Memories |Wrapper `prim_ram_1p` / `prim_rom` / EL2 TCM |RTL macros + backdoor init |`tb_backdoor_mem` loads images at t=0
|===

=== DUT-Local Model Ownership

Shared VIP packages own protocol-neutral driving, monitoring, and result
packaging. SEP-local code owns hierarchy binding, address maps, expected values,
lifecycle / fuse policy, and scoreboarding.

[cols=",,,",options="header"]
|===
|Model / Helper |Current Scope |Why It Stays DUT-Local |Promotion Trigger
|`SepAxiAgent` / `SepAxiItem` |LSU + SMN-inbound masters |Prefix binding, timeout / expect_error policy, AxUSER for inbound src_id |Thin over `ocah_axi_vip`; carries SEP policy
|`sep_reg_meta` |PeakRDL-exported addresses / resets / masks |SEP register export layout |Share only with a second consumer of the same export contract
|`sep_*_golden.py` |AES / HMAC / KMAC / OTBN / entropy / LCC / DRBG |SEP datapath + config objects |Promote a stage only after an independent consumer needs the same KAT
|`SepDrbgScoreboard` |Entropy CHK1–CHK5 chain |SEP ESRC→DRBG→EDN probe set and sink policy |Stay local while probes are tb_top-specific
|`SepEfuseImage` |OTP image + shadow expectation |SEP fuse map and secret-blanking |Shared model already exists; image semantics stay SEP
|`SepBootScoreboard` / `SepCpuTraceMonitor` |FW console, PC-advance, call stack |EL2 retirement ports and outbound mailbox |Promote only with a second EL2 consumer
|`SepSeededRng` |Seed→stimulus stream |DV reproducibility contract (not a CSPRNG) |Reusable as is; no shared DV home for seeded RNG exists
|`sep_cpu` stub |no_cpu LSU master splice |First-class run mode, not a workaround |Never promote as a product CPU
|===

=== Testbench Hierarchy

[source,text]
----
sep_<scenario>_test (@pyuvm.test)
  -> sep_base_test
       build_phase:
         SepEnvCfg -> ConfigDB
         SepCpuTraceMonitor (idle unless +cpu_boot)
         SepEnv (optional; build_env=True)
       run_phase:
         raise_objection
         run_scenario()   # concrete test owns the flow
         drop_objection

SepEnv
  -> axi_agent        SepAxiAgent  prefix s_axi   (CPU-LSU)
  -> ext_axi_agent    SepAxiAgent  prefix m_axi   (SMN-inbound; idle by default)
  -> scoreboard       SepScoreboard  (subscribes to s_axi completed items)
  -> axi_monitor      SepAxiMonitor  s_axi  (fail on DECERR)
  -> ext_axi_monitor  SepAxiMonitor  m_axi  (tally DECERR; filter may block)
----

Concrete tests inherit `sep_base_test`, override `run_scenario()`, and use
bring-up helpers rather than re-implementing clock/reset:

[cols=",",options="header"]
|===
|Helper |Use
|`bring_up_no_cpu()` |CPU held off; wait for fuse-sense done (or skip-sense fast path)
|`bring_up_and_wait_fuse_sense()` |Real OTP sense; stages image first
|`bring_up_cpu_boot()` / `boot_firmware(...)` |VeeR EL2 ICCM/DCCM load + boot scoreboard poll
|`start_seq(seq)` |Start on the CPU-LSU agent sequencer (default)
|`start_ext_seq(seq)` |Start on the external SMN-inbound sequencer
|`write_efuse_image(image)` |Stage golden before real sense
|`bring_up_entropy(...)` |Program ESRC/DRBG path with a shared config object
|===

[[sep-hdl-top]]
=== HDL Top

`tb/tb_top.sv` instantiates `sep_wrapper` as `sep_uvm_top` and adapts packed RTL
structs to cocotb-friendly scalar/vector ports. It is ONE module with two
shapes: by default the ANSI port list cocotb drives; under the bare `UVM`
define (set by the native profile's `uvm` framework) the same signals become
internal TB nets and a harness block at the end of the module adds the
clocks, the shared AXI VIP interfaces on the CPU-LSU splice, quiescent
tie-offs, `uvm_config_db` publication, and `run_test()`. Every TB signal is
declared once in `tb/sep_tb_signal_list.svh` and expanded into the selected
shape by the `SEP_TB_*` macros; see <<sep-uvm-realization>>.

[cols=",",options="header"]
|===
|DUT Interface |`tb_top` Handling
|CPU-LSU AXI |Flattens to `s_axi_*`. On the `lsu_stub_*` targets the no_cpu `sep_cpu` stub drives `lsu_axi_req` from these ports (`assign`, single driver). On the full-CPU VCS `--target default` build, which produces the graded cocotb coverage logs, a no_cpu leaf holds the core off and `tb_top` forces `u_sep_cpu.lsu_axi_req` from the same ports and holds `u_sep_cpu.lsu_axi_resp_raw` at zero; VIP addresses bypass `u_lsu_local_alias_remap`. Response XMR-read back into the flat bus on both builds.
|SMN-inbound AXI |Flattens the real inbound port to `m_axi_*` for a second master agent. Traverses `u_inbound_filter`.
|SEP->SMC AXI |`rom_boot` target only: `ocah_axi_struct_bridge` places the wrapper's `sep_ext_to_smc_axi` struct port on `u_smc_axi_if` and the shared `OcahAxiSlaveAgent` answers it. `env/sep_smc_mem.py` holds the geometry and preloads the scratch, status, strap, and manifest+BL1 image words from the testlist plusargs; the SMC address-decode check counts accesses outside the generated map. Other targets tie the port idle.
|Clocks |cocotb drives `clk_i`, `clk_wdt_i`, `entropy_rosc_sample_clk_i`
|Resets / straps |`rst_ni`, `ext_boot_seq_done_i`, `mpc_reset_run_req`, `wdt_rst_ni_i`, `dbg_rstb_i`, `test_en_strap_i`, …
|SPI host pads |Scalar MISO/MOSI/SCK/CS ports for `OcahSpiFlash`
|Entropy noise |`esrc_noise_ext_i` forces the decorrelator input (deterministic)
|FW console |`sep_outbound_mbx` watches outbound mailbox stores (PASS/FAIL magic)
|CPU trace |Exports EL2 `el2_trace_pkt_t` fields for `SepCpuTraceMonitor`
|Observation probes |Observation-only unless listed as an inject exception. The probe groups are listed below the table
|===

Observation probe groups:

* eFuse shadow, scratch, and the KM and OTBN counters.
* KM mailbox SEP-side write-error probes (`km_mbox_sep_wr_err_*`).
* KM SRAM read-latency probes (`km_sram_rd_*`) and scrambled-write probes
  (`km_sram_scr_wr_*`).
* Entropy CHK probes and the IRQ aggregate.
* AXI-Lite split handshakes.
* Local-crossbar `ext`-initiator handshakes (`xbar_ext_in_*`). Owner:
  `sep_unmapped_access_policy_test`.
* DRBG lane-adapter channel packs (`drbg_csrng_axil_chan_o` /
  `drbg_edn_axil_chan_o`).
* The KM internal AXI-Lite SVA bind.
* eFuse read and program interface retirement outputs and bank-request valids;
  the eFuse SHIM `efuse_debug_bus_o`.
* Crypto reset-sequencer probes (`*_gated_rst_n_probe_o`,
  `*_isolated_probe_o`, `*_host_isolate_req_probe_o`,
  `trng_reset_active_probe_o`).
* EDN and entropy-AXIS handshake probes (`crypto_edn_*`, `pool_edn_*`,
  `km_entropy_*`, `axis1_*`, `axis2_*`, `entropy_pool_packer_depth_o`).
* RMA-SIP token-digest latch probes (`token_digest_*`).
* KM OTP ID probes (`km_otp_sep_*_id_o`).
* SEP SRAM word probes (`sram_word0_probe_o` / `sram_payload_probe_o`).
* KM SRAM word probes (`km_sram_word0_o` / `km_sram_probe_o`): continuous reads
  of the KM SRAM macro array that carry the KM ROM images' result words.
* SEP reset probes (`dbg_sep_reset_n_o` / `sep_cpu_reset_n_o`).
* The DMA/CPU SRAM overlap counter (`dma_cpu_sram_overlap_count_o`).
* SPI-to-DMA transmit pacing probes (`spi_tx_qd_probe_o`,
  `spi_lsio_trigger_probe_o`, `dma_busy_probe_o`). Owner:
  `sep_spi_ot_dma_tx_test`.
* Adams Bridge ML-KEM seed Z words (`abr_mlkem_seed_z_probe_o`).
* Fabric-slot register-block W-channel counters (`fabric_slot_w_*`).
* The covergroup sampler's direct reads of the WDT bark interrupt
  (`intr_wdog_timer_bark`, owner `sep_nmi_sanity_test`) and the LSU read
  `ARSIZE` (owner `sep_axi_partial_lane_read_test`).

Exceptions (a closed set):

* *CPU-LSU splice* — primary no_cpu stimulus (stub assign, not a `force`) on
  the `lsu_stub_*` targets.
* *CPU-LSU force-splice* — primary no_cpu stimulus on the full-CPU VCS
  `--target default` build (`tb_top` no_cpu force-splice block). Without
  `+cpu_boot` it forces `u_sep_cpu.lsu_axi_req` from the flat `s_axi_*` ports
  and holds `u_sep_cpu.lsu_axi_resp_raw` at zero, so the halted core sees no
  beats it did not issue. The VIP request enters after
  `u_lsu_local_alias_remap`, so a test whose checked path includes the remap
  or the core names the build its evidence comes from. Owner: every no_cpu
  leaf graded on that build; each logs `LSU VIP force-splice active`.
* *ESRC noise force* — `esrc_noise_ext_i` into the decorrelator.
* *LC differential / token-comparator fault inject* — fail-closed paths with no
  legal OTP frontdoor.
* *eFuse read/program FSM state inject* — `efuse_read_state_inject_i` /
  `efuse_program_state_inject_i` with their enables force `read_state_q` /
  `program_state_q` for one cycle at a time. The only legal encodings are
  2'b01 and 2'b10, so the fail-closed recovery specified for 2'b00 and 2'b11
  has no frontdoor. Scope is those two registers and nothing else — never the
  error, data, busy or request outputs the checkers read. Owner:
  `sep_efuse_illegal_state_fail_closed_test`.
* *RMA-SIP digest test-enable inject* — `token_digest_test_en_inject_i`
  forces the digest latch `test_en_i`. The production DFT input is tied low
  at this boundary, so the latch-freeze path has no frontdoor. The force
  targets that input only. Token commands, digest capture, and the fault
  flags the checker reads stay frontdoor. Owner:
  `sep_efuse_digest_latch_fault_test`.
* *DMA host-path command-integrity inject* — `dma_host_intg_inject_i` forces
  the host-adapter command-integrity checker input to 0 so the checker
  asserts on the next DMA command. Software cannot emit a broken command
  user code. The force targets that input only. `DMA_BUS_ERR_STATUS` and
  the interrupt aggregate stay frontdoor. Owner: `sep_dma_basic_test`.
* *`tb_backdoor_mem` image init* — power-up / hex load into public macro arrays
  (not runtime pass-faking).
* *Observation-only XMR probe ports* — continuous assigns out of the DUT for
  scoreboards that have no CSR mirror (entropy CHK chain, IRQ aggregate,
  `drbg_csrng_axil_chan_o` / `drbg_edn_axil_chan_o` at each DUT lane
  adapter's AXI-Lite-64 port — concurrent AW/W/AR observation has no CSR
  mirror; `drbg_csrng_fwd_o` / `drbg_edn_fwd_o` at each DUT lane adapter's
  AXI-Lite-32 request — no CSR shows a request the bridge answered without
  error). The TB-owned `u_tbadp_vehicle` instance
  is idle and held in reset unless a vehicle leaf
  (`sep_drbg_axil_adapter_port_arbitration_test`,
  `sep_drbg_axil_adapter_refusal_test`) releases it; it and its
  AXI-Lite-32 request probe `tbadp_fwd_o` are not DUT XMRs.
* *SPI-to-DMA transmit pacing probes* — the OpenTitan SPI host transmit-FIFO
  depth (`spi_tx_qd_probe_o`), the SPI trigger bit at the secure DMA input
  (`spi_lsio_trigger_probe_o`) and the DMA `STATUS.busy` flop
  (`dma_busy_probe_o`). `STATUS.TXQD` is readable, but a CPU read cannot
  sample it on each clock of a DMA transfer, and no CSR shows the trigger.
  Read-only; no force. Owner: `sep_spi_ot_dma_tx_test`.
* *Crypto reset-sequencer probes* — the per-domain gated resets, the
  `isolated_o` completion bits and the host `isolate_req_i` bits at the crypto
  AXI interconnect (`*_gated_rst_n_probe_o`, `*_isolated_probe_o`,
  `*_host_isolate_req_probe_o`). Tests use them to order a domain reset against
  isolation and to place a read inside the drain window. `SW_RESET_N` holds the
  request but not the sequencer state, so none of these has a frontdoor. Used by
  the crypto reset-isolation, TRNG reset-recovery, KM isolate-termination and
  ABR tests.
* *Adams Bridge ML-KEM seed Z probe* — `abr_mlkem_seed_z_probe_o` is a
  read-only XMR of the Z words the engine holds for ML-KEM KEYGEN. The
  encapsulation key depends on D only, software cannot read Z back, and after a
  KV seed read the decapsulation key reads as zero, so the Z a KV read delivered
  has no frontdoor. Observation only; it drives nothing. Owners:
  `sep_km_sideload_share_walk_test`, `sep_km_abr_mlkem_sideload_test`.
* *Key Manager internal AXI-Lite SVA bind* — observation-only `bind` of
  `ocah_axi_sva` on `cpu_axil_*` / `rst_warm_sync_n`. No TB master can
  reach that port. Protocol, not data.

[[sep-run-modes]]
=== Run Modes and RTL Targets

The run mode selects who owns the CPU master buses. The RTL target selects
which CPU image is compiled. The testlist groups that pick the leaf set are in
the "Regression Groups" section of xref:SEP_VPLAN.adoc#sep-dv-verification-plan[SEP_VPLAN].

==== No-CPU AXI (`run_modes.no_cpu`)

The CPU is held off (`mpc_reset_run_req=0`). Two masters can drive the DUT:

* *LSU splice (`s_axi_*`).* The `lsu_stub_all_live` target swaps in
  `shims/cpu/sep_cpu_stub.sv`. The stub is the sole driver of `lsu_axi_req`
  and drives it from the `tb_top` net `lsu_req_drive` with a plain `assign`,
  not a `force`. This path has no inbound filter. On a full-CPU VCS
  `--target default` elaboration, a no_cpu test force-splices the same
  post-remap node (see the exceptions under <<sep-hdl-top>>).
* *SMN-inbound (`m_axi_*`).* A second `SepAxiAgent` on the real
  `smn_inbound` port. It is idle unless the test starts an external sequence.
  This path goes through `u_inbound_filter`, which blocks by default (DECERR
  unless `feat_ctrl.sep_debug=1`).

`sep_axi_smoke_test` is the smallest no_cpu test. It reads
`sep_cpu_ctrl.SEP_LOCAL_BASE_ADDR` (`+0x0C8`) for its reset value, then walks a
masked write and readback of `SEP_SW_DEBUG`, `SEP_NMI_VEC`, `PKA_CTRL` and
`SEP_REGION_SIZE`.

==== CPU firmware boot (`run_modes.cpu`)

`+cpu_boot` runs the full-CPU build. The core owns its buses and runs firmware
from the wrapper's real TCM macros, which `tb_backdoor_mem` in `tb/tb_top.sv`
loads by backdoor. `--stage c_compile` builds the gitignored
`fw/build/tests/<name>/{.itcm,.dtcm}.hex` images through `fw/fw.mk`.

`sep_hello_world_test` is the smallest firmware test. It loads the
`fw/tests/hello_world` image into ICCM and DCCM and passes
`rst_vec=0xC0000000` to `tb_top.sv`, which drives the wrapper's reset-vector
input before reset releases and sets `mpc_reset_run_req=1`. The test checks PC
advance (`sep_cpu_trace`) and the firmware banner and PASS magic on the
outbound mailbox (`tb/sep_outbound_mbx.sv`).

Production Boot ROM firmware tests use the `rom_boot` target and their own
`c_compile` profiles (<<_boot_rom_firmware_builds>>). Key Manager `rom_main`
tests declare `firmware = { name = "rom_main", mode = "km_rom_main" }`
(<<_km_rom_main_firmware_builds>>).

==== Boot and fuse-sense invariants

`ext_boot_seq_done_i` is held at 1. Fuse-sense policy is test metadata, not a
run mode. Tests that do not grade the eFuse usually add `+skip_fuse_sense` to
the `args` of their testlist entry to bypass the slow sense path. Real eFuse
tests omit that bypass and let the RTL fuse-sense FSM finish against the
generic eFuse model.

=== Environment Components

==== `SepEnv` / `SepEnvCfg`

`SepEnvCfg` holds clock periods (`sys_clk_period_ns` is 1.25 ns, the 800 MHz
silicon target, and `ref_clk_period_ns` is 10 ns), the AXI
access timeout, and the `reset_done` event the AXI driver waits on. `SepEnv`
builds both AXI agents, the value scoreboard, and the two passive monitors.

==== `SepAxiAgent`

PyUVM adapter over `ocah_axi_vip.OcahAxiMasterSequence`. Translates
`SepAxiItem` (op, addr, length, size, wdata, expected, expect_error,
allow_timeout, user, burst) into the VIP result API and broadcasts completed
items on an analysis port. Default prefix `s_axi`; set `axi_prefix = "m_axi"`
for the external master.

==== `SepScoreboard`

Subscribes to the CPU-LSU agent only. Checks OKAY responses, exact read
`expected` values when set, and the inverse for `expect_error` probes (must be
a real non-OKAY, not OKAY and not a timeout). `check_phase` requires zero
errors and at least one observed transaction.

==== `SepAxiMonitor`

Passive raw-pin integrity monitor (in-TB substitute for Verilator-disabled RTL
assertions). LSU bus fails on DECERR; external bus tallies DECERR because the
inbound filter may block by design. Also bounds slave READY wait on AW/W/AR
to ``cfg.axi_timeout_ns``: a permanent ``1'b0`` is legal AXI and not X, so
the protocol SVA cannot see it.

==== Entropy / crypto goldens and `SepDrbgScoreboard`

Entropy noise, decorrelator, BIW, and SHA models come from
`hw/ip/entropy_source/dv/cocotb/models/`; the standalone
entropy-source and SEP environments import that same package. SEP-specific
goldens remain under `cocotb/env/` (`sep_ctr_drbg_golden`, AES/HMAC/KMAC, LCC,
…). The DRBG
scoreboard consumes the same config object the sequence programs into the DUT
and compares against the datapath probes (CHK1–CHK5). Details of noise
staging and SR seeding are in the VPLAN entropy procedures.

==== Boot path: `SepBootScoreboard` + `SepCpuTraceMonitor`

CPU tests call `boot_firmware()`, which stages ITCM/DTCM hex, loads via
`tcm_load_i`, brings up with `+cpu_boot`, and polls PC-advance / console /
PASS magic. The trace monitor reconstructs a shadow call stack from EL2
retirement ports; see <<env-cpu-trace>>.

Before the boot, `RUN-IDENTITY-FW` logs the sha256 of both images and
`CHK-FW-IDENTITY` checks where they came from. The firmware build (`fw/fw.mk`)
compiles `FW-BUILD-ID:<digest>` into every image, with `<digest>` from
`fw/fw_src_digest.py` over the firmware source directories, once in ICCM and
once in DCCM. The test reads the string out of both loaded images and requires
each to equal the digest of the tree it runs from, which `RUN-IDENTITY` binds to a commit. An image built from other
source, or left over from an older build, fails the check.

==== Register metadata

`sep_reg_meta.py` imports generated PeakRDL headers under
`hw/sys/sep/regs/gen/` so sequences prefer source-derived addresses and reset
values over hand-kept literals.

==== Sequence Library

Stimulus lives in `cocotb/seq_lib/`. Prefer parameterized `uvm_sequence` classes
with register-map constants co-located in the same module. Tests orchestrate
bring-up / wait / check via `sep_base_test` helpers and start sequences with
`start_seq` / `start_ext_seq`.

[cols=",",options="header"]
|===
|Layer |Role
|`sep_base_test` helpers |Bring-up, fuse image, entropy wait, boot firmware
|Feature / IP sequences |DMA, SPI, inbound filter, eFuse, crypto KATs, fabric walks, …
|Concrete `@pyuvm.test` |Scenario steps only — no raw clock/reset paste
|===

New leaf pattern: `seq_lib/sep_<feature>_seq.py` +
`tests/<area>/sep_<scenario>_test.py`. Randomized tests use a config object as
the single source of truth for DUT programming and golden expectations
(`RAND-REP` / `RANDCFG` in the VPLAN).

=== eFuse Content Selection

All eFuse tests select their contents through
`sep_base_test.select_efuse_image()`. The shared helper uses
`+sep_efuse_preload` as the selector for fixed contents; without that plusarg it
generates constrained-random eFuse contents from the test seed.

[cols=",",options="header"]
|===
|Selector |Contents
|`+sep_efuse_preload=<path>` |A specific fixed `.hex` / `.preload` image
|`+sep_efuse_preload` (no path) |The committed default preload image (`tb/efuse_preloads/`)
|(none) |A random image generated from the test seed
|`+sep_efuse_hex=<path>` |Model-file override only; normal eFuse tests use the generated `out/sep_efuse.hex`
|===

The selected `SepEfuseImage` is the single source of truth. Because the generic
eFuse model deposits its image once at t=0 (not on every reset), the per-seed
image is staged BEFORE the simulator launches by the pre-sim hook
(`cocotb/dv_sim_prestage.py`, driven from `run_dv.py`), which writes
`out/sep_efuse.hex`; the model `$readmemh`s it at t=0 and its persistent W1S
storage retains programmed bits across resets. The same `SepEfuseImage` object
computes the expected shadow-register data for comparison.

End to end, one eFuse test runs:

[arabic]
. Test starts; calls `select_efuse_image()`, which reads the cocotb plusargs.
. Per the selector table above, a fixed, default, or seed-random image is built
  into one `SepEfuseImage` golden object.
. The pre-sim hook writes that image to `out/sep_efuse.hex`.
. The simulator launches; the model deposits the image at t=0.
. Reset is applied and released; the model's W1S storage persists.
. The RTL fuse-sense FSM reads the OTP words and fills the eFuse shadow
  registers; the test waits on `sep_fuse_sense_done_o`.
. The test reads the actual shadow data and compares it against the expected
  data computed from the same `SepEfuseImage`. Mismatch fails the test.

==== Readout method vs image source

The generic eFuse model sense flow (OTP image -> sense FSM -> shadow) is used by
more than the two shadow-compare tests. *Readout method and image source are
independent axes* for those two — backdoor is the default readout, exactly one
test uses the AXI front door, and either readout can run any source:

`sep_efuse_sense_test`:: *Backdoor* shadow compare (the default), reading the
  sensed array directly from the top-level `efuse_shadow_probe_o` port. Enrolled
  with `+sep_efuse_preload` (committed default preload).
`sep_efuse_image_test`:: The *one* test that reads the shadow over the *AXI front
  door* (exercising the real software read datapath), plus a resense cycle with a
  fresh image. Runs the default (random) source.

Other enrolled tests also run *real* fuse sense (no `+skip_fuse_sense`) for a
different contract — lifecycle decode, inbound-filter `SEP_DBG` gating, public-ID
delivery to the Key Manager — and do not replace the shadow-compare pair:
`sep_efuse_lcc_lc_state_stitch_test`, `sep_lcc_uvm_inbound_filter_gating_test`,
`sep_fabric_inbound_filter_rule_matrix_test`, `sep_efuse_km_public_id_test`. The
last reads the Key Manager's OTP input from the `km_otp_sep_*_id_o` ports.

=== Memory, eFuse, and SPI Models

The memory and eFuse integration is RTL inside `sep_wrapper`
(`hw/top/sep_ip_integration.sv`). The OpenTitan SPI host is RTL inside the `sep`
core. The TB does not back those ports with responders.

==== Memory macros

Real `prim_ram_1p` / `prim_rom` / EL2 TCM (`ram_16384x39`) macros. They have no
runtime init, so `tb_backdoor_mem` (in `tb/tb_top.sv`) pre-fills correct
power-up patterns (KM ROM NOP+parity, KM SRAM zero+valid parity, OTBN
SECDED-valid zero) and backdoor-loads images:

* boot-ROM / SEP-SRAM / KM-ROM via the `+sep_boot_rom_hex` / `+sep_sram_hex` /
  `+km_rom_hex` plusargs, with a CWD-default fallback to `sep_boot_rom.hex` /
  `sep_sram.hex` / `km_rom.parhex`. A named `+km_rom_hex` file must exist at
  t=0 (`$fatal`); `rom_main` tests declare
  `firmware = { name = "rom_main", mode = "km_rom_main" }` so `c_compile` builds
  it.
* the ICCM/DCCM firmware on `tcm_load_i`, de-interleaved with per-word Hsiao ECC.

These backdoor writes require the target arrays to be public under Verilator
(`sep_public_scope.vlt`: `prim_ram_1p.mem`, `prim_rom.mem`,
`ram_16384x39.ram_core`).

==== Generic eFuse model

`hw/ip/efuse/dv/models/efuse_bank_model.sv`, shared with SMC via a plusarg
prefix. It backs the eFuse bank-control and fuse-command datapath so fuse sense
runs without foundry OTP macros. It self-preloads its OTP image at t=0 via
`+sep_efuse_hex` (default `out/sep_efuse.hex`, staged by the pre-sim hook) and
persists W1S programs across reset. It can inject opt-in OTP program failures
with `+sep_efuse_prog_fail_count`, `+sep_efuse_prog_fail_percent`, and
`+sep_efuse_prog_fail_seed`.

==== OpenTitan SPI host

Internal to the wrapper; its pads come out as scalar cocotb ports in `tb_top.sv`
so tests can attach the Apache-2.0 `OcahSpiFlash` Python BFM.

==== TB shims

`shims/` holds the `sep_cpu` stub (no_cpu build) and the entropy
ring-oscillator. `tb/sep_outbound_mbx.sv` (the fw
console / PASS monitor) services a real wrapper output port,
not a memory model.

[[env-cpu-trace]]
=== Processor-State Monitoring and Firmware Stack Tracing

Firmware execution visibility has three layers: the virtual console
(`tb/sep_outbound_mbx.sv`, byte stores to `0x8000_0000` plus the PASS/FAIL
magic), the processor-state monitor, and firmware stack tracing. The last two
live in `cocotb/env/sep_cpu_trace_monitor.py`, a passive `uvm_component` built
by `sep_base_test` for every test and self-idling unless the `+cpu_boot` run
mode is active.

==== Trace source

`tb_top.sv` exports the complete VeeR EL2 retirement-trace struct
(`el2_trace_pkt_t`) as ports: `cpu_trace_valid_o`, `cpu_trace_addr_o`,
`cpu_trace_insn_o`, `dbg_cpu_trace_exc_o`, `cpu_trace_ecause_o`,
`cpu_trace_interrupt_o`, and `cpu_trace_tval_o`. The no-CPU shim ties the struct
to zero, so no_cpu targets elaborate unchanged. Sampling gates on
`sep_cpu_reset_n_o`; a warm CPU reset (e.g. the WDT bite path) flushes the
shadow call stack while history and tallies survive.

==== What the monitor reconstructs

PC history:: every retirement feeds a count, a distinct-PC set (the boot
  scoreboard's PC-advance evidence), and a 512-entry ring of the most recent
  retirements.
Shadow call stack:: retired RV32IMC encodings are decoded for linking calls
  (`jal`/`jalr`/`c.jal`/`c.jalr` through ra/t0), returns (`jalr`/`c.jr` through
  ra/t0), and `mret`. Exception-flagged retirements push a synthetic trap frame
  carrying ecause/interrupt/tval; `mret` unwinds it.
Trap records:: every exception retirement is kept with its cycle, PC, decoded
  mcause name, and tval.
Hang watch:: after the first retirement, a 20k-cycle retirement-free gap out of
  reset logs a one-shot warning with a full dump. Diagnostic only — a core idling
  in a wait loop or halt is legitimate.

Reconstruction hiccups (pop of an empty stack, depth overflow) are tallied as
resync notes and logged, never failed; pass/fail judgement stays in
`sep_boot_scoreboard.py`.

==== Symbolization

`cocotb/env/sep_fw_symbols.py` parses the `nm -B -n` listing the firmware build
emits next to every ELF (`<test>.tcm.sym`; `boot_rom.sym` for ROM profiles — both
staged into the run directory via the `[c_build.*].outputs` manifests) and
resolves PCs to `name+0xoff`. `boot_firmware` attaches the listing automatically
from the ITCM hex path; a missing listing degrades to numeric PCs and never fails
a test. Trace PCs are link addresses — the `-0xC0000000` bias in `fw.mk` only
rebases the TCM hex images.

==== Output

On any failing boot exit (no boot, hang, cycle exhaustion, firmware FAIL) the
monitor dumps the symbolized call stack, trap records, and the tail of the
retirement ring at error level before the scoreboard assertion ends the run; a
passing run logs the same summary at info level in `report_phase`. Passing
`+cpu_trace_log` additionally streams every retirement (cycle, PC, encoding,
symbol) to `cpu_trace.log` in the run directory.

`sep_cpu_trace_diag_test` (`testlists/cpu.toml`, firmware
`fw/tests/cpu_trace_diag_test`) audits the reconstruction against architectural
ground truth: a known noinline call chain, one breakpoint trap with the CSR-true
`mcause`/`mepc` reported on the console, cross-checked against the monitor's trap
record, shadow-stack depth, and symbolization.

RTL SVA participation depends on the backend. Under Verilator, first-party
and OpenTitan concurrent macros expand to nothing because those headers test
`VERILATOR`. The shared native profile also defines `COMMON_CELLS_ASSERTS_OFF`,
so PULP `common_cells` inline assertions are off on every backend. The checks
above are the checking layer the Verilator acceptance path relies on: nothing
else is watching there for a checker miss.

=== Coverage Strategy

Verilator does not support SystemVerilog covergroups on the acceptance path
(guard SV covergroups with `` `ifndef VERILATOR ``). Cocotb phases collect
named checker evidence and the traceability matrix in
xref:SEP_VPLAN.adoc#iconic-scorecard[SEP_VPLAN Matrix]. RTL code coverage is a different number
from feature coverage and carries no threshold. `[coverage.verilator]` in
`sep_sim_cfg.toml` instruments line, expression and user coverage (toggle off).
No scheduled CI tier collects coverage. The graded code-coverage number is the
VCS run that xref:SEP_FCOV.adoc#sep-dv-functional-coverage[SEP_FCOV] describes, and
`cov/config/vcs/coverage_policy.toml` is its report scope only — no thresholds
and no run gate on a percentage. Do not mix the two numbers.

=== Canonical RTL and Shim Selection

Bender targets are `["sep", "sep_el2", "sep_wrapper"]` only — never
`"simulation"`. Excluded for OSS hygiene: proprietary IPs in nonfree. They stay
out of the filelist rather than being blackbox-stubbed. Verilator override
shims under `shims/` are listed ahead of the Bender filelist so first-def-wins
selects them (`sep_cpu` stub on no_cpu, entropy RO). Scoped `sep_public_scope.vlt` replaces global
`--public-flat-rw` so AXI ready/valid cones stay optimizable.

[[_boot_rom_firmware_builds]]
=== Boot ROM Firmware Builds

Production Boot ROM firmware tests (188 in `testlists/rom_fw.toml`, for example
`sep_rom_non_secure_boot_test` and `sep_rom_ot_{dma,pio,secure}_boot_test`) run
in the `rom_fw` group only -- naming that group, or the test, is the only way to
reach them. They belong to the ROM-FW owner; the OSS suite
grades ROM *hardware* access only (`sep_boot_rom_smoke_test`,
`sep_rom_sanity_test`, `sep_boot_rom_lsu_read_test`).

A named ROM run needs the Boot ROM + manifest + BL1 image. Each test declares
both keys of a `firmware = { name = ..., mode = ... }` pair (`mode` alone does not
select a `[c_build.*]` block), and the two profiles select two different blocks
in `sep_sim_cfg.toml`, both driving `hw/sys/sep/bootrom/prod/Makefile`:

`boot_rom`:: `[c_build.boot_rom]`, built into `build/`, drains the SPI RX FIFO
  with the secure DMA. `sep_rom_non_secure_boot_test` boots this image down the
  SMC-SRAM manifest path and `sep_rom_ot_dma_boot_test` /
  `sep_rom_ot_secure_boot_test` boot it over the SPI host: which path runs is a
  strap set at run time, not a build difference.
`boot_rom_pio`:: `[c_build.boot_rom_pio]`, built into `build_pio/`, drains the
  RX FIFO by CPU programmed I/O instead. `sep_rom_ot_pio_boot_test` is its only
  user.

The one prerequisite a build step must not mutate git for is the manifest packer
submodule; without it the pack half dies with `No module named tt_boot_manifest`:

[source,bash]
----
git submodule update --init hw/sys/sep/bootrom/prod/tools/tt-oca-manifest
----

Build the ROM by hand only when iterating on the ROM sources themselves. The two
halves are split by tool dependency, so each runs where its tools are:

`toolchain-images`:: Needs the RISC-V toolchain *with* picolibc — the generated
  register headers close their packing checks with `static_assert`, i.e.
  `<assert.h>`, which is not a freestanding header. Use the toolchain container.
`oca-images`:: Pure Python; its deps come from the submodule's own
  `pyproject.toml`, installed on demand by `uv` (no `pip3 install` needed).

`[c_build.boot_rom]` performs exactly these two steps. An explicit
`$RISCV_TOOLCHAIN` must provide picolibc; when it is unset, the build uses the
OCAH container. It does not probe a site or `$HOME` toolchain path:

[source,bash]
----
# host toolchain has picolibc:
make -C hw/sys/sep/bootrom/prod toolchain-images \
  GCC_PREFIX=... RISCV_TOOLCHAIN=... RISCV_PREFIX=...
# otherwise, in the OCAH toolchain container:
./scripts/docker-run.sh run-here make -C hw/sys/sep/bootrom/prod toolchain-images

# oca-images is pure Python and always runs on the host:
make -C hw/sys/sep/bootrom/prod oca-images
----

Tests that boot the production KM ROM (`sep_km_*_sideload_kat_test`,

[[sep-uvm-realization]]
=== SystemVerilog UVM Realization (`--framework uvm`)

The SV-UVM realization runs through the same native runner: `sep_sim_cfg.toml`
declares it as the `[frameworks.uvm]` overlay (shared DV root, sim config, and
testlist; `build/uvm/` build tree), and `--dut sep --framework uvm` selects it
on VCS (the `native` profile's `uvm` framework, `-ntb_opts uvm`). Scenarios
carry both implementations in their testlist `module` binding map
(`module = { cocotb = "<module>", uvm = "<name>" }`); group selections skip
those without a `uvm` entry, and naming one errors. The framework
conventions and the bring-up walkthrough this realization follows are the
shared adopter guide, `hw/common/dv/docs/uvm-framework.adoc`; the reference
benches are DTP and SMC.

There is exactly ONE testbench top module: `sep_uvm_top` in `tb/tb_top.sv`,
shared between both realizations (<<sep-hdl-top>>). Under `UVM` the harness
adds the clocks (periods from `sep_tb_if`: `clk_i` at 1.25 ns and
`clk_ref_i` at 10 ns), the shared
AXI VIP master interface driving the `s_axi_*` request side of the CPU-LSU
splice and a passive mirror interface for the VIP monitor, quiescent
tie-offs for every other cocotb-driven pin at the idle value
`sep_base_test.drive_idle_defaults` uses, the `uvm_config_db` publication of
every virtual interface, and `run_test()`. The protocol SVA on the splice is
the `u_s_axi_sva` instance of the shared body, enabled through
`sep_tb_if.axi_sva_en` in this shape. The no_cpu scenarios keep
their `target = "lsu_stub_all_live"` binding, so the `sep_cpu` stub stays
the sole LSU driver in this shape as well. The class library mirrors the
cocotb conventions under `uvm/` with identical basenames, one class per
file, on the shared framework bases of `hw/common/dv/vip/ocah_lib/`:

[arabic]
. `hw/common/dv/vip/ocah_lib/uvm/ocah_lib_pkg.sv` — the shared framework
  bases every SEP class extends (test, env, sequence, sequencer, scoreboard,
  reference model, the two cfg bases, knob and seed accessors, pattern
  helpers).
. `hw/common/dv/vip/ocah_axi_vip/uvm/ocah_axi_uvm_pkg.sv` — the shared
  SV-UVM AXI VIP (items, configs, master driver and sequence API, passive
  monitor, agents, environments) with its interface, SVA, and coverage
  collateral. The CPU-LSU splice is the first driven interface: the active
  `ocah_axi_master_env` issues the traffic and a monitor-only passive
  `ocah_axi_env` feeds the SEP scoreboard.
. `tb/sep_tb_if.sv` — the SEP-local TB interface: harness clock periods,
  the primary reset and the boot/run controls, the fuse-sense-done and
  reset observables, the OTP JTAG2AXIL disable bits, the reset assertion
  counter, the SVA enable.
. `uvm/env/sep_env_pkg.sv` — `sep_types` (CPU-LSU geometry, the predicted
  `sep_cpu_ctrl` register table built from the generated
  `hw/sys/sep/regs/gen/svh/sep_reg.svh`, 32-bit-CSR lane helpers for the
  64-bit bus), `sep_test_cfg`, `sep_env_cfg`, `sep_virtual_sequencer`,
  `sep_cpu_ctrl_csr_ref_model`, `sep_scoreboard`, and `sep_env`.
. `uvm/seq_lib/sep_seq_lib_pkg.sv` — the reusable operation sequences
  (`sep_axi_csr_write_seq`, `sep_axi_csr_read_seq`) and the scenario
  virtual sequences on `sep_base_test_seq`.
. `uvm/tests/` — thin test classes named exactly like the scenario;
  `uvm/tests/sep_tests.sv` is the include manifest that `tb_top.sv` includes
  under `` `ifdef UVM `` (`+UVM_TESTNAME` selects the class).

Compile order is explicit and load-bearing: the library and VIP layers come
from their manifests (`hw/common/dv/vip/ocah_lib/uvm/sources.toml`,
`hw/common/dv/vip/ocah_axi_vip/uvm/sources.toml`, listed in
`[frameworks.uvm.build].source_lists` and expanded ahead of the DUT's own
sources), then the TB collateral both flows compile (the picorv32 KM core
files, `sep_outbound_mbx`), `sep_tb_if`,
`sep_env_pkg`, `sep_seq_lib_pkg`, and `tb_top.sv` last.

The scoreboard is always on and compares only. Each feature has its own
reference model on the shared `ocah_ref_model` base:
`sep_cpu_ctrl_csr_ref_model` subscribes to the CPU-LSU monitor stream,
keeps a shadow of the predicted `sep_cpu_ctrl` registers rebuilt from the
strobed writes it observes (each at its generated reset value until written
and again after every primary reset), and publishes one expected item per
OKAY predicted-register read on `expected_ap`; the scoreboard's
`cpu_ctrl_csr` feature pairs it in order with the observed read, and a test
that requires the feature fails when it recorded no comparison.
`+SEP_CSR_SCOREBOARD_NEGATIVE` corrupts the reference model's prediction so
the run must FAIL, proving the mandatory scoreboard gates pass/fail end to
end. Scenario sequences add named `CHK-*` evidence through the shared
`ocah_checker` (`CHECKER_SUMMARY name=sep_csr`), finalized per pass with
required IDs.

Logical item names stay framework-neutral and match the VPLAN scenarios, and
the UVM class name equals the scenario name (testlist
`name = "sep_axi_smoke_test"`,
`module = { cocotb = "system.sep_axi_smoke_test", uvm = "sep_axi_smoke_test" }`),
so `--items <name>` selects the same scenario in either realization. Nine
scenarios are bound; the "SystemVerilog UVM Smoke Set" section of
xref:SEP_VPLAN.adoc#sep-dv-verification-plan[SEP_VPLAN] lists them. For `sep_axi_smoke_test` a
pass covers fuse-sense release, the
`SEP_LOCAL_BASE_ADDR` reset-value read, directed and seeded-random
write/readback of `SEP_SW_DEBUG`, `SEP_NMI_VEC`, `PKA_CTRL` and `SEP_REGION_SIZE` through
their generated field masks, and a restore to reset
values, with the non-vacuity count of real CPU-LSU CSR accesses as
evidence. Every looped UVM test runs at least 16 scenario passes
(`ocah_test.MinDefaultLoops`), each seeded `+ntb_random_seed` + pass index,
with the loop knobs `+SEP_<TEST>_LOOPS`, `+SEP_<GROUP>_LOOPS`,
`+SEP_TEST_LOOPS`, and `+SEP_RANDOM_COUNT` resolved specific-first. `UVM TEST
PASSED` is emitted only in the base test's `report_phase` when the global
UVM_ERROR/UVM_FATAL counts are zero, matching the `uvm-log` parser policy.

==== Running the realization

[source,bash]
----
# SV-UVM build only (VCS)
python3 tools/dv/run_dv.py --dut sep --framework uvm --build-only

# PyUVM (cocotb) and SV-UVM, same logical scenario name
python3 tools/dv/run_dv.py --dut sep --items sep_axi_smoke_test --seed 1
python3 tools/dv/run_dv.py --dut sep --framework uvm --items sep_axi_smoke_test --seed 1

# Smoke group, UVM-implemented subset
python3 tools/dv/run_dv.py --dut sep --framework uvm --items smoke

# Negative validation: a corrupted scoreboard prediction must make the run FAIL
python3 tools/dv/run_dv.py --dut sep --framework uvm --items sep_axi_smoke_test \
  --plusarg +SEP_CSR_SCOREBOARD_NEGATIVE

# Loop and volume knobs (specific-first): +SEP_AXI_SMOKE_TEST_LOOPS=N,
# +SEP_SYSTEM_TEST_LOOPS=N, +SEP_TEST_LOOPS=N, +SEP_RANDOM_COUNT=N
python3 tools/dv/run_dv.py --dut sep --framework uvm --items sep_axi_smoke_test \
  --plusarg +SEP_TEST_LOOPS=4
----

A group runs its UVM-implemented subset. Naming a scenario that has no `uvm`
entry is an error.

=== Adding a Scenario to the SV-UVM Realization

One VPLAN scenario, two implementations: the testlist entry's `module`
binding map carries both, and the same `--items` name selects either
realization. To add the SV-UVM twin of a cocotb scenario:

[arabic]
. *Sequence* — add `uvm/seq_lib/<name>_seq.svh` on `sep_base_test_seq`.
  Start operations through the `csr_*` wrappers, or add a new reusable
  `sep_<if>_<op>_seq`. Add the include line to `uvm/seq_lib/sep_seq_lib_pkg.sv`.
. *Test* — add a thin `uvm/tests/<name>.svh` on `sep_base_test` (file, class
  and scenario share the name). Add the include line to `uvm/tests/sep_tests.sv`.
. *Testlist* — change the scenario's entry to
  `module = { cocotb = "<module>", uvm = "<name>" }`. The `uvm` value drives
  `+UVM_TESTNAME`.
