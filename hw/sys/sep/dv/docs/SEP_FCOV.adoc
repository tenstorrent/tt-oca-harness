[[sep-dv-functional-coverage]]
== SEP OCAH Open-Source Functional Coverage Plan

=== Overview

This plan covers **basic legal operating modes** of every SEP IP the OSS suite
already walks. It is the functional-coverage contract for the PyUVM/Verilator
flow.

Verilator does not compile SystemVerilog `covergroup`. Phase 1 bins are VCS
covergroups in `hw/sys/sep/dv/cov/sv/sep_fcov.sv` (`ifndef VERILATOR`),
sampled by the single passive `u_sep_fcov` instance in `tb/tb_top.sv`. There
is no Verilator cover-property layer.

Feature checkers stay on the VPLAN scorecard. The FCOV number is the URG
Group report on `sep_uvm_top.u_sep_fcov`, not the DUT line/cond/toggle/FSM
SCORE.

|===
|Field |Value
|DUT |`sep_wrapper`
|Reference specification |`hw/sys/sep/doc/`
|Reference VPLAN |`SEP_VPLAN.adoc`
|Open-source framework |PyUVM on cocotb
|Open-source simulator |Verilator
|===

=== Collection

`sep_fcov` is a passive TB-side sampler. It drives nothing.

Its CSR side reads the post-remap CPU-LSU AXI bus, wired from the same node
`tb_top` already mirrors to its flat `s_axi_*` ports and force-splices on the
no-CPU builds -- not a new probe, and not a Python path into the fabric
(`sep_public_scope.vlt` keeps public marks off it). The flat `s_axi_*` request
ports carry TB stimulus only, so under `+cpu_boot` the EL2 owns the bus and a
port-side sampler would score nothing on any firmware test. Everything else is
the real `m_axi_*` DUT port or a `tb_top` probe port.

The sampler also reads two DUT nets directly, read-only like the LSU bus: the
WDT bark interrupt that drives the CPU NMI (`intr_wdog_timer_bark`) and the LSU
read `ARSIZE`. Through existing `tb_top` probe ports it reads the HMAC and ABR
host isolate requests, `sep_reset_n` and the SPI `sd[0]` pad.

Register data bins are gated on exactly ONE outstanding AXI transaction in
that direction, and that transaction must be a single beat, so the address
that labels a bin is unambiguously the address that carried the data. A burst
would pair its start address with a later beat's data, and a W beat accepted
before its own AW belongs to the next transaction; both are skipped. A
pipelined burst of firmware traffic is therefore sampled only where it is
serial: a missed sample is a missed hit, never a false one.

The LSU demux sits inside `sep_cpu`, which resets on `sep_cpu_reset_n`, so the
outstanding counts restart when that reset asserts, as well as on the cold
reset. A warm reset that drops a transaction in flight would otherwise leave a
stale count and gate off every bus-decoded bin for the rest of the run.
Counting goes on while the reset is held, because the no-CPU bus still
completes transactions then (the SEC_DIS leaves read `LC_STATE` with
`sep_cpu_reset_n` low), and a response with no count does not decrement. The
SMN inbound counts restart when `sep_reset_n` asserts, because the inbound
filter sits in `sep_system_peripherals`, which resets on it.

A covergroup bin is an interface event. It is not a substitute for a VPLAN
checker that compares a golden (digest, banner text, shadow image).

Collect with `--tool vcs --cov --target default` and read the URG Group pages
for `u_sep_fcov`. The code-coverage number (line/cond/toggle/FSM/branch) is a
different number, and the sampler is not part of it:
`cov/config/vcs/sep_cov_scope.hier` removes `sep_uvm_top.u_sep_fcov` from code
coverage, so only its covergroups are graded, as the Group number. The URG
headline SCORE averages both.

`OCAH_FCOV_COVER` cover-property points are unused.

=== Phase 1 coverage definitions

Each row is one coverpoint of the named covergroup in
`cov/sv/sep_fcov.sv`. A row states what the sampler must SEE, which is not
always the whole feature contract: where the contract needs a golden, the row
says which checker keeps it. Do not read a hit as the checker's claim.

==== `sep_axi_decode_cg`

*Description*: The LSU bus decodes a live CSR and returns OKAY.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_reset_value` |An OKAY read of `SEP_LOCAL_BASE_ADDR` returns its generated reset value
|`cp_wr_rdback` |A whole-word CSR write, then an OKAY read of that address returning the written word
|`cp_resp_wr` / `cp_resp_rd` |An OKAY write response; an OKAY read response (separate coverpoints, so a write-only or read-only run cannot fill both)
|`cp_block` |An OKAY read in each LSU-reachable register block of `sep_reg.svh`: `SEP_CPU_CTRL`, `SECURE_DMA`, `WDT_TIMER`, the cold and warm scratch banks, `SEP_RESET_CTRL`, OTBN, AES, HMAC, KMAC, CSRNG, EDN, `ENTROPY_SOURCE`, `SEP_LIFECYCLE_CTRL`, the KM mailbox, the eFuse shadow map, `EFUSE_INTERFACE_CTRL`, `EFUSE_MMR`, ABR, the entropy pool, the AXI-Lite mailboxes, and the alias, AP remap, STEE remap, outbound filter and inbound filter banks, and the SPI host. SRAM and the boot ROM have their own groups. The PIC is inside the VeeR core and `SEP_EXTERNAL` is the outbound port, so neither has a cell. TRNG has no cell because no `all` leaf makes an OKAY read of it
|`cp_aw_w_order` |Which VALID the master raised first for a write that then completed OKAY: `aw_first`, `w_first`, `same_cycle`. Taken at the first cycle either VALID is high with no write outstanding
|`cp_ar_during_write` |A read address accepted while a write has its address accepted and no data beat yet
|`cp_wstrb` |Byte lanes of a completed write: 1, 2, 4, 8
|`cp_rd_depth` |Reads in flight when a read is accepted, this one included: 1, 2-4, 5 or more
|`cp_arsize` |`ARSIZE` of a completed read: 1, 2, 4, 8 bytes
|===

`cp_block` records decode, not a value: the reset-value and RW checks stay on
`sep_address_map_test` and `sep_reg_bit_bash_rand_test`.

==== `sep_cpu_boot_cg`

*Description*: VeeR EL2 boots firmware and reports PASS.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_console` |A firmware console-byte strobe
|`cp_pass` |Firmware completion with PASS
|`cp_pc` |A retired PC that is non-zero
|===

`cp_pass` is sampled in the time step the outbound-mailbox model raises
`fw_done` with PASS, not on a clock. The cocotb boot loop reads `fw_done` on the
next rising edge and ends the run there, so a clock-sampled strobe races the end
of the simulation and was lost on almost every firmware leaf. VCS does not
allow an explicit `sample()` on a group with a clocking event, so this group is
sampled by function: every clock for `cp_console` / `cp_pc`, and once at the
PASS edge.

The expected banner text and the distinct-PC count stay on the boot
scoreboard. A covergroup counts hits, not distinct values.

==== `sep_aes_mode_cg`

*Description*: AES legal mode x key-size x operation. The suite walks 15 cells.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_mode` |ECB, CBC, CTR
|`cp_key` |128, 192, 256
|`cp_op` |ENC, DEC
|`cp_sideload` |SW key (`KEY_SHARE` CSRs) and KM sideload key (`CTRL_SHADOWED.sideload`)
|`x_mode_key_op` |15 cells: the 9 ENC cells plus the ECB/CBC decrypt legs of the round-trip. CTR x DECRYPT is excluded, see below. A cell is sampled when that configuration reached `STATUS.output_valid` and its `DATA_OUT_0` word was read
|===

CTR x DECRYPT is an `ignore_bins` in the cross because the cell has nothing
to score, not because the suite happens not to drive it. CTR is a stream
mode: the engine runs the forward cipher whichever way `OPERATION` is
programmed, so a test that programmed DECRYPT there would pass with the
field disconnected. It is not a deferral -- there is no cipher contract
behind that cell for a later phase to claim. The scoreable neighbour is
`OPERATION`'s shadowed-register behaviour, which is mode-independent and
belongs on a CSR vehicle. `cp_op` and the decrypt cells are owned by
`sep_aes_mode_keysize_rand_test` CHK-RT (the engine round-trip);
`cp_sideload.km_key` by `sep_km_aes_sideload_kat_test` and

==== `sep_crypto_isolate_cg`

*Description*: The per-IP isolate-then-reset sequencing for the HMAC and Adams Bridge domains.
An accelerator reset waits on both the SEP host path and the Key Manager path,
so the ordering bin reads both completion bits.

Every bin is an EDGE, not a state. Both isolate bits stay high for the whole
reset window, so a state bin would fill on any run that parks HMAC at all --
including one where the reset preceded the drain, which is the thing the
ordering bin exists to catch.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_km_iso` |The cycle the `km_hmac` path reports isolated while the HMAC isolate request is high. The host-side isolation entries never present a transaction on this path; that a KM master path reaches isolation under the HMAC request is what this bin records.
|`cp_rst_ordered` |The cycle the HMAC gated reset falls under the HMAC isolate request, with both the host and Key Manager isolate bits high and the KM bit raised by that request (`cp_km_iso`). A reset that fell before either bit does not fill this bin.
|`cp_abr_rst_ordered` |The cycle the Adams Bridge gated reset falls under the ABR isolate request, with both isolate bits high and the host bit (a full-AXI isolate) raised by that request. The leaves that reset ABR hold the KM in reset, so `km_abr` is already high and only the host term is ordered; see below.
|`cp_reopen` |The cycle `km_hmac` reports un-isolated again after a `cp_km_iso` edge, so the path was released rather than left isolated for the rest of the run.
|===

The KM-path bits are also raised by a Key Manager reset: `sep_reset_ctrl.sv`
ORs the KM isolate request into `km_hmac` and `km_abr`. A leaf that holds the KM
in reset therefore sees them high from time 0, and a KM hold or release on
`SW_RESET_N` moves them with no HMAC or ABR isolate at all. So every KM-path
edge counts only while the domain's own isolate request is high, and an
ordered reset counts only when the KM bit rose under that request: a KM bit
that was already high cannot show that the sequencer waited for it. The
request also excludes a warm reset, because `sep_reset_n` forces the gated
resets without the sequencer and leaves the request low.

The ABR Key Manager term (`km_abr` raised by an ABR request with the KM
released) has no leaf: `sep_crypto_per_ip_reset_isolation_test` holds the KM
at its reset default and grades the host term only (`CHK-ABR-DRAIN-ORDER`). It
is planned for a leaf that resets ABR with the KM released, and has no bin
until that leaf exists.

==== `sep_dma_copy_hash_cg`

*Description*: DMA copies memory and computes a hash.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_copy` |`CONTROL.GO` with opcode COPY
|`cp_hash` |`CONTROL.GO` with opcode SHA256
|`cp_hash_opcode` |Which inline-hash opcode was commanded on a `CONTROL.GO`: `sha256`, `sha384`. `cp_hash` above is SHA-256 only, so it does not distinguish a SHA-384 transfer. SHA-512 is a legal opcode (`OpcSha512`) that no leaf commands, so it has no bin rather than a permanent hole.
|`cp_copy_done` |Completion after a COPY GO
|`cp_hash_done` |Completion after a SHA256 GO
|`cp_chunk` |`STATUS.chunk_done` observed while a GO'd transfer is outstanding
|`cp_rego` |A GO with `INITIAL_TRANSFER` = 0, i.e. a continuation chunk
|===

`cp_chunk` and `cp_rego` record the DMA's normal one-chunk-per-GO protocol:
the engine raises `CHUNK_DONE` and drops BUSY, and firmware W1Cs it and re-GOes
until the final chunk reports DONE (`fw/drivers/sep_dma.h`,
`dma_basic_test.c`). That loop is why one transfer produces many GO writes, and
without these two bins it hides inside `cp_copy`. They do not claim the Phase 2
`sep_dma_transfer_cg` enumeration -- chunk sizes, endpoints and range configs
stay there.

Completion is `STATUS.done` OR the DMA-done interrupt
(`sep_internal_interrupts[8]`, `sep.sv:535`), because the suite's firmware uses
both routes: `dma_basic_test` polls `STATUS`, while `dma_hash_test` enables
`INTR_ENABLE.DMA_DONE`, WFIs, and its handler clears `STATUS.done` before
software reads it -- so on that path no `STATUS` read with the DONE bit ever
reaches the bus. A `STATUS`-only bin therefore cannot fill `cp_hash_done`.
The GO'd opcode still labels the cell, so an interrupt cannot score the
wrong one.

The destination-matches-source and digest-matches-golden claims stay in the
DMA firmware. These cells are driven only by the firmware tests
(`sep_dma_basic_test`, `sep_dma_hash_test`, `sep_dma_cpu_contention_test`, and
the SPI DMA leaves `sep_spi_ot_dma_rx_test` / `_tx_test`, which GO a COPY),
which is why the sampler reads the internal LSU bus: on the flat TB ports they
could not fire at all. Opcode and range errors are Phase 2.

==== `sep_inbound_filter_allow_cg`

*Description*: One legal inbound transaction is allowed.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_allow_wr` |An `m_axi` write OKAY whose address is inside the programmed enabled window
|`cp_allow_rd` |An `m_axi` read OKAY inside that window
|===

The window is decoded from the `FILTER_CONFIG` / `START_ADDR` / `END_ADDR`
writes on the CSR bus. `START_ADDR` and `END_ADDR` hold a 56-bit address in two
32-bit halves, and the compare uses all 56 bits of the `m_axi` address. A write
OKAY counts only when the entry's `FILTER_CONFIG.WRITE_ALLOWED` is set, and a
read OKAY only with `READ_ALLOWED`: an OKAY in a direction the entry refuses
came from another entry or the default policy. The compare is against the
PROGRAMMED range, not its 4 KB page:
`traffic_filter.sv` compares `addr[.:12]` only in its allow_burst arm, and
`addr[.:DATA_BUS_WIDTH_LOG2]` otherwise, so a page compare is a superset of the
real grant. Comparing the range can only miss a page-widened grant, never
invent one. Both bins are also gated on exactly one outstanding inbound
transaction, like the CSR-side bins -- `sep_axi_order_sweep_m_axi_test` runs
several at once, and a last-write latch would pair one access's response with
another's address.

The window is committed as ONE entry: each half of START and END is latched
with its entry index, and they are accepted only at the enabling
`FILTER_CONFIG` write of that same entry. Independent last-writes would otherwise assemble a window out
of one entry's START, another's END and a third's ENABLE -- a window the DUT
never held. The entry count comes from
`sep_pkg::INBOUND_FILTER_NUM_FILTERS`, not a literal.

The full rule matrix, the deny path, and the winner walk over all 48 entries
(inbound `INBOUND_FILTER_NUM_FILTERS` = 16 plus outbound
`OUTBOUND_FILTER_NUM_FILTERS` = 32) are Phase 2.

==== `sep_efuse_program_lock_cg`

*Description*: A spare eFuse field is programmed while unlocked, and refused
once its write-lock is set.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_field` |SPARE0..SPARE8
|`cp_lock` |The target's write-lock state when the program was issued: unlocked, locked. A spare counts as locked once a program of its lock bit completed with `PROGRAM_DONE` and a clear `PROGRAM_STATUS`; a refused lock program leaves it unlocked
|`x_field_lock` |18 cells
|`cp_outcome` |Sampled on the first `PROGRAM_CTRL` read with `PROGRAM_DONE` set after the GO: programmed (`PROGRAM_STATUS` clear) and refused (`PROGRAM_STATUS` set)
|===

`PROGRAM_STATUS` is the outcome only on a read that also shows `PROGRAM_DONE`.
GO clears DONE but not STATUS, and both update together when the program ends
(`efuse_program_interface.sv`), so a STATUS read while the program is busy
still holds the previous program's outcome.

Programming a write-locked field is a legal software action with a specified
outcome, not a fault injection -- the same class as writing a read-only
register -- so it is Phase 1 and not one of the Phase 2 error groups.

All 18 cross cells are filled by a SINGLE seed:
`sep_efuse_program_lock_matrix_test` walks unlocked-program, then lock, then
reject on each of SPARE0..SPARE8 in order, and only the bit offset inside a
spare is seed-selected. Walking every spare is what makes the slot numbering
falsifiable -- a lock bit wired to the wrong slot would otherwise be caught only
on the seed that happened to draw that spare.

The outcome is a separate coverpoint rather than a third cross dimension: a
`field x lock x outcome` cross would declare 18 cells that only a broken DUT
could fill, and the program-succeeds / lock-refuses contract belongs to the
test's checker.

Everything is decoded frontdoor from `EFUSE_PROGRAM_CTRL` -- `EFUSE_ADDR` plus
`PROGRAM_GO` on the write, `PROGRAM_DONE` / `PROGRAM_STATUS` on the readback --
and the spare index comes from the generated `SEP_EFUSE_MAP_SPARE*` offsets, not
a literal. The spare count comes from the generated `LOCKS_SPARE` reserved-field
shift.

PROD_END -- none at TEST_DEV -- so TEST_DEV to PROD has no producer; the

it produces nothing here. TEST_DEV to PROD_END and TEST_DEV to RMA_SIP have no
walk either, and PROD to PROD_END is impossible under write-1-to-set at all:
`0x1 | 0x8` is `0x9`. The transition-legality claim stays on
`sep_lcc_golden.lc_state_next`.

==== `sep_feat_ctrl_cg`

*Description*: The decoded debug profile `FEAT_CTRL` produced, per sensed
lifecycle state and per override.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_state` |The seven legal raw encodings, taken from the SENSED shadow value
|`cp_debug` |none / partial / full over the five defined debug bits: `DBG_1` `sep_debug`, `chiplet_dbg`, `sep_fuse_dbg`, `smc_fuse_dbg` and `DBG_2` `sip_debug`
|`cp_sec_dis` / `x_sec_dis_debug` |SEC_DIS off/on crossed with the profile; `on` can only pair with `full`, so the other two products are `ignore_bins`
|`cp_secure_tm` |The latched TEST_EN strap, both polarities
|===

Sampled when the second 32-bit half of `FEAT_CTRL` is read, so the profile is a
complete 64-bit value, and only after a real fuse sense completed: the shadow
reads 0x0, which is the TEST_DEV encoding, until sensing is done, and a
`+skip_fuse_sense` run never senses at all. `sep_lc_demote_cg` takes the same
sample.

There is no state x debug cross: the decode fixes one legal profile per
lifecycle state, plus the SEC_DIS all-ones override, so most of the 21 products
are illegal and would be permanent holes. Naming the legal set means restating
`sep_lcc_golden.feat_ctrl_expected`, which belongs to the checker.

`SECURE_TM` is a standalone coverpoint and NOT crossed with the profile: it does
not qualify feature control (`env/sep_lcc_golden.py`). The `FEAT_CTRL` layout is
`DBG_1[23:0]`, `DBG_2[47:24]`, `Function[63:48]`, with no test group to cross
against.

The state comes from the sensed shadow probe rather than a frontdoor
`LC_STATE` read, because the probe is the state the decode used at the time of
the `FEAT_CTRL` read. A frontdoor read of `LC_STATE` is a separate access that
can come before or after it.

The decode-matches-golden claim stays on `sep_lcc_golden`. Token faults and the
`sigint` fail-closed matrix are Phase 2.

==== `sep_mailbox_pic_cg`

*Description*: A mailbox interrupt is raised and cleared, per source domain.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_raise` / `cp_clear` |Rising and falling edge of any SEP AXI mailbox source, `sep_internal_interrupts[7:0]`, driven from `inbound_interrupt_o` in `sep.sv`
|`cp_km_raise` / `cp_km_clear` |Rising and falling edge of the KM mailbox, `sep_internal_interrupts[14]`, after software wrote a non-zero `SEP_IRQ_ENABLE`. ==== `sep_wdt_bark_cg`

*Description*: Watchdog bark reaches NMI.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_thold` |A `WDOG_BARK_THOLD` write that the watchdog acted on: the bark interrupt rises after it
|`cp_bark` |An OKAY read of the WDT `INTR_STATE` with `wdog_timer_bark` set
|`cp_nmi` |A retired exception flagged as an interrupt while the bark interrupt, which is the CPU NMI input, is high
|===

`cp_nmi` reads the bark interrupt itself (`intr_wdog_timer_bark`, the net
`sep.sv` connects to the CPU `nmi_int_i`), so it does not depend on when
firmware reads `INTR_STATE`. The firmware reads it inside the NMI handler,
after the trap, so a bin that required the read first could never see the NMI
that the bark caused. An unrelated interrupt with the bark low does not score.
`cp_thold` needs a bark after the write, because a register walk writes the
threshold with the watchdog disabled. A run whose WDT never barks leaves these
cells empty, and that is the honest report, not a gap to close by loosening the
bin. Bite, wakeup cause, and
`REGWEN` lock are Phase 2.

==== `sep_scratch_reset_cg`

*Description*: Warm scratch clears on warm reset; cold scratch retains.

[cols=",",options="header"]
|===
|Coverpoint |Bins
|`cp_warm_wr` |An OKAY write in the warm bank, scored at the warm reset that follows it
|`cp_cold_wr` |An OKAY whole-word write in the cold bank, scored at the warm reset that follows it
|`cp_warm_rst` |A falling edge of `sep_cpu_reset_n`, after the reset release has settled and after a scratch value was staged
|`cp_warm_rd` |A warm-bank read returning 0 AFTER that reset, with a warm write before it
|`cp_cold_rd` |A cold-bank read returning the value written before that reset
|===

The two write bins are scored at the warm reset, not at the write: many bus
leaves use scratch as plain storage and never reset it, and those writes say
nothing about retention. The two read bins are sampled after the reset edge, not on it: a bin ANDed
with the falling edge can never fire, because no read completes in that cycle.

`cp_warm_rst` carries two guards for the same reason. `sep_cpu_reset_n`
(`sep_reset_n & wdt_rst_ni`) also falls during cold bring-up, so a bare edge
term scores in any test and, worse, arms the
two retention bins off an edge the scenario never produced. Requiring a
settled release and a staged scratch value makes the bin the scenario's warm
reset.

=== Maintenance

Add a Phase 1 bin only when an `all`-group test already walks that cell, or

belongs in the Phase 2 named set. Keep covergroup instance names stable
when a module is added: the URG Group report matches them by hierarchy name.
