== SEP OCAH Open-Source Verification Plan

=== Overview

[cols=",",options="header"]
|===
|Field |Value
|Design Under Test |`sep_wrapper` (`hw/top/sep_wrapper.sv` + `sep_ip_integration`)
|Bare core |`sep` (`hw/sys/sep/rtl/sep.sv`)
|Repository |`tt-oca-harness`
|Project |OCAH
|Framework |PyUVM on cocotb (Phase 1 / Phase 2); UVM planned (Phase 3)
|Primary simulator |Verilator
|Architecture reference |`hw/sys/sep/doc/`
|Register export |`hw/sys/sep/regs/gen/` (via `env/sep_reg_meta.py`)
|How to run |`README.md` in this DV tree (`tools/dv/run_dv.py --dut sep`)
|Phase 1 test cases |31
|Phase 2 test cases |45
|Phase 3 |T.B.D. (new UVM bench)
|===

This VPLAN is the technical contract for the open-source SEP DV
suite: what each phase covers, how tests are named, which VIPs
drive the DUT, and what each registered test must prove. It is
written for adopters and maintainers of the public tree. Testbench
structure (env hierarchy, HDL top, bring-up helpers) is in
link:SEP_TB_ARCH.adoc[SEP_TB_ARCH].

PASS/FAIL needs positive evidence in the simulation log (named
`CHK-*` lines or equivalent). A clean simulator exit alone is
not enough.

=== Verification Strategy

One DUT. Two environments across three phases.

[cols="1,2,3",options="header"]
|===
|Phase |Environment |Job

|Phase 1
|cocotb / PyUVM + Verilator
|Smoke plus subsystem representatives. Fewest tests that carry the most real datapath behaviour.

|Phase 2
|Same cocotb environment
|Iconic feature coverage by IP, plus cross-IP edges a per-IP bench cannot see. Includes block activation for instantiated IPs that otherwise had no vehicle. Randomize when there is a legal matrix (`RAND-REP` / `RANDCFG`); keep directed (`RAND-NONE`) when there is not.

|Phase 3
|New UVM testbench
|Bring-up + smoke first, then coverage-driven corners, error/security permutations, and code-coverage close-out. Low overlap with Phase 1 / Phase 2. See <<phase-3>>.
|===

[arabic]
. *Stimulus*: no-CPU tests drive the CPU-LSU AXI splice through
  `ocah_axi_vip` / `SepAxiAgent`. An optional second master drives the
  real SMN-inbound port (traverses the inbound filter). CPU tests boot
  VeeR EL2 firmware from ICCM. SPI flash uses `ocah_spi_vip`.
. *Checking*: frontdoor reads/writes, independent Python goldens where
  needed (AES/HMAC/KMAC/OTBN/entropy/LCC), and named checkers that can
  fail on a broken DUT. Prefer source-derived expected values from the
  register export and architecture docs.
. *Bring-up*: drive `ext_boot_seq_done_i`; use `+skip_fuse_sense` only
  when the test does not need real OTP sense; hold the CPU off for
  `no_cpu` runs.
. *Coverage*: iconic feature scorecard (<<iconic-scorecard>>) for the
  cocotb phases; RTL code coverage is collected under Verilator and
  closed out in Phase 3. SystemVerilog covergroups are not used on the
  Verilator acceptance path.
Randomization contract: the *same* config object programs the DUT and the
golden. Pin the datapath directed first, then upgrade that test to randomized —
do not ship a one-point stand-in for a matrix. Skip randomization only when the
feature has no legal knob space (a strap, a single named handshake).


=== Naming Rules

[cols=",",options="header"]
|===
|Rule |Requirement
|Test case name |`sep_<feature>_<scenario>_test` in lower snake case
|Single-scenario module |Module name matches the test case
|Multi-scenario / RAND-REP |One leaf test walks every required discrete cell in one invocation; do not silently ship a one-point stand-in for a matrix
|Open-source files |PyUVM test under `cocotb/tests/`, stimulus in `cocotb/seq_lib/`, shared helpers on `sep_base_test` / `cocotb/env/`
|Testlist enrollment |Leaf entry in the owning `testlists/*.toml` and in `testlists/all.toml`
|Evidence |Every checker needs a positive log line naming the contract
|===

|===

|`sep_fabric_inbound_filter_rule_matrix_test`
|no_cpu, real PROD fuse sense
|ocah_axi_vip
|Brings the lifecycle controller up in PROD so the inbound filter is genuinely active (`sep_debug=0`, value-checked against the lifecycle golden), then walks entries 0 and 7, two address windows, and `{rw, read-only, write-only}` at `src_id=0` (match-all), plus entry 0 / window 0 × `{rw, r, w}` at `src_id=0x5` with a matching AXI `user[3:0]` and one src-mismatch cell — 16 cells in one invocation — then the same-page `allow_burst=1` granule, page-bound, and `FILTER_CONFIG.locked` on entry 15.
|`sep_fabric_remap_filter_csr_bank_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|R/W, 64-bit, RO, valid, and write-once-set across the alias/AP/STEE remap and inbound/outbound filter CSR banks.
|`sep_fabric_output_remap_datapath_proxy_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Live remap plus outbound-filter drop.
|`sep_reg_bit_bash_rand_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|`env/sep_reg_meta.py` exports `addr`, `reset`, `mask` (software-usable field bits) and `mask_all` (storage, reserved included) from the generated SystemRDL.
|`sep_fabric_deadspace_decode_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Negative control on intra-block dead space. Each block owns an address window and populates only part of it; an access past the allocated size owns no register and must be refused. Window ends come from `hw/sys/sep/doc/memory_map.adoc`, which states the rule: within an aperture only the unit's register extent responds and the remainder returns DECERR. Landing on a live register instead is a hard failure. A later beat of a burst that ends past the window's extent must be refused on the same terms as a single beat.
|`sep_fabric_local_alias_datapath_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Scope is the sixteen programmable local-master regions ahead of the system-peripherals routing demux (`hw/sys/sep/doc/fabric.adoc`, `axi_alias_remap`).
|`sep_axi_order_sweep_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|AW and W are independent channels with no ordering requirement between them (IHI 0022 A3.3), so AW-first, W-first and same-cycle are all legal and each must deliver the write without displacing its neighbour. Each block terminates AXI at its own register adapter, so the contract has to hold at each of them: 321 cells over 27 blocks, crossed with 1/2/4-byte sizes on the scratch words. The ordering each cell presented is read off the AW/W valid assertions and asserted against what was requested.
|`sep_axi_order_sweep_m_axi_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|The same ordering walk driven from the SMN inbound master. m_axi reaches the same eleven IP blocks through the inbound filter, which denies by default, so the walk opens allow windows from the CPU-LSU side first. The sixteen `INBOUND_FILTER_CTRL` blocks are excluded and counted: those CSRs gate the access in flight, so writing them mid-walk would measure filter reprogramming rather than adapter ordering. Unlike the CPU-LSU splice, this path grants a W-first handshake.
|`sep_axi_strobe_window_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Narrow-write lane masking against the AXI strobe rule (IHI 0022 A3.4.3), plus write/readback of the OTBN IMEM and DMEM memory windows. The KMAC state window is not probed: it is gated by the engine's own configuration, so a probe there would test KMAC bring-up rather than the read mask. A window behind an SRAM-style adapter applies the mask on reads, unlike a register behind a register adapter, so a bridge driving that mask from the write strobe returns zeros with a correct response — only a data compare sees it.
|`sep_axi_partial_lane_read_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Read-side counterpart of the strobe test: a read narrower than the 64-bit beat only obligates the responder to drive the addressed byte lanes (a 32-bit CSR leaves RDATA[63:32] undriven; a narrow-ARSIZE beat leaves every non-addressed lane undriven), so the value handed to the test must be a pure function of the addressed lanes. Every read is compared against an independent golden and repeated around a checked disturbing access, so a result that leaks undriven lanes or leftover channel state fails as a mismatch.
|`sep_axi_map_refuse_test`
|no_cpu, +skip_fuse_sense
|ocah_axi_vip
|Inter-block reserved space: rows marked `_RSV_` in `hw/sys/sep/doc/memory_map.adoc` allocate nothing, so an access there must not answer OKAY. The refusal expectation comes from the map, never from the RTL. The crossbar decode table is parsed both as a logged cross-check and as a stimulus filter: an address the crossbar routes is left out of the probe set, because whether the fabric must refuse a routed-but-reserved span is an open specification question. Walks the gaps BETWEEN block windows; `sep_fabric_deadspace_decode_test` walks the dead tail INSIDE one.

The architecture docs under `hw/sys/sep/doc/` define the feature set. An
*iconic* row is the mode, command, or contract that makes that IP itself.

[[sep_otbn_mem_smoke_test]]
===== `sep_otbn_mem_smoke_test`

*Phase*: 1

*Run mode*: `no_cpu` (`target = "lsu_stub_all_live"`, `+skip_fuse_sense`)

*VIP / Model*: ocah_axi_vip

*Objective*: Proves the OTBN instruction and data memories are writable and readable over the CPU LSU frontdoor at the 32-bit access width OTBN's own program-load driver uses.

*Test Procedure*:

[arabic]
. Bring up in `no_cpu` mode.
. Read OTBN `STATUS` and require it to be neither `LOCKED` nor a memory-wipe state.
. Write a known word to the OTBN instruction memory base; read it back.
. Write a known word to the OTBN data memory base; read it back.
. Read the instruction and data memory request and write counters.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-IMEM
|The instruction-memory word reads back exactly as written.
|CHK-DMEM
|The data-memory word reads back exactly as written.
|CHK-ARRIVED
|Both memories saw exactly the issued accesses — 2 SRAM requests each, of which 1 is a write — proven by the counters rather than by the readback alone.
|CHK-WRESP
|Both write responses are `OKAY`.
|CHK-PRECOND
|OTBN is neither `LOCKED` nor executing when the memories are accessed, so a bus access to them is legal. This is an exclusion, not an exact-state check: any other `STATUS` value is acceptable. Bus access is diverted and flagged illegal only while OTBN executes.

*Scope limit*: OTBN sits in `StatusBusySecWipeInt` (`0x04`) for the whole of this
test — leaving that state needs EDN entropy to reseed URND, and the `no_cpu`
smoke configuration never brings EDN up. The internal wipe does not touch
IMEM/DMEM, which is why every access completes OKAY. `CHK-PRECOND` excludes only
the states that would invalidate the access (`LOCKED`, and `BusyExecute`, in which
the core owns these memories and a bus request is diverted to a dummy response
and flagged illegal); it does not pin `STATUS`, and it does not detect a change
from `BusySecWipeInt` to `IDLE` or `BusyExecute`.

*Design context, not a claim*: accesses drive `AxSIZE=2` (4-byte beats). These
memories are 32-bit SECDED words and reject the 64-bit default beat with SLVERR;
the 32-bit width is what OTBN's own program-load driver issues. No enrolled test
covers that rejection.

[[sep_dma_hash_test]]
===== `sep_dma_hash_test`

*Phase*: 1

*Run mode*: `cpu`

*VIP / Model*: ocah_axi_vip, CPU FW

*Objective*: Drives the secure DMA engine from real firmware to copy a block from SRAM into the CPU's data tightly-coupled memory with inline SHA-256 enabled, then proves two things independently: the copied data is identical to the source, and the hardware digest equals a software SHA-256 computed over the same bytes. Completion is delivered as an interrupt to a registered service routine, so the interrupt path is proven as well as the datapath. The digest comparison is the strong part: copy correctness alone would not show the inline hash engine consumed the same bytes that were copied.

*Test Procedure*:

[arabic]
. Initialise the fabric filter; register the DMA done and error service routines.
. Program the enabled memory range and confirm the configuration lock is open.
. Fill the SRAM source region with random data.
. Program source, destination, size, transfer width and increment modes.
. Start the transfer with the SHA-256 opcode and digest-swap set.

. Read the hardware digest; compute the software digest; compare. Compare source against destination word for word.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-CFG
|The DMA configuration lock is open before programming. A wrong value is counted as an error: the firmware emits `ERROR: CFG_REGWEN not unlocked`, increments its error count, and that count gates the mailbox PASS magic.
|CHK-COMPLETE
|The transfer completes and the interrupt reaches the service routine.
|CHK-DIGEST
|The hardware digest equals an independent software SHA-256 over the same data. The eight hardware digest words are read through the array-indexed accessor `SHA2_DIGEST_0_BASE_ADDR(i)`, so a wrong array stride or a silently renamed register shifts the assembled digest and the `memcmp` below fails.

|CHK-NONVAC
|The software digest is recomputed from the actual SRAM contents on every run and no digest literal exists anywhere in the firmware or the testbench, so the comparison cannot be satisfied by a constant. `rand()` is never seeded, so the byte vector is the same for every seed within one firmware build -- the seed randomises only the clock period -- but it is NOT stable across builds, which is why no digest literal is pinned anywhere in this plan.

[[sep_lcc_lc_state_w1s]]
===== `sep_lcc_lc_state_w1s_*` (six leaves)

*Phase*: 2

*Run mode*: `no_cpu`, real fuse sense

*VIP / Model*: ocah_axi_vip, LCC golden

*Leaves*: `sep_lcc_lc_state_w1s_prod_test`, `sep_lcc_lc_state_w1s_prod_demote_test`, `sep_lcc_lc_state_w1s_rma_sip_test`, `sep_lcc_lc_state_w1s_rma_chiplet_test`, `sep_lcc_lc_state_w1s_prod_end_test`, `sep_lcc_lc_state_w1s_transient_test` — one module, one sensed starting state per leaf, selected by `+lc_start` and staged at t=0 by `cocotb/dv_sim_prestage.py`.

*Objective*: Prove the next lifecycle state computed on the frontdoor shadow write. This is the second writer of the lifecycle state and the stitch walk does not reach it: that walk programs a one-time-programmable bit and re-senses, which never evaluates this logic. The contract is the specification's three rules — write-one-to-set, a don't-care low bit inside each return-material-authorisation state, and the two hardware-ordered token gates — from which the reachable destinations follow.

*Why one leaf per starting state*: the one-time-programmable image is deposited at time zero and a fuse holds its state across every reset, so a test cannot re-sense its way to a different starting state; from one image only a write-one-to-set superset is reachable. Each starting state is therefore its own leaf, with the sensed value read off the device and required to match what the leaf asked for.

*Test Procedure*:

[arabic]
. Sense the leaf's starting state from a real fuse image; require the sensed lifecycle value to be the one requested, and the security-disable override to be inactive so no feature-control check can pass by being forced to all-ones.
. Present the return-material-authorisation tokens the cell needs, and require each to reach a match code before relying on it — an unmatched token would let a gate check pass for the wrong reason.
. Write the lifecycle word write-one-to-set, and require both the differentially encoded lifecycle word and the controller's decoded feature-control output to match the specification-derived golden for the expected next state.
. Re-check the observed step against the transition rules in value form, using the code the device returned rather than the one the test wrote.
. On the demoted leaf, assert both demotion registers first and prove the demotion is visible in feature control before requiring the transition to succeed.
. On the transient leaf, present the token and take no bus write at all; the same rules must apply.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-W1S-NO-CLEAR
|A write of zero to the lifecycle word clears nothing. Write-one-to-set means a bit never returns to 0, so a controller that treated the write as an assignment fails here.
|CHK-GATE-SIP
|The system-in-package bit does not set without a matching token. The write is otherwise identical to the one that succeeds later in the same leaf, so the gate is the only difference between the two outcomes.
|CHK-GATE-CHIP-ORD
|The chiplet bit does not set from the production state even with the chiplet token *already matched*, because the system-in-package state is not yet established. This isolates the ordering requirement from the token requirement — with the token gate open, only the ordering gate can hold.
|CHK-GATE-CHIP-TOK
|The complementary half: from the system-in-package state, the chiplet bit does not set without a chiplet token match.
|CHK-SIP-ADVANCE
|With a matching token the production part advances to the system-in-package state, and feature control decodes the new state. Together with CHK-GATE-SIP this is an allow and a block observed under one image.
|CHK-DEMOTE-OPEN
|Both demotion registers read back asserted AND the decoded feature-control word matches the golden *with demotion applied*. This is what stops CHK-DEMOTE-NO-BLOCK from passing vacuously: a leaf that silently failed to demote would fail this check first.
|CHK-DEMOTE-NO-BLOCK
|The same authorized advance succeeds while both demotion groups are asserted. Demotion is volatile debug state and not a lifecycle term, so a demoted part must transition exactly as a non-demoted one does.
|CHK-RMA-BIT0
|The low bit sets inside the system-in-package state and, on its own leaf, inside the chiplet state. The specification writes these encodings with a don't-care low bit, so this is a move within one state rather than a transition out of it.
|CHK-CHIP-ADVANCE
|With the chiplet token matched and the system-in-package state established, the chiplet bit sets and feature control decodes the chiplet profile.
|CHK-INVALID-REACH
|A write whose result falls outside the named encodings lands there, reached from a state the same leaf advanced into legitimately. Feature control must then read exactly 0 — the fail-closed default. Under the pinned disable vectors no named state decodes to 0, so this discriminates rather than coinciding.
|CHK-INVALID-TERM
|From outside the named set, a write of every lifecycle bit with BOTH tokens matched changes nothing. This is the strongest available form of the end-of-life property: every gate that could open is open, and the state still does not move.
|CHK-PROD-END-INVALID
|From the terminal product state, the reachable destination is outside the named set — the specification's "the only permitted transition is to INVALID", proven rather than assumed.
|CHK-TRANSIENT-INVALID
|The transient return-material-authorisation path applies the same write-one-to-set and token rules with no bus request at all, including when the result falls outside the named set.
|CHK-UPPER-MERGE
|The upper three bytes of the lifecycle word merge as ordinary set-only shadow bytes and do not disturb the lifecycle nibble, and the nibble's special handling does not leak into them. The pattern comes from the run seed, so this is not a fixed-constant check.
|CHK-LEAF
|Per-leaf closing line naming which walk ran, the sensed starting state, and the seed the tokens and upper-byte pattern came from.
|===

[NOTE]
====
The expected next state comes from `lc_state_next` in `cocotb/env/sep_lcc_golden.py`,

the golden states them the same way — a destination table would be a second, weaker

[[sep_irq_ip_to_aggregator_test]]
===== `sep_irq_ip_to_aggregator_test`

*Phase*: 1

*Run mode*: `no_cpu`

*VIP / Model*: ocah_axi_vip

*Objective*: Proves that interrupts owned by the entropy blocks reach the SEP interrupt aggregator on the correct bit, using each block's real interrupt-test register rather than a forced wire. After that walk, one in-window unmapped read through the Secure DMA adapter and one through each HMAC, KMAC and OTBN adapter must complete SLVERR, latch the matching `DMA_BUS_ERR_STATUS` / `PERIPH_BUS_ERR_STATUS` bit, raise aggregator bits 39 and 41, and clear on the matching CLEAR write.

*Test Procedure*:

[arabic]
. For each covered interrupt: clear the test register and the pending state.
. Assert the aggregator bit is low.
. Enable the interrupt and write the real test bit.
. Wait for the matching aggregator bit to assert; confirm the other covered bits stay low.
. Clear the test bit and the pending state; wait for deassertion.
. Confirm both bus-error STATUS registers and aggregator bits 39 and 41 read 0.
. Read the unused word between the last DMA `INTR_SRC_ADDR` and the first `INTR_SRC_WR_VAL`; require SLVERR, exclusive `reg_path_err`, and bit 39.
. Write `DMA_BUS_ERR_CLEAR`; STATUS and bit 39 read 0.
. Read the unused word between the HMAC CSRs and the message FIFO; require SLVERR, exclusive `hmac`, and bit 41. Write `PERIPH_BUS_ERR_CLEAR.hmac`; STATUS and bit 41 read 0.
. Repeat for the KMAC CSR/STATE gap (`kmac`) and the OTBN CSR/IMEM gap (`otbn`).

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-AGG
|All six interrupts propagate to their expected aggregator bit and clear again — baseline-low, assert, isolation and clear all covered. "One-hot" here means one-hot among the six covered bits. Bits outside that set are not compared — and the logged vector shows some of them are legitimately high, so this is a real scope limit rather than a theoretical one.
|CHK-NONVAC
|A non-zero number of AXI transactions was observed, so the run cannot pass having done nothing. This is a transaction floor, not a per-source minimum: no assertion requires that all six sources ran. The six per-source lines are what evidence that.
|CHK-BUSERR-BASE
|`DMA_BUS_ERR_STATUS` and `PERIPH_BUS_ERR_STATUS` read 0, and aggregator bits 39 and 41 read 0, before either fault. A stuck-high latch fails here.
|CHK-BUSERR-DMA
|The DMA hole read completes SLVERR, not DECERR. `DMA_BUS_ERR_STATUS` is exactly `reg_path_err`. Aggregator bit 39 is 1; bits 40 and 41 stay 0.
|CHK-BUSERR-PERIPH
|Each HMAC, KMAC and OTBN hole read completes SLVERR, not DECERR. `PERIPH_BUS_ERR_STATUS` is exactly that block's bit. Aggregator bit 41 is 1; bit 39 stays 0.
|CHK-BUSERR-CLR
|Each matching CLEAR write returns its STATUS word and its aggregator bit to 0. The CLEAR registers are write-only single-pulse fields that always read 0, so their read value is not graded.
|===

*Not claimed*: DMA host-path integrity (`host_path_err` / bit 40) — this leaf does not start a DMA transfer, so the host-adapter checker never sees `a_valid`. AES, CSRNG, EDN and WDT register-bridge bits — those adapter windows are packed to the last register. Lockstep punch-through. Per-block clear isolation: each hole is raised and cleared on its own, so no run holds two peripheral bits at once. The aggregator OR is likewise never driven by more than one source at a time. Persistence across a CPU-only reset, and the rule that a fault arriving in the clear cycle still latches, are unproven. The misaligned-offset and access-control terms of `reg_path_err` are unproven.

*VIP / Model*: ocah_axi_vip, entropy golden

*Objective*: Proves the one `SW_RESET_N` bit that resets ESRC, CSRNG and EDN

*Test Procedure*:

[arabic]

|CHK-TRNG-ISOLATE-ALL

|CHK-TRNG-DECERR

|CHK-TRNG-EXTERNAL

[cols="2,5",options="header"]

|CHK-READ-ALLOWED

|CHK-NONVAC
|Allow and block were both observed under one lifecycle state.
|CHK-SRC-ID
|A non-zero `FILTER_CONFIG.src_id` matches only the external master's `user[3:0]`. The match cells keep r/w-allow gating; the mismatch cell DECERRs with both allow bits set.

|With `allow_burst=0`, a single-beat external read of the scratch window is OKAY (anti-vacuous) and a 2-beat INCR (AxLEN=1) to the same address is DECERR. `traffic_filter.sv` `pass_burst` is not vacuously true.
|CHK-BURST-ALLOW
|With `allow_burst=1` and a programmed window that already spans two 4 KB pages, the same 2-beat INCR is OKAY and returns the staged scratch value. START/END read back as programmed (the same-page 4 KB granule widen does not fire). The granule widen itself is `CHK-PAGE-WIDEN`.
|CHK-BURST-WRITE-DENY
|The write-side `traffic_filter` (`aw.len`) with `allow_burst=0`: a single-beat external write is OKAY and lands; a 2-beat INCR write is DECERR and does not land.
|CHK-BURST-WRITE-ALLOW
|With `allow_burst=1` and the same two-page window, a 2-beat INCR write is OKAY and the poke lands on a CPU-LSU readback. START/END stay the programmed range.
|CHK-BURST-TO-SINGLE
|A filter-allowed 2-beat INCR (AxLEN=1) becomes two AXI-Lite singles on the system-CSR bridge (`u_system_csr_a2l_1`): AR/AW at start and start+4. A denied AxLEN=1 produces zero Lite handshakes (filter before the converter). `hw/sys/sep/doc/fabric.adoc`: convert burst to single.
|CHK-PAGE-WIDEN
|A same-page `allow_burst=1` window grants the whole 4 KB page (`hw/common/axi/axi_filter/doc/index.adoc`: `START_ADDR` rounds down, `END_ADDR` rounds up, `allow_burst` selects 4 KB). The hardware-adjusted `START_ADDR`/`END_ADDR` readback is the setup step showing the rewrite took effect; a CSR mirror is not evidence of what the filter passes.
|CHK-PAGE-BOUND
|The 4 KB grant stops at both page edges. Under a scratch-page grant an access one page below is refused; with that page granted instead it answers OKAY while the scratch address turns DECERR. This is the security contract: 4 KB is the block pitch for the DMA CSR, watchdog and scratch-bank blocks, so a page-crossing grant would reach a neighbouring block.
|CHK-CONFIG-LOCK
|`FILTER_CONFIG.locked` freezes `allow_burst`. Asserting the response alone would not prove the field held, so the readback and the still-granted access are checked with it.
|===

`src_id=0`, plus the source-ID product on entry 0 / window 0, then the

Lite split, then the same-page 4 KB granule, page-bound, and `FILTER_CONFIG.locked`
on entry 15. `CHK-OWNERSHIP` keeps inbound CFG, outbound CFG, the remap banks, and `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE` outside every allow window. WRAP, FIXED and
`AxLEN>1` are not walked: the Lite bridges convert those bursts to singles, so the
filter only ever sees `tx_len==0`.

[cols="2,5",options="header"]
|===
|Checker |Contract

[[sep_locked_field_access_irq_path_test]]
===== `sep_locked_field_access_irq_path_test`

*Phase*: 2

*Bucket*: Mailbox, IRQ, PIC

*Run mode*: `no_cpu`, real fuse sense (no `+skip_fuse_sense`), `LC_PROD`

*VIP / Model*: ocah_axi_vip

*Objective*: Stage the spare field's lock bits in the OTP image (same spare-slot geometry as <<sep_efuse_program_lock_matrix_test>>), sense at `LC_PROD`, then access the *shadow* aperture.

*Test Procedure*:

[arabic]
. Stage the spare field's lock bits in the OTP image (same spare-slot geometry as <<sep_efuse_program_lock_matrix_test>>), sense at `LC_PROD`, then access the *shadow* aperture.
. This is not an OTP program: the program-lock vehicle already owns `PROGRAM_ERR`.
. An unlocked spare in the same image is the negative control.
. Walk write-lock then read-lock every seed — they are two different branches in `efuse_shadow_reg_access_control`.

*Checkers*:

[cols="2,5",options="header"]
|===
|Checker |Contract
|CHK-UNLOCKED
|Unlocked spare write/read never raises `[33]`; readback matches the write.
|CHK-WRITE-LOCK
|Bit [33] during the write, BRESP OKAY, following read equals pre-write, bit [33] low after retire.
|CHK-READ-LOCK
|Bit [33] during the read, RDATA sentinel, OKAY, bit [33] low after retire.
|===
*Datapath facts that decide the checkers*: the lock decision is made in
`efuse_shadow_reg_access_control` (`hw/ip/efuse/rtl/`) from the sensed `LOCKS` /
`LOCKS_SPARE` vector: a write to a write-locked field or a read of a read-locked
field is answered with pslverr low, prdata matching the sentinel, and
`locked_field_access_interrupt_o` high, which aggregates into
`sep_internal_interrupts[33]`. Consequently:

* *The AXI write has no sentinel on BRESP* — APB `prdata` is not a
  write-response field. The write-lock denial proof is `[33]` high during the
  write, BRESP OKAY, then a read of the same field (write-lock does not block
  reads) returning the pre-write value. Do not expect SLVERR; JTAG deny is a
  different path (DECERR plus the same sentinel).
* *A read-lock has no following legal read* — `LOCKS` are OTP W1S, so the field
  stays read-locked. The read itself is the denial proof: RDATA=`0xbadcab1e`,
  OKAY, `[33]` high during the beat.

high. The denial conjunct (unchanged write-lock readback / sentinel on read-lock)
attributes `[33]` to the locked path.

*Not claimed*: end-to-end delivery to the CPU — PIC claim, masking and ISR entry

`secure_tm` matrix is not claimed either. This entry is generate-and-deassert on

[[sep_axi_order_sweep_test]]
===== `sep_axi_order_sweep_test`

*Phase*: 2

*Bucket*: Fabric and remap

*Run mode*: `no_cpu`, `+skip_fuse_sense`

*VIP / Model*: ocah_axi_vip

*Randomization*: RANDCFG — every (register x ordering) cell runs on every seed, and every (ordering x size) cell with it. The seed varies the staged data, the channel separation and the response backpressure, never which cell runs.

*Objective*: AXI write address and write data are independent channels with no ordering requirement between them (IHI 0022 A3.3), so AW-first, W-first and same-cycle are all legal stimulus and each must leave the written value in the addressed register without displacing its neighbour. The ordering is driven by holding the trailing channel until the leading one asserts VALID, and the ordering each cell actually presented is read off the bus and asserted against what was requested. Every block behind the crossbar terminates AXI at its own register adapter, so the contract has to hold at each adapter rather than at one scratch word. The sweep configures all three orderings at every write-safe register and crosses them with the 1/2/4-byte sizes on the scratch words, where a narrow write has no side effect. The narrow cells compare the whole software-usable word against the AXI lane rule; `sep_axi_strobe_window_test` owns the same rule at default timing.

*Test Procedure*:

[arabic]
. Take the register inventory and the exclusion reasons from `sep_reg_bit_bash_seq`: `write_reason() is None` for the no-side-effect blocks, plus `touch_reason() is None` restricted to `TOUCH_BLOCKS` for plain RW storage inside the other major IPs. A second list would let two sweeps disagree about which registers are safe to write.
. Drop the blocks where the access itself would decide the result. `WDT_TIMER` is the one today: aon_timer runs on a clock 1000 times slower than the system clock, so the AXI timeout spans about ten of its edges and whether a round trip fits depends on the phase the access arrives on. A probe there measures CDC latency against the timeout rather than channel delivery. `sep_reg_bit_bash_rand_test` covers that block's storage.
. Prime the register with the complement under its write mask at default timing, and read it back, so a write that never lands reads as the prime rather than looking plausible.
. Apply the cell's timing profile through the VIP master (`AxiTimingProfile`, `ocah_axi_master_config`) to hold AW or W back, write the staged value, and read it back at default timing so the compare tests the write and not the read.
. Read a second register in the same block, write it back with one software-usable bit flipped at default timing, read it again, then re-read the swept register. Deriving the value from the current contents keeps a write that never arrived from reading back correct.
. A shadowed register commits on the second identical write. The profile arms a one-shot release, so it shapes the first write only and the committing second write goes out same-cycle. The ordering under test is the one the register sees first; the commit itself is not an ordered access.

firmware can write plaintext with scrambling on, disable it, and read the raw
stored words back through a legitimate frontdoor. Do not set the key lock until
the final checker — locking is sticky.

*Precondition*: `km_kpv_regfile` has no reset, so power-up is undefined and a
whole-vault "exactly one non-zero" scan is not a contract until the file is
known-zero. Wipe the file as *setup* before the write — that is not a wipe
security checker. Alternatively snapshot every logical word with the scrambler
off and diff the raw scan against that snapshot.

*Checkers (planned)*: the written word round-trips exactly with scrambling
enabled; after disable, exactly one word in the raw scan differs from the
post-wipe (or pre-write) snapshot and that word differs from the plaintext; that
word sits at a different index than the logical one, proving the address tweak;
the same plaintext under a different key stores a different word, proving the
scrambler is actually keyed; and after the key lock the key register reads back
zero while the round-trip still recovers the plaintext.

*Anti-vacuity*: requiring exactly one *new* differing word versus the snapshot is
what makes the confidentiality claim real. A write that never landed gives zero
diffs and fails; a read path stuck at zero gives zero and fails. A bare "stored
differs from plaintext" check would pass in both cases, and a Verilator
X-to-zero default would pass a dirty file that was never written. Round-trip is a
required conjunct, so a scrambler that destroys data cannot pass by looking
scrambled. The plaintext is chosen with mixed nibbles because the substitution is
nibble-wise and a uniform value would weaken the difference signal.

*Not claimed*: the eraser's use of the shared scrambler, the seal and retire
contracts owned by the vault test, and the wipe security contract.

'''''

[[audit]]
=== Anti-Vacuity Failure Classes

Checker contracts in this plan are written against these known ways a check can pass
while the DUT is unable to fail it. Several entries above cite this list.

*An expectation that shares a source with the thing it measures.* A golden must not be
selected by asking the engine which candidate it agrees with. The HMAC software-key
word order is pinned from the IP register specification:
`vendor/lowRISC/opentitan/upstream/hw/ip/hmac/data/hmac.hjson:446-447` states
`key[1023:0] = {KEY0, KEY1, ... , KEY31}`, so `KEY_0` is the most-significant word and
the software path needs no reversal. The RTL agrees (`hmac.sv:219-221` assigns the key
CSRs into the secret-key vector in reverse index order), and that agreement is
corroboration rather than the source: a golden transcribed from the RTL cannot disagree
with the RTL. A two-candidate scan is legitimate only as a failure diagnostic that
separates a word-order regression from a general digest fault.

*Golden compared against golden.* An assert between a result already pinned bit-exact to
its golden and another output of the same model holds with the simulator switched off.
The degenerate case compares list lengths rather than domains — a four-word wrong-mode
golden against an eight-word digest.

*A guard whose own constructor makes it unfalsifiable.* Non-vacuity must not rest on a
relation the configuration builder already guarantees: an unwritten (zero-initialised)
address required to differ from a pattern built as `getrandbits(64) | 1`, or
`start_lo != 0` where the config builds that value as `(random & ~0xFFF) or 0x1000`.

*A stimulus with no fan-out.* Driving a pin that is unread in the configuration under
test and asserting that two observables did not move is a DV-invented scenario, not a
specification claim. `dbg_rstb_i` is routed only into `sep_cpu`, so it has no observable
in a CPU-stub run, and `hw/sys/sep/doc/port_table.adoc` does not require isolation from
system reset.

*A tolerance wider than the signal.* A post-event bound above the count the window
actually reaches passes when the event is ignored. The window must run long enough that
the pre-event count clears the tolerance by a wide margin.

*A check that reads back nothing.* Walking a register through several encodings without
reading it back cannot distinguish a register stuck at its reset value when those
encodings produce byte-identical output for the chosen stimulus.

*Entailed guards.* The absence of a complementary-arm marker, or a deferred line, is not
a checker; the owning test already fails if a forbidden marker appears.

[[known-limitations]]
=== Known Limitations

This table holds two different kinds of item, and the distinction matters when
reading a row: a *hardware* gap or spec-vs-RTL divergence, where the RTL or the
specification is expected to change; and a *firmware* constraint, where the
hardware is correct as built and software must program it correctly. A firmware
constraint is not an open defect.

[cols="2,4",options="header"]
|===
|Topic |Contract

|Inbound CFG allow-list (firmware constraint)
|Hardware does not hard-block allow-listing the inbound-filter CFG window, outbound CFG, the remap banks, or `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`, and is correct as built: the filter applies the rules it is given. Firmware must keep those CSRs outside every allow window — allow-listing them is a programming error, not a hardware defect, and nothing is expected to change in the RTL. The suite proves ownership under correct programming (`CHK-OWNERSHIP`).

|Routed-but-reserved spans (specification)
|`sep_axi_map_refuse_test` drives only reserved addresses the crossbar does not route. An address the crossbar routes but `memory_map.adoc` marks `_RSV_` is counted as a skip and reported by `MAP-AUDIT`, not asserted: whether the fabric must refuse a routed reserved span is an open specification question, and `expect_error` would settle it by the back door. A fabric that answers OKAY there therefore passes this vehicle.

|Dead-space per-beat refusal on writes (AXI)
|Read bursts are proven per beat: the bus monitor keeps each beat's `RRESP` in order, so `CHK-DEADSPACE-BEAT` can name the beat that answered. Write bursts cannot be, and no tooling will change it — AXI returns one `BRESP` for a whole write burst, so a write burst that refused only its tail is indistinguishable from one that refused every beat. The write contract stays at burst granularity: the burst is refused and no live register moves.

|Dead-space refusal flavour (specification)
|`memory_map.adoc` names DECERR for the reserved remainder inside an aperture. `spi_controller` refuses a dead-space write with SLVERR. The access is refused either way, which is the contract `sep_fabric_deadspace_decode_test` asserts, so the flavour is reported as `DEADSPACE-FLAVOUR` for the design owner and is not failed. Which error responses are permitted is the open question.

|Isolated write answers SLVERR, not DECERR (hardware)
|While a crypto domain is held in software reset, an in-window read of that domain returns DECERR and carries the isolate's own `DecErrData` literal, so the read is genuinely terminated by `axi_lite_isolate`. An in-window *write* to the same aperture, same beat shape, same window, returns SLVERR. `axi_lite_isolate` emits only DECERR, on both the B and R channels, and SLVERR appears nowhere on that path, so the write was answered downstream of the isolate — the write leg was not isolated while the read leg was. `sep_crypto_per_ip_reset_isolation_test` fails on this at `CHK-ISOLATE-WR` and is left failing: the expected response set is not widened to accept SLVERR, and it is not converted to an expected failure. The finding is reported against the issue auditing the crypto AXI isolation and reset sequencing.

|OSS hygiene exclusions
|No licensed/proprietary IP in the build. Bender targets stay `sep` / `sep_el2` / `sep_wrapper` only.

|Verilator covergroups
|SystemVerilog covergroups are not available under Verilator. Feature coverage is the iconic scorecard; RTL code coverage is collected separately and thresholded in Phase 3.

|ROM-FW ownership
|Boot-ROM firmware contracts are out of this VPLAN (separate owner / `rom_fw` class).

|Signed-off observation probes
|A small set of TB observation/inject ports is documented with the DV house rules. New backdoors need explicit sign-off.
|Behavioural OTP array
|The array behind the fuse-command interface is a simulation-only behavioural bank, not an OTP macro. Two properties the eFuse programming entries appear to establish are properties of that model rather than of hardware: write-one-to-set additivity is OR-only by construction, so a bank that overwrote instead of OR-ing cannot be represented and no-clobber is not a failable contract; and persistence across cold reset comes from the model having no reset on its storage. What is proven against real logic is that each program reached its addressed bit through the real programming path, and that the sense FSM re-reads the array after reset with the shadow tracking it.

|JTAG MMR token-block access
|`hw/sys/sep/doc/periphs.adoc` allows the MMR token block and denies the shadow, the program/read interface, and the SHIM. No checker claims DECERR on the MMR token block. Inbound ownership under correct programming (CFG, outbound CFG, remap banks, and region CSRs outside every allow window) is owned by `sep_fabric_inbound_filter_rule_matrix_test` `CHK-OWNERSHIP`.
|RTL assertions are backend-dependent
|What participates depends on the backend. Under Verilator, `prim_assert.sv`, `abr_prim_assert.sv` and `ocah_assert.svh` all gate their macros on `VERILATOR`, so design and vendored-IP SVA — the `ocah_axi_sva` protocol bind included — expand to nothing. Under VCS those macros are live. The shared native profile also defines `COMMON_CELLS_ASSERTS_OFF`, so the PULP `common_cells` inline assertions are off on every backend. Where a checker proves a property, that checker is the whole of the proof on Verilator; no assertion layer sits underneath it there.

|Entropy-pool interrupt numbering (spec)
|`hw/sys/sep/doc/crypto.adoc` numbers the two entropy-pool interrupts one lower than the canonical table in `hw/sys/sep/doc/interrupts.adoc`. PIC source IDs are 1-based, so aggregation index 36/37 is PIC source 37/38; firmware following `crypto.adoc` would enable and mask the wrong two sources. No checker asserts this today; do not XFAIL it.

|CPU reset-vector TDR (spec)
|`hw/sys/sep/doc/cpu.adoc` documents a CPU reset-vector TDR selected by a JTAG opcode. The vendored tap implements no such register — the vector reaches the CPU through a direct wrapper input. The testbench shifts that opcode on every CPU-boot run and the sequence is inert: stimulus that reads as coverage and cannot fail. Remove it or give the claim an owner.

|Scratch bank register count (spec vs RTL)
|`hw/sys/sep/doc/cpu.adoc` requires "two sets of 16 x 32-bit scratch register banks". `hw/sys/sep/regs/blocks/sep_scratch/sep_scratch.rdl` declares `SCRATCH[8]`, so each bank implements eight registers, not sixteen. The reset-domain behaviour of the banks that exist is proven; the count is not, and no test asserts it. This row is the record of the difference, not a claimed contract. Do not XFAIL.

|AP/STEE output-remap attributes and pass-through (spec)
|`hw/sys/sep/doc/fabric.adoc` gives the AP/STEE remappers a cacheable attribute and says unprogrammed regions are transparent pass-throughs. `hw/common/axi/output_remap/rtl/output_remap.sv` has neither a valid bit nor a cacheable bit and rewrites the address unconditionally, so an unprogrammed region zeroes the upper address bits instead of passing through. The vehicle on this bank is `sep_fabric_output_remap_datapath_proxy_test`, which proves a programmed window translates and that a beat outside it is refused; the pass-through behaviour of an unprogrammed region has no checker, so this row is the record of the gap and not a claimed contract. Do not XFAIL.

This row is about the AP/STEE bank only. The local-master aliaser is a different block: `hw/common/axi/axi_alias_remap/rtl/axi_alias_remap.sv` carries `region_valid` per region, drives the outbound cache bits from the region on a hit, and passes an address through unchanged when no region hits. `sep_fabric_local_alias_datapath_test` covers the enable with `CHK-VALID-GATE`.

|Class 2 scan-root count (spec)
|`hw/sys/sep/doc/attack_countermeasures.adoc` states "exactly 10" Class 2 scan roots. The RTL instantiates an eleventh on the entropy-pool EDN leg that is absent from the list, and nothing lints the manifest against the RTL. That manifest is the sole input deciding what is never scan-dumpable.

|`sec_dis` is not forced
|No entry forces `sec_dis`. The LC→`feat_ctrl` stitch stays an end-to-end path; a forced override is not an acceptable substitute for it.

|Checkers sharing one pass line
|Three firmware tests evaluate several conditions and print a single pass line, so their rows do not fail independently of each other: `sep_spi_ot_dma_rx_test` (3 of 3 checkers), `sep_dma_cpu_contention_test` (5 of 5), `sep_mailbox_plic_test` (4 of 4). Firmware counters still gate the verdict.

|Lifecycle codes with no owner
|Closed for the encodings, narrowed for the mechanism. `sep_efuse_lcc_lc_state_stitch_test` walks four of the seven named codes on the OTP-program path (`LC_TEST_DEV`, `LC_PROD`, `LC_RMA_SIP_1`, `LC_RMA_CHIP_1`); the `LC_STATE` write-1-to-set leaves add `LC_RMA_SIP_0`, `LC_RMA_CHIP_0` and `LC_PROD_END` as sensed starting states with a `FEAT_CTRL` claim on each, plus two codes outside the named set. What remains unowned is the *pairing*: `LC_RMA_SIP_0`, `LC_RMA_CHIP_0` and `LC_PROD_END` are sensed but never reached by programming a fuse bit, because the OTP image is a t=0 deposit and a fuse survives reset — from a given image only a W1S superset is reachable in one leaf.
