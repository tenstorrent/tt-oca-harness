[[sep-coverage-stimulus-plan]]
== SEP Code-Coverage Stimulus Plan

=== Purpose and scope

This plan lists stimulus that reaches SEP logic which the current test suite
never exercises. It is a CODE-COVERAGE plan, not a verification plan. The
verification contracts stay in link:SEP_VPLAN.adoc[SEP_VPLAN].

Every test in this plan is STIMULUS ONLY:

* No checker, no scoreboard, no assertion is added by these tests.
* A test in this plan PASSES when the stimulus completes without a bus error.
  It asserts no contract, so it cannot fail a design behaviour.
* The single requirement is that the target logic is REACHABLE BY FRONTDOOR --
  legal AXI or AXI-Lite transactions, legal register programming, or KM
  firmware running from ROM. No backdoor writes. No hierarchical forces.

Read that literally when auditing this suite. A `sep_cov_*` test that passes is
evidence that a path was driven, and evidence of nothing else. Do not cite one
as proof that a behaviour is correct, and do not count one toward a VPLAN row.

=== Naming

Coverage-driven tests take the prefix `sep_cov_`:

  sep_cov_<ip>_<behaviour>_test

The `sep_cov_` prefix sorts the whole suite together and marks it as
stimulus-only at a glance. Each test carries the same statement in its
docstring and in its testlist comment.

=== Baseline

Measurements below come from the merged VCS run
`build/runs/20260919_114453__vcs__all`. Per-module line and toggle counts do
not depend on the scope epoch, so they hold against any epoch. The headline
SCORE does depend on it: this plan is measured against epoch
`sep-code-cov-v2`, whose baseline SCORE is 55.08 (LINE 54.58, COND 55.85,
TOGGLE 50.66, FSM 23.90, BRANCH 53.83, ASSERT 48.18).

The design-wide shape is the same in every IP below: LINE is largely closed and
TOGGLE is not. Most SEP modules execute every line while their bus fields hold
one value for the whole simulation.

Two causes account for most of it:

. No master in the design issues a multi-beat burst. `ar.len` and `aw.len[7:0]`
  are fully untoggled on every port of both crossbars.
. Register banks are programmed at one index, or with one value, so the
  replicated slots and the wide address fields stay at reset.

=== Environment changes this plan needs

. `env/sep_axi_agent.py` pins `prot` to `None`. The OCAH VIP already accepts a
  `prot` argument (`ocah_axi_master_sequence.py:501-506`), so the agent needs
  one item field to pass it through. This unlocks `AxPROT[0]` and `AxPROT[2]`.
. The AXI sequences leave `burst` unset and drive `AxLEN=0`. They need
  multi-beat `BURST_INCR` support, and `BURST_FIXED` where the slave allows it.

=== SEP system fabric, system CSR and crypto interconnect

Scope: `hw/sys/sep/rtl/sep_system_peripherals/rtl/sep_system_csr.sv`,
`sep_system_peripherals.sv`, `hw/sys/sep/rtl/sep_local_axi_xbar.sv`,
`hw/sys/sep/rtl/crossbars/sep_system_peripherals_xbar.sv`,
`hw/sys/sep/rtl/sep_crypto_axi_interconnect.sv` and the crypto wrappers.
Source of the numbers: the merged VCS report of run
`20260919_114453__vcs__all` (96 tests), `cov/report/modinfo.txt`.

Line coverage is not the gap. `sep_system_csr` is 43/43 lines, `hmac_wrapper`,
`kmac_wrapper`, `sep_dma_wrap`, `sep_crypto_otbn_wrapper` and
`sep_crypto_abr_wrapper` are all 100% line. The mass is toggle:

* `sep_system_csr` — 34.95% bits (49,780 of 142,422); 4,737 signals, 1,573
  toggled.
* `sep_system_peripherals` — 14.96% (252 of 1,685 signals).
* `sep_local_axi_xbar` — 22.17% (300 of 1,353).
* `sep_system_peripherals_xbar` — 29.87% (158 of 529).
* `sep_crypto_axi_interconnect` — 40.68% (711 of 1,748).
* `sep_abr_kv_shim` — 17.52% (24 of 137).

The shape of the gap is uniform. All 48 filter slots and all 48 remap regions
elaborate and every slot receives traffic — `outbound_filter_axil_reqs[k]` shows
9 toggled signals for every k in 0..31 — but the data that is written is sparse.
`seq_lib/sep_fabric_csr_bank_seq.py` (`bank_field_walk`) writes an index-derived
pattern `(bank<<22)|((idx+1)<<16)|((word+1)<<12)` into the low 32-bit word only.
The result is that `outbound_filter_ctrl_o[k].FILTER_CONFIG.read_allowed`,
`write_allowed`, `entry_enabled`, `allow_ns`, `allow_burst` and `locked` never
toggle for any k, `START_ADDR`/`END_ADDR` bits [55:24] never toggle, and the
per-slot lock error slave (`err_slv`, `locked_reg_req`) is exercised on two
slots per seed. The proposals below extend that sweep; they do not replace it.

The second shape is AXI attributes. No master in the design ever issues a
multi-beat burst: `ar.len[7:0]` and `aw.len[7:0]` are fully untoggled on every
master and slave port of both crossbars. `AxPROT[0]` and `AxPROT[2]` are never
driven, `AxCACHE[3:2]` is never set, and `AxBURST[1]` (WRAP) is never used.

==== Not frontdoor reachable

`AxCACHE[3:2]` beyond the remap case, `AxQOS[3:0]`, `AxREGION[3:1]`, `AxLOCK` and
`AxUSER[11:4]`::
The OCAH AXI master VIP wrapper passes only `burst`, `prot`, `size`, `id` and
`user` to the driver (`ocah_axi_master_sequence.py:501-506`). These attributes
are legal AXI, but no sequence can drive them until the VIP wrapper exposes
them. They are not reachable with the stimulus API as it stands.

`aw.atop[5:0]` on every crossbar port::
AXI atomic operations. The VIP has no atomic API, and
`sep_system_peripherals.sv:214-216` instantiates the demux with
`AtopSupport(1'b0)`, so the fabric does not carry them.

`{aw,ar}.size[2]` on every 64-bit port::
`size[2]` encodes a beat of 16 bytes or more. The bus is 64-bit, so the largest
legal `AxSIZE` is 3 and bit 2 cannot be set by a legal transaction.

`dbg_req_i` / `dbg_resp_o` on `sep_local_axi_xbar` (32 + 13 signals, zero
covered)::
The debug master port is driven by the RISC-V debug module, not by a test
master. It needs `+ENABLE_SEP_CPU_AXI_VIP` and a debug-master sequence. That is
a separate environment change, not a register write, so it is out of scope for a
stimulus-only test; listed here so it is not counted as an ordinary hole.

`otbn_otp_key_req` / `otbn_otp_key_rsp` in `sep_crypto_otbn_wrapper` (6
signals)::
The OTP scrambling-key handshake is a sideband interface to an OTP key
provider. No register in the OCAH hierarchy starts it, so there is no legal
frontdoor path.

`scan_mode_i`, `test_en_i`, `test_i`, `lsio_trigger_i`::
DFT and trigger pins tied off at the top level. No frontdoor path.

`alert_rx_i` on the crypto wrappers (3..6 signals each)::
The alert receiver inputs come from the alert handler ping mechanism. The SEP
open tree has no alert-handler frontdoor to drive a ping, so the `ping_p`/`ping_n`
bits stay quiet.

Anomaly, not a proposal::
`key_csr_hwif_out.KEY_SHARE0[*]` and `KEY_SHARE1[*]` in `hmac_wrapper`,
`kmac_wrapper` and `sep_crypto_otbn_wrapper` show zero toggle in this merge,
although `sep_km_hmac_sideload_kat_test`, `sep_km_kmac_sideload_kat_test` and
`sep_km_otbn_sideload_kat_test` all PASS in the same run and are in the merged
test list. `KEY_CTRL.key_valid` does toggle. Either the key words the KATs
sideload leave those bits at their reset value, or the toggle data for those
instances did not reach the merge. Resolve this before the
`sep_cov_crypto_key_share_walk_test` estimate above is relied on.
=== AXI fabric

The pulp-platform AXI fabric in SEP scores 1232/2041 lines (60.4%) and
75128/218280 toggle bits (34.4%). The gap is one shape, not one block: every
AXI master in the current suite drives single-beat INCR only. `cocotb/seq_lib/`
confirms it -- `sep_sram_breadth_seq.py` states the SRAM port is driven
AWLEN=0/ARLEN=0 only, `sep_axi_partial_lane_read_seq.py` sweeps AxSIZE 0..2 at
AxLEN=0, and `sep_axi_access_seq.py` leaves `burst` at `None` for all callers
except the inbound-filter tests. No test drives AxLEN>0, BURST_FIXED or
BURST_WRAP anywhere in SEP.

Effect on the width converters. `axi_dw_downsizer` has two parameter groups.
The AxiMaxReads=8 group (9 instances: the 8 crypto/eFuse converters plus the
DMA register converter) is 483/1256 lines, 38.46%, with per-instance line
scores from 18.31 (TRNG) to 37.98 (HMAC). The AxiMaxReads=16 group (sep_io,
sep_wdt) is 542/2400, 22.58%. 87 lines of the crypto group are dead in *every*
replicate of *every* instance.

Reachability of the crypto downsizers. They are 64-bit slave to 32-bit master,
behind one `axi_demux` slave port in `sep_crypto_axi_interconnect.sv:236-266`,
fed by `sep_crypto_axi_req_i`. `sep.sv:427` drives that port from
`sep_local_axi_xbar_wrapper`. The inbound external master is slave port 4 of
that same crossbar (`sep_local_axi_xbar.sv:255`, `sep.sv:414`), and
`sep_local_axi_xbar_pkg.sv:217-223` gives input 4 the connectivity vector
`10'b1110101110`; output index 5 is sep_crypto, and that bit is 1. The inbound
port data width is 64 bits end to end (`sep_pkg.sv:22` and `sep_pkg.sv:623`).
So the crypto downsizers are inbound-reachable with 64-bit bursts. They are
not CPU-only.

==== Not frontdoor reachable

*`axi_atop_filter` filtering path, lines 139-326 (57 of 110 lines, 30
instances).* Every one of these lines needs `aw.atop != 0`. The SEP fabric is
built ATOPs=0 throughout: `sep_local_axi_xbar.sv:266`,
`sep_crypto_axi_interconnect.sv:275`, `sep_crypto.sv:560` and `sep_cpu.sv:596`.
With ATOPs=0 the fabric carries an `assume property` that the atop field is
zero -- `axi_err_slv.sv:253-254` and `axi_demux_simple.sv:536-540`. The
testbench also ties the field: `tb/tb_top.sv:950` builds the inbound request
with `'{default: '0}`, and `tb/tb_top.sv:879` does the same for the CPU-LSU
splice. Removing those ties is a testbench change, not a backdoor, and would be

== Not legal-consume, so not stimulus: waiver candidates

A path the design DECLARES illegal cannot be reached by legal-consume
stimulus. Driving one is out-of-spec usage, not coverage work, so these belong
in `cov/config/vcs/` as structural exclusions rather than in the plan above.

The discriminator is cheap: **when an assertion or an assume guards the arm,
the design is telling you the arm is unreachable.** All three items below carry
one.

* **`axi_atop_filter` active path.** The fabric is `ATOPs=0`
  (`sep_local_axi_xbar.sv:266`, `sep_crypto_axi_interconnect.sv:275`,
  `sep_crypto.sv:560`, `sep_cpu.sv:596`) and carries
  `assume property aw.atop=='0` (`axi_err_slv.sv:253`,
  `axi_demux_simple.sv:536-540`). No conforming master issues an atomic.
* **`km_crc_engine` default mode arms.** `picorv32_pcpi_crc.sv:88-95` decodes
  three encodings and defaults a fourth to `CRC_MODE_32C_WORD`, so
  `insn_recognized` stays low and the core traps; `mode_i` is never `2'b11`.
  Guarded by `km_crc_engine.sv:135 LegalModeOnStart_A`.
* **`drbg_axil64_lane_adapter` unsupported-access arms.** The block enforces
  single-lane 32-bit semantics (header, `:16-17`): `read_supported` requires
  `addr[1:0]==2'b00`, `write_supported` requires strobe `0x0F` or `0xF0`. A
  test that drives a sub-word or unaligned access is issuing a shape the spec
  refuses. `sep_cov_drbg_lane_adapter_unsupported_test` was written and then
  withdrawn for this reason.

== What a sep_cov_ test still catches

These leaves add no checker, but they are not blind. A `sep_cov_*` test fails
on:

* an unexpected AXI error response (the agent fails any ungraded non-OKAY);
* a transaction that never retires (the VIP raises on timeout);
* any RTL assertion the stimulus provokes -- legal stimulus must not fire one,
  and if it does, that is a finding to investigate, not a result to waive;
* a bring-up failure, and for the KM leaves a ROM that never boots
  (`wait_km_cov_done` requires the 0xC0 magic in `km_sram_word0_o`).

`allow_error` marks the few legal accesses the design answers with an error by
design -- an unpopulated leg terminated by an error slave, an empty-FIFO read.
It tolerates the response and asserts nothing about it. It does NOT cover a
wedge: a tolerated error is still a response.
