[[smu-dv-testbench-architecture]]
== SMU OCAH Open-Source Testbench Architecture

=== Overview

The SMU open-source environment is a PyUVM-on-cocotb testbench driven by
`tools/dv/run_dv.py`. `hw/sys/smu/dv/README.md` owns which simulators run
which groups and why; this chapter describes the bench.

One DUT view lives in this DV root:

[cols=",,",options="header",]
|===
|Launch name |HDL top |What it is for
|`--dut smu` (alias `smu_wrapper`) |`tb/tb_wrapper_top.sv` (`smu_wrapper_uvm_top`) |
`hw/top/smu_wrapper.sv` with production pins, in one compile profile,
`compile_smu_chiplet` (SEP=1). The SMU regression (`testlists/all.toml`)
|===

Logs carry `DUT_TAG=WRAPPER`. The SEP=0 composition (`smu #(.SEP(0))`) is
not elaborated by this package; `hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc`
holds the names that need it.

=== Directory Structure

`hw/sys/smu/dv/README.md` owns the layout: its table lists every directory
and top-level file under `dv/` and says why each of the additions to the
shared DV directory set is held here. This chapter names paths only where it
describes the component behind them.

=== Environment Components

`SmuEnv` (`cocotb/env/smu_env.py`) builds the
scoreboard and reads `SmuEnvCfg` out of the PyUVM `ConfigDB`; the JTAG and AXI
agents are created on demand by the sequences that need them, against
`cocotb.top`, rather than being instantiated for every test. The one agent that
exists from time zero is the responder of the outbound SMN AXI4 boundary:
`tb_wrapper_top.sv` places the `ext_out` request/response structs, behind its
`axi_cut`, on the `ocah_axi_if` instance `u_axi_out_if` through
`ocah_axi_struct_bridge`; `smu_base_test.bring_up` binds the shared
`OcahAxiSlaveAgent` to that instance before the clocks start and publishes its
slave sequence as `SmuEnvCfg.axi_out_mem` (backdoor reads and writes of what
the SMU wrote out, one-shot SLVERR/DECERR injection, bounded READY stalls).

[cols=",",options="header",]
|===
|Component |Role
|`SmuEnvCfg` |Clock periods (`ref`, `smu`, `periph`, `jtag`), idle TCK count and
post-reset settle cycles, randomised from the run seed; the outbound SMN
geometry, memory span, and slave sequence (`axi_out_mem`)
|`SmuScoreboard` |Every check in the suite goes through it; see
<<smu-checking-strategy,Checking Strategy>>
|`smu_evidence_map.py` |Per-testcase `(CHK_ID, TOKEN, EXPECT)` token contracts,
plus the `UNMAPPED_TESTS` declarations for testcases that run without rows
|`smu_fcov.py` |Scenario-intent coverage bins, hit per test
|===

=== Clock and Reset Strategy

`smu_base_test.bring_up()` starts `clk_smu_i`, `clk_ref_i`, `clk_periph_i` and
the JTAG clock at the periods `SmuEnvCfg` derived from the seed, then releases
the resets and waits `post_reset_settle_cycles`.

Clocks must be scheduled with `cocotb.start_soon(Clock(...).start())`. A bare
`.start()` returns a coroutine nobody awaits: every clock stays dead, the
simulation never advances, and the test ends early looking like a fast pass.

Timing is the randomised axis of this environment. `--seed N` reaches the
sequences as `RANDOM_SEED`, `SmuEnvCfg.randomize_timing(seed)` turns it into
clock periods and settle counts, and the chosen values are logged at the start
of every run.

=== Stimulus Strategy

Sequences drive the DUT through its real pins and buses. One enrolled force
exists, `+esrc_noise_force` on the twelve ESRC raw-noise lanes of three
SEP=1 leaves; it and every other stand-in on a proof path (the fuse-sense
skip, the `abr_reg.sv` waiver, the scan-chain loopbacks, the `prim_sync`
stand-ins, the eFuse models) have a six-field entry in the *Bench stand-ins
and exceptions* section of
`hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc`. A scenario that needs a
force or deposit outside that record is not reportable as PASS and is
classified OUT in the same document.

[[smu-checking-strategy]]
=== Checking Strategy

`SmuScoreboard` enforces three things, and a test cannot opt out of any of
them:

. *No vacuous PASS.* `check_phase` raises if zero checks executed. A test that
  drives stimulus but never compares anything fails.
. *No invented checkboxes.* The base test
  (`cocotb_wrapper/tests/smu_base_test.py`)
  calls `bind_testcase` before bring-up and `prove_mapped_features()` after
  the scenario for every leaf that builds an `SmuScoreboard`
  (`use_shared_env`). The call requires that every TOKEN mapped to the
  testcase in `smu_evidence_map.py` was logged by an `expect_*` call that
  passed; tokens cannot be claimed after seeing a green path. A
  scoreboard-bearing testcase with no mapped rows must be declared in
  `UNMAPPED_TESTS` with the reason, and the gate logs the declaration instead
  of failing; an undeclared row-less testcase fails here. A leaf that builds
  no `SmuScoreboard` -- the firmware terminal-loop leaves, the two smokes, the
  elaboration leaves -- is not gated: the base test logs one
  `EVIDENCE MAP GATE SKIPPED` line naming it, and its verdict is the
  sequence's own raise or its own scoreboard. What this does *not* establish is
  the EXPECT column: it is free-text contract wording, nothing compares an
  observed value against it, and the per-row `EVIDENCE TOKEN SEEN` line says
  only that the token was carried by a passing check. Each row prints its
  binding -- `evidence-arg` when a caller named the token outright,
  `check-name-substring` when the token was matched against the check's name
  -- and the rows in the second class are collected into an
  `EVIDENCE BINDING WEAK` warning.
. *Traceable evidence.* Each satisfied check logs `EVIDENCE: <TOKEN>`, and the
  run ends with an `EVIDENCE_SUMMARY` line. `CHK-NONVAC` is emitted by
  `check_phase` itself once the check count is non-zero, so the non-vacuity
  proof is in the log like any other token.

`expect_eq` and `expect_true` are the only two check primitives; both take an
optional `evidence=` argument naming the TOKEN they prove.

[[sep-processor-state-monitor]]
=== SEP Processor-State Monitoring (wrapper)

The wrapper's firmware leaves boot real SEP images, so every wrapper test
builds `cocotb_wrapper/env/smu_sep_cpu_trace_monitor.py`, a passive
`uvm_component` that self-idles unless `+sep_itcm_hex` names a SEP image. It is
the wrapper realization of the SEP bench's `env/sep_cpu_trace_monitor.py` and
reconstructs the same processor state.

==== Trace source

`tb/tb_wrapper_top.sv` exports the complete VeeR EL2 retirement record
(`el2_trace_pkt_t`) as ports: `sep_trace_valid_o`, `sep_pc_o`,
`sep_trace_insn_o`, `sep_trace_exc_o`, `sep_trace_ecause_o`,
`sep_trace_interrupt_o`, and `sep_trace_tval_o`, all masked to zero while
`sep_reset_n_o` is low (a four-state simulator leaves the struct at X until the
SMC arm firmware releases the SEP). The sticky fetch-window detectors
(`sep_boot_rom_fetch_seen_o`, `sep_iccm_fetch_seen_o`) stay in hardware because
the boot-ROM trampoline retires before any Python loop samples; the monitor owns
the retirement tally.

==== What the monitor reconstructs

PC history:: every retirement feeds a count, a distinct-PC set (the SEP boot
  scoreboard's liveness evidence), and a 512-entry ring of the most recent
  retirements.
Shadow call stack:: retired RV32IMC encodings are decoded for linking calls
  (`jal`/`jalr`/`c.jal`/`c.jalr` through ra/t0), returns (`jalr`/`c.jr` through
  ra/t0), and `mret`. Exception-flagged retirements push a synthetic trap frame
  carrying ecause/interrupt/tval; `mret` unwinds it. A SEP reset flushes the
  stack while history and tallies survive.
Trap records:: every exception retirement is kept with its cycle, PC, decoded
  mcause name, and tval.
Hang watch:: after the first retirement, a 20k-cycle retirement-free gap out of
  reset logs a one-shot warning with a full dump. Diagnostic only — `wfi` and the
  firmware's terminal loops are legitimate.

Reconstruction hiccups (pop of an empty stack, depth overflow) are tallied as
resync notes and logged, never failed; pass/fail judgement stays with the
sequences and `SmuSepBootScoreboard`.

==== Symbolization

`smu_base_test` feeds the monitor the staged `nm -B -n` listing of the booted
image: `+sep_sym` names it, otherwise the `+sep_itcm_hex` stem selects
`<stem>.tcm.sym` (SEP firmware engine) or `<stem>.sym` (`fw/build_firmware.py`).
`seq_lib/sep_fw_common.py` parses it with weak entry points included, so
picolibc functions carry their own names in a backtrace. A missing listing
degrades to numeric PCs and never fails a test.

==== Output

`SmuSepBootScoreboard` takes its retirement count and distinct-PC evidence from
the monitor. A scenario that raises ends with the monitor's symbolized call
stack, trap records, and recent-PC tail at error level ahead of the assertion; a
passing run logs the same summary at info level in `report_phase`.
`+sep_trace_log` streams every retirement (cycle, PC, encoding, symbol) to
`sep_trace.log` in the run directory.

=== Coverage Strategy

`SMU_FCOV.adoc` owns coverage intent: the metric choice, the `cov/sv`
cover-property modules, and what the plan may claim from a database. Verilator
does not compile SystemVerilog covergroups, so `smu_fcov.py` records
scenario intent Python-side -- `run_phase` marks the bins a testcase claims
before the scoreboard checks -- and that table is not coverage.

=== Open-Source BFM Policy

[cols=",",options="header",]
|===
|Interface / Protocol |Open-source replacement
|Primary JTAG TAP |`ocah_jtag_vip`
|External SMN AXI4 |`ocah_axi_vip`: `OcahAxiSlaveAgent` on the outbound
boundary (struct port bridged by `ocah_axi_struct_bridge`), master on the
inbound pins
|SMC OTP AXI-Lite over JTAG2AXI |`ocah_axi_vip` AXI-Lite wrappers
|SMC scratch / mailbox |Backdoor read plus cocotb polling
|Cross-trigger / iJTAG |product-pin stimulus from the sequences; every CT_Req_out pad
sits on an `ocah_open_drain_bus` shared wire (private or the group the pads in
`tb_xtrig_ctp_wire_group` share), resting at the board pull of the port's INVERT sense; no
dedicated VIP otherwise
|SMC and SEP eFuse / OTP |`efuse_interface_shim` + `efuse_bank_model`, instantiated by
`hw/top/smc_ip_integration.sv` and `hw/top/sep_ip_integration.sv` inside the DUT
compile (a model in the product composition, not a testbench component). Shadow
registers are preloaded under `+skip_fuse_sense`
|BSR / STAP / DFD host scan chains |testbench loopback of `scan_out` to `scan_in`
(`tb/tb_wrapper_top.sv`, all five host chains and the I/O and extra STAP TDO-to-TDI returns)
|CDC synchronisers on Verilator |`prim_sync3` stand-in from
`hw/sys/smc/dv/tb/verilator_stubs/`, listed in `[build].stubs`
|===

The last three rows are stand-ins on a proof path; their scope and approval
fields are the *Bench stand-ins and exceptions* entries in
`hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc`.

=== Testlists

`testlists/all.toml` holds the leaf entries — one `[[tests]]` table per test,
with its module, tags and timeout — and is the one root `smu_sim_cfg.toml`
selects; the groups it declares, and what each group is for, are the
*Regression Groups* section of `SMU_VPLAN.adoc`. A test is selectable by its
own name or by any group it belongs to.

Names classified deferred or OUT are catalogued in
`hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc`; none of them is enrolled and
none is reportable as a PASS.
