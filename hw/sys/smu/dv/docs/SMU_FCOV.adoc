[[smu-dv-functional-coverage-plan]]
== SMU OCAH Open-Source Functional Coverage Plan

=== Overview

This plan covers the legal operating modes of the SMU wrapper that the `all`
regression walks at the wrapper boundary: reset and boot sequencing, the
address map and the inbound fabric, the debug bridges, the lifecycle
broadcast, cross-trigger and clock-stop, and the external ports. It is the
functional-coverage contract of the open-source SMU testbench.

The contract is carried by ten passive modules under `cov/sv/`, one instance
each in `tb/tb_wrapper_top.sv`. Each module has two layers: labelled
`cover property` points declared through `OCAH_FCOV_COVER`, which every
simulator compiles and which land in the runner's `user` family, and SV
covergroups under `ifndef VERILATOR`, which only the commercial simulators
compile and which urg reports as the GROUP score.

Feature checkers stay on the VPLAN scorecard. A hit here says the wrapper
presented the event at its boundary; it is not the checker's claim, which
compares a golden.

vendored I3C core declares under `u_dut` leave through the group exclusion
file (`cov/config/vcs/README.md`, "Covergroups from vendored RTL").

=== Two-Phase Scope

[cols="1,4",options="header",]
|===
|Phase |Scope
|*Phase 1* |The points and bins below: legal cells of the wrapper's behaviour that a named `all` test walks, or that a test added in the same change walks.
|*Phase 2* |Error and fault paths the bench cannot produce, and encodings the specification makes illegal. Named in <<smu-fcov-phase2>>. Not compiled.
|===

A point enters Phase 1 only with a test that walks it. A point that no legal
configuration of this bench reaches is not carried in the collected
population as an accepted hole: it is Phase 2, and its reason and what would
bring it back are recorded there.

=== Collection

==== Metric choice

SMU is an integration level: `hw/sys/smu/rtl/smu.sv` wires SMC, DTP, SEP and
the AXI crossbar together and carries almost no procedural logic. An
unscoped line, branch or expression build produces on the order of 1.3
million sites, every one of them outside SMU, so those families cannot grade
it. Toggle instruments nets, which is what an integration level owns; it is
measured on the VCS flow over the SMU's own logic (`cov/config/vcs/README.md`).
The `cov/sv` points and covergroups are the functional half beside it. Each
subsystem grades its own internals in its own DV package.

==== What the Verilator database holds

`cov/config/verilator/smu_wrapper_cov_scope.vlt` drops everything the wrapper
instantiates at compile time, so the Verilator line and expression figures
are the wrapper's own file plus the `cov/sv` modules, and `user` is the
cover-property layer. Toggle is not collected on Verilator.

`coverage_off -file` matches the path as Verilator opened it, and
`+incdir+`-resolved files are opened relative, so a leading `*/` scopes only
half the tree: `*vendor/*` matches both forms. Two vendored trees under
`.u_smc` and `.u_dtp` (`axi_lite_demux.sv`, the `generic_dff*` family) are
unreachable by any file pattern. Verify a scope change by counting
instrumentation sites per source bucket in the generated model, not by the
build passing: a wrong scope changes nothing and warns about nothing.

==== Three ways a point leaves the population

* The scope file applies `coverage_off` by source file, so a point never
  enters the database. Structural, by file.
* `SEP_PRESENT` gates the `g_sep` and `g_nosep` generate blocks. A point whose
  observable exists only with the SEP elaborated, or only without it, is not
  elaborated on the other build. `tb_wrapper_top.sv` passes
  `SEP_PRESENT = 1'b1`, so every `g_sep` point exists and no `g_nosep` point
  does. Structural, by elaboration.
* `SMU_FCOV_PHASE2` guards the Phase 2 points. Structural, by plan.

A collected point that stays unhit is a missing test, a collector that
measures the wrong thing, or a Phase 2 point that has not been moved yet; the
Closure Policy below says which change each takes.

==== Sampling rules

* Points need stimulus beyond power-up and reset release. A level that is
  true in the quiescent state is either absent or qualified by a sticky flag
  recording that its counterpart happened first, so "released" means "the
  stall lifted", not "no stall was ever applied".
* `smu_boot_fcov` and `smu_rst_fcov` disable on `powergood`, not on reset, so
  the reset sequence itself stays observable. The other modules disable on
  the cold or primary reset.
* Every register in a module has a reset branch, so a four-state simulator
  never holds a term at X.

==== Fuse-sense run modes

Every run mode in `smu_sim_cfg.toml` passes `+skip_fuse_sense` except
`[run_modes.sep_rtl_fuse_sense]`, under which the eFuse bank models supply
the sensed data. The fuse-sense completion points need that mode, and the
two leaves enrolled in it carry them.

==== Scenario intent is not coverage

`cocotb/env/smu_fcov.py` is a static table from a test class name to the bins
its scenario is claimed to reach. Running the test marks the bins; no signal
is observed, and nothing under `tools/` or `.github/` reads its output. It is
neither the release metric nor a gate.

=== Phase 1 coverage definitions

Each table row is one cover property, or one covergroup. A row states what
the module must see at the wrapper boundary. Points named `g_sep.c_*` sit in
the `g_sep` block; urg prints them with that prefix and Verilator with
`g_sep__DOT__`.

[[smu-fcov-phase2]]
=== Phase 2 (not collected)

The points below compile only with `SMU_FCOV_PHASE2` defined. No run mode or
target defines it, so they are outside the collected population and no
policy entry names them.

[cols="2,4,3",options="header",]
|===
|Point |Why it is not a legal operating mode of this bench |What brings it back
|`c_axi_in_bresp_exokay`, `c_axi_in_rresp_exokay` |EXOKAY answers an exclusive access, and no subordinate behind the crossbar has an exclusive monitor: every AXI interconnect in the SEP and SMC is built without atomics and the memory adapters tie exokay off. `smu_axi_in_attribute_sweep_test` checks that an AxLOCK=1 access is answered OKAY |A subordinate behind the SMU crossbar with an exclusive monitor
|`g_sep.c_lc_sigint_err` |`lc_sigint_err` rises only when the exported LC_STATE differential pair disagrees with itself. The eFuse shadow re-encodes the raw state, so the pair is valid unless corrupted in flight, which takes a fault injected inside the SEP; the SEP bench grades that path |A fault-injection hook on the exported LC_STATE pair in `tb/tb_wrapper_top.sv`
|`c_map_smc_size_zero` |A zero SMC REGION_SIZE is illegal: `smc_base_config` requires a non-zero power of two, and zero leaves no reachable local aperture. The crossbar rule it forms has `start == end`, which the decoder's map check rejects |A specification change that makes a zero SMC window a legal state
|===

The covergroups carry the same facts as ignored bins: `cg_axi_in_resp`
ignores EXOKAY and `cg_map_window` ignores the zero SMC window. The ignored
bins of `cg_lifecycle`, `cg_lc_at_release`, `cg_block_release`,
`cg_tel_rate`, `cg_wdt_rate`, `cg_dbg_disable_slice`, `cg_smn_ids` and
`cg_alias_path`, and the state `cg_sep_window` leaves out, are values the
design, the routing or the bench clocks cannot present, each stated beside
its coverpoint in `cov/sv/`.

The claim that inbound writes to the SEP TRNG window are refused with DECERR
is Phase 2. `doc/integrator/src/smu.adoc` ("External TRNG") terminates an
unconnected `ext_trng_axil` with a DECERR slave, and `hw/sys/sep/doc/memory_map.adoc`
says every access in the window reaches the TRNG slave. The writes
`smu_axi_in_sep_aperture_test` sends there are observed to return SLVERR, while
its reads there return DECERR, and no specification text names SLVERR for
them. The test checks the reads for DECERR and records the write responses
without grading them. The claim comes back when the design answers those
writes with DECERR or a specification states the code they return.

=== Closure Policy

Coverage closes against a finished `all` run, not against a waiver. Every
collected point or bin the run leaves unhit takes one of three outcomes, with
evidence:

. *Reachable*: a leaf is added or extended so `all` hits it, with a testlist
  entry, evidence ids in `cocotb/env/smu_evidence_map.py` and a VPLAN card.
  Goldens come from generated headers, IP-XACT or the specification, never
  from the RTL.
. *Wrong measurement*: the collector is corrected to express the specified
  behaviour, citing the specification or generated map line, and then hit.
. *Not a legal operating mode*: the point moves to <<smu-fcov-phase2>> with
  its reason and what would bring it back. A covergroup bin no legal
  configuration reaches becomes an ignored bin with the fact beside it.

The covergroups declared inside vendored RTL are the only ones the group
exclusion file drops; the companion's `gen_smu_wrapper_group_exclusions.py` names each class
with its reason, and a covergroup under `u_dut` that no class names stops the
generator.

==== What the plan may claim

. *Per-testcase attribution is measured, never asserted.* The points are
  free-running cover properties on boundary signals, so which testcase lights
  which point is a property of a run. <<smu-fcov-owners>> is that
  measurement: written by `tools/dv/fcov_owners.py` from the per-leaf
  databases of a named `all` run, it carries the commit and simulator it was
  measured on and is regenerated after each coverage run. A point one leaf
  alone reaches depends on that leaf.
. *`smu_fcov.py` sources no coverage claim.*
. *No CI gate is set on these numbers.* `SMU_COVERAGE_POLICY.adoc` states the
  targets and how a floor would be set from a measured database.

==== Evidence

A closure claim names the tool and the `run_dv.py` run it was read from and
quotes the launcher `result status=` line. A Verilator run is evidence for
the cover properties only; the covergroups need a VCS run. Local paths under
`build/runs/` are not durable.

==== Owning tests

The table below is regenerated from the coverage run's directory:

    python3 tools/dv/fcov_owners.py --dut smu --run-dir <run dir> \
        --output hw/sys/smu/dv/docs/SMU_FCOV_OWNERS.adoc

`--check` in place of a rewrite says whether the committed table still
matches the run. A row with `Leaves` of 1 is a point one leaf alone reaches;
a row with 0 carries the policy disposition of the hole, or `unclassified`
when the policy has none.
