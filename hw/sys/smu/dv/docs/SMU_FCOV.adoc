[[smu-dv-functional-coverage-plan]]
== SMU OCAH Open-Source Functional Coverage Plan

=== Overview

This chapter states what coverage the SMU open-source testbench collects,
what the collected number measures, and what the verification plan is
allowed to claim from it. The collection mechanics -- the scope file, the
policy file and the Verilator knobs -- are under `cov/`; the release-group
grading rules and the waiver fields are in
`hw/sys/smu/doc/dv/SMU_COVERAGE_POLICY.adoc`.

[cols=",",options="header",]
|===
|Field |Value
|Reference VPLAN |`SMU_VPLAN.adoc`
|Reference architecture |`SMU_TB_ARCH.adoc`
|Framework |PyUVM on cocotb
|Simulator that collects |Verilator (`--cov`) in public CI; a `[coverage.vcs]` table and `cov/config/vcs/smu_wrapper_cov_scope.hier` mirror the wrapper's scope for the licensed flow, which no public job runs
|What each DUT collects |`--dut smu_block`: toggle plus `user` over its scope file. `--dut smu` (the release group, weekly `--cov` in `regress.yml`): line, expression, toggle and `user` over a scope that drops everything the wrapper instantiates, so the toggle points that remain are `smu_wrapper`'s own; `cov/interface_toggle.py` folds the ones on its ports into a per-port figure
|Scope files |`cov/config/verilator/smu_cov_scope.vlt` (`--dut smu_block`); `cov/config/verilator/smu_wrapper_cov_scope.vlt` (`--dut smu`)

=== Metric Choice

SMU is an integration level: `hw/sys/smu/rtl/smu.sv` wires SMC, DTP, SEP and
the AXI crossbar together and carries almost no procedural logic. Verilator
emits no line, branch or expression instrumentation site for anything under
`hw/sys/smu/rtl/`. An unscoped line/branch/expression build produces on the
order of 1.3 million sites, every one of them outside SMU: the vendored trees,
the chipyard-generated CPU cluster, `hw/ip`, `hw/common`, `hw/sys/smc` and the
testbench account for all of them.

Those three families therefore cannot grade SMU. Toggle instruments nets,
which is what an integration level owns -- whether the interconnect it wires
up was exercised -- so the metric this package intends is *toggle*, with the
`cov/sv` cover properties as *functional (`user`)* coverage beside it. Each
subsystem grades its own internals in its own DV package.

Toggle is measured on both DUTs. `--dut smu_block` collects it over the SMU
block, the logic that bench owns. `--dut smu` collects it over `smu_wrapper`
alone -- its scope drops the SMU block, SEP, SMC and DTP at compile time --
and the release figure is the share of the wrapper's ports on which any bit
toggled, which `cov/interface_toggle.py` reads out of the run's
`cov/merged.dat`; `SMU_COVERAGE_POLICY.adoc` states the target and the last
measured value.

Toggle over the whole elaborated model, SMC cluster and vendored fabric
included, produces a database of about 0.5 GB per leaf.
`smu_cov_scope.vlt` drops all of it at compile time so the toggle denominator
is SMU's own RTL; enabling toggle without the scope reproduces that database.

=== What the Toggle Number Measures

The SMU integration RTL *plus two vendored trees the tool cannot exclude*, not
"SMU coverage" alone. `vendor/pulp-platform/axi` (`axi_lite_demux.sv`) and
`vendor/tenstorrent/tt-hw-debug` (`generic_dff*`) hold the large majority of
the scoped toggle sites; `hw/sys/smu/rtl/smu.sv` and `cov/sv` hold the rest.

Every vendored site sits under `.u_smc` or `.u_dtp` -- none is under SMU's
own crossbar -- so the intent is unambiguous and only the mechanism falls
short. `smu_block_coverage_policy.toml` records the two hierarchy selectors
that close it and why their counts can only come from a coverage database.

The `cov/sv` modules' own registers are toggle sites too. `coverage_off` is
whole-file, so excluding them would delete the `user` points; they stay in
the denominator, named here.

==== Verilator glob matching

`coverage_off -file` matches the path as Verilator *opened* the file, not the
absolute path it records in the generated code, and `+incdir+`-resolved files
are opened relative. A leading `*/` therefore scopes only half the tree:
`*vendor/*` matches both forms, `*/vendor/*` matches only the absolute one.

Two vendored trees are unreachable by any file pattern: `*vendor/*`,
`*pulp-platform/*`, `*tt-hw-debug/*` and the bare `*axi_lite_demux.sv` /
`*generic_dff.sv` forms all leave the site count unchanged, so none of them is
in the scope file.

Verify a scope change by counting `__vlCoverToggleInsert` sites per source
bucket in the generated model, not by the build passing: a wrong scope
changes nothing and warns about nothing.

=== Functional Coverage Points

`cov/sv/` carries 11 modules of labelled cover-property points, 115 in all,
each declared through the `OCAH_FCOV_COVER` macro. Under `--cov` they land in
the `user` metric family of the native coverage database, so they reach
`cov_merge`, `cov_report` and the coverage policy.

The block bench `tb/tb_top.sv` instantiates nine of them and the wrapper bench
`tb/tb_wrapper_top.sv` ten. `smu_clk_fcov.sv` and `smu_alias_fcov.sv` are
wrapper-bench only: one reads clock mirrors, the other boundary probes, that
only that bench publishes. `smu_nosep_fcov.sv` is block-bench only: its points
exist without SEP, and the wrapper elaborates SEP. Point counts below are the
declarations in each file, counted from
the source; how many of them *elaborate* on a given target is lower wherever a
`g_sep` guard removes one, and that number needs a run rather than a count.

==== `SepPresent`, a third scope mechanism

Two mechanisms keep a point out of a graded number, and `SepPresent` is a
third that is easy to confuse with them.

* The scope files `smu_cov_scope.vlt` and `smu_wrapper_cov_scope.vlt` apply
  `coverage_off` by source file at compile time, so the point never enters the
  database. Structural OUT, by file.
* `SepPresent` gates the `g_sep` generate blocks in `cov/sv/*_fcov.sv`. A
  point whose observable exists only with SEP elaborated is not elaborated at
  all on a SEP=0 build, so it never reaches the database and no waiver has to
  name it. Structural OUT, by elaboration.
* A `[[holes]]` entry is the opposite case: the point exists, is not hit, and
  is carried with a category, a rationale, an owner and an expiry.

`tb_wrapper_top.sv` passes `SepPresent = 1'b1` unconditionally: the wrapper
has one compile profile, `compile_smu_chiplet`, and it elaborates SEP, so every
`g_sep` point exists there. The block bench passes `1'b0` unconditionally,
because it hardcodes SEP=0, and it is where the SEP=0 composition proofs
(the `nosep` group of `testlists/block.toml`) run.

The `g_sep` guards still matter on the block bench: an accepted waiver whose
selector matches a covered point is a hard `ConfigError`, so a point which can
only fire with SEP present must not exist on the SEP=0 elaboration.

==== Fuse-sense run modes

Every run mode in `smu_sim_cfg.toml` passes `+skip_fuse_sense`, under which
`efuse_shadow_regs.sv` drives `fuse_sense_done` from the plusarg and loads the
shadow array from a preload file. A test that observes fuse-sense completion
has to run without it, so that the eFuse bank models supply the sensed data.
`[run_modes.sep_rtl_fuse_sense]` is the one that leaves the plusarg unset, and
it carries the only two tests needing it.

Points must need stimulus beyond power-up and reset release. A level that is
true in the quiescent state is either absent or qualified by a sticky flag
recording that its counterpart happened first, so "released" means "the stall
lifted" rather than "no stall was ever applied".

=== Scenario Intent Is Not Coverage

`cocotb/env/smu_fcov.py` is a static `TEST_FCOV_HITS` table mapping a
test class name to the bins its scenario is *claimed* to reach. Running the
test marks the bins; no signal is observed, and nothing under `tools/` or
`.github/` reads its output. It records scenario intent and is neither the
release metric nor a gate.

=== What the Plan May Claim

Three limits decide what `SMU_VPLAN.adoc` is allowed to say about coverage:

. *No per-testcase coverage attribution.* The `cov/sv` points are
  free-running cover properties on DUT signals, not per-scenario covergroups,
  so which testcase lights which point is a property of a run, not of the
  source. Naming bins per plan entry without a run would be a claim nobody
  measured.
. *`smu_fcov.py` sources no coverage claim.* It is scenario intent, as stated
  above.
. *No CI gate is set on these numbers.* `SMU_COVERAGE_POLICY.adoc` states the
  targets (85 percent of the wrapper's ports toggled, 95 percent of the `user`
  points effective) and the last measured values, says how a floor would be
  set from a measured weekly database, and lists the fields a waiver must
  carry.

=== Two DUTs, One Policy File Name

`smu` and `smu_block` share one `hw/sys/smu/dv` tree, so the canonical
`cov/config/<tool>/coverage_policy.toml` discovery would resolve identically
for both DUTs, and whichever DUT the file did not name would fail
`--validate-configs`. `[coverage.verilator].policy_file` in
each config names a DUT-qualified file instead: `smu_block_coverage_policy.toml`
for the block bench and `smu_wrapper_coverage_policy.toml` for `--dut smu`.
Each carries one `[[holes]]` entry per unhit point, with
`disposition = "waive"`, `status = "accepted"` and an `expires` date after
which it grades as open again. Neither sets a threshold.
