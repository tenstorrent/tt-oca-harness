[[smu-coverage-policy]]
== SMU coverage targets and closure policy

This chapter defines *what* the SMU release group is graded on and *how*
a hole is waived. It does not install a CI fail-on-hole gate; that gate
needs a measured database first.

[cols=",",options="header",]
|===
|Field |Value
|Release group |`--dut smu --items sep0_all` (live size in
`SMU_RELEASE_MATRIX.adoc`)
|Public metric |toggle. Weekly `--cov` on this tree does not collect it —
see below
|Numeric target |none; a target is set only from a measured database
|===

[[smu-cov-paths]]
=== Public versus commercial evidence

[cols="2,3,3",options="header",]
|===
|Path |What it collects |Where it runs
|Public Verilator |line / expr / user, because wrapper
`smu_sim_cfg.toml` `[coverage.verilator]` leaves toggle off
(the DUT elaborates real SEP/SMC/DTP; unscoped toggle is the 0.5 GB
case) |weekly `--cov` on the large runner (`regress.yml`). Nightly does
not collect.
|Intended public metric |toggle on the SMU interconnect after
compile-time scope |`--dut smu_block` collects it over
`smu_cov_scope.vlt` (`smu_block_sim_cfg.toml`). The release group's
weekly `--cov` runs `--dut smu` and writes line / expr / user, not
toggle.
|Commercial |toggle / code / assertion databases under the licensed
flow |not a public CI job; not a substitute for the public weekly
|===

The DUT is an integration shell: `smu.sv` is wiring, and Verilator
emits no line / branch / expression sites under `hw/sys/smu/rtl/`.
That is why the intended metric is toggle rather than the families
the weekly run writes. A Python `smu_fcov.py` sampler is
not the release metric and is not a gate.

[[smu-cov-out]]
=== Structural OUT versus a waiver hole

Two mechanisms. Do not mix them.

[cols="2,3,3",options="header",]
|===
|Kind |Effect |Carrier
|Structural OUT |the point never enters the database |`coverage_off`
file patterns (SMC, DTP, SEP, `hw/ip`, `hw/common`, CPU cluster, TB,
vendor trees the file pattern can reach)
|Waiver hole |the point exists and is not hit |`[[holes]]` with the
fields below
|===

A vendor site that `coverage_off` cannot name (hierarchy under `.u_smc`
/ `.u_dtp`) is a hole with `category = "out_of_scope"` and
`disposition = "exclude_scope"`. Write it only from a real database:
`expected_matches` is a hard count, and a guessed count is a
ConfigError on the first run.

[[smu-cov-waiver]]
=== Waiver fields

Every `[[holes]]` row must carry:

* `tool`, `metric_family` (the family that database holds: line / expr
/ user on `--dut smu`; `toggle` on `--dut smu_block`), `hierarchy` or
file selector
* `category` (`out_of_scope` / `excluded` / `waived` / `open`)
* `disposition`
* `owner`
* `review_date`
* `issue` when the disposition is actionable

`max_unclassified_points = 0` is the fail-on-new-hole knob. It is not
set here; it is set together with the threshold, from a measured weekly
`--cov` database.

A waiver reaches a finished run without a simulator:
`python3 tools/dv/run_dv.py --dut smu --run-dir <run> --waive` re-grades
the run's report against this policy and rewrites its coverage grade in
place. A dispatch of `dashboard.yml` with the weekly's regress run id does
the same for the published weekly. Both are described on the runner and
dashboard pages under `tools/dv/doc/`.
