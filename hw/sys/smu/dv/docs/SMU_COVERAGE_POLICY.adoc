[[smu-coverage-policy]]
= SMU coverage targets and closure policy

This chapter defines *what* the SMU release group is graded on and *how*
a hole is waived. It does not install a CI fail-on-hole gate; that gate
needs a measured database first.

[cols=",",options="header",]
|===
|Field |Value
|Release group |`--dut smu --items all` on VCS, the coverage set
(`cov/config/vcs/README.md`); `hosted` is its toolchain-free subset, 84 of
the 120 leaves (`testlists/all.toml`; the Regression Groups section of
`hw/sys/smu/dv/docs/SMU_VPLAN.adoc` lists every group)
|Metrics |the runner's native families: `user` (the `cov/sv` cover
properties) on Verilator and VCS; on VCS also line, condition, branch and
`toggle` over the SMU's own logic, where `toggle` is every bit of every net of
`smu_wrapper`, `smu`, `smu_axi_xbar`, `axi_window_remap` and every other
SMU-owned unit under `u_smu` outside the SMC, DTP and SEP trees
(`cov/config/vcs/gen_smu_cov_scope.py`), in both directions after the
exclusion files have left the population, and
`assertion`, where urg reads the cover properties and the one
`smu_axi_xbar` assertion
|Numeric target |VCS `user` 100 percent effective, the one
`\[[thresholds]]` row of `cov/config/vcs/smu_wrapper_coverage_policy.toml`.
No code-metric family carries a floor on either tool, the way DTP and SEP set

run's status comes from its tests, and the figures are read against the
targets this chapter states.

`\[[thresholds]]` row at all
|Measured (Verilator, the `cov/sv` cover properties) |`all`, 120 leaves,

|Measured (VCS) |The run of record of epoch `smu-vcs-cov-v3`

percent effective on every family it collects, the `user` cover properties

[[smu-cov-paths]]
== Public versus commercial evidence

[cols="2,3,3",options="header",]
|===
|Path |What it collects |Where it runs
|Public Verilator |line / expr / user over `smu_wrapper_cov_scope.vlt`,
which drops everything the wrapper instantiates at compile time -- the SMU
block, the SEP, SMC and DTP trees, the `hw/top`
integration shells, vendored and generated RTL. Toggle is not collected on
Verilator, as the DTP set does not collect it: `coverage_off -file` does not
apply to a source file whose last line has no newline, and the vendored and
`hw/common` files in that state would carry subsystem toggle points into the
wrapper's database |a developer or self-hosted run,
`python3 tools/dv/run_dv.py --dut smu --tool verilator --items all --cov`,
followed by `tools/dv/fcov_owners.py` over its run directory, which writes
`hw/sys/smu/dv/docs/SMU_FCOV_OWNERS.adoc`. No `regress.yml` tier collects
coverage: both `smu` rows carry `coverage: false`
|Commercial |line / condition / branch / toggle / assertion databases under
the licensed flow. `smu_wrapper_cov_scope.hier`, written by
`gen_smu_cov_scope.py`, follows the rule the SEP and SMC scopes state: SMC,
DTP and SEP leave as instance trees because each is graded on its own bench,
as do the integration shells and the bench's AXI egress glue; bench units,
library cells and the vendored interconnect cells leave by design unit; the
`cov/sv` monitors leave the code and toggle metrics and stay in the assertion
metric. Toggle covers every net of what stays, and `-cm_noconst` leaves
tied-off nets out. `cov/config/vcs/smu_wrapper_toggle_exclusions.el` and
`smu_toggle_exclusions.el` name, one fact per class, the fields no SMU logic
reads or writes, and the policy applies them at report time.
`cov/config/vcs/smu_wrapper_coverage_policy.toml` floors none of these
families; `run_dv.py` prints each on its `coverage` line and grades only the
`user` row (see `cov/config/vcs/README.md`) |a licensed host,
`python3 tools/dv/run_dv.py --dut smu --tool vcs --items all --cov`
(`cov/config/vcs/README.md`); no public CI job runs it
|===

The VCS figure is the SMU's own logic: the wrapper's wiring, `smu.sv` with
its reset, lifecycle and cross-trigger glue, `smu_axi_xbar` and the SEP
alias remap. Most of it is wiring, so toggle carries most of the population,
on the same per-bit, both-directions definition and through the same runner
family as every other DUT. The Verilator figure is narrower, the wrapper and
the `cov/sv` points; quote the flow with the number. The exclusion files are
the only place where the population is shaped after compile, and every class
in them states its fact and what would retire it. A Python `smu_fcov.py` sampler is
not the release metric and is not a gate.

[[smu-cov-out]]
== Structural OUT versus a waiver hole

Three mechanisms. Do not mix them.

[cols="2,3,3",options="header",]
|===
|Kind |Effect |Carrier
|Structural OUT, by source file |the point never enters the database
|`coverage_off` file patterns (`hw/sys/smu/rtl`, SMC, DTP, SEP, `hw/ip`,
`hw/common`, CPU cluster, TB, vendor trees the file pattern can reach)
|Structural OUT, by elaboration |the point is not elaborated, so it never
enters the database and no waiver names it |the `SEP_PRESENT` parameter and
its `g_sep` generate blocks in `cov/sv/*_fcov.sv`; a point whose observable
exists only with SEP elaborated is absent from a SEP=0 build; the wrapper's
single target elaborates SEP, so every `g_sep` point exists there
|Waiver hole |the point exists and is not hit |`[[holes]]` with the
fields below
|===

A vendor site that `coverage_off` cannot name (hierarchy under `.u_smc`
/ `.u_dtp`) is a hole with `category = "out_of_scope"` and
`disposition = "exclude_scope"`. Write it only from a real database:
`expected_matches` is a hard count, and a guessed count is a
ConfigError on the first run.

[[smu-cov-reviewers]]
== Reviewers

An entry's `reviewer` differs from its `owner`, and the review class follows
the kind of fact the entry rests on. `cov/config/vcs/README.md` states each
class's fact and what retires it.

[cols="2,3,2",options="header",]
|===
|Class family |Fact it rests on |Review
|The port-toggle classes `AXI-USER`, `AXI-DATA`, `ATB-PAYLOAD`,
`RTL-CONSTANT`, `UNION-ALIAS`, `REGISTER-WIDTH` and `SEP-OWNED`, and the
block classes whose ANNOTATION names an RTL tie, a packed union, a fixed
attribute or a reserved field |a design fact, cited to the RTL file and line
|design review
|The port-toggle class `DFT` and every block class whose ANNOTATION opens
`bench scope` |a bench fact: what this testbench ties, drives or leaves
undriven |DV review
|`VENDORED-I3C` |a covergroup declared inside vendored RTL that another
package grades |coverage-flow review
|A `pass:[[[holes]]]` entry |the class the hole names; a hole whose
disposition is `fix_model` or `cover` takes DV review |as above
|===

Every entry change is graded against a named finished run with the runner's
`--waive` re-grade.

[[smu-cov-reopen]]
== Reopen triggers

An accepted exclusion or waiver stays accepted until the policy changes; the
calendar does not reopen it. It reopens, by the entry being removed at the
next regeneration or by a `pass:[[[holes]]]` entry's status returning to
`open`, when:

* an RTL change moves the module or instance checksum of the scope the entry
  names, which drops the entry on its own, since URG applies no entry whose
  checksum differs from the design it reports on;
* an enrolled leaf covers the point: the exclusion files are written from the
  uncovered set of a graded run, so a covered point is not written again, and
  the runner rejects an accepted `pass:[[[holes]]]` entry whose selector
  matches a covered point;
* the retiring condition the class's `Retired by` column states is met;
* the policy's `scope_epoch` changes, or the compile-time scope
  (`smu_wrapper_cov_scope.hier`, `smu_wrapper_cov_scope.vlt`) changes which
  points enter the database;
* a regenerated file is written from a new graded run, which replaces every
  entry that run no longer leaves uncovered;
* a covergroup a vendored block adds falls in no class the group exclusion
  generator names, which stops the generator rather than admitting it
  silently.

[[smu-cov-no-formal]]
== No formal unreachability behind the denominator

SMU has no formal coverage-unreachability analysis. The companion's SMU
formal configuration holds a connectivity app and no coverage app, so no
list of the kind `hw/sys/smc/dv/cov/config/vcs/smc_unreachable.el` or
`hw/sys/dtp/dv/cov/config/vcs/dtp_unreachable.el` exists for this DUT, and
nothing proves that a point left in the `toggle` denominator is reachable at
all. The exclusion files do that work by hand instead: each class states a
design or bench fact and names what retires it, which is a weaker claim than
a proof and is reviewed as such.

This is one of the reasons `cov/config/vcs/smu_wrapper_coverage_policy.toml`
sets no `toggle` floor: a floor over a denominator no proof has filtered
fails a run on a number rather than on a fact. A floor becomes meaningful
when an unreachability analysis supplies the filter the SMC and DTP policies
have; until then the figure is reported and read against the target this
chapter states.

[[smu-cov-waiver]]
== Waiver fields

Every `[[holes]]` row must carry:

* `tool`, `metric_family` (the family that database holds: `user` and the
wrapper's own `toggle`), `hierarchy` or file selector (`[[holes.native]]`)
* `category` (one of the runner's hole categories, such as
`missing_stimulus`, `config_disabled`, `out_of_scope` or `unreachable`)
* `disposition`, `status`, `confidence`, `rationale`
* `owner`, `reviewer`
* `issues` when the disposition is actionable

`max_unclassified_points = 0` is the fail-on-new-hole knob. It is not
set here; it is set together with the threshold, from a measured
`--cov` database.

A waiver reaches a finished run without a simulator:
`python3 tools/dv/run_dv.py --dut smu --run-dir <run> --waive` re-grades
the run's report against this policy and rewrites its coverage grade in
place. A dispatch of `dashboard.yml` with a regress run id does the same
for that run's published record when it carries a coverage grade; the
scheduled weekly carries none. Both are described on the runner and
dashboard pages under `tools/dv/doc/`.
