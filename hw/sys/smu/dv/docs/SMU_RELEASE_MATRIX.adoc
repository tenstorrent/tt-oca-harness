[[smu-release-matrix]]
== SMU v0.5.0 release regression matrix

This chapter records the #485 decision. The mandatory qualification set
is the *live* CI matrix in `.github/workflows/sim.yml` and
`regress.yml`. It is not revised. `--dut smu` is the wrapper bench and its
`sep0_all` is the mandatory job; `--dut smu_block` is not.

[[smu-release-combinations]]
=== Mandatory combinations

[cols="2,2,1,1,3",options="header",]
|===
|Tier |Command |Group size |Seeds |Blocks
|PR |`--dut smu --tool verilator --items smoke_sep0` |4 |1 |PR merge (`sim.yml`)
|Nightly |`--dut smu --tool verilator --items sep0_all` |53 |1 |v0.5.0 release qualification (`regress.yml`)
|Weekly |`--dut smu --tool verilator --items sep0_all` |53 |3 |Coverage / dashboard; same group as nightly
|===

The live group is 53. Nightly is one seed;
weekly is three. A red nightly is not a PR merge gate (`regress.yml`
says so) but it *does* block the #478 release package.

`smu` smoke members: `smu_smc_smoke_test`, `smu_dtp_jtag_smoke_test`,
`smu_no_sep_configuration_test`, `smu_ext_boot_seq_gate_test`.

[[smu-release-decisions]]
=== Decisions

* Keep `smu_ext_boot_seq_gate_test` PR-only. Do not add it to
  `sep0_all` / nightly. It stays in `smoke` / `smc`.
  Re-enrollment is a later #493 choice, not this matrix.
* `--dut smu_block` is **not** a v0.5.0 CI job beyond its own `smoke`. Its
  PASSes stay labelled `DUT_TAG=BARE` and are not `sep0_all` density (#489).
* Feature credit stays the enrolled `sep0_all` set on `--dut smu`. The SEP=1
  firmware groups and `tests_deferred/` names are OUT.

https://github.com/tenstorrent/tt-oca-harness/actions/runs/34051136716
keeps JUnit, per-test logs, and `result.json` on artifact
`dv-run-smu-verilator-nightly`. Score: 51 PASS / 1 FAIL on the 52-member
`sep0_all` group. The FAIL is `smu_xtrig_ctm_remap_test` (#482; fix in
#1572). That leaf does not change this matrix.

That run predates the DUT unification: at `a273033a0`, `--dut smu` was the
bare `smu #(.SEP(0))` bench and `sep0_all` held 52. The group is 53 on the
wrapper now, which is what the table above states; the retained artifact is
kept as the evidence for that SHA, not as the current score.
