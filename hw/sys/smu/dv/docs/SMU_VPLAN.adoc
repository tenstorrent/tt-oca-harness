== SMU OCAH Open-Source Verification Plan

=== Overview

[cols=",",options="header",]
|===
|Field |Value
|Design Under Test |`hw/top/smu_wrapper.sv` through `hw/sys/smu/dv/tb/tb_wrapper_top.sv`
|Framework |PyUVM on cocotb
|Primary simulator |Verilator
|Reference testbench architecture |`SMU_TB_ARCH.adoc`
|Executable contract |the enrolled groups in `testlists/wrapper.toml`
|===

This plan describes what the SMU open-source suite verifies and against which
RTL. The executable contract is the enrolled testlist groups; this document
describes them, it does not replace them.

=== Verification Strategy

The SMU is verified at its own boundary with `SEP=0`: the SMC and DTP
subsystems below it are real RTL, the SEP is not instantiated, and the external
SMN fabric is driven by the shared AXI VIP. Four surfaces are covered:

. *Fabric and address decode* — external SMN AXI into SMC, ID-width conversion,
  crossbar error handling, ATOP rejection, alias remap and the inbound and
  outbound filters, driven both from the external port and through JTAG2AXI.
. *SMC under SMU* — bring-up, reset control, mailbox, watchdog, GPIO straps and
  the security demote path, reached through the SMU rather than at the SMC
  boundary.
. *DTP under SMU* — primary JTAG, STAP selection, boundary-scan and iJTAG, the
  OTP bridge and the cross-trigger routing, as they appear once DTP sits under
  the SMU.
. *Clock, reset and boot sequencing* — clock-stop coordination, boot stall,
  IC_RESET domains and external boot-sequence gating.

Checking is centralised in `SmuScoreboard`, which refuses a vacuous PASS and
requires every mapped evidence token to have been proven by a real check. See
the checking strategy in `SMU_TB_ARCH.adoc`.

=== Naming Rules

[cols=",",options="header",]
|===
|Rule |Requirement
|Single-scenario module |Use the module name, for example `smu_clock_stop_coordination_test`
|Multi-scenario module |Use `+smu_<feature>_<scenario>_test+`, for example
`smu_axi_filter_in_instance_matrix_test`
|Scenario names |Use descriptive lower-snake-case names that encode operation,
mode, direction or coverage target
|Names from another subsystem |Normalise to `+smu_*+` and keep the target inside
the name, for example `smu_smc_wdt_sanity_test` for the SMC watchdog reached
through the SMU
|Open-source files |One PyUVM test class per scenario -- under
`cocotb_wrapper/tests/` for `--dut smu`, under `cocotb/tests/` for the
`--dut smu_block` leaves -- so each scenario is independently selectable from
a testlist. Sequences in `common/seq_lib/` are shared by both DUTs where
scenarios differ only in stimulus
|===

=== Open-Source BFM Policy

The BFM table lives in `SMU_TB_ARCH.adoc` so the testbench chapter and the plan
cannot drift apart. The policy itself: standard protocols use the shared OCAH
VIP packages, SMU-specific behaviour uses OCAH-local models under `env/`, and
no enrolled test may reach into the DUT with Force or deposit.

[[smu-test-procedures]]
=== Test Procedures

Each entry below is a test body and its sequence. The Checkers table lists the
evidence tokens the body emits, and those tokens are also the
`(CHK_ID, TOKEN, EXPECT)` rows in `common/smu_dv_env/smu_evidence_map.py`.
Those rows are a token contract, not a behavioural one. The gate that applies
it is in the base test of each bench: `cocotb_wrapper/tests/smu_base_test.py`
(`--dut smu`) and `cocotb/tests/smu_base_test.py` (`--dut smu_block`) call
`bind_testcase` before bring-up and `prove_mapped_features()` after the
scenario for every leaf that builds an `SmuScoreboard` (`use_shared_env`).
The call fails the test when a TOKEN mapped to the testcase was not logged by
a passing `expect_*` compare, and when the testcase has no rows and is not
declared in `UNMAPPED_TESTS`. A leaf that builds no `SmuScoreboard` -- the
firmware terminal-loop leaves, the two smokes, the elaboration leaves -- is
not gated; the wrapper base test logs one `EVIDENCE MAP GATE SKIPPED` line
naming it, and its verdict is the sequence's own raise or its own scoreboard
(`SmuSepBootScoreboard`, `sep_terminal_loop_seq`). `UNMAPPED_TESTS` holds
only scoreboard-bearing tests that run without rows.

The EXPECT column is free-text contract wording for readers. Nothing compares
an observed value against it, so the per-row log line `EVIDENCE TOKEN SEEN`
reports that a mapped token was carried by a passing check -- not that the
sentence beside it was verified. Each row also prints how the token bound:
`evidence-arg` when the caller named it in an `evidence=` argument, or
`check-name-substring` when the TOKEN or CHK id was matched against the check's
name. Rows in the second class are the weaker binding and are collected into an
`EVIDENCE BINDING WEAK` line. To know what a row's sentence is worth, read the
check.

[[sec-004-smu_axi_external_port_connectivity_test]]
===== 4 `smu_axi_external_port_connectivity_test`

*Source Module*: `smu_axi_external_port_connectivity_test`

*BFM / Model*: `ocah_axi_vip`, `ocah_jtag_vip`

*Objective*: SMU_ALL_002: SEP=0 inbound SMN→SMC + direct IW converters.

*Test Coverage*:

* Sequence for smu_axi_external_port_connectivity_test (SMU_ALL_002).
* SMU_ALL_002 owns SMU-PORT-SMN-AXI.S1 — inbound 56/64-bit on smu_axi_in reaches SMC via direct IW converters (block bench, SEP=0; required_cells dir=in + dest=smc_aperture only).
* SMU-SEP-PARAM.S2 — SEP=0 elaboration of direct SMC↔external ID converters (non-OTP-error).
* The S1 probe (`CHIP_CONFIG.VERSION_LO`) lands on SMC BlockByDefault, so the write and the read answer DECERR. A DECERR alone is also what a dead bus or a stuck converter returns, so the same run carries a positive control on the same master and path: JTAG2AXI opens inbound filter 0 over the probe, the external read must return OKAY with the RDL reset value of `VERSION_LO`, and the window is cleared so the DECERR returns.
* SEP aperture inbound (dest=sep_aperture) is owned by SMU-PORT-SMN-AXI.S4 on SMU_ALL_008 — out of scope for this card.

*Test Procedure*:

[arabic]
. Drive `smu_axi_external_port_connectivity_test_seq` over the block bench's product interfaces (`--dut smu_block`, `smu #(.SEP(0))`; the wrapper's single profile elaborates SEP=1).
. Write and read `VERSION_LO` from `smu_axi_in` with distinct AWID/ARID before any inbound window is programmed; the response class must be OKAY or DECERR and BID/RID must equal the issued IDs.
. Bring the PTAP out of TLR, require the SMC JTAG2AXI gate open, and program inbound filter 0 over the probe's 4 KB granule.
. Read `VERSION_LO` again from `smu_axi_in` with a third ARID: OKAY, RID match, data equal to the RDL reset value.
. Clear inbound filter 0 and require the DECERR to return on the same probe.
. Observe the SEP=0 direct IW converters and the tied-off SEP aperture, then the bounded-wait inventory.
. Emit the evidence tokens listed under Checkers.

*Checkers*:

[cols="1,2",options="header",]
|===
|Checker |Description
|`CHK-SMU-PORT-SMN-AXI-S1` |Inbound write and read on `VERSION_LO` complete within the bound with BRESP/RRESP in {OKAY, DECERR} and BID/RID equal to the issued AWID/ARID. The response class is the deny of BlockByDefault; its liveness is `CHK-SMU-PORT-SMN-AXI-S1-CONTROL` in the same run

* *The verdict is usually the firmware's.* Most of these boot a real SEP DV

  and symbol table come from different firmwares, and reports a fail loop the
  linker garbage-collected as a path *not covered* rather than as passed. Its

=== Known Limitations

* *`smoke` is not a subset of `hosted`.* `smoke` is the two elaboration
  leaves plus `smu_smc_smoke_test` and `smu_sep_smoke_test`.
  `smu_ext_boot_seq_gate_test` is in `hosted` and `hosted_smoke`, not in
  `smoke`.

* *`all` includes SEP=1 leaves.* The names in `all` that compile under the
  real-SEP profile are the `all_with_sep_exec` group. The hosted credit set
  is `hosted`. Dual-firmware SRAM-bring-up leaves are in
  `sep_smc_sram_blocked` and not in `all`.
* *The wrapper is the surface.* `--dut smu` is the wrapper bench and carries
  `hosted` itself; its PASSes are labelled `DUT_TAG=WRAPPER` and are the
  density evidence. The bare block bench is `--dut smu_block`, whose PASSes
  carry `DUT_TAG=BARE` and are not feature credit.
* *The OUT catalog is `hw/sys/smu/doc/dv/SMU_DEFERRED_DISPOSITION.adoc`.* Some of its names
  are also enrolled in wrapper `all` on the SEP=1 track
  (`smu_sep_smoke_test` and `sep_real_fw` images) and are not in
  `hosted`; the rest are in no wrapper regression. The per-entry bucket
  and the condition each name needs are in that document.
* *Cross-trigger and iJTAG have no OCAH-local model*, so the coverage those
  interfaces get is what the DTP-under-SMU tests reach through JTAG.
* *No functional coverage closure target is set.* Coverage intent, the
  metric choice and what this plan may claim from a database are in
  `SMU_FCOV.adoc`; the wrapper `--dut smu` has no policy file of its own.
