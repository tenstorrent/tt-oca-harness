== SMU OCAH Open-Source Verification Plan

=== Overview

[cols=",",options="header",]
|===
|Field |Value
|Design Under Test |`smu #(.SEP(0))` through `hw/sys/smu/dv/tb/tb_top.sv`
|Framework |PyUVM on cocotb
|Primary simulator |Verilator
|Reference testbench architecture |`SMU_TB_ARCH.adoc`
|Live test bodies |59 under `cocotb/tests/`, 56 of them enrolled
|Enrolled leaf entries |54 in `sep0_p4_all`, 52 in `sep0_all`
|Non-enrolled inventory |28 bodies under `cocotb/tests_deferred/`
|===

This plan describes what the SMU open-source suite verifies and against which
RTL. The executable contract is the enrolled testlist groups; this document
describes them, it does not replace them.

=== Verification Strategy

The SMU is verified at its own boundary with `SEP=0`: the SMC and DTP
subsystems below it are real RTL, the SEP is not instantiated, and the external
SMN fabric is driven by the shared AXI VIP. Four surfaces are covered:

. *Fabric and address decode* — external SMN AXI into SMC, ID-width conversion,
  crossbar error handling, ATOP rejection, alias remap and the inbound and
  outbound filters, driven both from the external port and through JTAG2AXI.
. *SMC under SMU* — bring-up, reset control, mailbox, watchdog, GPIO straps and
  the security demote path, reached through the SMU rather than at the SMC
  boundary.
. *DTP under SMU* — primary JTAG, STAP selection, boundary-scan and iJTAG, the
  OTP bridge and the cross-trigger routing, as they appear once DTP sits under
  the SMU.
. *Clock, reset and boot sequencing* — clock-stop coordination, boot stall,
  IC_RESET domains and external boot-sequence gating.

Checking is centralised in `SmuScoreboard`, which refuses a vacuous PASS and
requires every mapped evidence token to have been proven by a real check. See
the checking strategy in `SMU_TB_ARCH.adoc`.

=== Naming Rules

[cols=",",options="header",]
|===
|Rule |Requirement
|Single-scenario module |Use the module name, for example `smu_clock_stop_coordination_test`
|Multi-scenario module |Use `+smu_<feature>_<scenario>_test+`, for example
`smu_axi_filter_in_instance_matrix_test`
|Scenario names |Use descriptive lower-snake-case names that encode operation,
mode, direction or coverage target
|Names from another subsystem |Normalise to `+smu_*+` and keep the target inside
the name, for example `smu_smc_wdt_sanity_test` for the SMC watchdog reached
through the SMU
|Open-source files |One PyUVM test class per scenario in `cocotb/tests/`, so
each scenario is independently selectable from a testlist. Sequences in
`seq_lib/` are shared where scenarios differ only in stimulus
|===

=== Open-Source BFM Policy

The BFM table lives in `SMU_TB_ARCH.adoc` so the testbench chapter and the plan
cannot drift apart. The policy itself: standard protocols use the shared OCAH
VIP packages, SMU-specific behaviour uses OCAH-local models under `env/`, and
no enrolled test may reach into the DUT with Force or deposit.

=== Known Limitations

* *`smoke` is not a subset of `sep0_all`.* `smu_ext_boot_seq_gate_test` is in
  `smoke` and `smc` but in neither `sep0_all` nor
  `sep0_p4_all`, so the nightly does not run a test every pull request does.
  #485 keeps it PR-only. Re-enrollment is a later #493 choice.

* *SEP=1 is out of scope here.* Everything in this plan runs with `SEP=0`. The
  dual-firmware SEP-under-SMU work is gated on the SEP instruction-fetch
  blocker and is not ported.
* *The wrapper is a separate surface.* `--dut smu_wrapper` proves production-pin
  boot and elaboration. Its PASSes are labelled `DUT_TAG=WRAPPER` and are not
  counted as `sep0_all` density evidence.
* *123 catalogued entries are not enrolled*, against 28 bodies under
  `cocotb/tests_deferred/`. The rest are named for catalog continuity and have
  no body at all. Per-entry v0.5.0 bucket, owner, and reintroduction trigger
  are in `SMU_DEFERRED_DISPOSITION.adoc`. None of those names is a v0.5.0
  restore.
* *Cross-trigger and iJTAG have no OCAH-local model yet*, so the coverage those
  interfaces get is whatever the DTP-under-SMU tests reach through JTAG.
* *No functional coverage closure target is set.* `smu_fcov.py` records
  scenario intent, but there is no agreed bin list to close against and no RTL
  code-coverage configuration checked in for this DUT.
