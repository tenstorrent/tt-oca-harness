[[smu-coverage-policy]]
== SMU coverage targets and closure policy

This chapter defines *what* the SMU release group is graded on and *how*
a hole is waived. It does not install a CI fail-on-hole gate; that gate
needs a measured database first.

[cols=",",options="header",]
|===
|Field |Value
|Release group |`--dut smu --items sep0_all` (live size in
`SMU_RELEASE_MATRIX.adoc`)
|Public metric |interface toggle: the `toggle_signal` family over the ports
of `smu_wrapper` (`smu_wrapper_uvm_top.u_dut`), a port counting once any of
its bits has toggled; plus the `user` points
|Numeric target |interface toggle floor 45 percent (the
`wrapper-interface-toggle` threshold in `smu_wrapper_coverage_policy.toml`,
below the 50.6 and 57.2 percent the first databases measured); the plan works
toward 85 percent
|===

`cov/sv/` carries eleven cover-property modules, 115 points in all; the counts
are the `OCAH_FCOV_COVER` invocations in each file. The block bench
`tb/tb_top.sv` instantiates nine of them and 84 points elaborate there; the
wrapper bench `tb/tb_wrapper_top.sv` instantiates ten and 111 points elaborate
on its single target, `compile_smu_chiplet`, which has SEP present.
`smu_alias_fcov.sv` and `smu_clk_fcov.sv` are wrapper-bench only --
`smu_clk_fcov` reads clock mirrors that only that bench publishes;
`smu_nosep_fcov.sv` is block-bench only, its points exist without SEP.

[cols="2,1,4",options="header",]
|===
|Module |Points |Spec area
|`smu_xbar_fcov.sv` |25 |Window programming and reprogramming, inbound AXI
handshake, all four response encodings, inbound traffic not forwarded outbound
|`smu_boot_fcov.sv` |21 |Reset-release edges, boot-stall sources and release,
lifecycle broadcast, fuse sense, SRAM auto-init
|`smu_rst_fcov.sv` |17 |Cold-reset assertion and release, per-domain reset

|`smu_nosep_fcov.sv` |4 |The SEP=0 composition: the direct converter path

|`smu_dtp_fcov.sv` |7 |Cross-trigger ports and XTRIG mode
|`smu_lc_fcov.sv` |6 |Lifecycle state broadcast and demotion
|`smu_alias_fcov.sv` |6 |Alias / remap manager scope at the SMU boundary

[[smu-cov-paths]]
=== Public versus commercial evidence

[cols="2,3,3",options="header",]
|===
|Path |What it collects |Where it runs
|Public Verilator |line / expr / toggle / user over
`smu_wrapper_cov_scope.vlt`, which drops the SEP, SMC and DTP trees, the
`hw/top` integration shells, vendored and generated RTL at compile time; the
runner derives `toggle_signal` from the toggle points |weekly `--cov` on the
large runner (`regress.yml`). Nightly does not collect.
|Public metric |`toggle_signal` scoped to `smu_wrapper_uvm_top.u_dut`: the
ports of the wrapper, one point per port, every one of them live because the
single target elaborates SEP |the `wrapper-interface-toggle` threshold,
evaluated on every `--cov` run of `--dut smu` and re-gradable with `--waive`
|Commercial |toggle / code / assertion databases under the licensed
flow |not a public CI job; not a substitute for the public weekly
|===

The DUT is an integration shell: `smu.sv` is wiring, and Verilator
emits no line / branch / expression sites under `hw/sys/smu/rtl/`.
That is why the metric is toggle rather than line or expression, and
why it is counted per port rather than per bit: a 256-bit struct port is one
interface, not five hundred and twelve. A Python `smu_fcov.py` sampler is not
the release metric and is not a gate.

[[smu-cov-out]]
=== Structural OUT versus a waiver hole

Three mechanisms. Do not mix them.

[cols="2,3,3",options="header",]
|===
|Kind |Effect |Carrier
|Structural OUT, by source file |the point never enters the database
|`coverage_off` file patterns (SMC, DTP, SEP, `hw/ip`, `hw/common`, CPU
cluster, TB, vendor trees the file pattern can reach)
|Structural OUT, by elaboration |the point is not elaborated, so it never
enters the database and no waiver names it |the `SepPresent` parameter and
its `g_sep` generate blocks in `cov/sv/*_fcov.sv`; a point whose observable
exists only with SEP elaborated is absent from a SEP=0 build, which is what
lets one Verilator policy grade both wrapper targets
|Waiver hole |the point exists and is not hit |`[[holes]]` with the
fields below
|===

A vendor site that `coverage_off` cannot name (hierarchy under `.u_smc`
/ `.u_dtp`) is a hole with `category = "out_of_scope"` and
`disposition = "exclude_scope"`. Write it only from a real database:
`expected_matches` is a hard count, and a guessed count is a
ConfigError on the first run.

[[smu-cov-waiver]]
=== Waiver fields

Every `[[holes]]` row must carry:

* `tool`, `metric_family` (the family that database holds: line / expr
/ user on `--dut smu`; `toggle` on `--dut smu_block`), `hierarchy` or
file selector
* `category` (`out_of_scope` / `excluded` / `waived` / `open`)
* `disposition`
* `owner`
* `review_date`
* `issue` when the disposition is actionable

`max_unclassified_points = 0` is the fail-on-new-hole knob. It is not
set here; it is set together with the threshold, from a measured weekly
`--cov` database.

A waiver reaches a finished run without a simulator:
`python3 tools/dv/run_dv.py --dut smu --run-dir <run> --waive` re-grades
the run's report against this policy and rewrites its coverage grade in
place. A dispatch of `dashboard.yml` with the weekly's regress run id does
the same for the published weekly. Both are described on the runner and
dashboard pages under `tools/dv/doc/`.
