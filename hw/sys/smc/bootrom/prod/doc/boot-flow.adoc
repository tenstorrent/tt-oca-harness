[[boot-flow]]
== Boot flow

The assembly entry path runs before any stack or writable global data is used.
After the C runtime is ready, hart 0 runs Phase 0 through Phase 5.
Other harts remain in the runtime's `wfi` loop.

=== Assembly early boot

`_enter` performs these operations in order:

. Clear general-purpose registers `x1` through `x31`.
. Call `__metal_sram_init_early`.
. Call the strong `__metal_mbist_early_check` implementation.
. Call the strong `__metal_memory_repair_check` implementation.
. Establish `gp`.
. Install `early_trap_vector` in `mtvec`.
. Clear coordination scratch registers 8, 9, 11, 13, and 14 while preserving scratch register 15.
. Establish a 16-byte-aligned stack for the current hart and call `_start`.

The C runtime copies initialized data from ROM, clears BSS, initializes TLS and constructors, synchronizes harts, and disables interrupt sources before calling `main` on hart 0.

Unused ROM is filled with the 32-bit `EBREAK` instruction.
Once the early trap vector is installed, a breakpoint whose `mepc` lies in the linker-defined padding range writes `0xBADF00D0` to scratch register 15 and loops.
Other early traps write `0xFFFFFFFF` to scratch register 0 and loop.

=== C boot phases

.Phase 0 -- initialization
Initializes POST tracking, the software OCCP status word, both status ring buffers, and scratch coordination.
It publishes the SEP ring-buffer offset and safe SRAM range, then sets the status-buffer-ready and SRAM-initialized bits.
After publishing that state, the implementation writes POST phase 2 before it
starts the phase 1 strap and eFuse work.

.Phase 1 -- straps, eFuses, and lifecycle
Caches the eFuse and strap fields used by the ROM.
The ROM validates the differential lifecycle encoding and halts on an invalid encoding or unsupported lifecycle value.
If `BL0_PLLCLK` is set, it calls `smc_pll_init`; the open implementation is a weak hook that returns success without programming a PLL.

.Phase 2 -- SRAM state
Records the SRAM setup phase again after phase 1 completes.
The actual conditional zeroing and memory-health checks have already completed in assembly.

.Phase 3 -- interface map
Marks I2C0, I2C1, I3C0, I3C1, and I3C3 enabled in the software map.
The current ROM uses one common map for all strap roles.

.Phase 4 -- OCCP ready
Initializes the fixed target-interface set, updates the OCCP interface status, and drives status GPIO 58 high on success or low on failure.
Any initialization error is fatal to the C boot flow.

.Phase 5 -- OCCP processing
Enters the non-returning command loop described in <<occp-command-processing>>.
The ROM records boot complete when the loop is entered; direct execution or authenticated handoff terminates command processing as described in <<occp-protocol>>.
