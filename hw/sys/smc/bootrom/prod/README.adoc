== Quick Start

1. Build from the harness root (or from this directory):
    ```
    # Release build (default)
    make -C hw/sys/smc/bootrom/prod

    # Debug build
    make -C hw/sys/smc/bootrom/prod BUILD_TYPE=debug

    # Explicit toolchain override (if not on PATH)
    make -C hw/sys/smc/bootrom/prod RISCV_TOOLCHAIN=/path/to/riscv64/bin
    ```

2. Verify the build outputs are present:
    ```
    ls hw/sys/smc/bootrom/prod/build/release/hex/
    # prod_rom.hex  prod_rom.preload.hex  prod_rom.ecc.hex  prod_rom.bin64
    ```


== Overview

The SMC production ROM provides basic system initialization and boot sequencing for the System Management Controller. It's designed as a minimal, standalone firmware that handles hardware setup and transitions control to the main application.

This ROM is intentionally small and focused - it gets the hardware into a known good state and then hands off to more sophisticated firmware. The build system is self-contained and doesn't require the full firmware infrastructure.

== Architecture

=== Core Components

The ROM is organized into several key areas:

* **Boot sequence** - Assembly startup and C runtime initialization (`boot/`)
* **Hardware drivers** - Strap pins, efuse access, basic peripherals (`drivers/`)
* **Status reporting** - Ring buffer system for logging and diagnostics (`lib/smc_ring_buffer.*` and `lib/smc_status.*`)
* **Security detection** - Device lifecycle and security mode (`lib/smc_security.*`)
* **Interface mapping** - I2C/I3C configuration based on device role (`lib/smc_interface_map.*`)
* **OCCP Command Processing** - Command processor to handle and respond to Open Chiplet Communication Protocol commands (`lib/occp.*` and `lib/smc_occp_status.*`)

The main application logic lives in `src/main.c` and follows a straightforward 6-phase boot sequence that's visible to external test equipment.

=== Hardware Integration

The ROM interfaces with several hardware subsystems:

**I3C Target Interface** - I3C target communication is abstracted behind a weak symbol hook in `drivers/src/i3c_target_driver.c`.
The default stub is a no-op so the ROM links on platforms without I3C hardware.
Link a strong-symbol driver override (via `NONFREE_DRIVER_SOURCES`) to program the vendor I3C IP.
See `drivers/include/i3c_target_driver.h` for the interface that any replacement driver must satisfy.

**Strap Configuration** - Hardware strap pins determine boot mode, chiplet role, and interface selection. See `drivers/smc_strap.*` for the complete API.

**Efuse Access** - Device identity, I3C addressing, and configuration data comes from efuse. The `drivers/smc_efuse.*` module handles all efuse operations.

**Security State** - The device lifecycle registers determine whether we're in production, development, or RMA mode. This affects which interfaces are enabled. Check `lib/smc_security.*` for the detection logic.

== Building and Testing

=== Building the ROM

Basic build commands:
----
make clean && make             # Release build (optimized, ~20KB)
make BUILD_TYPE=debug          # Debug build (~960KB, with console)
----

Release builds remove all debug code and console output to minimize size. Debug builds include full console support for development.

Build outputs go to `build/release/` or `build/debug/` with hex files, ELF binaries, and disassembly.

== Status Reporting System

The ROM includes a ring buffer system for status logging and diagnostics. This is useful for tracking boot progress and debugging issues in production.

=== Design

The system uses two fixed-size ring buffers (512 entries each) - one for SMC status and one for SEP status. The buffers are placed at the end of SRAM where they're naturally protected from stack overflow.

**Core ring buffer**: `lib/smc_ring_buffer.*` - Simple circular buffer with automatic wraparound.

**Status API**: `lib/smc_status.*` - Higher-level interface with structured 32-bit messages.

Message format: [31:28] Firmware ID, [27:24] Message Type, [23:0] Message Value

=== Memory Layout

The ring buffers live at the top of SRAM:
----
SMC SRAM (1MB total):
├── Application space (stack, heap, code)
├── SMC Status Buffer (512 entries at end-2048 bytes)
└── SEP Status Buffer (512 entries at end-1024 bytes)
----

This placement provides natural protection - stack overflow would hit the application before corrupting the status buffers.

== Hardware Configuration

=== Strap and Efuse Configuration

Hardware behavior is controlled by strap pins and efuse data. The `drivers/smc_strap.*` and `drivers/smc_efuse.*` modules provide access to this configuration.

Common strap settings control boot mode (I2C vs SPI), chiplet role (primary vs secondary), and various feature enables. Efuse data provides device identity, I3C addresses, and security configuration.

For testing, efuse configurations are in `meta/efuse/efuse_configurations/` (TOML format) and preload files are in `meta/efuse/efuse_preloads/`. The test environment uses plusargs like `+PRIMARY_CHIPLET`, `+BOOT_I2C`, etc. to control strap values.

=== Interface Selection

The ROM automatically determines which communication interfaces to enable based on the device role and security state.

**Interface mapping logic** (`lib/smc_interface_map.*`):
* I2C0: Enabled if boot strap indicates I2C mode
* I3C0: Primary chiplets only
* I3C1: All secondary chiplets
* I3C3: Non-secure secondary chiplets only

This ensures each device exposes the appropriate interfaces for its role in the system.

== Development Notes

=== File Organization

Key files and their purposes:
* `src/main.c` - Main application and boot sequence
* `include/smc_rom_defs.h` - Essential constants and definitions
* `drivers/` - Hardware abstraction (strap, efuse)
* `lib/` - Utilities (ring buffers, status reporting, security detection, OCCP command processing)
* `boot/` - Assembly startup and C runtime setup
* `linker/smc/smc_rom.ld` - Memory layout and section placement

=== Register Access

Basic register operations are in `lib/include/smc_defines.h`. Debug console functions (which become no-ops in release builds) are in `lib/include/virt_console.h`.

=== Toolchain

The build system automatically locates the RISC-V toolchain or you can set `RISCV_TOOLCHAIN` manually. All necessary build rules are self-contained in the local Makefile.
