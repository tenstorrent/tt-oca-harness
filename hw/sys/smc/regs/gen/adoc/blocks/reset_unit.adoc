.SS_CONFIG Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `ss_config` | RW | 0x0 a| Configuration registers to setup system configuration.
Usage is integration-specific; see the adopter chiplet specification.
|===

[cols="1,3,1,1,6", options="header"]
.SS_CONFIG_LOCK Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `config_lock` | RW | 0x0 a| Written to lock down SS config. If bit 0 is written, then bit 0 of other SS config
cannot be written to again
|===

[cols="1,3,1,1,6", options="header"]
.SS_COLD_RESET_N Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `reset_n_n0_scan` | RW | 0x0 a| Subsystem active low cold resets
|===

[cols="1,3,1,1,6", options="header"]
.SS_WARM_RESET_N Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `reset_n_n0_scan` | RW | 0xFFFFFFFF a| Subsystem active low warm resets
|===

[cols="1,3,1,1,6", options="header"]
.SS_CONFIG_HOLD Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `configuration_state_hold` | RW | 0x0 a| Used with warm_reset_n. Asserting ensures all registers configured during boot, including fuse values for
export compliance, SRAM repair, other fuse values, etc. are preserved
|===

[cols="1,3,1,1,6", options="header"]
.SS_SRAM_HOLD Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `sram_hold` | RW | 0x0 a| Used with warm_reset_n. Asserting ensures SRAMs, latch arrays and anything else that MBIST is
used to test and initialize during cold reset are preserved
|===

[cols="1,3,1,1,6", options="header"]
.SS_CRITICAL_HOLD Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `critical_signal_hold` | RW | 0x0 a| Used with warm_reset_n. Asserting ensures security, RAS, NMIs, perf counters, debug/trace and other
subsystem specific registers are preserved
|===

[cols="1,3,1,1,6", options="header"]
.SS_DEBUG_HOLD Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `debug_hold` | RW | 0x0 a| Used with warm_reset_n. Debug hold signal to ensure any debug registers are preserved
|===

[cols="1,3,1,1,6", options="header"]
.SS_RESET_COMPLETE Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `reset_complete` | R | 0x0 a| Response signal from subsystem to indicate reset (or some other critical step) has completed.
Bitwise write 1 to clear
|===

[cols="1,3,1,1,6", options="header"]
.SS_COLD_RESET_LOCK Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `cold_reset_lock` | RW | 0x0 a| Written to lock down SS cold reset. If bit 0 is written, then bit 0 of other SS cold reset
cannot be written to again
|===

[cols="1,3,1,1,6", options="header"]
.SS_FORCE_TO_REF_CLK Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `force_ss_to_ref_clk_n` | RW | 0x0 a| Forces clock to be ref clk. The ensures reset reaches all FFs within a subsystem in same clock cycle
|===

[cols="1,3,1,1,6", options="header"]
.SYNC_REG Register
|===
| Bits | Field | Access | Reset | Description
| 31:1 | `Reserved` | - | - a| Reserved
| 0 | `sync` | RW | 0x0 a| Set to assert global sync bit
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_REG Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `isolate_req_reg` | RW | 0x0 a| Isolate request. This prevents reset from being propagated to SS, keeping them alive in case of a cold reset
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_PINEN_REG Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `isolate_req_pinen_reg` | RW | 0x0 a| Isolate request pin enable. This enables the external isolate request pin to have an effect on ss isolate requests
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_SMC_REG Register
|===
| Bits | Field | Access | Reset | Description
| 31:1 | `Reserved` | - | - a| Reserved
| 0 | `isolate_req_smc_reg` | RW | 0x0 a| Isolate request smc. Asserted once cfg_flr_pf_active is asserted, de-asserted by sw
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_SMCEN_REG Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `isolate_req_smcen_reg` | RW | 0x0 a| Isolate request smc enable. This enables the FLR lock to have an effect on ss isolate requests
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_VIS Register
|===
| Bits | Field | Access | Reset | Description
| 31:9 | `Reserved` | - | - a| Reserved
| 8 | `cool_reset_n_o` | R | 0x1 a| Visibility bit for cool reset output
| 7:5 | `Reserved` | - | - a| Reserved
| 4 | `cool_reset_n_i` | R | 0x1 a| Visibility bit for cool reset input
| 3:1 | `Reserved` | - | - a| Reserved
| 0 | `isolate_req_pin` | R | 0x1 a| Visibility bit for isolate request pin
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_FLR_COUNTER_VALUE Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `isolate_req_flr_counter_value` | RW | 0x0 a| Number of cycles post cfg_flr_pf_active assertion is waited until cool_reset_n is asserted
|===

[cols="1,3,1,1,6", options="header"]
.ISOLATE_REQ_FLR_RESET_COUNTER_VALUE Register
|===
| Bits | Field | Access | Reset | Description
| 31:0 | `isolate_req_flr_reset_counter_value` | RW | 0x0 a| Number of cycles cool_reset_n is asserted for. NOTE: The cool reset flow requires this value to be greater than 0; a value of 0 will prevent initiation, regardless of ISOLATE_REQ_FLR_COUNTER_VALUE's value
|===
