[[smc-dv-functional-coverage-plan]]
== SMC OCAH Open-Source Functional Coverage Plan

=== Overview

This document defines functional coverage intent for the OCAH open-source SMC
testbench and its PyUVM/Verilator flow.

Verilator does not compile SystemVerilog `covergroup`, `coverpoint`, or
`cross`, but it does compile a labelled `cover property`. The SMC
open-source path therefore collects functional coverage on two levels:

* *Native cover-property points* in `hw/sys/smc/dv/cov/sv/`, written with
  `OCAH_FCOV_COVER` (`hw/common/assert/ocah_fcov_macros.svh`). Under
  `--coverage-user` these land in the simulator's own coverage database as
  the `user` metric family, so they reach `cov_merge`, `cov_report`, the
  coverage-policy engine and `threshold_met`. This is the only functional
  coverage the tooling can merge or gate on.
* *Python-side observation counters* in `SmcScoreboard`, which emit
  `FUNC_COV_VALUE` log lines. These stay useful for the DV-bookkeeping bins
  that have no RTL signal to observe (`protocol_vip`), but they are log text:
  no tool consumes them, and they are scraped by the aggregator script below.

SV covergroups mirroring the cover-property points live in the same
`cov/sv/` modules under ``ifndef VERILATOR`` and are collected only by the
commercial simulators, together with assertion and full code coverage.

|===
|Field |Value
|Reference VPLAN |`SMC_VPLAN.adoc`
|Reference architecture |`SMC_TB_ARCH.adoc`
|Open-source framework |PyUVM on cocotb
|Open-source simulator |Verilator

=== Coverage Goals

[cols=",,",options="header",]
|===
|Metric |Target |Open-Source Collection Path
|Functional coverage (gateable) |Every `cov/sv/` cover point either hit by the
approved release group or carried as a classified hole in the coverage policy
|`user` metric family in the native database (`--cov`)
|Functional coverage (observation) |Every `FUNC_COV_VALUE` bin named below is
hit by the enrolled `smoke` / `per_ip` suite |Python-side counters in `SmcScoreboard`
|Line/branch/FSM/condition coverage |Collected for signoff in the commercial
flow |VCS native coverage databases (`--cov --tool vcs`)
|Assertion coverage |Collected for enabled assertions in the commercial flow
|VCS `-cm assert` under the same `-cm_common_hier` scope, read in URG
|===

No numeric threshold is committed here.
Thresholds belong in `cov/config/<tool>/coverage_policy.toml` and only after
an owner approves a measured baseline, so a run cannot be graded against a
number nobody signed.

SAMPLE-only bins (`i2c_state`, `irq_state`, `gpio_state`, `axil_master`)
saturate at unique=1 until an active driver exists; growing them is a
stimulus problem, not a missing coverpoint. The `cov/sv/` modules therefore
do *not* mirror those tuples: a point that can only ever take one value
inflates the `user` percentage without proving anything. Each observable is
split into its own point instead, so an undriven source shows up as a named
hole the coverage policy can carry with evidence.

[[native-cover-points]]
=== Native cover points (`cov/sv/`)

The modules below are compiled into both flows (registered in
`smc_sim_cfg.toml` under `[build].sources` and repeated in
`[frameworks.uvm.build].sources`) and instantiated in `tb/tb_top.sv` inside
`smc_uvm_top`, in the single-instance body only -- the `SMC_DUAL` port
surface is narrower and does not carry these observables. Every port is a
`smc_tb_signal_list.svh` signal, so no hierarchical reference and no
`smc_public_scope.vlt` change is required.

[cols=",,,",options="header",]
|===
|Module |Points |Area |Point families

|`smc_clk_fcov.sv` |40 |`clk_bucket` |Domain-ratio windows (ref vs smc vs

The sixteen modules carry 467 cover-property points in all. Point counts are
the `OCAH_FCOV_COVER` invocations in each file.

`protocol_vip` has no RTL signal to observe -- it is a DV-bookkeeping ledger
of promoted tests -- so it has no `cov/sv/` module and stays on
the Python path.

Point naming is `c_<area>_<point>`, which makes the coverage-policy
hierarchy selector `smc_uvm_top.u_smc_<area>_fcov.c_<area>_<point>`; for the
per-manager AXI points it is
`smc_uvm_top.u_smc_fabric_fcov.u_<manager>.c_<point>`.

A point must need stimulus beyond power-up and reset release. The quiescent
half of a pair — a closed gate, an idle bus, a released open-drain line — is
true from reset with nothing driving it, so covering it proves nothing and
inflates the `user` percentage exactly the way the saturated Python tuples
do. Those halves are either dropped (`c_axil_all_masters_idle`, the GPIO
`_idle` levels, `c_i2c0_disabled`, `c_i2c0_smbalert_released`) or qualified
by a sticky flag recording that the active half was seen first, which turns
"closed" into "closes again after opening" and "idle" into "returned to idle
after working". `c_gpio_boot_stall_pad_*` is qualified by the pad having
changed at least once, because which of its two values is the power-on
default depends on the straps.

Two conventions are load-bearing:

* Every cover-property body and disable-iff argument is a single
  continuous-assign wire (the `dtp_fcov.sv` convention; Verilator's
  localization pass otherwise ICEs).
* A `//` comment must not open with the word "verilator" -- the lexer reads
  it as a pragma and `BADVLTPRAGMA` fails the build. Likewise, a `define`
  parameter list must stay on one line: Verilator does not register the
  first parameter after a line continuation, and the unsubstituted parameter
  name survives into elaboration.

`smc_reset_fcov.sv` gates its points on powergood rather than reset, because
a reset-assertion point behind `disable iff (in reset)` can never fire.

=== Coverage Definitions

[[how-it-works]]
`hw/sys/smc/dv/cocotb/env/smc_scoreboard.py` maintains event bins and emits a
`FUNC_COV_VALUE bin=<name> value=<...>` log line on every observation.

==== `reset_op`

*Description*: Covers each `SmcResetOp` enum hit (SAMPLE, COLD_RST_LO/HI, …).

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Reset operation |all 8 `SmcResetOp` values
|===

==== `reset_state`

*Description*: Covers the 4-tuple of post-reset stable signals, including
mid-glitch via RAW_SAMPLE.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Post-reset tuple |ceiling 3 (DUT synchronously releases bits)
|===

==== `i2c_state`

*Description*: (resolvable, cg_en). Unique count stays 1 until I2C clock-gate
toggle stimulus exists.

==== `clk_bucket`

*Description*: `(ref_edges // 50, smc_edges // 50, periph_edges // 50)`. Grows
with seed count because `randomize_timing(seed)` varies clock periods and
`smc_clk_multi_window_test_seq` picks random window sizes per seed.

==== `irq_state`

*Description*: `(sync_irq, gpio_irq_any, uart_irq_any)`. Unique count stays 1
until an IRQ source is actively driven.

==== `gpio_state`

*Description*: `(core2pad_any, core2pad_en_any, pad2core_en_any)`. Unique count
stays 1 until a GPIO driver is bound.

==== `axil_master`

*Description*: `(any_master_active,)`. Unique count stays 1 until AXI master
traffic is present; CSR tests grow this through SEP_IN.

==== `protocol_vip`

*Description*: `SmcProtocolVipItem` kind/test/proxy triple. Grows with each
promoted protocol-VIP test.

[cols=",",options="header",]
|===
|Flow |Strategy
|Verilator open-source CI (graded) |Native database: `line`, `branch`,

[[coverage-scope]]
==== Coverage scope

Both flows scope the denominator at *compile* time, following what SEP
measured (`hw/sys/sep/dv/cov/config/vcs/README.md`): a report-time filter
prunes the report pages and still grades the whole database.

[cols=",,",options="header",]
|===
|File |Flow |Mechanism
|`cov/config/verilator/smc_cov_scope.vlt` |public CI (graded)
|`coverage_off -file`, globs
|`cov/config/vcs/smc_cov_scope.hier` |commercial signoff
|`-cm_hier` + `-cm_common_hier`, instance trees
|===

They express the same intent in two forms the simulators cannot share —
Verilator has no `-module` form for `coverage_off`, and no `-tree` reaches the
pulp glue that VCS would have to name — so they must be kept in step by hand.
`cov/config/vcs/README.md` records what each scoped number is, how to
measure a scope change, and the VCS bring-up checklist.

The scoped Verilator number is *the SMC DUT minus the CPU cluster, the I3C
core, the lowRISC prims and TB code*. `vendor/pulp-platform/**` and
`vendor/tenstorrent/tt-hw-debug/**` stay in the denominator — no file pattern
reaches them, which `cov/config/vcs/README.md` records. Do not quote the
number as "SMC coverage".

[[aggregator-script]]
==== Aggregator script

Scans one or more run dirs and reports unique events per bin plus the union
across runs.

[source,python]
----
#!/usr/bin/env python3
"""Aggregate SMC OSS functional coverage events across run dirs.

Usage:
    python3 aggregate_cov.py <run_dir> [<run_dir> ...]
    # Lists per-run + UNION counts of FUNC_COV_VALUE events.
"""
import sys
import re
import glob
from collections import defaultdict

def collect(run_dir: str) -> dict[str, set[str]]:
    bins: dict[str, set[str]] = defaultdict(set)
    for log in glob.glob(f"{run_dir}/**/*.log", recursive=True):
        try:
            with open(log) as f:
                for line in f:
                    m = re.search(r"FUNC_COV_VALUE bin=(\S+) value=(.+)$", line.rstrip())
                    if m:
                        bins[m.group(1)].add(m.group(2))
        except OSError:
            pass
    return bins

def main(argv: list[str]) -> int:
    if len(argv) < 2:
        print(__doc__)
        return 2

    union: dict[str, set[str]] = defaultdict(set)
    for run_dir in argv[1:]:
        bins = collect(run_dir)
        print(f"=== {run_dir} ===")
        for b in sorted(bins):
            print(f"  {b:14s} unique={len(bins[b]):3d}")
            union[b] |= bins[b]
        print(f"  TOTAL={sum(len(v) for v in bins.values())}")
        print()

    if len(argv) > 2:
        print("=== UNION ===")
        for b in sorted(union):
            print(f"  {b:14s} unique={len(union[b]):3d}  sample={sorted(union[b])[:4]}")
        print(f"  TOTAL={sum(len(v) for v in union.values())}")
    return 0

if __name__ == "__main__":
    sys.exit(main(sys.argv))
----

[[sec-4-simulator-side-coverage]]
==== Commercial simulator collection

`--cov --tool vcs` instruments the build with
`-cm line+cond+tgl+fsm+branch+assert`, scoped at compile time by
`cov/config/vcs/smc_cov_scope.hier` (`-cm_hier` plus `-cm_common_hier`, so one
scope file governs code and assertion coverage), and writes one native
database per test leaf:

....
<run_dir>/<test>/coverage/simv.vdb
....

The `cov_merge` / `cov_report` stages merge the per-leaf databases with `urg`
into `<run_dir>/cov/merged.vdb` and report from there.
`cov/config/vcs/README.md` carries the VCS bring-up checklist and how to
measure a scope change.

`smc_sim_cfg.toml` has `[coverage.vcs]` and `[coverage.verilator]` tables and
no `[coverage.xcelium]`: Xcelium builds and runs the same tests, but there is
no SMC coverage scope for it and no Xcelium number is graded.
