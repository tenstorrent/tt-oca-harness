[[smc-dv-functional-coverage]]
== SMC OCAH Open-Source Functional Coverage Plan

=== Overview

This plan covers the legal operating modes of the SMC subsystem that the
`smc_wrapper` bench can present, and states which of them the suite must
reach. It is the functional-coverage contract for the cocotb/PyUVM flow.

The functional points are SystemVerilog cover properties in
`hw/sys/smc/dv/cov/sv/`, written with `OCAH_FCOV_COVER`. Each collector is a
passive module that `tb/tb_top.sv` instantiates once and drives from
`smc_tb_signal_list.svh` signals and `smc_wrapper` boundary ports; none of
them drives anything. Unlike `OCAH_COVER`, the macro stays live on every
simulator, so the same points land in the `user` family of a Verilator run
and of a VCS run. `smc_fabric_fcov` instantiates `smc_axi_chan_fcov` once per
inbound manager (`u_sep_in`, `u_sys_in`, `u_jtag_axi`), so those points exist
once per instance.

Several collectors also carry covergroups under `ifndef VERILATOR`. They are
the commercial simulator's `group` metric, crossing what a flat point list
cannot. They are not part of the `user` family, and <<smc-fcov-groups>>
states the contract they are held to.

Feature checkers stay on the VPLAN scorecard. A cover point records that the
suite presented a legal event and that it completed; the claim that the
response was right belongs to the checker of the leaf that reached it.

[cols=",",options="header"]
|===
|Field |Value
|DUT |`smc_wrapper`
|Reference specification |`hw/sys/smc/doc/`, the generated map `hw/sys/smc/regs/gen/`
|Reference VPLAN |<<smc-vplan,SMC_VPLAN>>
|Open-source framework |cocotb with PyUVM
|Simulators |Verilator (public), VCS (commercial)
|===

[[smc-fcov-goals]]
=== Coverage Goals

[cols="2,2,3",options="header"]
|===
|Metric |Contract |Collection path
|Phase 1 functional coverage |Every compiled cover point hit; no accepted
waiver for a `user` point |`user` family of a `--dut smc --items hosted fw
--cov` run, Verilator or VCS
|Phase 2 functional coverage |The named set in <<smc-fcov-phase2>> |Not collected
|Line / branch / expression |Targets, not gates: the figures the coverage set
measures on the run <<smc-fcov-owners>> names (its commit and simulator). No
floor is set |`--coverage-line`, `--coverage-expr`
|Condition / FSM / toggle / assertion / covergroups |Commercial sign-off |VCS
|===

The coverage set is `--dut smc --items hosted fw`: the package regression
`all` less the three `sanity` leaves, whose second build target the coverage
merge cannot combine with `default` (SEP names its set the same way, `all`
less `rom_fw`). `hosted` alone is the toolchain-free nightly and weekly tier
(`regress.yml`); the fw leaves need the RISC-V toolchain, so the run of record
is a developer or self-hosted run. `--dut smc` already instantiates
`smc_wrapper`; there is no second wrapper job.

`cov/config/verilator/coverage_policy.toml` carries one
`pass:[[[thresholds]]]` row, on the `user` family, with
`max_unclassified_points = 0`: it fails
`run_dv --dut smc --items hosted fw --tool verilator --cov` on any point that
is neither hit nor classified. No code-metric family carries a floor, on
either tool. DTP and SEP each set none and say why -- a run's status comes
from its tests, and a threshold without an agreed score target fails runs
without saying anything true -- and the line, branch and expression
populations here still hold unclassified vendor and generated-CPU points that
`smc_cov_scope.vlt` cannot drop, so a floor over them would grade a
denominator this package does not own. The figures above are what the
coverage set measures and what a closure reading compares against. The VCS
policy, `cov/config/vcs/coverage_policy.toml`, names the exclusion files the
report applies and grades no floor either.

Do not mix line coverage with the Phase 1 points: the line population of this
DUT would mask them.

[[smc-fcov-scope]]
=== Two-Phase Scope

[cols="1,4",options="header"]
|===
|Phase |Scope
|**Phase 1** |Every cover point compiled into the collectors below. Each
records a legal behaviour of this bench that a named `all`-group leaf walks,
expressed against the specification or the generated map.
|**Phase 2** |Points that need a mode this bench cannot present: a responder
the bench leaves out by policy, a stimulus shape the bench manager cannot
drive, an input clock stopping, a strap capture the reference integration
does not implement. Each sits under `ifdef SMC_FCOV_PHASE2`, which no target
defines, and is listed in <<smc-fcov-phase2>> with what would bring it back.
|===

A point is closed by a hit, by rewriting it to express the behaviour the
specification describes, or by moving it to Phase 2 with its reason. A point
that describes an event the design cannot produce under any stimulus (an
encoding no subordinate returns, a region the map does not have) is removed,
not deferred: there is no later phase in which it becomes reachable.

[[smc-cov-paths]]
=== Collection

[cols="2,3,3",options="header"]
|===
|Path |What it collects |Where it runs
|Public Verilator |line, branch and expression (`--coverage-line`,
`--coverage-expr`) plus the `user` family from the `cov/sv/` cover
properties, scoped at compile time by `smc_cov_scope.vlt` |local
`run_dv --dut smc --items hosted fw --tool verilator --cov`. Nightly and
weekly `hosted` do not collect (`coverage: false` in `regress.yml`)
|Commercial |code, assertion, the `user` family and the covergroups under
`ifndef VERILATOR` |licensed VCS; not a public CI job
|===

The address windows are the generated map's. Unit bases, strides and
instance counts come from `smc_top_addrmap_pkg`; a unit's aperture is the
`Size` column and its top the `Decoded Extent` column of
`regs/gen/adoc/memory_map.adoc`, whose functional-organization table also
gives the layout regions. Placements inside the adopter external window are
the reference integration's, from `bootrom/prod/registers/smc_top_regs.h`
(`SMC_TOP_SMC_EXTERNAL_*`). A collector attributes a response to an address
only while exactly one transaction is outstanding in that direction, so an
overlapped burst under-counts rather than pairing one access's response with
another's address.

`FUNC_COV_VALUE` log text from `SmcScoreboard` is not a mergeable metric.
Nothing under `tools/` or `.github/` reads it; do not credit it as the
functional-coverage gate. SAMPLE-only Python bins that saturate at unique=1
(`i2c_state`, `gpio_state`, `irq_state`, `axil_master`) are stimulus holes,
not coverpoints to publish as 100%; the collectors carry their intent as one
point per observable.

[[smc-fcov-groups]]
=== Covergroups

Every covergroup bin and cross cell is either walked by an `all`-group leaf
or carried as an `ignore_bins` whose comment states the specification or bench
fact that keeps it out of reach, the way the cover points are held. The bins
and cells that fact removes:

[cols="2,2,4",options="header"]
|===
|Group |Bin or cell |Why it is ignored
|`smc_rst_seq_fcov::cg_primary_holds` |`cp_fabric` released |The primary
reset covers the fabric infrastructure (`clk_rst.adoc`, Primary Reset), so
both SEP_IN ready terms are low for the whole hold
|`smc_fabric_fcov::cg_sep_in_shape` |`cp_wstrb` none |The bench AXI manager
cannot present a zero-strobe beat; the matching cover point is in
<<smc-fcov-phase2>>

|`smc_iso_fcov::cg_isolate_terms` |Software term set, nothing isolated |Each

|`smc_clk_fcov::cg_clk_ratio` |SMC and peripheral stalled buckets

|The frontend clock runs whenever the backend clock does, with the same

`cg_map_access` grades a completion against a refusal rather than the
response code: `memmap.adoc` and `fabric.adoc` say an address is refused but
fix no code. `cg_sep_in_shape` crosses every AxSIZE with every burst type;
`smc_sep_in_axi_shape_test` issues FIXED and WRAP bursts at each size, which
the SEP_IN path refuses, and the cells record the refusal at that size.

A gated clock is observed through a flop it toggles itself, and the gate
terms it is crossed with are taken one sample late, because a movement seen at
one sample is the edge the gate let through on the previous cycle. Sampling
the clock net on the edge of the clock it is gated from reads the same level
whether it runs or not.

[[smc-coverage-policy]]
=== Closure Policy

[[smc-cov-out]]
==== Structural OUT, Phase 2 and waiver holes

[cols="2,3,3",options="header",]
|===
|Kind |Effect |Carrier
|Structural OUT |the point never enters the database |compile-time
scope (`coverage_off` / VCS hier). Vendored RTL and the
chipyard-generated CPU cluster are SMC-level OUT; they are not this
package's to close.
|Phase 2 |the point is not compiled |`ifdef SMC_FCOV_PHASE2` in the
collector, listed in <<smc-fcov-phase2>>
|Waiver hole |the point exists and is not hit |`coverage_policy.toml`
`\[[holes]]`, written from a measured run
|===

A `user` point takes no accepted waiver. A collected point the run of record
leaves unhit is an open hole with an owner until a leaf reaches it, the point
is corrected, or it moves to Phase 2. The code-coverage families keep their
waivers; they carry no floor.

`\[[holes]]` is written from a measured `--dut smc --items hosted fw --cov`
database. `expected_matches` is a hard count.

[[smc-cov-waiver]]
==== Waiver fields

Every `\[[holes]]` row must carry the fields `coverage_policy.py`
requires:

* `tool`, `metric_family`, hierarchy or file selector (`\[[holes.native]]`)
* `category` (one of the runner's hole categories; this file uses
`missing_stimulus`, `needs_review` and `unreachable`)
* `disposition`, `status`, `confidence`, `rationale`
* `owner`, `reviewer`
* `issues` when the disposition is actionable

`max_unclassified_points = 0` on the `user` row is the fail-on-new-hole
knob, and the `user` row is the only `\[[thresholds]]` row in either policy
(<<smc-fcov-goals>>).

A waiver reaches a finished run without a simulator:
`python3 tools/dv/run_dv.py --dut smc --run-dir <run> --waive` re-grades
the run's report against this policy and rewrites its coverage grade in
place. A dispatch of `dashboard.yml` with the weekly's regress run id does
the same for the published weekly. Both are described on the runner and
dashboard pages under `tools/dv/doc/`.

There is no checked-in 98%-after-waiver figure. SMC does not inherit
an unwritten default. Do not invent one.

[[smc-cov-reopen]]
==== Reopen triggers

An accepted exclusion or waiver stays accepted until the policy changes; the
calendar does not reopen it. It reopens, by the entry being removed at the
next regeneration or by a `pass:[[[holes]]]` entry's status returning to
`open`, when:

* an RTL change moves the module or instance checksum of the scope the entry
  names, which drops the entry on its own, since URG applies no entry whose
  checksum differs from the design it reports on;
* an enrolled leaf covers the point: the nine per-run files are written from
  each graded run's uncovered set, so a covered point is not written again,
  and the runner rejects an accepted `pass:[[[holes]]]` entry whose selector
  matches a covered point;
* the retiring condition the class's ANNOTATION states is met -- for the
  reviewed classes, design engineering withdrawing the review recorded in
  `smc_reviewed_exclusions.toml`;
* the policy's `scope_epoch` changes, or the compile-time scope
  (`smc_cov_scope.hier`, `smc_cov_scope.vlt`) changes which points enter the
  database;
* a regenerated list is written from a new graded run, which replaces every
  entry the run no longer leaves uncovered;
* for the unreachability list, the pinned SHA-256 and the file differ, which
  makes the runner refuse the policy until a new entry is written.

[[smc-fcov-unreachability-list]]
==== Unreachability exclusion list

`cov/config/vcs/smc_unreachable.el` is the URG exclusion list of the
code-coverage points that a formal unreachability analysis proves no stimulus
reaches in the bench's environment. That environment is `smc_wrapper` as the
cocotb bench instantiates it:

* every input the bench ties to a constant holds that value: the DTP CSR
  response idle, the eFuse security-disable input low, the SRAM auto-init
  bypass high, the BISR and MBIST status inputs done, successful and passed,
  the scan reset released, the cross-trigger, TDR clock-stop and external debug inputs at
  zero, the external interrupts above the bench's seventeen pins low, AW.ATOP
  zero on every inbound manager, the telemetry receivers above the bench's
  three idle and the CPU JTAG identity at the bench's constants;
* the three domain clocks have no fixed ratio or phase between them, since
  under `+pll_osc_bench` each follows a bench clock whose period the leaf
  chooses; the PLL model is left out of the formal model, and the telemetry
  write clock, which the bench ties to the SMC clock, is free as well;
* the state the bench's fault-injection hooks force, the zeroer and eFuse
  interface state registers and the eFuse read-error and secure-test-mode
  inputs, takes any value at any cycle;
* every other input is free: power-good, the cold and cool resets, the test
  enable and the abort inputs among them.

The CPU cluster and its memory macros, the I3C controllers, the generic pad
cell, the trace sink macro and the behavioural PVT and eFuse bank models are
left out of the formal model, so whatever they drive into the SMC is free.
Each of these choices can only leave a point reachable that the bench never
reaches, never the reverse. The CPU cluster, the I3C controllers and the
library cells are outside the compile-time scope, so none of their points is
analysed.

The analysis runs in the runner's formal mode from a configuration that is not
in this repository; a reader without it runs their own unreachability tool
over the same database with the same environment and writes the same URG
exclusion format.

The accepted list is seeded from the merged database of the commercial-path
`--items hosted fw` regression (<<smc-cov-paths>>), so it targets the points
that regression left uncovered, and it runs on the RTL that produced that
database, because the formal model and the seed must describe one RTL.

A re-run of the analysis over the accepted list is a check that no accepted
entry has become reachable, not a source of the list: a list seeded from a
group smaller than the coverage set (the `smoke` group, for one) leaves far
more points uncovered, so it proves a larger exclusion set and leaves a
smaller effective population behind it. A signoff-grade list takes a hand-run
coverage-set seed, and a list of unrecorded provenance is not one.

The `pass:[[[native_files]]]` entry of `cov/config/vcs/coverage_policy.toml`
that names the list pins the file's SHA-256. The runner refuses the policy
when the file and the pinned digest differ, so a regenerated list takes a new
entry. URG applies no entry whose module or instance checksum differs from
the design it reports on, so an RTL change under an excluded scope drops that
scope's exclusions on its own.

Regeneration rule: after a change to the SMC RTL file set, the list is
regenerated from the merged database of a fresh `--items hosted fw`
regression. Until it is, URG drops the entries of every scope whose checksum
the change moved, and the entries of the other scopes still apply; the
analysis's check mode over the accepted list fails when an excluded point has
become reachable. A regenerated list
takes design review before its entry changes, and the review accepts no entry
that stimulus can reach.

[[smc-cov-owners]]
=== Owning tests

SEP's coverage plan names, for every covergroup, the leaf that has to fill
it: a hole is not gradable without knowing which test was supposed to fill
it. Which leaf lights a `cov/sv` point is a property of a run, not of the
source, so SMC measures the table rather than writing it. The include below
is regenerated from the coverage run's directory:

    python3 tools/dv/fcov_owners.py --dut smc --run-dir <run dir> \
        --output hw/sys/smc/dv/docs/SMC_FCOV_OWNERS.adoc

`--check` in place of a rewrite says whether the committed table still
matches the run. A row with `Leaves` of 1 is a point one leaf alone reaches,
which goes dark when that leaf is retired or narrowed; a row with 0 carries
the policy disposition of the hole, or `unclassified` when the policy has
none.
