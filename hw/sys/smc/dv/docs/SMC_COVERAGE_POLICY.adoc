[[smc-coverage-policy]]
== SMC v0.5.0 coverage targets and closure policy

This chapter records the #501 decision. It approves *what* the SMC
release group is graded on and *how* a hole is waived. It does not
install a CI fail-on-hole gate; that is #507, after a measured
database exists and the owner signs a number. Collection of a native
`user` family is #1638. Project-wide collection mechanics stay on
#528.

Do not treat a merged copy as design-owner or DV-lead sign-off.

[cols=",",options="header",]
|===
|Field |Value
|Status |CANDIDATE — awaiting SMC design owner + DV lead approval
|Release group |`--dut smc --items smoke` (live size in
`SMC_RELEASE_MATRIX.adoc`). `--dut smc` already instantiates
`smc_wrapper`; there is no second wrapper job.
|Public metrics |line, branch, and (once #1638 merges) native `user`
|Numeric target |none until an owner signs a measured number
|===

[[smc-cov-paths]]
=== Public versus commercial evidence

[cols="2,3,3",options="header",]
|===
|Path |What it collects |Where it runs
|Public Verilator |line + branch today (`--coverage-line`,
`--coverage-user` with no cover point on `main`). #1638 adds
`--coverage-expr`, compile-time scope, and `cov/sv/` cover properties
so the `user` family is real |weekly `smoke` already sets
`coverage: true`. That is collection, not a signed gate.
|Commercial |code + assertion + covergroups under `ifndef VERILATOR`
|licensed VCS / Xcelium; not a public CI job
|===

`FUNC_COV_VALUE` log text from `SmcScoreboard` is not a mergeable
metric. Nothing under `tools/` or `.github/` reads it. Do not credit
it as the release functional-coverage gate.

There is no checked-in 98%-after-waiver figure. SMC does not inherit
an unwritten default. Do not invent one.

SAMPLE-only Python bins that saturate at unique=1 (`i2c_state`,
`gpio_state`, `irq_state`, `axil_master`) are stimulus holes, not
coverpoints to publish as 100%.

[[smc-cov-out]]
=== Structural OUT versus a waiver hole

[cols="2,3,3",options="header",]
|===
|Kind |Effect |Carrier
|Structural OUT |the point never enters the database |compile-time
scope (`coverage_off` / VCS hier). Vendored RTL and the
chipyard-generated CPU cluster are SMC-level OUT; they are not this
package's to close.
|Waiver hole |the point exists and is not hit |`coverage_policy.toml`
`[[holes]]` once #1638 lands the file and #507 fills it from a run
|===

Do not write `[[holes]]` or `[[thresholds]]` before a database exists.
`expected_matches` is a hard count.

[[smc-cov-waiver]]
=== Waiver fields

Every `[[holes]]` row that #507 writes must carry:

* `tool`, `metric_family`, hierarchy or file selector
* `category` (`out_of_scope` / `excluded` / `waived` / `open`)
* `disposition`
* `owner`
* `review_date`
* `issue` when the disposition is actionable

`max_unclassified_points = 0` is the fail-on-new-hole knob. #507 sets
it after the owner signs. Weekly `coverage: true` without that knob
is not a release coverage gate.
