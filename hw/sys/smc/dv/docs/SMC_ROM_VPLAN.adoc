== SMC Boot ROM Firmware Verification Plan

=== Overview

[cols=",",options="header"]
|===
|Field |Value
|Design Under Test |The production SMC Boot ROM (BL0), `hw/sys/smc/bootrom/prod`, executing on the target instance of the dual-SMC model, or on the single-SMC model for the eFuse shadow override
|Platform |The `dual` RTL target in `smc_sim_cfg.toml`: two SMC instances on a shared I3C bus. |Repository |`tt-oca-harness`
|Project |OCAH
|Framework |cocotb, with the OCCP checks in the controller firmware
|Primary simulator |Verilator
|Design specification |The SMC Boot ROM chapters that `hw/sys/smc/bootrom/prod/doc/index.adoc` includes, and `hw/sys/smc/doc/rom.adoc` for the ROM region and reset vector
|Error and status codes |`hw/sys/smc/bootrom/prod/include/smc_occp_error_codes.h` and the ring-buffer status values in `status-coordination.adoc`
|Register sources |`hw/sys/smc/regs/` (SystemRDL) and the generated export `hw/sys/smc/regs/gen/`
|Testbench architecture |<<smc-dv-testbench-architecture,SMC_TB_ARCH>>

This plan is the technical contract for the SMC Boot ROM firmware tests. It
states what each test drives, what it observes, which checkers can fail it, and
which sections of the ROM specification it claims. <<smc-vplan>> grades only
its `all` group, which holds none of these tests.

The DUT is firmware. The RTL is the platform that executes it. A test proves a
ROM behaviour only through state that the ROM makes visible: the OCCP responses
on the bus, the scratch registers, the POST word, the status ring buffers and
the target memory.

=== Verification Strategy

[[smc-rom-vplan-stimulus]]
==== Stimulus

The ROM image is the production build. A test changes the inputs of the ROM,
never the ROM itself.

* *ROM image.* Every build stage of these tests builds `hw/sys/smc/bootrom/prod` with `I3C_CORE=chipsalliance` and `ENABLE_RELEASE_PRINTS=1` (virtual console only) into `prod_rom.bin64`, and `+rom_bin64` loads it into both instances.
* *Controller.* `+bfm_rom_hex` replaces the controller ROM with a DV image from `hw/sys/smc/dv/fw/tests/<name>/`, linked with the OCCP controller library in `hw/sys/smc/dv/fw/common/occp/`. The image sends the OCCP sequence of the test.
* *Straps and lifecycle.* `smc_dual_base_test` forces the per-instance straps before strap capture. `+BOOT_I3C` selects I3C and `+lc_state` sets the target lifecycle. `STATUS_RPT_DISABLE` is drawn from the seed: when it is set, every GetStatus must return error 0x07 (Unsupported_StatusID), and the status-value checks run only when it is clear. `+FORCE_STATUS_REPORTING` clears it and `+STATUS_RPT_DISABLE` sets it; `smc_occp_boot_sequence_status_test` and `smc_sep_ring_buffer_test` pass `+FORCE_STATUS_REPORTING` because they read entries back. `+MEM_REPAIR_BYPASS` and `+MEM_BIST_BYPASS` set the target bypass straps. `bring_up(dut_primary=, dut_recovery=)` sets the target `PRIMARY_CHIPLET` and `BOOT_RECOVERY` straps, and `chiplet_is_primary` follows `PRIMARY_CHIPLET`; the controller stays primary.
* *eFuse.* `env/smc_efuse_stimulus.py` regenerates the eFuse image for the run seed before cold reset, on both targets. `+fuse_transport_timeout` pins the OCCP transport timeout, `+fuse_i2c_ids` programs I2C ID slots 6 and 7 with two distinct seeded addresses, and `+fuse_dft_ignore_error=0|1` sets `SMC_CONFIG.dft_ignore_error`. On the single-SMC target the `ej_axi` AXI-Lite manager drives the JTAG-facing eFuse port.
* *DFT status.* `+dft_scenario` (terminal) or `+dft_continue_case` (continuation) drives the target memory-repair and MBIST status lines to a failure pattern. Without either, the lines are tied to passing.
* *Cold reset.* `smc_prod_rom_mid_boot_cold_reset_test` pulls the shared `rst_cold_ni` pin low during a target boot and holds it until the primary reset asserts.
* *Payload.* `+occp_payload_bin` and `+occp_payload_sym` supply the image that the hand-off tests transfer or stage.
* *SEP ring buffer.* The dual bench has no SEP. `env/smc_sep_ring_buffer_driver.py` takes its place and writes SEP status entries into the target SEP ring buffer over the target AXI port, plus a mirror copy in controller SRAM that the firmware compares against when `STATUS_RPT_DISABLE` is clear. `+sep_rb_entries` sets the entry count (drawn from the seed when absent), `+sep_rb_terminal` makes the first two entries the SEP status 0x01010001 and the SEP terminal signature-failure error 0x0F01000E, and `+sep_rb_case` only labels the case.

[[smc-rom-vplan-checking]]
==== Checking

* *Controller firmware.* The rom-only tests check each OCCP response in the controller firmware: header, error code, CRC and body. The firmware reports the result through `TEST_PASS` or `TEST_FAIL` in scratch 0.
* *Driver verdict.* `smc_occp_rom_only_test` polls scratch 0 of both instances. `TEST_FAIL` in either instance, or the end of the poll budget, fails the test.
* *POST word.* Target scratch 1 carries the boot phase and error fields. The lifecycle and hand-off tests judge it.
* *Scratch contract.* Scratch 8, 9 and 15 carry the manifest address, the ready flags and the DFT result.
* *Evidence.* `dual_test` fails a test that does not log every `CHK-<ID>` in its `REQUIRED_EVIDENCE`. Each procedure group names those IDs.
* *Halt.* A terminal test samples the target hart 0 retired PC and requires a span of a few PCs for a fixed window.
* *Per-hart retirement.* The dual bench exports the retirement record of every target hart. `smc_rom_boot_hart_gate_test` samples all four on every cycle and locates ROM functions from the staged `prod_rom.sym` and `prod_rom.dis`.
* *Memory.* The hand-off tests read the target SRAM over AXI or through the backdoor peek and compare it with the payload.
* *Functional coverage.* The dual target collects no simulator coverage. A passing `smc_occp_boot_sequence_status_test` seed writes its `{PRIMARY_CHIPLET, BOOT_RECOVERY}` cell to `smc_rom_mode_coverage.json` in its run directory, and `env/smc_rom_mode_coverage.py merge <run-dir>` unions the cells of the PASS runs; closure is all four cells, `satisfied=true`.

[[smc-rom-vplan-bringup]]
==== Bring-up

. Regenerate the eFuse image for the run seed.
. Force the straps, the lifecycle and the DFT status lines of both instances before strap capture.
. Release cold reset and wait for strap capture on both instances.
. Hold `boot_stall`, program the reset vectors over AXI, write the firmware seed to scratch 3 (and the controller I2C target IDs to scratch 4), then release the target and the controller at the ROM base.
. Poll the verdict words up to the budget of the test, and judge the observables.

[[smc-rom-vplan-expansion]]
==== Scenario Expansion

Each rom-only test is one controller image. The image draws its command mix,
addresses and transfer sizes from the run seed, which the harness writes into
scratch 3. Every test runs on `seed = 1`, so a randomized test covers one draw
per regression, except `smc_occp_boot_sequence_status_test`, which runs
`reseed = 32` seeds so that the union of its draws closes the four boot-mode
cells.

=== BFM Policy

[cols="1,1,2",options="header"]
|===
|Interface / Protocol |VIP / Model |Purpose
|OCCP over I2C and I3C |Controller instance with DV firmware |Sends OCCP requests to the target ROM and checks every response
|AXI into each instance |`DualCsr` in `smc_dual_base_test` |Programs reset vectors and reads scratch, POST and SRAM
|eFuse |Seeded eFuse image generator (`env/smc_efuse_stimulus.py`) |Supplies the sensed configuration for each run
|JTAG-facing eFuse port (single-SMC target) |`ej_axi` AXI-Lite manager (`OcahAxiLiteMasterAgent`) |Rewrites and reads an eFuse shadow register during boot stall
|SEP ring buffer |`env/smc_sep_ring_buffer_driver.py` |Writes SEP entries into the target buffer
|DFT status |`env/smc_dft_status_driver.py` |Drives the memory-repair and MBIST status lines
|Virtual console |`env/smc_virt_console.py` |Decodes the firmware trace on scratch 2 of both instances
|===

A model generates stimulus or observes passively. A test judges the ROM through
a checker that can fail. Activity on an interface is not proof.

[[smc-rom-vplan-scope]]
=== Verification Scope

This plan claims SMC Boot ROM behaviour from the release of the target core to
the end of OCCP service, as the SMC Boot ROM chapters define it, on the `dual`
target, plus one eFuse shadow override on the single-SMC target.

[cols="1,2",options="header"]
|===
|Behaviour |Disposition
|OCCP command service and transfer sizes |Verified by <<smc-rom-vplan-occp-command>>
|OCCP memory-access policy |Verified by <<smc-rom-vplan-memory-policy>>
|Malformed and corrupted requests |Verified by <<smc-rom-vplan-malformed>>
|Interface latching |Verified by <<smc-rom-vplan-latch>>
|Status and SEP ring buffers, boot-mode status, and OCCP service after a SEP terminal status |Verified by <<smc-rom-vplan-status-ring>>
|Lifecycle policy |Verified by <<smc-rom-vplan-lifecycle>>
|Memory-repair and MBIST gate, bypass straps, `dft_ignore_error` continuation and the boot-hart restriction of both checks |Verified by <<smc-rom-vplan-dft-gate>>. When MBIST and memory repair both fail, scratch 15 keeps one code; see <<smc-rom-vplan-known-limitations>>
|eFuse shadow override during boot stall |Verified by <<smc-rom-vplan-efuse-shadow>> on the JTAG-facing eFuse port. The JTAG TAP and JTAG-to-AXI bridge are out of scope
|Cold reset during boot |Verified by <<smc-rom-vplan-cold-reset>>
|ExecuteImage and AuthenticateImage hand-off |Verified by <<smc-rom-vplan-handoff>>
|Dual-SMC platform |Qualified by <<smc-rom-vplan-harness>>. These tests grade no ROM behaviour
|SMC hardware |Owned by <<smc-vplan>>
|SEP Boot ROM |Owned by the SEP plans. This bench models the SEP side through the ring-buffer driver
|Secondary SMC flow after `AuthenticateImage` |Not claimed. The SEP terminal-status check covers the primary flow only
|===

A green regression proves only the sections that the traceability matrix credits.

[[smc-rom-vplan-credit-rules]]
==== Credit rules

* Section credit needs a test that maps to the section, a passing `results.xml`,
  and the verdict that the test's procedure group names. This plan records no
  run. Each matrix row is a planned vehicle until a run supplies that evidence.
* A refusal test expects the error code that its member row names.
* A test that forces a signal or stages memory through a backdoor declares it in
  its member row. The forced value is stimulus, never a ROM-generated result.
* This plan maps each test to specification sections from the behaviour that
  the test judges.

[[smc-rom-vplan-harness]]
==== Dual-SMC harness bring-up

*Tests:* 2.

*Objective:* The two-instance model elaborates and leaves reset, the shared I3C bus is idle, `boot_stall` gates memory initialization, and an inbound AXI manager reaches the CPU scratch window that the payload tests stage through. These tests qualify the platform. They grade no ROM behaviour.

*Procedure:*

. Bring up both instances with `boot_stall` held, or released for the AXI probe.
. Check the instance and channel decode, power-good, reset release and fuse sense on both instances.
. Check the boot-stall contract in both directions, or write and read back the scratch-window patterns over AXI and through the backdoor peek.

*Checkers:*

[cols="2,5",options="header"]
|===
|Checker |Contract
|`CHK-DUAL-ELAB`, `CHK-DUAL-RESET`, `CHK-DUAL-FUSE-SENSE`, `CHK-DUAL-BOOT-STALL`, `CHK-DUAL-MEM-INIT`, `CHK-DUAL-I3C-IDLE`, `CHK-DUAL-I3C-INDEXING` |`smc_dual_elaboration_test`: every listed ID is required.
|`CHK-AXI-INIT-MEM-DONE`, `CHK-AXI-SCRATCH-REACHABLE`, `CHK-SCRATCH-BACKDOOR-DECODE` |`smc_dual_axi_sram_probe_test`: every listed ID is required.
|===

*Anti-vacuity:* The boot-stall check requires `init_mem_done` low while stall is held and high after release. The AXI probe uses one pattern per decode field and cross-checks every AXI read against an independent backdoor read.

*Observation:* Top-level TB ports of both instances: power-good, reset, fuse-sense and memory-init status, the I3C pull-down probes, and the AXI responses.

[[smc-rom-vplan-latch]]
==== Interface latching

*Tests:* 2.

*Base:* `hw/sys/smc/dv/cocotb/tests/smc_occp_rom_only_test.py`.

*Objective:* The ROM latches onto the first interface that delivers a header with a valid CRC and a recognized AppID and MsgID, ignores the other interfaces while latched, and releases the latch after five consecutive errors.

*Procedure:*

. Regenerate the eFuse image for the run seed. Force the straps and the `TEST_DEV` lifecycle on both instances and tie the DFT status inputs to passing.
. Hold `boot_stall`, program the reset vector over AXI, and release the target and then the controller at the ROM base.
. The controller firmware waits for the target ready GPIO, runs dynamic address assignment on I3C, sends its command sequence and checks every response.
. The controller firmware writes `TEST_PASS` or `TEST_FAIL` to scratch 0 (its own, or the target's through OCCP WriteData).
. The driver polls scratch 0 of both instances. `TEST_FAIL` in either, or the end of the `+rom_test_timeout` budget, fails the test.

==== Status ring buffers

*Tests:* 5.

*Base:* `hw/sys/smc/dv/cocotb/tests/smc_sep_ring_buffer_test.py` (SEP ring buffer), `hw/sys/smc/dv/cocotb/tests/smc_occp_boot_sequence_status_test.py` (boot-mode status), `hw/sys/smc/dv/cocotb/tests/smc_occp_rom_only_test.py` (the others).

*Objective:* The ROM records boot and command status in the SMC status ring buffer and serves it through GetStatus, with boot-mode entries that match the sampled role and recovery straps, and it serves the SEP ring buffer through GetStatus ID 0x8000 in order, including the full and empty cases. *Procedure:*

. Bring up both instances with `STATUS_RPT_DISABLE` drawn from the seed, or cleared by `+FORCE_STATUS_REPORTING` for the boot-mode and nominal SEP members.

[[smc-rom-vplan-dft-gate]]
==== Early DFT gate

*Tests:* 11.

*Base:* `hw/sys/smc/dv/cocotb/tests/smc_rom_dft_fail_test.py` (terminal), `hw/sys/smc/dv/cocotb/tests/smc_rom_dft_continue_test.py` (continuation), `hw/sys/smc/dv/cocotb/tests/smc_rom_boot_hart_gate_test.py` (boot hart).

*Objective:* The ROM checks the memory-repair and MBIST results in its assembly early boot. Without a bypass or `SMC_CONFIG.dft_ignore_error`, it records the failure code in scratch 15 and halts. A bypass strap skips its check and records the bypass code; with `dft_ignore_error` set, a memory-repair failure, MBIST failure or MBIST abort records its failure code and boot continues to OCCP service. Only the boot hart runs the two checks; the other harts still install `early_trap_vector` and end in the `secondary_main` `wfi` loop.

*Procedure:*

. Bring up both instances with the target DFT status lines held low, then drive the `+dft_scenario` or `+dft_continue_case` pattern before the target leaves `boot_stall`. For a continuation member, read back the DFX status register, the bypass straps and the `SMC_CONFIG` shadow before the target fetches; for a terminal member, read back the `SMC_CONFIG` shadow and require `dft_ignore_error` clear.
. Release the target and the controller at the ROM base.
. Terminal: poll target scratch 15 until it leaves its reset and progress values, require the failure code of the scenario, then sample the target hart 0 retired PC for 20000 cycles and require a halt.
. Continuation: from the release on, fail at the first hart-0 retirement inside the DFT halt loops or the park loop; wait for occp_sanity's TEST_PASS in target scratch 0, require the POST phase OCCP_PROC, sample hart 0 outside the DFT halt loops and the park loop, and read scratch 15.
. Boot hart: with the DFT lines passing, sample the retirement records of all four target harts on every cycle from release until occp_sanity's TEST_PASS, then judge each hart's retired PCs against the symbol extents.

[[smc-rom-vplan-handoff]]
==== Image hand-off

*Tests:* 4.

*Base:* `hw/sys/smc/dv/cocotb/tests/smc_occp_random_jump_test.py`, `hw/sys/smc/dv/cocotb/tests/smc_occp_validate_boot_test.py`, `hw/sys/smc/dv/cocotb/tests/smc_occp_secure_boot_test.py`, `hw/sys/smc/dv/cocotb/tests/smc_occp_dual_unsecure_boot_test.py`.

*Objective:* The ROM receives an image through OCCP WriteData or finds it staged in SRAM, then either jumps to it on ExecuteImage or publishes the manifest address on AuthenticateImage and halts for the SEP.

*Procedure:*

. Bring up both instances with `boot_stall` held, and stage the payload image and the transfer parameters.
. Release the target and the controller. The controller sends the transfer and the terminal command.
. For ExecuteImage: poll target scratch 0 for `TEST_PASS` from the payload. For AuthenticateImage: poll target scratch 9 for MANIFEST_READY and compare scratch 8 with the manifest address.
. Require bus activity, and the member-specific landing, halt or PC checks.

[[smc-rom-vplan-park]]
==== Hart 0 park interlock

*Tests:* 2.

*Base:* `hw/sys/smc/dv/cocotb/tests/smc_rom_park_request_test.py`, `hw/sys/smc/dv/cocotb/tests/smc_rom_park_entry_clear_test.py`, `hw/sys/smc/dv/cocotb/tests/smc_rom_park_defs.py`.

*Objective:* Between OCCP commands the ROM parks hart 0 when the SEP writes the park request to scratch 3: it writes back its D-cache, sets HART0_PARKED and services nothing further. A request left in scratch 3 across a reset is discarded.

*Procedure:*

. Bring up both instances with `boot_stall` held. For the entry-clear case, write the park request value to target scratch 3 after the firmware seed and before `boot_stall` drops, and read it back.
. Release the target and the controller.
. For the request: wait for the controller to report an answered probe and then its WriteData, require the written block to be at least partly missing from the SRAM array, write the park request to target scratch 3, require HART0_PARKED and the park loop, require the whole block in the SRAM array, then release the controller's second probe and require it unanswered.
. For the entry clear: wait for the controller's TEST_PASS in target scratch0, then read target scratch 3 and 9.

*Checkers:*

|`CHK-ROM-PARK-REQUEST` |`smc_rom_park_request_test`: HART0_PARKED sets after the request, hart 0 stays in `smc_park_hart0`, the SRAM array holds the written bytes, and the later command goes unanswered.
|`CHK-ROM-PARK-ENTRY-CLEAR` |`smc_rom_park_entry_clear_test`: the ROM clears the stale request, does not park, and completes the controller's OCCP exchange.
|===

*Anti-vacuity:* The SRAM checks read the array through the backdoor peek, which bypasses the CPU D-cache. The block must be at least partly missing from the array before the park and wholly present after it, so the run shows the park routine's write-back rather than an earlier eviction. The live target must answer a probe with the same 2000-poll timeout before the park, so the unanswered probe after it is not a timeout too short to succeed; the second probe is released only after HART0_PARKED, so an answer means the ROM serviced a command after parking. *Observation:* Target scratch 0, 3 and 9, controller scratch 0, 5, 6 and 7, the target SRAM array, and the target hart 0 retired PC.
