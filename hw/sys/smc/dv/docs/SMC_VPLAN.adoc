[[smc-vplan]]
== SMC OCAH Open-Source Verification Plan

=== Overview

This plan covers the SMC subsystem as it is verified in the open-source
harness: the `smc_wrapper` DUT driven over SEP_IN AXI and AXI-Lite, with
cocotb/PyUVM as the primary framework and an SV-UVM view for the scenarios
that carry one. 156 testcases are enrolled. The `all` group is 149 of
them: five dual / production-ROM leaves build a different DUT, and two
enrolled leaves are held out against #585 and #1488.

Every entry below names a testcase that exists and runs. Where the harness
cannot reach a feature, the testcase is not listed here as enrolled; it is
recorded under Known Limitations with the reason, so this plan states what
is verified rather than what was once intended.

=== Verification Strategy

* *Frontdoor only.* Stimulus is driven through product ports -- SEP_IN AXI,
  AXI-Lite, JTAG, and the pad-level protocol VIPs. Force and backdoor writes
  are not used to create the condition a testcase claims to verify.
* *Checked, not observed.* A read that is printed but not compared is not
  evidence. Expectations come from the generated RDL reset values, the
  preloaded assets, or the specification -- never from a value the DUT
  returned earlier in the same run.
* *Negative checks carry a positive control.* A claim that a signal stays
  low is only meaningful if the same run shows it going high.
* *Evidence tokens.* Each testcase emits `CHK-*` lines that name what was
  compared and against what, so a kept log can be read without the source.

=== Naming Rules

* Testcases are `smc_<feature>_<scenario>_test`, lower snake case.
* The cocotb module and the testlist entry share that name.
* Sequences are `<testcase>_seq`, in `cocotb/seq_lib/`.
* Evidence tokens are `CHK-<AREA>-<CLAIM>`, upper kebab case.

=== Open-Source BFM Policy

Shared and vendored components are used where they exist. A local model is
written only where none fits, and every one carries a README beside it
naming what it replaces and why -- see `dv/models/README.md`.

Bus terminators answer a port that a real integration fills with the
adopter's CSRs. They are declared as terminators, never presented as
verifying the block behind the port.

=== Test Procedures

==== MISC

[[sec-001-smc_5agent_observability_test]]
===== 1 `smc_5agent_observability_test`

*Source Module*: `smc_5agent_observability_test`

*BFM / Model*: ocah_axi_vip (AXI)

*Objective*: SMC OSS PyUVM 5-agent full observability test.

*Test Coverage*:

* A bare idle IRQ sample, whose `sync_irq` / `gpio_irq_any` / `uart_irq_any` == 0 compares also pass on a stuck-at-0 or mis-bound probe, proves nothing on its own. The SAMPLE is therefore preceded by a **positive control**: GPIO0 is armed over the real SEP_IN AXI frontdoor and driven low at the pad until `tb_gpio_irq_any` is observed at 1, and an IRQ item carrying `expect_gpio_irq_any = 1` is sampled inside that window (`[NEGATIVE-NEEDS-POSITIVE-CONTROL]`).
* A single SAMPLE gated only on `item.resolvable` gives `CHK-5AGENT-GPIO` no FAIL-ON path, because `resolvable` cannot be False under the 2-state simulator every retained run uses. The GPIO leg is therefore a *pair* of SAMPLEs whose expectation is stated on the **raw pad-bus vectors** (`tb_core2pad_o` / `tb_core2pad_en_o`), backed in the same run by `ensure_gpio_pad_bus_control`. The three `tb_gpio_*_any` aggregates are unbackable in this TB and stay OBSERVED-ONLY -- the scoreboard refuses a stated expectation on them (`[EVIDENCE-TOKEN-CONDITIONAL]`, `[NEGATIVE-NEEDS-POSITIVE-CONTROL]`).
* The 5-agent composition claim is gated on the **per-type** scoreboard counters, not on the aggregate `total > 0` gate, so a missing item type is a composition failure instead of an invisible hole (`[EXACT-EXPECTATION]`).

*Test Procedure*:

[arabic]
. Drive the sequence `smc_5agent_observability_test_seq` over the interfaces named above.
. Compare every access against its stated expectation in the scoreboard.
. Emit the evidence tokens listed under Checkers.

*Checkers*:

|Checker |Description
|`CHK-5AGENT-IRQ-POSITIVE` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-RESET` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-I2C` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-IRQ-IDLE` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-GPIO` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-CLK` |Evidence token emitted only after the compares it names have held
|`CHK-5AGENT-COMPOSITION` |Evidence token emitted only after the compares it names have held
|assertion |IRQ positive-control sample is X/Z: <value>
|assertion |IRQ positive control: tb_gpio_irq_any = <value>,

|assertion |I2C idle sample unexpected: <value>

[[sec-026-smc_filter_multi_entry_test]]
===== 26 `smc_filter_multi_entry_test`

*Source Module*: `smc_filter_multi_entry_test`

*BFM / Model*: ocah_axi_vip (AXI)

*Objective*: P1 coverage-gap round 2: filter 16 inbound + 16 outbound CONFIG sweep.

*Test Coverage*:

* RTL exposes 16 inbound + 16 outbound filter entries; this sweep covers every one of the 32 slots rather than entry 0 of each direction.
* Each of the 32 slots is proven *individually discriminable*, not merely "a window that answers 0x3000": every slot gets a signature value unique to (direction, index), and the sweep is PHASED so that the 32 signatures are CO-RESIDENT when they are read back.
* Phasing is the whole point.
* A per-slot write/readback/restore cycle proves nothing about aliasing: only one slot is ever non-default at a time, so an RTL that mapped all 32 windows onto one physical register would return the value just written through the very same address and pass.
* Here phase 2 programs all 32 slots without restoring any of them, and phase 3 reads all 32 back while all 32 are still resident -- so a read of slot i can only return sig_i if slot i has storage of its own.
* Under total aliasing the register holds sig_31 when phase 3 starts and the very first readback fails; under any partial aliasing of two windows the later-written one overwrites the earlier and that slot's readback fails.
* Phase 1 checks the RDL reset content of every window before anything is written, and phases 4/5 restore and re-confirm the RDL default, so the run also keeps the reset-value evidence it had before.

[[sec-161-smc_fw_hello_world_test]]
===== 161 `smc_fw_hello_world_test`

*Source Module*: `smc_fw_hello_world_test`

*BFM / Model*: the SMC C image `fw/tests/hello_world`, executed by the CPU cluster; verdict read over SEP_IN AXI

*Objective*: Boot the smallest SMC C image and read the verdict it posts over MMIO.

*Test Coverage*:

* The firmware path end to end, and nothing else: c_compile, output staging by basename, the 64B-striped scratch load, the reset-vector handoff, crt0 and picolibc init across four harts, and the MMIO store to CPU_CTRL SCRATCH_0.
* The image is `test_pass(0)` and a `wfi` loop, so no DUT feature is under test.
* Not a duplicate of `smc_cpu_firmware_boot_test`, and the two cannot be merged. That one boots `min_pass.rom.hex` from the ROM window -- a four-line hand-assembled stub that deliberately avoids crt0 and the hart barrier -- and its `CHK-ROM-IS-TARGET` requires that no scratch image be supplied. *Test Procedure*:

[arabic]
. Build `hello_world` through `[c_build.default]` and stage `hello_world.ecc.hex` beside the simulator.

. Program the reset vector, release all four cores, then release `boot_stall`.
. Poll SCRATCH_0 for the PASS magic, failing on `TEST_FAIL`, on the `0xBAD0_xxxx` namespace, and on the bound expiring.

*Checkers*:

[cols="1,2",options="header",]

|Checker |Description
|`CHK-FW-HELLO-WORLD-BOOT` |The firmware's own PASS word is read back from CPU_CTRL SCRATCH_0 after a cleared-and-verified start
|===

[[sec-162-smc_cold_reset_lock_test]]
===== 162 `smc_cold_reset_lock_test`

*Source Module*: `smc_cold_reset_lock_test`

*BFM / Model*: ocah_axi_vip (AXI)

*Objective*: SS_COLD_RESET_LOCK is write-one-to-set and masks the reset it guards.

*Test Coverage*:

* `RESET_UNIT.SS_COLD_RESET_LOCK`, which no other testcase reads. Found by the porting necessity analysis: `fw/tests/cold_reset_lock_sanity` was the only thing in the tree touching it, and this covers the same two properties natively rather than adding a firmware dependency.
* `reset_unit.rdl:87-95` declares `cold_reset_lock[31:0]` as `sw = rw; hw = r; onwrite = woset;` reset 0, so a taken lock cannot be released by software.
* `smc_subsystem_resets.sv` gates `SS_COLD_RESET_N` writes with `~ss_cold_reset_lock`. `cool_reset_isolate_cfg` records the same fact as its reason for *not* comparing that register, so the masking is asserted here and nowhere else.

*Test Procedure*:

[arabic]
. Require both bits under test to be clear in SS_COLD_RESET_LOCK, since `woset` means a set bit could not have been cleared by this sequence.
. Write bit 0 to SS_COLD_RESET_N with nothing locked and read it back, proving the register is writable before any lock exists.
. Write bit 1 to SS_COLD_RESET_LOCK and require it to set, then write all zeroes and require it to remain set.
. Write bits 0 and 1 to SS_COLD_RESET_N in one access. Require bit 1 to stay clear and bit 0 to follow the write.

*Checkers*:

[cols="1,2",options="header",]
|===
|Checker |Description
|`CHK-COLD-RESET-LOCK-ARM` |SS_COLD_RESET_N accepts a write with the lock clear, so "unchanged" later cannot be explained by a register that never changes
|`CHK-COLD-RESET-LOCK-WOSET` |A set lock bit survives an all-zeroes write, per `onwrite = woset`
|`CHK-COLD-RESET-LOCK-MASKS-WRITE` |In one write carrying both bits, the locked bit does not follow software while the unlocked bit does -- so the write demonstrably reached the register
|===

*Pass Criteria*: all three checkers hold. Measured PASS on Verilator 5.050: the lock held 0x2 through an all-zeroes write, and a 0x3 write to SS_COLD_RESET_N read back 0x1. This testcase leaves one lock bit set for the rest of its simulation, which is what `woset` means; each testcase runs its own simulation. Enrolled in: `all`, `reset`.
