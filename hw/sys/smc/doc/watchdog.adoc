= Watchdog Timers

[[smc-watchdog]]

== Operation

Each CPU core includes a dedicated watchdog timer (at 0xC000_0000 + N *
0x400), providing per-core timeout monitoring. Reset effects are described in
Clocks and Resets. Base addresses and interrupt-related context for the WDT are
summarized in
ifdef::backend-html5[]
xref:smc:interrupts.adoc#interrupts[Interrupts].
endif::backend-html5[]
ifdef::backend-pdf[]
<<interrupts,Interrupts>>.
endif::backend-pdf[]

Timeouts are configurable to suit different workloads, and staged
warnings (followed by reset) allow software intervention before hardware
reset is triggered.

Watchdog monitoring can be disabled during debugging to prevent false
triggers, supporting uninterrupted development and troubleshooting.

The watchdog interrupt is `CTRL.wdogip0`. Hardware sets it on every cycle the
scaled count is at or above `CMP`, so it cannot be cleared while that holds.
Feeding the watchdog resets the count but leaves `wdogip0` set. To clear the
interrupt, feed the watchdog (or otherwise bring the scaled count below
`CMP`), write `KEY` again, and write `CTRL` with `wdogip0` at zero and its
other fields unchanged.

=== Register Access

Each watchdog is locked out of reset, and a write to any register other
than KEY locks it again. Software changes one register at a time:

. Write `0x51F15E` to KEY. KEY reads 1 while the watchdog is unlocked.
. Write the target register. The watchdog locks again on this write, so
  the next write needs a new KEY write first.

A write acts only when its byte enables cover the register's width, and a
narrower write completes with an OKAY response without changing anything,
so software cannot detect a dropped write from the response. Software uses
32-bit stores for every register except CTRL, which accepts byte writes.
The Detailed Register Map below gives the width each register requires.
