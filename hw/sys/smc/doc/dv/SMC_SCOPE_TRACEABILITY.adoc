[[smc-scope-traceability-candidate]]
== SMC scope and traceability

This chapter is the requirement-to-test-to-coverage matrix. Live group
membership is `hw/sys/smc/dv/testlists/all.toml` and the lists it includes;
`hw/sys/smc/dv/docs/SMC_VPLAN.adoc` states what each testcase verifies. This
file is the reconciliation between the two — which of those testcases count as
feature credit, and which are bring-up or decode-only names that must not be
counted twice.

[cols=",",options="header",]
|===
|Field |Value
|DUT |`--dut smc` → `smc_wrapper` under `smc_uvm_top`
|Spec / plan |`hw/sys/smc/dv/docs/SMC_VPLAN.adoc` plus the groups
`hw/sys/smc/dv/testlists/all.toml` resolves
|Coverage intent |`hw/sys/smc/dv/docs/SMC_FCOV.adoc` (Python counters; no
Verilator covergroup)
|Checker |`SmcScoreboard` non-vacuous SAMPLE/AXI/VIP counts + `results.xml`
|CI |`.github/workflows/sim.yml` PR `smoke`; `.github/workflows/regress.yml` nightly and weekly `hosted`
|===

[[smc-live-groups]]
=== Live groups versus credit

Executable membership is resolved from the testlists; the groups and their
`expected_count` guards are in `hw/sys/smc/dv/testlists/all.toml`:

[cols="2,3",options="header",]
|===
|Group |Role
|`smoke` |PR gate (`sim.yml`): canonical bring-up, cold reset, and a CSR frontdoor read
|`hosted` |Nightly and weekly (`regress.yml`): `all` minus the five leaves that need the RISC-V toolchain (two `fw` leaves, three dual-target leaves that run a ROM or firmware image)
|`per_ip` |One pass across every IP the bench drives
|`all` |The package regression; `all.toml` names the leaves outside it and why, and `SMC_DEFERRED_DISPOSITION.adoc` records the leaves no scheduled tier runs
|`functional` |One name per functional bucket; mixes SAMPLE bring-up with feature rows
|===

`smoke` is the three-leaf PR gate (`smc_canonical_smoke_test`,
`smc_cold_reset_test`, `smc_register_sanity_test`). `smc_i3c_to_fabric_test`
is in neither `smoke` nor `functional` and receives no feature credit.

[[smc-credit-rules]]
=== Credit rules

* Feature credit requires active CSR/fabric/pin stimulus and a
  non-vacuous `SmcScoreboard` count. SAMPLE-only bring-up stays in
  `smoke` and is not a requirement row.
* `smc_i3c_to_fabric_test` is HCI_VERSION decode (`proxy=True`). It
  remains runnable via `i3c_depth` / `per_ip` / by name. It is not
  stub-signature SLVERR, and it is not I3C protocol credit.
* Names in `SMC_DEFERRED_DISPOSITION.adoc`, adopter PLL/PVT OKAY+0 wraps, and
  TB-glue DFD tokens are OUT.
* UART loopback / ROM firmware stay on their existing intake issues.
  They are not re-scoped here.
* `--dut smc` already instantiates `smc_wrapper`. There is no separate
  `wrapper.toml` and no test named `main_wrapper` or `main_wrapper_por`.
  Bring-up / POR successors are `smc_canonical_smoke_test` and the reset
  cluster (`smc_cold_reset_test`, `smc_powergood_glitch_test`,
  `smc_multi_reset_csr_persistence_test`).

[[smc-traceability-matrix]]
=== Matrix (feature-credit subset)

Requirement IDs are the VPLAN TC rows or the canonical scenario those
tests actually run. Coverage bins are the `hw/sys/smc/dv/docs/SMC_FCOV.adoc`
families the scoreboard can hit; Verilator does not close SV covergroups.

The Groups column is resolved membership, not intent. Every feature-credit row
below is reachable through both `smoke` and `per_ip`; the column names the
narrower groups that also carry it, so a reviewer can run one feature without
the whole gate.

`smc_clk_running_test`, `smc_gpio_observe_test`, `smc_i2c_cg_sanity_test`,

`smc_input_fabric_axi_wr_rd_test`, `smc_avsbus_sanity_test`,
`smc_dbs_idle_test`). Those stay category aliases. They are not extra
feature rows.
