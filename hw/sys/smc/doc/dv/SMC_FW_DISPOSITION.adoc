[[smc-fw-disposition]]
== SMC firmware image disposition

This is the disposition of record for every firmware image name under
`hw/sys/smc/dv/fw/tests/`. The shared engine (`hw/common/dv/fw/compile.mk`)
builds every `tests/<name>/` directory it finds, so being built is not a
consumer. A consumer is a testlist entry that stages the image: a
`firmware = "<name>"` key in `hw/sys/smc/dv/testlists/*.toml` resolved through
a `[c_build.*]` block of `smc_sim_cfg.toml`, or an SMU DV `[c_build.*]` that
builds and stages it. Every directory in the tree has a row here, and the rule
for adding one is in `hw/sys/smc/dv/fw/README.md`: a new image is added
together with its consumer and its row.

Buckets:

* `enrolled` -- staged by a testlist entry in this tree. The row names the
  leaf and the `[c_build.*]` block.
* `external-consumer` -- staged only by another package: an SMU DV group
  outside SMU `all`, or a regression outside this repository. The image is
  kept for that consumer and is not counted toward this tree's coverage.
* `deferred` -- kept for a stated blocker. The row is the blocker and the
  condition that closes it; a closed row moves to `enrolled` with its leaf,
  or to `superseded`.
* `superseded` -- the property is proven by a live enrolled name or by another
  image, or the image has no DUT property. There is no directory in the tree;
  the code is in git history under the image name, and the row is what a
  reader searching for that name finds.

The cocotb test names of this package have their own record,
`SMC_DEFERRED_DISPOSITION.adoc`; rows below that cite a waived cocotb alias
point at it. SMU's record of the tests that stage SMC images is
`hw/sys/smu/dv/docs/SMU_DEFERRED_DISPOSITION.adoc`.

=== Deferred images

Each row states the blocker and the consumer whose arrival closes it. The
`smc_fw_hello_world_test` pattern is a fire-and-forget CPU verdict on
`CPU_CTRL SCRATCH_0`; the `smc_fw_plic_claim_test` pattern adds an `arm_value`
the cocotb side waits for before it drives a stimulus. Rows that need a
rom-mode OCCP build share one trigger: the generic `[c_build.*]` is added with
the first image that consumes it, not ahead of it.
