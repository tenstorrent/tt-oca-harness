= JTAG Operation
:description: DTP-level JTAG topology, scan chain ordering, clock domains, reset and lifecycle feature control.

[[dtp-jtag-integration]]

This page describes how the DTP integrates its JTAG components at the
subsystem level: topology, scan chain ordering, clock domains, reset hierarchy
and lifecycle feature control. For the detailed implementation of each
component, see the JTAG reference pages that follow this one.

== DTP JTAG Topology

The DTP instantiates a single JTAG Interface Unit (JIU) as the primary debug
entry point for the chiplet. The JIU connects to:

* The five external JTAG pins (TCK, TDI, TDO, TMS, TRST_n).
* The Cross Trigger Network, for the `jtag_clock_stop` bit in the DEBUG_CONTROL
  instruction and for the `cla_clock_stop` readback status.
* The SMC AXI fabric via a JTAG2AXI bridge.
* The SMC and SEP OTP controllers via AXI4-Lite JTAG2AXI bridges.
* The SMC and SEP CPU debug TAPs via STAPs.

<<dtp-jtag-scan-chain-figure>> shows the PTAP, secondary scan path, and iJTAG instrument
network.

[[dtp-jtag-scan-chain-figure]]

image::dtp-jtag-scan-chain.svg[alt="DTP JTAG scan chain: TDI fans out to the PTAP instruction and data registers, the boundary-scan chain and the three iJTAG SIBs; the PTAP output passes through the STAP chain and an external STAP chain back to the TDO mux",width=100%,pdfwidth=100%]

Read <<dtp-jtag-scan-chain-figure>> along the arrows from TDI to TDO. TDI reaches
every register and external chain at once; the IR and TDR mux returns the
instruction register in Shift-IR and, in Shift-DR, the register the current
instruction selects. Italic labels beside a mux name the instructions or the
select bit that choose its input. The PTAP output then enters the STAP chain, whose
return reaches TDO only while the `TAP_3DCR` STAP-select bit is set; otherwise TDO
takes the PTAP output directly. Each STAP and SIB carries, in italics, the
`dbg_disable_i` field that closes it. Dashed blocks exist only when their enable
parameter is set, as the list below gives for the STAPs; the JTAG2AXI bridges
follow `JTAG_SMC_DBG_ENABLE` and `JTAG_SEP_DBG_ENABLE`. Each STAP adds one SIB bit
to the chain; opening the SIB inserts the STAP's 3-bit 3DCR, and setting the 3DCR
STAP-select bit splices in its secondary TAP. Each iJTAG SIB inserts its external
segment after its SIB bit while that bit is set.

== STAP Secondary Scan Path

The PTAP secondary scan path connects the STAPs in this fixed order:

. PTAP
. I/O STAP — when `JTAG_STAP_IO_ENABLE=1`
. SMC debug STAP — when `JTAG_SMC_DBG_ENABLE=1`
. SEP debug STAP — when `JTAG_SEP_DBG_ENABLE=1`
. Extra STAP instances `[JTAG_NUM_EXTRA_STAPS-1:0]`
. Return to PTAP

When a STAP is disabled by parameter, the DTP bypasses it in the secondary
scan chain and drives its host outputs low, apart from TCK, which still follows
the PTAP.

== JTAG2AXI Bridges

The PTAP contains three JTAG2AXI bridges, each selected by its own group of six
instructions (<<dtp-jtag2axi-bridges-table>>). The request and response type
parameters of a bridge set its bus type, address width and data width. Its read
and write pipeline-depth parameters set how many transactions it queues, where
0 allows a single outstanding transaction. The table lists the DTP defaults.
Each bridge reports its configuration in its `*_JTAG2AXI_CAPS` register.

== Clock Domains

The DTP operates in two clock domains (<<dtp-clock-domains-table>>).

[[dtp-clock-domains-table]]
[cols="<25%,<25%,<50%",options="header"]
.DTP clock domains
|===
|Domain |Signal |Description

|System clock
|`clk_i`
|Main clock for cross-trigger logic and AXI interfaces. All CTN and CSR
logic runs in this domain.

|JTAG clock
|TCK
|JTAG test clock for all TAP controller and scan logic. Clocks the PTAP,
STAP state machines, and scan registers. Asynchronous to `clk_i`.
|===

All cross-trigger signals crossing from TCK to `clk_i` are synchronised
within the CTPs using two-flip-flop synchroniser chains.

== Reset Architecture

<<dtp-reset-signals-table>> identifies the reset inputs and the logic they reset.

[[dtp-reset-signals-table]]
[cols="<30%,<70%",options="header"]
.DTP reset signals
|===
|Signal |Description

|`rst_n_i`
|Active-low asynchronous reset for cross-trigger logic and AXI interfaces.
Resets all CTN and CSR state; clock-stop output resets to 0 (clocks running).

|`pwr_on_rst_ni`
|Active-low asynchronous power-on reset for JTAG logic. Combined internally
with TRST_n; resets the PTAP to Test-Logic-Reset state and clears all TDRs.

|TRST_n (JTAG pin)
|Optional external active-low TAP reset. When asserted, drives the PTAP
to Test-Logic-Reset regardless of the TCK or TMS state.
|===

All registers reset to safe states. The JTAG TAP returns to Test-Logic-Reset
on either TRST_n or power-on reset.

[[dtp-ic-reset-overrides]]
== IC_RESET Overrides

The primary TAP implements the IEEE 1149.1-2013 §17 IC_RESET TDR. Per reset
port it holds `reset_control`, the active-low reset value to drive, and
`reset_enable`, which selects it. One `reset_hold` bit sits nearest TDO.

`reset_enable` is active low despite the name: it resets to 1, leaving the
port's functional reset connected, and writing 0 hands the port over to
`reset_control`. The overrides leave the DTP on
`jtag_ic_reset_{smc,sep,ext}_o`, whose `.ovrd` member is active high and whose
`.val` carries `reset_control`.

`reset_hold` also resets to 1, which lets Test-Logic-Reset clear the
enable/control bits. Write 0 to keep an override asserted across TLR; only TRST
clears `reset_hold` itself.

Consumers select between the two sources with a hazard-free multiplexer, which
holds its output while the select alone moves. Write `reset_control` first and
clear `reset_enable` in a second Update-DR: moving both in one update changes
the select and a data input together, which can pulse a reset on a port that
neither source is resetting.

At the SMU the TDR concatenates three slices from TDI to TDO: SMC, SEP, then
the external slice, followed by `reset_hold`. The SMC and SEP port lists are
OCAH-defined. The external slice is adopter-defined: its width and fields come
from the SMU type parameter `ic_reset_ext_t`. The Integrator Guide records the
SMU-composed port map.

== Debug Disable

`dbg_disable_i` (`sep_lifecycle_ctrl_pkg::dbg_disable_t`) is a per-path
debug/test disable vector. Each field is active-high (1 = path disabled). The
JTAG interface unit synchronizes the vector into the TCK domain and applies
each field to the named path.

<<dtp-debug-disable-paths-table>> maps each debug path to its active-high disable field.

A disabled path remains observable only where required for control and
readback. For a JTAG2AXI bridge, disabling means TDR update registers are not
latched, buffered requests are dropped and the AXI state machine is held in
idle — no AXI traffic can be generated. For a STAP, the host-visible scan
access is clamped so the disabled path cannot reach downstream secure logic.

The STAP and iJTAG fields are applied in `jtag_intf_unit`; the three JTAG2AXI
fields are applied in `jtag_ptap`.
