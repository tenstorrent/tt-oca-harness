[[dtp-simulation-defines]]
=== Simulation and test defines

DTP RTL and DV compiles select simulation behavior with preprocessor defines
(`+define+NAME` or `-D NAME`). The open-source DV runner applies a shared
native-profile set to every DUT, then DTP-specific overlays for Verilator and
the SV-UVM framework. Lint and synthesis apply `SYNTHESIS` instead of the DV
set.

Runtime environment variables (`DTP_TEST_LOOPS`, `DTP_AXI_SCOREBOARD_NEGATIVE`)
and simulator plusargs (`+DTP_JTAG_TAP_CHECKER_NEGATIVE`) are not preprocessor
defines; those knobs are documented in `hw/sys/dtp/dv/README.md`.

==== How the DTP DV flow applies defines

A DTP simulation compile merges these layers, in this order:

1. The shared native profile
   (`hw/common/dv/configs/profiles/native.toml`,
   `[target_defaults.default].defines`) — the same set for every native-profile
   DUT, including both the cocotb and SV-UVM frameworks. That set includes
   `SIMULATION`.
2. The DTP Verilator overlay (`hw/sys/dtp/dv/dtp_sim_cfg.toml`,
   `[targets.default.tools.verilator].flags`) — extra `+define+` flags only
   when the tool is Verilator.
3. The shared native profile's SV-UVM overlay
   (`[frameworks.uvm.target_defaults.default].defines` in `native.toml`) —
   the bare `UVM` framework gate, only when the run is
   `--dut dtp --framework uvm`. Target-table `defines` dedup-append across
   the profile/DUT/framework merge layers, so the overlay adds `UVM` to the
   shared set instead of replacing it.

`python3 tools/dv/run_dv.py --define NAME` appends a further `+define+` for
that run. The supported DTP configuration is the merged set above.

Lint and synthesis (`make lint-slang` / `make synth-all` with `BLOCK=dtp`)
do not use the native DV profile. They pass `-D SYNTHESIS=1` from
`OCAH_FLOW_COMMON_DEFINES` in `flows/common.mk`.

==== Defines the DTP flows consume

[cols="<,<,<,<,<",options="header"]
|===
|Define |Applied by |Why |With the define |Without the define

|`SIMULATION`
|Native profile (every DTP DV tool)
|Marks a simulation compile. Vendored OpenTitan prims in the DTP graph gate
simulation-only paths on this name, and the two-state protocol checker macros
(`hw/common/assert/ocah_sva_macros.svh`) expand to live assertions only under
it.
|Those prim paths compile in; the protocol checkers carry their two-state
rules.
|Those prim paths are omitted; the two-state checker macros expand to nothing
(the lint and synthesis view).

|`UVM`
|Native profile SV-UVM overlay (`[frameworks.uvm]` in `native.toml`; every
`--framework uvm` DUT)
|The first-party SV-UVM framework gate (the same bare-name wording rule as
`SIMULATION`): it adds the SV-UVM harness block to the shared testbench top
`dtp_uvm_top` in `hw/sys/dtp/dv/tb/tb_top.sv`, and the shared assertion
headers report through `uvm_report_error` instead of `$error`.
|The harness block compiles: the clock generator on `dtp_tb_if.clk`, the test
classes, the `uvm_config_db` publication of every interface instance, and
`run_test()`. Required for `--framework uvm` (VCS).
The testbench architecture document (`hw/sys/dtp/dv/docs/DTP_TB_ARCH.adoc`)
describes the core the block extends.
|Only the framework-neutral core compiles (interface instances, DUT,
adapters, counters, coverage, protocol SVA); cocotb drives the interface
members through hierarchical handles. Required for the default cocotb/PyUVM flow (cocotb is
the default framework, so no define means the core alone). Defining it on a
cocotb compile adds a second clock generator and `run_test()` against the
Python test.

|`VERILATOR`
|DTP Verilator overlay (Verilator also predefines it)
|Tells the assertion headers that the compiler is Verilator, a two-state
simulator.
|`hw/common/assert/ocah_assert.svh` and the OpenTitan `prim_assert.sv` that
`dtp_pkg` includes leave `OCAH_INC_ASSERT` / `OCAH_OT_INC_ASSERT` undefined, so
the four-state assertion macros (`OCAH_ASSERT`, `OCAH_COVER`, `OCAH_OT_ASSERT`)
expand to nothing. The two-state checker macros in
`hw/common/assert/ocah_sva_macros.svh` do not test this define; Verilator
evaluates them under the target's `--assert` flag (below).
|On Verilator, the four-state macro bodies compile in; their `$isunknown` rules
pass vacuously on a two-state model. On VCS/Xcelium this define is not set, so
those headers keep SVA enabled unless another gate (`SYNTHESIS`) applies.

|`ASSERTS_OFF`
|DTP Verilator overlay
|Turns off the PULP `common_cells` assertion macros (`OCAH_PULP_INC_ASSERT` in
`assertions.svh`).
|`common_cells` `OCAH_PULP_ASSERT_I` / `OCAH_PULP_ASSERT` / `OCAH_PULP_ASSERT_INIT`
macros expand to nothing. DTP pulls `common_cells` in through Bender
(`common_cells_rtl`).
|On Verilator those macros compile as SVA and typically fail the compile. On
VCS/Xcelium this define is not set; `common_cells` macros stay enabled unless
`SYNTHESIS` is also set.

|`COMMON_CELLS_ASSERTS_OFF`
|Native profile, Verilator tool flags only
(`[target_defaults.default.tools.verilator].flags`)
|Turns off the inline assertion blocks inside `common_cells` modules
(`fifo_v3`, `cdc_fifo_gray`, `rr_arb_tree`, `stream_xbar`, `addr_decode_dync`,
and others that DTP's AXI/CDC path instantiates) that are compiled only when
`COMMON_CELLS_ASSERTS_OFF` is unset.
|Those inline asserts are omitted (Verilator). The scoreboards and checkers
carry the pass/fail evidence there.
|The inline asserts compile and are live for every DTP test (VCS, Xcelium).
On Verilator they fail the compile even if `ASSERTS_OFF` is set, because they
are independent of `OCAH_PULP_INC_ASSERT`.

|`SYNTHESIS`
|Lint and synthesis (`OCAH_FLOW_COMMON_DEFINES`); not the DTP DV profile
|Elaborates the production netlist view: no simulation-only SVA, no
simulation-only initial blocks.
|`jtag2axi` concurrent `OCAH_OT_ASSERT` properties are omitted.
`prim_assert` / `ocah_assert` also leave their include-assert macros undefined.
DTP DV does not set this define, so a `--dut dtp` run is not a synthesis view.
|The JTAG2AXI SVA compiles. On VCS/Xcelium cocotb that means those properties
are live; on Verilator `VERILATOR` still compiles them out. Defining
`SYNTHESIS` on a DTP DV compile would drop that SVA and is not the supported
test configuration.
|===

The DTP Verilator overlay also passes the tool flags `--assert --no-assert-case`
(`[targets.default.tools.verilator].flags`). They are simulator options, not
preprocessor defines: `--assert` makes Verilator evaluate the concurrent and
immediate assertions it compiles, which is the two-state protocol SVA set, and
`--no-assert-case` leaves the `unique`/`priority` case checks of the DUT and
vendored RTL out of that set. A failing assertion prints an `%Error` line and
stops the simulation.

The profile overlay's explicit define is the only source of `UVM`: the simulator's
`-ntb_opts` option selects which UVM library is compiled but does not set
this preprocessor name. The runner defaults that library to `uvm-1.2`; a DUT
or profile selects another one with `[build.vcs]` `uvm_lib` in its sim config
(for example `uvm_lib = "uvm-ieee"`). `uvm-1.2` is the floor — the vendored
OpenTitan assertion macros do not compile against older libraries. There are
no DUT-specific framework defines.

An adopter overlay (`run_dv.py --overlay`, see the runner manual's "Adopter
overlay layer") may dedup-append further defines into the target tables —
the intended use is commercial-VIP gate defines such as
`OCAH_JTAG_VENDOR_IF`/`OCAH_AXI_VENDOR_IF`, which no checked-in config sets.

==== Bender targets

`hw/sys/dtp/dv/dtp_sim_cfg.toml` sets `bender_targets = ["dtp", "simulation"]`.
Those are Bender target names, not preprocessor defines. `dtp` selects the DTP
RTL source graph. `simulation` selects simulation-only files from vendored
packages. They do not appear as `+define+dtp` / `+define+simulation` unless a
tool is also told to do that separately.
