[[dtp-dv-testbench-architecture]]
== DTP OCAH Open-Source Testbench Architecture

=== Overview

[cols=",",options="header",]
|===
|Field |Value
|DUT |`dtp` (`hw/dtp/rtl/dtp.sv`)
|Repository |`tt-oca`
|Project |OCAH
|Framework |PyUVM on cocotb (primary); SystemVerilog UVM smoke layer (`--dut dtp_uvm`, VCS)
|Primary simulator |Verilator
|Commercial simulator use |Coverage and CSR paths that Verilator cannot elaborate today; SV-UVM smoke flow (VCS)
|Reference TB |`dv/dtp/` working DTP environment and docs
|===

The OCAH open-source DTP testbench follows the canonical `hw/sys/<system>/dv/` layout under
`hw/sys/dtp/dv/`. It ports the working reference plan from `dv/dtp/` into
a public PyUVM environment using the unified OCAH BFM packages for standard
interfaces.

=== VIP Selection Policy

[arabic]
. Import unified OCAH BFM wrappers from `hw/common/dv/vip` for standard
protocol access.
. Wrap those BFMs in PyUVM agents so tests remain sequence-based and reusable.
. Use OCAH-local BFMs/models for custom OCH protocols and standards without a
shared wrapper yet.
. Keep every BFM behind the same transaction-level agent boundary so backend
changes do not affect sequences or scoreboards.

[cols=",,,",options="header",]
|===
|DTP Interface |Preferred VIP |Modeling Approach |Notes
|Primary JTAG TAP |`ocah_jtag_vip` `OcahJtagMasterDriver` |Unified OCAH BFM |Active JTAG transaction driver and TAP helper
|SMC fabric AXI4 manager |`ocah_axi_vip` `OcahAxiSlaveAgent` |Unified OCAH BFM |AXI memory responder with scoreboard backdoor access
|SMC/SEP OTP AXI-Lite managers |`ocah_axi_vip` AXI-Lite wrapper |Unified OCAH BFM |AXI-Lite responder model for OTP bridge scenarios
|XTRIG AXI-Lite CSR subordinate |`DtpFlatAxiLiteMaster` |DUT-local adapter |Current flattened-fixture driver; required generic behavior should converge into `ocah_axi_vip`
|BSR/STAP scan loopbacks |Minimal OCAH-local scan model |OCAH-local simple model |Compact scan loopback and observable model
|iJTAG SIB networks |OCAH-local IEEE 1687 model |OCAH-local model |IEEE 1687 scan-network transaction model
|CTP/CTM cross-trigger protocols |OCAH-local BFMs |OCAH-local BFM |CTP/CTM protocol BFMs; debug TDR clock-stop requests may be driven directly in the TB
|===

=== DUT-Local Model Ownership

The shared promotion checklist is defined in `hw/common/dv/README.md`. The DTP
models below intentionally remain local because they encode this DUT's
topology, lifecycle rules, signal binding, or testbench fixtures:

[cols=",,,",options="header",]
|===
|Model / Helper |Current Scope |Why It Stays DUT-Local |Promotion Trigger
|`DtpScanModel` |8-bit BSR identity-loopback stimulus and checking |Models the compact DTP TB fixture, not generic IEEE 1149.1 boundary cells |A parameterized boundary-cell model with an independent DUT consumer
|`DtpIjtagSibModel` |Three DTP SIBs, DTP lifecycle gates, looped instruments |Hard-coded DTP scan topology and security policy |Topology/instrument-neutral IEEE 1687 transactions plus a second consumer
|`DtpStap3dcrModel` |DTP PTAP/STAP selection, 3DCR state, reset/gating |Downstream STAPs are wire loopbacks and the hierarchy is DTP-specific |A parameterized IEEE 1838/STAP model validated against a real downstream topology
|`DtpXtrigBfm` / `DtpCtmRefModel` |DTP CTP wire-OR/P2P pins, CTM masks, CSR layout |Assumes DTP port counts, flattened signal names, and OCH routing policy |Parameterize binding/counts and demonstrate independent reuse; domain-local ownership may precede shared VIP promotion
|`DtpFlatAxiLiteMaster` |XTRIG CSR access over this TB's flattened signals |Duplicates a standard protocol already owned by `ocah_axi_vip` |Migrate required behavior to the shared AXI-Lite wrapper; never promote as a second AXI VIP
|`DtpBypassSuiteCfg` / `DtpBypassRefModel` |BYPASS opcode, pattern, capture, and one-bit-delay prediction |Encodes the DTP BYPASS scenario and evidence context |Consider protocol-level promotion only after an independent JTAG consumer needs the same model
|DTP TDR maps/packers |DTP instruction/register semantics layered over `ocah_jtag_vip` |Register layout and polling policy are DUT semantics, not JTAG protocol |Share only with a domain consumer that uses the same DTP register contract
|===

The shared `ocah_jtag_vip` and `ocah_axi_vip` packages own protocol-neutral
driving, monitoring, result, and error behavior. DTP agents remain responsible
for hierarchy binding, address/TDR maps, expected values, lifecycle policy, and
scoreboarding.

=== BYPASS Reference-Model Contract

The DTP BYPASS scenario is the concrete reference-model/scoreboard example for
https://github.com/tenstorrent/tt-oca-hw/issues/3294[tt-oca-hw#3294]:

[source,text]
----
DtpBypassSuiteCfg
  -> load_ir / shift_dr JTAG stimulus
  -> DtpBypassRefModel.predict(case) -> expected TDO
completed DtpJtagItem.result         -> observed TDO
expected + observed
  -> OcahJtagChecker
  -> CHK-BYPASS-* / CHK-NONVAC / CHECKER_SUMMARY
----

The frozen suite config is the single source for opcode, width, pattern,
capture bit, seed, and evidence context. The pure model has no simulator
handles or DUT reads. Aggregate checker mode lets every configured case run;
finalization then reports total checks/errors/missing IDs before failing.
Passing `results.xml` and native `result.json` remain the run authority.

[source,text]

  -> dtp_base_test
       build_phase:

       run_phase:
         clock/reset bring-up
         cfg.reset_done event
         start_seq(test sequence)

DtpEnv
  -> DtpJtagAgent
       sequencer
       DtpJtagDriver -> ocah_jtag_vip OcahJtagMasterDriver
       analysis port -> completed DtpJtagItem stream

       JTAG2AXI write/read data integrity checks
----

=== HDL Top

`tb/tb_top.sv` instantiates `dtp` as `dtp_uvm_top` and provides signal adapters
between packed RTL structs and cocotb-friendly scalar/vector ports.

[cols=",",options="header",]
|===
|DUT Interface |`tb_top` Handling
|JTAG TAP |Exposes `jtag_tck`, `jtag_tms`, `jtag_trst`, `jtag_tdi`, `jtag_tdo`, `jtag_tdo_oen` for `OcahJtagMasterDriver`
|SMC fabric AXI4 |Flattens `+axi_smc_dbg_*+` structs into `+m_axi_*+` for `OcahAxiSlaveAgent.from_prefix(dut, "m_axi")`
|Lifecycle |Drives enable-polarity `feat_ctrl_i` from TB; base bring-up uses the all-one/full-debug setting
|BSR/STAP/iJTAG |Looped back or tied idle for scenarios that do not actively use these paths
|SMC/SEP OTP AXI-Lite |Tied idle until OCAH AXI-Lite responder agents are added
|DEBUG_CONTROL and IC_RESET |Flattens boot-stall, clock-stop, and IC_RESET struct outputs into cocotb-visible scalar signals
|XTRIG CSR/CTP/CTM |CSR blocks tied idle or stubbed for Verilator; `xtrig_clk_stop_req` is directly driven for DEBUG_CONTROL clock-stop tests
|Clocks/resets |cocotb drives `clk_i`, `rst_n_i`, and `pwr_on_rst_ni`; JTAG driver owns TCK/TRST sequencing
|===

=== Environment Components

==== `DtpJtagAgent`

The active JTAG agent wraps `ocah_jtag_vip.OcahJtagMasterDriver`. It accepts
`DtpJtagItem` transactions for TAP reset, raw TMS steps, IR/DR scans, IDCODE
reads, generic named-TDR reads/writes, and JTAG2AXI single operations. The
driver initializes the BFM, resets the TAP, and broadcasts completed items on its
analysis port.

For writable TDR reads, the transaction can carry a caller-selected DR
`shift_value`. The default remains zero to expose unintended side effects, while
debug TDR sequences pass preserve values when the scenario must hold
TMP_STATUS, IC_RESET, or DEBUG_CONTROL fields across the read.

==== `DtpAxiAgent`

The AXI agent wraps `ocah_axi_vip.OcahAxiSlaveAgent` on the SMC fabric debug
manager interface. It provides a memory responder for AXI writes/reads and a
backdoor view used by the scoreboard.

==== `DtpScoreboard`

The scoreboard subscribes to completed JTAG items. It verifies IDCODE bit 0,
checks JTAG2AXI write data against the OCAH AXI RAM backdoor, and checks read data
against preloaded memory contents. `check_phase` requires zero errors.

==== Sequence Library

The DTP sequence library uses a hierarchical helper model. The generic base
sequence owns only cross-cutting sequence infrastructure. Feature base sequences
then collect helpers for one verification domain, such as Basic JTAG, debug TDR,
or JTAG2AXI.

Directed tests should inherit from the narrowest feature base that matches the
scenario. This keeps each concrete test readable and makes helper ownership
obvious. Random and stress tests should prefer composition: instantiate small
command-library sequence helpers for each domain and keep the random orchestration
in the top-level stress sequence.

Conceptually:

[cols=",",options="header",]
|===
|Layer |Role
|Generic base sequence |Common sequence infrastructure shared by all scenarios
|Feature base sequence |Domain-specific directed-test helpers
|Command-library sequence |Small reusable operations for random/stress composition
|Concrete test sequence |One readable scenario flow for one `@pyuvm.test` wrapper
|===

New tests should keep the one-sequence plus one-`@pyuvm.test` pattern:
`+seq_lib/<test_name>_seq.py+` and `tests/<test_name>.py`. Test wrappers and test
classes end in `+_test+`; concrete test sequence files/classes end in `+_test_seq+`;
reusable helper sequence/library files/classes also end in `+_seq+`.

=== Clock and Reset Strategy

[cols=",,",options="header",]
|===
|Clock / Reset |Source |Notes
|`clk_i` |cocotb clock in base test |System/AXI/XTRIG domain
|JTAG TCK |`OcahJtagMasterDriver` |TAP clock domain
|`rst_n_i` |base test |Active-low system reset
|`pwr_on_rst_ni` |base test |Power-on reset for JTAG logic
|TRST |`OcahJtagMasterDriver` |TAP reset
|===

JTAG2AXI sequences poll response status instead of sleeping for a fixed number
of cycles. This keeps CDC and AXI latency handling protocol-based.

=== Stimulus Strategy

The open-source stimulus strategy is mostly directed and deterministic, with
seeded randomization in the debug TDR and Basic JTAG pattern sweeps where it adds
coverage value:

[cols=",",options="header",]
|===
|Area |Strategy
|Smoke |Verify TAP FSM traversal and IDCODE readout through focused JTAG tests
|Basic JTAG |Verify primary TAP instruction decode, bypass variants, reset behavior, and compact BSR/iJTAG loopback smoke behavior
|Debug TDR |Verify TMP_STATUS, IC_RESET, DEBUG_CONTROL, JTAG_CAPS, and JTAG2AXI_CAPS with decoded logs, deterministic loops, seeded random patterns, and read-only sweeps
|JTAG2AXI write |Shift a single-op write request, poll completion, check OCAH AXI RAM memory
|JTAG2AXI read |Backdoor-preload OCAH AXI RAM, shift a single-op read request, poll completion, compare data
|===

Additional stimulus categories are derived from the reference
`dv/dtp/doc/DTP_VPLAN.md`: OTP bridge operations, STAP/3DCR, iJTAG, XTRIG CSR,
CTP, and CTM.

=== Checking Strategy

[cols=",,",options="header",]
|===
|Check Type |Component |Description
|TAP data |`DtpJtagDriver`, `DtpScoreboard` |IDCODE and TDR returned data
|Debug TDR observables |`tb_top.sv`, `DtpJtagDriver` samples |Boot-stall, clock-stop, IC_RESET, and decoded-instruction observables
|AXI data integrity |`DtpScoreboard` |JTAG2AXI writes/reads against OCAH AXI RAM
|Protocol completion |`DtpJtagDriver` |JTAG2AXI status polling until non-busy
|Test completion |PyUVM phases |Objections drop only after sequences finish
|Regression parsing |Global DV parser |Requires positive cocotb result evidence
|===

=== Coverage Strategy

Verilator does not support SV covergroups. The OCAH open-source path should collect
Python-side functional observations in the PyUVM environment and rely on
commercial simulators for SV covergroups, assertion coverage, and full code
coverage. See `DTP_FCOV.adoc`.

=== Canonical RTL Selection

Bender supplies the HW-owned `prim_sync2` and generated
`cross_trigger_port_reg` and `cross_trigger_matrix_reg` implementations to the
DTP simulator flows. Verilator and VCS therefore compile the same synchronizer
and CSR RTL selected by the subsystem source graph.

=== SystemVerilog UVM Smoke Layer (`--dut dtp_uvm`)

Alongside the PyUVM environment, a compact SV-UVM smoke layer runs through the
same native runner via the registered `dtp_uvm` alias (shared DV root,
separate `dtp_uvm_sim_cfg.toml`, `testlists/uvm.toml`, and `build/uvm/` tree).
It is a maintainer flow on VCS (`native-uvm` profile, `-ntb_opts uvm`);
Xcelium is planned behind a real-run sign-off gate.

There is exactly ONE testbench top module: `dtp_uvm_top` in `tb/tb_top.sv`,
shared between both flows. `+define+DTP_UVM_TB` (set by the `dtp_uvm` sim
config) switches its shape — without it the module exposes the cocotb pin
port list; with it the ports become internal TB signals and an in-module
harness adds the clock, interface instances, quiescent tie-offs, and
`run_test()`. The class library mirrors the cocotb directory conventions
under `uvm/`:

[arabic]
. `hw/common/dv/vip/ocah_jtag_vip/interface/ocah_jtag_if.sv` — shared
  pin-level IEEE 1149.1 interface (JTAG pins only; reused by any DUT)
. `tb/dtp_tb_if.sv` — DTP-local resets and one-hot TAP-state observable
. `hw/common/dv/vip/ocah_jtag_vip/uvm/ocah_jtag_uvm_pkg.sv` — shared SV-UVM
  JTAG VIP (item/cfg/driver/monitor/sequencer/agent/env + encoding-agnostic
  IEEE 1149.1 TAP model); the driver owns the pin-level TCK bit-bang, the
  passive monitor publishes per-TCK `STEP` and async `TRST` events, and
  `ocah_jtag_master_env` is the commercial-overridable unit DUT envs instantiate
. `uvm/seq_lib/dtp_seq_lib_pkg.sv` — `dtp_jtag_base_seq` issues
  `ocah_jtag_item`s (TAP reset, IR/DR scans, raw TMS walks) on the agent's
  sequencer and keeps the DTP-local reset sequencing, scan-path checks, and
  the BYPASS latency check; scenario sequences (`dtp_sanity_seq`) extend it;
  partially reusable
. `uvm/env/dtp_env_pkg.sv` — `dtp_uvm_env` builds the JTAG agent and
  `dtp_tap_fsm_checker` (a monitor-event subscriber holding the IEEE 1149.1
  reference model: per-cycle legality always on, state/edge closure asserted
  by closure-obligated scenarios); fully reusable
. `uvm/tests/dtp_tests.sv` — non-reusable thin test classes
  (`dtp_uvm_base_test`, `dtp_uvm_sanity_test`), `include`d by `tb_top.sv`
  under `ifdef DTP_UVM_TB` (+UVM_TESTNAME selects the class); the sanity
  test starts its sequence on the agent sequencer and then invokes
  `check_fsm_closure()`

Compile order is explicit and load-bearing: interfaces first, then
`ocah_jtag_uvm_pkg`, `dtp_seq_lib_pkg`, `dtp_env_pkg`, and `tb_top.sv` last.

==== JTAG2AXI Checker Layer

The UVM harness additionally consumes the shared `ocah_axi_vip` SV layer:

* `tb/tb_top.sv` (UVM block) replaces the historical never-responding OTP
  tie-off and the undriven `m_axi_*` response inputs with error-injectable
  responders: the shared `ocah_axi_vip` UVM slave agent answers
  `smc_otp_axil` (reactive `ocah_axi_slave_driver` over a dedicated
  `ocah_axi_if` instance, injection programmed via
  `ocah_axi_slave_sequence`), and the behavioral `ocah_axi_ram_responder`
  module answers `m_axi`. It instantiates `ocah_axi_if` monitor adapters and
  the clean-room `ocah_axi_sva` SVA on both ports, and mirrors the
  request-activity pulse counters into `dtp_tb_if`. The `sep_otp_axil` port
  keeps its tie-off (documented stretch).
* `tb/dtp_tb_if.sv` carries test-drivable lifecycle enables (init 0 preserves
  the old gated-off tie-off for the sanity test), responder error controls,
  the SVA `axi_sva_en` knob, and counter mirrors.
* `dtp_uvm_env` builds one passive `ocah_axi_env` (monitor -> reference model
  -> scoreboard with `CHK-*`/`CHECKER_SUMMARY` evidence) per observed port;
  zero-check rejection (`cfg.require_checks`) is armed only by AXI tests so
  `dtp_uvm_sanity_test` is unaffected.
* `uvm/seq_lib/dtp_jtag2axi_base_seq.svh` mirrors the cocotb helper layer:
  SINGLE_OP DR packing (LSB-first `OP|SIZE|WSTRB|DATA|ADDR`, 72b OTP / 132b
  SMC via the JTAG VIP wide-scan `wbits`/`rbits` path), busy polling,
  lifecycle sequencing, and `arm_target_error()` which drives the responder
  error ports AND `ocah_axi_config.arm_expected_resp()` in one place — the
  injected non-OKAY is therefore EXPECTED for the scoreboard.
* `dtp_jtag2axi_single_op_seq` runs randomized write/readback, armed
  SLVERR/DECERR, recovery, and a security-gating no-activity case
  (`CHK-AXI-GATE-*` from the pulse-counter mirrors);
  `dtp_uvm_jtag2axi_smc_otp_test` and `dtp_uvm_jtag2axi_smc_axi_test` set the
  required evidence IDs (`CHK-AXI-RESP/RDATA/ERR-INJ/GATE-*`).

Logical item names stay framework-neutral and match the VPLAN scenarios
(testlist `name = "dtp_sanity_test"`, `module = "dtp_uvm_sanity_test"`), so
`--items dtp_sanity_test` selects the same scenario in either flow. The SV-UVM
sanity test implements the VPLAN 0.1 checkers: a deterministic 32-edge TAP FSM
closure walk checked against an IEEE 1149.1 reference model, BYPASS (6-bit IR
0x00) 1-TCK TDI-to-TDO latency, clean scan-path returns, and randomized TMS
stress walks reproducible from the runner seed. `UVM TEST PASSED` is emitted
only in `report_phase` when the global UVM_ERROR/UVM_FATAL counts are zero,
matching the `uvm-log` parser policy.

=== Build and Run

[source,bash]
----
python3 tools/dv/run_dv.py --dut dtp --items dtp_sanity_test
python3 tools/dv/run_dv.py --dut dtp --items dtp_jtag_idcode_test
python3 tools/dv/run_dv.py --dut dtp --items basic_jtag
python3 tools/dv/run_dv.py --dut dtp --items debug_tdr
python3 tools/dv/run_dv.py --dut dtp --items dtp_jtag2axi_smc_axi_wr_test
python3 tools/dv/run_dv.py --dut dtp --items dtp_jtag2axi_smc_axi_rd_test
python3 tools/dv/run_dv.py --dut dtp --items functional
python3 tools/dv/run_dv.py --dut dtp --items all --dry-run

# SV-UVM smoke layer (VCS, maintainer flow)
python3 tools/dv/run_dv.py --dut dtp_uvm --items dtp_sanity_test --tool vcs --seed 1
python3 tools/dv/run_dv.py --dut dtp_uvm --items smoke --tool vcs
----

The `smoke` group remains a fast two-test TAP/IDCODE gate. The `basic_jtag`
group runs all 19 Smoke and Basic JTAG scenarios. The `debug_tdr` group runs 12
TMP_STATUS, IC_RESET, DEBUG_CONTROL, and CAPS scenarios. The `functional` group
runs the legacy four public DTP smoke/JTAG2AXI tests, while `all` collects the
included public DTP testlists.
