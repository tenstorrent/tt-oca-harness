[[dtp-dv-testbench-architecture]]
== DTP OCAH Open-Source Testbench Architecture

=== Overview

[cols=",",options="header",]
|===
|Field |Value
|DUT |`dtp` (`hw/sys/dtp/rtl/dtp.sv`)
|Repository |`tt-oca-harness`
|Project |OCAH
|Framework |One UVM environment, realized in PyUVM on cocotb (`cocotb/`) and in SystemVerilog UVM (`uvm/`, `--framework uvm`)
|Primary simulator |Verilator (cocotb realization; the PR gate and the scheduled regressions)
|Supported simulator matrix |cocotb on `verilator` (default), `vcs`, and `xcelium`; SV-UVM on `vcs` only, because Verilator has no SV-UVM support and the runner's SV-UVM flow is VCS-only (`run_dv.py --list --json` reports the pairs for `dtp`)
|Commercial simulator use |SV covergroup, assertion, and code coverage collection; the SV-UVM realization
|===

The OCAH open-source DTP testbench follows the canonical `hw/sys/<system>/dv/` layout under
`hw/sys/dtp/dv/`. One testbench top (`tb/tb_top.sv`) serves both realizations,
and both compose the shared OCAH VIPs (`hw/common/dv/vip/`) for the standard
interfaces; both extend the shared framework library
`hw/common/dv/vip/ocah_lib/`. Scenario names, testlist bindings, knob names,
the evidence grammar, and the functional-coverage modules are common to both.

=== VIP Selection Policy

[arabic]
. Import unified OCAH BFM wrappers from `hw/common/dv/vip` for standard
protocol access.
. Wrap those BFMs in PyUVM agents so tests remain sequence-based and reusable.
. Use OCAH-local BFMs/models for custom OCAH protocols and for standards that
have no shared wrapper.
. Keep every BFM behind the same transaction-level agent boundary so backend
changes do not affect sequences or scoreboards.

[cols=",,,",options="header",]
|===
|DTP Interface |Preferred VIP |Modeling Approach |Notes
|Primary JTAG TAP |`ocah_jtag_vip` `OcahJtagMasterDriver` |Unified OCAH BFM |Active JTAG transaction driver and TAP helper
|SMC fabric AXI4 manager |`ocah_axi_vip` `OcahAxiSlaveAgent` |Unified OCAH BFM |AXI memory responder with scoreboard backdoor access
|SMC/SEP OTP AXI-Lite managers |`ocah_axi_vip` AXI-Lite wrapper |Unified OCAH BFM |AXI-Lite responder model for OTP bridge scenarios
|XTRIG AXI-Lite CSR subordinate |`ocah_axi_vip` AXI-Lite master |Unified OCAH BFM |Shared AXI-Lite master on `u_xtrig_master_if`; channel-skew, RREADY-hold, and partial-strobe operations come from its sequence API
|BSR scan loopback |Minimal OCAH-local scan model |OCAH-local simple model |Compact scan loopback and observable model
|STAP host ports / 3DCR |`ocah_jtag_vip` slave devices (`OcahJtagSlaveAgent`, cocotb / `ocah_jtag_slave_agent`, SV-UVM) behind an OCAH-local chain model |Unified OCAH BFM + OCAH-local model |Wire loopback by default; the STAP-selection scenarios splice one reactive downstream TAP per port and judge it through `ocah_jtag_slave_sequence`
|iJTAG SIB networks |OCAH-local IEEE 1687 model |OCAH-local model |IEEE 1687 scan-network transaction model
|CTP/CTM cross-trigger protocols |OCAH-local BFMs |OCAH-local BFM |CTP/CTM protocol BFMs; debug TDR clock-stop requests may be driven directly in the TB
|===

=== DUT-Local Model Ownership

The shared promotion checklist is defined in `hw/common/dv/README.md`. The DTP
models below are DUT-local because they encode this DUT's topology, lifecycle
rules, signal binding, or testbench fixtures:

[cols=",,,",options="header",]
|===
|Model / Helper |Scope |Why It Is DUT-Local |Shared-VIP criterion
|`DtpScanModel` |8-bit BSR identity-loopback stimulus and checking |Models the compact DTP TB fixture, not generic IEEE 1149.1 boundary cells |A parameterized boundary-cell model with an independent DUT consumer
|`DtpIjtagSibModel` |Three DTP SIBs with stored-open retention under a gate, per-SIB debug-disable gates, the bench's instrument stubs (chain layout, composed scans, capture prediction, latched instrument values) |Hard-coded DTP scan topology, stub widths, and security policy |Topology/instrument-neutral IEEE 1687 transactions plus a second consumer
|`DtpStap3dcrModel` |Composed TAP_3DCR chain state (PTAP 3DCR, per-STAP SIB and 3DCR), network-wide IR-scan composition, capture prediction, per-STAP debug-disable update blocking, and the downstream TAP segments (IR, IDCODE, BYPASS, or a latched register) of the `ocah_jtag_vip` devices attached behind the STAP host ports |The chain hierarchy, the splice flops, and the downstream parking rules are DTP-specific |A parameterized IEEE 1838/STAP model with an independent DUT consumer
|`DtpXtrigBfm` / `DtpCtmRefModel` |DTP CTP wire-OR/P2P pins, CTM masks, CSR layout from the generated cross-trigger register headers |Assumes DTP port counts, flattened signal names, and OCAH routing policy |Parameterized binding and port counts with an independent consumer
|`DtpBypassSuiteCfg` / `DtpBypassRefModel` |BYPASS opcode, pattern, capture, and one-bit-delay prediction |Encodes the DTP BYPASS scenario and evidence context |An independent JTAG consumer of the same model
|DTP TDR maps/packers |DTP instruction/register semantics layered over `ocah_jtag_vip` |Register layout and polling policy are DUT semantics, not JTAG protocol |A domain consumer of the same DTP register contract
|===

The shared `ocah_jtag_vip` and `ocah_axi_vip` packages own protocol-neutral
driving, monitoring, result, and error behavior. DTP agents own
hierarchy binding, address/TDR maps, expected values, debug-disable
policy, and scoreboarding.

=== BYPASS Reference-Model Contract

The DTP BYPASS scenario is the concrete reference-model/scoreboard example:

[source,text]
----
DtpBypassSuiteCfg
  -> load_ir / shift_dr JTAG stimulus
  -> DtpBypassRefModel.predict(case) -> expected TDO
completed DtpJtagItem.result         -> observed TDO
expected + observed
  -> OcahJtagChecker
  -> CHK-BYPASS-* / CHK-NONVAC / CHECKER_SUMMARY
----

The frozen suite config is the single source for opcode, width, pattern,
capture bit, seed, and evidence context. The pure model has no simulator
handles or DUT reads. Aggregate checker mode lets every configured case run;
finalization then reports total checks/errors/missing IDs before failing.
Passing `results.xml` and native `result.json` are the run authority.

=== Testbench Hierarchy

One component tree from the test down to the pins; the two realizations
differ only where the language forces it (table below).

[source,text]
----
dtp_<scenario>_test          thin: create_scenario_seq(), loop-knob names,
  -> dtp_base_test            configure_test_cfg() (required features, evidence IDs)
       build:  dtp_test_cfg   seed and knobs -> randomize(): clock and TCK periods
               dtp_env_cfg    derived -> config_db -> dtp_env
       run:    bring_up()     reset ladder through the TB interface
               run_looped_scenario()  dtp_<scenario>_test_seq on dtp_env.m_vseqr,
                                      one pass per loop, scenario_seed = seed + pass

dtp_<scenario>_test_seq       virtual sequence on dtp_virtual_sequencer; one flow
  -> dtp_<family>_base_test_seq  (jtag, jtag2axi, debug_tdr, scan, xtrig)
  -> dtp_base_test_seq           TAP-state tracking, DTP checks, system-domain waits
       starts reusable operations on the virtual sequencer's typed handles:
         dtp_jtag_<op>_seq          -> m_jtag_seqr   (ocah_jtag_master_sequence)
         dtp_jtag2axi_<op>_seq      -> m_jtag_seqr
         dtp_axi_csr_<op>_seq       -> m_xtrig_seqr  (ocah_axi_master_sequence)
         responder backdoor/inject  -> m_<target>_slave_seq, m_stap_ds_seq[i]
       per-scenario evidence checker (required IDs) -> finalize() at end of body()

dtp_env                       composes; drives nothing; checks no protocol
  -> dtp_virtual_sequencer    m_jtag_seqr, m_xtrig_seqr, three AXI responder
                              sequences, four downstream STAP device sequences
  -> ocah_jtag_master_env     primary TAP: sequencer, driver, monitor (event_ap)
  -> ocah_axi_master_env      XTRIG CSR AXI-Lite initiator
  -> ocah_axi_slave_agent x3  SMC OTP / SEP OTP AXI-Lite, SMC fabric (AXI4) responders
  -> ocah_axi_env x4          passive per port: monitor -> ref model -> scoreboard -> checker
                              (monitor only on the XTRIG CSR port)
  -> ocah_jtag_slave_agent x4 downstream STAP TAPs, attached per test
  -> dtp_<feature>_ref_model  one per scoreboard feature: subscriber on the monitor
                              stream the feature is judged on (event_ap, scan_ap, the
                              XTRIG or bridge item_ap) and dtp_tb_if; holds a plain
                              dtp_<x>_model; publishes expected items on expected_ap
  -> dtp_scoreboard ALWAYS ON pairs each feature's expected_ap with its observed stream:
                              ir_decode, idcode, bypass, xtrig_csr, xtrig_decode,
                              jtag2axi_req, jtag2axi_status; predicts nothing; a required
                              feature with zero comparisons or an unpaired item fails
  -> dtp_tap_fsm_checker      subscriber on event_ap; VIP TAP reference model
  -> dtp_scan_window_monitor  subscriber on event_ap; temporal scan-control windows
  -> ocah_jtag_scan_builder   IR/DR scan reconstruction (scan_ap)
  -> ocah_jtag_checker        env-owned aggregate evidence, finalized once

tb/tb_top.sv                  one framework-neutral core: interface instances, DUT,
                              adapters, counters, coverage, protocol SVA; the UVM
                              block adds the clock generator, config_db publication,
                              run_test()
  dtp_tb_if                   control domain: clock and period, resets and counters,
                              named debug disables, TAP-state and debug-TDR observables,
                              request-activity counters, JTAG2AXI bridge FSM, pending
                              and CDC-clear observables, SVA enables
  dtp_scan_if                 scan domain: scan-chain controls, forwarded STAP pins,
                              downstream-TAP attach enables
  dtp_xtrig_if                cross-trigger domain: CTM req/ack pairs, CTP pad quartets
  ocah_jtag_if x5             primary TAP and four downstream STAP TAPs
  ocah_axi_if x8              one active and one passive instance per DTP bus
----

|===
|Element |cocotb (PyUVM), `cocotb/` |SV-UVM, `uvm/`
|Framework bases |`ocah_lib` bases for the test and the base sequence (`OcahTest`, `OcahSequence`, with `OcahKnobs` and `OcahRng` behind them); the env, agents, and scoreboard on bare `pyuvm` classes |`ocah_lib_pkg` bases (`ocah_test`, `ocah_env`, `ocah_sequence`, `ocah_sequencer`, `ocah_scoreboard`, `ocah_ref_model`, `ocah_subscriber`)

|Clock |`Clock(...)` on `dtp_tb_if.clk` in the base test bring-up, period from the env cfg |`always` in the harness block toggling `dtp_tb_if.clk`, period from `dtp_tb_if.clk_period_ns` set by `dtp_env`
|Knob transport |environment variables |plusargs through `ocah_knobs`
|Seed source |`RANDOM_SEED` |`+ntb_random_seed`
|Run verdict |phase assertions, `results.xml` |`UVM_ERROR`/`UVM_FATAL` counts plus `UVM TEST PASSED` from `report_phase`
|Tests |one module per scenario, `@pyuvm.test()` |one class per scenario, `include`d by `dtp_tests.sv` in module scope
|===

=== HDL Top

`tb/tb_top.sv` (`dtp_uvm_top`) is one framework-neutral core with no ports: it
instantiates the TB interfaces, the `dtp` DUT, the adapters between the DUT's
packed structs and the interface members, the reset and request-activity
counters, the functional-coverage modules, and the protocol SVA checkers. Both
realizations consume the same interface instances: SV-UVM through
`uvm_config_db`, cocotb through the hierarchical handles `DtpTbIf`
(`cocotb/env/dtp_tb_if.py`) holds. The `UVM` define adds the harness block:
the clock generator on `dtp_tb_if.clk`, the test classes, the `uvm_config_db`
publication of every instance, and `run_test()`. The `ocah_axi_if` instances carry the interface's
default geometry so the SV-UVM layer sees one virtual type; cocotb binds them
through `OcahAxiConfig.bus()` at each bus's real geometry.

[cols=",",options="header",]
|===
|DUT Interface |`tb_top` Handling
|JTAG TAP |`u_jtag_if` (`ocah_jtag_if`): the shared JTAG master drives tck/tms/trst_n/tdi, the DUT drives tdo/tdo_oen
|SMC fabric AXI4 |`+axi_smc_dbg_*+` structs flattened onto `u_smc_axi_slave_if` (responder) and mirrored onto `u_m_axi_if` (monitor); real geometry ID 2 / ADDR 56 / DATA 64 / USER 12 in the VIP configs
|Debug disables |One named `dtp_tb_if.dbg_disable_<field>` member per `dbg_disable_i` path (init 1 = fail-closed), bound by field name into the typed `sep_lifecycle_ctrl_pkg::dbg_disable_t` that `tb_top` forwards to `dbg_disable_i`; cocotb deposits the members by name and SV-UVM writes them through `dtp_tb_if.drive_dbg_disable`; base bring-up drives the all-clear/full-debug startup vector and tests assert disables explicitly
|JTAG2AXI bridge state |`dtp_tb_if.<target>_fsm_state`, `<target>_op_pending` and the sticky `<target>_cdc_clear_seen` per bridge, driven by `tb_top` from the bridges' TCK-domain FSM and pending registers and the `axi_cdc_clearable` instance's `src_clear_pending_o` through the hierarchical references the coverage instance uses; `cdc_clear_seen_clear` clears the sticky flags. cocotb reads them through `DtpTbIf.bridge_fsm_state`, `bridge_op_pending` and `cdc_clear_seen`; SV-UVM through the JTAG2AXI base sequence's functions of the same names
|BSR |Looped back; the chain controls mirrored onto `dtp_scan_if`
|iJTAG SIB host chains |One `prim_jtag_scan_reg` instrument stub per SIB (4, 5, 6 bits behind secure DFT, non-secure DFT, DFD) that captures its own update register, so open-SIB subsets have distinct chain lengths and a written value reads back on the next scan; the chain controls mirrored onto `dtp_scan_if`
|STAP host ports |Loopback (`tdi <- tdo`) by default; `dtp_scan_if.stap_<x>_ds_en` splices the downstream `u_stap_<x>_ds_if` TAP behind the port for the STAP-selection scenarios; the forwarded TAP pins mirrored onto `dtp_scan_if`
|SMC/SEP OTP AXI-Lite |Flattened onto `u_smc_otp_slave_if` / `u_sep_otp_slave_if` (responders) and `u_smc_otp_axil_if` / `u_sep_otp_axil_if` (monitors); real geometry 32/32
|DEBUG_CONTROL and IC_RESET |Boot-stall, clock-stop, and IC_RESET struct outputs flattened onto `dtp_tb_if`; `dtp_tb_if.xtrig_clk_stop_req` drives the CLA clock-stop requests
|XTRIG CSR/CTP/CTM |`u_xtrig_master_if` (initiator) and `u_xtrig_axil_if` (monitor) for the CSR port (the generated CSR blocks elaborate under Verilator); CTM/CTP pins on `dtp_xtrig_if`
|Clocks/resets |`dtp_tb_if.clk`, `sys_rst_n`, `por_rst_n`: cocotb deposits them, the UVM harness generates the clock and sequences drive the resets; the JTAG master owns TCK/TRST sequencing
|===

The three JTAG2AXI bridge geometries (bus type, address width, data width) live
in one table per realization, `JTAG2AXI_TARGETS` in `cocotb/env/dtp_types.py`
and the `dtp_j2a_target_*` functions in `uvm/env/dtp_types.svh`, holding the
values each bridge publishes in its `*_JTAG2AXI_CAPS` TDR; every other TDR field
width derives from those three values by the `*_AXI_SINGLE_OP` and
`*_AXI_SERIES_CTRL` tables of the PTAP document. Every JTAG2AXI scenario opens
each pass with the geometry gate in the JTAG2AXI base sequence's `pre_body`: it
reads the three `*_JTAG2AXI_CAPS` TDRs and records `CHK-J2A-GEOMETRY` against
the table, so a DUT that publishes a different geometry fails before any bridge
request is packed.

=== Environment Components

==== Configuration: `dtp_test_cfg` and `dtp_env_cfg`

`dtp_test_cfg` is the highest configuration level and the only object the
seed touches: the runner seed and random volume, the randomized system-clock
period (10..100 ns) and TCK period (100..1000 ns), the knob-derived controls
(IDCODE reads per pass, JTAG2AXI random operations, random walks, matrix
rows), the negative-validation switches, the downstream STAP attach mask, the
scoreboard features a test requires, and the required evidence IDs of each
shared-VIP recorder. The base test fills and randomizes it once; a thin test
adds its requirements in `configure_test_cfg()`. `dtp_env_cfg` is derived
from it (clock and TCK timing, responder memory size, attach mask, evidence
policy) and is what the environment reads. The cocotb `DtpEnvCfg` carries
the same timing randomization.

==== `dtp_virtual_sequencer`

The handle set every scenario coordinates through: `m_jtag_seqr`
(`ocah_jtag_master_sequencer`, the primary TAP), `m_xtrig_seqr`
(`ocah_axi_master_sequencer`, the XTRIG CSR AXI-Lite initiator), the three
JTAG2AXI responder sequences (`m_smc_otp_slave_seq`, `m_sep_otp_slave_seq`,
`m_smc_axi_slave_seq`, `ocah_axi_slave_sequence`), and the four downstream
STAP device sequences (`m_stap_ds_seq[i]`, `ocah_jtag_slave_sequence`, in
io, smc, sep, extra0 order). It holds nothing else.

==== Shared VIP environments and agents

`dtp_env` fills one VIP config per port from `dtp_env_cfg` (interface,
geometry, `name_tag`, evidence policy) and builds: the active
`ocah_jtag_master_env` on the primary TAP (the commercial-overridable unit;
its `event_ap` feeds every JTAG checker); the active `ocah_axi_master_env`
driving the XTRIG CSR AXI-Lite port; one memory-backed, fault-capable
`ocah_axi_slave_agent` per JTAG2AXI bridge (SMC OTP and SEP OTP AXI-Lite,
SMC fabric AXI4), reached only through their responder sequences; one
passive `ocah_axi_env` per observed port (monitor, reference model,
scoreboard, evidence; monitor-only on the XTRIG CSR port, whose volatile
status reads and reset-cleared selects the memory-shadow model cannot
describe); and one `ocah_jtag_slave_agent` per STAP host port as the
downstream TAP a test may splice behind it (`dtp_scan_if.stap_<x>_ds_en`;
default keeps the wire loopback). The cocotb realization wraps the same
shared engines in `DtpJtagAgent`, `DtpAxiAgent`, `DtpXtrigAgent`, and
`DtpStapDsAgent`.

==== `dtp_scoreboard` and the reference models

Always on, in every test, and comparing only. Every feature is judged on two
streams: the observed VIP monitor stream, and the expected items published on
`expected_ap` by that feature's `dtp_<feature>_ref_model`, a subscriber
(`ocah_ref_model`) on the same monitor stream and `dtp_tb_if` that holds any
plain `dtp_<x>_model` it needs and neither compares nor reports. The
scoreboard pairs the two streams in order per feature and lane
(`ocah_scoreboard`), extracts the observed value from the monitor item,
records the verdict, and counts; it holds no expected-value state. Expected
values come from the DUT collateral and the stimulus the monitors saw, never
from the observation under check.

|`idcode` |`dtp_idcode_ref_model` (`dtp_jtag_ir_model`) on the scan and event streams |Reconstructed DR scans (TDO bits) |While IDCODE is active (after TAP reset or an explicit load), the shifted-out low 32 bits equal the DTP device identification |IDCODE, sanity, reset-family tests
|`bypass` |`dtp_bypass_ref_model` (`dtp_jtag_ir_model`) on the scan and event streams |Reconstructed DR scans (TDO bits) |Under a bypass-class instruction the TDO is TDI delayed by one TCK; INV_BYPASS the inverted delayed image behind a captured 1; ZERO_LENGTH_BYPASS TDI itself |bypass, inverted bypass, zero-length bypass, undefined-instruction, sanity tests
|`xtrig_csr` |`dtp_xtrig_csr_ref_model` (`dtp_xtrig_csr_model`) on the XTRIG monitor stream |Passive XTRIG AXI-Lite monitor items (read data) |Every OKAY read of a CSR with a readback contract (CTM selects, CTP CONFIG, STRETCH_MULT) equals the shadow rebuilt from the observed writes and cleared on every reset (`dtp_tb_if` reset counters) |every cross-trigger test but the decode-error scenario
|`xtrig_decode` |`dtp_xtrig_decode_ref_model` (stateless) on the XTRIG monitor stream |Passive XTRIG AXI-Lite monitor items (response) |Every access to the unmapped cross-trigger address space completes with DECERR |the read-decode backpressure test
|`jtag2axi_req` |`dtp_jtag2axi_req_ref_model` (`dtp_jtag_ir_model`, `dtp_jtag2axi_model`) on the scan and event streams and the three bridge port streams |Passive monitor items of the three bridge ports, one lane per port |Every bridge transaction is the one its decoded JTAG request asked for (direction, address, size on AXI4, strobes, strobed write data), in order; every request that the bridge accepts lands on the bus, and none does while the bridge's lifecycle disable is asserted |every test arming a bridge recorder
|`jtag2axi_status` |`dtp_jtag2axi_status_ref_model` (`dtp_jtag_ir_model`, `dtp_jtag2axi_model`) on the same streams |Reconstructed DR scans (the SINGLE_OP or SERIES_CTRL capture) |The captured status is the outcome of the completed transactions behind it (SUCCESS, SLVERR, DECERR, BUSY_OR_FULL while pending) and the SINGLE_OP data field after a completed OKAY read is the word the bus returned |every test arming a bridge recorder
|===

Composed scans (a wider instruction scan spanning the STAP chain, or a DR
scan after one) make the primary-TAP instruction unrecoverable at this level,
so the JTAG reference models stand down until the next plain instruction load
or TAP reset. An instruction scan that reaches Update-IR without a Shift-IR
cycle latches the Capture-IR pattern, 01 in the two LSBs and zeros above
(IEEE 1149.1 7.1.1, `jtag_inst_reg`), which is the IDCODE opcode; the models
track it as an IDCODE load. STATUS reads carry no data contract. A reference
model on a one-to-one stream publishes one expected item per observed item,
marking the ones outside its contract as carrying none, so the two streams
stay in lockstep; the bridge request model publishes one item per launched
transaction on the lane of its port. The bridge model follows the jtag2axi
update, capture, and completion rules (single-operation rejection while
pending, the series address and read budget per CTRL programming, the
byte-lane placement of series transfers, reset on Test-Logic-Reset) and
applies completions at the capture or update that follows them, so a capture
during a shift sees the state of its own Capture-DR; a capture inside the CDC
settle window after a completion carries no contract, and the series read-data
FIFO is not predicted. Each feature ends the run as one `CHK-SB-<FEATURE>`
record through the shared evidence recorder; a required feature with zero
comparisons fails, and so does any item left unpaired.

The cocotb `DtpScoreboard` checks inline on the JTAG agent's completed-item
stream (IDCODE reads, JTAG2AXI write and read data against the responder
memory), and every cocotb JTAG2AXI test also enables the shared `ocah_axi_vip`
scoreboard with required evidence IDs and per-stream minimum counts.

==== `dtp_tap_fsm_checker` and `dtp_scan_window_monitor`

`dtp_tap_fsm_checker` is the always-on invariant subscriber on the JTAG
event stream: on every completed TCK cycle the DUT one-hot TAP state must
match the VIP IEEE 1149.1 next-state model, and the run ends as one
aggregate `CHK-TAP-STATE` record; the sanity scenario additionally asserts
full state and edge closure. `dtp_scan_window_monitor` counts high samples
of named scan-control observables once per TCK cycle while a scenario holds
a window open, so a gated resource proves zero control pulses across a whole
composed scan and an enabled resource proves the expected pulses; the
cocotb twin is `DtpScanControlWindowMonitor`.

==== Plain models

Plain model classes without simulator handles or reporting, held by a
reference model or by a scenario sequence: `dtp_jtag_ir_model` (TAP state and
the active primary-TAP instruction, held by every JTAG reference model),
`dtp_xtrig_csr_model` (the CSR readback shadow), `dtp_jtag2axi_model` (the
JTAG-visible state of the three bridges), `dtp_ijtag_sib_model` (SIB
requested, gated, and effective state under a disable mask),
`dtp_stap_ds_state` and `dtp_stap_3dcr_model` (the PTAP 3DCR and STAP
configuration chain with the downstream TAP segments, composed-scan values
and capture prediction; held by the scan scenarios), `dtp_xtrig_ctm_model`
(OR of the selected input ports onto each output, per the cross-trigger matrix
register map; held by the cross-trigger scenarios and compared against the DUT
output vector on every route as a scenario-level check). The
cocotb twins live in
`env/dtp_scan_ref_model.py` and `env/dtp_xtrig_types.py`.

Two tiers, one readable flow per scenario.

`_test_seq`, reusable operations in `_seq`.

|===
|Clock / Reset |cocotb realization |SV-UVM realization |Notes

=== Stimulus Strategy

Stimulus is directed and deterministic except for seeded randomization in
the debug TDR and Basic JTAG pattern sweeps, the JTAG2AXI random operations,
and the cross-trigger route selections. Randomization happens at the
test-cfg level (timing) and in
each scenario pass from its per-pass seed.

[cols=",",options="header",]
|===
|Area |Strategy
|Smoke |Verify TAP FSM traversal and IDCODE readout through focused JTAG tests
|Basic JTAG |Verify primary TAP instruction decode, bypass variants, reset behavior, and compact BSR loopback smoke behavior
|Debug TDR |Verify TMP_STATUS, IC_RESET, DEBUG_CONTROL, JTAG_CAPS, and JTAG2AXI_CAPS with decoded logs, deterministic loops, seeded random patterns, and read-only sweeps
|JTAG2AXI write |Shift a single-op write request, poll completion, check the responder memory
|JTAG2AXI read |Backdoor-preload the responder memory, shift a single-op read request, poll completion, compare data
|===

Additional stimulus categories cover OTP bridge operations, STAP/3DCR, iJTAG,
XTRIG CSR, CTP, CTM, and per-field debug-disable gating (the `dbg_disable`
matrix tests drive one-hot, boundary, and seeded multi-hot disable vectors).

Every looped scenario runs at least 16 passes with `scenario_seed = seed +
pass`, resolved through the same knob names in both realizations:
`+<SCENARIO>_LOOPS` (per test), the group knobs (`DTP_BASIC_JTAG_TEST_LOOPS`,
`DTP_DEBUG_TDR_TEST_LOOPS`, `DTP_JTAG2AXI_TEST_LOOPS`, `DTP_SCAN_TEST_LOOPS`,
`DTP_XTRIG_TEST_LOOPS`), `DTP_TEST_LOOPS` (suite-wide), `DTP_RANDOM_COUNT`
(random volume per pass), plus the scenario knobs `DTP_IDCODE_READS_PER_LOOP`,
`DTP_JTAG2AXI_RANDOM_OPS`, `DTP_RAND_WALKS`, and
`DTP_DBG_DISABLE_MULTI_HOT_ROWS`. The base-test hooks are
`create_scenario_seq`, `configure_test_cfg`, `plumb_scenario_seq`,
`bring_up`, `run_looped_scenario`, `specific_loops_knob`, `group_loops_knob`,
and `default_loops`.

=== Checking Strategy

Five checking places, each owned once, in this order of authority. The four
class-level places emit the `CHK-<ID> PASS|FAIL expected= observed= context=`
grammar and finalize exactly once with a `CHECKER_SUMMARY`; the protocol SVA
report through their assertion action blocks.

[cols=",,,",options="header",]
|===
|Place |Owns |Feed |Fails when
|`dtp_scoreboard` (mandatory, always on) with one `dtp_<feature>_ref_model` per feature |`ir_decode`, `idcode`, `bypass`, `xtrig_csr`, `xtrig_decode`, `jtag2axi_req`, `jtag2axi_status` |JTAG monitor event and scan streams, XTRIG monitor stream, the three bridge port monitor streams, `dtp_tb_if` observables and reset counters; the reference model publishes the expected item, the scoreboard pairs it with the observed one |Any pair mismatches, an item is left unpaired, or a required feature ends with zero comparisons
|Env subscribers |`dtp_tap_fsm_checker` (per-cycle TAP legality, closure on demand), `dtp_scan_window_monitor` (temporal scan-control windows) |JTAG monitor event stream |Any illegal transition; zero activity when activity is required; a gated control pulsing inside a window
|Passive `ocah_axi_env` per port |Response codes, addresses, data, strobes, completion, ordering; expected non-OKAY responses armed by the scenario alongside the injection |The VIP's own monitor and reference model |Any protocol violation; zero checks or a missing required ID when the test armed the recorder
|Per-scenario checkers and the env aggregate |Scenario intents by named ID (`CHK-BYPASS-*`, `CHK-IR-DECODE`, `CHK-DBG-*`, `CHK-SCAN-*`, `CHK-DS-*`, `CHK-XTRIG-*`, `CHK-AXI-*`), non-vacuity, the pin-level scan cross-check |The scenario's reads through the reusable operations; the env `ocah_jtag_checker` |A retained failure, zero checks, or a missing required ID at finalize
|Protocol SVA in the `tb_top.sv` core (`ocah_jtag_sva` on the primary TAP, `ocah_axi_sva` per bus) |Pin-level IEEE 1149.1 and IHI 0022 rules: the two-state set on every simulator (Verilator under `--assert`), the X-hygiene set on four-state simulators |The flat TB nets, gated by `dtp_tb_if.jtag_sva_en` / `axi_sva_en` |Any rule violation: `%Error` and a simulation stop under Verilator, `uvm_error` under SV-UVM
|===

Negative validation proves each checking path can fail:
`DTP_JTAG_FAMILY_CHECKER_NEGATIVE` corrupts every family expectation,
`DTP_JTAG_TAP_CHECKER_NEGATIVE` arms a wrong IDCODE, `DTP_AXI_SCOREBOARD_NEGATIVE`
arms the wrong expected response, `DTP_XTRIG_CHECKER_NEGATIVE` inverts the
CTM model selects, and (SV-UVM) `DTP_J2A_REF_MODEL_NEGATIVE` makes the bridge
request reference model predict corrupted addresses so the scoreboard pairing
fails against the observed bus; a run with any of them set must fail. The same
knob names are environment variables in cocotb and plusargs in SV-UVM.

=== Coverage Strategy

Verilator does not compile SV covergroups. The `cov/sv/` coverage modules,
instantiated once in the shared `tb_top`, carry labeled `cover property`
points that Verilator records as user coverage and the same bins as
covergroups for the commercial simulators; the debug-disable 22-cell
contract keeps its checker-gated Python ledger. Assertion coverage and full
code coverage come from the commercial simulators. See `DTP_FCOV.adoc`.

=== Canonical RTL Selection

Bender supplies the HW-owned `prim_sync2` and generated
`cross_trigger_port_reg` and `cross_trigger_matrix_reg` implementations to the
DTP simulator flows. Verilator and VCS therefore compile the same synchronizer
and CSR RTL selected by the subsystem source graph.

=== SystemVerilog UVM Realization (`--framework uvm`)

The SV-UVM realization runs through the same native runner: `dtp_sim_cfg.toml`
declares it as the `[frameworks.uvm]` overlay (shared DV root, sim config, and
testlist; `build/uvm/` build tree), and `--dut dtp --framework uvm` selects
it on VCS (the `native` profile's `uvm` framework, `-ntb_opts uvm`). Scenarios
carry both implementations in their testlist `module` binding map; those
without a `uvm` entry error at selection unless `--skip-unimplemented` is
passed.

There is exactly ONE testbench top module: `dtp_uvm_top` in `tb/tb_top.sv`,
a framework-neutral core with no ports (interface instances, DUT, adapters,
counters, coverage, protocol SVA) shared between both realizations. The bare
`+define+UVM` (set by the native profile's `[frameworks.uvm]` overlay) adds
the harness block: the clock generator (period from `dtp_tb_if`), the
`uvm_config_db` publication of every interface instance, the test classes,
and `run_test()`.
Preprocessor defines used by DTP compiles, including `UVM`, are listed in
`hw/sys/dtp/doc/defines.adoc`. The class library mirrors the cocotb
conventions under `uvm/` with identical basenames, one class per file:

[arabic]
. `hw/common/dv/vip/ocah_lib/uvm/ocah_lib_pkg.sv` — the shared framework
  bases every DTP class extends (test, env, sequence, sequencer, scoreboard,
  subscriber, the two cfg bases, knob and seed accessors, pattern helpers).
. `hw/common/dv/vip/ocah_jtag_vip/uvm/ocah_jtag_uvm_pkg.sv` and
  `hw/common/dv/vip/ocah_axi_vip/uvm/ocah_axi_uvm_pkg.sv` — the shared
  SV-UVM VIPs (items, configs, drivers, monitors, sequencers, sequence APIs,
  agents, environments, reference models, scoreboards, checkers) with their
  interfaces, SVA, responders, and coverage collateral.
. `tb/dtp_tb_if.sv`, `tb/dtp_scan_if.sv`, `tb/dtp_xtrig_if.sv` — the
  DTP-local TB interfaces: the control domain (clock and period, resets and
  reset counters, the one-hot TAP state and the debug-TDR observables,
  named debug disables, request-activity counters, SVA enables), the scan domain
  (scan-chain controls, forwarded STAP pins, downstream-TAP attach
  enables), and the cross-trigger pins.
. `uvm/env/dtp_env_pkg.sv` — `dtp_types` (DUT constants, the JTAG2AXI
  codec and request decoder, the STAP device map, the cross-trigger CSR map
  from the generated address maps), `dtp_test_cfg`, `dtp_env_cfg`,
  `dtp_virtual_sequencer`, the expected items, the plain models, one
  `dtp_<feature>_ref_model` per scoreboard feature, `dtp_tap_fsm_checker`,
  `dtp_scan_window_monitor`, `dtp_scoreboard`, and `dtp_env`.
. `uvm/seq_lib/dtp_seq_lib_pkg.sv` — the reusable operation sequences and
  the scenario virtual sequences on `dtp_base_test_seq`.
. `uvm/tests/` — thin test classes named exactly like the scenario;
  `uvm/tests/dtp_tests.sv` is the include manifest `include`d by `tb_top.sv`
  under `ifdef UVM` (`+UVM_TESTNAME` selects the class). Two group bases sit
  between `dtp_base_test` and the thin tests: `dtp_xtrig_base_test` for the
  cross-trigger scenarios, which drive no JTAG traffic (it requires the
  `xtrig_csr` scoreboard feature and lifts the TAP checker's activity demand),
  and `dtp_jtag2axi_robustness_base_test` for the cross-bridge scenarios,
  which arms the evidence contract of all three bridge recorders.

Compile order is explicit and load-bearing: the library and VIP layers come
from their manifests (`ocah_lib/uvm/sources.toml`,
`ocah_jtag_vip/uvm/sources.toml`, `ocah_axi_vip/uvm/sources.toml`, listed in
`[frameworks.uvm.build].source_lists` and expanded ahead of the DUT's own
sources), then the three DTP TB interfaces, the generated cross-trigger port address map,
`dtp_env_pkg`, `dtp_seq_lib_pkg`, and `tb_top.sv` last.

Logical item names stay framework-neutral and match the VPLAN scenarios, and
the UVM class name equals the scenario name (testlist
`name = "dtp_sanity_test"`,
`module = { cocotb = "dtp_sanity_test", uvm = "dtp_sanity_test" }`), so
`--items dtp_sanity_test` selects the same scenario in either realization.
`UVM TEST PASSED` is emitted only in the base test's `report_phase` when the
global UVM_ERROR/UVM_FATAL counts are zero, matching the `uvm-log` parser
policy.

=== Realization differences

Both realizations run the same scenarios, knobs, evidence grammar, and
coverage modules, and in both the expected value of every check comes from
the design collateral, the configuration, or the responder memory, never
from the observation under check. The two realizations differ in the rows
below; each row states what each realization does.

[cols="1,3,3",options="header",]
|===
|Element |cocotb realization |SV-UVM realization
|Primary TAP agent |DUT-local `DtpJtagAgent`: a sequencer and `DtpJtagDriver` over the shared `OcahJtagMasterDriver` engine, with `DtpJtagItem` carrying the TAP, TDR, and JTAG2AXI operations |Shared `ocah_jtag_master_env`; the operations are `dtp_jtag_<op>_seq` and `dtp_jtag2axi_<op>_seq` on its sequencer
|Scenario coordination |Every scenario runs on the JTAG agent's sequencer; the XTRIG CSR master and the CTP/CTM pin BFM are reached through `DtpEnvCfg` handles; the command libraries are helper objects held by the sequence |`dtp_virtual_sequencer` with typed handles; every scenario is a virtual sequence
|Configuration |One `DtpEnvCfg` with `randomize_timing(seed)` |`dtp_test_cfg` randomized from the seed and the derived `dtp_env_cfg`
|Scoreboard |`DtpScoreboard` on the driver's completed-item stream: IDCODE against the device identification, JTAG2AXI write and read data against the responder memory backdoor; a run with JTAG traffic but no scoreboard-checkable operation is reported, not failed. `DtpAxiScoreboard` builds the shared `ocah_axi_vip` reference models and scoreboard when a test opts in (`use_axi_scoreboard`, required IDs, stream minimums); every JTAG2AXI test does |`dtp_scoreboard` pairing seven `dtp_<feature>_ref_model` streams, always on; a required feature with zero comparisons fails
|TAP reference model |`DtpTapFsm` in `env/dtp_types.py`, a DUT-local next-state and TMS-path model; the `OcahJtagChecker` is attached per scenario |`dtp_tap_fsm_checker`, an env subscriber on the VIP next-state model
|Debug-TDR evidence |Inline `CHECK` assertions of the base sequence |Named `CHK-DBG-TDR`, `CHK-DBG-PIN`, `CHK-CAPS`, `CHK-CAPS-RO`, and `CHK-TMP-*` records
|Plain-model basenames |`env/dtp_scan_ref_model.py` and `env/dtp_xtrig_types.py` hold the plain scan and cross-trigger models |`dtp_stap_3dcr_model.svh`, `dtp_ijtag_sib_model.svh`, `dtp_xtrig_ctm_model.svh`
|===

python3 tools/dv/run_dv.py --dut dtp --items dbg_disable
python3 tools/dv/run_dv.py --dut dtp --items all --dry-run

python3 tools/dv/run_dv.py --dut dtp --framework uvm --items basic_jtag

python3 tools/dv/run_dv.py --dut dtp --framework uvm --items xtrig

The `smoke` group is a fast TAP/IDCODE gate. The `basic_jtag` group runs the
Smoke and Basic JTAG scenarios. The `debug_tdr` group runs the TMP_STATUS,
IC_RESET, DEBUG_CONTROL, and CAPS scenarios. The `functional` group runs the
smoke tests plus the single-operation JTAG2AXI write/read tests, while `all`
collects every included DTP testlist.
