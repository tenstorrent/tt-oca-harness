[[dtp-dv-functional-coverage]]
== DTP OCAH Open-Source Functional Coverage Plan

=== Overview

This document defines functional coverage intent for the OCAH open-source DTP
testbench and its PyUVM/Verilator flow.

Verilator does not compile SystemVerilog `covergroup`, `coverpoint`, or
`cross`. Functional coverage is therefore collected by the SystemVerilog
coverage modules under `hw/sys/dtp/dv/cov/sv/`, instantiated once in the
shared `tb_top` so the same source serves the cocotb and SV-UVM flows. Each
module carries two layers: labeled `cover property` points (always compiled;
under Verilator they land in the coverage database as `user` points), and the
same bins as SV covergroups under an `ifndef VERILATOR` guard for the
commercial simulators. The debug-disable 22-cell contract additionally keeps
its checker-gated Python ledger (`env/dtp_fcov.py`).

|===
|Field |Value
|Design specification |`hw/sys/dtp/doc/index.adoc` (designer-owned)
|Reference VPLAN |`DTP_VPLAN.adoc`
|Coverage policy |`cov/config/verilator/coverage_policy.toml` (hole dispositions, waivers, threshold rules); `cov/config/vcs/coverage_policy.toml` (the VCS thresholds) and `cov/config/vcs/dtp_cov_scope.hier` (the VCS compile-time scope)
|Open-source framework |PyUVM on cocotb
|Open-source simulator |Verilator
|Commercial simulator |VCS, the cocotb and SV-UVM realizations
|===

=== Coverage Goals

The signoff target is one figure for every applicable metric: at least 98
percent of the points that remain after the accepted waivers and scope
exclusions of the coverage policy file (the runner's `effective`
population), per metric family, over the candidate commit's `all`
regression, with the DUT instance as the scope for the code-coverage
families. A hole below that line closes through a test, a design or model
fix, or a reviewed waiver (<<dtp-fcov-closure>>); the raw figure, which no
waiver moves, is reported beside the effective one.

[cols="1,1,2,2",options="header",]
|===
|Metric |Signoff target |Public evidence path (Verilator) |Commercial evidence path (VCS)
|Functional coverage |98% effective |The `user` family: the `cover property` points of the `cov/sv/` modules, merged over the weekly `all` regression and graded by the policy file |The same points as cover properties plus the covergroup bins, in the merged database of the cocotb and SV-UVM `all` runs
|Line and branch coverage |98% effective, scoped to the DUT instance |`--coverage-line`, reported beside the functional figure |`-cm line+branch` in the merged database
|Condition and expression coverage |98% effective, scoped to the DUT instance |`--coverage-expr` |`-cm cond`
|FSM coverage |98% effective, scoped to the DUT instance |Not collected under Verilator |`-cm fsm`
|Toggle coverage |98% effective, scoped to the DUT instance |Not collected under Verilator, where toggle instrumentation multiplies the per-test database size |`-cm tgl`
|Assertion coverage |Every enabled assertion attempted; every `cover` directive of the SVA and coverage modules hit |The two-state assertion set stops the simulation on a failure and records no coverage |`-cm assert` in the merged database
|===

On VCS the scope is applied at compile time by `cov/config/vcs/dtp_cov_scope.hier`
(`-cm_hier` with `-cm_common_hier`): the code-coverage families grade the DUT
instance `dtp_uvm_top.u_dut` with everything it instantiates, the vendored
cells included, and assertion coverage grades the DUT, the `cov/sv/` modules
and the shared protocol checker instances under the bench top. Nets a
constant drives leave the toggle denominator (`-cm_noconst`,
`-cm_seqnoconst`) and continuous assignments count as lines
(`-cm_line contassign`); condition coverage is URG's `basic` mode. The
covergroups are unaffected by the scope file.

=== Coverage Definitions

==== `tap_smoke_cg`

*Description*: Covers basic TAP bring-up and IDCODE access.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|TAP reset source |TRST, TMS-to-TLR
|IDCODE read |power-up/TLR default, explicit IDCODE instruction
|IDCODE marker |marker bit `1`, invalid marker observed
|===

Coverage observations include TAP FSM bring-up through `dtp_sanity_test`, IDCODE
marker checking through `dtp_jtag_idcode_test`, and TRST/POR/TLR reset coverage
through the Basic JTAG reset tests.

==== `jtag_instruction_cg`

*Description*: Covers the 6-bit instruction space and instruction categories.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Opcode |All 64 IR values
|Category |mandatory, optional, debug, IEEE 1838, iJTAG, JTAG2AXI, reserved, undefined
|Disabled behavior |enabled instruction, disabled instruction to BYPASS, undefined to BYPASS
|===

`dtp_fcov` samples the flattened `jtag_ptap_inst_decoded` observable at every
completed IR scan (the edge after Update-IR): one labeled point per opcode,
one per category from a one-mask-per-category partition of the decode, and
behavior points that cross the committed opcode with the `dbg_disable`
fields. Standard JTAG driving uses `ocah_jtag_vip`.

==== `tap_state_cg`

*Description*: Covers TAP FSM states and valid TMS transitions.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|TAP state |All 16 IEEE 1149.1 states
|TMS transition |All legal `(state, tms) -++>++ next_state` arcs
|Reset reachability |TRST from active states, 5 TMS=1 from active states
|===

==== `jtag2axi_single_op_cg`

*Description*: Covers single-operation JTAG2AXI TDR use.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Target |SMC fabric, SMC OTP, SEP OTP
|Operation |NOP, READ, WRITE
|Size |Byte widths supported by the target
|WSTRB |none, single byte, partial, all bytes
|Address class |aligned, memory-window boundary (unaligned and unmapped accesses are outside the bridge TDR and testbench address-map contract)
|===

`dtp_jtag2axi_fcov` samples every completed response from each bridge's own
status, pending, and launched-operation registers, so the bins describe the
exact operation including BUSY_OR_FULL polls.

==== `jtag2axi_response_cg`

*Description*: Covers completion status and recovery behavior.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Response status |SUCCESS, SLVERR, DECERR, BUSY_OR_FULL
|Poll count |immediate, short wait, long wait
|Recovery |next NOP, next read/write after error, reset abort
|===

==== `jtag2axi_robustness_cg`

*Description*: Covers series operations, backpressure, and CDC clear/abort
paths. Size-aligned narrow series transfers (`AxSIZE` smaller than the data
bus, starting at a non-zero beat offset) are in contract for the SMC fabric
series path.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Series mode |INCR, NO_INCR, WITH_ERROR_STATUS
|Channel skew |AW-before-W, W-before-AW, read response held
|Reset timing |idle, request issued, data phase, response wait
|CDC recovery |clear, isolate, back-to-back reset
|===

==== `otp_jtag2axi_cg`

*Description*: Covers the SMC OTP and SEP OTP JTAG2AXI bridge paths.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|OTP target |SMC OTP, SEP OTP
|Operation |READ, WRITE (and status-poll NOPs)
|Response status |SUCCESS, SLVERR, DECERR
|Series mode |INCR, NO_INCR, WITH_ERROR_STATUS
|Security gating |gated attempt, release without replay, recovery
|===

Sampled per bridge by `dtp_jtag2axi_fcov` at the completed-response boundary;
the gating bins follow the committed gated TDR accesses and the sticky
per-target recovery history.

==== `tmp_ic_reset_cg`

*Description*: Covers TMP_STATUS and IC_RESET debug TDR behavior.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|TMP persistence |reset/off, CLAMP_HOLD/on, chip-reset preserved, BYPASS_ESCAPE release
|TMP read shift value |zero, persistence bit set, escape-arm bit set (the first two shifted TDO bits)
|BYPASS escape |unarmed, armed, BYPASS double-load escape observed
|IC_RESET slice |SMC, SEP, External
|IC_RESET override |override disabled, override enabled, reset asserted, reset deasserted
|IC_RESET hold |reset_hold=0 TLR preserve, reset_hold=1 TLR default restore, TRST default restore
|IC_RESET pattern source |stimulus intent (test layer); the coverage module records the resulting slice, override, and hold behavior
|===

`dtp_debug_tdr_fcov` samples these bins from the TMP unit's state and status
registers, the BYPASS-escape pulse, the flattened IC_RESET outputs, and the
first two TDO bits of each TMP_STATUS read; the `+dtp_jtag_tmp_status_*+` and
`dtp_jtag_ic_reset_test` scenarios drive them.

==== `debug_control_cg`

*Description*: Covers DEBUG_CONTROL TDR fields and associated outputs.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Boot stall |all four override/stall combinations
|Boot-stall interaction |standalone, with JTAG clock stop, with CLA clock stop enable, with both
|JTAG clock stop |asserted, deasserted
|CLA clock stop enable |disabled, enabled
|CLA clock stop readback |no request, one request, multiple requests
|Clock-stop request source |no request, each single request bit, multi-request masks (seeded randomization is stimulus intent, test layer)
|Clock-stop output |JTAG-only, CLA-only, combined, released
|===

`dtp_debug_tdr_fcov` samples these bins from the boot-stall and clock-stop
outputs plus the DEBUG_CONTROL stop contributions; the
`+dtp_dbg_ctrl_clk_stop_*+` and `dtp_dbg_ctrl_boot_stall_test` scenarios
drive them. `stop_clks_o` checking polls across synchronizer/output latency.

==== `caps_tdr_cg`

*Description*: Covers read-only DTP capability TDR behavior.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|CAPS register |JTAG_CAPS, SMC_JTAG2AXI_CAPS, SMC_OTP_JTAG2AXI_CAPS, SEP_OTP_JTAG2AXI_CAPS
|JTAG_CAPS fields |XTRIG counts, STAP/debug enables, IC_RESET counts, instruction enables, OCAH version
|JTAG2AXI bus type |AXI4 SMC fabric, AXI4-Lite SMC OTP, AXI4-Lite SEP OTP
|JTAG2AXI geometry |address width, data width, read pipeline depth, write pipeline depth
|Read stability |repeated reads stable
|Read-only write attempt |all-zero, all-one, alternating, deterministic random
|Instruction switch side effect |read after IDCODE, read after BYPASS
|===

`dtp_debug_tdr_fcov` samples the capability accesses from the committed
instruction decode, the write patterns from the shifted TDI stream, and the
instruction-switch context from a two-stage committed-instruction history;
`dtp_dbg_jtag_caps_test` and the three `+dtp_dbg_*_jtag2axi_caps_test+`
sequences drive them. The parameter-derived field bins (JTAG_CAPS fields, bus
type, geometry) are carried by the commercial covergroup on the per-register
capture events.

==== `stap_3dcr_cg`

*Description*: Covers IEEE 1838 STAP/3DCR behavior.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|STAP type |I/O, SMC, SEP, extra
|3DCR fields |select, TMS hold, config hold
|Chain behavior |SIB open, SIB closed, selected STAP in scan path
|Security state |enabled, gated by the STAP's `dbg_disable` field
|===

==== `ijtag_sib_cg`

*Description*: Covers IEEE 1687 SIB network selection across the DFT Secure, DFT Non-Secure, and DFD (Design-for-Debug) chains.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|SIB pattern |All DFD/DFT-secure/DFT-nonsecure on/off combinations
|Instrument access |DFD, DFT secure, DFT non-secure
|Security gating |enabled, gated by the SIB's `dbg_disable` field (`dft_secure`, `dft_nonsecure`, `dfd`)
|===

==== `ctp_cg`

*Description*: Covers CTP external protocol behavior.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Mode |wire-OR, point-to-point
|Inversion |normal, inverted
|Stretch |min, mid, max
|P2P state |idle, request phase, acknowledge phase, reset recovery
|===

==== `ctm_cg`

*Description*: Covers CTM source-to-destination routing.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Source type |CTP, internal CT
|Destination type |CTP, internal CT
|Routing fanout |none, single destination, multicast
|Source index |all configured source ports (26 default: 16 CTP {plus} 10 internal CT)
|Destination index |all configured destination ports (26 default)
|===

==== `dbg_disable_cg`

*Description*: Covers the per-field debug-disable gating contract for the
eleven pre-resolved active-high disables of
`sep_lifecycle_ctrl_pkg::dbg_disable_t` (`1 = interface disabled`). Deriving
these fields from lifecycle policy is verified at the SEP level; DTP coverage
closes on each field gating exactly its interface.

The sample tuple is `(field, disable_value, observed_outcome)`. For each of
the eleven fields, both legal cells are required:

* `(field, 0, allowed)`
* `(field, 1, blocked)`

This produces 22 required cells. The contradictory tuples —
`(field, 0, blocked)` and `(field, 1, allowed)` — are checker failures, never
coverage bins.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Field |`stap_io`, `stap_smc`, `stap_sep`, `stap_extra`, `stap_host`, `dft_secure`, `dft_nonsecure`, `dfd`, `smc_jtag2axi`, `smc_otp_jtag2axi`, `sep_otp_jtag2axi`
|Field outcome |`(field, 0, allowed)` and `(field, 1, blocked)` per field (22 cells)
|Mask class |all clear, one-hot, multi-hot, all disabled
|Unrelated-resource isolation |an enabled resource proven usable while another field is asserted
|Release without replay |no queued operation completes after a disable clears
|Recovery |a sanctioned operation succeeds after release
|===

Sampling rules:

* A cell is recorded only after the associated functional checker passes;
  coverage is never auto-hit from a test name or from writing a disable
  input.
* Every coverage log line records the field, the full named disable mask,
  the attempted operation, and the observed result.
* Each matrix test enforces its own cells before completing: the scan
  matrix requires all 16 cells of its eight fields and the JTAG2AXI matrix
  the 6 cells of its three bridge fields, so a passing `dbg_disable` group
  run covers all 22 required cells. Each matrix also emits a JSON artifact
  under its `coverage/` directory recording the cells it hit.
* `dtp_scan_fcov` additionally mirrors the field values as cover points
  (`c_dbg_disable_<field>_{clear,set}`) so the merged coverage database
  records field exercise; the checker-gated cells above are the
  contract.

[[dtp-fcov-closure]]
=== Closure Policy

Coverage closes against the policy file, not against a rerun: every
uncovered point of the candidate regression is either fired by a new or
extended scenario, held open by a defect that a tracker item owns, or removed
from the effective denominator by a reviewed waiver. The rules below bind
the DTP policy file; the runner's schema and grading behavior are in
`tools/dv/doc/run-dv.adoc`.

==== Evidence paths

* **Public path.** The weekly `all` regression at three seeds with `--cov`
  on Verilator. Its run tree carries `cov/report/coverage-details.json`
  (every point with its disposition), `cov/report/summary.json` (the raw
  and effective figures per family and the hole counts), and
  `cov/report/policy-application.json`; the hosted job publishes them as
  the `dv-run-dtp-verilator-weekly` artifact. A policy change is graded
  against a finished run with `run_dv.py --dut dtp --run-dir <run> --waive`,
  which rewrites the grade without a simulation.
* **Commercial path.** The cocotb `all` and SV-UVM `all` regressions on
  VCS with the full `-cm` set and the compile-time scope, each merged by the
  runner, then combined across frameworks into one run with
  `run_dv.py --dut dtp --cov-combine <cocotb-run> <uvm-run>`; the report
  of that combined run is the code-coverage evidence and carries the covergroup bins
  of the same points. URG hands the runner family totals and no per-point
  list, so `cov/config/vcs/coverage_policy.toml` carries `[[thresholds]]`
  only and a VCS hole closes through a scenario, a design or model change,
  or an entry in the URG exclusion list that the `pass:[[[native_files]]]`
  entry of that policy names (<<dtp-fcov-unreachability-list>>); the runner
  passes that list to `urg -elfile`, records its checksum, and reports the
  figures with and without it as `effective_metrics` and `raw_metrics`.
  Covergroup bins take no exclusion.
* A metric is applicable on the path that collects it, and a point that
  both paths collect is one point: a hole on either path needs one
  disposition, and a waiver written for one path names the same
  structural reason on the other.

==== Hole dispositions

[cols="1,3,2,1",options="header",]
|===
|Disposition |Meaning |Requires while open |Counts as
|`cover` |The point is reachable and needs a scenario or a stimulus change |A tracker link |Open hole
|`fix_design` |A design defect blocks the point |A tracker link naming the defect |Open hole
|`fix_model` |A bench, model, or coverage-module defect blocks the point |A tracker link |Open hole
|`review` |The point awaits a disposition |A tracker link |Open hole
|`waive` |The point has no reachable stimulus on this bench or configuration, for the structural reason the rationale names |`status = "accepted"`, the fields below |Removed from the effective denominator
|`exclude_scope` |The point is outside the DTP verification contract (integration-level behavior, vendor IP internals, elaboration-time constants) |`status = "accepted"`, the fields below |Removed from the effective denominator
|===

An open hole never shrinks a denominator; only an accepted `waive` or
`exclude_scope` entry does, and only at `medium` or `high` confidence. The
runner rejects an accepted waiver that matches a covered point, a
low-confidence waiver, an entry whose `dut` is not the run's, and an open
actionable hole without a tracker link.

==== Waiver fields

Every `pass:[[[holes]]]` entry carries `id`, `title`, `category`, `disposition`,
`status`, `confidence`, `rationale`, `owner`, `reviewer`, `date`, and at
least one `pass:[[[holes.native]]]` selector (`tool`, `metric_family`,
`hierarchy`); an accepted entry also carries `expires` and, where the
selector is a pattern, `expected_matches`. The rationale states the design
or bench fact that makes the point unreachable, in words the reviewer of a
later design or bench change can recognize; a rationale that restates the
point's name is not one. `issues` carries the tracker link of the defect or
task an open hole waits on, and of the review that accepted a waiver.

==== Reviewers

An entry's `reviewer` differs from its `owner`. A `waive`,
`exclude_scope`, or `fix_design` entry whose rationale is a design fact
takes design review; a `fix_model` or `cover` entry takes DV review; a
`pass:[[[thresholds]]]` rule or a `pass:[[[native_files]]]` entry takes coverage-flow
review. Every entry change is graded against a named finished run with the
runner's `--waive` re-grade.

==== Expiry and reopen triggers

Every accepted waiver carries an `expires` date. Past it the waiver grades
as open, its point returns to the effective denominator, the report carries
a lapsed-waiver warning, and the entry is either renewed by a fresh review
or closed by the scenario that fires the point. A waiver also reopens, by
the entry's status returning to `open` or the entry being removed, when:

* the runner rejects it because its selector matches a covered point;
* the policy's `scope_epoch` changes, which restarts every dashboard
  series;
* a design or bench change removes the structural reason its rationale
  names;
* the metric set of `[coverage.verilator]` or the VCS `-cm` set changes;
* the tracker item its `issues` list names closes.

==== Gating

The compatibility threshold (`--fail-under`, else
`[coverage.<tool>].fail_under`) grades the tool's raw figure and no waiver
moves it. The signoff gate is one `pass:[[[thresholds]]]` rule per applicable
metric family in the policy file of each path: on Verilator with
`population = "effective"` and the DUT instance as its `scope`, on VCS over
the family total of the compile-time scope, at 98 percent for the
code-coverage families and 100 percent for assertion and functional
coverage. The hosted weekly publishes the figures without a threshold, so
the gate runs on the qualification regression and on every `--waive`
re-grade of its run tree.

[[dtp-fcov-unreachability-list]]
==== Unreachability exclusion list

`cov/config/vcs/dtp_unreachable.el` is the URG exclusion list of the
code-coverage points that a formal unreachability analysis proves no stimulus
reaches in the bench's environment: the DTP at its parameter defaults, the
DFT ports at their functional values, the boundary-scan and extended STAP
chains looped back, and every other input free, the resets included. The
analysis starts from the merged database of the qualification regression
(<<dtp-fcov-evidence-paths>>), so it targets the points that regression left
uncovered, and it runs in the checkout that produced that database, because
the formal model and the seed must describe one RTL. The analysis is the
`dtp_cov_vcf` item of the runner's formal mode in the companion's DTP formal
configuration; a reader without the companion runs their own unreachability
tool over the same database with the same environment and writes the same
URG exclusion format.

The `pass:[[[native_files]]]` entry of `cov/config/vcs/coverage_policy.toml`
that names the list pins the file's SHA-256, and a comment beside it records
the commit the analysis ran at, the date and the reviewer. The runner refuses
the policy when the file and the pinned digest differ, so a regenerated list
takes a new review. URG applies no entry whose module or instance checksum
differs from the design it reports on, so an RTL change under an excluded
scope drops that scope's exclusions on its own.

Regeneration rule: the list is regenerated from the candidate's qualification
regression before every candidate, and re-checked after any change to the
DTP RTL file set with the analysis's check mode over the accepted list, which
fails when an excluded point has become reachable. A regenerated list takes
design review before its entry changes: the review reads the list against the
hole inventory of the closure issues and accepts no entry the inventory
classes as reachable by stimulus.

=== Collection Strategy

[cols=",",options="header",]
|===
|Flow |Strategy
|Verilator open-source CI |Labeled `cover property` points in the `cov/sv/` modules; `run_dv.py --cov` collects them as `user` coverage in each test's `coverage.dat`, merges across tests and seeds (`cov_merge`), and reports through `cov_report` with `cov/config/verilator/coverage_policy.toml` applied
|Per-group reporting |The DV dashboard ingests the merged run's `coverage-details.json` (policy dispositions included), keyed by the cover points' native hierarchy names (`u_dtp_<area>_fcov.c_<label>`)
|Verilator metric set |`[coverage.verilator]` in `dtp_sim_cfg.toml` instruments line, expression, and `user` coverage and leaves toggle out; the weekly regression merges every leaf and seed into one report
|Commercial simulation |The same modules' covergroups compile under VCS/Xcelium (the `ifndef VERILATOR` layer); both frameworks collect through the runner — `run_dv.py --cov --tool vcs` for cocotb, `run_dv.py --framework uvm --cov` for SV-UVM — with per-test `simv.vdb` databases merged (`cov_merge`, `urg` with the design database) and reported (`cov_report`); the two frameworks' merged databases are combined with `run_dv.py --dut dtp --cov-combine <cocotb-run> <uvm-run>` into one DUT-scoped report for signoff
|Code coverage |VCS/Xcelium line, branch, condition, FSM, toggle, assertion coverage, scoped to the DUT instance
|Closure triage |Add directed tests for reachable holes; record blocked or unreachable points as hole entries in the coverage policy file, each stating the structural reason the point cannot fire
|===

Sampling happens at the documented transaction boundaries: completed IR scan,
completed DR scan, completed JTAG2AXI response (each bridge's own status and
launched-operation registers), CTP/CTM event, and debug-disable configuration
change.

=== Exclusions and Limitations

[cols=",",options="header",]
|===
|Item |Reason
|SV covergroups in Verilator |Unsupported by the tool; the cover-property layer carries the public flow
|`jtag2axi_robustness_cg` reset-timing request-issued and response-wait bins and CDC clear bins |Sampled only by the two reset-abort scenarios, which drive the system reset while the bridge is mid-flight; the bins carry dispositions in the coverage policy file, not waivers
|Stimulus-intent bins (IC_RESET pattern source, seeded random request masks) |Test-layer randomization intent, not signal-observable; the modules record the resulting behavior instead
|Invalid IDCODE marker, contradictory debug-disable outcomes |Checker failures in a passing run, never coverage bins
|Unaligned and unmapped JTAG2AXI addresses |Outside the bridge TDR and testbench address-map contract
|Static parameter toggles |Compile-time constants; not meaningful runtime coverage
|Protocol-specific behavior without shared VIP support |Covered by OCAH-local DTP BFMs
|===
