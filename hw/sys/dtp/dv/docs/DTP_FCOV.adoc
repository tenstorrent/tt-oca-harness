[[dtp-dv-functional-coverage]]
== DTP Functional Coverage Plan

=== Overview

This document defines functional coverage intent for the DTP testbench and
its cocotb and SV-UVM realizations.

Functional coverage is collected by the SystemVerilog coverage modules under
`hw/sys/dtp/dv/cov/sv/`, instantiated once in the shared `tb_top` so the same
source serves the cocotb and SV-UVM flows. Their SV covergroups are the
functional model, and every simulator compiles them: the runner maps URG's
`group` metric and Verilator's `covergroup` points to the functional family,
and leaves out Verilator's ignore and illegal bins, which are not coverage
goals. Verilator drops cross select expressions (`binsof`, explicit cross
bins) and coverage weights, so the covergroups use neither: every cross is the
full product of its coverpoints, and a combination that must not occur is an
illegal bin of a coverpoint, so both simulators build the same bins. The
`cov/sv/` modules hold no `cover property` point; those of the AXI and JTAG
protocol checkers land in the Verilator coverage database as the `user`
family, and on VCS they are graded with the assertion family as cover
directives. The 16-cell scan-side debug-disable contract additionally keeps
its checker-gated Python ledger (`env/dtp_fcov.py`).

=== Coverage Goals

The target of the code-coverage families and of the Verilator `user` family
is one figure: at least 98 percent of the points that remain after the
accepted waivers and scope exclusions of the coverage policy file (the
runner's `effective` population), per metric family, over the `all`
regression. The code-coverage families count the points each simulator's
compile-time scope keeps, which the paragraphs after the table describe.
A hole below that line closes through a test, a design or model fix, or a
reviewed waiver (<<dtp-fcov-closure>>); the raw figure, which no waiver moves,
is reported beside the effective one.

The target of the functional family is 100 percent of the covergroup model,
with no waiver. A combination that no stimulus can reach on the bench
configuration has no bin in the model, and one that only a design or checker
failure produces is an illegal bin, whose hit VCS reports as a runtime error
and Verilator as an error that stops the simulation.

[cols="1,1,2,2",options="header",]
|===
|Metric |Target |Public evidence path (Verilator) |Commercial evidence path (VCS)
|Functional coverage |100% of the covergroup model, no waiver; 98% effective for the Verilator `user` family |The covergroup bins (Verilator's `covergroup` points) and the `user` family, the `cover property` points of the AXI and JTAG protocol checkers, merged over the `all` regression and graded by the policy file |The covergroup bins (URG's `group` metric) in the merged database of the cocotb and SV-UVM `all` runs
|Line and branch coverage |98% effective, over the compile-time scope |`--coverage-line`, reported beside the functional figure |`-cm line+branch` in the merged database
|Condition and expression coverage |98% effective, over the compile-time scope |`--coverage-expr` |`-cm cond`
|FSM coverage |98% effective, over the compile-time scope |Not collected under Verilator |`-cm fsm`
|Toggle coverage |98% effective, over the compile-time scope |Not collected under Verilator, where toggle instrumentation multiplies the per-test database size |`-cm tgl`
|Assertion coverage |Every enabled assertion attempted; every `cover` directive of the SVA modules hit |The two-state assertion set stops the simulation on a failure and records no coverage |`-cm assert` in the merged database, with the `cover property` points of the protocol checkers as cover directives
|===

On VCS the scope is applied at compile time by `cov/config/vcs/dtp_cov_scope.hier`
(`-cm_hier` with `-cm_common_hier`): the code-coverage families grade the DUT
instance `tb_top.u_dut` with everything it instantiates, the vendored
cells included, except `prim_cdc_rand_delay`, the simulation-only CDC jitter
model that the synchronizer primitives instantiate only under `SIMULATION`.
Assertion coverage grades the DUT, the protocol checker instances under the
bench top and its SMC fabric AWATOP rule. Nets a constant drives leave the
toggle denominator (`-cm_noconst`, `-cm_seqnoconst`) and continuous
assignments count as lines (`-cm_line contassign`); condition coverage is
URG's `basic` mode. The covergroups are unaffected by the scope file.

On Verilator the scope is applied at compile time by
`cov/config/verilator/dtp_cov_scope.vlt`, which `[coverage.verilator]` passes
to the build. Its `coverage_off` rules select source files: the bench under
`tb/`, the VIP interfaces, protocol checkers and shims under `hw/common/dv/`,
the `cov/sv/` modules, `prim_cdc_rand_delay` and Verilator's `verilated_std.sv`
leave the line, branch and expression families, and the DUT's sources stay,
the vendored cells included.
A rule that selects a file cannot select an instance, so the bench's own
instances of a DUT source stay in the scope: the `prim_jtag_scan_reg`
instances of the iJTAG instrument stubs and the STAP host segment.
Verilator can keep one set of points for every instance of a module
elaborated with the same parameter values, so a bench instance whose
parameters match a DUT instance's can share that instance's points, and
bench stimulus can cover them.
`coverage_off` leaves a `cover property` point and a covergroup bin in place,
so the `functional` family keeps every bin of the `cov/sv/` modules and the
`user` family keeps the cover properties of the AXI and JTAG protocol
checkers. Toggle and FSM coverage are not collected.

=== Coverage Definitions

==== `cg_tap_smoke`

*Description*: Covers the resets that return the TAP to Test-Logic-Reset and
IDCODE access.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_reset_source` |`trst`, `por`, `tms5`: TRST with power-on reset deasserted, power-on reset with TRST deasserted, and TMS held high, each moving the TAP from an active state to Test-Logic-Reset
|`cp_trst_from_state` |One bin per TAP state other than Test-Logic-Reset: the state the TAP held when TRST fell, for each `trst` reset; a state that is not one-hot is an illegal bin
|`cp_idcode_read` |`default_after_trst`, `default_after_por`, `default_after_tms5` (a DR scan with no IR load since that reset), `explicit_instruction`
|`cp_idcode_marker` |`marker_1`; marker bit `0` is an illegal bin
|===

`dtp_fcov` latches the TAP state while TRST is high, so it holds the state
the asynchronous reset interrupted, and samples the `trst` bin and
`cp_trst_from_state` at the first TCK edge under TRST when that state was
active. It samples the `por` and `tms5` bins at the first TCK edge on which
the TAP is in Test-Logic-Reset after an active state; a power-on reset is
seen at the first TCK edge after the pulse even when TCK stays idle across
it. An IDCODE read is a completed DR scan with IDCODE the current instruction
and the PTAP TAP_3DCR select clear, and the marker bin samples its first
captured bit on TDO. While the select is set the STAP chain return drives TDO,
so those scans are not IDCODE reads.

==== `cg_tap_state`

*Description*: Covers the TAP controller states.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_state` |All 16 IEEE 1149.1 states; a state register that is not one-hot is an illegal bin
|===

==== `cg_tap_arc`

*Description*: Covers the legal TMS transitions of the TAP controller.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_arc` |All 32 legal `(state, tms) -++>++ next_state` arcs; an arc off the IEEE 1149.1 state graph that does not end in Test-Logic-Reset is an illegal bin
|===

Both groups sample at every TCK rising edge outside TRST, from the exported
one-hot TAP state at that edge and at the edge before it and the TMS value
that moved it. TRST and power-on reset hold or move the TAP to
Test-Logic-Reset whatever TMS is, so the first transition after a reset can
end there off the graph; `cg_tap_arc` does not sample that transition, and
`cg_tap_smoke` collects the reset.

==== `cg_scan_boundary`

*Description*: Covers completed IR and DR scans.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_boundary` |`ir_scan` (Update-IR), `dr_scan` (Update-DR)
|===

==== `cg_jtag_instruction`

*Description*: Covers the 6-bit instruction space, the instruction categories,
and the two ways Update-IR loads the instruction register.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_opcode` |`op[0]` to `op[63]`, all 64 IR values; a decode that is not one-hot is an illegal bin
|`cp_category` |`mandatory`, `optional_instr`, `ieee1838`, `debug`, `ijtag`, `jtag2axi`, `reserved`, `undefined`
|`cp_ir_update` |`shifted` (an instruction shifted in), `capture_pattern` (an Update-IR with no Shift-IR cycle since Capture-IR, which latches the Capture-IR pattern, IDCODE); a capture-pattern update that decodes anything but IDCODE is an illegal bin
|===

`dtp_fcov` samples the flattened `jtag_ptap_inst_decoded` observable at every
completed IR scan (the edge after Update-IR). The category bins come from a
one-mask-per-category partition of the 64 opcodes, checked at time zero.
Standard JTAG driving uses `ocah_jtag_vip`.

==== `cg_dr_scan`

*Description*: Covers the data register each IEEE 1149.1 instruction places
between TDI and TDO.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_dr_instruction` |A completed DR scan under `bypass_alt` (`0x00`), `idcode`, `runbist`, `sample_preload`, `extest`, `extest_train`, `extest_pulse`, `clamp`, `highz`, `intest`, `clamp_hold`, `clamp_release`, `reserved` (`0x10` to `0x17`), `undefined` (`0x0F`, `0x21` to `0x3C`), `zero_length_bypass`, `inv_bypass`, and `bypass` (`0x3F`)
|`cp_zero_length_path` |ZERO_LENGTH_BYPASS with the PTAP TAP_3DCR select clear (`zero_length`, TDI to TDO with no stage) and set (`as_bypass`, the bypass register leading the STAP chain)
|===

`dtp_fcov` samples every completed DR scan (the edge that leaves Update-DR)
from the instruction decode and the PTAP TAP_3DCR select. The TDR
instructions of the debug-control, scan, and JTAG2AXI areas have no bin here;
the debug-control and scan groups cover their registers, and the JTAG2AXI
scenarios check the bridges' DTMCS and DMI registers.

==== `cg_instruction_gate`

*Description*: Covers each instruction whose data register, or the bus port
behind it, a debug-disable field gates, scanned with that field clear and set.
A field never gates the decode: the instruction decodes as itself and keeps
its register on the scan path.

[cols=",",options="header",]
|===
|Cross |Bins
|`cx_gate_disabled` |`cp_gate` x `cp_disabled` (`clear`, `set`), where `cp_gate` is the SMC fabric bridge's DTMCS and DMI TDRs (`0x1F` and `0x20`, `smc_axi_tdr`) with `smc_jtag2axi`, the SMC OTP bridge's (`0x1B` and `0x1C`, `smc_otp_tdr`) with `smc_otp_jtag2axi`, the SEP OTP bridge's (`0x1D` and `0x1E`, `sep_otp_tdr`) with `sep_otp_jtag2axi`, SELECT_IJTAG with each of `dft_secure`, `dft_nonsecure`, and `dfd`, and RUNBIST with `dft_nonsecure`
|===

`dtp_fcov` samples every completed DR scan of a gated instruction with the
value of the field that gates it. RUNBIST pairs with
`dft_nonsecure`, the field of the non-secure DFT host that receives the
RUNBIST control; the SIB gating of the other two fields does not depend on
which instruction selects the network.
The STAP fields and `stap_host` gate the STAP chain and its return path,
which no instruction selects, and `cg_stap_3dcr` and `cg_dbg_disable_scan`
carry them. The JTAG2AXI reference model predicts what a set bridge field
does: the bridge answers every bus request with DECERR from its internal error
slave and issues nothing on its manager port. The iJTAG and debug-disable
groups cover a SIB held closed under its field.

==== `cg_tmp`

*Description*: Covers the TMP controller and the TMP_STATUS TDR.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_read_value` |TMP_STATUS[1:0] shifted out: `zero`, `escape_armed` (`0b01`), `persistence` (`0b10`), `persistence_armed` (`0b11`)
|`cp_read_match` |`match`; a value that differs from the persistence state and escape arm at Capture-DR is an illegal bin
|`cp_change` |`clamp_hold_on`, `clamp_release_off`, `bypass_escape_off`, `tap_reset_off`; a change with no CLAMP_HOLD, CLAMP_RELEASE, armed BYPASS load, or TAP reset behind it, and persistence kept through a TAP reset, are illegal bins
|`cp_bypass` |A BYPASS load while persistence is on: `unarmed_held`, `armed_escaped`; an unarmed load that releases or an armed load that holds is an illegal bin
|`cp_tlr` |`chrst_n` on entry to Test-Logic-Reset by TMS: `persistence_on_released`, `persistence_off_asserted`; the other two pairs are illegal bins
|`cp_sys_reset` |`persistence_preserved`: persistence on when `rst_n_i` asserts and when it releases
|===

`dtp_debug_tdr_fcov` samples a TMP_STATUS read at the TCK edge that leaves
Update-DR after a two-bit scan with the PTAP TAP_3DCR select clear, from the
first two bits on TDO; while the select is set the STAP chain return drives
TDO. A persistence change is judged at the edge after it, against the
instruction or escape condition the TMP unit saw, and a TAP reset is judged at
the first TCK edge after it, so a power-on reset with TCK idle counts. The TAP
reset is TRST or power-on reset, as the PTAP combines them. The
`+dtp_jtag_tmp_status_*+`, `dtp_jtag_clamp_hold_test`, and
`dtp_jtag_clamp_release_test` scenarios drive these bins.

==== `cg_ic_reset`

*Description*: Covers the IC_RESET TDR and its slice outputs.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_smc`, `cp_sep`, `cp_ext` |The slice's `{ovrd, ctrl_n}` after an update: `functional` (`0b01`, the reset default), `staged` (`0b00`), `override_reset` (`0b10`), `override_run` (`0b11`)
|`cp_hold` |`reset_hold` after an update: `hold_clear`, `hold_set`
|`cp_reset` |`tlr_preserve` (`reset_hold` = 0 keeps the slices through Test-Logic-Reset), `tlr_restore` (`reset_hold` = 1 restores them), `tap_reset_restore` (a TAP reset restores the whole register); every other outcome is an illegal bin
|===

The slice bins sample the flattened `jtag_ic_reset_{smc,sep,ext}_o` outputs at
each IC_RESET update. A Test-Logic-Reset entered by TMS is judged when the
slices were away from their default, under the `reset_hold` written before
it; a TAP reset is judged when any field, `reset_hold` included, was away from
its default. `dtp_jtag_ic_reset_test` drives every bin; its four directed
`reset_hold` = 0 patterns give each slice all four values.

==== `cg_debug_control`

*Description*: Covers the DEBUG_CONTROL TDR fields, the `cla_clock_stop`
readback, and their reset.

[cols=",",options="header",]
|===
|Coverpoint / cross |Bins
|`cp_boot` |`{boot_stall_ovrd, boot_stall}`: `ovrd0_stall0`, `ovrd0_stall1`, `ovrd1_stall0`, `ovrd1_stall1`
|`cp_jtag_stop`, `cp_cla_en` |`off`, `on`
|`x_boot_clock_stop` |`cp_boot` x `cp_jtag_stop` x `cp_cla_en`
|`cp_readback` |Bit 4 against the request lines at Capture-DR: `no_request`, `one_request`, `multiple_requests`
|`cp_capture_jtag_stop`, `cp_capture_cla_en` |`off`, `on`, while bit 4 was captured
|`x_readback` |`cp_readback` x `cp_capture_jtag_stop` x `cp_capture_cla_en`
|`cp_reset` |`tlr_cleared`, `tap_reset_cleared`: nonzero fields cleared by Test-Logic-Reset or a TAP reset; fields kept are an illegal bin
|===

The field bins sample the `jtag_boot_stall_ovrd_o`, `jtag_boot_stall_o`, and
`cla_clock_stop_en_o` outputs and the JTAG clock stop at each DEBUG_CONTROL
update. Bit 4 reaches the TDR through a two-flop TCK synchronizer, so a
request change within two TCK edges of Capture-DR reads either way and counts
in no readback bin. The `+dtp_dbg_ctrl_clk_stop_*+` and
`dtp_dbg_ctrl_boot_stall_test` scenarios drive these bins, and
`dtp_jtag_tlr_reset_test` drives `tlr_cleared`.

==== `cg_clock_stop`

*Description*: Covers the aggregation of the JTAG clock stop and the CLA
clock-stop requests into `stop_clks_o`.

[cols=",",options="header",]
|===
|Coverpoint / cross |Bins
|`cp_req_source` |`line_0` to `line_8` (one `xtrig_clk_stop_req_i` line alone), `none`, `multi`
|`cp_jtag_stop`, `cp_cla_en` |`off`, `on`
|`cp_stop_clks` |`running`, `stopped`; a `stop_clks_o` that is not the OR of the JTAG clock stop and the request lines is an illegal bin (`stopped_without_source`, `running_with_source`)
|`x_aggregation` |`cp_req_source` x `cp_jtag_stop` x `cp_cla_en`, each combination with the `stop_clks_o` that `cp_stop_clks` requires
|===

`stop_clks_o` follows its sources three `clk_i` edges later, after the
two-flop synchronizer and the output flop, or four when the synchronizer's
delay model holds a change back an edge. `dtp_debug_tdr_fcov` delays the
sources to line up with it and samples each combination of the request
lines, `jtag_clock_stop`, and `cla_clock_stop_en` that holds for two `clk_i`
edges. `cla_clock_stop_en` is crossed so that every cell shows it leaves the
output unchanged. The directed sweep of
`dtp_dbg_ctrl_clk_stop_random_clock_stop_test` drives every single-line and
multi-line cell in each seed, and the four DEBUG_CONTROL scenarios drive the
cells with no request.

==== `cg_caps_tdr`

*Description*: Covers the read-only JTAG_CAPS TDR.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_pattern` |Pattern shifted in: `all_zero`, `all_one`, `alternating`, `mixed`
|`cp_after` |Instruction committed before JTAG_CAPS: `after_idcode`, `after_bypass`
|`cp_stability` |`stable`: the value equals the previous direct read; a changed value is an illegal bin
|===

`dtp_debug_tdr_fcov` samples JTAG_CAPS at the TCK edge that leaves Update-DR
after a full-length 60-bit scan; the pattern comes from TDI, the value from
TDO, and the stability bin compares only reads taken with the PTAP TAP_3DCR
select clear. `dtp_dbg_jtag_caps_test` drives every bin.

==== `cg_stap_3dcr`

*Description*: Covers the IEEE 1838 STAP 3DCRs: each STAP's SIB, its stored
select, TMS hold, and config hold, its debug disable, and its forwarding.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_type` |`io`, `smc`, `sep`, `extra`
|`cp_sib` |`closed`, `open`
|`cp_forwarded` |`forwarded`: the port drove its host TDO enable during the scan
|`cp_select` |with the SIB open: `deselected`, `selected` (the stored select)
|`cp_tms_hold` |with the SIB open: `low`, `high`
|`cp_config_hold` |with the SIB open: `clear`, `set`
|`cp_security` |with the SIB open: `enabled`, `gated` by the STAP's `dbg_disable` field
|`x_type_sib` |`cp_type` x `cp_sib`
|`x_type_forwarded` |`cp_type` x `cp_forwarded`
|`x_config` |with the SIB open: `cp_type` x `cp_select` x `cp_tms_hold` x `cp_config_hold` x `cp_security`
|===

`dtp_scan_fcov` samples the group once per STAP at every Update-IR and
Update-DR that the STAP chain takes, that is, every update of a scan run with
the PTAP 3DCR select set. The SIB state is the one the scan ran under, since a
STAP's 3DCR is in the chain only while its SIB is open; the 3DCR fields are the
stored values after the update. The disable blocks the 3DCR update and keeps
the stored fields, so every `x_config` combination is reachable, and a
`selected` STAP under its disable is a port parked at its TMS hold.
`dtp_3dcr_tms_hold_test` writes every payload to every STAP, enabled and under
the four STAP disables, in each pass.

==== `cg_stap_chain`

*Description*: Covers the PTAP 3DCR select gating the STAP chain on instruction
and data scans.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_ptap_select` |`held_unselected`, `scanned_selected`
|`cp_scan` |`ir`, `dr`
|`x_chain` |`cp_ptap_select` x `cp_scan`
|===

Sampled at every Update-IR and Update-DR with the PTAP 3DCR select the scan ran
under: with it clear the STAP chain and the host scan controls held their state
through the scan, with it set the chain shifted.

==== `cg_3dcr_hold`

*Description*: Covers CONFIG_HOLD across the TAP resets for the PTAP 3DCR and
every STAP 3DCR.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_reg` |`ptap`, `io`, `smc`, `sep`, `extra`
|`cp_case` |`tlr_unheld_cleared`, `tlr_held_retained`, `trst_unheld_cleared`, `trst_held_cleared`; any other result is an illegal bin
|`x_hold` |`cp_reg` x `cp_case`
|===

Sampled once per 3DCR holding a non-zero image at each reset, against the image
held just before it: a Test-Logic-Reset entered through TMS, compared on the
edge that leaves its first cycle, and a TRST, compared on the first edge after
its release. The PTAP ANDs power-on reset into the TRST it applies and
forwards to the STAPs, so a power-on reset samples the `trst` bins too.
Test-Logic-Reset keeps the image while CONFIG_HOLD is set and clears it
otherwise; TRST clears it at either value.

==== `cg_ijtag_sib`

*Description*: Covers IEEE 1687 SIB network selection across the DFT Secure, DFT Non-Secure, and DFD (Design-for-Debug) chains.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_instr` |`select_ijtag`, `runbist`
|`cp_pattern` |`pattern[0]` to `pattern[7]`: every open set of {DFT secure, DFT non-secure, DFD}

==== `DtpDbgDisableFcov`

*Description*: The checker-gated ledger (`env/dtp_fcov.py`) of the per-field
debug-disable gating contract for the eight scan-side fields of the eleven
pre-resolved active-high disables of `sep_lifecycle_ctrl_pkg::dbg_disable_t`
(`1 = interface disabled`). Deriving these fields from lifecycle policy is
verified at the SEP level; DTP coverage closes on each field gating exactly
its interface.

The sample tuple is `(field, disable_value, observed_outcome)`. For each of
the eight fields, both legal cells are required:

* `(field, 0, allowed)`
* `(field, 1, blocked)`

This produces 16 required cells. The contradictory tuples,
`(field, 0, blocked)` and `(field, 1, allowed)`, are checker failures, never
ledger cells.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|Field |`stap_io`, `stap_smc`, `stap_sep`, `stap_extra`, `stap_host`, `dft_secure`, `dft_nonsecure`, `dfd`
|Field outcome |`(field, 0, allowed)` and `(field, 1, blocked)` per field (16 cells)
|Mask class |all clear, one-hot, multi-hot, all disabled
|Unrelated-resource isolation |an enabled resource proven usable while another field is asserted
|Release without replay |no queued operation completes after a disable clears
|Recovery |a sanctioned operation succeeds after release
|===

Sampling rules:

* A cell is recorded only after the associated functional checker passes;
  coverage is never auto-hit from a test name or from writing a disable
  input.
* Every coverage log line records the field, the full named disable mask,
  the attempted operation, and the observed result.
* In the cocotb realization `dtp_scan_dbg_disable_matrix_test` requires all
  16 cells before completing and emits a JSON artifact under its `coverage/`
  directory recording the cells it hit.
* The SV-UVM realization keeps no ledger: every matrix pass runs each field's
  one-hot row and both boundary rows.
* `cg_dbg_disable_scan` in `dtp_scan_fcov` records the sixteen cells at the
  signal level in both realizations, with the contradictory tuples as illegal
  bins; in the cocotb realization the checker-gated ledger cells above are
  the contract.

==== `cg_dbg_disable_scan`

*Description*: The signal-level twin of the sixteen scan-side cells of the
`DtpDbgDisableFcov` ledger.

[cols=",",options="header",]
|===
|Coverpoint |Bins
|`cp_field` |`stap_io`, `stap_smc`, `stap_sep`, `stap_extra`, `stap_host`, `dft_secure`, `dft_nonsecure`, `dfd`
|`cp_value` |`clear`, `set`
|`cp_outcome` |`allowed` with the field clear, `blocked` with it set; the contradictory pairs are illegal bins
|`cp_mask` |`all_clear`, `one_hot`, `multi_hot`, `all_disabled` over the eight scan-side fields
|`cp_isolation` |on an attempt with the field clear: `other_field_set` (another scan-side field set)
|`cp_sequence` |`released`, `recovered`
|`x_cell` |`cp_field` x `cp_value`: `(field, clear)`, which `cp_outcome` requires to be allowed, and `(field, set)`, which it requires to be blocked
|`x_field_isolation` |`cp_field` x `cp_isolation`
|`x_sequence` |`cp_field` x `cp_sequence`
|===

`dtp_scan_fcov` samples one tuple per field and attempt, with the
synchronized disable the gate applies:

* `stap_io`, `stap_smc`, `stap_sep`, `stap_extra`: a STAP chain shift cycle
  while the port's stored select is set; `allowed` when the port drives its
  host TDO enable, `blocked` when it stays parked.
* `stap_host`: a STAP chain shift cycle; `allowed` when the extended host
  shift enable follows it, `blocked` when that enable stays low.
* `dft_secure`, `dft_nonsecure`, `dfd`: an iJTAG network Update-DR that loads
  a 1 into the SIB bit; `allowed` when the SIB opens, `blocked` when it stays
  closed.

A release is the field clearing after a blocked attempt, and a recovery the
first allowed attempt after a release. `dtp_scan_dbg_disable_matrix_test`
reaches every bin in each realization: the one-hot rows give each field's
blocked cell and its isolation from the others, the all-clear row the allowed
cells, and the release after the all-disabled row with the recovery row that
follows give each field's release and recovery.

[[dtp-fcov-closure]]
=== Closure Policy

Coverage closes against the policy file, not against a rerun: every
uncovered point of the `all` regression is either fired by a new or
extended scenario, held open by a defect that a tracker item owns, or removed
from the effective denominator by a reviewed waiver, which a covergroup bin
never takes. The rules below bind the DTP policy file; the runner's schema
and grading behavior are in `tools/dv/doc/run-dv.adoc`.

[[dtp-fcov-evidence-paths]]
==== Evidence paths

* **Public path.** The `all` regression at three seeds with `--cov` on
  Verilator. Its run tree carries `cov/report/coverage-details.json`
  (every point with its disposition), `cov/report/summary.json` (the raw
  and effective figures per family and the hole counts), and
  `cov/report/policy-application.json`. A policy change is graded
  against a finished run with `run_dv.py --dut dtp --run-dir <run> --waive`,
  which rewrites the grade without a simulation.
* **Commercial path.** The cocotb `all` and SV-UVM `all` regressions on
  VCS with the full `-cm` set and the compile-time scope, each merged by the
  runner, then combined across frameworks into one run with
  `run_dv.py --dut dtp --cov-combine <cocotb-run> <uvm-run>`; the report
  of that combined run is the code-coverage evidence and carries the
  covergroup model. URG hands the runner code-coverage family totals and no
  per-point list, so `cov/config/vcs/coverage_policy.toml` carries no
  `pass:[[[holes]]]` and a VCS hole closes through a scenario, a design or
  model change, or an entry in one of the two URG exclusion lists that the
  `pass:[[[native_files]]]` entries of that policy name
  (<<dtp-fcov-unreachability-list>>, <<dtp-fcov-waiver-list>>); the runner
  passes each list to `urg -elfile`, records its checksum, and reports the
  figures with and without them as `effective_metrics` and `raw_metrics`.
  Covergroup bins take no exclusion.
* A metric is applicable on the path that collects it, and a point that
  both paths collect is one point: a hole on either path needs one
  disposition, and a waiver written for one path names the same
  structural reason on the other.

==== Hole dispositions

[cols="1,3,2,1",options="header",]
|===
|Disposition |Meaning |Requires while open |Counts as
|`cover` |The point is reachable and needs a scenario or a stimulus change |A tracker link |Open hole
|`fix_design` |A design defect blocks the point |A tracker link naming the defect |Open hole
|`fix_model` |A bench, model, or coverage-module defect blocks the point |A tracker link |Open hole
|`review` |The point awaits a disposition |A tracker link |Open hole
|`waive` |The point has no reachable stimulus on this bench or configuration, for the structural reason the rationale names |`status = "accepted"`, the fields below |Removed from the effective denominator
|`exclude_scope` |The point is outside the DTP verification contract (integration-level behavior, vendor IP internals, elaboration-time constants) |`status = "accepted"`, the fields below |Removed from the effective denominator
|===

An open hole never shrinks a denominator; only an accepted `waive` or
`exclude_scope` entry does, and only at `medium` or `high` confidence. The
runner rejects an accepted waiver that matches a covered point, a
low-confidence waiver, an entry whose `dut` is not the run's, and an open
actionable hole without a tracker link.

==== Waiver fields

Every `pass:[[[holes]]]` entry carries `id`, `title`, `category`, `disposition`,
`status`, `confidence`, `rationale`, `owner`, `reviewer`, and at least one
`pass:[[[holes.native]]]` selector (`tool`, `metric_family`, `hierarchy`); an
entry whose selector is a pattern also carries `expected_matches`. The
rationale states the design
or bench fact that makes the point unreachable, in words the reviewer of a
later design or bench change can recognize; a rationale that restates the
point's name is not one. `issues` carries the tracker link of the defect or
task an open hole waits on, and of the review that accepted a waiver.

==== Reviewers

An entry's `reviewer` differs from its `owner`. A `waive`,
`exclude_scope`, or `fix_design` entry whose rationale is a design fact
takes design review; a `fix_model` or `cover` entry takes DV review; a
`pass:[[[native_files]]]` entry takes coverage-flow review. Every entry
change is graded against a named finished run with the runner's `--waive`
re-grade.

==== Reopen triggers

An accepted waiver stays accepted until the policy changes; the calendar does
not reopen it. It reopens, by the entry's status returning to `open` or the
entry being removed, when:

* the runner rejects it because its selector matches a covered point;
* the policy's `scope_epoch` changes, which restarts every dashboard
  series;
* a design or bench change removes the structural reason its rationale
  names;
* the metric set of `[coverage.verilator]` or the VCS `-cm` set changes;
* the tracker item its `issues` list names closes.

==== Run status

A regression passes or fails on its tests; its coverage figures do not move
its status. Neither policy file sets a `pass:[[[thresholds]]]` rule and
`dtp_sim_cfg.toml` sets no `fail_under`, so the runner grades coverage
against 0 percent, and `cov_report` fails only when the report tool fails or
the runner refuses a policy file. Both paths report the raw and effective
figure of every metric family, and closure reads them against the targets of
the Coverage Goals section.

[[dtp-fcov-unreachability-list]]
==== Unreachability exclusion list

`cov/config/vcs/dtp_unreachable.el` is the URG exclusion list of the
code-coverage points that a formal unreachability analysis proves no stimulus
reaches in the bench's environment: the DTP at the bench configuration, the
DFT ports at their functional values, the boundary-scan chain looped back,
and every other input free, the extended STAP host scan-in and the resets
included. The DFT ports reach no listed point other than their own toggles,
which `dtp_jtag2axi_reset_test` covers and the list leaves out: `scan_rst_ni`
reaches only the JTAG2AXI bridges, which hold no entry, and `test_en_i` also
the `testmode_i` of the CSR crossbar's FIFOs, which no logic reads. The analysis starts from the merged database of the
commercial-path `all` regression (<<dtp-fcov-evidence-paths>>), so it targets
the points that regression left uncovered, and the list holds for the RTL
that produced that database. No analysis in this repository writes the list:
it is regenerated by an unreachability tool run over that database in the
same environment, written in the URG exclusion format. A run may assume
invariants of the design that an assertion run in the same environment
proves at every formal step; a check of the list that leaves those
invariants out reports the entries that rest on them inconclusive.

The `pass:[[[native_files]]]` entry of `cov/config/vcs/coverage_policy.toml`
that names the list pins the file's SHA-256. The runner refuses the policy
when the file and the pinned digest differ, so a regenerated list takes a new
entry. URG maps each code-coverage entry onto the design it reports on by the
item's signature and applies it whatever the scope checksum. A toggle or
condition entry outlives an RTL change that leaves the signal or expression it
quotes in place. A branch entry's signature spans every condition of its
decision tree, and a line entry's, which URG writes as `Block`, spans its
statement and the condition that governs it; an FSM state or transition
entry's signature names its states. Any change to that text, a renamed
localparam or state included, drops the entry. The runner applies the list at
report time without re-checking it, so until the list is regenerated for a
changed RTL, the effective figures rest on a list proven against the RTL
before the change.

Regeneration rule: after any change to the DTP RTL file set, the list is
regenerated from the merged database of a fresh `all` regression, and an
accepted entry that stimulus reaches or that does not map onto the changed
design is removed. A regenerated list takes design review before its entry
changes, and the review accepts no entry that stimulus can reach. A condition
or line that holds only inside one simulation time step, while an
`always_comb` block evaluates before its inputs settle, is not reached:
coverage credits that evaluation, but no settled state of the design holds it.

[[dtp-fcov-waiver-list]]
==== Waiver list

`cov/config/vcs/dtp_waivers.el` is the URG exclusion list of the points the
bench reaches by no stimulus the DTP's interface contract allows. Each is a
DTP input, a bench checker rule, an assertion, or a point the cross-trigger
network's register map and crossbar flow control rule out, none of which the
formal unreachability analysis proves, and the `ANNOTATION` before each entry
states the fact that rules it out:

[cols=",",options="header",]
|===
|Points |Fact
|BID and RID toggles of `axi_smc_dbg_resp_i` at `u_dut`, `u_jtag_intf_unit` and `u_jtag_ptap` |The JTAG2AXI bridge issues every SMC fabric request with ID 0, and an AXI subordinate returns the request's ID
|`xtrig_ctp_ack_out_din_i` toggles at `u_dut`, and `ctp_ack_out_din_i` at `u_cross_trigger_network` |CT_Ack_out is output-only: the cross-trigger network holds the pad input enables low and reads the pad inputs only into its lint sink
|The FIXED and WRAP burst rules and the multi-beat covers of `u_m_axi_sva` |The bridge issues every SMC fabric request as a single-beat INCR burst
|The `RECEIVER_WAIT_REQ_DEASSERT` arm of every external CTP's receiver with CT_Req_in high |The receiver enters the state with CT_Req_in low; a four-phase sender raises its next request only after it sees CT_Ack_out fall, which the receiver drives low in that same transition
|Condition row W valid without AW valid in every CTP register block and the matrix register block |The crossbar demux forwards a W only after presenting its AW, and only once the previous write's B has left the block, by which time the block has taken that AW
|Bits 26 and 30 of the R data held in the CSR port's R spill register |No subordinate returns them: a CT_SRC select holds 26 bits, every CTP register fewer, and the decode-error subordinate answers `0xBADCAB1E`
|`flush_valid` on the five CSR port spill registers |The spill register wrapper ties their flush input low
|`full_write` of the decode-error subordinate's B FIFO |The demux presents it a W only while its own one-entry B FIFO is empty, and that FIFO stays full until the write's B
|`ar_select_stable` of the crossbar demux |The demux presents an AR only while its one-entry R FIFO is empty, and a subordinate refuses an AR only while it owes a read its R, which keeps that FIFO full
|===

The entries carry the checksums `urg -dump full_exclusions` reports for each
scope, and the `pass:[[[native_files]]]` entry that names the file, with
`role = "waive"`, pins its SHA-256. An `Assert` entry applies only while its
instance checksum matches the design, so a change to the checker drops it
with a URG warning. Toggle, condition and branch entries map by the signature
rule of the unreachability list (<<dtp-fcov-unreachability-list>>), so a
change to any condition of a waived branch's decision tree drops that entry,
and its replacement comes from a fresh dump. A changed entry takes design
review.

=== Collection Strategy

[cols=",",options="header",]
|===
|Flow |Strategy
|Verilator simulation |The covergroups of the `cov/sv/` modules and the cover properties of the AXI and JTAG protocol checkers; `run_dv.py --cov` collects them as `covergroup` and `user` coverage in each test's `coverage.dat`, merges across tests and seeds (`cov_merge`), and reports through `cov_report` with `cov/config/verilator/coverage_policy.toml` applied
|Per-group reporting |The merged run's `coverage-details.json` carries every point with its policy disposition, keyed by each covergroup bin's name (`<covergroup>.<coverpoint>.<bin>`) and each protocol checker cover point's native hierarchy name
|Verilator metric set |`[coverage.verilator]` in `dtp_sim_cfg.toml` instruments line, expression, and `user` coverage, leaves toggle out, and passes the compile-time scope `cov/config/verilator/dtp_cov_scope.vlt`
|Commercial simulation |The same modules' covergroups are the functional family; the cover properties stay compiled and grade with the assertions. Both frameworks collect through the runner, cocotb with `run_dv.py --cov --tool vcs` and SV-UVM with `run_dv.py --framework uvm --cov`, with per-test `simv.vdb` databases merged (`cov_merge`, `urg` with the design database) and reported (`cov_report`); the two frameworks' merged databases are combined with `run_dv.py --dut dtp --cov-combine <cocotb-run> <uvm-run>` into one DUT-scoped report
|Code coverage |VCS line, branch, condition, FSM and toggle coverage scoped to the DUT instance, and assertion coverage over the DUT and the protocol checkers; Verilator line, branch and expression coverage over its compile-time scope
|Closure triage |Add directed tests for reachable holes; record a blocked or unreachable point as a hole entry in the Verilator policy file, and an unreachable VCS point as an entry of `dtp_unreachable.el` or `dtp_waivers.el`, each stating the structural reason the point cannot fire
|===

Sampling happens at the documented transaction boundaries: TCK rising edge
(TAP state and transition), completed IR scan, completed DR scan (the TDR,
STAP chain, and iJTAG network groups sample at the edge that leaves Update-IR
or Update-DR), Test-Logic-Reset and TRST, STAP chain shift cycle, system
reset, clock-stop source change, CTP/CTM event, completed XTRIG CSR access,
DMI update and DTMCS `dmireset` of a JTAG2AXI bridge, and debug-disable
configuration change.

=== Exclusions and Limitations

[cols=",",options="header",]
|===
|Item |Reason
|JTAG_CAPS field values |Elaboration-time constants with one reachable value each; `CHK-CAPS` compares every field on every read, and `cg_caps_tdr` covers their stability and read-only behavior
|Illegal bins: a TAP state or instruction decode that is not one-hot, a TAP transition off the IEEE 1149.1 state graph, a Capture-IR update that is not IDCODE, an invalid IDCODE marker, a contradictory debug-disable outcome, an open SIB under its disable, a 3DCR reset result CONFIG_HOLD does not call for, an XTRIG CSR response the memory map does not give, a DMI status of 1 or 2, and the other illegal bins each definition names |Only a design or checker failure reaches them; VCS reports a hit as a runtime error, Verilator stops the simulation on one, and the ledger records a contradictory outcome as a checker failure, never a cell
|Internal cross-trigger lanes in point-to-point mode |The bench elaborates `XTRIG_INT_CT_MODE` = 0, so every internal CT runs pulse mode
|Static parameter toggles |Compile-time constants; not meaningful runtime coverage
|`prim_cdc_rand_delay` under every synchronizer primitive (`prim_flop_2sync`, `prim_sync3r` and their siblings) |Simulation-only CDC jitter model with no counterpart in a synthesized DTP; the VCS scope file removes the module from code coverage
|DFT mode outside the JTAG2AXI bridge reset |`dtp_jtag2axi_reset_test` drives `test_en_i` and `scan_rst_ni` for the bridges' reset selection, and every other scenario holds them at their functional values; outside the bridges `test_en_i` reaches only the `testmode_i` of the CSR crossbar's FIFOs, which no logic reads, and scan behaviour is a scan-insertion level concern
|Protocol-specific behavior without shared VIP support |Covered by OCAH-local DTP BFMs
|===
