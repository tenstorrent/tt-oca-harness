Memory Map
Overview

The I3C Core Controller provides a comprehensive register interface organized into five major sections accessible through an AXI4-Lite slave interface. The register space is organized into a 12-bit address space (0x000-0xFFF) per I3C instance, with each instance occupying 0x1000 bytes of address space when multiple instances are implemented via i3ccore_wrapper.

The register map follows the MIPI I3C HCI v1.2 specification with OCA-specific extensions for recovery and enhanced IBI handling. All registers are 32-bit aligned and support only 32-bit access widths.

Register Organization

  • I3CBase Section (0x00-0x68): Core controller configuration and status registers including bus control, capabilities, interrupts, and reset management

  • PIOControl Section (0x80-0xB0): Programmable I/O interface with queue ports, threshold controls, and PIO-specific interrupt management

  • I3C_EC Section (0x100-0x3A0): Extended Capabilities including Secure Firmware Recovery Interface (0x100-0x168), Standby Controller Mode (0x180-0x1C0), Target Transaction Interface (0x200-0x290), SoC Management Interface (0x300-0x390, includes bus-timing registers), Controller Config (0x398-0x39C), and Termination (0x3A0)

  • DAT Section (0x400-0x7FF): Device Address Table, 128-entry address window (2 DWORDs / 64-bit per entry); physical depth DAT_DEPTH=16 (usable index 0-15)

  • DCT Section (0x800-0xFFF): Device Characteristic Table, 128-entry address window (4 DWORDs / 128-bit per entry); physical depth DCT_DEPTH=16 (usable index 0-15)

Address Alignment and Access

Address Alignment: * All registers are aligned to 32-bit boundaries (addresses are multiples of 4) * Effective address space per instance: 12 bits (0x000-0xFFF) * Instance spacing in multi-instance configurations: 0x1000 bytes

Access Width Requirements: * All registers must be accessed using 32-bit operations * Byte and halfword accesses are not supported * AXI4-Lite write strobe signals should be set to 4’b1111 for full-word writes

Endianness: * Data byte ordering: Little-endian (configurable via HC_CONTROL.DATA_BYTE_ORDER_MODE) * Bit numbering: Bit 0 is LSB, bit 31 is MSB * Multi-byte fields follow little-endian byte ordering

Detailed Register Descriptions

Description: Primary control register for enabling and configuring the I3C Host Controller. Software must configure this register during initialization to enable bus operation and select operating modes.

RESET_CONTROL (0x10) - Reset Control

Description: Software reset control for the Host Controller and individual queue structures. Allows selective reset of queues without full controller reset. All reset bits are self-clearing (write 1 to reset, hardware clears to 0 when reset completes).

Access: Read/Write

Reset Value: 0x00000000 (no resets asserted)

IBI_QUEUE_RST

RW

0

IBI Queue Reset: Clear IBI queue. Write 1 to flush all IBI status descriptors and IBI data from queue. Hardware clears to 0 when reset completes. Only valid in PIO mode. Software should not reset IBI queue while transactions are in progress.

4

RX_FIFO_RST

RW

0

RX FIFO Reset: Clear RX data FIFO. Write 1 to flush all received data. Hardware clears to 0 when reset completes. Only valid in PIO mode. Resetting RX FIFO while read transaction is in progress will cause data loss.

3

TX_FIFO_RST

RW

0

TX FIFO Reset: Clear TX data FIFO. Write 1 to flush all transmit data. Hardware clears to 0 when reset completes. Only valid in PIO mode. Resetting TX FIFO while write transaction is in progress will cause underflow error.

2

RESP_QUEUE_RST

RW

0

Response Queue Reset: Clear response queue. Write 1 to flush all response descriptors. Hardware clears to 0 when reset completes. Only valid in PIO mode. Flushing response queue discards completion status for pending commands.

1

CMD_QUEUE_RST

RW

0

Command Queue Reset: Clear command queue. Write 1 to flush all pending command descriptors. Hardware clears to 0 when reset completes. Only valid in PIO mode. Flushing command queue aborts all pending transactions.

0

SOFT_RST

RW

0

Software Reset: Reset entire Host Controller. Write 1 to reset controller state machines, queues, and internal logic. Hardware clears to 0 when reset completes. Does NOT reset CSR register values - software must reconfigure after soft reset. Bus must be idle before issuing soft reset.

Usage Notes:

  • All reset operations are self-clearing - poll the register to confirm reset bit returns to 0 before proceeding

  • Queue resets are lightweight operations affecting only FIFO pointers and flags, not the underlying storage

  • SOFT_RST provides full controller reset without affecting register configuration

  • Reset individual queues for error recovery (e.g., TX underflow, RX overflow)

  • Never reset queues while HC_CONTROL.BUS_ENABLE=1 and transactions are active

R

Active Controller Current Owner: Indicates whether this controller currently owns the I3C bus. 0 = Not bus owner (either idle or secondary controller has ownership), 1 = This controller owns the bus and can initiate transactions. COMMAND_PORT (0x80) - Command Queue Port

Description: Write-only port for submitting command descriptors to the command queue. Command descriptors are 64 bits (2 DWORDs), requiring two sequential 32-bit writes to this address. First write provides descriptor bits [31:0], second write provides bits [63:32] and triggers command submission.

Access: Write-only

Reset Value: N/A (write-only FIFO port)

Table 7. COMMAND_PORT Register Bit Fields
Bits Name Access Reset Description

31:0

COMMAND_DATA

W

N/A

Command Descriptor Data: Write descriptor DWORD. First write (bits [31:0]): Command attributes, transfer type, device index, data length. Second write (bits [63:32]): Command-specific parameters, defining byte, reserved fields. Second write atomically enqueues complete 64-bit descriptor.

Command Descriptor Format (64-bit):

  • Bits [6:0]: Command Attribute - transfer type (write, read, address assignment, CCC)

  • Bits [11:7]: Target Device Index - index into DAT for target address lookup

  • Bits [15:12]: Command Type - private, CCC, HDR mode selection

  • Bits [31:16]: Transfer Length - number of bytes to transfer (write/read)

  • Bits [39:32]: Defining Byte - CCC defining byte (if CCC_DEFBYTE=1 in descriptor)

  • Bits [63:40]: Reserved/command-specific fields

Usage Notes:

  • Always write both DWORDs for each command descriptor

  • Check PIO_INTR_STATUS.CMD_QUEUE_READY_STAT or poll QUEUE_SIZE before writing to avoid queue overflow

  • Command queue depth is indicated by QUEUE_SIZE.CR_QUEUE_SIZE (typically 8 entries)

  • Commands are executed in FIFO order (first-in, first-out)

  • For bulk command submission, use threshold-based interrupts to minimize polling overhead

RESPONSE_PORT (0x84) - Response Queue Port

Description: Read-only port for retrieving response descriptors from the response queue. Each read returns a 32-bit response descriptor providing transaction completion status, error codes, and transferred byte count.

Access: Read-only

Reset Value: N/A (read-only FIFO port)

Table 8. RESPONSE_PORT Register Bit Fields
Bits Name Access Reset Description

31:0

RESPONSE_DATA

R

N/A

Response Descriptor Data: 32-bit response descriptor. Bits [31:28] = Error code (0x0=success, 0x1=CRC error, 0x2=parity error, 0x3=frame error, 0x4=address NACK, 0x7=transfer aborted, 0x8=I2C W NACK, 0x9=I2C R NACK, 0xF=overflow/underflow). Bits [27:24] = Transaction ID (TID, matches command descriptor). Bits [15:0] = Data length (actual bytes transferred).

Response Descriptor Format (32-bit):

  • Bits [15:0]: Data Length - actual number of bytes transferred before completion or error

  • Bits [23:16]: Reserved

  • Bits [27:24]: Transaction ID (TID) - matches TID from command descriptor for correlation

  • Bits [31:28]: Error Status - primary error code indicating transaction outcome

Error Status Codes:

  • 0x0: SUCCESS - transaction completed without errors

  • 0x1: CRC_ERROR - CRC check failed (HDR modes only)

  • 0x2: PARITY_ERROR - parity error detected

  • 0x3: FRAME_ERROR - framing error (illegal START/STOP)

  • 0x4: ADDRESS_NACK - target did not ACK address

  • 0x7: TRANSFER_ABORT - software aborted via HC_CONTROL.ABORT

  • 0x8: I2C_W_NACK - I2C write data NACK

  • 0x9: I2C_DATA_NACK - I2C read data NACK

  • 0xF: OVERFLOW_UNDERFLOW - TX underflow or RX overflow

Usage Notes:

  • Check PIO_INTR_STATUS.RESP_READY_STAT before reading to avoid reading stale data

  • Response queue depth equals command queue depth (QUEUE_SIZE.CR_QUEUE_SIZE)

  • Responses are generated in same order as commands (FIFO order)

  • Software must drain response queue to avoid blocking command execution

  • Non-zero error status requires software error handling (retry, device reset, etc.)

TX_DATA_PORT (0x88) - Transmit Data Port

Description: Write-only port for writing transmit data to the TX FIFO. Data is consumed by controller during write transactions. Each write provides 32 bits (4 bytes) of data in little-endian format. Same address as RX_DATA_PORT but distinguished by write vs. read access.

Access: Write-only

Reset Value: N/A (write-only FIFO port)

Table 9. TX_DATA_PORT Register Bit Fields
Bits Name Access Reset Description

31:0

TX_DATA

W

N/A

Transmit Data: 32-bit DWORD of transmit data. Byte 0 in bits [7:0], byte 1 in bits [15:8], byte 2 in bits [23:16], byte 3 in bits [31:24] (little-endian ordering). Controller consumes bytes LSB-first during I3C write transactions.

Usage Notes:

  • Write TX data after writing command descriptor but before controller starts transfer

  • Monitor PIO_INTR_STATUS.TX_THLD_STAT to know when FIFO needs refill

  • TX_START_THLD controls when controller begins transfer (waits for minimum data threshold)

  • TX_BUF_THLD controls when TX_THLD_STAT interrupt triggers (FIFO has space available)

  • TX FIFO depth: 2^(QUEUE_SIZE.TX_DATA_BUFFER_SIZE + 1) DWORDs

  • Underflow (insufficient data) triggers TRANSFER_ERR response and may abort transaction

RX_DATA_PORT (0x88) - Receive Data Port

Description: Read-only port for reading received data from the RX FIFO. Data is written by controller during read transactions. Each read returns 32 bits (4 bytes) of data in little-endian format. Same address as TX_DATA_PORT but distinguished by read vs. write access.

Access: Read-only

Reset Value: N/A (read-only FIFO port)

Table 10. RX_DATA_PORT Register Bit Fields
Bits Name Access Reset Description

31:0

RX_DATA

R

N/A

Receive Data: 32-bit DWORD of received data. Byte 0 in bits [7:0], byte 1 in bits [15:8], byte 2 in bits [23:16], byte 3 in bits [31:24] (little-endian ordering). Controller writes bytes LSB-first during I3C read transactions.

Usage Notes:

  • Read RX data after response descriptor indicates transfer completion

  • Monitor PIO_INTR_STATUS.RX_THLD_STAT to know when FIFO has data available

  • RX_START_THLD controls when controller begins transfer (waits for minimum free space)

  • RX_BUF_THLD controls when RX_THLD_STAT interrupt triggers (FIFO has data available)

  • RX FIFO depth: 2^(QUEUE_SIZE.RX_DATA_BUFFER_SIZE + 1) DWORDs

  • Overflow (insufficient FIFO space) triggers TRANSFER_ERR response and aborts transaction

  • Software should drain RX FIFO promptly to prevent overflow on subsequent reads

IBI_PORT (0x8C) - IBI Status and Data Port

Description: Read-only port for retrieving In-Band Interrupt status descriptors and associated IBI data. First read returns 32-bit IBI status descriptor, subsequent reads return IBI data payload (if any). Hardware manages alternation between status descriptors and data reads.

Access: Read-only

Reset Value: N/A (read-only FIFO port)

Table 11. IBI_PORT Register Bit Fields
Bits Name Access Reset Description

31:0

IBI_DATA

R

N/A

IBI Status or Data: Multiplexed IBI queue output. First read after IBI_STATUS_THLD_STAT interrupt: 32-bit IBI status descriptor containing IBI source address, data length, timestamp. Subsequent reads: IBI data payload (if data length > 0). Data is 4-byte aligned; unused trailing bytes are padded to DWORD boundary.

IBI Status Descriptor Format (32-bit):

  • Bits [7:0]: IBI Source Address - 7-bit device address that initiated IBI, shifted left by 1

  • Bits [15:8]: Data Length - number of bytes in IBI payload (0-255)

  • Bits [23:16]: IBI ID - unique identifier for IBI type (device-specific or common IBI codes)

  • Bits [31:24]: Timestamp or error info - optional timestamp or error flags

Usage Notes:

  • IBI status descriptor is always present for each IBI event

  • IBI data reads follow status descriptor only if Data Length > 0

  • Data is padded to 4-byte boundary - use Data Length field to determine actual bytes

  • IBI queue depth: QUEUE_SIZE.IBI_STATUS_SIZE entries (typically 8)

  • Extended IBI queue: if ALT_QUEUE_SIZE.EXT_IBI_QUEUE_EN=1, queue size is 8× larger

  • Software must service IBI queue promptly to avoid losing subsequent IBIs

  • Check INTR_STATUS.HC_INTERNAL_ERR_STAT if unexpected IBI queue behavior occurs

RW

0x01

Command Empty Buffer Threshold: CMD_QUEUE_READY_STAT interrupt triggers when command queue has N or more free entries available. Valid range: 1-255. Higher values allow burst writes of multiple commands per interrupt.

Usage Notes:

  • Set thresholds based on software latency and desired interrupt rate

  • Higher thresholds reduce CPU interrupt overhead but require faster software response

  • Lower thresholds provide more granular control and reduce buffer requirements

  • Typical configuration: RESP_BUF_THLD=4, CMD_EMPTY_BUF_THLD=4 for balanced performance

  • For bulk transfers, increase thresholds to minimize interrupts

  • For low-latency applications, keep thresholds at minimum (1) for immediate notification

  • Value 2: 2^(2+1) = 8 entries

  • Value 3: 2^(3+1) = 16 entries

  • Value 4: 2^(4+1) = 32 entries

  • Value 5: 2^(5+1) = 64 entries

  • Value 6: 2^(6+1) = 128 entries

  • Value 7: 2^(7+1) = 256 entries

Usage Notes:

  • TX/RX_START_THLD should be set based on expected transfer sizes and FIFO depths

  • Higher start thresholds increase latency but reduce risk of underflow/overflow

  • TX/RX_BUF_THLD should be set to trigger interrupts when FIFO is approximately half full/empty

  • For maximum throughput, set start thresholds low and buffer thresholds high

  • For minimum latency, set all thresholds to minimum value (0 = 2 entries)
