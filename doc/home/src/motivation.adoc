= Why Open Chiplet Atlas Harness?

== Implements OCA v0.8

The Open Chiplet Atlas (OCA) Harness exists to bridge the gap between a
chiplet interoperability architecture and a deployable chiplet design. The
OCA architecture defines the rules needed to make chiplets from different
vendors plug together at the software, system, protocol, transport, and
physical layers, but real adoption depends on turning those rules into
reusable implementation collateral.

The architecture specification lives at
https://www.openchipletatlas.org/[openchipletatlas.org].

*OCA Harness is that implementation vehicle: an open-source chiplet framework
that currently implements OCA Specification v0.8, intended to make
interoperability practical rather than purely conceptual.*

== Reusable framework

The motivation for OCA Harness is rooted in the cost and complexity of modern
silicon development. Advanced chips require a large amount of
non-differentiating but essential infrastructure, including security, boot,
system management, debug, test, and die-to-die integration. Recreating or
licensing these subsystems for each chiplet raises cost, extends schedules,
and increases integration risk, which in turn limits who can participate in
advanced silicon design. 

*OCA Harness addresses this by packaging the common chiplet-management and infrastructure 
logic into a reusable framework so that adopters can spend their effort on their
own value-differentiating application logic.*

== Chiplet focus

A key design premise behind OCA Harness is that most interoperability requirements
in OCA land in the chiplet framework rather than in the application
subsystem itself. OCA Harness integrates the non-application-specific
functions that repeatedly appear across chiplets, such as the Security
Processor (SEP), System Management Controller (SMC), System
Management Network (SMN), debug/test access, and bridges such as
AXI-over-UCIe. 

By reusing this framework across chiplets, designers gain OCA-aligned 
boot, security, management, and communication behavior by construction, 
instead of rebuilding those capabilities from scratch in every project.

== Open by design

OCA Harness is released under the Apache-2.0 license as the Harness pillar of the
OCA Ecosystem: an open-source, reusable design framework containing the
non-application logic a chiplet needs, so designers can focus on their
unique value-add while remaining automatically interoperable with the rest
of the ecosystem.

== Ecosystem growth

The open-source release of OCA Harness is therefore motivated not only by reuse
inside Tenstorrent, but by ecosystem growth. Tenstorrent's stated goal is to
enable broader adoption of an open chiplet ecosystem by removing objections
to integration, improving out-of-box usability, and making high-quality
common infrastructure available under a permissive license.

*OCA Harness is both a technical framework and an adoption mechanism: it reduces
duplicated engineering work, lowers the barrier to interoperable chiplet
design, and gives partners a concrete foundation on which to build
OCA architecture compliant chiplets and systems.*
