= Project Defines
:trm-url: https://tenstorrent.github.io/tt-oca-harness/ocah-docs/latest
:page-role: integrator-guide

[[project-defines]]
Use the build mode and controls below when preparing an adopter build. A
preprocessor define changes compiled RTL; a Bender target selects source files;
a module parameter changes elaboration; a plusarg is read at simulation runtime.
Keep those settings distinct in the integration configuration.

== Build controls

[cols="1,1,3",options="header"]
|===
|Control |Kind |Integration use
|`SIMULATION` |Preprocessor define
|Set for RTL simulation. Enables the hooks described below; omit from synthesis,
formal and gate-level builds.
|`SYNTHESIS` |Preprocessor define
|The shared lint/synthesis flow passes `-D SYNTHESIS=1`. It removes simulation
paths guarded by this name, including the randomized delay in `prim_sync2`.
Do not add it to RTL DV builds to suppress simulation failures.
|`simulation`, `synth` |Bender targets
|Select the appropriate file graph. OCAH's generic technology-cell models are
under `not(synth)`; synthesis must supply the target technology implementations.
A target does not set a same-named preprocessor define.
|`SEP`, JTAG and pipeline settings |Module parameters / configuration fields
|Select the instantiated hardware. See
xref:smu-integration.adoc#smu-composition[SMU Composition and Internal Wiring].
|===

The shared build defaults are in `flows/common.mk`; the RTL source selection
is in `Bender.yml`. Preserve both the source selection and the compiler defines
when reproducing a build in another flow.

== Verification controls

The native DV profile (`hw/common/dv/configs/profiles/native.toml`) supplies
`SIMULATION` and the following verification settings. Tool and DUT overlays can
add to this set; it is not a production configuration.

[cols="1,2",options="header"]
|===
|Setting |Purpose / scope
|`COMMON_CELLS_ASSERTS_OFF`
|Disables inline assertions gated by that name in PULP common cells.
|`RANDOM=0`, `RANDOMIZE_MEM_INIT`, `RANDOMIZE_REG_INIT`, `RANDOMIZE_DELAY=0.02`
|Controls initialization in the generated CPU RTL used by the native profile.
Keep the profile's values when reproducing its tests.
|`UVM`
|Added by the native profile's SV-UVM framework overlay; selects the SV-UVM
harness. Leave unset for the default cocotb framework.
|`VERILATOR`, `ASSERTS_OFF`
|Tool-specific assertion controls used by the DTP Verilator overlay. Do not
copy assertion-disabling flags into another simulator's configuration without
checking the selected DUT's requirements.
|===

See {trm-url}/dtp/defines.html#dtp-simulation-defines[OCAH TRM — DTP Simulation and Test Defines]
for the DTP overlay and assertion behavior. Other DUTs have their own simulation
configuration; this chapter does not enumerate private model or per-test macros.
`NO_LIBCELL` is not the selector for the open RTL simulation cell models; those
models are selected by the Bender file graph.


[[simulation-define]]
== `SIMULATION`

`SIMULATION` selects the verification view of OCAH RTL. Set it on every
simulation compile and on no other kind of build:

[source,shell]
----
+define+SIMULATION   # VCS, Xcelium
-DSIMULATION         # Verilator, Icarus
----

OCAH's own DV flows set it; a compile driven by an adopter's testbench does not.

[WARNING]
====
Do not let `SIMULATION` reach synthesis, formal, or a gate-level flow. It
enables `initial` blocks, `$readmemh`, `$random` and DPI exports; a tool that
skips those rather than rejecting them yields a netlist that does not
correspond to the RTL you verified.
====

Without the define, these testbench hooks are not compiled in and the plusargs
are silently ignored:

[cols="<40%,<60%",options="header"]
|===
|Plusarg |Effect

|`+skip_fuse_sense`
|`efuse_shadow_regs` reports fuse sense complete immediately rather than
sensing the bank through the adopter's SHIM.

|`+smc_shadow_reg_preload=<file>`,
`+sep_shadow_reg_preload=<file>`
|Loads the shadow registers from a hex image. Takes effect only alongside
`+skip_fuse_sense`.

|`+rom_bin64=<file>`, `+rom_hex=<file>`
|Preloads `OCAH4CORECluster_rom_ext`, the SMC CPU ROM simulation model. Applies
only to integrations that use the reference memory swaps.
|===

The define also zeroes the RMA and security-disable token and digest bits in
`efuse_token_processing` at time 0, which have no reset and otherwise power up
X, and routes OpenTitan assertion failures in the SEP `prim_assert` shim to
`$error` on non-UVM runs.

Two model families it enables make simulation deliberately non-deterministic:
`prim_flop_2sync` and its Caliptra and Adams Bridge equivalents insert
`prim_cdc_rand_delay` ahead of the synchronizer, and
`prim_lfsr` and `prim_double_lfsr` randomize their default seed on simulators
other than Verilator (`+prim_lfsr_use_default_seed=1` pins it). Two runs of one
test are therefore not identical unless the simulator seed is fixed; record the
seed with any failure you intend to reproduce.
