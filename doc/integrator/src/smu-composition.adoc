[[smu-composition]]
= SMU Composition and Internal Wiring

The System Management Unit (SMU) combines the SMC, DTP, and optionally the
SEP into a unified subsystem. The interface descriptions in the preceding
sections apply directly when integrating the SMU, since the SMU inherits all
three subsystems' ports. This section covers the module variants available to
adopters, how the SMU wires its subsystems together internally, and what
additional configuration it exposes.

[[smu-module-variants]]
== Module Variants and IP Integration

OCAH core modules (`smc.sv`, `sep.sv`, `dtp.sv`, and the composite `smu.sv`)
expose logic-level interfaces only. All technology-specific components -- PLLs,
PVT sensors, eFuse shims, memory macros, GPIO padrings, SPI controllers, and
external TRNG -- are instantiated outside the core modules by the adopter. This
separation keeps the OCAH deliverable technology-neutral.

The figure below shows that boundary. `smu` exposes a technology integration
interface for each of these components, and a reference integration module
holds the shims, models and macros behind them. An adopter keeps the interfaces
and replaces what lies below the boundary with its own technology IP.

.SMU Technology Integration
image::smu-technology-integration.svg[SMU Technology Integration,scaledwidth=100.0%]

The repository provides reference wrappers that demonstrate how to bridge the
gap between OCAH core interfaces and adopter-specific IP:

* `smu_wrapper.sv` wraps `smu.sv` with pad-level signal handling for clocks,
  resets, GPIO, eFuse, and JTAG interfaces. It internally instantiates
  `smc_ip_integration.sv` for SMC-related vendor IP and
  `sep_ip_integration.sv` for SEP-related vendor IP. Each integration module
  holds its own eFuse interface shim and eFuse bank.
* `smc_wrapper.sv` provides an equivalent reference wrapping `smc.sv` alone,
  useful when integrating the SMC without the DTP/SEP subsystems.

Neither the wrappers nor the IP integration modules are part of the OCAH
deliverable; they exist as integration guides. Adopters must develop their
own equivalents following the interface
patterns demonstrated in these modules. The interface contracts at the module
boundaries ensure technology substitution without modifying the verified OCAH
logic.

The figure below illustrates the relationship between the OCAH core modules, the
wrapper layer, and the IP integration modules.

.SMU Integration Components
image::smu-integration-components.svg[SMU Integration Components,scaledwidth=100.0%]

=== IP Integration Modules

`smc_ip_integration.sv` demonstrates integration of SMC-side technology
components: PLL wrappers (generating `pll_cgm_clk_o` and `pll_awm_clk_o`),
PVT sensor interfaces, eFuse shims, GPIO padring logic, memory macros (ROM,
scratchpad RAM, cache tag and data arrays), and trace memory instances.

`sep_ip_integration.sv` demonstrates integration of SEP-side technology
components: SEP memory macros (TCM, scratch SRAM, boot ROM, OTBN IMEM/DMEM,
Key Manager ROM/SRAM), eFuse shim, external TRNG, and SPI controller selection.

=== Wrapper Clock Architecture

The behavioral `pll_wrap` model is a DV/reference
placeholder: it free-runs refclk, sys_clk, and periph_clk at 100 / 800 / 200 MHz
(`+pll_sys_period_ns=10` runs sys_clk at 100 MHz; with `+pll_osc_bench` a bench
toggles the oscillator nets itself), muxes sys and periph with ref
through `prim_clock_mux2` then `prim_ag_clk_mux`, and terminates the AXI-Lite PLL
control interface with OKAY. It is not a synthesis stand-in. An adopter who
replaces `smc_ip_integration` supplies equivalent clocks internally; the
bare cores still have the three clock inputs.

== Clock and Reset Architecture

Connect `clk_smu_i` to the primary system clock and `clk_ref_i` to a stable
reference source. The DTP operates on TCK for JTAG logic and on the system clock
for cross-trigger and AXI bridges. Reset sequencing follows the SMC flow; the
DTP JTAG state machine uses `pwr_on_rst_ni`, which the SMU connects to
the SMC `powergood_stable` output. The SMU internally connects DTP debug paths to the SMC and
optionally instantiates the SEP when the `SEP` parameter is set to 1. The full
interconnection details are described in <<smc-dtp-interconnection>> and
<<sep-conditional-wiring>> below.

[[smu-axi-xbar-address-map]]
== SMU AXI Crossbar Address Map

Inside the SMU, the `smu_axi_xbar` module routes traffic between three
AXI4 manager/subordinate pairs: the SEP outbound master (`sep_out`),
the SMC outbound master (`smc_out`), and the external SMU AXI input
(`ext_in` / `smu_axi_in`). The corresponding targets are the SEP and
SMC inbound subordinates, and the external SMU AXI output
(`ext_out` / `smu_axi_out`).

ifdef::backend-html5[]
Connectivity is described in
xref:ocah-docs:ROOT:architecture.adoc#smu-axi-crossbar[SMU AXI Crossbar];
the split between hardware-fixed behaviour and firmware-programmable apertures
is documented in
xref:ocah-docs:ROOT:architecture.adoc#ocah-memory-map[OCAH Memory Map].
endif::backend-html5[]
ifdef::backend-pdf[]
See the _SMU AXI Crossbar_ and _OCAH Memory Map_ sections of the Technical
Reference Manual for connectivity and the responsibility split between
hardware-fixed and firmware-programmable apertures.
endif::backend-pdf[]

The crossbar uses a *runtime* address map with two rules, the SEP and
SMC apertures, both programmable at runtime. `ext_out` has no address
rule. The apertures are driven as follows:

* `sep_global_base_addr_i` / `sep_region_size_i` come from the
  `sep_cpu_ctrl` CSRs `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`,
  exposed at both the `sep.sv` and `smu.sv` boundaries as
  `sep_global_base_addr_o` / `sep_region_size_o` (both 56-bit).
  `SEP_REGION_SIZE` is a 32-bit CSR field, zero-extended to 56-bit at
  the SEP system CSR; the xbar input takes only the lower 32 bits.
  `SEP_REGION_SIZE` defines the SEP global/chiplet aperture for SMU
  routing and SEP inbound global-to-local remap. It is distinct from the
  SEP CPU's architectural local-alias span. `SEP_REGION_SIZE` currently
  resets to `0x0100_0000` (16 MiB). Tied to `'0` at the `smu.sv`
  boundary when the `SEP` parameter is `0`.
* `smc_global_base_addr_i` / `smc_region_size_i` come from the SMC CPU
  control CSRs `GLOBAL_BASE` / `REGION_SIZE`, exposed at both the
  `smc.sv` and `smu.sv` boundaries as `smc_global_base_o` (56-bit) /
  `smc_region_size_o` (32-bit). `REGION_SIZE` resets to `0x0100_0000`
  (16 MiB).

SEP, SMC, and `smu_axi_xbar` all run on `clk_smu_i`, so these
quasi-static CSR fields need no clock-domain crossing. The crossbar's
address arithmetic is done on 57-bit widened sums. For where unmatched
requests go, and which requests return `DECERR`, see
ifdef::backend-html5[]
xref:ocah-docs:smu:index.adoc#smu-axi-crossbar-routing-table[SMU AXI crossbar routing].
endif::backend-html5[]
ifdef::backend-pdf[]
the SMU AXI Crossbar section of the Technical Reference Manual.
endif::backend-pdf[]

[[smu-firmware-programming-order]]
=== Firmware programming order

Firmware must program `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE` and
SMC `GLOBAL_BASE` / `REGION_SIZE` during early boot, *before any
cross-subsystem AXI traffic is issued*, and must ensure the two
apertures do not overlap and both fall within the chiplet-visible SMU
envelope assigned by the integrator. The SMU crossbar does not itself
constrain envelope size.

ifdef::backend-html5[]
See xref:ocah-docs:ROOT:architecture.adoc#ocah-memory-map[OCAH Memory Map] for
the responsibility split between integrator, firmware, and the internal SEP/SMC
address maps.
endif::backend-html5[]
ifdef::backend-pdf[]
See the _OCAH Memory Map_ section of the Technical Reference Manual for that
responsibility split.
endif::backend-pdf[]

== SMU Default Parameters

The DTP JTAG features, identification, cross trigger, and pipeline depths are
fields of the `CFG` parameter, of type `smu_pkg::smu_cfg_t` with default
`smu_pkg::DefaultCfg`.

ifdef::backend-html5[]
The parameters of `smu` are listed in xref:ocah-docs:ROOT:rtl-modules-reference/sys/smu/smu.adoc[smu].
endif::backend-html5[]
ifndef::backend-html5[]
The parameters of `smu` are listed in the HTML edition of the Technical Reference Manual, under RTL Modules Reference.
endif::backend-html5[]

SEP-related DTP configuration is not exposed as an SMU config-struct field.
The SMU derives SEP debug/STAP enablement from the module parameter `SEP` and
wires the corresponding DTP interfaces internally to the SEP block when `SEP=1`.

[[ic-reset-tdr-structure]]
== IC_RESET TDR Structure

The DTP primary TAP implements the IEEE 1149.1-2013 §17 IC_RESET TDR as three
independently enabled slices plus a single `reset_hold` bit nearest TDO. At the
SMU the scan order from TDI to TDO is:

[source]
----
TDI → SMC slice → SEP slice → external slice → reset_hold → TDO
----

The SMU enables the SMC slice unconditionally, the SEP slice when `SEP=1`
(otherwise that slice has width 0 and is omitted), and the external slice when
`JTAG_IC_RESET_ENABLE` is set. Each slice is a packed struct with `.ovrd` and
`.val` halves of equal width; `jtag_ptap` sizes the slice from `$bits(type)/2`.
Each port has the reset-enable and reset-control pair IEEE §17 requires, with
`reset_enable` nearer TDO. `.val` carries `reset_control`, and `.ovrd` carries
the inverse of `reset_enable`. Declaration order within each half is the TDI-to-TDO
scan order: the first field is nearest TDI.

[cols="<18%,<12%,<28%,<42%",options="header"]
|===
|Slice |Ports |Defined by |Consumed by
|SMC |68 |OCAH (`smc_pkg::jtag_smc_reset_ctrl_t`) |SMC reset unit; SMU-internal, no SMU port
|SEP |8 when `SEP=1`, else 0 |OCAH (`sep_pkg::jtag_sep_reset_ctrl_t`) |SEP reset controller; SMU-internal, no SMU port
|External |`$bits(ic_reset_ext_t)/2` |Adopter (`ic_reset_ext_t`) |SMU output `jtag_ic_reset_ext_o`
|`reset_hold` |1 bit |IEEE 1149.1 §17 |Nearest TDO; not a reset port
|===

The TDR length is `2 * (SMC ports + SEP ports + external ports) + 1`. Programming
order and `reset_enable` polarity are in the DTP JTAG chapter of the Technical
Reference Manual.

=== SMC slice (TDI to TDO)

The SMC slice covers the SMC reset domains and the 32 managed-subsystem (SS)
cold and warm resets. Vector index `[31]` of each SS field is nearer TDI than
`[0]`.

[cols="<35%,<65%",options="header"]
|===
|Port |Reset domain
|`ss_warm_reset_n[31:0]` |Per-subsystem warm reset
|`ss_cold_reset_n[31:0]` |Per-subsystem cold reset
|`cold_reset_n` |SMC cold reset
|`cool_reset_n` |SMC cool reset
|`warm_reset_n` |SMC warm reset
|`fuse_reset_n` |Fuse reset (nearest the SEP slice)
|===

=== SEP slice (TDI to TDO)

When `SEP=1` the SEP slice covers the SEP main reset and the crypto, Key
Manager, and TRNG resets consumed by `sep_reset_ctrl`. `abr_jtag_rst_n` is
nearest TDI.

[cols="<35%,<65%",options="header"]
|===
|Port |Reset domain
|`abr_jtag_rst_n` |Adams Bridge
|`trng_jtag_rst_n` |TRNG
|`sep_reset_n` |SEP main reset
|`kmac_jtag_rst_n` |KMAC
|`hmac_jtag_rst_n` |HMAC
|`aes_jtag_rst_n` |AES
|`otbn_jtag_rst_n` |OTBN
|`km_jtag_rst_n` |Key Manager (nearest the external slice)
|===

=== External slice (adopter-defined)

The external slice is reserved for reset overrides on logic instantiated
outside the SMU. OCAH does not name its ports. Set the SMU type parameter
`ic_reset_ext_t` to a packed struct with `.ovrd` and `.val` halves of equal
width, and route `jtag_ic_reset_ext_o` to that logic. The parameter default
(`jtag_tap_pkg::jtag_ic_reset_default_t`) is a single-override stub. Clear
`JTAG_IC_RESET_ENABLE` when no external overrides are required.

Declare a new external override at each half's MSB so already-assigned TDR
positions do not shift. Extra subsystem reset controls beyond the SMC slice
use this typed port.

=== Cross Trigger Matrix Interface

[cols="<30%,<10%,<20%,<40%",options="header"]
|===
|Port |Direction |Width |SMU Connection

|`xtrig_ctm_src_req_o` |output |[XTRIG_NUM_INT_CT-1:0] |SMC-reserved DTP lanes stay inside the SMU; remaining lanes are the SMU external port
|`xtrig_ctm_src_ack_i` |input |[XTRIG_NUM_INT_CT-1:0] |SMC-reserved DTP lanes tied off; remaining lanes are the SMU external port
|`xtrig_ctm_dst_req_i` |input |[XTRIG_NUM_INT_CT-1:0] |SMC-reserved DTP lanes from SMC `xtrigger_ss_o`; remaining lanes are the SMU external port
|`xtrig_ctm_dst_ack_o` |output |[XTRIG_NUM_INT_CT-1:0] |SMC-reserved DTP lanes unused; remaining lanes are the SMU external port
|===

The low `smu_pkg::XTRIG_SMC_INT_CT_LANES` DTP internal-CT lanes are reserved for
SMC (both bits of `xtrigger_ss_o`). The SMU exposes the remaining DTP lanes, so
the SMU `XTRIG_NUM_INT_CT` field is that many less than DTP's. The SMC uses
pulse-synchronization mode, so ack signals for the reserved lanes are unused:
the DTP `xtrig_ctm_src_ack_i` reserved slice is tied to `'0` and
`xtrig_ctm_dst_ack_o` reserved bits are left unconnected. The usage of ack
signals depends on the `XTRIG_INT_CT_MODE` parameter: when a mode bit is 0
(pulse synchronization), the corresponding ack is unused; when 1 (req/ack
handshaking), the ack must be connected to the cross trigger endpoint.

The remaining DTP `xtrig_ctm_src_ack_i` lanes (exposed as SMU
`xtrig_ctm_src_ack_i[XTRIG_NUM_INT_CT-1:0]`) are ported out through the SMU.
The integrator should tie off to `'0` when using pulse-sync mode
(`XTRIG_INT_CT_MODE` bit = 0), or connect to actual ack signals when using
req/ack mode (bit = 1).

== SMU Port Interface

The SMU exposes a single consolidated boundary that an adopter connects to
at the chip or chiplet level. The following table defines all SMU top-level
ports including clock, reset, JTAG, cross trigger, SMC-originated interfaces
(AXI, GPIO, eFuse, PLL, PVT, memory), and SEP passthrough interfaces
(memory macros, eFuse, crypto SRAM, SPI, AXI extension). Ports prefixed
with `sep_` are only active when the module parameter `SEP=1`.
