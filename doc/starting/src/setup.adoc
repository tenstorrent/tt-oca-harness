= Environment Setup

====
This document is currently under development.

== Repository

To clone the repository, ensure that you have `git` installed (`sudo apt install git`), and then run the following commands:

```bash
git clone https://github.com/tenstorrent/tt-oca-harness.git

cd tt-oca-harness
```

The repository's open RTL, documentation, register generation, lint, and
containerized firmware flows do not require submodules. The production SEP boot
manifest tooling is an optional submodule that requires separate access; do not
use `--recursive` for the public setup path.

== Toolchain access

Most OCAH workflows require a RISC-V cross-compiler, EDA tools (Yosys, Verilator,
Slang, Verible), and documentation tools (Antora, Asciidoctor). There are three
ways to get these:

[cols="1,3",options="header"]
|===
| Method | Summary

| <<container,*Container (recommended)*>>
| A Nix-built container image bundles all EDA and firmware tools. No individual
  tool installs needed beyond a container engine (Podman or Docker). This is the
  primary supported method for the initial release.

| <<native,*Native*>>
| Install each tool individually on the host. Gives the most control but requires
  the most setup. The remainder of this page documents the native path; see
  xref:dependencies.adoc[Dependencies] for version requirements.

| <<nix-shell,*Nix dev shell*>>
| `nix develop` provides the same tool set as the container, directly on the host,
  via the Nix package manager. Available but not first-class supported — useful on
  NixOS or hosts that already have Nix installed.
|===

[[container]]
== Container (recommended)

The container is the primary toolchain access method for the initial release. It
is built from the Nix flake in this repository — there is no pre-built image to
pull from a registry; `docker-run.sh` builds it locally on first use.

The container bundles:

* RISC-V cross-compiler (`riscv64-unknown-elf-gcc` + picolibc) — making a native
  RISC-V toolchain install optional for firmware workflows
* `yosys` + `yosys-slang` for synthesis
* `slang`, `verilator`, `verible` for lint
* `antora` for documentation

Tools that must be installed natively even when using the container: Python /
`uv` (for register generation and DV Python tooling), `bender` (IP dependency
management), and `git`.

=== Container engine setup

Install a container engine (Podman or Docker):

- https://podman.io/docs/installation#ubuntu[*Podman*] (recommended)
- https://docs.docker.com/engine/install/ubuntu/[*Docker*]

If you installed Podman, also install `fuse-overlayfs` and register the Docker
Hub registry:

```bash
sudo apt install -y fuse-overlayfs

sudo mkdir -p /etc/containers/registries.conf.d
cat <<'EOF' | sudo tee /etc/containers/registries.conf.d/docker.conf
unqualified-search-registries = ["docker.io"]
EOF
```

=== Using the container

All container interaction goes through `scripts/docker-run.sh`. The image is
built automatically on first use:

```bash
# Open an interactive shell (builds the image if needed)
./scripts/docker-run.sh shell

# Run a command inside the container
./scripts/docker-run.sh run make dv-fw-tests TARGET=smc

# Run with 1:1 host paths (needed for workflows using absolute paths)
./scripts/docker-run.sh run-here make ocah-synth-yosys-all
```

To pre-build the image explicitly (e.g. before going offline):

```bash
./scripts/docker-run.sh build
```

[[native]]
== Native Installation
=== Python

We recommend the use of pyenv to ensure the correct version of python is in use.
To install pyenv, visit https://github.com/pyenv/pyenv[their GitHub page],
or run `curl https://pyenv.run | bash`.

[WARNING]
====
The piping of a script from the internet as above, without checking it, is never safe.
You should always check the contents of the script first to guarantee safety.
This may be done using `curl https://pyenv.run`, which will print the script,
instead of running it.
====

To install Python 3.11 with pyenv, first install the https://github.com/pyenv/pyenv/wiki#suggested-build-environment[python build dependencies], and then Python 3.11 itself:

```bash
# Check Pyenv GitHub for up-to-date build environment
sudo apt update
sudo apt install make build-essential libssl-dev zlib1g-dev \
libbz2-dev libreadline-dev libsqlite3-dev curl git \
libncursesw5-dev xz-utils tk-dev libxml2-dev \
libxmlsec1-dev libffi-dev liblzma-dev libzstd-dev

pyenv install 3.11
```

From here, enter a pyenv shell, and install `uv` using the following commands:

```bash
pyenv shell 3.11

# In the shell
pip install uv
```

=== Package Dependencies

Once the repository is cloned, install the required open source tools:

```bash
sudo apt install asciidoctor asciidoctor-pdf verilator gcc \
ccache picolibc-riscv64-unknown-elf cmake
```

Follow the instructions on the following pages for tools not packaged within Ubuntu:

- https://docs.antora.org/antora/latest/install-and-run-quickstart/[*Antora*]
- https://github.com/pulp-platform/bender[*Bender*]
- https://github.com/chipsalliance/verible[*Verible*]
- https://github.com/MikePopoloski/slang[*Slang*]
- https://github.com/YosysHQ/yosys[Yosys] (Also packaged via `apt`, but newer version recommend)
-- https://github.com/povik/sv-elab[SV-Elab] (Formerly Yosys-Slang) Required to allow Yosys to synthesise SystemVerilog
- https://surfer-project.org/[*Surfer*] (optional, alternatives available, used for wave trace debugging)
- https://www.drawio.com/[*Drawio*] (optional, used for creating new diagrams for documentation)
- https://github.com/wavedrom/wavedrom.github.io/releases[*Wavedrom*] (optional, used for creating new diagrams for documentation)

Enter the repository and use the following command to set up the Python environment:

```bash
uv sync # or `make uv-sync`
```

[[nix-shell]]
== Nix dev shell (available, not first-class supported)

If you have https://nixos.org/download/[Nix] installed, the dev shell provides
the same tool set as the container directly on the host — no container engine
needed:

```bash
nix develop    # activates the dev shell; tools are then available on PATH
```

With https://github.com/direnv/direnv[direnv] configured, the shell activates
automatically on `cd` into the repo.

[NOTE]
====
The Nix dev shell is not first-class supported for the initial release. It works
well on NixOS and Linux hosts with Nix installed, but may have edge cases on
other platforms. The container is the recommended path.
====
