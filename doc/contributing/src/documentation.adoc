=== Document formats

OCAH primarily uses AsciiDoc (.adoc) for structured documentation.

Native README files in GitHub which are intended to be read in isolation are written in Markdown (.md)

This approach provides:

* GitHub-native rendering for README files
* Professional documentation rendering with Asciidoctor for detailed specs
* Human readable document source text that can be revision controlled
* Multiple output formats (PDF, HTML) with cross-referencing
capabilities

=== Updating documentation

Documentation is authored in AsciiDoc.  In most cases it is built in two formats:
- Using Antora for the HTML site
- Using asciidoctor-pdf for downloadable PDFs

Material specific to the website may not be built as downloadable PDFs

Documents are published in GitHub Pages at [https://tenstorrent.github.io/tt-oca-harness/](https://tenstorrent.github.io/tt-oca-harness/)

Document updates are made by pushing changes to `main`.
The CI process deploys to the published site on all pushes to `main` (see `.github/workflows/doc.yml`).

=== Build Process

Documentation may also be built locally for development.

To avoid the need to install local tools, the toolchain is included as container images.
The two commands below may be executed from the root of the checked out repository.  They generate the built material in subfolders under each book.

```bash
scripts/docker-run.sh doc-html all    # HTML site → doc/XXXX/_build/html_antora/
scripts/docker-run.sh doc-pdf  all    # PDF       → doc/XXXX/dist/ocah-trm.pdf
```

Once the documents are built they can be staged with the command below.
This builds the site in the location shown.
```bash
scripts/docker-run.sh doc-stage       # site → doc/_build/html_antora
```

The build can then be served locally for viewing
```bash
cd doc/_build/html_antora
python3 -m http.server
```

=== Embedding Images

All images are stored in the repository at `doc/trm/assets` regardless of which document they
appear in.  This allows images to be reused across documents without requiring a copy for each
document.

Images are copied to the `assets` directory of every document as part of the build process.

Any image can then be embedded in an Asciidoc document with:

```
image::<my_image>.png[Alternative Text]
```

=== Creating Diagrams

Diagrams are most easily created using the DrawIO program. Generate SVG
files and embed them directly in the AsciiDoc document.

Timing diagrams are created with the Wavedrom program. The interactive
application makes it easy to create the JSON source files and edit them
while the CLI version of the application is used to create the output
SVG files that are embedded in the AsciiDoc document.

Install Wavedrom waveform generator and viewer:

```
pip3 install wavedrom

sudo npm install -g wavedrom  # for the interactive editor

sudo npm install wavedrom-cli -g # for the CLI application
```

The editor is launced with `wavedrom-editor` or directly from the
website. Save the JSON source file for the figure and generate the SVG
rendering as follows:

```
wavedrom-cli -i mywaveform.json5 > mywaveform.svg
```

Then embed the SVG figure into the AsciiDoc document.
