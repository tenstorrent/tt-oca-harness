=== Build with Bender and Make

Bender is used for managing IP dependencies and managing builds.

Makefiles will be used for build automation. We have previously
considered other flow such as Bazel but are hesitant to take on extra
complexity.

To initialise or update the Bender-generated file list, run the following
command:

```bash
make generate_filelist
```

=== Simulation and Testing

We will use open source tools as much as possible and hence will focus
on using Verilator for unit tests. Verilator has comprehensive
SystemVerilog (SV) support and is widely used in industry.

==== Testbench and Test Sequence

Most components use Cocotb Python tests. The DTP also has a nonfree UVM
test workflow using VCS. The testbench is run and configured using a Python
script. Run the following command to see all available options:

```bash
./tools/dv/run_dv.py --help
usage: run_dv.py [options]

Native OSS DV/FV launcher for listing DUTs, validating configs, and running simulation or formal flows.

options:
...
```

If you want to manage python dependencies yourself, rather than through `uv`, the environment variable `OCAH_DV_SKIP_UV=1`
may be set, in which case the system Python installation will be used.

To check that all testsuites are configured properly, run the following:

```bash
./tools/dv/run_dv.py --validate-configs
```

Having selected a Device to Test with the `--dut` flag, use `--list` to
print the available tests and testlists for the device.

```bash
./tools/dv/run_dv.py --dut sep --list
name       : sep
kind       : dv
framework  : cocotb
root       : hw/sys/sep/dv
tools      : verilator, xcelium, vcs

stages     : ...
tests      : ...
groups     : all=... cpu=... no_cpu=... sanity=...
```

To run an individual set of tests, list them using the `--items` flag.

```bash
./tools/dv/run_dv.py --dut smc_wrapper --items octs_sanity_test smc_axil_idle_test
...
```

This may similarly be used to run preconfigured test groups.

Further options, including seeds and regressions are available, consult the `--help`
flag to see usage.

==== Visual Debugging and Waveform Viewer

When debugging particularly difficuly RTL issues, it is useful to be able to view the signals
travelling between components. For this, a wave trace may be generated and inspected. To
generate a trace, use the `--waves` argument.

```bash
./tools/dv/run_dv.py --waves ...
...
```

We use https://surfer-project.org/[Surfer] for viewing wave traces, but if you prefer a
different program, the program suggested may be overridden with `--wave-viewer-binary`.

To automatically open your chosen viewer on test completion, use the `--open-waves` flag.

The `--waves-on-fail` flag may be used instead of `--waves`, to only generate wave traces for failing tests.

=== Linting

We use linters within the development of OCAH to perform static analysis
on the codebase. The below rules will check code for errors and poor
formatting. They also enforce a consistent code style.

==== Verilog Style and Lint checking with Verible

To run the verible linter on all SystemVerilog files, use the following command:

```bash
make lint-sv-verible
```

To apply the verible formatter, use the following:

```bash
make format-sv
```

The need for the above may be checked with `make format-sv-check`.

==== Verilog Linting with Verilator

Verilator structurally lints each discovered hardware block as its own top:

```bash
make lint-verilator-all
```

Use `BLOCK=<block>` to restrict the run, for example
`make lint-verilator-all BLOCK=sep`.

==== Verilog Style and Lint checking with Slang

To run the slang linter on all SystemVerilog files, use the following command:

```bash
make lint-slang-all
```

==== TCL Script Style, Lint and Format with Tclint

To lint the TCL scripts in the repository, we use the package `tclint`.
The repository's uv environment supplies both tclint and tclfmt.

To lint, use the following command:

```bash
make lint-tcl
```

To then run the formatter and style checker, use the following, whose changes may first be checked with `make format-tcl-check`:

```bash
make format-tcl
```

==== C/C++ Style and Format with Clang-Format

The C/C++ Firmware files included in each component are checked and formatted with `clang-format`.
The repository's uv environment supplies the pinned clang-format version.

```bash
make format-c
```

To check for errors without modifying files, use `make format-c-check`.

==== Python Lint and Format with Ruff

Ruff lints and formats first-party Python while excluding generated register
models, vendored sources, submodules, `nonfree/`, and build output.

```bash
make lint-python
make format-python-check
```

To apply safe lint fixes and formatting locally, run:

```bash
make lint-python-fix
make format-python
```

Pass `PYTHON_PATH=<path>` to restrict any command to part of the tree.

==== Optional Pre-Commit Checks

The optional pre-commit hook runs check-only Ruff, clang-format, tclfmt, and
tclint operations on staged files. Enable it explicitly with
`make hooks-install`; use `make hooks-uninstall` to remove it. The installation
writes the standard local Git hook, does not change `core.hooksPath`, and is
never performed by repository setup or checkout flows. See
`CONTRIBUTING.md` for all hook commands.
