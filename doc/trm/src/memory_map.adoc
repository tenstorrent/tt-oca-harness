= OCAH Memory Map
:description: The chiplet-visible SMU aperture and the SEP/SMC global apertures firmware programs.

[[ocah-memory-map]]

OCAH separates the chiplet-visible SMU aperture from the internal address
maps used by SEP and SMC firmware. The chiplet integrator decides which
system address range reaches the SMU external AXI input. Firmware then
programs the SEP and SMC global base/size CSRs so the SMU crossbar can
route incoming traffic to the correct inbound port.

<<ocah-address-map-configuration-layers-table>> distinguishes the chiplet envelope,
programmable apertures, and internal address maps.

[[ocah-address-map-configuration-layers-table]]
[cols="<24%,<24%,<32%,<20%",options="header"]
.OCAH address-map configuration layers
|===
|Concept |Configured by |Purpose |Example

|Chiplet NoC envelope
|Integrator / chiplet address map
|Controls which external-master addresses reach SMU `ext_in`
|Example only: 64 MiB total SMU aperture

|SEP global aperture
|SEP firmware via `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`
|Controls SMU `ext_in` to `sep_in` routing and SEP inbound global-to-local remap
|Example only: 32 MiB SEP slot in a 32 MiB + 32 MiB SEP/SMC partition

|SMC global aperture
|SMC firmware via `GLOBAL_BASE` / `REGION_SIZE`
|Controls SMU `ext_in` to `smc_in` routing and SEP-to-SMC decode
|Example only: 32 MiB SMC slot in a 32 MiB + 32 MiB SEP/SMC partition
|===

External masters use chiplet-global addresses and are bounded first by the
chiplet NoC decode. The SMU crossbar applies the firmware-programmed SEP and
SMC global apertures to route those transactions to `sep_in` or `smc_in`.
Subsystem-internal CPU maps and local aliases are described in the SEP and SMC
chapters.

At reset, `SEP_GLOBAL_BASE_ADDR` is `0x0000_0000` and the SMC's
`GLOBAL_BASE` register is `0x4000_0000`. Their separate size registers,
`SEP_REGION_SIZE` and SMC `REGION_SIZE`, both reset to `0x0100_0000`
(16 MiB). The corresponding half-open address ranges are therefore
`[0x0000_0000, 0x0100_0000)` for SEP and
`[0x4000_0000, 0x4100_0000)` for SMC.

The global base addresses and region sizes are software-programmed and must
not overlap. The hardware does not derive them from a chiplet ID. The
Programmer's Guide gives the
ifdef::backend-html5[]
xref:ocah-programmer-guide::index.adoc#sep-smc-address-remapping[aperture programming sequence]
endif::backend-html5[]
ifdef::backend-pdf[]
https://docs.tenstorrent.com/tt-oca-harness/ocah-programmer-guide/latest/index.html#sep-smc-address-remapping[aperture programming sequence]
endif::backend-pdf[]
for early boot.

Register tables throughout this manual report each field's software access as a
compact token in their *Access* column; xref:register-field-access.adoc#trm-register-field-access[Register Field Access Notation]
decodes that notation.

[[ocah-decode-response-codes]]
== Decode Response Codes

The SMC, SEP, Key Manager and cross-trigger network address maps state, for
each unit, how a 32-bit access that no register or memory backs is answered.
A cell reads _read response, read data / write response_, for example
`DECERR, 0xBADCAB1E / DECERR`. `OKAY`, `SLVERR` and `DECERR` are the AXI
response codes returned on `RRESP` and `BRESP`.
The read data is the word a 32-bit read returns in either half of a 64-bit
data bus. Where the two halves differ, a note on the cell gives the word
returned when address bit 2 is set.

* The _Hole in Extent_ column covers an unbacked offset inside the unit's
  decoded extent.
* The _Past Extent_ column covers the rest of the unit's aperture, the range
  its Size column gives.
* A `Reserved` row is an address between unit apertures.

The fabric routes each register block a window, the addresses it passes to
that block, and inside its window a block answers for itself. The fabric is
the subsystem crossbars and, inside a unit, the demultiplexer or crossbar that
routes between the unit's register blocks.

Windows follow one rule in the cross-trigger network and in the SMC, apart from
the eFuse blocks, the units inside the CPU cluster and the external window.
The SMC crossbars route
each register target whole 4 KiB pages, so an AXI burst, which never crosses a
4 KiB boundary, stays on one target. Inside a page, and in the cross-trigger
network's register space, a window is a power of two in size and starts at a
multiple of its size, so a decoder compares only the address bits above the
window:

* A block alone in its page has the whole page.
* A block that shares a page has the space up to the next block or, if it is
  the last block, the window its register block decodes.
* Each instance of an array has its stride.
* A vendored block has the window its own decoder implies.

A register block generated from SystemRDL answers an access that reaches it as
follows:

* An offset between its registers answers `OKAY`: a read returns 0 and a write
  has no effect.
* An offset past the end of its last register answers `SLVERR` with read data 0.
  That end is a multiple of the block's register width, so an access wider than
  the registers that runs past it, such as a 64-bit read of the last register of
  a block with 32-bit registers, answers `SLVERR`.

A block instantiated as an array at a stride wider than one instance, such as
the alias remap regions, the traffic filter entries, the GPIO interfaces and the
cross-trigger ports, answers `OKAY` at every offset, so the padding between
instances behaves as a hole; past its last instance, the fabric answers
`DECERR`. An array of whole controllers, such as the I2C controllers, answers
`SLVERR` in its padding instead.

A vendored block keeps the responses of its own decoder. At an offset with no
register, the PWM core and the other blocks that keep their OpenTitan register
interface, such as the SEP OTBN, HMAC and KMAC, answer `SLVERR` with read data
`0xFFFFFFFF`, and the register file of the SMC DMA controller answers `OKAY`
with read data `0xFFFFFFFF`.

Where the parts of a wrapper answer differently, the _Hole in Extent_ cell
names each part:

* `between sub-blocks` is space in the wrapper that no sub-block's window
  holds, which the fabric answers with `DECERR`.
* `past sub-block registers` is a sub-block's window past its last register.
  Where the sub-blocks of one wrapper answer there differently, the cell names
  each instead, as `past <instance> registers` with the sub-block's instance
  name in the wrapper's SystemRDL, as in the SMC PWM row.
* `between instances` is the padding after each element of an array. It
  answers as the array does, or `DECERR` for an array of wrappers such as the
  UART instances, where each wrapper's own demultiplexer answers.

[[ocah-decode-response-codes-table]]
.Decode response codes
[cols="<24%,<76%",options="header"]
|===
|Code |Meaning

|`OKAY`
|The access completes. A read returns the listed data, and a write has no
effect.

|`SLVERR`
|The access reaches a component that refuses it. With read data 0, that
component is a register block with no register at the offset.

|`DECERR`
|No window holds the address, so the fabric refuses the access before it
reaches a unit or sub-block. The read data is `0xBADCAB1E`.

|Aliases registers
|The access reaches a live register at another offset, which answers it.

|Forwarded
|The subsystem passes the access on without decoding it, and its target
answers.

|Adopter-defined
|The adopter's implementation answers.

|`-`
|The region does not exist: the unit is memory, its registers fill its
extent, or its aperture ends at its extent.
|===
