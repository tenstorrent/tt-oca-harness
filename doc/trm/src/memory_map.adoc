= OCAH Memory Map
:description: The chiplet-visible SMU aperture and the SEP/SMC global apertures firmware programs.

[[ocah-memory-map]]

OCAH separates the chiplet-visible SMU aperture from the internal address
maps used by SEP and SMC firmware. The chiplet integrator decides which
system address range reaches the SMU external AXI input. Firmware then
programs the SEP and SMC global base/size CSRs so the SMU crossbar can
route incoming traffic to the correct inbound port.

<<ocah-address-map-configuration-layers-table>> distinguishes the chiplet envelope,
programmable apertures, and internal address maps.

[[ocah-address-map-configuration-layers-table]]
[cols="<24%,<24%,<32%,<20%",options="header"]
.OCAH address-map configuration layers
|===
|Concept |Configured by |Purpose |Example

|Chiplet NoC envelope
|Integrator / chiplet address map
|Controls which external-master addresses reach SMU `ext_in`
|Example only: 64 MiB total SMU aperture

|SEP global aperture
|SEP firmware via `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`
|Controls SMU `ext_in` to `sep_in` routing and SEP inbound global-to-local remap
|Example only: 32 MiB SEP slot in a 32 MiB + 32 MiB SEP/SMC partition

|SMC global aperture
|SMC firmware via `GLOBAL_BASE` / `REGION_SIZE`
|Controls SMU `ext_in` to `smc_in` routing and SEP-to-SMC decode
|Example only: 32 MiB SMC slot in a 32 MiB + 32 MiB SEP/SMC partition
|===

External masters use chiplet-global addresses and are bounded first by the
chiplet NoC decode. The SMU crossbar applies the firmware-programmed SEP and
SMC global apertures to route those transactions to `sep_in` or `smc_in`.
Subsystem-internal CPU maps and local aliases are described in the SEP and SMC
chapters.

At reset, `SEP_GLOBAL_BASE_ADDR` is `0x0000_0000` and the SMC's
`GLOBAL_BASE` register is `0x4000_0000`. Their separate size registers,
`SEP_REGION_SIZE` and SMC `REGION_SIZE`, both reset to `0x0100_0000`
(16 MiB). The corresponding half-open address ranges are therefore
`[0x0000_0000, 0x0100_0000)` for SEP and
`[0x4000_0000, 0x4100_0000)` for SMC.

The global base addresses and region sizes are software-programmed and must
not overlap. The hardware does not derive them from a chiplet ID. The
Programmer's Guide gives the
ifdef::backend-html5[]
xref:ocah-programmer-guide::index.adoc#sep-smc-address-remapping[aperture programming sequence]
endif::backend-html5[]
ifdef::backend-pdf[]
https://docs.tenstorrent.com/tt-oca-harness/ocah-programmer-guide/latest/index.html#sep-smc-address-remapping[aperture programming sequence]
endif::backend-pdf[]
for early boot.

Register tables throughout this manual report each field's software access as a
compact token in their *Access* column; xref:register-field-access.adoc#trm-register-field-access[Register Field Access Notation]
decodes that notation.

[[ocah-decode-response-codes]]
== Decode Response Codes

The SMC, SEP, Key Manager and cross-trigger network address maps state how
each unit answers a 32-bit access that no register or memory backs. The
response depends on whether a component owns the address and, if one does, on
how that component decodes it. <<ocah-decode-response-codes-table>> gives the
three AXI response codes returned on `RRESP` and `BRESP`.

[[ocah-decode-response-codes-table]]
.Decode response codes
[cols="<24%,<76%",options="header"]
|===
|Code |Meaning

|`OKAY`
|The component that owns the address accepts the access. A read returns the
listed data and a write has no effect.

|`SLVERR`
|The component that owns the address refuses the access.

|`DECERR`
|No component owns the address, so the decoder in front of the components
refuses the access without passing it on.
|===

=== Address Ownership

The SMC and SEP crossbars give each register target whole 4 KiB pages. An AXI
burst never crosses a 4 KiB boundary, so every beat of a burst reaches one
target.

A register block alone in one of these pages owns the whole page, so every
address in the page past its last register answers `SLVERR`. A generated
register block gives that response itself. A vendored block decodes only part of
the page, and its wrapper answers the rest with `SLVERR` and read data
`0xBADCAB1E`.

Where several register blocks share a page, a demultiplexer splits the page
into one window per block. A window is an address range whose size is a power
of two and whose base address is a multiple of that size, for example `0x400`
bytes starting at offset `0x800`. The demultiplexer therefore matches a window
on the address bits above its low log~2~(size) bits alone, and those low bits
are the offset that the block decodes. An address outside every window has no
owner, and the demultiplexer answers it with `DECERR`.
Each element of an array counts as a block, and the windows are sized as
follows:

* Each element of an array owns the space up to the next element, the array's
  stride.
* A vendored block owns the window its own decoder implies.
* Any other block owns the space up to the next block or, if it is the last
  block, the window its register block decodes.

The cross-trigger network divides its own address map into windows by the same
rules. The eFuse blocks, the external window of each subsystem, the units
inside the SMC CPU cluster and the units behind the SEP crypto interconnect keep
their own decode.

=== Responses Inside a Window

A register block generated from SystemRDL answers an access in its window as
follows:

* Between its registers it answers `OKAY`: a read returns 0 and a write has no
  effect.
* Past its last register it answers `SLVERR` with read data 0. The registers end
  on a multiple of the register width, so an access wider than the registers
  that runs past the end also answers `SLVERR`. A 64-bit read of the last
  register of a block with 32-bit registers is one example.

An array element whose stride is wider than its registers answers `OKAY` across
its padding, as it does between registers. The alias remap regions, the traffic
filter entries, the GPIO interfaces and the cross-trigger ports work this way.
The I2C controllers, an array of whole controllers, answer `SLVERR` in their
padding instead.

NOTE: Holes between registers and the padding of an array answer `OKAY` so that
a register sweep can read every word up to the end of a block or array without
an error.

A vendored block keeps the responses of its own decoder at an offset with no
register. The PWM core and the other blocks that keep their OpenTitan register
interface, such as the SEP DMA controller, watchdog timer and SPI host, answer
`SLVERR` with read data `0xFFFFFFFF`. The register file of the SMC DMA
controller answers `OKAY` with read data `0xFFFFFFFF`, and the interrupt
controller in the SEP CPU answers `OKAY` with read data 0.

=== Reading the Map Cells

A cell reads _read response, read data / write response_, for example
`DECERR, 0xBADCAB1E / DECERR`. The read data is the word a 32-bit read returns
in either half of a 64-bit data bus. Where the two halves differ, a note on the
cell gives the word returned when address bit 2 is set.

* The _Hole in Extent_ column covers an unbacked offset inside the unit's
  decoded extent. Where parts of a wrapper answer differently, the cell lists
  each part: `between sub-blocks`, `between instances` for the padding after
  each array element, and `past sub-block registers`. Where sub-blocks differ
  past their registers, the cell names each by its SystemRDL instance name, as
  in the SMC PWM row.
* The _Past Extent_ column covers the rest of the unit's aperture, the range
  its Size column gives.
* A `Reserved` row is an address between unit apertures.

A cell can also hold one of these values instead of a response code:

`Aliases registers`:: The access reaches a live register at another offset,
which answers it.
`Forwarded`:: The subsystem passes the access on without decoding it, and its
target answers.
`Adopter-defined`:: The adopter's implementation answers.
`-`:: The region does not exist: the unit is memory, its registers fill its
extent, or its aperture ends at its extent.
