= Register Overlays

This note captures the minimal adopter-overlay flow for register generation.
It is intentionally rough; the integrator guide can polish it later.

== When an overlay is needed

Most adopters do not need a register overlay. The open tt-oca tree already
provides the canonical SystemRDL sources and committed generated collateral for
the open OCAH IP blocks:

* `hw/ip/*/regs/*.rdl` (block tops and standalone sibling blocks)
* `hw/sys/*/regs/*.rdl` (composite subsystem tops)
* `hw/sys/*/regs/blocks/<sub>/<sub>.rdl` (composite local CSR sub-blocks)
* `*/regs/include/*.rdl` (pure `` `include `` fragments; never generated directly)
* `*/regs/gen/{c,sv,svh,py,adoc}`

Each first-party `regs/` directory follows the layout convention documented in
`doc/user_guide/regs.adoc` ("RDL tree layout"): the dir-name top, standalone
siblings at the regs root, pure fragments under `include/`, and composite
sub-blocks under `blocks/<sub>/`. The role of an RDL is its location, which is
what makes register discovery a pure glob with no hand-maintained block list.

An adopter should use those generated files directly unless they need to model
technology-specific or proprietary wrapper blocks. The expected overlay use
case is the small set of intentional shim slots and extension regions, such as
PLL/PVT wrappers, eFuse shims, or subsystem extension windows. The adopter does
not need to duplicate all tt-oca IP RDLs.

== How the overlay is included

An adopter overlay lives in an adopter-controlled tree outside tt-oca. Keep
proprietary RDL, generated collateral, and the overlay makefile in that external
tree; do not add them under the open tt-oca checkout.

Copy `doc/integrator_guide/examples/overlay.example.mk` into the adopter tree,
fill in the paths, and pass it to make:

[source,sh]
----
make regen-regs OCAH_ADOPTER_OVERLAY_MK=/path/to/acme-overlay/overlay.mk
----

The template is:

[source,makefile]
----
include::examples/overlay.example.mk[]
----

The overlay fragment sets the same generic register-generation variables used
by the open flow:

* `OCAH_EXTRA_REG_RDL_FILES` registers standalone adopter RDL entry points.
* `OCAH_EXTRA_REG_BLOCKS` registers additional block ids, typically subsystem
  variants such as an adopter-specific `smc`.
* `OCAH_REG_RDL_OVERRIDE_<key>` lets a variant reuse a canonical tt-oca top RDL.
* `OCAH_REG_EXTRA_SEARCH_<key>` prepends adopter RDL directories so bare
  SystemRDL includes resolve to adopter files first.
* `OCAH_REG_GEN_OVERRIDE_<key>` and `OCAH_REG_BUILD_OVERRIDE_<key>` keep
  generated collateral under the adopter overlay tree.

The example template is inert by default and shows the expected variables
without registering real blocks.

== Standalone shim generation

If an overlay provides a shim RDL such as:

[source,text]
----
/path/to/acme-overlay/hw/sys/smc/dv/shims/regs/pll_wrap.rdl
----

then the overlay can add it to `OCAH_EXTRA_REG_RDL_FILES`. Running:

[source,sh]
----
make regen-regs TARGET=pll_wrap OCAH_ADOPTER_OVERLAY_MK=/path/to/acme-overlay/overlay.mk
----

generates the usual per-block collateral next to that RDL, for example:

[source,text]
----
/path/to/acme-overlay/hw/sys/smc/dv/shims/regs/gen/c/pll_wrap.h
/path/to/acme-overlay/hw/sys/smc/dv/shims/regs/gen/sv/pll_wrap_reg.sv
----

== Subsystem-top variants

For subsystem tops, the overlay should normally reuse the canonical tt-oca top
RDL instead of forking it. For example, an adopter-specific SMC variant can point
`OCAH_REG_RDL_OVERRIDE_<key>` at:

[source,text]
----
$(OCAH_ROOT)/hw/sys/smc/regs/smc.rdl
----

and set `OCAH_REG_EXTRA_SEARCH_<key>` to the adopter shim directories. When
PeakRDL elaborates the canonical top, bare includes such as `"pll_wrap.rdl"`
resolve to the adopter shim first. The top address map stays shared; only the
replaceable shim contents change.

The canonical top's other bare includes — its local CSR sub-blocks (now under
`hw/sys/<top>/regs/blocks/<sub>/<sub>.rdl`) and its pure fragments (under
`hw/sys/<top>/regs/include/`) — still resolve automatically: the engine adds the
open tree's `regs/blocks/*` and `regs/include` directories to the search path for
composite tops, so a variant reusing the canonical top RDL needs only its own
`OCAH_REG_EXTRA_SEARCH_<key>` for the replaceable shims.

Running:

[source,sh]
----
make regen-regs TARGET=smc OCAH_ADOPTER_OVERLAY_MK=/path/to/acme-overlay/overlay.mk
----

can generate both the open SMC collateral and the registered adopter SMC
variant collateral.

== Firmware include paths

The hand-maintained firmware umbrellas (`hw/common/dv/fw/smc.h` and `sep.h`)
include generated headers by basename. Firmware builds must therefore search
adopter generated C-header directories before open generated directories.

Pass explicit include directories for the adopter generated headers:

[source,sh]
----
make -C hw/sys/smc/dv/fw \
  OCAH_ADOPTER_OVERLAY_FW_INCLUDE_DIRS="/path/to/acme-overlay/hw/sys/smc/regs/gen/c /path/to/acme-overlay/hw/sys/smc/dv/shims/regs/gen/c"
----

This is compile-time header selection only. The register-generation selection is
controlled by `OCAH_ADOPTER_OVERLAY_MK` and the `OCAH_EXTRA_*` / `OCAH_REG_*`
variables.

== KISS guidance

Use overlays only for blocks that are intentionally replaceable or adopter
specific. Do not fork tt-oca's canonical top RDLs or duplicate every open IP
register description. Keep the overlay small: provide same-named shim RDLs,
register them with an overlay Makefile, regenerate only the affected blocks, and
let firmware include order select the adopter headers.
