# Register Generation

OCAH register collateral is generated from each block's SystemRDL file under
`hw/ip/<block>/regs/<block>.rdl`. Generated files stay with the RDL under
`hw/ip/<block>/regs/gen/`.

Some OpenTitan-sourced blocks start from HJSON instead of hand-authored RDL.
Those blocks are listed in `OCAH_HJSON_REG_BLOCKS` using their vendored block
roots; `hw/regs.mk` first exports the vendored HJSON to RDL with
`tools/regs/reggen_wrapper.py`, then runs the same PeakRDL outputs as the
native RDL blocks.

## Targets

Run all register generators:

```sh
make regen-regs
```

Run one block:

```sh
make regen-regs TARGET=gpio
make regen-regs TARGET=system_timer_octs
make regen-regs TARGET=otbn
```

Run one output class:

```sh
make regen-regs-sv TARGET=gpio
make regen-regs-h TARGET=gpio
make regen-regs-svh TARGET=gpio
make regen-regs-py TARGET=gpio
make regen-regs-adoc TARGET=gpio
make regen-regs-html TARGET=gpio
```

Implementation targets are prefixed as `ocah-*` in make fragments. The top-level
`Makefile` exposes unprefixed aliases such as `regen-regs`.

## HJSON-backed blocks

OpenTitan HJSON inputs are vendored under
`vendor/lowRISC/opentitan/upstream/hw/ip/<block>/data/`.
For example, OTBN uses:

```text
vendor/lowRISC/opentitan/upstream/hw/ip/otbn/data/otbn.hjson
```

The generated source RDL is written to:

```text
vendor/lowRISC/opentitan/upstream/hw/ip/otbn/regs/otbn.rdl
```

The local wrapper intentionally supports only the HJSON-to-SystemRDL path. The
OpenTitan reggen modules it imports are vendored directly from the pinned
OpenTitan revision under `vendor/lowRISC/opentitan/upstream/util/`.

## Outputs

For a block named `gpio`, generation produces:

```text
hw/ip/gpio/regs/gen/
  sv/gpio_reg.sv
  sv/gpio_reg_pkg.sv
  svh/gpio_reg.svh
  c/gpio.h
  c/gpio_addr.h
  py/gpio_addr.py
  adoc/gpio.md
  adoc/gpio.adoc
  html/index.html
```

The generated RTL package, such as `gpio_reg_pkg.sv`, is for the generated CSR
block's hardware interface. The address package include, such as
`gpio_reg.svh`, is for DV/RTL code that needs base addresses and register
offsets.

## Firmware Headers

`<block>.h` is generated by `peakrdl c-header` and is the primary firmware
header. It provides packed C structs plus field masks and bit positions:

```c
#include "gpio.h"

volatile gpio_t *gpio = (volatile gpio_t *)base_addr;
gpio->CONTROL.w = value;
```

`<block>_addr.h` is generated by `peakrdl-rawheader --format c`. It provides
raw constants for firmware or DV firmware that uses explicit MMIO helpers:

```c
#include "gpio_addr.h"

mmio_write32(GPIO_BASE_ADDR + GPIO_CONTROL_BASE_ADDR, value);
```

Both headers live in `regs/gen/c/`, but they use distinct filenames and include
guards. Keep rawheader prefixes enabled to avoid macro collisions across blocks.

## Documentation

HTML documentation is generated directly with `peakrdl html`.

AsciiDoc documentation is generated by first exporting Markdown with
`peakrdl markdown`, then converting it with Pandoc:

```sh
pandoc -f markdown -t asciidoc input.md -o output.adoc
```

Pandoc is required for `regen-regs-adoc`.
