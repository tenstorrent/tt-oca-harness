Interrupts

SMC external interrupts pass through the Platform-Level Interrupt Controller (PLIC). CLINT supplies per-core timer and software interrupts. Each bus error unit (BEU) has both a direct core output and a separately selected PLIC output. This chapter distinguishes raw SMC vector bits from software-visible PLIC IDs.

PLIC Sources and Contexts

The four-core implementation has 336 PLIC inputs with source IDs 1–336. ID 0 means no interrupt. The inputs comprise:

Table 2. PLIC input groups
Input group PLIC IDs Origin

Raw SMC vector bits 0–327

1–328

cpu_interrupts_o; detailed below.

Cluster watchdogs 0–3

329–332

Added by the cluster interrupt crossbar.

Core BEU PLIC outputs 0–3

333–336

Added within the PLIC clock domain.

Reserved raw-vector positions remain reserved PLIC IDs. The 256 external input meanings come from the enclosing SoC integration; an input count is not a promise that every position is an active source.

There are eight delivery contexts: machine contexts for cores 0–3, then supervisor contexts for cores 0–3. Priorities are shared per source; enable masks, thresholds and claim/complete registers are per context. A priority must exceed the context threshold to raise its external-interrupt output. Priority zero suppresses a source. See the generated map for context offsets and priority range. These settings route interrupts; they do not themselves enforce MMIO access policy.

The gateways are active-high and level-sensitive, with no selectable edge mode. External SMC pins pass through prim_sync3 before the raw vector. A short pulse can be missed if it is not sampled; stretch it or hold the request until serviced. A gateway admits one request and waits for completion before accepting another. It does not count repeated pulses while one request is in flight.

CLINT

CLINT provides a shared 64-bit timer, per-core compare registers and per-core software-interrupt state. Timer and software interrupts go directly to the cores rather than through PLIC claim/complete. The timer advances on the cluster’s periodic tick; see the Clocks and Resets chapter for its clock relationship.

Bus Error Units

A Bus Error Unit (BEU) accumulates error events for one core. The register named ACCRUED_ENABLE is sticky status, not an enable mask: events set its bits independently of ENABLE. Ordinary writes replace those bits; write zero to clear them. ENABLE instead gates capture of the first error’s CAUSE and PHYS_ADDR while CAUSE is zero. Software can also write PHYS_ADDR.

LOCAL_ENABLE selects accrued errors for direct delivery to the core, bypassing the PLIC and the ordinary per-source mie bits. This is not an unconditionally non-maskable interrupt: in machine mode, mstatus.MIE = 0 suppresses delivery. The machine interrupt is enabled while executing in lower privilege modes. The BEU also has a separate output selected by PLIC_ENABLE. The Bus Error Unit service sequence is in the Programmer’s Guide.

Sources and Routing

Raw Vector and PLIC Numbering

Raw bit N maps to PLIC source ID N+1. For example, DMA completion is raw bit 322 and PLIC ID 323. Watchdog IDs 329–332 and BEU IDs 333–336 are not additional bits on the 328-bit raw SMC vector.

SMC CPU Interrupt Vector Map

This section documents the raw cpu_interrupts_o vector assembled in hw/sys/smc/rtl/smc_base.sv. The vector is built from four sources:

  • smc_ext_interrupts_i

  • peripheral_interrupts_i[31:0]

  • mailbox_interrupts[31:0]

  • four internal interrupt signals

Unless otherwise noted, the bit numbers below are raw cpu_interrupts_o bit indices, not PLIC source IDs. When these signals feed the PLIC, the PLIC source ID is cpu_interrupts_o bit index + 1.

The vector layout is:

cpu_interrupts_o[NumExtInterrupts-1:0]        = ext_interrupts_smc_clk; // smc_ext_interrupts_i after 3-stage sync to clk_smc
cpu_interrupts_o[NumExtInterrupts+:32]        = peripheral_interrupts_i;
cpu_interrupts_o[(NumExtInterrupts+32)+:32]   = mailbox_interrupts;
cpu_interrupts_o[(NumExtInterrupts+64)]       = tdr_dbg_ctrl_clocks_stopped_by_cla_o;
cpu_interrupts_o[(NumExtInterrupts+64)+1]     = cla_interrupt;
cpu_interrupts_o[(NumExtInterrupts+64)+2]     = dma_intp;
cpu_interrupts_o[(NumExtInterrupts+64)+3]     = zeroer_intp;

NumExtInterrupts = 256 and NumCpuInterrupts = 328.

AXI hang detector OR

OR of the three AXI hang detectors (sys_axi, sep_axi, data_accel). Asserts while any detector’s irq_o is high, so software must read SMC_BASE_CONFIG.HANG_DET_{SYS_AXI,SEP_AXI,DATA_ACCEL}_CTRL to identify the stalled master. There is no status latch to clear: the level drops when that master’s bus makes progress, or when the detector’s enable or irq_en is cleared. The CPU AXI master is not covered here; it is covered by the watchdog.

Routing Notes

smc_base.sv assembles the raw vector; smc_peripherals.sv assembles its 32-bit peripheral slice. The AXI hang-detector OR enters peripheral bit 30 (raw bit 286), while bit 31 is reserved. The table preserves the individual sources behind combined GPIO, UART/log-engine and hang-detector indications; software must inspect their local status to identify and service the cause.

The six I3C entries are connected through the peripheral CDC block. The AVSBus and external-watchdog indications are also synchronized into the SMC domain. Do not infer pulse-capture guarantees merely from the presence of a synchronizer. DMA and zeroer completion indications are busy-falling pulses, not counted queues.

Software Handling

The PLIC priority, enable and threshold registers are not reset by hardware. A source’s priority is shared by every context that enables it. Completion releases the source’s gateway, so a still-asserted source pends again; claim and complete do not clear a peripheral’s own sticky status. CLINT timer and software interrupts do not use PLIC completion.

The Interrupt Control section of the Programmer’s Guide gives the PLIC initialization and claim/complete sequence, CLINT timer and software interrupt service, and Bus Error Unit service. Watchdog recovery and CPU reset/isolation ordering are described in the Watchdog Timers and CPU chapters. For CPU cluster context, see CPU and Memory System.
