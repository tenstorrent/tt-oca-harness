Mailbox Unit

Overview

This document specifies the Mailbox Unit hardware IP functionality. The Mailbox Unit provides FIFO-based bidirectional communication channels for inter-processor or inter-chiplet communication using AXI4-Lite interfaces. It enables efficient data exchange between processing elements through dedicated hardware channels with minimal software overhead.

Description and Features

The Mailbox Unit enables secure, FIFO-based, bidirectional communication between processing elements or chiplets in multicore systems. Each configurable mailbox instance consists of paired inbound and outbound channels, allowing simultaneous data transfer with a 64-bit data path. Multiple independent mailbox pairs are supported, each equipped with dedicated control registers, status monitoring, and programmable interrupt thresholds.

The architecture uses standard AXI4-Lite interfaces for integration and provides robust error detection, reporting, and software-controllable FIFO flushing. Channel depth is adjustable per instance to suit system needs, while hardware minimizes software overhead for efficient, low-latency data exchange.

Architecture

The SMC Mailbox IP provides inter-processor and inter-chiplet communication through a register-based interface. The design separates protocol handling from storage implementation, allowing system integrators to choose appropriate FIFO implementations while maintaining consistent software interfaces.

Address Space

The architecture supports up to 64 mailbox instances (32 bidirectional pairs):

  • Address Width: 18 bits (0x20008 bytes total)

  • Data Width: 64 bits

  • Per-Mailbox Space: 0x800 bytes (2KB)

  • Decoding: Efficient address decode logic for up to 32 pairs

The 64-bit data width optimizes handling of addresses, data payloads, and status information without multi-word transfers. The 2KB allocation per mailbox enables threshold configuration, priority handling, and diagnostic features.

Hardware Interface

The SystemRDL-generated register block provides hardware interfaces to external FIFO implementations through two signal structures:

Hardware Input Interface (mailbox_wrap__in_t)
Signal Description

rd_ack

Read acknowledge for handshake protocol

wr_ack

Write acknowledge for handshake protocol

rd_data[63:0]

64-bit read data from external FIFO

The acknowledge signals implement handshake protocol for reliable data transfer regardless of external FIFO timing. The 64-bit read data interface eliminates width conversion overhead.

Hardware Output Interface (mailbox_wrap__out_t)
Signal Description

req

Transaction request to external FIFO

addr[6:0]

Local address within mailbox space

req_is_wr

Transaction type (1=write, 0=read)

wr_data[63:0]

64-bit write data to external FIFO

wr_biten[63:0]

Byte enable for write data

The 7-bit local address enables multiple registers per mailbox. Byte enables provide granular write control for external FIFO optimization.

Transaction Processing

AXI4-Lite transactions follow this flow:

  1. Address Decode: Register block decodes mailbox instance and operation type

  2. Hardware Interface: Generates req, addr, req_is_wr signals to external FIFO

  3. FIFO Processing: External logic processes request according to timing characteristics

  4. Acknowledge: External FIFO asserts rd_ack/wr_ack when complete

  5. AXI Response: Register block completes AXI4-Lite protocol

This coordination mechanism maintains consistent AXI4-Lite timing while allowing external FIFOs to optimize internal operations for specific performance or resource requirements.

Bidirectional Communication

Each mailbox pair provides separate inbound and outbound register spaces:

  • Inbound Space: Optimized for low-latency command processing

  • Outbound Space: Optimized for high-throughput status/telemetry transfer

  • Independence: No mutual interference or resource contention

Separate register spaces enable different optimization strategies per direction. Interrupt generation integrates with external FIFO status reporting for event notification.

Clock and Reset

The mailbox uses a single clock domain for integration reliability:

Signal Type Description

clk_i

Single clock

Unifies functional logic and AXI4-Lite interface

rst_ni

Asynchronous, active-low

Primary reset, initializes all mailbox state

test_en_i

Test enable

DFT support

No internal clock domain crossings eliminates CDC complexity. Single clock domain simplifies timing analysis and integration verification.

Interrupt Architecture

The mailbox provides independent interrupt outputs for each mailbox instance:

  • inbound_interrupt_o[NUM_MAILBOXES-1:0]: Inbound communication events

  • outbound_interrupt_o[NUM_MAILBOXES-1:0]: Outbound communication events

Separate inbound/outbound interrupts reflect different processing requirements. Inbound interrupts indicate incoming commands requiring immediate processing; outbound interrupts indicate successful transmission or buffer availability.

The following table reports the interrupt sources.

Source Description

Write Threshold

FIFO fill level exceeds configured threshold (proactive buffer management)

Read Threshold

FIFO data available for efficient retrieval scheduling

Overflow Error

Write to full FIFO (fault detection)

Underflow Error

Read from empty FIFO (fault detection)

Each interrupt output aggregates these sources. Threshold-based interrupts reduce polling overhead. Error interrupts enable fault recovery and diagnostic analysis.

Memory Map
Address Space Organization

Each mailbox instance occupies a dedicated 2KB (0x800) address space. The total address space is 0x20008 bytes supporting up to 64 mailbox instances (32 pairs):

Base + 0x00000 - 0x007FF: Outbound Mailbox 0
Base + 0x00800 - 0x00FFF: Inbound Mailbox 0
Base + 0x01000 - 0x017FF: Outbound Mailbox 1
Base + 0x01800 - 0x01FFF: Inbound Mailbox 1
Base + 0x02000 - 0x027FF: Outbound Mailbox 2
Base + 0x02800 - 0x02FFF: Inbound Mailbox 2
...
Base + 0x1F000 - 0x1F7FF: Outbound Mailbox 31
Base + 0x1F800 - 0x1FFFF: Inbound Mailbox 31
Base + 0x20000 - 0x20007: MAILBOX_RSVD (Reserved space)
Address Space Characteristics:

  • Per-Mailbox Size: 2KB (0x800)

  • Total Address Space: 0x20008 bytes

  • Address Width: 18 bits

  • Maximum Mailboxes: 32 pairs (64 instances)
