Security Processor (SEP)

The Security Processor (SEP) is the chiplet Root of Trust. Its documentation is organized into focused topic pages so architecture, security policy, software interfaces, and generated register details can be read independently.

1. Start Here

  • Introduction — SEP responsibilities and services.

  • Threat Model — attacks considered by the design.

  • Attack Countermeasures — architectural, debug, and DFT protections.

  • Hardware Overview — major SEP blocks and their relationships.

2. Architecture and Interfaces

  • SEP Interconnect — internal and external transaction paths.

  • AXI Traffic Filter — shared SEP and SMC filter decode.

  • Memory Map and Register Reference — address regions and generated register tables.

  • CPU Subsystem — VeeR EL2 configuration, boot, DMA, and alarms.

  • Boot ROM — immutable boot firmware and ROM architecture.

  • Interrupts — PIC assignments and non-PIC interrupt paths.

  • Cryptographic Subsystem — cryptographic accelerators, entropy, and key management.

  • Fuse Controller and Lifecycle Controller — OTP, lifecycle and security control, SPI, watchdog, and reset control.

3. Security Control

  • Token Processing — token generation, matching, and fault handling.

  • Security Disable — emergency security-disable behavior.

  • Life Cycle Controller — lifecycle states, demotion, and feature control.

  • Test Mode Entry — secure test-mode qualification.
